# End to end: what a halt from blank tape needs

`thm/EndToEnd.lean` puts the Lean results together into one statement about the machine
`1RB0RE_1LC0RA_1LA1LD_1LA---_0RF0LB_0LD1RE` started on blank tape. It does not settle the question. It says exactly
where a halt would have to come from: a clean tape of width at least 2³² whose width lies in one of a list of
explicit residue classes, of total measure 2.4 × 10⁻⁵.

## The statement

```lean
theorem blank_halt_structure (T : Nat) (hT : steps T ⟨blank, blank, .A⟩ = none) :
    (∃ W k, prefixWidth ≤ W ∧ W % 2 = 0 ∧ cleanTree.cutMem [(W : Int) / 2, 0] = true ∧
      steps k ⟨blank, blank, .A⟩ = some (roundStart [⟨.M, W - 2⟩] W) ∧
      steps (T - k) (roundStart [⟨.M, W - 2⟩] W) = none ∧
      ∃ t, Reach ⟨[], 1, [⟨.M, W - 2⟩], W⟩ t ∧ t.wf ∧ (EndClose t ∨ InteriorContact t)) ∧
    (∀ (R : Nat) (ms : List Mark) (W k : Nat), PassStart448 ms W R →
      steps k ⟨blank, blank, .A⟩ = some (roundStart ms W) →
      ∃ n₁ ms₁ W₁ R₁, roundsZ 1000 n₁ ms W = .newRound ms₁ W₁ ∧ (∀ d ∈ meetsRounds 1000 n₁ ms W, 3 ≤ d) ∧
        PassStart448 ms₁ W₁ R₁ ∧ R₁ ≤ R ∧
        ((InCloseClass ms₁ W₁ R₁ ∧ ∃ t, Reach ⟨[], 1, ms₁, W₁⟩ t ∧ t.wf ∧ (EndClose t ∨ InteriorContact t)) ∨
          ∃ n₂ ms' W', roundsZ 1000 n₂ ms₁ W₁ = .newRound ms' W' ∧ (∀ d ∈ meetsRounds 1000 n₂ ms₁ W₁, 3 ≤ d) ∧
            LoopEnd 1000 R₁ n₂ (meetsRounds 1000 n₂ ms₁ W₁) ms' W' ∧
            ∃ t, Reach ⟨[], 1, ms', W'⟩ t ∧ t.wf ∧ (EndClose t ∨ InteriorContact t)))

theorem never_halts_of_cut_classes
    (h : ∀ W, prefixWidth ≤ W → W % 2 = 0 → cleanTree.cutMem [(W : Int) / 2, 0] = true →
      ∀ T, steps T (roundStart [⟨.M, W - 2⟩] W) ≠ none) :
    ∀ T, steps T ⟨blank, blank, .A⟩ ≠ none
```

In words: if the machine halts from blank tape, then

1. on the way it reaches a **clean tape** (the gap at 1, then only the end marker M at W − 2) of even width
   W ≥ 2³² = 4,294,967,296 whose half W/2 lies in one of the **cut classes** of the clean-tape tree, and it halts from
   that clean tape;
2. the mark model, run on from that clean tape, reaches a **stuck configuration**: a close at the right end (the gap
   meets the end marker at distance 0, or touches a block at the end of the tape) or an interior contact;
3. every **phase-0 pass start** it passes on the way (walls at a, b, E − R − 1, width E, a odd, b even, E even, every
   gap ≥ 448: `PassStart448`) is followed by a close-free stretch the model covers, through the pass starts whose gaps
   are again all ≥ 448 to the last of them (right end R₁ ≤ R), and the halt needs a stuck configuration after it:
   either right there, with R₁ in the closing set {2, 4, 8, 16, 24, 32, 48, 64, 176} and L₁ in R₁'s class
   (`InCloseClass`), or after a further close-free stretch to where the run leaves the loop (`LoopEnd`: it leaves
   phase 0, its end meetings leave the halving chain, or it reaches the next pass start, and it is not at a pass
   start with every gap ≥ 448 there).

The same holds after every loop state with the exit stretch (`exit_halt_needs_contact`, `thm/ExitHalt.lean`: a
stuck configuration after a clean tape, a chain break or a loop state again after a full pass), but it is not part of
the conjunction.

**Why the stretches name their ends** (October 27). The first versions of items 3 and the exit said only "the model
covers n rounds from the pass start, with no close, and the halt needs a stuck configuration after them". With n = 0
that is just the round theorem: it holds for every start, with no tree. The trees' leaves now end at events stated in
`BB6/Ends.lean`, none of which holds after zero rounds, so the stretches are real: from a pass start the run is
followed until it leaves phase 0, breaks the end-meeting chain, or reaches the next pass start, and through every pass
start whose gaps stay ≥ 448.

`never_halts_of_cut_classes` is item 1 read backwards: the open question is now only about the clean tapes of width at
least 2³² in the cut classes.

## The pieces

| file | result | how |
|---|---|---|
| `thm/Prefix.lean` | `blank_prefix`: from blank tape the machine reaches the clean tape of width exactly 2³², without halting | the mark model from the first round start, 1,204,297,272 rounds, evaluated by `native_decide`, then `blank_rounds` |
| `BB6/CleanTree.lean` | `RTree.okW` / `RTree.soundW`: a route tree whose `clean` leaves are one-marker clean tapes **wider** than the start; `roundStart_one_ne`: clean tapes of different widths are different configurations | proved, no `sorry`, standard axioms |
| `thm/CleanTheorem.lean` (generated by `thm/gen_clean.py` from `thm/clean_tree36.txt.gz`) | `clean_tree_step`: from every clean tape of even width W ≥ 2³², the machine reaches a wider clean tape without halting, unless W/2 is in a cut class | the 36-digit tree, checked by `RTree.okW` with `native_decide` |
| `thm/EndgameTheorem.lean`, `thm/LoopTheorem.lean` | `endgame_stretch`: from a phase-0 pass start with gaps ≥ 448, a close needs R in the closing set and L₁ in R's class, and otherwise the run is close-free to an end event; `loop_stretch`: the same through every pass start with gaps ≥ 448 | the endgame trees checked by the kernel (`Tree.okEnd`, `decide +kernel`); strong induction on R |
| `thm/LoopHalt.lean` | `loop_halt_needs_contact`: a halt from a phase-0 pass start with gaps ≥ 448 needs a stuck configuration after the loop's close-free stretch | `loop_stretch` and `halt_after_rounds` |
| `thm/EndToEnd.lean` | `clean_chain`, `blank_halt_structure`, `never_halts_of_cut_classes` | strong induction on the halting time: each step of the clean-tape tree takes at least one machine step, because the next clean tape is wider |

## Why a one-variable tree over clean tapes, and not the two-marker route tree

The route tree (`ROUTE_TREE.md`) starts from two-marker states G 1, M m, M E − 2 with both gaps at least
8,000,000. Chaining it along the machine's run does not work: the machine's own run reaches two-marker states with a
tiny first gap again and again (for example m = 56 at width 34,478,025, m = 152 at width 12,260,337), which no cone
of large gaps contains. Clean tapes have one number, the width W, and every position on the way to the next clean tape
is an affine function of it, so the cone is just W ≥ Γ, and the clean tapes the run reaches are all wider than the
first one. This is the class tree of the exhaustive check (`../csearch/nrefdfs2.c`), proved: a split on the next
binary digit of W/2 when a round is not decided, and a path stops at the first wider clean tape.

## The clean-tape tree

| depth | Γ | closed classes | cut classes | cut measure | build (native) |
|---|---|---|---|---|---|
| 24 | 2³² | 9,814 | 10,722 | 6.4 × 10⁻⁴ | 4 s |
| 28 | 10¹⁰ | 52,599 | 57,934 | 2.2 × 10⁻⁴ | 18 s |
| 32 | 2³² | 276,728 | 303,559 | 7.1 × 10⁻⁵ | 2.5 min |
| **36** | **2³²** | **1,507,364** | **1,660,016** | **2.4 × 10⁻⁵** | **18 min** |

The cut classes grow about 1.52-fold per digit, as the open classes of the exhaustive check do (1.53), so the cut
measure falls about 0.76-fold per digit. A path is cut when it has made 36 splits without reaching a wider clean
tape; 6 of the 1,660,016 cut leaves are instead order tests the cone W ≥ 2³² does not decide (at depth 30 to 35),
which are cut as well. Longest path: 59 rounds. Every clean leaf is a one-marker clean tape decided to be wider than
the start (the builder checks `widerB` before it stops a path, and `RTree.okW` checks it again).

## What is trusted

Lean's kernel, plus Lean's compiler through `native_decide` for two evaluated checks, `prefix_ok` and `clean_tree_ok`
(`#print axioms blank_halt_structure` lists them besides `propext`, `Classical.choice` and `Quot.sound`). The exit
and endgame trees are checked by the kernel itself (`decide +kernel`, subtree by subtree in `thm/ExitPieces*.lean`
and `thm/EndgamePieces*.lean`, assembled in `thm/ExitTheorem.lean` and `thm/EndgameTheorem.lean`). `check_end.sh` also compiles the BB6 modules to a shared library
and loads it with `--load-dynlib`, so that `native_decide` runs native code; this adds the C compiler to the trusted
base (`--interpreted` avoids it, at about an hour for the prefix alone). The prefix cannot be moved to kernel
evaluation at any reasonable cost (10⁹ rounds). The clean-tape tree could be, at a cost: kernel evaluation is about 500
times slower than native code on these checks (0.06 s per round of the endgame trees against 0.12 ms), which would
turn its 4 minutes into something like 35 hours.

## What is not claimed

* **The cut classes.** Nothing is said about the clean tapes in them. Combined with the exhaustive check (every clean
  tape below 2⁶¹ reaches the next one without halting; a C computation, not in Lean), a halt would need a clean tape
  in a cut class above 2⁶¹. Deeper trees shrink the cut measure by about 0.76 per digit; the classes themselves are
  infinite, so no depth closes them.
* **Item 3** is a statement about the stretches after a pass start, not a claim that a halt goes
  through the loop. The σ bound (log₂W ≤ σ + 6.38 at the first pass start) is still not in Lean: the L₁ classes of
  the closing R are (`endgame_stretch`), but it also needs the pass map (R′ = R/16, L₁′ = L₁/64) and a way across
  half passes.
* The **two-marker route tree** (`route_tree_clean`) is not used here.

## How to check

```sh
LEAN=/path/to/lean LEANLIB=/path/to/lib/lean ./check.sh       # the BB6 modules
LEAN=/path/to/lean LEANLIB=/path/to/lib/lean ./check_end.sh   # the trees, the prefix and EndToEnd (about 12 minutes)
# rebuild the clean-tape tree (optional, 18 minutes):
LEAN=/path/to/lean LEANLIB=/path/to/lib/lean ./cbuild_ct.sh && ./cbuild/ExploreCT 36 4294967296 thm/clean_tree36.txt
```
