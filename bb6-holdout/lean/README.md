# Formalization of the mark rules in Lean 4

Started October 25. Self-contained (no Mathlib): Lean 4 core only, so it can be checked with a bare `lean` binary.

## Design

* A pattern with unknown surroundings is a configuration whose streams are variables. Because the step function
  reads only `r 0`, a `rfl` proof of `steps n c = some c'` can only succeed if the n steps never look at `L` or
  `R`; this is the Lean counterpart of the Python prover's "the simulator raises if it would read a context".
* A repeat `(10)^m` is `rep m [true, false] s`. Unrolling one copy is definitional (`rep (m+1) w s = app w (rep m w s)`),
  so single steps can walk into a repeat by `rfl` when its count is a successor. Crossing a whole repeat is one of
  the three cycle lemmas. The only non-definitional facts about repeats are `rep_app_comm` (a repeat absorbs a copy
  behind it) and `rep_shift'` (`x (y x)^n = (x y)^n x`), proved by induction.
* The step counts are exact; the rule counts are checked by `omega` against the sum of the segments.

## Status

* Checked with Lean 4.34.0 (release build): `./check.sh` compiles the 25 BB6 modules in about half a minute, with
  no `sorry`, and every theorem in them depends at most on Lean's three standard axioms (`propext`, `Quot.sound`,
  `Classical.choice`), the rules on none or the first two (`BB6.lean` prints the audit). `./check_end.sh` and
  `./check_route.sh` check the theorem files (`END_TO_END.md`, `ROUTE_TREE.md`).
* **The round theorem is proved.** One round of the machine, from the tape any well-formed mark state denotes, is one
  round of the mark model (`roundZ`), or a halt where the model says halt. With `first_round_start` this gives
  `blank_rounds`: from blank tape the machine follows the model for as many rounds as the model covers. The model's
  `uncovered` (configurations no proven rule covers: marks touching where a rule needs a stripe cell, an odd meeting
  distance, …) makes no claim.
* The zipper model `roundZ` was checked against the list model `Model.round` (the port of the certificate checkers'
  simulator): identical for the 200 rounds from the first round start, and on 20,000 random well-formed round starts
  no outcome differs where both make a claim.
* **A correction to the simulator** (Python checkers, C explorers and `Model.lean`), found by this comparison. When a
  shift reaches a block that ends the tape (block in the last three cells), the simulator writes a wall in the last
  two cells, partly past the width: the same tape as no wall and width W − 1, but a mark the simulator later treats as
  real. A shift that reaches that "trailing wall" turns it into a block past the width, where the machine forms an end
  marker. In 1,500 random well-formed starts run 8 rounds each, the list model gave a wrong tape in 2 (always this
  sequence); the zipper model never did (it cannot: it is proved), and covered at least as many rounds in every case.
  `roundZ` writes the canonical form (no wall, width W − 1); `build_trailing_wall` is the fact that the two are the same
  tape. Whether any certified run passes through this sequence is audited in the lab notes ("The trailing wall").
* **Certificates checked through the proved model.** `CheckExit.lean` and `CheckEndgame.lean` (run with
  `lean --run`) read a certificate file and run every leaf through `symRoundsZ`: the exit certificate checks completely
  (all 358 leaves, every round covered, every shape as claimed) once the cone threshold is Γ = 390 (the Python checker
  needs 255: the proved model makes a few extra decisions, at the end of the tape and for the guards of its
  subtractions, with larger margins). By `leaf_run` this is a statement about the machine for every member of every
  leaf with all gaps ≥ 390. The partition check is not needed for the theorems below (their trees cover the start
  class by construction), and the end meetings that classify break and clean-tape exits are now in Lean as well
  (`BB6/Meets.lean`, `BB6/Ends.lean`).
* **Two certificate results are Lean theorems** (`thm/ExitTheorem.lean` and `thm/EndgameTheorem.lean`, both checked
  by Lean's kernel alone): `exit_stretch` (every loop state with gaps ≥ 390 runs, without halting and with every end
  meeting at distance ≥ 3, to a clean tape, a break of the end-meeting chain, or a loop state again after a full pass)
  and `endgame_stretch` (every phase-0 pass start with R even, R ≥ 2, and gaps ≥ 448: either R is in the closing set
  {2, 4, 8, 16, 24, 32, 48, 64, 176} and L₁ is in R's class, or the run is halt-free and close-free until it leaves
  phase 0 or its end meetings leave the chain, at a round start that is not three walls, or it lands on three walls
  again by a full pass, a half pass or a round-7 break, with that step's exact map on E, R and L₁). Coverage is by construction
  (coordinate splits and skews), so no partition argument is used. The number of rounds is existential (chosen per
  class by an untrusted program), but it ends at a stated event that never holds after zero rounds; the first
  versions of these theorems (`exit_no_halt`, `endgame_no_close` before October 27) said only "a round start without
  halting", which zero rounds satisfy.
* **The loop's chain, at any width** (`thm/LoopTheorem.lean`, `thm/LoopHalt.lean`): `LoopChain`, the stretches of
  `endgame_stretch` carried through every landing on a pass start whose gaps are again ≥ 448: full passes
  (R′ = R/16, L₁′ = L₁/64), round-7 breaks (R′ = (4E + 4R − b + 110)/32) and a half pass (R′ = R/2, only as the
  first step), each with its exact map checked at the trees' leaves. A round-7 break can raise R, so the chain is
  followed by induction on the halting time (`loop_chain_halt`). Within the loop a close comes only from a pass start
  whose R is in the closing set and whose L₁ is in that R's class.
* **The σ bound** (`LoopChain.sigma`, `loop_halt_sigma`, `blank_halt_sigma`): a close through the loop needs
  R³/L₁² ≤ 176³/256² at the start of the chain's last run of full passes, that is log₂W ≤ σ + 6.38 with
  σ = 3 log₂(W/R) + 2 log₂(|L₁|/W); the bound is attained (R = 2,816, L₁ = −16,384: one pass to R = 176, L₁ = −256,
  then a close). At a round-7 landing it needs E < 2²⁷ (`break7_sigma`), so from a width ≥ 2²⁷ a close through the
  loop is p full passes after at most one half pass (`LoopChain.close_wide`, `loop_halt_wide`, `blank_halt_wide`). The former `loop_pass`
  (a tree for R ≥ 4097 with the pass map R′ = R/16, L₁′ = L₁/64 or R′ = R/2) is retired: its "not a phase-0 pass
  start" end held after one round, so it did not say that the pass map is ever reached.
* **End to end** (`thm/EndToEnd.lean`, `thm/EndToEndDirect.lean`, `END_TO_END.md`): `blank_halt_clean` — a halt
  from blank tape needs a clean tape of width ≥ 2³² that the clean-tape tree leaves open at every depth (at 36 digits:
  one of 1,660,024 cut classes, measure 2.4 × 10⁻⁵, the exhaustive check's open classes), then a close at the right
  end or an interior contact;
  `blank_halt_loop`, `blank_halt_exit` — every pass start with gaps ≥ 448 or loop state on the way is followed by
  its certified stretch first, to the event where the stretch ends, through the loop's chain (`blank_halt_sigma`:
  beyond the σ bound, the run does not close through full passes alone); `blank_halt_clean_direct` — with the clean tapes
  below 2⁴¹ in the cut classes run one by one (26,508,327 runs), the clean tape is at least 2⁴¹ wide;
  `blank_halt_structure_kernel` — the same from width 2²⁰ (the kernel's prefix, then the tree over the widths ≥ 2²⁰),
  with no `native_decide` at all: `#print axioms` lists `propext`, `Classical.choice` and `Quot.sound` only.
* **Trees built by a proved explorer** (`BB6/RouteExplore.lean`): the clean-tape tree and the two-marker route tree
  are no longer data checked by `native_decide`; the theorems hold at every depth with the standard axioms only, and
  only the measure of the cut classes is evaluated.
* **The cone's edge** (`drop` in `BB6/CleanTree.lean`, October 27): a class whose smallest member decides a
  comparison differently no longer stays cut at every depth; that member is run directly, so the clean-tape trees'
  cut classes are the exhaustive check's open classes at 36 and 40 digits, with the cone at 2²⁰, 2³² or 2⁴¹ alike.
