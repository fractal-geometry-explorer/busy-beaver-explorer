What is known about 1RB1RA_1RC1LB_1LD0RA_1LB0LE, and what is open

1RB1RA_1RC1LB_1LD0RA_1LB0LE_1LF1LD_---0LD

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape. This page tracks what has been established about it, sorted by what each result rests on. (It shares its first three states with 1RB1RA_1RC1LB_1LD0RA_---0LE_1LC0LF_1RE0LB, which has its own page; the two are different machines.)

The run is made of passes, and a pass is a map on the lengths of the blocks of ones. The closed form of that map is proved in Lean for every block list, and with it the reduction: the machine halts only if some pass's sweep stops at a block of a single 1. The explainer runs the machine, its passes and the closed form in the browser.

Status as of 1 November 2026.

In short

The question is open. Lean proves no halt in the first 20,000 steps by the kernel alone and in the first 107 steps with native_decide; the C simulator finds no halt in the first 1011 steps.

Where it stands. At the start of each pass the tape is 1^y1 0 1^y2 0 … 0 1^yk A>0. Lean's kernel proves the closed form of the pass map for every block list, that a pass adds exactly four ones, that a halt needs the last block odd and all others even (so an odd number of ones), and from these the reduction: if the machine halts from blank tape, the orbit of block lists reaches a pass whose sweep stops at a block of a single 1 (halts_only_by_one). Iterated one pass at a time for 1011 passes it never does: after pass 50 no sweep stops at a block below 59, and the lists have 2 to 6 blocks, all of them a fixed fraction of the tape except a tail that halves each pass.

The return map, now a theorem. Every two-block state [a, 2a+d] with |d| ≤ 3 leads in at most three passes to one with d = 1 (Lean, every a ≥ 5), and from [a, 2a+1] the orbit comes back to [a+12k, 2(a+12k)+1] after 9k passes. Lean's kernel checks this return for every a = 1 mod 4 with 5 ≤ a < 262, by running the pass map on residue classes of a with a symbolic evaluator that is itself proved to agree with the pass map. With the reduction: the first 3·260 ≈ 3.46·1018 passes never stop at a block of 1, and the machine reaches every one of their pass starts (no_one_3e18_kernel, kernel only). Whether the machine halts is now a question about the excursion from [a, 2a+1] for a ≥ 262, and the route list there is infinite, so this way of checking cannot settle it. The same computation in Python reaches 274 (1.4·1022 passes, trusted).

Is it Collatz-like? Not at the level of the return map: G only adds 12k (k ≥ 1), so its orbit is a counter that runs through about 95% of all a = 5 mod 12 in order, and the question is not where one orbit goes but whether every excursion is safe, a statement for all a. Inside the excursions there is Collatz-style mixing, but only on a thin 2-adic set (dimension about 0.19), and with a wide margin: on every route checked a stop block is at least about a/64, where a stop block of 1 needs about 1/a. So a proof looks possible, as an inequality on the stop blocks proved by induction, but not as a finite case analysis.

The pass

A pass starts with A on the blank cell right of the tape. A, B and C write three ones and D turns back (start). D and E then run left writing 0 and 1 in turn (de_sweep), halving the last block into (10)^m. Where E reaches a 0 between blocks it crosses into the next block on the left (e_cross), unless that block is empty: then F reads a 0 and the machine halts. Where D reaches one, the sweep ends (d_stop), and A, B and C zigzag back to the right end, each round absorbing a 0 1 and moving a 0 one cell right (zig), until C meets a 0 at the right end and the next pass begins.

So the last block is crossed if it is odd, the blocks before it are crossed while they are even, and the sweep stops at the first odd one, yj. The closed form (py/passmap.py): if yk = 2m is even, the last block goes and the two before it each gain m+2; if yk is odd, yj-2 gains (yj−1)/2, yj-1 gains (yj+1)/2 + hj+1, and the blocks from yj on become hj+1+hj+2, …, hk-1+hk, hk−1, with hi = yi/2 and hk = (yk+5)/2. The blank on the left counts as empty blocks. A stop block yj = 1 is the one case outside the form, and there the count of ones changes by an odd number.

The closed form of a pass, for every block list

The pass map is defined in Lean (next, with the sweep, the stop and the zigzag as sweep, bump and zag), and the machine follows it: from the pass start of any block list it reaches the pass start of next of it, and it halts whenever next says halt. Every block list, every length; the zigzag and the sweep are inductions on top of the pieces. The only case left out is a sweep that stops at a block of a single 1.

pass, pass_halt, lean/Pass.lean

The reduction to a stop block of 1

A pass adds exactly four ones and keeps every block nonempty (next_sum); a halting pass needs an odd count of ones (next_halt_odd). So pass n from blank tape starts with 4n ones and no pass halts (orbit_ok, orbit_ne_halt), and if the machine halts from blank tape then some pass of the orbit stops at a block of a single 1 (halts_only_by_one). Kernel only; the standard axioms (propext, Quot.sound, Classical.choice), no native_decide.

halts_only_by_one, never_halts_of_no_one, lean/Pass.lean

The stop block of 1 can only be the first block

Every block after the first stays at least 2 (next_good, orbit_good), so a sweep stops at a block of 1 only at the first block, after crossing every other one (one_front). With a count of ones divisible by 4, two passes in a row never both stop at the first block (front_twice): both would force 2 mod 4 ones. So if the machine halts, some pass start is 1 0 1^e 0 … 0 1^b A>0 with every e even and b odd, and the pass before did not stop at its first block (halts_only_at_front). Kernel only, no native_decide. No invariant was found that excludes the first block falling to 1.

halts_only_at_front, lean/Front.lean, tests/test_front.py

The short chains between two-block states, for every a

From [a, 2a+d] with a ≥ 5 in the right class mod 4: d = 0 goes to −2, −2 to −1, 2 to −3 (one pass each), −1 to 1 and 3 to 2 (two passes), −3 to 0 (three passes), with a growing by 2, 1, 3, 2, 3, 3. So every two-block state reaches one with d = 1. Proved for every a by running Lean's pass map on the class a = p + 4u symbolically (srunN, proved sound by srunN_ok).

The return map G(a) = a + 12k, for every a below 262

For every a = 1 mod 4 with 5 ≤ a < 262, Lean's pass map takes [a, 2a+1] to [a+12k, 2(a+12k)+1] in exactly 9k passes, k ≥ 1 (Returns). How: snext is the pass map on values p + q·u, failing wherever a parity or a comparison is not the same on the whole class, and snext_ok proves it agrees with next at every u. explore runs a class, splits it by the parity of u, sets the single value u = 0 aside to run concretely, and runs the one member below 262 of each class left at mod 262; explore_ok proves that when it says yes, every member returns. One kernel decide on the whole class runs out of memory, so lean/return62.py cuts it into 1,575 subclasses, each checked by decide +kernel in its own theorem (8 files, lean/R62/), and Cov.split puts them together. About an hour of CPU (17 minutes on 4 cores); lean/check_return62.sh, its own CI workflow. The same computation by native_decide (returns_2_62) takes seconds and is in the regular check, and the kernel alone does a < 216 there (returns_2_16). The Python run (py/returnmap.py classes 60: 19,231 routes, k = 1 to 11) agrees.

returns_2_62_kernel, lean/Return62.lean; explore_ok, snext_ok, lean/Return.lean

No stop block of 1, and no halt, in the first 3.46·1018 passes

Pass 4 from blank tape (counting blank tape as pass 0, so pass n has 4n ones) is [5, 11]. A pass start [a, 2a+1] has 3a + 1 = 4n ones, so a = 1 mod 4 and a < 262 while 4n ≤ 3·262; the return map then gives a later pass start of the same shape, and a later block list means every earlier pass was a block list too (orbit_ok_upto). So every pass n ≤ 3·260 + 1 is a block list with 4n ones, never a stop block of 1, and the machine reaches its pass start (reach_upto, from pass). Kernel only: propext, Quot.sound, Classical.choice.

The block count is not bounded by 6 on excursions

From the two-block pass start [a, 2a+1] with a = 2203 + 2221 + 1 (a = 5 mod 12, like every two-block state of the blank orbit) the machine reaches a pass start with 7 blocks after 204 passes, and is back at [a+288, 2(a+288)+1] after 216. The route, in (block count, psi), is exactly the escape the graph allows; the classes to mod 266 missed it because it needs a mod 2222. So the 6-block reduction rests on a statement that fails for some excursions.

The orbit of G is a counter

G never goes down: the state [a', 2a'+1] has 3a'+1 ones, four more per pass than [a, 2a+1] (next_sum), so a' = a + 12k with k ≥ 1. From a = 5 the orbit steps through the values a = 5 mod 12 in order and skips exactly those inside a jump, a + 12j with 0 < j < k(a): 4.8% of them in the first 300,000 returns (up to a = 3,780,401), where k = 1, 2, 3, 4 occur 285,232, 14,510, 251 and 7 times. The deep values are on it: every a = 2r + 1 with r even in that range, and the values with v2(a−1) = r occur about 2−r as often as for a uniform a. So there is no orbit to follow: in practice the machine halts if and only if some excursion from [a, 2a+1] is unsafe.

An excursion reads only the low bits of a

The route of the excursion from [a, 2a+1], and so k and the stop blocks as fractions of a, depends only on a mod 2m for some m: for random a of 64 or of 1,024 bits, m is 5 on average and at most 16, and k and the margin have the same distribution at both sizes. The classes that need more than m bits have measure about 2−0.81m (15,828·2−72 of a = 1 mod 4 at m = 74).

A second invariant: psi

psi = yk − 2yk−1 + 4yk−2 − … obeys 2·psi(next) = −psi + 3(−2)n − 7 exactly, where n is the number of blocks the sweep crosses past the last. On [a, 2a+d] it is d, so the six d-chains of the return map are this recurrence. The last block's parity is psi mod 2. It ends the halving loop of [110, 63, 23]: that loop maps psi to (psi − 13)/4 and needs psi = 1 mod 4 every round, so it runs about log4|psi| rounds. The free-parity game, which drives the first block to 0, ignores it.

A conditional reduction to the block count

The (block count, psi) graph, with every stop index psi allows and no two front stops in a row, is exact for every list. With at most 6 blocks it has 158 states, and on its paths at most 9 front stops come between two other changes of the first block. A front stop halves the first block, so with at most 6 blocks a first block of 1 needs one of those changes to leave it at most 511.

heuristic Evidence only

Stop blocks stay above a fixed fraction of a

On every route down to mod 274, each stop block is at least about a/64 (2−6 from depth 48 to 74, 2−4 from 19 to 45): the worst fraction shrinks with the depth m of the residue class, about as 2−m/10 or slower (a = 2r + 1: about a·2−r/10). A stop block of 1 would need it to shrink like 2−m. The route list is infinite: the tail left by the first pass lives v2(a−1) passes, so k is unbounded, and the front runs nested excursions inside it; for each k the routes are finite (k = 1 to 5 need a mod 28, 217, 226, 235, 244).

python3 py/returnmap.py classes 72, notes/LAB_NOTES.md

Collatz-like mixing, but only on a thin set

The classes still open at depth D (members whose route needs more than D+2 bits) number 5, 20, 67, 261, 584, 2,061, 4,332, 15,828 at D = 16, 24, …, 72: about 20.19D, a 2-adic Cantor set of dimension about 0.19 that holds every a not yet proved safe (and a = 1, whose excursion is the stop block of 1). On it the blocks are a·c + e with c a dyadic fraction whose odd numerator is about as long as the modulus (51 bits at depth 48), and no two open classes share their coefficients even up to scale (584 of 584 at depth 48): the deep excursions mix the bits of a like an affine map with odd multipliers, as Collatz does, and are not a finite automaton in these coordinates. What separates this from Collatz is the margin: a halt needs a stop block of 1, a fraction about 1/a, and every route checked keeps it above 1/64.

Which starts meet a stop block of 1

The pass map from other starts. Of all 268 million lists of 1 to 28 ones, every one with an odd count meets a stop block of 1 or halts, and every such event comes by pass 59; the survivors of 60 passes survive 1,000. Every two-block start [a, b] with a ≥ 2, a, b ≤ 104 and 4 | a+b (the blank orbit's class) runs 1,000 passes without the event, and 5·106 random lists with an even count and blocks near 109 never meet it. The event needs a sweep to stop at a block of 3 in the first two places one pass earlier: [x, 3, z] with x ≡ 2, z ≡ 3 mod 4 meets it on its second pass, and on the machine itself such lists halt a few passes later. So the event belongs to small blocks, and the blank orbit's stop blocks grow with the tape.

No invariant of sizes or fixed residues

Small starts reach the stop block of 1 by a halving loop: a stop at the first of three blocks, then an even last block on four, repeated, halves the first block every two passes ([110, 63, 23] reaches it in 9 passes, every block but the last at least 23). So no lower bound on block sizes is kept by the pass map, and since each pass halves blocks, the route depends on ever higher bits: no set described by inequalities and residues modulo a fixed power of 2 is closed under the map and excludes the event. What keeps the orbit out of the loop is the 2-adic digits of its blocks.

An induction for the excursion

The excursion from [a, 2a+1] for every a (the orbit of G is a counter, so a statement for all a is what is needed). The route list is infinite because of the halving tail and the loops it nests, and the deep routes mix the bits of a, so a finite table or automaton will not do: this needs an inequality proved by induction on the tail length, that stop blocks stay above a fraction of a that shrinks slower than 1/a (observed: a/64 on every route to mod 274). With orbit_ok_upto (Lean: if every a below B returns, the first (3B+4)/4 passes are safe) and the reduction, that would prove the machine never halts; Lean's kernel now covers a < 262. Equivalently (halts_only_at_front), a lower bound above 1 on the first block along the orbit.
