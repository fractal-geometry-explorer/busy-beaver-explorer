A 6-state Busy Beaver machine · Status as of 8 November 2026.

Does this machine ever halt?

1RB0LD_0LB1RC_0RD---_1RE0RF_1LF0RA_0LA0LF

A six-state machine that counts in base 5. Its digits are little defects in a periodic tape; each sweep of the head adds one to the number; the digits drift across the tape, overflow, and now and then crash into each other. Nobody knows whether one of those crashes will stop it. No halt in the first 1017 steps.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in C reading 1. C is entered only from B1 (writes 1, moves R): B>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The shape of the run

Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

Macro structure

What the tape is made of

Stop the machine each time its head stands on the leftmost cell of the tape in state D (a sample configuration). The tape then always reads the same way: a long periodic background of the four-cell word W = 0001, interrupted by a few short defects, and closed on the right by a fixed wall 001 that hardly ever moves. The left end grows by three cells per sample.

Almost every defect is one of five words, which we call digits and give values:

digitcellsvalueafter the visitgaps
a00111b = 2one W fewer after it
b00110012c = 3—
c0011013d = 4—
d001114e = 0carry: the head goes on to the next digit
e001010a = 1one W moves from the gap after it to the gap before it

So the tape is 0 0 Wg0 X1 Wg1 X2 … Xk Wgk 0 0 1: a left gap of g0 copies of W, then digits, each followed by its own gap. A sixth defect, the single extra 0 (written z), is an empty digit; it appears when the counter overflows (below).

Macro structure

One visit is one increment

Between two sample configurations the head makes one visit: it runs right through the left gap (turning each 0001 into 1010 as it goes, 12 steps per W there and back), reaches the first digit, and acts on it. A d (value 4) becomes e (value 0) and the head runs on to the next digit: a carry. Any other digit takes one step up (a→b→c→d, e→a) and the head turns back, restoring the background on its way to the left end, where it adds three cells. Read with the first digit as the least significant, the digits are a base-5 counter, incremented once per visit.

The increment also moves the digits. a→b and e→a each take one W from the gap after the digit; e→a gives it to the gap before; every visit adds a W to the left gap. In cells, a digit moves 9 cells to the right per 5 increments, while the left end moves 3 cells left per visit. Digit i is incremented once every 5i visits, so the lowest digit runs right at about 1.8 cells per visit, the next at a fifth of that, and the high digits barely move: every digit slowly catches up with the next one.

Exactly: if the digits after the left gap are d…d X with X ≠ d and at least one W after X, the visit takes 12·g0 + 11 + ∑passed d(12·gi + 30) + 32 steps and gives the counter plus one with the gaps moved as above. Lean proves this for every list of digits and gaps and every tape beyond (visit in lean/Counter.lean); in the run it describes 99.990% of all visits.

Emergent behaviour

Digits are born, drift and collide

Every twelfth sample configuration of the first 30,000 visits, one row each, time going down; each defect is a dot at its distance from the right end of the tape. The black line is the left end, moving left; a line that starts on it is a digit born there.

Three things happen, and only three:

  • Drift. The lowest digit starts at the left end and runs right at about 1.8 cells per visit; higher digits crawl, the highest stand almost still near the wall.
  • Overflow. When every digit is d (the counter reads 44…4), the carry runs into the wall. All the d become empty digits z, the wall moves a few cells to the right, and a new digit is born at the left end. The counter gains a digit.
  • Collision. When the lowest digit reaches the next one (the gap between them runs out), the two stand side by side and the plain rule no longer applies. The gap runs out on an a→b or e→a step, so a collision starts as a or b next to any of the five digits. For a few increments the pair forms compound words; then it fuses into a single digit (the counter loses a digit and its value jumps), or it leaves a phase defect 001, and the next visit gives birth to a new lowest digit at the left end.

Overflows and collisions are rare: in the first 1013 steps they touch 260 of 2,631,785 visits. Between them the machine is a clean base-5 counter whose digits spread across a tape of width about the square root of the step count. That is the fixed/sqrt growth of the triage.

Where it could halt

A near miss inside some collisions

The machine halts only in state C reading a 1. It gets there only from state A reading 0 1: A writes a 1 and moves right, B reads that 1 and moves right in state C, and C halts on a 1 (in the usual case A>0 0, B steps back onto the new 1 and C then reads the 0). So it halts exactly when the head, in state A, finds 0 1 1. In the background and in every plain visit, A always finds 0 0.

A>0 1 does happen, but only inside a few kinds of collision (for example when two e meet), and there the next cell has always been a 0. In the first 1015 steps it happened 12 times, each time followed by 0. Configurations built by hand with crowded digits (several collisions at once, or compound words next to each other) do reach 0 1 1 and halt: 210 of 2,000 random tapes with gaps of 0 to 3 halted within 3·106 steps. So the question is whether the counter ever crowds its digits that badly. That depends on the exact gaps at the moment of each collision, which depend on the whole history of the counter.

Four machines, one counter

Where the four machines part ways

This machine and three others, 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_0LA---, 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_0LC---, 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_0RA---, run exactly the same counter: the same tape at every sample configuration, up to renaming the states. 1RB0LD_0LB1RC_0RD---_1RE0RF_1LF0RA_0LA0LF steps over each 0 0 in four steps where the other three take two (so 12 steps per W per visit against 10; 12 here), with the same result; the three others differ from each other only in what follows the near miss. So the four runs first part ways at the first 0 1 0 (step 49,361 for the first machine, 49,247 for the others), and again at every later one. The commonest case is two e side by side:

After that the four runs are different counters with the same rules, and they collide differently. Each one is open for the same reason.

What is proved

What is proved, and what is left

  • Lean, kernel: the nine piece rules of a visit for all counts (lean/Pieces.lean); visit: one visit is one base-5 increment with the gap moves above, for every configuration where the increment is defined (lean/Counter.lean); the merge of two adjacent e (lean/Merge.lean).
  • Lean, native_decide: the run from blank tape reaches a sample configuration of standard digits after 1,010,696 steps, and the counter rule alone then carries it 282 more visits (reach, counted in lean/Reach.lean).
  • Computed: an exact visit-level simulator (py/vsim.py, identical to the direct simulator on every sample configuration of the first 3·107 steps) finds no halt in the first 1017 steps (272,935,363 visits).
  • Open: the collisions. A proof of non-halting would need to show that the counter never brings its digits into a crowded collision that reads 0 1 1, which needs control of all the gaps at once.
