Does this machine ever halt?

1RB---_0RC0LD_1LB1RC_0LE0LF_1RD1LE_1RF1RA

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows. The tape is blocks of 1s separated by 0s, and the machine moves cells from block to block: a zigzag cuts a block to two thirds, a sweep shifts every 0 one cell left. Lean proves that this block arithmetic is all the machine does, and that it halts exactly if a zigzag ever leaves a block of 3 cells next to a block of 8.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in A reading 1. A is entered only from F1 (writes 1, moves R): F>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

What it does

Cutting a block to two thirds

Stop the machine each time the head is at the left end in state E. The tape is then a few long blocks of 1s, separated by single 0s, except that the first two blocks are separated by a double 0: at step 968,072,934 it is E>0 1^494 0 0 1^248 0 1^2831.

The next three such moments are E>0 1^330 0 0 1^413 0 1^2831, E>0 1^220 0 0 1 0 1^522 0 1^2831, and then, after a pass to the right end, a long first block again. Each time the first block went to two thirds of its length, rounded up (494 → 330 → 220), and the cells it lost (plus one) went to the block after the double 0. That rule, x → ⌈2x/3⌉, held in all 810 such steps of the first 109.

The cut is made by a zigzag. Between the single 0 inside the first block and the double 0, the head goes back and forth; each trip moves the single 0 two cells right, takes three cells from the stretch between them and gives one to the block beyond the double 0. A cut of a block of x cells takes about x/3 trips of length about x, so about x²/3 steps.

The other half

Merging at the right end

When the first block gets short, the head runs to the right end in state C and works on the last blocks: at step 968,216,616 the tape ends 0 1^522 0 1^2831 0 1 C>0, and by step 972,860,864 it ends 0 1^1682 0 1^1745 0 1 C>0. Long blocks are rebuilt there, and the next left-end visit starts a new run of cuts from a long first block (2,049 cells at step 976,608,441).

The machine halts only if D reads a 1 that has a 0 on its left and two 1s on its right; the zigzag always keeps 1s on D's left, so far.

What is proved

The machine as arithmetic on a list of blocks

Read the tape as blocks of 1s, each followed by one 0: 1^7 0 1^5 0 0 1^4 0 is the list 7, 5, 0, 4 (the double 0 is an empty block). Stop the machine only at four kinds of moments: E or C standing on a 0 between two blocks, B or F standing on the first cell of a block. Then the whole tape is two lists of numbers, the blocks left of the head (nearest first) and the blocks right of it.

From such a moment the machine always reaches another one, and the new lists are given by a short formula on the first one or two numbers of each list. For example, with E on a 0, i ones on its left and a block of m ≥ 2 ones on its right, the machine moves two cells of that block to the left block and stands in state C at the end of what remains: 1^i E>0 1^m 0 becomes 1^(i+2) 0 1^(m−2) C>0. With C after a block of a ≥ 3 ones, the 0 under the head moves one cell left and C runs on over the next block: 1^a C>0 1^r 0 becomes 1^(a−1) 0 1^(r+1) C>0. With C after a block of exactly one 1, the machine turns round and E runs back to the previous 0. There are 16 such cases. Lean proves each one for all block lengths and all surroundings (next_sound).

Three situations have no next frame: 0 1 1 C>0 1 (C after a block of exactly two 1s, and a 1 two cells ahead), 0 1 B>1 1 1 and F>1 1. In each the machine halts within 8 steps, and these are the only ways it can halt: Lean proves that the machine halts from blank tape if and only if the block map, started from the frame after the first step, ever reaches one of these three (halts_iff_critical). The first 108 frames, 3.0·1011 steps, do not.

The cut of the section above is three of the cases in a row; a sweep to the right is the second example repeated. Two of the three patterns are excluded for good by an invariant (next section); whether the third is ever reached is the open part.

What is proved

Where it could halt: only at the start of a sweep

Lean now proves an invariant of every frame after the first (lean/Invariant.lean, kernel only). In E frames the tape has exactly one double 0, and it sits right after the block next to the head: blk(L) E>0 1^m 0 0 blk(R'), with m ≥ 1 and no other empty block. In B frames the block left of the head has at least five 1s, and there is no empty block anywhere. No F frame is ever reached. Two of the three critical frames, 0 1 B>1 1 1 and F>1 1, are therefore impossible. The machine halts iff the block map reaches 0 1 1 C>0 1 (halts_iff_C), and it can never get there straight from an E frame (critical_after_BC).

The head reaches that frame only while it moves right through C frames, in a sweep. Each step of a sweep moves one block from the right list to the left list unchanged. The sweep stops at the first block of fewer than two 1s: a 0 turns the head round, and a 1 halts the machine unless it is the last block. A sweep starts at a B frame (or, once early in the run, at E L (1 :: 0 :: R)). lean/Sweep.lean proves that the machine halts iff some sweep start has a right list r₀, r₁, r₂, … with r₀ = 3 and r₁ ≥ 1, or with r₀ ≠ 2 and a block of exactly one 1, not the last block, before the first block of 0 (halts_iff_sweep).

At the left end the descent of cuts makes every value after the first one even. lean/Cuts.lean (cut_even) computes how such a descent ends when its last two blocks are 18u + 6 and then 12u + 4: at B [8u+7] (4u+1 :: …). The sweep then starts on 1, 5, 9, 13, … cells, never 3. A start on 3 needs an odd block of 15 at the beginning of a descent, which is the halts_of_15 event. Run the block map below and look at the first block of every sweep start. The small values cluster at 1 mod 4, and 2, 3, 4, 6 and 7 never occur.

Why no simple invariant closes the question: after the first 105 frames, blocks of fewer than 20 cells occur only among the leftmost five or six blocks, as the last block, or next to the head. Every other block is larger, and most have thousands of cells or more. The right end, though, sometimes shrinks its last block to about a third. An abstract model that keeps the small blocks at both ends exactly and lumps the others into "at least N" still reaches the critical frame (py/absint.py). Each path it finds needs several small blocks in a row next to each other, which the real run has not produced. Whether the run ever produces them is the lottery the community tracker describes.

What is proved

Where it could halt, exactly: a block of 3 next to a block of 8

lean/Pair.lean (kernel only) goes one step further and finds the single event behind every bad sweep start. In an E frame the tape is blk(L) E>0 1^m 0 0 1^j 0 blk(R). The zigzag works on the block of m cells. The block of j cells behind the double 0 is an accumulator: it collects one cell per trip. When m is down to 2, 3 or 4 cells, a 2 merges into the left neighbour and the zigzag goes on with the same accumulator. A 3 merges the same way, but leaves the accumulator behind for good and starts a new one of 1 cell. A 4 starts a sweep, with the accumulator as its first block r0.

A sweep that starts on r0 = 3 halts, and a new accumulator of 1 reaches exactly 3 at the end of a zigzag only from a block of 10: 10 → 7 → 4 while the accumulator goes 1 → 2 → 3. A block of 10 with a fresh accumulator is made by a 3 merging into a left neighbour of 8. Lean proves the converse too: an invariant (Inv4) says that every block has at least 2 cells except next to the head and at the right end, and that the accumulator is safe. That invariant holds at frame 4 and is broken only at that one event. So the machine halts iff a zigzag ever cuts a block down to exactly 3 cells while its left neighbour has exactly 8 (halts_iff_8). With the zigzag rule, a block of m cells with i cells on its left leads to a halt iff m is a multiple of 3 and i + 2m/3 = 10.

Frames from E (i :: 50 :: 50) (m :: 0 :: j :: 50 :: 50), nearest block first on each side, until the first sweep ends or a critical frame is reached.

So the question is whether two such small blocks are ever neighbours. Small blocks come from two places. One is the left-end descents, where a block is cut to two thirds again and again. The other is the last block at the right end, which a pass cuts to about a third. Run the block map below and watch the left neighbour each time a zigzag stops at 3 cells. Next to the left end, inside a descent, it is always 2 mod 4, because the descent values are even. It can be 8 there only when a descent starts on exactly 15. Everywhere else it is large.

Growth law

Why the width grows like t1/3

A cut costs the square of the block length over three, and a whole series of cuts (lengths x, 2x/3, 4x/9, …) costs about x²/3 · 1/(1 − 4/9) = 0.6·x² steps, of the order of the width squared, while the tape grows by only a few cells per series. That gives width3 ~ steps: 3,612 cells after 109 steps.

Kernel
next_sound, lean/Blocks.lean; pieces in lean/BPieces.lean (generated by py/blocks.py)
The block map

Write the tape as blocks of 1s, each followed by one 0 (a block may be empty, so 0 0 is an empty block). A frame is a state E, C, B or F and the lists of block lengths left and right of the head. The map next (16 cases, each a formula on the first one or two block lengths of each side) sends every frame to the next frame the machine reaches; this is proved for all block lists, each case by one symbolic run.

Kernel
next_none_iff, none_halts, init_start, halts_iff_critical, lean/Blocks.lean
It halts iff the block map reaches a critical frame

The block map is undefined exactly at three kinds of frames: C just after a block of exactly two 1s when the cell after the next is a 1 (0 1 1 C>0 1); B on a block of at least three 1s just after a block of exactly one 1 (0 1 B>1 1 1); F on a block of at least two 1s (F>1 1). From each the machine halts within 8 steps. The run from blank tape reaches the frame B [1] [] after one step, and the machine halts from blank tape if and only if the orbit of that frame under the block map reaches a critical frame.

Kernel
inv_next, inv_orbit, no_F, no_B_critical, halts_iff_C, critical_after_BC, lean/Invariant.lean
An invariant of every frame: two of the three critical frames are never reached

After the first frame, every E frame is E L (m :: 0 :: R') with m ≥ 1 and no other empty block (the tape blk(L) E>0 1^m 0 0 blk(R') has exactly one double 0); every C frame has at least two blocks on its left, the second not empty, and an empty block on its right only first; every B frame has at least five 1s left of the head and no empty block; and no F frame is ever reached. So the critical frames 0 1 B>1 1 1 and F>1 1 never occur, and the machine halts iff the block map reaches C (2 :: L) (r+1 :: R), never straight from an E frame.

Kernel
bad, bad_reaches, safe_step, halts_iff_sweep, lean/Sweep.lean
It halts iff some sweep to the right starts on a bad block list

While the head moves right through C frames, each step moves one block from the right list to the left list, until the first block of 0 or 1 cells: a 0 turns the head round, a 1 halts unless it is the last block. A sweep starts at a B frame (or at E L (1 :: 0 :: R)). The machine halts from blank tape iff the run reaches a sweep start whose right list r₀, r₁, … has r₀ = 3 and r₁ ≥ 1, or r₀ ≠ 2 and a block of exactly one 1, not the last, before the first block of 0.

Kernel
cut_even, lean/Cuts.lean
A descent at the left end that ends after an even cut starts its sweep on 4u+1 cells

E [] (18u+6 :: 0 :: j :: R) reaches B [8u+7] (4u+1 :: j+6u+1 :: R) in 30u + 7 frames. After the first cut every value of a left-end descent is even, so a descent whose last cut is from a block divisible by 3 hands the sweep a first block of 1, 5, 9, 13, … cells, never 3. Kernel
halts_iff_8, halts_iff_pat, inv4_next, inv4_total, pat_halts, lm_next, lean/Pair.lean
It halts iff a zigzag cuts a block to 3 cells next to a block of 8

The machine halts from blank tape iff the block map reaches E L (3 :: 0 :: j :: R) with a block of exactly 8 cells first in L: a zigzag has cut the block next to the head down to 3 cells while its left neighbour has 8. From there the critical frame 0 1 1 C>0 1 follows in 11 frames, for all L, j ≥ 1 and R. The converse is an invariant of the block map, kept by every frame except that one: every block has at least 2 cells except next to the head and the last block, the block behind the double 0 (which collects one cell per trip of the zigzag) never ends a zigzag at 3 against a block of 4, and the leftmost block of the tape is never 3. With the zigzag rule, a block of m cells with i on its left leads to a halt iff m is a multiple of 3 and i + 2m/3 = 10.

Kernel
cases nextE (m+2), nextC (a+3), nextC (1) of lean/Blocks.lean
How the cut is made

In the block map the cut is three cases in a row: E (i :: L) (m :: 0 :: j :: R) goes to C (m−2 :: i+2 :: L) (0 :: j :: R), to C (1 :: m−3 :: i+2 :: L) (j :: R) and to E (i+2 :: L) (m−3 :: 0 :: j+1 :: R) (for m ≥ 5): the block left of the head gains 2 cells, the block being cut loses 3, the block behind the double 0 gains 1. Each of the three cases is proved, and so is their composition over a whole cut (zig, below).

Kernel
zig, zig1_end, lean/Series.lean
A whole zigzag in one rule

From E (i :: L) (m+2+3t :: 0 :: j :: R) the block map reaches E (i+2t :: L) (m+2 :: 0 :: j+t :: R) after 3t frames, for every t: the block being cut loses 3t cells, the block on its left gains 2t, the block behind the double 0 gains t. At the left end of the tape the first trip is special (zig1_end).

Kernel
halts_of_15, critical_15, critical_mid, lean/Series.lean
Cutting a block of exactly 15 cells at the left end halts

If the run from blank tape ever reaches E [] (15 :: 0 :: j :: R), the machine halts: 23 frames later the frame is critical. The same happens away from the left end for a block of 9 with 4 cells on its left, 12 with 2, and 6 with 6 (critical_mid, stated for the block map from those frames). None of these frames has been seen in the run.

Kernel
never_halts_of_2, never_halts_of_3, loop_2, lean/Series.lean
Cutting a block of exactly 2 or 3 cells at the left end never halts

From E [] (2 :: 0 :: j :: R) two frames lead to E [] (2 :: 0 :: j+1 :: R), forever; a block of 3 becomes a block of 2 in two frames. So if the run from blank tape ever reaches one of these frames, the machine does not halt. Neither frame has been seen in the run.

Heuristic
c/series.c built with -DSTATS: ./series 60000000000; c/mc.c: ./mc 3000000 2000 100 4
Observed: how the left end is cut

At the left end a block of m cells is cut to 2(m+1)/3 or 2m/3 cells, again and again, until m ≡ 1 mod 3, when the head leaves to the right. After the first cut the values are even, so 15 can only be the first value of such a descent. In 6·1010 steps of the C program (1.3·1010 ones) descents reach a block of at most 20 cells about five times per doubling of the tape, with no sign of dying out: the values cut were 4, 6, …, 20 (15 to 25 times each) and 7, 9, 19 once each, early in the run. In 2,000 restarts from the tape at 647,185 ones with every block of 100 cells or more changed by a random 0 to 99 cells, each run until the tape had grown fourfold, none reached a critical frame or the loop; random small tapes halt often. This suggests the non-halting is structural, but no invariant is known.

Heuristic
py/absint.py 30 8 8 START
No finite pattern invariant of the two ends closes

After the first 105 frames, blocks below 20 cells occur only among the leftmost five or six blocks, as the last block, or next to the head. An abstract block map that keeps up to 8 blocks at each end exactly, values below T exactly and larger ones as "at least k", started from the real frame 108, still reaches the critical frame. Each path it finds makes the last block small and then several small blocks next to each other, which the real run has not produced. What keeps the blocks large is their size, which such a model cannot hold.

Does it halt from blank tape?

Not known. It halts iff a zigzag ever cuts a block down to exactly 3 cells while the block on its left has exactly 8 (lean/Pair.lean), which needs two small blocks next to each other. Small blocks come only from the left-end descents and from the last block at the right end, and the run has never put one next to the other or next to a second small block away from the left end. At the left end the pattern needs a descent that starts on exactly 15 cells; a descent starting on 2 or 3 would instead never halt. Neither has happened while the tape grew to 5.3·1010 ones. No invariant is known that keeps the small blocks apart; the community tracker lists the machine as a "lottery".
