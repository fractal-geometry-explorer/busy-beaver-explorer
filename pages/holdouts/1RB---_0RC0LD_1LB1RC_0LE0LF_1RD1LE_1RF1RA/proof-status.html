1RB---_0RC0LD_1LB1RC_0LE0LF_1RD1LE_1RF1RA

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state machine halts from blank tape. The tape is almost all 1s: blocks separated by single 0s, plus one double 0 near the left end. At the left end a zigzag cuts the first block down to two thirds of its length, over and over, a little like writing a number in base 3/2; at the right end the machine merges blocks back together.

Status as of 12 November 2026.

In short

The question is open, but it is now an exact arithmetic question. Lean proves (kernel only) that the machine is a rewriting system on lists of block lengths, the block map, with 16 cases, and that it halts from blank tape if and only if the block map reaches one of three critical frames: 0 1 1 C>0 1, 0 1 B>1 1 1 or F>1 1. By native_decide none of the first 108 frames is critical (3.0·1011 machine steps). Whether a critical frame is ever reached is not known.

The block map

Write the tape as blocks of 1s, each followed by one 0 (a block may be empty, so 0 0 is an empty block). A frame is a state E, C, B or F and the lists of block lengths left and right of the head. The map next (16 cases, each a formula on the first one or two block lengths of each side) sends every frame to the next frame the machine reaches; this is proved for all block lists, each case by one symbolic run.

next_sound, lean/Blocks.lean; pieces in lean/BPieces.lean (generated by py/blocks.py)

It halts iff the block map reaches a critical frame

The block map is undefined exactly at three kinds of frames: C just after a block of exactly two 1s when the cell after the next is a 1 (0 1 1 C>0 1); B on a block of at least three 1s just after a block of exactly one 1 (0 1 B>1 1 1); F on a block of at least two 1s (F>1 1). From each the machine halts within 8 steps. The run from blank tape reaches the frame B [1] [] after one step, and the machine halts from blank tape if and only if the orbit of that frame under the block map reaches a critical frame.

next_none_iff, none_halts, init_start, halts_iff_critical, lean/Blocks.lean

How the cut is made

In the block map the cut is three cases in a row: E (i :: L) (m :: 0 :: j :: R) goes to C (m−2 :: i+2 :: L) (0 :: j :: R), to C (1 :: m−3 :: i+2 :: L) (j :: R) and to E (i+2 :: L) (m−3 :: 0 :: j+1 :: R) (for m ≥ 5): the block left of the head gains 2 cells, the block being cut loses 3, the block behind the double 0 gains 1. Each of the three cases is proved; their composition over a whole cut is not stated as one theorem.

The splitting step

Each time the head is at the left end in state E on a 0, the tape starts E>0 1^x 0 0 1^y …. In the first 109 steps, 810 of the 1,241 consecutive pairs of such moments are a splitting step: the next one is E>0 1^x' 0 0 1^y' … with x' = ⌈2x/3⌉ and y' = y + (x − x') + 1 (the new second block sometimes written 1 0 1^(y'−2)), the rest of the tape unchanged. The others come after a pass at the right end.

tools/c/tmrun.c (at E L), py/splits.py

Does it halt from blank tape?

Not known. It halts iff the block map ever reaches one of the three critical frames. In the frames seen, C stands after a block of two 1s only with an empty block ahead, B after a block of one 1 only on a block of one or two 1s, but no invariant is known that forces this. The community tracker lists the machine as a "lottery": each round has a small chance of hitting a critical frame.
