Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. Its run is a nested binary counter: a block of 1s at the left end grows by two cells per event, each event taking twice as long as the one before, until it outgrows the block next to it; then a reset rebuilds the list of blocks and the counter starts over, about twice as long. This page lists what has been established, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. The counter (the part of the run that takes nearly all the time) is proved in Lean for all parameter values; the resets are not. An exact accelerated simulator, checked against the direct one for the first 2·109 steps, follows the run through 6 resets, to about 1075 steps, without a halt. Halting would need the head in state B on 0 1 0, which no counter step can produce; whether a reset ever produces it is the open question.

Five basic rules

With K(n, c) the tape B>0 1^(2n+1) 0 1^c right of the head: P: B>0 1^(2i+5) 0 1^(c+1) → 0 1 1 0^(2i) B>0 1^3 0 1^c (2i+11 steps); M1: 0 0 B>0 1^3 0 1^(c+1) → B>0 1^5 0 1^(c+1) (18 steps); and the three pieces X0, Y, Z of the collapse of a stack of frames 0 1 1. For all values of i, c, s and every tape around them.

ruleP, ruleM1, ruleX0, ruleY, ruleZ, lean/Base.lean (written by bbtools.symtm.prove; the same rules and step counts as the sibling, with D in place of E)

The recursive counter step, for every k

For every k ≥ 1, r ≥ 0, c ≥ k and all tapes L, R: L 0 0 (0 1 1)^r B>0 1^(2k+1) 0 1^c R reaches L B>0 1^(2(r+k+1)+1) 0 1^(c+r) R. With r = 0 this is the counter step M_k: 0 0 B>0 1^(2k+1) 0 1^c → B>0 1^(2k+3) 0 1^c, two cells further left. Proved by strong induction on k: M_k is P, then M_1, …, M_(k−2), then G(1, k−1).

rule_G, rule_M, chain, lean/Recursion.lean

Where it can halt

The only halting transition is F on 0, and F is entered only from C on 1, and C only from B on 0: the machine halts exactly when the head is in B on 0 1 0, that is at K(0, ·), a block of a single 1. Both directions are proved in Lean by enumerating the cells the head reads: a configuration halts two steps later if and only if it is B> 0 1 0 (halt_iff_2), so a halting run from blank passes through it (halts_blank_pred_2). Every counter step reads blocks of 3 or more.

Why halting looks unlikely

Halting can only happen inside a reset, and resets get rare very fast: the first block of the list roughly doubles at each reset (5, 23, 51, 115, 235, 489), so the n-th reset comes after about 22n steps. A probabilistic model with a fixed chance per reset would still give a positive chance of halting; nothing here rules it out.
