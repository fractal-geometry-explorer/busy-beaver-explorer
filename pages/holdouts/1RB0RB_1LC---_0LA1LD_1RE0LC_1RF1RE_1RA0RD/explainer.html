The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in B reading 1. B is entered only from A0 (writes 1, moves R): A>0 1; A1 (writes 0, moves R): A>1 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

The run at a glance

Space-time diagram and records

The diagram stacks the tape at many moments. Sampling at each new cell shows the shape of the run as the visited region grows; sampling evenly in time shows where the head spends its time. The records list every step at which the head reaches a cell no earlier step reached, with the side, the width so far and the whole tape: the first place to look for a repeating macro structure.

What the tape looks like

A string of digits that keeps being rewritten

Each time the head is at the left end in state D, the tape consists of runs of 1s separated by single 0s, and the runs alternate between length 1 and a length of the form 4j + 1. Here are the first run lengths at step 28,947,103 (tape width 8,068):

1 1 1 5 1 5 1 9 1 5 1 1 1 1 1 5 1 9 1 9 1 5 1 1 1 9 1 5 1 5 1 5 1 5 1 1 1 1 1 5 1 9 1 5 …

Read as digits j this is 0 1 1 2 1 0 0 1 2 2 1 0 2 1 1 1 1 0 0 1 2 1 …. One round trip later the string is completely different and shows no regularity.

How a pass works

Local rewritings, proved

The passes themselves are simple. Going left, state C turns each pair 11 into 01 (halving the ones); going right, state D turns each 0101 into 1110, state E turns each 0101 into 1011 and crosses runs of 1 unchanged. These four rules are proved in Lean for every length. What happens where one rule hands over to another, at the boundaries between runs, is what scrambles the digits.

Can it halt?

Only through a double 0

The only halt is B reading a 1. B always follows A, and A follows either C reading a 0 (then B reads the 0 C has just written: safe) or F reading a 0, which happens only when E reads a 0 with another 0 right after it. Inside the tape this has never happened: in 2·108 steps every 0 that E read inside the tape had a 1 after it. All 44 visits of F to a 0 in 1010 steps were at the blank right end. So the machine halts if and only if, at some point, a double 0 followed two cells later by a 1 appears ahead of a right-moving E inside the tape. Whether the rewriting can produce one is not known.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.507). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.072).

After 109 steps the tape spans 47,743 cells (38,175 left of the start, 176 right), with a density of 1s of 0.796.

Where a halt can come from

If the machine halts on its third step from a configuration, that configuration is one of: F with 0 under the head, 1 two right. So a run can reach a halt only through one of these patterns, and a proof that the machine never halts only has to rule them out. The proof splits on the state and the five cells around the head.

tools/c/tm.h (transition counts and windows)
Where a halt would have to come from

The halt is B reading a 1. B is entered only from A, which comes either from C reading 0 (then B reads the 0 that C wrote) or from F reading 0, which needs E to read 0 with a 0 next to it. In the first 2·108 steps E read a 0 about 12.5 million times; inside the tape the next cell was always 1, and the 44 times F read a 0 in 1010 steps were all at the blank right end, where B then reads blank tape.

Heuristic
tools/c/tokrun.c
A digit string

With the head in D at the left end, the tape reads as runs of 1 separated by single 0s, alternating 1 and 4j + 1 (j = 0, 1, 2, …; seen up to j = 8): a string of digits j. The string changes completely from one round trip to the next with no visible pattern, while the tape grows by about 2 cells per round trip on the left (square root of the steps) and very slowly on the right.

Open
Does it halt?

Not known, and not reduced to a number question: the digit string is not decoded. The halting question is whether a pair 00 can ever form inside the tape ahead of a right-moving E.

sweeps of 13 November 2026 (family F11); the tagged and run-length deciders are not in the repository yet
Regular-language deciders tried (F11)

None of these closes: each reaches a halting configuration in its abstraction, which says nothing about whether the machine halts. n-gram CPS (tools/c/ngramcps.c), equal widths on both sides: a halting local configuration is reached with plain up to width 18, history 1 up to width 20, history 2 up to width 16, history 3 up to width 15, LRU history up to width 3 (larger widths ran out of the 150 s or 60 million configuration budget). n-gram CPS with every cell tagged by its position mod p: fails for p = 2 up to width 16, p = 3 up to width 16, p = 4 up to width 16, p = 6 up to width 16. n-gram CPS where each side also carries the state of a small automaton that has read that side from the far end (every automaton with up to 3 states on both sides, or 4 states on one side), with position mod 1..4 and widths 4, 6, 8: no closed set without a halt in all 120 parameter sets. Run-length windows (the K nearest runs of equal macro cells on each side, run lengths kept exactly below T and mod M above): fails for all 72 parameter sets (cells of 1 to 4 bits, K = 2, 4, 6, T = 2, 4, M = 1, 2, 4). Two-automaton closed tape language by SAT (a deterministic automaton reading each side inward, n states each, CaDiCaL): no solution for n = 2..8; n = 9 not finished in 150 s.
