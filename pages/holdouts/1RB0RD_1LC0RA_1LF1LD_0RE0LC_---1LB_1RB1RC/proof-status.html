What is known about 1RB0RD_1LC0RA_1LF1LD_0RE0LC_---1LB_1RB1RC

1RB0RD_1LC0RA_1LF1LD_0RE0LC_---1LB_1RB1RC

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open, but it is now reduced in Lean to one configuration about 1.96·1020 steps in. The machine is a counter ticked once per round trip across a growing wall, and the tick is a carry automaton on the counter's digits; both facts are proved for every wall and every digit string. A certificate checked by compiled Lean code shows that the first 8,072,508,823 sweeps after step 30,225 all stop inside the digits. The next sweep runs off the end without halting and turns the whole wall into pairs 11. So the machine halts from blank tape exactly when it halts from that configuration, C> 1 (11)^8072508832 R1.

The wall's round trip

From D leaving the counter, 0^inf (10)^n D> 1 R, the head crosses the wall, adds one pair at the blank end and comes back: 0^inf (10)^(n+1) A> 0 R after 6n + 4 steps, for every n and every tape R. Built from the three pieces wall_right, wall_left, left_end.

round, lean/Rules.lean

A whole sweep that sets x1

When the counter's first digit x1 is 0: 0^inf (10)^n 1 0 A> 1 1 0 1 R reaches 0^inf (10)^(n+2) A> 1 1 1 1 R in 6n + 18 steps: x1 becomes 1, the wall grows by one pair, and A is back at x0.

toggle, sweep_toggle, lean/Rules.lean

The carry's zigzag

Over a stretch of ones the carry moves right three cells per 7 steps: L 1 0 0 D> (111)^n R reaches L (110)^n 1 0 0 D> R.

zig, lean/Rules.lean

A sweep is one step of the carry automaton, for every digit string

An arrival 0^inf (10)^(n+1) A> 1 1 x1 1 ... xk 1 R reaches 0^inf (10)^(n+2) A> 1 1 y1 1 ... yk 1 R whenever the automaton (a: 0→1 stop, 1→0 b; b: 0→1 a, 1→0 c; c: 0→0 c, 1→1 a) stops inside the digits and turns xs into ys. This holds for every n, every digit string and every tape R. The proof is by induction over the digits, chaining symtm rules for each state and digit on the way right and each pending pair on the way back.

sweep, run, lean/Sweep.lean; rules in lean/Rules.lean

Halting only at end events

If no sweep ever runs off the end of the digits, the machine never halts from that arrival. Along any number of sweeps that stop inside the digits, halting is unchanged.

not_halts_arrival, halts_arrival_iff, lean/Event.lean

8,072,508,823 sweeps without reaching the end

The automaton becomes a transducer on words of generators, and ak is kept as a straight-line program of 6,010 nodes. The checker's soundness is proved in Lean, and the certificate of 7,351 entries is checked by compiled code. The result: all 8,072,508,823 sweeps after the first arrival stop inside the digits, ending with the digits Y0.

The first end event does not halt; halting reduces to one configuration

The next sweep runs into the last cell in state b and passes it without halting. It then comes back across the whole wall, turning each pair 10 into 11, and reaches post n = C> 1 (11)^n R1; the kernel checks this for every wall n. Together with the claims above: the machine reaches post 8072508832 from blank tape, about 1.96·1020 steps in, and it halts from blank tape if and only if it halts from there.

The automaton permutes digit strings

Digit i of a sweep's result depends only on digits 1..i, and on the strings of each length up to 12 the automaton is a bijection whose cycles all have power-of-two lengths: an odometer-like map. Deep carries are rare: the first sweeps reaching x40, x70, x100 come 1,635, 402,291 and 69,230,963 sweeps after step 2·107.

py/automaton.py, c/counter.c

After the first end event

The counter runs on with the same automaton on the n + 111 digits, now on the other parity of cells, and a new wall grows from the left end. This was simulated from that counter with walls of 1 to 33 pairs.

py/automaton.py

Which end events halt

An end event is a carry that runs into the last cell; the outcome depends on the state the carry is in after that cell. With the last cell a digit (as from blank tape): a halts, c turns the wall into 11s (the first event), and b goes back in the normal mode. This was checked on 20,000 random carry paths of up to 40 digits. With the last cell a 1 (as after the first event), b halts; this was checked on counters of k ones with walls of 3 to 6 pairs.

The next end event is beyond simulation

The second end event needs a carry through all n + 111 digits, n ≈ 8·109, most of them ones. Simulation cannot reach it. Which state it arrives in is a question about the automaton group generated by a = (e, b)σ, b = (a, c)σ, c = (c, a); the straight-line programs of py/slp.py might reach it if the number of sweeps can be found.

Does it halt from blank tape?

Not known. It halts if and only if it halts from post 8072508832, the configuration right after the first end event, which does not halt.
