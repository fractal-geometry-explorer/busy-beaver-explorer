Does this machine ever halt?

1RB0RD_1LC0RA_1LF1LD_0RE0LC_---1LB_1RB1RC

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows yet, but we know exactly what it is doing. This machine is a counter: a stretch of digits at the right end of the tape, ticked once every time the head makes a round trip across a long, growing wall of 10s. The tick is a carry, like adding one, but in a strange number system with three carry states. Whether the machine halts is decided at the rare moments when a carry runs through every digit: Lean proves what each such moment does, and one kind of moment halts.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in E reading 0. E is entered only from D0 (writes 0, moves R): D>0 0. So a halt is the moment this pattern appears, with the head on the cell after >.

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.491). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

After 109 steps the tape spans 36,723 cells (26,953 left of the start, 9 right), with a density of 1s of 0.501.

Macro structure

A wall and a counter

After the first 40,000 steps the tape has two parts. On the left is a wall: n copies of 10. On the right, fixed in place, is a counter of 221 cells: a digit on every even cell and a 1 on every odd cell, x0 1 x1 1 x2 1 ... x110, with x0 = 1.

The head bounces. State A runs right across the wall (two steps per pair), does some work in the counter, then D, C and F run back left (four steps per pair). At the blank end the wall gains a pair and A turns back. A round trip costs 6n + 4 steps, proved in Lean for every n (round). Because the wall gains one pair per trip, N trips take about 3N2 steps: the left end of the tape grows like the square root of the time, while the right end, the counter, stays put.

The tick

Each trip adds one, in a strange number system

Each time A arrives at the counter, the digits x1, x2, ... change by a carry rule. It is a finite automaton that reads the digits from x1 rightwards, rewriting each one:

carry statedigit 0digit 1
a (start)write 1, stopwrite 0, go on in b
bwrite 1, go on in awrite 0, go on in c
cwrite 0, go on in cwrite 1, go on in a

State a alone would be ordinary binary counting: flip trailing 1s to 0 until a 0 becomes 1. States b and c make the carry travel further and in a more tangled way. The rule was read off the machine and checked against it on every trip of the first three million steps.

It behaves like an odometer: digit i of the result depends only on digits 1 to i, and on strings of any fixed length the rule is a permutation whose cycles have lengths 1, 2, 4, 8, ... So the low digits cycle quickly and the carry reaches deep digits only rarely: x40 first changes 1,635 trips after step 2·107, x70 after 402,291 trips, x100 after 69 million.

The question

What happens when the carry runs through every digit

The counter has 110 digits; beyond x110 the tape is blank. Each sweep starts the carry at x1, so to know when the carry first reaches the end you have to iterate the automaton about 8·109 times. That is a minute of plain computation. It can also be done exactly in a fraction of a second: write the automaton's states as group elements (a = (e, b)σ, b = (a, c)σ, c = (c, a)) and keep the huge power ak as a straight-line program, a table of a few thousand pieces each made of two earlier ones. Lean checks a certificate for that table. The first 8,072,508,823 sweeps after step 30,225 all stop inside the digits.

The next sweep, starting from a wall of 8,072,508,833 pairs about 1.96·1020 steps in, runs through all the digits and reads the last cell in state b. What happens at such a moment depends only on the carry's state and on the last cell, and Lean proves each case for every length of wall and every digit string:

carry state at the last celllast cell 0last cell 1

bhaltsthe wall becomes digits
cthe wall becomes digitshalts

From blank tape the first such moment is state b on a 1. The machine does not halt. It writes one new cell, and on its way back, one cell out of step, it turns every separator into a digit and every pair 10 of the wall into 11. The old wall has become eight billion new counter digits, all ones, followed by a 0 and by marks that record where the last carry was in state c. A new wall of one pair starts at the left end.

Every case leaves a counter of the same shape, so the table is the whole story: the machine halts from blank tape exactly when this little system of events reaches a halting entry (blank_halts_iff_events, checked by Lean's kernel alone).

What is not known is which entry comes next. The first sweep after the conversion runs straight through the eight billion ones, leaving 001 repeated, and then the carry has to work its way through all of that again. On small stand-ins for the wall the wait doubles about every three digits, so the real second event is of the order of 22.5·109 sweeps away. With stand-in walls of 1 to 30 pairs, 7 runs end in a halt and 23 in a second conversion (observed, not proved), with no pattern that would tell us the answer for the real wall.

The table above is the whole machine, so it can be played as a game on three things: the wall, the digits and the last cell. Each sweep starts the carry at the first digit. Kernel
sweep, run, lean/Sweep.lean; rules in lean/Rules.lean
A sweep is one step of the carry automaton, for every digit string

An arrival 0^inf (10)^(n+1) A> 1 1 x1 1 ... xk 1 R reaches 0^inf (10)^(n+2) A> 1 1 y1 1 ... yk 1 R whenever the automaton (a: 0→1 stop, 1→0 b; b: 0→1 a, 1→0 c; c: 0→0 c, 1→1 a) stops inside the digits and turns xs into ys. This holds for every n, every digit string and every tape R. The proof is by induction over the digits, chaining symtm rules for each state and digit on the way right and each pending pair on the way back.

If no sweep ever runs off the end of the digits, the machine never halts from that arrival. Along any number of sweeps that stop inside the digits, halting is unchanged.

Computed
py/automaton.py, c/counter.c
The automaton permutes digit strings

Digit i of a sweep's result depends only on digits 1..i, and on the strings of each length up to 12 the automaton is a bijection whose cycles all have power-of-two lengths: an odometer-like map. Deep carries are rare: the first sweeps reaching x40, x70, x100 come 1,635, 402,291 and 69,230,963 sweeps after step 2·107.

event, reaches_post, halts_iff_post, lean/Event.lean
The first end event does not halt; halting reduces to one configuration

The next sweep runs into the last cell in state b and passes it without halting. It then comes back across the whole wall, turning each pair 10 into 11, and reaches post n = C> 1 (11)^n R1; the kernel checks this for every wall n. Together with the claims above: the machine reaches post 8072508832 from blank tape, about 1.96·1020 steps in, and it halts from blank tape if and only if it halts from there.

Kernel
last_stop_event, ext_event, halt_event_b, halt_event_c, conv_event_b, conv_event_c, lean/Ends.lean
Every end event, for every counter

The counter is the digits x1..xk, each followed by a separator 1, then a last cell d with blank tape after it. When the carry runs through all the digits and reads d: in state a, d = 0 becomes 1, and d = 1 gives the counter one more digit; in state b on 0 or state c on 1 the machine halts; in state b on 1 or state c on 0 the pass back runs one cell out of step and turns the wall of n + 1 pairs into digits, leaving a wall of one pair and the digits 1n 0 marks 1, where the marks are 1 after each digit that left the carry in state c. Each case holds for every wall and every digit string, and each leaves a counter of the same shape.

Kernel
halts_iff_events, blank_halts_iff_events, lean/Ends.lean
The machine is the event system

evstep is one sweep as a map on (wall, digits, last cell), with no value when the sweep halts. From any arrival of this shape the machine halts if and only if iterating evstep reaches a halting event; from blank tape, if and only if it does so from a wall of 10 pairs, the 109 digits X0 and last cell 1.

The first end event of the run from blank tape is a conversion (state b on the last cell 1). The machine reaches the arrival with a wall of one pair and a counter of 8,072,508,943 digits: 8,072,508,832 ones, a 0, the 109 marks of the last carry and a 1. It halts from blank tape if and only if the event system halts from there. The certificate of the 8·109 sweeps before the event is checked by compiled code; the event itself by the kernel.

README.md, py/events.py
The next end event is beyond simulation

After the conversion the first sweep runs through the 8·109 ones and leaves the counter starting with 001 repeated 2.7·109 times. On the stand-in runs the number of sweeps to the next end event doubles about every 3 digits, which puts the real one at the order of 22.5·109 sweeps. Which state the carry is in then is a question about the automaton group generated by a = (e, b)σ, b = (a, c)σ, c = (c, a) on an almost periodic string.

Does it halt from blank tape?

Not known. It halts if and only if the event system reaches a halting event from the counter after the first end event. That needs the carry to read the last cell in state b on a 0 or in state c on a 1.
