What is known about 1RB0LE_1RC0LB_1RD1RF_1RE0RB_1LA0RD_0RE---

1RB0LE_1RC0LB_1RD1RF_1RE0RB_1LA0RD_0RE---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. The tape is a row of blocks (10)n separated by S = 01100, with one defect (a single 0 or 1 in place of an S). Every time the head reaches a new cell at the right end (an E-record) one sweep has run left to the defect and back. Lean proves (kernel) the four generic sweep rules, for every block size and every tape left of the defect, and that the run from blank tape reaches such a record. A Python macro simulator built from symbolic one-sweep runs, checked tape for tape against direct simulation, runs 5.69·106 sweeps (2.96·1013 steps) without a halt. With native_decide: no halt in the first 107 steps.

Other proofs and outside reports

In the community's BB(6) tracker the machine's class is Chaotic Bell Class 3. These are labels read off the run by others, not results.

The cell gadgets

The leftward signal crosses a block (10)^n A>1 in 2n steps (across) and a separator S in 21 steps, leaving (10)^2 1 on its right (sgad); it turns at a defect 1 (2Y + 4 steps, turn1) or at a defect 0 after a block of at least 2 (2Y + 16 steps, turn0); D, going right, turns each (10)^(w+2) 1 into S (10)^w (2w + 5 steps, dunit). Written by bbtools.symtm.prove, for all sizes and all surrounding tapes.

lean/Gadgets.lean, lean/Macro.lean

The generic sweep rules

For an E-record T d y S w1 S … S wr S z 1 E>0, any r, any tape T: defect 1 becomes 0, y + 3, z − 2 (record_d1, 4z + 4y + 40 + Σ(4w + 26) steps, rcost_eq); defect 0 after a block x + 2: x − 2, defect 1, y + 5, z − 2 (record_d0, 12 steps more); the same for a zone of one block (record1_d1: z + 1; record1_d0: x − 2, z + 3). Each sweep passes over the whole zone and lengthens the tape by two cells.

apass, dpass, record_d1, record_d0, record1_d1, record1_d0, lean/Macro.lean

The macro simulator agrees with the machine

py/mac15b.py takes each sweep from a symbolic run (bbtools.symtm) on a window around the defect and the zone, with the middle of the zone abstracted and paid by the generic cost; all 891 window rules met are cached. It reproduces the whole tape and the step count at every E-record of the first 2·108 steps (12,384 from its start record at step 3513) (py/cmpm.py against c/erec.c), and the sample records up to 4.09·109 steps (py/verify_e27k.py). The run-length version py/mac15c.py agrees on 12,014 of them (py/test15c.py). About 80% of the sweeps follow the four generic rules; the rest are events at the end of the zone, at the left edge or when the defect moves.

Why it does not halt soon

The machine can only stop with D>1 0 1 1 on the tape, which within a sweep means a turn at the defect with the first right block Y ≤ 1. In a zone of two or more blocks Y = y + 2 ≥ 2, so the generic rules never halt; in a zone of one block Y = z, and in the runs z only comes back as 2 after an event and then grows. No reachable window rule halts. The block sizes settle into values 4k − 2 (2, 14, 62, 254, …), each made by the n → 4n + 6 growth of a block as the defect passes, so the tape behaves like a counter whose digits are blocks; nothing in it is seen to drift toward a halting turn.

Does it halt from blank tape?

Not known. A proof would need a closed set of macro configurations covering the events (the end of the zone running out, the defect reaching a frozen separator or the left edge), with the generic rules already in Lean.
