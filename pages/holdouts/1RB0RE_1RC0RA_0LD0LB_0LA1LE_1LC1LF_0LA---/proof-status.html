1RB0RE_1RC0RA_0LD0LB_0LA1LE_1LC1LF_0LA---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 9 November 2026.

In short

The question is open. The run is an exact pass map: sampled at the left end, the tape is a counter and a list of blocks (10)^m, and each pass changes it only at the counter and at one frontier, by about a dozen rules with exact step counts. The map is checked pass by pass to 1.1·109 steps, and an accelerated simulator built on it goes to 7.9·1010 steps. Lean proves the main rule (a block grows by 4 while the next one shrinks) for every list of blocks. The other rules are not yet proved, and the long-term behaviour of the list is not known.

The block-growing pass, for every list

With S = 1 1 1 0 1, blk n = (10)^(n+3) S and front p q = (10)^(p+3) 1 (10)^(q+3) 1 1 1 0: for every c, p, q, every list of blocks m1..mk and every tape R, 0^inf A> 1 0 0 blk(c+1) blk(m1)...blk(mk) front(p, q+1) R reaches 0^inf A> 1 0 0 blk(c) blk(m1)...blk(mk) front(p+4, q) R. This is rule c of the pass map. The proof is by induction over the list.

The pass map

Sampled at each arrival at the left end in state A, the tape is a 0 a^c and a list of pairs 1^k a^n (a = 10). One pass changes only the counter c and the first place where the list stops alternating separators (2,1) and blocks (1,m). The rules (counter phase, block grows, next block, carry, timer, rebuild, and a few rare ones) come with step formulas such as 6c+20F+6M+6p+56. Replaying every one of the 16,064 passes from step 440 to step 1,099,824,330 gives the plain machine's tape and step count exactly. The rare rules h, i and f2 are checked on the tape only.

No halt in the first 7.9·1010 steps

The accelerated simulator py/accsim.py applies runs of identical passes at once, with exact step counts. It agrees with the plain machine (state and step) at all 72 batch ends up to step 2,782,338,426 and in windows of plain simulation at steps 4.89·1010 and 5.29·1010. It runs to step 79,277,382,450 (164,003 passes, 13 rebuilds) without a halt, and stops there at a case its rules do not cover.

py/accsim.py run

Rebuilds

When the counter runs out, the first block becomes the next counter. The counter blocks of the 13 rebuilds are 6, 10, 18, 66, 130, 258, 1026, 4098, 16386, 258, 3078, 3364 and 16590. A block grows by 4 per pass while the frontier eats its neighbour, so sizes 4k+2 appear. A frontier that is still open at a rebuild stays in the list as a bare block or a frozen carry.

py/accsim.py, README

heuristic Evidence only

Why it is hard

Each rule is local and simple, but the counter at each round is set by the first block, and the frontier freezes wherever the counter runs out. That leaves new kinds of items in the list (a bare block, a frozen carry). A proof needs a finite set of item kinds that the map preserves, and the run keeps finding new combinations (the latest at step 79,277,382,450).
