What is known about 1RB0LC_0LC1RF_1LE1RD_0RC1RC_0LA1LA_---1RA

1RB0LC_0LC1RF_1LE1RD_0RC1RC_0LA1LA_---1RA

Open: a cryptidIts halting is thought to come down to a Collatz-like question that no known method decides (the community's label, not a result).

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 22 November 2026.

In short

Open, and probably never halting. From step 118 the run is the orbit of an explicit map on two numbers, U(a, b) and V(a, b). Lean's kernel proves the machine halts if and only if that orbit meets an event with a and b both even and b − a equal to 4 or −2 (halts_iff_coincidence): a Euclid subtraction that leaves exactly b = 1, which always leads to a halt. The whole map is proved, including the odd-a rows the run never meets. Lean checks the orbit for 3,000 passes in the kernel (no halt in 10500 steps) and 105 compiled (1010000 steps). Lean also proves that no congruence modulo any M ≤ 10,000 can exclude the coincidence: the orbit visits its residues. The chance of a halt is about 2/a, and a grows exponentially.

Other proofs and outside reports

A halts-iff map in DeepMind's Lean, compiled here

M_1RB0LC_0LC1RF_1LE1RD_0RC1RC_0LA1LA_HHH1RA.lean in google-deepmind/cryptids (commit 3647718, 12 November 2026) proves IsHalt target ↔ CollatzHalts next start: the machine halts from blank tape if and only if an explicit map reaches its halting case. The module also proves a coarser higher-level version of the map. We built it with Lean v4.35.0-rc4 on 2026-11-17 (BusyBeaver.M_1RB0LC_0LC1RF_1LE1RD_0RC1RC_0LA1LA_HHH1RA.isHalt_iff_acceleration); it rests only on the axioms propext, Classical.choice, Quot.sound, and its transition table was checked against this machine. The map in this repository needs an assumption that Lean does not check, or proves only the no-halt direction; theirs has no such condition. Halting itself stays open.

The pass map for every even a

Events: Ev .U a b = A> 011011 1^a 0 1^b and Ev .V a b = A> 1110 1^a 0 1^b. next F a b gives the next event and the exact number of steps to it; next_sound proves that the machine goes there. next_isSome: it is defined at every event with a even, a ≥ 2 and b ≥ 1 except U/V(a, 1) with a = 0 mod 4. The cases: a = 2 mod 4 with b odd (to o((3a+10)/2, b)); a = 0 mod 4 with b = 3, 5 or b ≥ 7 odd; a, b even with b ≥ a+4, b ≤ a−2, b = a or b = a+2. Each is a family with a generic part and a few small values, 32 case theorems in all, built from symbolic-simulator segments and four loops proved by induction: a round of the b-odd phase (four 1s of a become six) for each residue of a mod 4, and a round of the Euclid phase (both blocks lose 11) for each of the two orders. Axioms: propext and Quot.sound only.

next_sound, next_isSome, lean/Map.lean; lean/Cases.lean, generated by py/gen_map.py and py/gen_mapdef.py

The whole table, odd a included

nextOdd proves the odd-a rows for every odd a ≥ 15 and every odd a < 15 with b ≥ 30 (48 case theorems from four new loops: with odd a the left of the head is a plain run of 1s, so a round starts at 1^r (111111)^i A> 0). The remaining corner, odd a < 15 with b < 30, is a table of all 420 events and their next events, run by the kernel on the list simulator (none of them halts). nextAll joins the three parts: nextAll_sound, and nextAll_isSome: defined at every event with a odd, and with a even, a ≥ 2, b ≥ 1 except the halting events. The run from blank tape never meets odd a, so this does not bear on halting.

nextAll_sound, nextAll_isSome, lean/MapAll.lean; lean/MapOdd.lean, lean/OddCases.lean, lean/Corner.lean, generated by py/gen_odd.py, py/gen_odddef.py, py/gen_corner.py

Non-halting reduces to the map; 3,000 passes checked

init_U: blank tape reaches U(4, 3) after 118 steps. not_halts_of_orbit: if the orbit of next from U(4, 3) never gets stuck, the machine never halts. Each pass takes at least one step (next_pos), so the orbit's step count grows without bound. The kernel evaluates the first 3,000 passes: never stuck, so no halt in the first 10500 steps (no_halt_3k). Pass 34 is U(35,354, 10,986) at step 1,916,511,832, as direct simulation finds (orbit_34).

not_halts_of_orbit, orbit_3k, no_halt_3k, orbit_34, lean/Orbit.lean

The halting events halt

From U(a, 1) or V(a, 1) with a divisible by 4 and a ≥ 4 the machine reaches 1^n F> 0 (n = 3a/2 + 8 for U, 3a/2 + 9 for V) and halts there. One generic case per letter (a = 4x + 8, through the b-odd loop lb) and the value a = 4, generated by py/gen_halt.py.

halt_event, lean/HaltIff.lean; lean/HaltCases.lean

Halts if and only if the orbit reaches a halting event

halts_iff: the machine halts from blank tape exactly when, for some k, the k-th event of the orbit of next from U(4, 3) has a = 0 mod 4 and b = 1. orbit_inv shows that along the orbit a stays even and at least 2 and b at least 1, so by next_isSome the orbit can only get stuck at a halting event; halt_event gives the converse of not_halts_of_orbit. halts_iff_stuck states the same as: halts iff the orbit is undefined at some k. Axioms: propext, Classical.choice, Quot.sound.

halts_iff, halts_iff_stuck, orbit_inv, lean/HaltIff.lean

Halts if and only if a Euclid coincidence: b − a = 4 or −2

halts_iff_b1: the machine halts exactly when the orbit reaches any event with b = 1. At b = 1 with a = 2 mod 4 the map keeps b = 1 and multiplies a + 10 by 3/2 (next_b1), so a + 10 loses a factor 2 every pass until a = 0 mod 4, a halting event. halts_iff_coincidence: it halts exactly when the orbit meets an event with a and b even and b = a + 4 or b = a − 2. A pass ending at b = 1 starts either at b = 1 or at such an event (next_to_b1, every branch of the map checked), and such an event always goes to b = 1 (next_of_coincidence). The b = 1 events with a = 2 mod 4 and the rows with odd b drop out: only the Euclid step matters. Axioms: propext, Classical.choice, Quot.sound.

halts_iff_b1, halts_iff_coincidence, lean/Coincidence.lean

No congruence proof modulo any M ≤ 10,000

no_residue_proof: for every 1 ≤ M ≤ 10,000 and every property S of (letter, a mod M, b mod M) that holds at all events of the orbit, S also holds at some valid coincidence event, which halts. So a proof of non-halting cannot be a closed set of residue classes, for any such modulus (2-adic, 3-adic or mixed). The witnesses are orbit events themselves: sweep_100k walks the first 105 passes and meets b − a = 4 or −2 (mod M) for every M ≤ 10,000 (the last one, M = 9,837, at pass 95,434). Checked with native_decide.

cited Cited axiom: an outside Lean proof, assumed here

Available in Lean here as a cited axiom: DeepMind's halts-iff map

deepmind_halts_iff states on this repository's definitions what DeepMind's compiled theorem proves: the machine halts from blank tape if and only if the orbit of their map next from start reaches none. The map is copied from their file unchanged, and running the copy and theirs for 120 steps gives the same states. It is an axiom: nothing in this repository proves it, and the translation from DeepMind's definitions (Mathlib's Turing machines) to ours is not checked by Lean. #print axioms names it in every theorem that uses it.

The pass map against direct simulation, including odd a

Sample the run when the head is in A at the left end. From step 118 the tape is U(a, b) = A> 011011 1^a 0 1^b or V(a, b) = A> 1110 1^a 0 1^b. The next such configuration is given by an explicit map with cases on a mod 4, the parity of b, and b compared with a (written out in py/emap.py): for example U(a, b) with a = 0 mod 4 and odd b ≥ 7 goes to U((3a+16)/2, b−5), and with a and b even and b ≤ a−2 to V(3b+4, a−b−1). The map was checked against direct simulation for every start with a < 60 and b < 70 (7,980 starts the map covers), 300 random starts with 15 ≤ a < 2,000, and 84 starts with small odd a and large b. Both halves are now also proved in Lean (above).

No halt in the first 106 passes

Iterating the map from U(4, 3) with exact big integers gives no halt in 106 passes. Both numbers then have about 96,600 digits. 14% of the passes make a smaller (a subtraction-and-swap step), and b came down to 2 a few times, but never to 1 with a = 0 mod 4. (The first 105 of these passes are also checked in Lean, above.)

py/emap.py far 1000000

b − a is equidistributed and has no lower bound

At the even/even events of the first 105 passes, b − a takes the residues 4 and −2 as often as a uniform even number would, modulo every M = 2j3i tried (8 to 5,832; for example 132 hits mod 1,024 against 130 expected). It is positive at a third of these events and negative at the rest, so it has no lower bound, and the record lows of |b − a|/a fall like 1/(number of passes) (10−3.9 by pass 98,298), as for random numbers; |b − a| itself stays about as large as a. The one rigid residue fact is that a = 2 mod 3 at every U-event and a = 1 mod 3 at every V-event past the first passes (the last odd-b step fixes it), which says nothing about b. For moduli up to 30,000 the orbit meets the coincidence residues within 3·105 passes, except M = 24,463.

heuristic Evidence only

Probviously non-halting: the chance of a halt is about 2/a

Reaching b = 1 needs a subtraction step that leaves exactly 1, so b has to land at a − 2 or a + 4 at an event where both are even (halts_iff_coincidence). Iterating the map from 20,000 random starts at each scale (100,000 at S = 10⁴) S (a in [S, 2S), b in [0, 2S)) gives halting frequencies 2.0·10−2, 2.5·10−3 and 2.1·10−4 for S = 102, 103 and 104, so the frequency is about 2/S. Since a grows exponentially, this sum is dominated by its first terms. From the last simulated event (a = 74,180) the estimate is about 3·10−5, and after the 106 passes iterated it is about 10−96,600.

py/emap.py mc 1000 20000

open Open

Does it halt from blank tape?

Not known, but probably not. A proof would need to show that b − a never equals 4 or −2 at an even/even event of this orbit. No congruence modulo M ≤ 10,000 can do it (no_residue_proof), and b − a has no lower bound, so it is a question about the long-run behaviour of a 3/2-Collatz-like orbit, which is out of reach.
