A 6-state Busy Beaver machine · Status as of 12 November 2026.

Does this machine ever halt?

1RB0RF_1LC1RE_0LD0LC_1RD0RB_1RA0RB_0LC---

Nobody knows. Started on a blank tape, this machine keeps a word of blocks of 1s on the left and a binary counter on the right, and rewrites the word by a fixed map at every count. Every kind of step it takes is now proved in Lean and packed into one small map on lists of numbers; the machine runs for ever if that map never fails. Whether it ever fails comes down to a race that is lost only if the counter shows a very round number at the wrong moment.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from A1 (writes 0, moves R): A>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

First look

The shape of the run

Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). The structure

A word and a counter

This machine is one of six G12 holdouts that share every transition except two: A1 (0RF or 1RF) and F0. Here A1 is 0RF and F0 is 0LC. Both are used only at an F event, when state A reads a 1, which is rare (see the last section). Everything else is the same for the six machines, and so is this page up to that point.

Most of the time the tape reads W 0 1^(3a) B>0 R. We call this a Q configuration. W is a word: blocks of 1s separated by single 0s, with a blank tape to its left. The first block is even and every later block is odd. R is a run of gaps 0^(3p+2) 1. The run of 3a ones before the head and the gaps together hold a binary counter: a and the gap sizes p are its digits, read in parts. The head stays between the word and the counter. It goes left and rewrites the end of the word, then goes right and adds one to the counter.

On the word the machine applies a fixed map φ. It removes the last block b, adds 2 to the block before it, and appends (b−1)/2 blocks of a single 1. The total width stays the same. Applying it repeatedly, a word with blocks 2 3 1 5 goes like this:

word (blocks)tape
2 3 1 51^2 0 1^3 0 1 0 1^5
2 3 3 1 11^2 0 1^3 0 1^3 0 1 0 1
2 3 3 31^2 0 1^3 0 1^3 0 1^3
2 3 5 11^2 0 1^3 0 1^5 0 1
2 3 71^2 0 1^3 0 1^7

Repeated φ carries every block into the first one: the word eventually becomes a single block. The number of steps this takes is exactly N(W) = Σi≥2 2(Si−1)/2, where Si is the width of the word from block i to the end. So φ is itself a counter, written in a mixed radix.

Proved in Lean

One Q-step: φ twice, the counter plus one

From one Q configuration to the next, the machine applies φ twice to the word and adds one to the counter. The step count is a linear function of the parameters. The step depends only on the last one or two blocks of the word (a last block of 2j+5, a last block of 3, or a last 1 after an odd block) and on the lowest part of the counter (at least two units, or one unit followed by t gaps of length 2). That gives six cases.

All six are Lean theorems checked by the kernel, for every value of the parameters and every tape beyond. lean/Rules.lean states them as shift rules. lean/Macro.lean restates them on Q configurations qc W a P T, with φ defined as a Lean function on lists, for example qstep_big_wide.

Simulated

Long cycles, anomalies and collisions

Between Q events the counter climbs. When it overflows, the run of ones 1^(3k) gets longer by one unit and the counter starts again from zero. A full cycle with counter length k applies φ about 2k times, and each extra unit roughly doubles the time. That is why the right side of the tape grows like the logarithm of the step count.

The regular Q-steps break down in two ways, called transients. An anomaly happens when the word has become a single block: φ has nothing left to carry, and the block restarts as 2 1 1 … one cell further left. A collision happens when the counter overflows into a gap that is too short (0 or 1 cells). The accelerated simulator py/hyb.py (in the folder of 1RB0RF_1LC1RE_0LD0LC_1RD0RB_1RA0RB_0LC---) jumps over regular stretches with the closed forms above and runs every transient cell by cell. It agrees with direct simulation on every F event up to 2·1010 steps, and on direct runs of 3·108 steps from Q events picked at random in the middle of phases.

For this machine it ran 300 transients without a halt, up to about 21248 steps, with the tape 2510 cells wide.

Proved in Lean

The anomaly: the word starts again

Each φ moves width into the first block, so after N(W) steps the word is a single block (or a block and a single 1). The next Q-step cannot apply φ and does something else, the anomaly. It is short and exact. The head erases the counter's low part, slides the block one cell to the right through the hole it leaves, and comes back rewriting the block as 1 1 0 1 0 1 …:

beforeaftersteps
1^(2c+2) 0 1^(3a+3) B>0 R1^2 (0 1)^c 0 1^3 B>0 0^(3a) 1 R3a+8c+17
1^(2c+2) 0 1 0 1^(3a+6) B>0 R1^2 (0 1)^c 0 1^3 0 1^3 B>0 0^(3a+1) 1 R3a+8c+46
1^(2c+2) 0 1 0 1^3 B>0 0^(3p+5) 1 R1^2 (0 1)^c 0 1^5 0 1^3 B>0 0^(3p+2) 1 R8c+57

The new word 2 1 1 … 1 has the same width w, and N(W) = 2(w−2)/2 − 1 for it: it lasts that many φ steps. The counter starts again from one unit. Where the old low part was there is now a gap of 3a or 3a+1 cells. That is not of the form 3p+2: it is the misaligned gap. All of the old counter's gaps are still behind it. These are Lean theorems for every a, c and every tape R (anomaly_one, anomaly_two in lean/Transients.lean).

As the new counter overflows, the misaligned gap shrinks by 3 each time. When it is down to 0 or 1, the next overflow is a collision. The head carries that part of the counter into the end of the word, and the next old gap, a few cells shorter, becomes the misaligned one. This cascade continues until the old gaps are used up and the counter is aligned again.

Lean

The collision: the counter's low part joins the word

After an anomaly the counter has a gap of the wrong length in it: 3p or 3p+1 cells instead of 3p+2. Each time the counter's low part overflows into this gap, the gap loses 3 cells, so it ends at 0 or 1 instead of 2. At the next overflow the regular step is impossible. The counter then reads: one unit, t gaps of length 2, the short gap g. What happens is the same whatever the word:

partbeforeafter
wordWφ(φ(W)), last block + 2, then about 3t/2 new blocks of a single 1 and a last block of 3, 5 or 7
counterone unit, t gaps of 2, gap gone unit (more if gaps of 2 follow)
next gaph + 5h, h + 1 or h + 2

The next gap had the right length 3p+2; after the collision it is 3, 4 or 5 cells shorter. If it lost 3 it is aligned again and the cascade is over. Otherwise it is the new misaligned gap and the story repeats further right. How much it loses depends on whether t is even or odd, on g and on the number U of gaps of length 2 that follow: 26 cases in all, each a Lean theorem for every value of the parameters (lean/Collide.lean; the table is coll in lean/Full.lean).

With these, every step of the run is covered. astep in lean/Full.lean is the whole macro map as one function on triples (word, low part, gaps); Lean proves that the machine follows it (astep_sound) and that the machine never halts if the map never fails from the configuration at step 27 (not_halts_of_arun). Compiled evaluation applies it 108 times without a failure (lean/Bound.lean).

Simulated

A race between two binary counters

The word is itself a binary number. Give each block after the first the weight 2(s−1)/2, where s is the width of the word from that block to its end; the sum N(W) is a number of B = (w−2)/2 binary digits for a word of width w, and φ lowers it by exactly one. So a regular step subtracts 2 from the word's number and adds 1 to the counter. The anomaly is the word's number reaching 0 or 1; it is then set back to all ones, 2B − 1.

Shape alone does not keep the machine running. Lean checks that the Q configuration 1^2 0 1^3 0 1^3 B>0 halts after 190 steps (qc_short_halts): its word is so short that it runs out again while the misaligned gap made by the first anomaly is still there, and the second anomaly then leaves gaps of 1 and 0 in a row. The real run avoids this only because each cascade of collisions ends long before the word runs out.

How long does the first collision take? If the counter's low part at the anomaly was a units, the misaligned gap has about 3a cells and the new counter must count to 2a to close it. The word lasts 2B−1 steps. So the race is won when a ≤ B − 1 and lost when a ≥ B (checked with the macro map for small sizes). Each collision then lengthens the word by about 3t cells, which multiplies its remaining time by about 21.5t, far more than the 2t steps the collision took to arrive; so the first collision is the one that matters.

a − 1 is the number of trailing zeros of the counter's value when the word runs out. In the run the counter is never longer than B digits, so losing the race means the counter shows an extremely round number, one or two leading digits followed only by zeros, exactly at an anomaly. In 108 simulated anomalies a was at most 18, while B went from 7 to over 1200. The values of a look like coin tosses (1 half the time, 2 a quarter of the time, …); if they were, the total chance of ever losing after the first few anomalies would be below 2−16. But nothing we know proves that the round number never comes up: the counter's digits are produced by the earlier epochs in a way that mixes them much like the Collatz map does.

Halting

Where it could stop

F is reached only from A reading a 1, and F halts on a 1. So a halt needs A to read 1 1. Regular Q-steps never let A read a 1. Only transients do; such a moment is an F event. In the first 2·1010 steps this machine has 5 F events, and at every one the cell after the 1 is a 0.

All the F events we saw happen in collisions. A collision starts when the counter's low part is one unit followed only by gaps of length 2 and then a misaligned gap of length 0 or 1. The head sweeps that part of the counter into the word, and the next gap becomes the misaligned one, shortened by a few cells. A halt needs a gap of length 0 right after such a gap. The gaps behind the misaligned one come from the counter as it was at the anomaly. In every run they have length ≡ 2 (mod 3) and at least 2, so the halt never comes.

Status: open. Lean proves all the macro steps and that the machine never halts unless the macro map fails. The map can fail only after a lost race. That the race is never lost is supported by the simulation and by the heuristic above, not proved.

The collision, in all its cases

A collision is the step taken when the counter's low part is one unit, followed by t gaps of length 2 and then a gap g of length 0 or 1. Lean proves what it does for every t, both values of g, any number U of gaps of length 2 behind it, and a next gap of at least 5 cells or blank tape (26 rules): the word takes its usual double step, its last block grows by 2, and the counter's low part is turned into about 3t/2 new blocks at the end of the word; the counter restarts from one unit (or a few, when U ≥ 2) and the next gap is shortened by 3, 4 or 5 cells. The rules do not depend on the word: they are proved for any tape to the left.

The anomaly with a one-unit counter

When the word is a block and a single 1 and the counter's low part is one unit followed by t gaps of length 2 and a gap of at least 3 cells (or blank tape), the new word is 2 1…1 5, the low part becomes t+1 units and the gap loses 3 cells, for every value of the parameters (4 rules). Kernel
astep, astep_sound, lean/Full.lean; configurations qr in lean/Abstract.lean
The macro map, and that the machine follows it

astep is a function on configurations (W, a, G) (the word's blocks, the counter's low part, the list of gap lengths, standing for the tape W 0 1^(3a) B>0 0^g1 1 0^g2 1 …). It returns the next such configuration: a regular step, an anomaly or a collision, or nothing when none of the proved rules applies. Lean proves that whenever it returns a configuration, the machine really goes from the first tape to the second, in at least 17 steps.

Kernel
start_reached, not_halts_of_arun, runs_of_arun, lean/Full.lean
Non-halting reduced to the macro map

The run from blank tape reaches the configuration W = 2 1, a = 1, no gaps at step 27. Lean proves: if the macro map can be applied any number of times starting there, the machine never halts; and if it can be applied k times, the machine does not halt in its first 27 + 17k steps. So the halting problem of this machine is now the question whether a short explicit function on lists of numbers ever returns nothing.

When the race is lost

After an anomaly from a one-block word, with the new word B bits long (see the explainer) and the counter's low part a units, the first collision comes after exactly 2a − 2 regular steps if a ≤ B − 1; if a ≥ B the word runs out first (checked for B = 2…8, a = 1…9 with the macro map). In the simulated run a is at most 18 while B grows from 7 to over 1200; the smallest B − a after the first three anomalies is 6, and the counter is never longer than B bits.

Heuristic
observed over 108 anomalies; not proved
Why it probably never halts

The low part a at an anomaly is one more than the number of trailing zeros of the counter's value at that moment. In the simulated run these values look like random bits: a = 1 about half the time, 2 a quarter of the time, and so on. If they were random, the chance of a ≥ B at an anomaly would be about 2−B, and since B grows by at least 5 at each anomaly the chances add up to less than 2−16 from the fourth anomaly on. This is a heuristic, not a proof: the bits are determined, not random.

Heuristic
observed over all simulated transients; not proved
Gap alignment

In every run the gaps behind the first misaligned gap have length ≡ 2 (mod 3), at least 2, so every collision meets a next gap of at least 5 cells, a run of gaps of 2, or blank tape: the cases the macro map covers.

Open
Does it halt from blank tape?

Not known. By the Lean reduction it is enough to show that the macro map never fails on the run. It can fail only if a misaligned gap is still there when the word runs out (the race is lost) and the gaps then line up badly. Winning every race needs, at each anomaly, that the counter's value is not divisible by a power of two about as large as the value itself (a ≤ B − 1). That value is the sum of the previous epochs' contributions, shifted and truncated by the collisions; we found no invariant that controls its low digits, and the situation resembles the Collatz-like problems where such digit questions are out of reach. A size bound alone (cascade length against word length) is not preserved from one epoch to the next: the counter may be as long as the word, and only its last digits decide.
