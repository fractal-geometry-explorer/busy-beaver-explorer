Does this machine ever halt?

1RB1LB_1LC0RD_0LE1LA_0RF1RA_1LE0LA_---0RB

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows. The left half of the tape is a long string of two 3-cell words, x = 111 and y = 110, and each round trip of the head replaces every word by the XOR of it and its right neighbour: a linear cellular automaton running on the tape. What could make it halt is a defect coming in from the right end.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 0. F is entered only from D0 (writes 0, moves R): D>0 0. So a halt is the moment this pattern appears, with the head on the cell after >.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.505). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.067).

After 109 steps the tape spans 43,577 cells (31,721 left of the start, 197 right), with a density of 1s of 0.805.

What the tape looks like

A string of 110s and 111s, run by the XOR rule

At step 985,607,083 the head is at the left end and the tape starts A>0 0 1^6 0 1^8 0 1^2 0 1^5 0 1^2 0 1^5 0 1^2 0 1^2 0 1^2 0 1^14 …: runs of 1s whose lengths are 2, 5, 8, 11, 14, … (2 more than a multiple of 3) separated by single 0s. In 3-cell words that is a string over x = 111 and y = 110, about 10,000 words long.

The rule. From the left end the head sweeps right in state B, reading one run at a time: 1^m 0 becomes 0^(m-1) 1 1 (the zigzag B→D→A→B moves one cell right every three steps). At the right it turns and sweeps left in states E, A, B, C, which turns the 0-runs back into 1-runs. Put together, word i of the new string is x if words i and i+1 of the old string were equal and y if they differed:

words
beforey y x y x x x x y y
afterx y y y x x x y x …

With x = 0 and y = 1 that is vi = wi xor wi+1, the linear cellular automaton called rule 102, whose pictures are Sierpinski triangles. py/xor_epoch.py checks it with the machine's own table for every string of up to 16 words. So the string is not a number in some base: it is a linear automaton, and any word string can appear.

Walls. Where the 3-cell alignment shifts (a run of length 0 or 1 mod 3, or a double 0) two XOR domains meet. A single wall survives: it cycles 00 → 1^(3k) → 1^(3k-3) → … → 1^3 → 00 while drifting left. A right sweep stops at the first 00 wall, so the walls behave like the digits of a counter, and the small structure at the right end (a 5-phase cycle that gains 2 cells per cycle) is where new walls come from.

Levels of abstraction

From cells to walls, interactively

The same tape can be read at five levels, each one coarser than the last and each one following from the one below it:

  1. Cells. 0s and 1s and a head in one of six states: the machine itself.
  2. Runs. Going right in state B, the head reads one run 1^m 0 at a time and writes 0^(m-1) 1 1. Going left in states E, A, B, C it turns the 0-runs back into 1-runs.
  3. Words. Runs of 1s have length 2, 5, 8, … so the tape cuts into 3-cell words, x = 111 and y = 110.
  4. Bits and the XOR rule. With x = 0 and y = 1, one round trip of the head turns bit i into (bit i) xor (bit i+1). That is the linear cellular automaton rule 102.
  5. Domains and walls. Where the 3-cell cut shifts by one or two cells, two XOR domains meet at a wall. Walls come in from the right end and drift left. A halt would need a wall in one particular shape.

Levels 1 to 4: run the machine on any word string

Type a string of x and y. Right sweep starts the real machine in state B on the first cell and runs it until it steps past the end. Left sweep then starts it in state C on the last cell and runs it until it leaves the left end. Each sweep is the machine's own table, step by step, with nothing shortcut. The last line compares the result with the XOR rule. A final y is kept at the right end, so the string keeps its length.

Level 4: many round trips draw a Sierpinski triangle

Each row is one round trip of the machine (computed by the real table, as above) on the row above it, drawn as bits: y is dark and x is light. Bit i of the next row depends only on bits i and i+1, so a pattern spreads only to the left and every triangle is right-angled, with its corner at the top right: half of the familiar Sierpinski triangle, nothing is cut off. The y held at the right end (drawn as an extra column at the right edge, always dark) feeds the pattern, which is why the last real column alternates: it is that column xor y. Starting from all x gives one clean triangle; at 32, 64, 128 or 256 words it exactly fills the square. The XOR rule predicts every pixel, and the counter confirms that the machine agrees.

One row per round trip of the real run from a blank tape, with time going down and the left end growing to the left. Each cell is coloured by its domain, that is where its 3-cell words start (cell number mod 3). Walls are drawn in orange. New walls appear at the right end. Switch to bits and the last 400 to see the XOR rule in the real run: on the left, which is updated on every round trip, the tape is the random-looking rule 102 texture, full of right-angled triangles. Behind each 00 wall the bits stand still (vertical stripes) until a sweep gets past it.

Does it halt?

Open

The only halt is F reading 0. It needs the right sweep's token reader (state B) to stand on 1 0 0: a run of a single 1, possibly followed by several 110 words read one cell out of step, running into a double-0 wall. Single 1s occur only within about 30 runs of the right end, and this combination was never seen in 3·108 steps.

A closed tape language (a regular set of tapes that contains the start, is closed under a step and has no halt) would settle it, and was searched for on 16 November 2026 with whole-tape automata and with run-length windows that count lengths mod 3; none closed. The bulk can hold any word string, so local windows explode, while the walls near the right end need exact lengths. A language that keeps the right end exact and lets the bulk be any word string with walls is the next thing to try.

Where a halt can come from

If the machine halts on its third step from a configuration, that configuration is one of: B with 1 under the head, 0 right, 0 two right. So a run can reach a halt only through one of these patterns, and a proof that the machine never halts only has to rule them out. The proof splits on the state and the five cells around the head.

One sweep pair is the XOR rule

Write x = 111 and y = 110. For every word string w over {x, y} ending in y, up to 16 words (65,535 strings): started in B on its first cell the machine sweeps right without turning, rewriting each run 1m0 as 0m−111; started in C at the end of that it sweeps left without turning; the result is the word string v with vi = wi xor wi+1 (x = 0, y = 1), last word x. This is the linear rule 102 cellular automaton, so every word string can occur and the left string looks random.

Heuristic
simulation, 16 November 2026 (project folder ctl-696/NOTES.md)
Defects are walls emitted at the right end

Where the word alignment shifts (a run of 1s of length 0 or 1 mod 3, or a double 0) there is a wall between two XOR domains. A single wall survives each epoch and cycles z2 → 13k → 13k−3 → … → 13 → z2, drifting left. A right sweep stops at the first double-0 wall (B reads 0), so walls act like digits of a counter. Walls are created by a 5-phase cycle at the right end, which grows by 2 cells per cycle. A halt needs the token parser (state B) at 1 0 0: a single 1 (seen only within about 30 runs of the right end) followed by 110 words and then a double 0; it was not seen in 3·108 steps.

Computed
c/rlwin.cpp (run-length windows); the model-checking scripts are in the project folder ctl-696/tools
Closed tape language searches (16 November 2026)

None closes; each reaches a halting configuration in its abstraction or runs out of budget. Abstract regular model checking over whole-tape automata, merging states by k-step Moore equivalence (forward, reversed, both), k = 1..6, forward from blank and backward from F reading 0. Run-length windows with lengths mod 3 (the F11 sweep tried M = 1, 2, 4 only): K = 2..16 nearest runs with exact lengths below 3 halt; exact lengths up to 4..8, or runs near the blank ends kept exact, exceed 5 to 30 million abstract configurations. The reason found: the bulk is a full shift (any word string), so windows of K runs grow like 2K, while the right end needs exact lengths.

Heuristic
mutation tests, 16 November 2026 (project folder ctl-696/tools/mut*.py, trace.py)
Halting needs a short gap that the XOR rule turns all y

Every left-visit tape up to 3·107 steps parses as words 111 and 110 with inserted defects 0 and 10. The halting read 1 0 0 needs the pattern 0 10 (110)* 0, which never occurs. In mutation tests on real tapes, random words between defects stay clear in 99 of 100 runs over 60 more left visits; every halting run, shrunk to its smallest change, alters the words W in a gap 10 W 0, which the XOR rule then turns into all 110 (for example 10 xyxyx 0 becomes 10 yyyyy 0), giving the pattern. So what keeps the machine from halting is a condition on the XOR orbit of these gaps, of any length, which a fixed-window closed tape language cannot express.
