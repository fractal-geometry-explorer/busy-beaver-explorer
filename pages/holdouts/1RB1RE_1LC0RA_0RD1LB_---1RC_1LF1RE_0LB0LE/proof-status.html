What is known about 1RB1RE_1LC0RA_0RD1LB_---1RC_1LF1RE_0LB0LE

1RB1RE_1LC0RA_0RD1LB_---1RC_1LF1RE_0LB0LE

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open, and reduced to a map on pairs of numbers. Lean proves (kernel, no native_decide) that the machine halts from blank tape if and only if the orbit of (2, 1) under the map f below reaches a pair with r = p + 1. Iterating the map 3,000,000 times, the orbit never does; by then p and r have about 650,000 binary digits, so the machine has run for more than 2650000 steps. A probability argument says a hit becomes ever less likely (the chance at each decision is about 1/p), so the machine is expected never to halt, but no proof is known.

Other proofs and outside reports

Community label

In the community's BB(6) tracker the machine's class is Quadratic Mess. Its 3 November 2026 edition lists the machine as a cryptid: its halting is thought to come down to a Collatz-like question that no known method decides. These are labels read off the run by others, not results.

The one-sweep rules

With W p q r = 0 (10)^p 0 (10)^q 1^r E> 0 and X p q = 0 (10)^p 0 (10)^q A> 0 (the head at the right end): W (p+1) q (r+2) → W p (q+2) (r+1); W (p+1) q 1 → X p (q+2); X (p+1) (q+2) → W (p+1) 0 (2q+6); X 0 (q+2) → W 2 0 (2q+5); W 0 q (r+2) → W (q+2) 0 (r+1); W 0 q 1 halts. Each a theorem for all values, by symbolic simulation.

l1…l6, lean/Rules.lean (generated by py/gen_rules.py); w1…w6, lean/Map.lean

The map

Read at the samples W p 0 r (r ≥ 1): if r ≥ p+2 then (p, r) → (2p+2, r−p−1); if r = p+1 the machine halts; if r = p then (p, r) → (2, 4p+1); if r < p then (p, r) → (p−r, 4r+2). Each case is a positive run of the machine, chained from the rules by induction on the number of sweeps.

map_step, lean/Map.lean

From blank tape the machine reaches W 2 0 1 in 27 steps; so it halts if and only if the orbit of (2, 1) under the map reaches a pair (p, p+1).

No halt in 3,000,000 map steps

The orbit of (2, 1), iterated with exact integers, does not reach r = p+1 in its first 3·106 steps; at the end p and r have about 650,000 bits. Each map step is at least one machine step and in fact at least p of them, so this covers far more than 2600000 machine steps.

py/orbit.py

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.074). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.483).

tools/py/bbtools/triage.py

Why a halt looks unlikely

Halting can only happen when a doubling run ends: the last step leaves r somewhere in a range of about 2p values, and halting needs exactly r = p+1. Treating the leftover as random, the chance is about 1/(2p) per run; p grows exponentially (about 0.22 bits per map step), so the expected number of future hits is far below 2-100000. The closest approach in the first 3·106 steps had |r−p−1|/p ≈ 3·10-6.

Does it halt from blank tape?

Not known: it halts exactly when the orbit of (2, 1) under the map reaches r = p+1, a question like a Collatz problem. No residue-class argument closes it (no modulus below 200 has an invariant set of residue pairs avoiding the halting pairs).
