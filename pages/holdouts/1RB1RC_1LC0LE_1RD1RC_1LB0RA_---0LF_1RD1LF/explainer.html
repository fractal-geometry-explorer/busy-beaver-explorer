Does this machine ever halt?

1RB1RC_1LC0LE_1RD1RC_1LB0RA_---0LF_1RD1LF

Nobody knows, but the question is now arithmetic. This machine is a counter whose digits are blocks of 1s. Every so often a carry wave runs through the digits, halving each one it passes, and the machine stops only if that wave ever reaches the far end of the tape carrying exactly the number 1.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in E reading 0. E is entered only from B1 (writes 0, moves L): 0 B>1. So a halt is the moment this pattern appears, with the head on the cell after >.

The records list every step at which the head reaches a cell no earlier step reached, with the side, the width so far and the whole tape: the first place to look for a repeating macro structure.

Macro structure

A counter whose digits are blocks of 1s

Stop the machine whenever the head is at the right end of the tape in state A, on a 1. The tape is then always a row of blocks of 1s, each followed by exactly one 0. Read the block lengths as the digits of a counter. The last four are always 14 7 6 4; the free digits sit to their left.

One cycle of 5,009 steps works only on the right end of the tape: it adds 48 to the last free digit and then starts a carry wave on it, a zigzag of the head that moves two cells of a digit per pass, one to each side, until the digit is used up. The wave sees the digit with 61 more cells than it had at the cycle start.

The rule

The carry wave halves the digits it passes

On a digit holding a cells the wave does one of two things:

  • a odd: the digit is replaced by (a−1)/2 + 1, the other half, (a−1)/2, is added to the next digit to the left, and the wave moves on to that digit;
  • a even: the digit becomes a/2 + 3, the next digit to the left grows by a/2, and the wave stops. The head runs back to the right end, to the next cycle start.

So a carry travels left through odd values, as in a binary counter, and the digits get bigger towards the left. A real example from the run, starting at step 2,705,689 with the digits 26 756 730 292 232 114: the wave meets 127, 295, 439, 949 (all odd) and stops on 1230 (even), leaving 641 618 475 220 148 64, which is exactly what the machine has on its tape at step 4,073,393.

At the left end of the tape there is no next digit: the wave goes on into the blank part, halving the value again and again while it stays odd. The machine halts exactly when this reaches the value 1, and that happens exactly when the value arriving on the leftmost digit is 2t−1, a number whose binary digits are all ones.

  Proof
  
What Lean checks


The rule above is not just observed: Lean proves, for every value of the digits, that the machine does exactly this. A Python script runs the machine symbolically on tapes with unknown block lengths and writes a Lean proof of each piece: the cycle, the start of the wave on a digit, one zigzag, the two ways a zigzag ends, the run back across one digit, the end of the run, and the halt. A hand-written file then glues the pieces: any number of zigzags (induction), the run back over any list of digits (induction on the list), the wave over any number of digits (induction again), and the left end (strong induction on the value).
The main theorem, halts_iff, says: the machine halts from blank tape if and only if iterating the digit map from [26, 13, 9, 6] ever gives none. The Lean kernel checked it; it uses no unproved assumptions.





  What is left
  
A question about binary digits


Whether the map ever gives none is a question about numbers only. Iterated exactly, it shows no halt for the first 9·1052 steps of the machine. Waves reach the leftmost digit rarely (once every several times more cycles than the previous time), and the values they bring grow: 7, 11, 10, 13, 17, 19, 23, 29 bits in the first 2·107 cycles, 85 bits by 1052 steps. A halt needs one of them to be all ones in binary. If the bits behaved like coin flips the chance would shrink like 2−bits at every visit, and it is already far below one in a trillion trillion.
So the machine almost surely runs forever, but proving it means showing that this deterministic process never produces 2t−1. That is a Collatz-like problem: easy to state, with no known method to settle it.





  A twin
  
The same machine under another name


1RB1RA_1LC0RC_1RE0LD_0RE0LF_1RA---_1RB1LF is another holdout of the same group. Its table is different, but at every cycle start it has exactly the same tape (in state C instead of A, and a few hundred steps later). The difference is in how the head travels: there, the run back to the right end shifts a double 0 through the digits; here, state C simply walks over them. Both machines have their own Lean proof of the same reduction.





  First look
  
The shape of the run


Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.53).



After 109 steps the tape spans 42,663 cells (17 left of the start, 30,165 right), with a density of 1s of 1.0.

Shift rules
For every length n of the run and any tape around it: L C> 1^n R reaches L 1^n C> R; L 1^n F> 1 R reaches L F> 1 1^n R. These are the moves the head makes across the long uniform stretches of the tape.

    
Kernel
halts_iff, lean/Wave.lean (pieces in lean/Rules.lean, from py/rules.py)
Halting is equivalent to an arithmetic iteration
HaltsFromBlank ↔ ∃ k, iter k = none, where iter iterates the digit map next from the digits [26, 13, 9, 6] of the first cycle start (step 6,053). One cycle (5,009 steps) starts a wave on the last digit plus 61; on an odd value a the wave leaves a/2+1 behind and adds a/2 to the next digit; on an even value it stops (the digit becomes a/2+3, the next digit grows by a/2); at the left end of the tape the value 1 halts (E reads a 0 five steps later). Every piece is a symbolic trace checked by Lean; the composition is by induction.

    
Computed
py/fast.py, py/model.py check
No halt in the first 9·1052 steps
The digit map iterated exactly (Python integers, with the step count of every piece), accelerated by memoizing the effect of the lowest digits until a wave leaves them: 29 visits of the left end, none with the value 1. The map and its step counts were compared with the direct run at every cycle start up to 5·107 steps, and the accelerated run with the plain map up to 2·106 cycles.

    
Heuristic
py/fast.py
Almost surely it never halts
A halt needs the value carried onto the leftmost digit to be 2t−1, all ones in binary. These values grow by a few bits per visit of the left end (85 bits by 1052 steps) and most of them are even; if their bits were random the chance of ever seeing all ones from here on would be below 2-80.

    
Open
Does it halt from blank tape?
Open: equivalent (Lean) to whether the digit iteration ever delivers 2t−1 to the left end, a Collatz-like question about the binary digits of the carried values.
