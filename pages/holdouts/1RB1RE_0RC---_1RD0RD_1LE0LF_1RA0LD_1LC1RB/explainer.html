Does this machine ever halt?

1RB1RE_0RC---_1RD0RD_1LE0LF_1RA0LD_1LC1RB

Nobody knows, but the question is now sharp. Every move of this machine is one rule, proved in Lean for all sizes, and the run is a copy of itself nested in the gaps it makes. It halts only if one of those gaps has one of a few fatal sizes. This page runs the real machine in your browser and explains the mechanism.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in B reading 1. B is entered only from A0 (writes 1, moves R): A>0 1; F1 (writes 1, moves R): F>1 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

The run at a glance

Space-time diagram and records

The diagram stacks the tape at many moments. Sampling at each new cell shows the shape of the run as the visited region grows; sampling evenly in time shows where the head spends its time. The records list every step at which the head reaches a cell no earlier step reached, with the side, the width so far and the whole tape: the first place to look for a repeating macro structure.

Right end

Draining a block of 1s

Most of the time the tape is a block of 1s followed by pairs 01, with the head at the right end in state C:

1^22 (01)^20 0 C>0   step 1,543
1^20 (01)^22 0 C>0   step 1,679
1^18 (01)^24 0 C>0   step 1,827

Each round trip the head runs left in E and D, turning every pair 01 into 10, bites two 1s off the block, and zigzags back right in F, B, C, D, turning the pairs back. The block shrinks by 2 and the pairs grow by 2: 1^(a+4) (01)^b 0 C>0 → 1^(a+2) (01)^(b+2) 0 C>0 in 6b + 16 steps. This is proved in Lean for every a and b (sweep). Since a trip costs time proportional to the tape, the right side grows like the square root of the step count.

One mechanism

Three shapes and one environment

Seen at the right moments, the tape always has one of three shapes, with blank tape on the left and an environment Z on the right:

D(A,B)   1^A (01)^B 0 C> 0 Z          the drain
P(A,B)   1^A (01)^B 1 1 1 0 C> 0 Z    the parity tail
T(n)     E> (01)^n Z                  the head at the left end

The environment is a row of blocks 0^g (10)^c 1: g zeros, then c pairs 10 and a 1. Two steps after the start the tape is 1 0 C> 0 = D(1,0) with nothing to its right. From then on the run is a chain of twelve rules, each proved in Lean for every A, B, n, g, c and every tape around:

sweep        D(A+2,B)        → D(A,B+2)            the next cell is 0
odd sweep    D(A+2,B) 0(10)^(c+2)1 → D(A,B+3) 0(10)^c 1
end          D(1,B) → T(B+3)      D(2,B) → D(1,0) 0(10)^(B+1)1 …
left end     T(n) (10)^(y+1)1 → D(2n-1,0) 0(10)^y 1     T(n) 0^5 → D(2n+2,0)
parity tail  P(A,2k) → D(A-1,2k+4)    P(A,2k+1) → D(1,0) 0^(A+1) (10)^(2k+3) 1
Left end

The ternary counter is the same sweep

Next to a block with a single 0 in front, 0 (10)^c 1, a sweep takes two 1s off the drain and two pairs off the block and writes three pairs: the odd sweep. Run from the left end this is a ternary counter: T(n) next to (10)^y 1 becomes D(2n−1,0), n−1 odd sweeps make D(1,3n−3), and that becomes T(3n) with 2n−1 pairs spent.

E> (01)^3   (10)^329 1     step 230,240
E> (01)^9   (10)^324 1     step 230,334
E> (01)^27  (10)^307 1     step 231,106
E> (01)^81  (10)^254 1     step 237,800
E> (01)^243 (10)^93  1     step 297,252

When the block runs out the drain goes on with whatever is left: an even or odd drain, or the parity tail when the last odd sweep has no pair left.

Big picture

A copy of the run inside every gap

The parity tail P(A,B) with B odd wipes its whole block of 1s: 1^391 (01)^141 1 1 1 0 C> 0 becomes 1 0 C> 0 0^392 (10)^143 1 (step 318,327). The left part is the start configuration again, and the gap of zeros in front of the block plays the role of blank tape: the run starts over from scratch inside the gap and repeats, step for step, what the run from blank tape did, until its right end reaches the block. Then the block is merged and the larger drain carries on.

So the run is self-similar. In the first 1012 steps the top level makes gaps of 392, 320, 124, 348, 22,456, 36,678 and 60,524 zeros; inside each of the large ones the copy makes gaps of 392, 320, 124 and 348 of its own, as the original did. This nesting is why the left side of the tape grows like a power of the step count other than 1/2.

In Lean

The whole run as one map

The three shapes and the environment are Lean data: a node is d A B e, p A B e or t n e, where e is the list of blocks (g, c) = 0^g (10)^c 1. One function F makes one macro move: a sweep, an odd sweep, an absorbed block, the end of a drain, a parity tail, a left-end phase, or one of four rules for a block that follows another with no gap (the cases the macro simulator used to run cell by cell). It returns the next node, halt (the two halting cases), or stuck (a small case no rule covers).

d A B ((1,c+2)::e)  →  d (A−2) (B+3) ((1,c)::e)        odd sweep (A ≥ 3)
d 2 B ((g+1,c)::e)  →  d 1 0 ((1,B+1)::(g,c)::e)      new block, fresh start
t (n+1) ((0,y+1)::e) → d (2n+1) 0 ((1,y)::e)        ternary round starts
p A B ((g+3,c)::e)  →  d 1 0 ((A+1,B+2)::(g,c)::e)   B odd: block wiped into a gap
d A B ((1,0)::(3,c)::e)  →  halt

Lean proves each move from the rules for every size (F_sem), and so: if the orbit of the start never gets stuck, the machine halts from blank tape exactly when the orbit reaches halt. The first 30 million moves are evaluated in Lean (20,000 by the kernel): no halt and no stuck node, and the drain is then D(7,667,001, 2,848,404) next to a block of 7,629,577 pairs, at least 5·1014 steps into the run. What remains is a question about one explicit orbit, which is where the Collatz-like difficulty lives.

What is assumed. The map has a rule for every node the run has met, not for every node one can write down. The main theorem halts_iff_of_no_stuck says: if the orbit never meets a node without a rule, the machine halts exactly when the orbit reaches halt. A second theorem, halts_iff_hybrid, assumes nothing: it completes the map by letting it fall back to plain machine steps on a node without a rule, and says that the machine halts exactly when this completed map reaches halt. The fallback has not been used in the first 3·107 nodes.

Halting

Three cells short of a block

The machine halts only when B reads a 1, and the last three steps before such a halt are always E, A and B reading 0, 0, 1: E running right over pairs 01 into 0 0 1. In the drain picture that is a drain ending exactly three cells short of the next 1. Lean proves both forms for all sizes: an odd drain D(2k+1,B) with exactly 2k+3 zeros after the head cell halts (drain_halts), and so does an odd sweep that uses up its block with exactly three 0s behind it (tail_halts).

At the top level there is only blank tape on the right, so neither can happen there. Inside a gap it can. A fresh run in a gap of G zeros halts before reaching the block exactly for

G = 3, 29, 75, 115, 289, 623, 716, 773, 1045, 1210, 3392      (all G ≤ 5000)

whatever the block holds. Each fatal size is a moment of the run from blank tape where a drain ends, or an odd sweep runs out, at that distance from the start. The gaps the run makes so far all miss the list. The fatal sizes thin out while the gaps grow roughly geometrically, so a hit looks unlikely, but both sequences come from the same counter and nothing rules a hit out: whether it halts is a Collatz-like question.

Kernel
sweep, lean/Rules.lean
The drain sweep

From 1^(a+4) (01)^b 0 C>0 with blank tape to the right, the machine reaches 1^(a+2) (01)^(b+2) 0 C>0 in 6b + 16 steps, for all a, b and any tape on the left.

Kernel
ternary, lean/Ternary.lean
The ternary step

With blank tape to the left, E> (01)^n (10)^(y+2n-1) 1 R reaches E> (01)^(3n) (10)^y 1 R, for every n ≥ 2, every y and any tape R. E turns the pairs into 2n ones, each round trip then spends two of the 1s and two pairs 10 and writes three pairs 01, and the last two 1s become a pair at the left end. Induction over the rounds is by hand, the pieces by symtm. In the run it applies to every visit of E to the left end with n = 3k (107 times in 3·109 steps, py/check_ternary.py).

Kernel
lean/Macro.lean (written by py/macro_rules.py), lean/Halt.lean
All the rules of the drain machine

Twelve rules, each for every count and every tape around it: the sweep D(A+2,B) → D(A,B+2) with any tape beyond the next cell (m_sweep), the odd sweep next to a block 0 (10)^c 1 (m_odd, the round of the ternary step), the ends of a drain (m_end0, m_end1, m_end2), the left end (m_tseg, m_tblank), the end of a block (m_absorb, m_odd_end1, m_odd_end0) and the parity tail (m_peven, and m_podd, which wipes the block of 1s into a gap of A+1 zeros with a fresh start 1 0 C> 0 in front). The sweeps are iterated by induction (drain, odd_drain).

Kernel
lean/Chain.lean
The rules chained into one map

The macro configurations are a Lean type (Node: D(A,B), P(A,B), T(n) with the environment as a list of blocks), and one function F makes one macro move, returning the next node, halt, or stuck where no rule applies. F_sem proves every move from the rules for all sizes. Main theorem halts_iff_of_no_stuck: if the orbit of the start d 1 0 [] (two steps from blank tape) never gets stuck, the machine halts from blank tape iff the orbit reaches halt; unconditionally, an orbit that reaches halt proves a halt (halts_of_orbit) and one that only meets nodes proves the machine runs for ever (not_halts_of_orbit). The hypothesis that the orbit never gets stuck is not proved.

Kernel
halts_iff_hybrid, hstep_next, hstep_halt, hrun_of_orbit, toF_cfg, lean/Hybrid.lean
With nothing assumed: halting is halting of the hybrid map

The map F has a rule for every node the run has met; on any other node it answers stuck, and the earlier main theorem (halts_iff_of_no_stuck) assumes that never happens. The hybrid map hstep is defined on every state: it is F where F is defined, and otherwise it continues with single steps of the machine itself, on the configuration written out cell by cell. Proved: each move of the hybrid map is a run of the machine of at least one step, its halt is a halting configuration, and therefore, in plain words, the machine halts from blank tape if and only if the hybrid orbit of the start node D(1,0) reaches halt (halts_iff_hybrid). Nothing is assumed. Also proved: as long as the orbit of F is not stuck, the hybrid orbit is exactly the orbit of F (hrun_of_orbit), which with orbit_native covers the first 3·107 nodes. What this does not give: any understanding of the uncovered nodes. After one, the hybrid map simply is the machine. The theorem removes the hypothesis from the statement, not the question whether an uncovered node is ever reached.

Heuristic
this page
What the uncovered nodes do

Tried on 12 November: 3,000 random nodes with small environments (gaps 0 to 7, blocks of 0 to 3 pairs, up to four blocks). On every node where F has a rule, the machine does reach the node F names (2,124 nodes, no mismatch). On the 876 nodes without a rule the machine reaches another node of the three shapes in every case (832 times a drain D, 21 times T, 18 times the parity tail P) or halts (5 times); it never leaves the three shapes. So the map could be completed by more rules, but the uncovered nodes fall into several hundred classes (445 by a coarse count of shape, size class and first two blocks), mostly a block directly after the head or after another block. Excluding them by an invariant looks as hard as the halting question itself: the uncovered cases T next to a gap of 3 or 4 sit right beside the halting case T next to a gap of 2.

Heuristic
py/drain.py run 1e12
The run is self-similar

A fresh run inside a gap repeats the run from blank tape until it reaches the block after the gap. The top level makes gaps of 392, 320, 124, 348 (by step 2.1·108), 22,456, 36,678 and 60,524 zeros (steps 4.2·109, 5.5·109, 1012), and inside each large gap the copy makes gaps of 392, 320, 124, 348 again. None of the small ones is a fatal size; the run went past the gaps of 22,456 and 36,678 without halting.

Open
Does it halt from blank tape?

Not known, and Collatz-like. It halts if and only if a drain somewhere ends exactly three cells short of the block to its right; at the top level that cannot happen, so it needs one of the gaps the run makes to have a fatal size for a run started from scratch, and both sequences come from the same counter. The fatal sizes thin out while the gaps grow, so a hit looks unlikely; nothing proves it never comes. The rules are chained in Lean (lean/Chain.lean): the question is exactly whether the orbit of one explicit map reaches halt, given that it never reaches a node no rule covers; that hypothesis and the orbit itself are open. By halts_iff_hybrid the reduction to a map now has no hypothesis, at the price of a fallback to plain machine steps on nodes no rule covers.
