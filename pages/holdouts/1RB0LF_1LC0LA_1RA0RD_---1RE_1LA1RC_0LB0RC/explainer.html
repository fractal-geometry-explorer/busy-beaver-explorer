Five levels

From six states to one number

The question "does this machine halt?" is answered here by walking down a ladder of five descriptions of the same run. Each level forgets detail that the level above keeps and has its own, longer unit of time. Each step down is a Lean theorem saying that one move at the lower level is a real run of the machine, at least one step long, from one configuration to the next. So a run that goes on forever at the bottom level is a run of the machine that goes on forever: the machine never halts. The badge on each card says what Lean used to check that step (Kernel: Lean's small trusted core; native_decide: a compiled program whose answer Lean takes on trust).

Level 1

The machine, and the one way it could halt

The table has one missing entry: D reading a 0. That is the only way to halt (step_none_iff, Kernel). The only transition into D is C reading a 1 (C writes 0, moves right, enters D), so a halt happens exactly when the head in state C sees 1 0. Lean also proves the short ways there (halt_C, halt_E, halt_F, halt_D in lean/Rules.lean, Kernel): C>1 0 halts after one step, E>1 1 0 and F>1 1 0 after two, D>1 1 1 0 after three.

The proof never looks for this pattern directly. It shows something stronger: from the blank tape, for every number n, the first n steps are all defined. That is the Lean statement ¬ HaltsFromBlank, where HaltsFromBlank means "some step reaches a configuration with no transition". In the first 2·108 steps the machine is in state D 22,202,037 times, every time on a 1 (c/visits.c, Computed).

From cells to a list of numbers

Watch the machine for a while (the simulator above) and most of the tape turns out to be long stretches of 0 1 0 1 0 1 …. Stop it at the moments when the head, in state B, stands at the left end of the written tape on a 0: the left-end moments. At those moments the tape reads

B>00(01) × a000(01) × b000(01) × c…

a list of numbers a, b, c, … written as stretches of 01, separated by short words such as 000, 00001000 or 11. The machine is a little computer working on this list. The first number a counts down, the second number b grows, and the short tail after them goes round in a cycle. The panel steps through the left-end moments of the run from blank tape and reads each tape as a list (two or more 01s in a row become a number, as in py/regimes.py).

Level 1 to level 2

Crossing a stretch in one move

Between left-end moments the head sweeps across the long stretches. A stretch of a million cells would take a million steps to simulate, but what happens to it is simple, and Lean proves it once for every length:

  • Going right (sweep_right): B, with a 1 just behind it, turns each block 010101 into 011001 and comes out the other side, again in state B, after exactly 14 steps per block.
  • Going left (sweep_left): C, with 110 ahead of it, turns each 011001 back into 010101, 22 steps per block.

Each is proved by running one block for real (rfl, so Lean's kernel computes the 14 or 22 steps) and then a general lemma, cross_r or cross_l, that says: if one copy takes the head through in the same state, n copies do too, in n times the steps. Kernel

Any number of blocks. Type a number of blocks n. The browser runs the plain machine on the rule's starting tape until the head comes out the far side in the starting state, and compares the step count and the tape with what the theorem says.

Level 2: the tape as a list, moved by moves

A round trip from a template is a claim about infinitely many tapes, one for each size. Lean cannot simulate them one by one. Instead it runs the machine symbolically: the tape is a list of tokens, single cells and stretches (01)n whose count n is a formula such as 3k + 7. The checker steps the machine on cells it can see. When the head meets a stretch, it tries one copy on its own (as in the panel above) and, if the head comes out the far side in the same state, crosses the whole stretch in one move. If it would need to know whether a count is 0 or not, it gives up and the check fails.

The checker is a program, auto in lean/SymCheck.lean, and it comes with a theorem, auto_reach, proved once by the kernel: if auto answers true for a start and a target, then for every value of the variables the real machine goes from the start to the target in at least one step. Kernel That is the step from level 1 to level 2: every move at level 2 is a run of the machine.

This page has its own small version of the same idea, the shift-rule simulator: the tape is a list of tokens with ordinary numbers as counts, a whole stretch is crossed in one move whenever one copy tried on its own takes the head through in the same state, and at each left-end moment the list is written in normal form again. It is not the Lean program, and it works with numbers rather than formulas, but it makes about as many moves (for example 140,054 from blank tape to step 1,277,431, where Lean's checker makes about 148,000). The one-moment panel checks it against the plain machine at every moment; the next sections use it to run round trips and epoch ends of any size.

Level 2 to level 3

One round trip, for any size

From one left-end moment to the next is a round trip: the head sweeps right to the far end of the tape and back. What it does to the list depends on the short tail, which takes one of 62 shapes (the 62 templates, named R0_0 … R3_8, see the next section). In each template the first two numbers are written with two free variables:

a = 3k + 4    b = 3j + β   (β between 6 and 8, fixed per template)

Lean proves, for each template t and for every k and j: a round trip takes template t with numbers (k + 1, j) to the next template nxt t with numbers (k, j + dj), where dj is a small constant listed for each template. So a drops by 3 and b grows by 3·dj. These are the 62 theorems round_0 … round_61, each a run of the symbolic checker of 200 to 2,500 moves, evaluated by the kernel. Kernel That is the step from level 2 to level 3: one round trip at level 3 is one run of the checker, so one run of the machine.

Level 3 to level 4

When the countdown runs out: from one epoch to the next

Round trips need k ≥ 1. When k reaches 0 (a = 4) the countdown cannot go on. What happens next has three parts, and Lean checks them together as one end case per template. We call the stretch between two such events an epoch.

  1. The reset (three returns to the left end). The last 4 copies of 01 in a are used up and the short word in front of b is rewritten. The old b ends up first in the list, with a few more copies. In the example below the new a is 724 + 6 = 730.
  2. The transient (up to about 145 round trips). Each trip still takes 3 from the new a, as before. But the tail of the list is in disorder after the reset, so it does not yet follow any of the 62 templates. The new b starts small and grows. Now and then two pieces of the tail merge.
  3. Settling. The tail falls into one of the four regimes, and the tape is a template again: endT t, with a new k that is large and a new j that is small.

Lean proves, for each template t and every j: from template t with numbers (0, j + 200), the machine reaches the template endT t with numbers (j + endC1, endC2). These are the 62 end cases, checked together as ends_ok: runs of the symbolic checker of 4,200 to 127,000 moves each, 2.5 million in all, evaluated by compiled code because the kernel runs out of memory on runs this long. native_decide That is the step from level 3 to level 4: an epoch is k round trips followed by one end case, and at level 4 the whole epoch is one move, from (t, k, j) to (endT t′, …) where t′ is the template reached at k = 0.

The first epoch end of the proof, in the real run. At step 1,908,405 the tape is template R1_10 with k = 0 and j = 239 (a = 4, b = 724). The proof's end case for R1_10 says the run reaches R1_16 with k = (239 − 200) + 81 = 120 and j = 259. Below, the browser runs the machine through it, from that step to step 4,054,968. The slider moves through every moment at which the head is back at the left end. The chart shows a (blue) and b (green) at each of those moments.

The reset, moment by moment. The four left-end moments from step 1,908,405 to step 1,946,128, as lists. Blue is the first count, green the second.

Why "j + 200". During the transient the new a, which comes from the old b, still loses 3 every round trip. It must not run out before the tail has settled, or the end case would be a different computation. The symbolic checker cannot ask whether a count is zero, so it needs a guarantee up front. The end cases are stated for an old b of at least 3 · 200 + β copies (j ≥ 200). The longest transient takes under 150 round trips, so it uses fewer than 450 of those copies. The potential (level 5) shows that j is always at least 200 when an epoch ends.

The second runs them on the shift-rule simulator at any j you choose. These are independent checks of the claims behind ends_ok, at one size each; Lean's check covers every size. Into level 4

Before the first template: the setup

The proof starts at step 1,277,431, not at step 0. The first 1,277,431 steps are the setup, and Lean checks them as one long computation: start_ok runs the symbolic checker from the blank tape to template R1_16 with k = 38, j = 163. The sweep rules let it cross long stretches in one move, so that takes about 148,000 symbolic moves. native_decide This is how the run enters level 4: from there on it is a sequence of templates.

What happens in the setup? The machine does the same things as later, at small sizes. From the start the left-end list counts down a by 3 per round trip, and resets when a runs out. So the setup is a series of short epochs (the table below lists their resets), each roughly twice as long as the one before. In the early ones the numbers are too small for the tail to settle into a regime. The first time the tape fits one of the 62 templates is step 1,277,431, in the epoch that began at step 503,461. That is where the proof takes over.

Level 4 to level 5

Why there is always enough room

The end cases need j ≥ 200 at the moment k reaches 0. The proof gets this from a potential, a single number for each good tape:

Φ = j + 2k + pot(t)

where pot(t) is a number between 0 and 15 listed for each template (potL in lean/Tables.lean). Two facts about the tables, both checked by Lean's kernel (tables_ok) Kernel:

in a round trip
k drops by 1 (Φ loses 2), j grows by dj, and pot changes; the tables satisfy pot(t) + 2 ≤ pot(nxt t) + dj(t), so Φ never decreases.
after an epoch end
the new values give Φ ≥ endC2 + 2·endC1 + pot(endT) ≥ 215 for every template.

So Φ ≥ 215 on every good tape. At an epoch end k = 0, so j ≥ 215 − pot(t) ≥ 215 − 15 = 200, exactly what the end cases need. That is the last step down, from level 4 to level 5: the whole run is now one number that never falls below 215. The bottom line

It never halts

It never halts. Started on a blank tape, the machine 1RB0LF_1LC0LA_1RA0RD_---1RE_1LA1RC_0LB0RC runs for ever.

The Lean theorem is H36670.nonhalting : ¬ HaltsFromBlank in lean/Cert.lean, where HaltsFromBlank is defined from the machine's transition table in lean/Machine.lean.

What it rests on. Lean's kernel checks everything except two evaluations: start_ok (blank tape to the first template, about 148,000 symbolic moves) and ends_ok (the 62 end cases, 2.5 million moves), which are run as compiled code with native_decide because the kernel runs out of memory (over 6 GB) on runs this long. #print axioms H36670.nonhalting lists propext and Quot.sound, two standard axioms of Lean's logic, and the two native_decide axioms, one for each of those evaluations. Nothing about the run is assumed: a wrong number in the tables would only make a check answer false. native_decide

The argument in one picture

The proof is an invariant: a description of a set of tapes, called good, with three properties.

  1. The run reaches a good tape. From the blank tape, after 1,277,431 steps, the tape is good.
  2. A good tape always leads to another good tape. From any good tape the machine makes at least one step, without halting, and arrives at a good tape again.
  3. So the machine never halts. Repeating the second property forever gives runs of every length, and a machine that halts has runs of only bounded length.

What makes a tape "good" is levels 3 to 5 above: it is one of the 62 templates, a list of numbers written on the tape in a fixed pattern, with two of the numbers free (k and j) and the size condition Φ ≥ 215 on them. The second property then splits into finitely many checks, one per template and case.

Who checks the computations

Each round trip and end case becomes a computation: "does auto answer true on this input?". Who runs that computation is the one place where the proof uses two levels of trust:

decide +kernel
Lean's kernel evaluates the program itself, step by step. This is the most trusted way, and it is used for the 62 round trips and the potential tables.
native_decide
Lean compiles the program to machine code and runs it. The kernel then accepts the answer as an axiom. Used for the start (about 148,000 symbolic moves) and the 62 end cases (2.5 million in all), because the kernel ran out of memory (over 6 GB) on runs that long.

nonhalting_of
