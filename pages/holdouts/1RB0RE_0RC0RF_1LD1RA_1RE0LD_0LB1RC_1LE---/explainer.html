Does this machine ever halt?

1RB0RE_0RC0RF_1LD1RA_1RE0LD_0LB1RC_1LE---

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows. Between its rebuilds this machine is a binary counter that applies one small operation to a list of blocks at every tick, and the list is, read in binary, the time left until the next rebuild. Every step of this, the irregular sub-rounds after each rebuild included, is one simple sweep machine, now proved in Lean for every size. This page runs the machine, lets you step the list, the counter and the sweep machine, and lists what is known.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from B1 (writes 0, moves R): B>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The picture

A binary counter that rewrites a list

Stop the machine each time the head is in state C on a 0 just right of a 1. The tape is then a list of blocks of 1s separated by single 0s, a last block, and right of the head a zone of single 1s. From one such moment to the next (a sub-round) two things happen, and they do not influence each other.

The list takes one step. Its last block, of 3a + 2 cells, gives 3 cells to the block on its left and falls apart into a blocks of 2: x, 3a+2 becomes x+3, 2, ..., 2. Counting a block of 3a + 2 as the digit a: the last digit a is removed, the digit before it grows by 1, and a zeros are appended.

The counter ticks. The last block and the zone hold a binary counter. A round is 2m sub-rounds in which they fill 4m + 1 cells; then the last block is 4m + 5 cells and round m + 1 starts. This is why each round takes twice as long as the one before.

The list gets shorter in the end, and how long that takes can be read off it: a list with digits a1, ..., ak is a single block after exactly T steps, where T has a binary 1 at the positions ak, ak + ak−1 + 1, ak + ak−1 + ak−2 + 2, and so on. The list is the time it has left, written in binary. Try it:



The start values are the tape at step 2,918 from blank tape (last block 9, so round 2). All of this was first read off the run and checked against the machine; it is now proved in Lean for every size: one sub-round is W on the list and one step of the counter (subround), and W lowers T by exactly one (T_W), so the single block comes after exactly T sub-rounds (collapse).


Rebuilds. When a single block of 3(k + 1) cells is left, one sub-round cuts it into 3 2^k (proved), and the last block leaves a new gap in the zone. On its own that would bring back the same single block after 2k sub-rounds. What makes the list longer is a cascade of small gaps: when the counter's carry reaches the new gap after it has shrunk to 1 or 2 cells, cells of the counter move into the list. These few dozen sub-rounds per rebuild (the transient) are not W and the counter, but they are the same sweep machine (next section), proved for every size. The first rebuilds:

  Every sub-round
  
One sweep machine, small gaps included


W on the list and the counter are not the whole story: after each rebuild come sub-rounds where the counter meets a gap of 1 or 2 cells and cells of the counter move into the list. All sub-rounds, these included, are one and the same procedure, now proved in Lean for every size and every tape (lean/General.lean).


The left sweep. The head runs left, erases the last block, moves the block before it one cell to the right and adds 3 cells to the block before that. Then it turns right in state A, in front of the moved block.


The right sweep reads the tape in one of three phases A, E, C, with an open block: the 1s just left of the head. On a 1, A writes 0 (the open block closes) and E and C keep the 1; the phase goes A, E, C, A, so a block of 3a + 2 ones becomes (011)^a 01: that is W. On a 0:


  • C after a non-empty open block: the sub-round is over, the open block is the new last block;
  • C or E next to an empty open block: the two cells become 11;
  • E after an open block, or A on 010: the open block moves one cell to the right, the block before it grows by 3, and A starts again in front of the moved block;
  • A on 000: 111, then C (the counter's carry through a gap of 3: 0001 becomes 1111);
  • A on 001: 101, the open block closes at the middle cell and becomes a block of the list (a small gap of 2);
  • A on 011: the machine halts. This is the only way it can halt.

  Halting
  
Why it is hard to settle


The machine halts only in state F reading a 1. In a sub-round between rebuilds that does not happen (proved). In the irregular stretch after a single block it can: the tape 1^(3k) 0 1^(4k−3) C>0, a single block of 3k cells arriving exactly when round k − 1 of the counter starts, halts for k = 3, ..., 9 (311, 659, 1,343, ... steps; each about twice the one before).


So the question is one about two binary numbers: the time T the list needs, which is written in the list itself, and the state of the counter. The run from blank tape has passed 986 rebuilds, more than 1031,896 steps, without a halt. The first 200 rebuilds are proved in Lean. Where the counter stands when the single block arrives now has a rule (below), checked rebuild by rebuild in Lean and for every case by a symbolic check in Python.





  The rebuild map
  
From one single block to the next, as arithmetic


When a single block arrives the counter has always been regular so far, so the moment is three numbers: the single block of 3(k + 1) cells, and the counter in round m with r sub-rounds left. The few dozen sub-rounds with small gaps after the rebuild (the transient) look complicated on the tape, but they follow a simple law: they read only the lowest bits of r.


Read r in groups of three bits from the lowest, each group a value 0 to 7. Start in state A of the automaton below and follow one group at a time; where it says stop after J groups, the transient has read exactly those 3J bits. It then has moved 4J − 1 cells' worth of the counter into the list (the next single block has 3(k + 4J) cells), left the counter regular in round m − 3J + 1 with 2(⌊r/8J⌋ − 1) sub-rounds to go, and left a list whose time is 2k+4J−1 − 1 minus a small deficit that depends only on the word read. The rest is counting: the next single block arrives after that many sub-rounds, which puts the counter in a round m′ with r′ left.

This map gives the run's rebuild states exactly at every rebuild checked (4 to 200 against the run), reaches rebuild 986 in half a minute and rebuild 2,000 in a few minutes, without a halt. In Lean it is a checked map: given a hint, the kernel runs the transient on the few blocks and gaps it touches, proves that nothing further out matters, and does the rest as arithmetic on k, m and r. That is how the run is proved to rebuild 200 (a single block of 54,075 cells). 


Why the automaton? Between two groups the transient always pauses in one of ten shapes: the sweep in mid-tape, waiting on the next bits of the counter, with one or two blocks of the list in front that it is still working on and the rest of the list beyond. Each shape is a family (its front block can be any of 1, 13, 25, ... cells, say), and each automaton state is one of these shapes. A program that handles the blocks as formulas in the family's parameter, and the rest of the list as an unknown number, runs every shape on every group value, for every parameter value at once: 516 cases, and the shapes it lands in give the automaton's table exactly. None of the cases halts. So the machine could only halt in a transient that runs past the top of the counter, or with a list too short for its transient; whether the run of the map ever gets there is now a question about the three numbers k, m and r. This check is done in Python; turning it into a Lean proof is the next step.

holdouts/1RB0RE_0RC0RF_1LD1RA_1RE0LD_0LB1RC_1LE---/py/model.py (check 300000)
Between rebuilds: a binary counter that applies one list operation per tick
At the moments the head is in C on a 0 just right of a 1, the tape is a list of blocks of 1s separated by single 0s (the interior), a last block l, and to the right of the head a zone of single 1s. Call it regular if the first block is a multiple of 3, the other interior blocks are 2 mod 3, l is 1 mod 4, and the gaps of the zone are 0 mod 4 (the first, counted from the head) and 3 mod 4 (the others). From one such moment to the next (a sub-round) a regular configuration changes in two independent ways. The interior takes one step W: (..., x, 3a + 2) becomes (..., x + 3, 2, ..., 2) with a blocks of 2. The last block and the zone are a binary counter: with segments s1 = g1, si = gi + 1, a last block l ≥ 5 becomes a new first segment l − 1 and l = 1; with l = 1 the n leading segments equal to 4 are removed, the next segment loses 4 cells (blank tape supplies them if there is none) and l = 4n + 5. So l plus the segments is 4m + 1 for 2m sub-rounds (one round, what earlier notes called the fast counter), then m grows by 1. Checked against the machine one sub-round at a time: of the 300,000 sub-rounds after step 2,918 (12.6 million steps) the 299,954 regular ones all follow this; the other 46 are the transients of the first two rebuilds. The rules are now proved in Lean for all sizes (the claims below); this check of the machine stays as a test.

    
Computed
holdouts/1RB0RE_0RC0RF_1LD1RA_1RE0LD_0LB1RC_1LE---/py/model.py (check 300000, partial, rounds)
The binary expansion, checked on the machine
With digits ai = (bi − 2)/3, W removes the last digit a, adds 1 to the digit before it and appends a zeros; the sum of all digits plus their number never changes. A tail (..., q, a) becomes (..., q + a + 1) after exactly 2a steps, so an interior with digits a1, ..., ak is a single block after exactly T = Σi 2ai + ... + ak + k − i steps of W: the positions of the 1s in the binary expansion of T are the partial sums of the list read from the right. Checked on the machine: the model predicts single blocks at sub-rounds 1,616 and 261,907 of that run and both are there; W steps and counter steps taken many at once agree with the machine in 28 test jumps; and after the third rebuild the lists at seven ends of rounds, up to step 2.8·1010, are those of a direct run of the machine (3 2^25 14 2 8 2 14 | 85 at step 22,558,329,286, ..., 3 2^12 20 2^6 14 2 8 2 14 | 109 at step 28,107,393,382).

    
Kernel
glong, gshort, gzero in lean/Subround.lean (generated by py/gen_subround.py); subround in lean/Collapse.lean
Every sub-round of the regular kind, for all sizes
Five machine rules, each for every value of its parameters and every tape further out: glong (last interior block 3a + 2, last block b + 2: W on the interior, the last block becomes 1 and a new zone gap of b + 1), gshort (last block 1: the carry removes the leading gaps of 3, takes 4 cells from the next gap, which has at least 4, and sets the last block to 4n + 5), gzero (the carry meets two 1s side by side before a gap of at least 2: last block 4n + 4), and the two rebuild sub-rounds below. Put together (subround): at the moments the head is in C on a 0 right of a 1, a configuration 1^(3q) 0 [digits] 0 1^l C> [gaps] with at least one digit goes in one sub-round to W of its digits and one step gstep of the counter, which is defined for every last block and every zone except at the small gaps (a carry meeting a gap of 1 or 2 cells, or two 1s side by side before a gap of 0 or 1). The rules are proved by rfl steps, the crossing lemmas and omega; the earlier observation that W and the counter do not influence each other is now a theorem.

    
Kernel
T_W, collapse, regular_total, collapse_regular, lean/Collapse.lean
The list is the binary expansion of the time it has left
With T(x :: r) = 2^x (1 + 2 T(r)) on the digits listed nearest the head first, W lowers T by exactly 1 and keeps the first block plus the digits plus their number (T_W, mass_W). So from any configuration of this shape the machine reaches the single block of 3 · mass cells after exactly T sub-rounds, the counter advanced T times, if the counter meets no small gap on the way (collapse; advance for fewer sub-rounds). A regular counter (last block 1 mod 4, every gap 3 mod 4: the binary counter of the picture) never meets one (regular_total), so from a regular configuration the collapse always happens, without a halt (collapse_regular).

    
Kernel
rebuild, rebuild_one, rebuild_cycle, lean/Collapse.lean
The rebuild sub-round, and why single blocks grow
A single block of 3(k + 1) cells with last block b + 5 becomes 3 2^k with last block 5 and a new zone gap of b cells in front (rebuild, rule single); with last block 1 and a first gap of at least 2 it becomes 3 2^k with last block 4 and the first gap 2 shorter (rebuild_one, rule singleone). The digits of 3 2^k give T = 2k − 1 and mass k + 1, so if the counter meets no small gap the single block comes back with the same 3(k + 1) cells after 2k sub-rounds (rebuild_cycle). The single blocks of the run grow (36, 57, 90, ...) only because small gaps move cells of the counter into the list; the new gap a rebuild makes (b, a multiple of 4 when the last block is 1 mod 4) is where the first small gap comes from.

Kernel
pstep_next, pstep_done, pstep_halt, sub_moment, sub_halt, subs_moment in lean/General.lean; the moves in lean/Pass.lean
Every sub-round, small gaps included: the pass machine
At every moment (the head in C on a 0, a last block l on its left, then any blocks of 1s separated by single 0s, and on its right any zone of gaps) the next sub-round is the same two sweeps. The left sweep (start) erases the last block, moves the block before it one cell to the right and adds 3 cells to the block before that. The right sweep reads the tape in one of three phases A, E, C (the machine states) with an open block, the 1s just left of the head. On a 1, A writes 0 (the open block closes, an empty one opens) and E and C keep it; the phase goes A, E, C, A. On a 0: C after a non-empty open block is the next moment (the open block is the new last block); C or E next to an empty open block fill two cells; E after an open block, and A on 010, move the open block one cell right, add 3 to the block before it and start again in A; A on 000 writes 111 and goes on in C; A on 001 writes 101 (the open block closes at the middle cell); A on 011 halts. Each move is a machine rule proved for every size (lean/Pass.lean, generated by py/gen_pass.py); pstep puts them into one total function, and sub_moment and sub_halt prove that a sub-round it computes is a run of the machine with exactly its number of steps, and that a halt it finds is a halt of the machine. So the halts of the machine are exactly the carries that meet 011 in phase A. W on the list and the binary counter (the rules above) are the cases where the right sweep only meets blocks 2 mod 3 and gaps 3 mod 4; the small gaps are the moves A on 001 and 010, which move cells of the counter into the list.

The rebuild map, checked: the run from blank tape to rebuild 200, without a halt in more than 105,425 steps
Three pieces make a rebuild cost the kernel only the transient, on short prefixes, whatever the size of the single block. Frames (lean/Frame.lean): a stretch of the pass machine or of the counter computed on the first blocks of the list and the first gaps of the zone (subsF, gfastF, which return none when a move would need more) holds for every tape further out, and T(F ++ X) = T(F) + 2σ(F) T(X). The counter as a number (lean/Bits.lean): cz m r is the regular counter in round m with r sub-rounds left, built from the bits of r; it is cut at a 0 bit into a low part the transient reads and a tail it never touches (cz_split), put back together after the transient (cz_join), and N counter steps are arithmetic on it (giter_cz). The checked map (lean/Map.lean): rstep takes a rebuild state (k, m, r) and a hint (where to cut the counter, how many digits of the list to keep, the stretches of the transient, the next round), runs the rebuild, the transient on the prefixes and the collapse, and returns the next rebuild state or none; rstep_sound: whatever it returns is reached by the machine, without a halt. When the counter has no 0 bit above the bits the transient reads, the zone is evaluated to its end (no tail on the right). lean/MapRun.lean (generated by py/gen_map.py 200, which computes the hints with Python mirrors of these functions) gives the 197 rebuild states from the third single block (rcfg 29 28 28950) to rebuild 200 and the kernel evaluates rstep once per rebuild. single_map_200: the run from blank tape reaches the single block of rebuild 200, 54,075 cells, the counter in round 18,024 (so more than 218,024 sub-rounds, more than 105,425 machine steps), and does not halt before it. This replaces the chain of segments to rebuild 40 (lean/Chain.lean, 3 minutes of kernel time; the map gets there in 21 seconds and to rebuild 200 in about 8 minutes, most of it in the few long transients). Its two lemmas stay in use: scaling (giter_scale, gfast_sound: with 4j more cells in the last block one counter step takes 2j) and part of a collapse (advance_to: after M sub-rounds the digits are the only list D′ with T(D′) + M = T(D)).

    
Heuristic
holdouts/1RB0RE_0RC0RF_1LD1RA_1RE0LD_0LB1RC_1LE---/py/rebuild_map.py (check-run 200, check-local 1000, auto)
How the small gaps evolve after each rebuild: a map on three numbers
At every rebuild from 4 to 200 the counter is regular when the single block arrives, so a rebuild state is three numbers: a single block of 3(k + 1) cells and the counter in round m with r sub-rounds left (the bits of r, lowest first, are the gaps of the zone). The transient (the sub-rounds with small gaps after the rebuild) follows a law that only the lowest bits of r decide. It reads the lowest 3J bits of r, and nothing else decides J: read in groups of three bits (value b0 + 2b1 + 4b2, lowest group first), the words where it stops form a prefix code recognized by a 7-state automaton (start in A, AUTO in py/rebuild_map.py). The list gains 4J − 1 units, so the next single block has 3(k + 4J) cells; the counter is regular again in round m − 3J + 1 with 2(⌊r/8J⌋ − 1) sub-rounds left; and the list left has time T = 2k+4J−1 − 1 − e(w), with a deficit e that depends only on the word w of those 3J bits. The collapse then takes T sub-rounds (proved), so the next rebuild state is arithmetic: V = 2m−3J+2 − 2(⌊r/8J⌋ − 1) + T, m′ = ⌊log2 V⌋, r′ = 2m′+1 − V. Checked: the map gives the rebuild state of the run exactly at all 197 rebuilds from 4 to 200 (check-run 200); on 1,000 random rebuild states J, e and r′ do not change with k or with the bits above w, and the automaton gives J (check-local 1000). For every word the automaton, the counter after the transient and the absence of a halt are now checked by a symbolic case analysis (next); the closed form of T, with e depending only on w, is checked on random words only, and in Lean each transient is still evaluated (below).

The rebuild law for every word: a symbolic case analysis of the transient
Fed the counter's bits three at a time, the transient stops between two groups at a frontier: the pass machine in mid-sweep, in phase A or C, waiting on the last gap of the zone (the bits above may still add to it), which is then a single gap of 0, 1 or 2 cells; the list there is a front of one or two blocks and a history of digits beyond them. Ten shapes of frontier occur, each a family with at most two parameters (the front block grows by 12 cells per loop). py/sym_law.py runs every shape on each of the 8 group values for every value of its parameters and every history: the moves of the pass machine on blocks that are affine in the parameters and on runs of equal blocks of any length; the regular sub-rounds as arithmetic on the list read as a number, 2q at a time as in gfast; the history as an unknown number whose digits are read only when a move needs one; a loop that eats a run of any length taken at once, after checking one turn from the general state (induction); and a case split wherever the parameters do not decide a move. All 80 pairs resolve, in 516 cases: none halts, each lands in one of the ten families or ends the transient, and which one does not depend on the parameters or the history, except at the stop shape. Named by the automaton state each shape is equivalent to, the shapes give exactly the table of the automaton, which stops when the front of the list reaches 4 3; after the stop the transient reads zero groups and one more nonzero group (two after a 1) and ends. The start (the rebuild sub-round and the first groups, for every number z of leading zero groups, when k ≥ 3z + 14) lands on the shape the automaton reaches from A, and at all 27 end cases the counter is the law's, round m − 3J + 1 with 2(⌊r/8J⌋ − 1) sub-rounds left. So for every word the automaton gives J, the counter after the transient is the law's, and the transient does not halt, as long as it ends below the top of the counter and the list is long enough for it; the list's time left after the transient is arithmetic on k and the word. Tests: the same engine run with concrete histories gives J, T and the length of the list of py/rebuild_map.py on 1,000 random rebuild states, and every case, instantiated, agrees with the concrete run on 4,000 random parameter values and histories. A Python check, not a Lean proof: the engine's rules are the Lean lemmas (pstep, gfast, T_append, the frames), but the engine itself is not verified.

Does it halt from blank tape?
Not known. Every sub-round is proved, with its exact step count, and the only halting move is a carry that meets 011 in phase A (a gap of one cell followed by two 1s side by side). Tapes of the same shape do halt that way (the halting family above ends with the zone ... 3 3 1 0). So the question is arithmetic: whether the single blocks and counters that this run produces ever lead a carry to such a place. The halting family needs the single block to arrive exactly when a round of the counter starts, a coincidence of two binary numbers that the run has avoided so far. The rule for the counter at the moment the single block arrives is now found: a rebuild is a map on three numbers (above), proved in Lean as a checked map and run by the kernel to rebuild 200 (more than 105,425 steps). The law for every word of the automaton is now checked by a symbolic case analysis in Python (above, not yet in Lean), and in it no transient halts. So the machine can halt only where that analysis does not reach: a transient that runs to the top of the counter (the automaton has not stopped within its m bits, as in the halting family, where the single block meets the counter at the start of a round) or a list too short for its transient. Whether the run of the map, pure arithmetic on k, m and r, ever gets there is the open question.
