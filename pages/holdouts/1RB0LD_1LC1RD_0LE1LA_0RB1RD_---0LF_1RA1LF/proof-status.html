OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open, and reduced in Lean to a question about one carry chain. The tape is a row of blocks of 1s with one moving gap; Lean proves (kernel) that the machine follows a block machine and halts if and only if the block machine halts (halts_iff), which happens exactly when a sweep reaches the left end of the tape carrying a block whose size is a power of two (mstep_halt_iff, wall_chain, wall_odd). With native_decide: no halt in the first 2.2·1014 steps. The block machine run in C: no halt in the first 1011 sweeps (1.95·1022 steps); only 17 sweeps in all reached the left end, carrying 3, 3, 7, 9, 25, 23, 26, 106, 1292, 649, 7148, 94000, 281084, 6578056, 283561618, 7939115926, 10931368378, none a power of two.

kernel Proved in Lean, kernel-checked

The halting configurations

The machine stops exactly when it reads the symbol of a halting transition (E0).

step_none_iff, lean/Blank.lean

The rules of a gap

With the tape a row of blocks of 1s separated by single 0s and one gap 0 B>0: a round takes two 1s off the block left of the gap and gives one to each neighbour (2b + 5 steps), for every b and every surrounding tape; m rounds at once; an even block is used up and the gap moves on to the next block left; an odd block keeps one 1, the gap closes (1 0 0 becomes 1 1 1), D runs to the right end of the tape and opens a new gap there.

round_gap, rounds_gap, even_gap, odd_gap, drun, lean/Macro.lean

The block machine

mstep maps one gap configuration (b, ls, rs) to the next, with its step count mcost; the machine follows it (mstep_sound), and where it says halt the machine halts (mstep_halt). From blank tape the first gap 1^3 0 B>0 comes after 7 steps (init_gap).

lean/Macro.lean, lean/Reduce.lean

The rules cover the whole run

Every block holds at least one 1 except the one just right of the gap; this is kept by every macro step, so the block machine never reaches a case the rules do not cover.

inv_next, mrun_ne_stuck, lean/Reduce.lean

Halting reduced to the block machine

The machine halts from blank tape if and only if the block machine, from the first gap, reaches halt.

halts_iff, lean/Reduce.lean

Where it halts: a power of two at the left end

Under the invariant the block machine halts exactly at gap 1 [] rs: an odd block that kept a single 1 with nothing left of it. A block 2k·q (q odd) reaching the left end halves k times, each half becoming a new leftmost block (wall_chain), and then q halts iff q = 1 (wall_odd). So the machine halts iff some sweep reaches the left end carrying a power of two.

mstep_halt_iff, wall_chain, wall_odd, lean/Reduce.lean

heuristic Evidence only

Why it probably never halts

A sweep reaches the left end only when every block it meets is even, like a carry running through every digit of a counter; such sweeps come ever more rarely (each between 1.4 and 30 times as many sweeps after the one before), and the block they carry grows like the number of sweeps. If its size behaves like a random number, the chance that it is a power of two is about log2v / v, and the expected number of halts still to come, with v already above 1010, is about 4·10-9.

Does it halt from blank tape?

Open: equivalent (in Lean) to whether a sweep ever carries a power of two to the left end. The carried values depend on the parities of all blocks, a Collatz-like question with no visible invariant that excludes powers of two.
