A 6-state Busy Beaver machine · Status as of 13 November 2026.

Does this machine ever halt?

1RB0RD_1RC0LF_1LA0LB_---1RE_1LB1RA_0LC0RA

It never halts, and Lean proves it. Two long blocks on this machine's tape act like two buckets: at every visit of the left end a little is poured from the left one into the right one, which grows about twice as fast as the left one shrinks. When the left one is empty the right one takes its place. A short stretch at the right end, the tail, decides how much is poured; at the end of a round it is always one of 62 words, and from none of them does the machine stop.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in D reading 0. D is entered only from A1 (writes 0, moves R): A>1 0. So a halt is the moment this pattern appears, with the head on the cell after >.

The tape

Two blocks and a tail

Seen at the moments when the head (in state A) arrives at the left end, the tape is always

010 (01)^a 000 (01)^b T

Here (01)^a means the pair 01 written a times. The left block has a pairs, the big block has b pairs, and T, the tail, is a short word made of a few small blocks of pairs separated by 000 or 111. Example, step 9,932,715,748: a = 2,110, b = 56,419, and the tail has blocks of 4, 13, 16 and 20 pairs.

One visit: the head crosses the whole tape to the right and back, twice. On the way it takes exactly 3 pairs from the left block, and the tail changes a little: its small blocks shrink by 3 pairs each, a block that is used up merges into its neighbour, and from time to time a block is absorbed into the big block. The five crossings of the two long blocks are proved in Lean for blocks of any length.

Within a round

The tail runs in a cycle

The tail does not grow. After a start-up of some dozens of visits it repeats with a fixed period, and in one period fixed amounts leave the left block and enter the big block. Four such cycles occur:

Each line was established by running the machine symbolically: the two block sizes are left as unknowns, and the simulator stops if any step would depend on their values. A run that comes back to the same tail is therefore valid for all sizes at once.

From round to round

When the left block is empty

A round ends when the left block is down to one pair: the tape is then

01001000 (01)^B T

and during the next two visits the big block (B pairs) becomes the new left block, of B + 3 pairs, with a new small big block. So each round is 2.06 to 2.2 times longer than the one before. Sizes B at the round ends: 586, 1,291, 2,827, 6,280, 12,967, 28,531, …

What the next round end looks like depends on two things only: the tail T, and at which point of its cycle the tail is when the left block runs out. The second is decided by the remainder of B when divided by the amount a period eats (45, 48, 66 or 27). The size of B beyond that plays no role, and that is what makes a finite analysis possible.

The argument

A closed set of 1,144 classes

Call a class all round ends with a given tail T and a given remainder of B (and B at least 20,000). For one class the symbolic simulator runs one whole round with B = r + m·x, where x is an unknown. The result is the next round end: a new tail T' and a new size B' = k + c·x. Whatever x is, B' has one of a few remainders; all of them are put on the list of classes to examine. Nothing about x is remembered, so the list over-counts what the real run can do.

Starting from the round end the real run reaches after 2,340,515,329 steps (B = 28,531), this search stops by itself: 62 tails, 1,144 classes, and every class leads only to classes already on the list. In none of the 1,144 symbolic rounds does the machine reach its halting transition (state D reading 0). So the machine never halts.

The remainders are not a hidden Collatz problem here: the search never asks which remainder comes next in the real run, it accepts all of them.

How sure

What this rests on

The closed set was found by our own symbolic simulator. It is now also a Lean proof: a second program of the same kind (a symbolic executor: it crosses whole blocks at once and applies a proved cycle many times in one go, a number of times that may depend on the unknown x) is written in Lean and proved correct once: whatever it does, the machine does, for every x. Lean then runs it on each of the 1,144 classes with x unknown, 133 million moves in all, and on the run from blank tape, and checks by a proved test that every round end it arrives at is on the list. Those runs are done by compiled code (native_decide), the one thing trusted beyond Lean's kernel.

What was done before that to test the first simulator, and still supports the step counts quoted here:

  • 1,302 consecutive rounds of the real run, with block sizes up to 437 digits, were compared with the classes: next tail, next size and number of steps agree exactly.
  • Ten symbolic rounds were replayed cell by cell by a plain simulator (about 4 billion steps each): same tape, same head position, same step count.
  • 20 deliberate errors were planted in the certificate and in the simulator; the checker reported all 20.
  • A separate checker re-runs all classes and tests that the set is closed without using the search.

Lean's kernel alone proves the five sweeps for blocks of any length, the executor's correctness, and the last step of the argument: a closed set of round ends that the run enters implies that it never halts.

A warning

Nearby tapes do halt

The shape 01001000 (01)^B T alone does not keep the machine running. Take one of the 62 tails and make one of its small blocks one pair longer or shorter: of 1,141 such classes tried, 1,136 fall back into the closed set after one round, but 5 halt, for every size B. One of them, checked cell by cell: with the tail 0000 (10)^10 000 (10)^4 000 (10)^12 111 0000 101 (the last block has 12 pairs; the real run has this tail with 11) and B = 20,002 the machine halts after 815,565 steps.

So the argument really needs the exact list of 62 tails; a statement about all tails would be false. Other remainders of B for the 62 tails are harmless: all 1,722 classes tried fall into the closed set.

nonhalting_of_closed_set, lean/Closed.lean
A closed set of round ends implies that it never halts

If the run from blank tape reaches a round end A> 01001000 (01)^B T that belongs to a set S, and every round end in S reaches a round end in S after at least one step, then the machine does not halt. Its two hypotheses are proved by the replay below.

Kernel
lean/Exec.lean, lean/Classes.lean; shRTbl_ok, shLTbl_ok in lean/ExecData.lean
A symbolic executor and the two class tests, proved sound

The executor of 1RB0RC_0RC1RC_0LD0RA_1LE0LF_0LA1LC_---1LA, adapted: tapes of cells and blocks (w)^n with n = c + a·x; shift rules with a carried word, one to three copies at a time; one machine step; at each arrival of state A at the left end a re-bracketing and a cycle rule applied N times, where N may itself be a count N0 + q·x (the subtraction is checked coefficient by coefficient). Any step that would depend on x fails. Theorems: whatever the executor does, the machine does, for every x (run_sound); a class whose run ends at the announced round end does so for every x, in at least one step (clsRun_sound); the coverage test, a finite check over one period of the remainders, implies that every announced B lies in a listed class (covers_sound); a list that passes both is closed (closed_of_checks). The 15 shift rules are proved by evaluation in the kernel.

py/closure/closure.py, py/closure/cert.json
The closed set: how it was found, step counts

A class is a tail T (62 of them) and a remainder of B (modulo 66: 682 classes; 45: 300; 48: 144; 27: 18), with B ≥ 20,000. For each class one symbolic round with B = r + m·x, x free, ends at 01001000 (01)^B' T' with B' = k + c·x (c = 141, 99 or 57, k ≥ 41,224); every remainder B' can have lies in a class again. The simulator refuses any step whose outcome depends on x. closure.py check re-runs all classes and tests the coverage independently of the search (5 minutes). That the set is closed is now a Lean theorem (above); this tool found it and supplies the step polynomials.
