What is known about 1RB0LE_1RC1RA_1RD0RF_1RE0RA_1LA1LD_1RA---

1RB0LE_1RC1RA_1RD0RF_1RE0RA_1LA1LD_1RA---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. The head sweeps across the whole tape. Read at the left end, the tape is a long list of numbers, each written as a run of the word 1 0 0; the sweeps count the first number down while the list grows at its other end, so the machine behaves like a queue of counters. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. Lean proves the exact way a halt would happen (A>0 0 1 1) and how the sweeps cross the counters; the C simulator finds no halt in the first 1011 steps. The rule that produces new counters at the end of the list has not been worked out.

The halting configurations

The machine stops exactly when it reads the symbol of a halting transition (F1); the generated statement covers every configuration.

step_none_iff, lean/Blank.lean

How a halt comes about

F reading 1 is the only halt. F is entered only from C reading 1, C only from B reading 0 and B only from A reading 0, all moving right (enter_F, enter_C, enter_B). So a halt is exactly C>1 1, that is B>0 1 1, that is A>0 0 1 1.

halt_F, halt_C, halt_B, halt_A, enter_F, enter_C, enter_B, lean/Halt.lean

Crossing the counters

For every n and every surrounding tape, moving right: A turns (0 0 1 0 0 1)^n into (1 1 0 1 1 1)^n, F turns it into (1 1 1 1 1 0)^n, C turns (1 0 0 1 0 0)^n into (0 1 1 1 1 1)^n and B into (1 1 1 0 1 1)^n, each in twelve steps a block. Also A fills (0 1)^n and B fills (1 0)^n moving right, and E and A cross (0 1)^n and (1 0)^n moving left.

aword, fword, cword, bword, afill, bfill, eleft, aleft, lean/Rules.lean

A queue of counters

Each time the head reaches a fresh cell at the left end, the tape is a list of runs of 1s spaced three cells apart (the words 1 0 0 or 0 0 1), the runs separated by 0 0 0 0; read as numbers, for example 48, 17, 53, 7, 47, 15, 37, ... From one sweep to the next only the first number changes (it goes down by 2) and the last five or so numbers are rewritten in no visible pattern; when the first number runs out, the next one takes its place. The list grew to over 200 numbers in the first 5·107 steps, with occasional reorganisations that halve it.

c/zrec.c, tools/c/tmrun.c records

Growth shape

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.517). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.5).

Does it halt from blank tape?

Not known. A proof would describe the queue: how a sweep pair acts on the first counter and on the end of the list, which new counters it appends, and why that never produces A>0 0 1 1. Queue-like machines of this kind can behave like tag systems, which are hard in general. Window CTL up to 7 cells and n-gram CPS (widths up to 9, see the README for the larger runs) fail.
