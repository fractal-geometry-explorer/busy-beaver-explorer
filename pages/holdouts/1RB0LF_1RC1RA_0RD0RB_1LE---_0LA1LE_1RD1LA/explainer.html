Does this machine ever halt?

1RB0LF_1RC1RA_0RD0RB_1LE---_0LA1LE_1RD1LA

Probably yes, after about 1055 steps: an outside proof in Rocq says so, and we have not compiled it yet. Started on a blank tape this machine keeps coming back to a tape that is one block of 1s, and the length of that block is all that matters. It is a Lean theorem that the machine halts exactly when an explicit map, iterated from 13, reaches a doubling round with no 1s left; the outside proof follows the same map all the way to such a round. The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in D reading 1. D is entered only from C0 (writes 0, moves R): C>0 1; F0 (writes 1, moves R): F>0 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

The run at a glance

The diagram stacks the tape at many moments. Sampling at each new cell shows the shape of the run as the visited region grows; sampling evenly in time shows where the head spends its time. The records list every step at which the head reaches a cell no earlier step reached, with the side, the width so far and the whole tape: the first place to look for a repeating macro structure.

Macro structure

One number on the tape

Most of the time the tape is almost featureless: a single block of 1s. Stop the simulator whenever the head, in state B, steps onto a new cell at the right end, and quite often the whole tape reads

0^inf 1^X 1 1 1 0 B> 0^inf   (call it S(X))

The first time is at step 110, with X = 13. Then come X = 29 (step 365), 45 (step 980), 137, 185, 217, 249, 345, ... Everything the machine does between two such moments depends only on X, so the whole run is the orbit of 13 under one map, X → f(X). In the first 2·109 steps the orbit has 161 points and has reached X = 9,265.

Macro structure

Doubling by zig-zag

Inside one return the head builds, at the left end of the block of 1s, a block of pairs 10, and then doubles it again and again. One round of the zig-zag takes one pair off the left block, crosses the block of 1s it has built, eats two 1s on the right and comes back:

(10)^(j+1) 1^(4i) F> 1 0 1^(m+2) → (10)^j 1^(4i+4) F> 1 0 1^m

(proved in Lean for all i, j, m). At the left end a pass then turns the 1s back into pairs. Watch the left end and the counts go

F> 0^2 a^3 1^297, F> 0^2 a^9 1^288, F> 0^2 a^21 1^267, F> 0^2 a^45 1^222, F> 0^2 a^93 1^129

(a = 10): k → 2k + 3. When the doubled block no longer fits in the 1s, the round stops in the middle: that is the overflow, described in the next section.

In Lean this is a theorem for every X (S_rounds): after t rounds the tape is F> 0 0 (10)^(6·2t − 3) 1^(X + 3t + 12 − 12·2t) 0 1, as long as 12·2t ≤ X + 3t + 12. So the doubling stops at the first t with 24·2t > X + 3t + 15. For X = 137 that is t = 3 (block 45, 62 ones left); for X = 549, t = 5 (block 189, 192 ones left).

The map

The whole map

When a round runs out of 1s the tape is

0^inf 1^6 0 (10)^p (1111)^i F> 1 0 1^r 0 1 0^inf   O(p, i, r)

with p pairs still to move, i zigs done and r = 0 or 1 ones left. What happens next depends only on the parities: the leftover pairs are swept back to the left end, two at a time; each pair of pairs becomes one unit 1110, an odd pair left over becomes a short block of pairs. The result is one of four shapes, all with the head at the left end in state F (or the reset S):

Others halt: S(X) reaches a round P(k, 0) for X = 9, 30, 68, 75, 168, 295, 357, 738, …

Open question

What halting would take

It is a Lean theorem (halts_iff_H) that the machine halts from blank tape exactly when the orbit of S(13) under these rules reaches a round P(k, 0): a doubling round that starts with no 1s at all. Everything else about the run is in the table above. So the open question is a question about one explicit map on four kinds of numbers, and nothing more.

The orbit 13, 29, 45, 137, 185, 217, 249, 345, 409, … has been followed for 108 returns to S (X up to 1.5·1010) without reaching P(k, 0); the first 107 nodes are also checked inside Lean. Proving that it never halts would mean proving that this orbit avoids a sparse but infinite set of bad values for ever. Every doubling threshold the orbit crosses is a new, irregular chance to hit one, which is what makes this a Collatz-like problem.

First look

The shape of the run

Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.313).

blank_to_S13, S_to_P, double, chain, S_rounds, lean/Doubling.lean; pieces reset_start, dbl_intro, zig, dbl_end in lean/Rules.lean
The doubling phase of a return, for every X

Write S(X) for 0^inf 1^X 1110 B> 0^inf and P(k, m) for 0^inf F> 0 0 (10)^k 1^m R. Lean proves: the blank tape is in S(13) after 110 steps; S(X) reaches P(3, X) for X ≥ 6; for k ≥ 2 and m ≥ 2k + 3, P(k, m) reaches P(2k + 3, m − 2k − 3) (one doubling round: one pair becomes the wall block, k − 1 zig-zag rounds by induction, then the 1s are turned back into 2k + 3 pairs); and in closed form, if 12·2t ≤ X + 3t + 12 then S(X) reaches P(6·2t − 3, X + 3t + 12 − 12·2t). So the doubling phase ends, and the overflow starts, at the first t with 24·2t > X + 3t + 15: these are the doubling thresholds where f changes regime.

Kernel
F, F_sem, halts_iff, F_none_iff, halts_iff_H, lean/Map.lean
Halts iff the orbit of S(13) reaches a round with no ones

The nodes s x = S(x+6), p a m = P(a+3, m), q u c = Q(u+1, 2c+1), t u v = T(u, v+1) and the map F on them are Lean definitions; F_sem proves that every value of F is where the machine goes (in at least one step), and that F = none only where the machine halts. Hence: the machine halts from blank tape iff the orbit of s 7 (= S(13), reached at step 110) under F reaches none (halts_iff), iff it reaches a node p a 0, a doubling round 0^inf F> 0 0 (10)^(a+3) 0 1 0^inf (halts_iff_H). Only the standard axioms (propext, Quot.sound, Classical.choice).

Heuristic
this page; c/reset_map.c
Why the map looks Collatz-like

Inside one return the zig-zag doubles a block of pairs, k → 2k + 3 from 3 (3, 9, 21, 45, 93, ...), until it runs out of 1s; the parity of the pairs left and of the 1s left then picks one of six overflow cases, some of which start a new, smaller doubling chain from a block of units 1110. So the next X depends on X modulo small powers of 2 and on where X lies between doubling thresholds: constant increments for long stretches (+40, +96, +100, ...), irregular jumps at thresholds. Each threshold is a fresh chance to land on a halting round.
