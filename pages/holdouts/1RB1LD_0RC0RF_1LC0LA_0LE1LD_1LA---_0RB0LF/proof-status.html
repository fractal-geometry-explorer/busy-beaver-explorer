What is known about 1RB1LD_0RC0RF_1LC0LA_0LE1LD_1LA---_0RB0LF

1RB1LD_0RC0RF_1LC0LA_0LE1LD_1LA---_0RB0LF

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 26 November 2026.

In short

The question is open; the event map, now proved in Lean, suggests a halt far beyond any run. The tape is a list of blocks of 1s. At each visit to the left end the first block is divided by 3: remainder 1 passes two thirds on and deals the next block too, remainders 0 and 2 end the visit. Lean's kernel checks that this map is what the machine does (visit_sound), and that the machine halts when the dealing meets a block of value 5, for instance from the lists that begin 4, 3 or 7, 1. Run for 1.1·1012 events the map never gets there, but it keeps coming close at a steady rate, about 20 times per doubling of the run with a second block below 100, so a halt looks more likely than not, at a time no run can reach.

The event map

At a left-end visit the tape is a list of blocks of 1s with single 0s between. Read it from the left with a running value cur = 3j + r: r = 1 keeps j + 1 and adds 2j to the next block, which is dealt in turn; r = 2 keeps j − 1, adds 2j + 5 to the next block and ends the visit; r = 0 keeps j, adds 2j to the next block and 2 to the one after, and ends the visit. Then the first block gets one more, and vanishes if that makes it 0. Missing blocks count as 0. Lean proves that wherever this map answers (no later value 2, 3 or 5), the machine goes from the left end with the one list to the left end with the next; that from blank tape it is at the list 7, 2 after 66 steps; and that if the map can be applied for ever from there, the machine does not halt. The proof chains 21 generated machine rules with the deal rule.

visit_sound, start, not_halts_of_run in lean/EventMap.lean; rules in lean/Rules.lean (generated by lean/rules.py)

A later value 5 halts

If the dealing meets a block of value 5 after the first block, the head comes back in state E onto a 1 and the machine halts. This covers the lists that begin 4, 3 or 7, 1 or 1, 5, and 4, 2, 3. So if the map from the list 7, 2 ever reaches such a list, the machine halts from blank tape.

Where it halts: two small blocks at the left end

Outside the map's domain the machine was run directly on 8,569 lists. A later value 5 halts every time (3,777 lists; proved in Lean, next entry); a later value 3 with a block after it halts every time (2,209); a 4 or 7 at the last block halts (383); a later value 1 with a block after it halts in 446 lists and not in 551; a later value 2 never halts. A bad value needs the first block to be 1, 4 or 7 and the second at most 5, or three small blocks in a row.

Growth shape: power/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.353). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.287).

Block picture

In 3·109 steps, every time C stands at the right end the tape is 2 to 8 blocks of 1s separated by 0^2, 0^3 or 0^5, with 0 1 0 C>0 at the end. The last block is close to twice the one before it in most samples (347, 700; 1,113, 2,230; 730, 1,468).

The base-3 cascade

When fewer than three ones are left in the dealt block, the remainder decides: 1, the finished block is dealt again (so a block is cut by 3 again and again while the remainder is 1); 2, the finished block is closed and the next block is dealt; 0, the two blocks merge. The sweep left adds one to every block but the last long one and cuts the block after a 00000 (n = 3t) into t + 1 and 2t + 2. Read off traces of the run; the exact map is the event map below.

Near misses come at a steady rate

Among the states whose first block is 1, 4 or 7, each doubling of the event count from 213 to 238 brings about 100 with a second block at most 200, about 20 at most 100 and about 2 at most 50; the smallest in the last ten doublings is 28. A power-law fit gives of the order of 0.01 halting lists per doubling, a sum that does not converge. So a halt looks more likely than not, but only after something like 270 events or more.

Does it halt from blank tape?

Not known. By the event map a halt needs two small blocks side by side at the left end; the run comes near at a steady rate and has not got there in 1.1·1012 events. The map and the halt at a later value 5 are proved in Lean; what the machine does at a later value 1, 2 or 3 is known only from runs.
