Does this machine ever halt?

1RB0LE_1RC---_1RD1RE_1LA0RF_0RC0LA_0LC0RB

Decided: it never haltsProved in this repository, checked by Lean and by Coq. The ledger below says what each part rests on.

It never halts, and Lean proves it. This machine alternates between long stays at its right end and rounds of full sweeps, each phase longer than the last; every way one phase can lead to the next is proved for all sizes, and linear inequalities on the counts show the run always stays where those rules apply. This page runs it in your browser.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in B reading 1. B is entered only from A0 (writes 1, moves R): A>0 1; F1 (writes 0, moves R): F>1 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

Four levels

From six states to a list of inequalities

The question "does this machine halt?" is answered here at four levels of description. Each level keeps less detail than the one above it, and each step down is a Lean theorem, checked by the kernel: what happens at the lower level is exactly what the machine does. At the bottom, the question is whether a list of linear inequalities on a few numbers is kept by twenty arithmetic cases, and that is a question omega can settle.

Level 1

The machine, and the only way it can halt

At the top of the ladder is the machine itself: a tape of 0s and 1s, a head, and the table above. Its table has one missing entry: B reading a 1. That is the only way to halt. Two transitions lead into B: A reading a 0 (writes 1, moves right) and F reading a 1 (writes 0, moves right). So the machine halts exactly when the head reads A> 0 1 or F> 1 1 (Lean: halt_A, halt_F in lean/Rules.lean). Kernel

The proof never looks for these patterns directly. It shows something stronger: from the blank tape, for every number n, the first n steps are all defined. That is the Lean statement ¬ HaltsFromBlank, where HaltsFromBlank means "some step reaches a configuration with no transition".

Without the proof, the run gives only bounds: no halt in the first 104 steps (kernel) and 107 steps (native_decide), both in lean/Blank.lean, and none in 109 steps of the C simulator. The simulator above (Watch it run) is this level.

Press Step to see a halt play out on a made-up tape.

Level 1 to level 2

The tape is a list of numbers

Watch the machine for a while and its tape turns out to be made of long runs of a few short words: 1000, 10, a 14-cell word such as 00001000001000, and a few others, with short fixed pieces between them. So the tape can be written as a form: a pattern with the run lengths as numbers. That is level 2. For example

is the form O a b c: the head in state A at the left end, then seven 0s, a copies of 1000, b copies of 10, c copies of the 14-cell word, and 101. The proof uses ten forms. Seven are seen with the head at the left end, in state A or E (the "round-trip" forms, counting O a 0 c separately), and three with the head at the right end, in state E (the "right-phase" forms). Pick one to see its shape:

A form names a whole tape, so a sequence of forms with step counts is a description of the run as faithful as the machine itself, as long as every form is on the tape at exactly the stated step. The first time the run is in one of these forms is at step 29,301, in the form O 14 37 11. Lean proves this by running the machine (blank_O in lean/Table.lean). Level 2

Crossing a run in one move

Level 2 counts time in rules, and a rule may span millions of steps. What makes that possible is that the head crosses long runs in a simple way, and Lean proves each crossing once for every length:

  • pass_10_right: C crosses (10)^n to the right in 2n steps and leaves it unchanged.
  • pass_10_left: A crosses (01)^n to the left in 8n steps (it carries 10 along).
  • fill_F: F turns (1000)^n into (1110)^n, 10 steps a copy.
  • fill_B: B turns (0001)^n into (0111)^n, 10 steps a copy.
  • clear_A: A, going left, turns (0111)^n into (0010)^n, 10 steps a copy.

Each is proved by running one copy for real (rfl: the kernel computes those few steps) and then a general lemma: if one copy takes the head through in the same state, n copies do too, in n times the steps (lean/Rules.lean). Kernel Pick a pass and play it on the real machine with n = 3.

Level 2

One rule, for any size

Using these passes, Lean proves 27 rules. Each rule says: from form X with numbers like (a, b + 6, c + 2), the machine reaches form Y with numbers that are simple formulas of a, b, c, in an exact number of steps that is also a formula. The rule holds for every value of the variables. Kernel This is the theorem that ties level 2 to level 1: a rule is a statement steps N (X …) = some (Y …) about the machine itself, so a chain of rules is a stretch of the real run, step count included.

The central example is the 4-visit cycle cycle: S1 a (b+2) (c+2) reaches S1 (a+3) (b+14) c in exactly 80a + 72b + 1356 steps. Each turn uses up two of the 14-cell words (c drops by 2), and the runs of 1000 and 10 grow by 3 and 12. The head visits the left end four times on the way.

Each rule's proof is a symbolic run: Lean steps the machine on a tape whose runs have lengths like b + 2, uses a pass to cross a whole run at once, and at the end shows the tape it got is the target form (by regrouping, e.g. (0010)^a 0 = 0 (0100)^a). Lean also proves the k-fold repeats such as cycle_iter, by induction on k. The rules are in lean/Cycle.lean, lean/Phase.lean, lean/Branch.lean and lean/Ends.lean.

Level 2 to level 3

Ten forms and twenty cases

Level 3 forgets the turns inside a phase and keeps only the form at the start of each phase. Put the rules together and every form leads to another form. The graph shows all of them. A loop on a form is a cycle rule, which runs as long as there are words left to use up. Each arrow out of a form is an exit, chosen by what is left over: how many 14-cell words remain (c = 0 or 1), how many 0010 remain in T3 (d = 0 to 4), or whether the run just built has even or odd length. Each case runs one cycle to its end with its k-fold iterate (cycle_iter, cycle2_iter, cycle3_iter, ucyc_iter, rcyc_iter, gcyc_iter, g3cyc_iter) and then applies one exit rule. Which exit is decided by a residue: c mod 2 for S1, T2 and U3, d mod 5 for T3, and the parity of the run being built for RF, RG and RG3. Once the residue is fixed the new numbers are affine functions of the old ones, so the 20 cases mv_* are exact formulas, proved by chaining the rules of level 2 (for every value of the variables). Kernel

Not every case is safe for every size. A case needs its numbers to be large enough (for mv_oentry, b ≥ 6 and c ≥ 2), and some combinations have no case at all, for example T3 running out of 14-cell words while 5 or more 0010 are left. Those are the gaps the invariant of level 4 closes.

Level 4

Why the moves never run out

The 196 moves cover a finite stretch of the run. To go on forever the proof needs one argument that works for all later moves. That is level 4, the invariant Good in lean/Closed.lean: for each form, a list of 3 to 16 linear inequalities on its numbers. They say three kinds of things:

shape
the growing numbers keep their ratios inside a fixed region (a polyhedral cone). For O a b c, b stays between about 1.7 and 4.2 times a, and c between about 0.3 and 2.3 times a, in the shaded region of the picture below.
small parts
the bounded numbers stay in range (in RF, k is 4 or 5; in RG and RG3, n is 4 or 5; in T3, 8 ≤ y ≤ 15), and some numbers keep exact relations (in T3, x = 2a + 4; in U3, x − 2a is between 0 and 2; in RG3, 4y + 21x − 49a is between −63 and 19).
size
one weighted sum is at least 50,000,000 or 100,000,000, such as 71·b ≥ 50,000,000 for O.

The picture shows, for the forms O and S1, the region that the ratio inequalities allow (shaded), and the ratios of every O or S1 state of the replay (dots). The ratios move around from phase to phase but stay in the region. Filled dots are good states. Hollow dots are early states, which are still too small for the size condition.

Why do the inequalities keep holding? Each of the 20 cases of level 3 is a fixed affine map on the numbers. So the step from Good to Good is a question about linear inequalities over the whole numbers, which Lean's omega procedure decides. Kernel Each case works because:

  • the map sends each form's region strictly inside the next form's region, with room to spare;
  • the size grows by a factor of at least 1.1 per case, so the room to spare grows faster than the fixed offsets in the formulas (the "+6", "+13" and so on);
  • the inequalities imply every condition a case needs (b ≥ 6 and so on), and that T3 has c ≥ 2⌊d/5⌋ + 3, enough 14-cell words for all its turns. That rules out the gaps of level 3.

That is good_step: from a good tape the machine makes at least one step and reaches a good tape. Its proof has one step_* lemma per form, each split by the residue into its cases, and each case is one mv_* lemma and one call of omega. The coefficients (up to 1,321) were found by linear programming on the replay's numbers, with scripts outside the proof. Lean does not trust them: if one were wrong, omega would fail.

The last state of the replay is good: Lean evaluates its 16 inequalities with decide (good_last). Kernel Along the replay every entry from the 39th on is good, and the panel above lets you check any of them, and the case that follows.

The bottom line

It never halts

The machine 1RB0LE_1RC---_1RD1RE_1LA0RF_0RC0LA_0LC0RB, started on a blank tape, never halts.

Kernel Lean theorem nonhalting : ¬ HaltsFromBlank in lean/Closed.lean. It rests on Lean's kernel alone: #print axioms for it lists only propext, Classical.choice and Quot.sound, the three standard axioms of Lean's logic. There is no native_decide and no compiled code anywhere in the proof.

The argument, in three sentences. From the blank tape the machine reaches a tape that is good: one of ten forms, with numbers that satisfy that form's inequalities (table_from_blank, good_last). From any good tape it makes at least one step, without halting, and reaches a good tape again (good_step). Repeating the second sentence gives runs of every length, and a machine that halts has runs only up to some fixed length.

The last lines of the proof, in words

The end of lean/Closed.lean, theorem by theorem:

Good t
t is one of the ten forms, with numbers that satisfy that form's inequalities (gOp, gO0, gS1, gRF, gEF, gT3, gT2, gU3, gRG, gRG3).
good_step
from a good t, at least one step leads to a good t′. One case per form (step_Op … step_RG3), each split by remainder or parity into the 20 cases.
table_from_blank
some run from the blank tape ends at the last state of the replay (blank_O then table_run).
good_last
that last state is good.
nonhalting
¬ HaltsFromBlank. By induction on N: for every N there is a run from blank of length at least N ending at a good tape. So runs of every length exist, and the machine does not halt.

Good, good_step, mv_*, lean/Closed.lean (written by py/closed.py)
The invariant

Good gives, for each of ten forms (O a b c with b large, O a 0 c, S1, RF, EF, T3, T2, U3, RG, RG3), 3 to 16 linear inequalities with integer coefficients: the growing counts keep their ratios in a polyhedral cone that every move maps strictly inside the next one; the bounded counts stay in range and T3, U3, RG3 keep exact relations (for example x = 2a + 4 in T3); and a positive linear size, which every move multiplies by at least 1.1, stays above a threshold. These give every offset the rules need, and c ≥ 2⌊d/5⌋ + 3 in T3, so the 5-visit cycle never runs out of words. good_step proves each of the 20 cases with one move lemma and omega; the end of table_from_blank satisfies Good (decide).

How the invariant was found

Not part of the proof. The forms' counts at the form entries along the replay, divided by their sum, give a cloud of points per form. A fixpoint of linear programs over the 20 moves (homogeneous parts, margin 10-3) enlarges their convex hulls until each move maps every cone inside the next; a second linear program finds the size function.
