1RB1RF_1LC0RE_1RD0LC_0LB0RA_1LD1RD_1RB---

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 21 November 2026.

In short

The question is open, and reduced to a counter with no assumption left. Write x = 1110 and a = 10. Most of the time the tape is C> 0 10 x^n0 [1 a^d1 x^n1] ... [1 a^dk x^nk] 1: blocks of x with a ternary digit d in front of each. One round trip of the head is a ternary decrement: the first nonzero digit drops by one, the zeros below it become 2, every block the borrow passes loses one x and the first block gains one. When the counter runs out a new round starts with one more block. Every rule is proved in Lean for all sizes, and the machine halts from blank tape if and only if the counter model reaches a halting pattern: the borrow meeting an empty block followed by a block with digit 0 (halts_iff_model, kernel-checked). Since 12 November the theorem has no hypothesis: the model is a function defined on every list of blocks, including the patterns that never show up in the run, and each of its cases is proved to be what the machine does. The model has run 332,875 rounds (more than 10292 steps) without halting. A halt needs a charged pair of blocks, two neighbours whose block length and digit do not match mod 3 (Lean, good_not_halt). A round-skipping simulator, tested round by round against the exact model for 60,000 rounds, has followed the model to round 33,199,619 without a halt. The run has carried one such pair since round 49,668 (observed), and the model halts if that pair's block runs out before the block after it; sizes say this is not about to happen, but nothing is proved about the long run.

One bounce is a ternary decrement

From C> 0 10 x^n0 [1 x^(m1+1)] ... [1 x^(mj+1)] [1 a^(e+1) x^n] rest (blank to the left, any tape after) the machine reaches C> 0 10 x^(n0+1) [1 a^2 x^m1] ... [1 a^2 x^mj] [1 a^e x^n] rest, for every n0, every list of passed blocks m1..mj, every n, every digit e + 1 ≥ 1 and every rest. In words: the first nonzero digit drops by one, the blocks before it lose one x each and get digit 2, the front block gains one x. Proved by induction over the passed blocks from pieces written by py/counter.py; nothing is assumed.

bounce_any, lean/Counter2.lean (and bounce_gen, lean/Counter.lean, for e ≤ 1)

The other rules of the counter

Empty blocks (0,0) at the right end: one is removed, two stay (an endless supply of borrows), three become (1,0). A round ends when every digit is 0: (n0; (0,m1+1), ..., (0,mk+1)) becomes (0; (1,n0+1), (0,m1+1), ..., (0,mk), (0,0)), and with no block at all (n0; ) becomes (0; (1,n0), (0,0)). An empty block followed by a block with digit 1 is one more x (a merge, an equality of tapes). The borrow meeting an empty block followed by a nonempty block with digit 0 (or by an empty block and then such a block, or by two empty blocks and anything more) halts the machine. New on 12 November, the cases that never occur in the run: the borrow meeting one or two empty blocks followed by a block with digit e + 2 makes the machine turn round as at the end of a round, (n0; Z, (0,0), (e+2,n), rest) → (0; (1,n0+1), Z, (0,0), (e,n), rest) with the passed blocks Z unchanged. All proved for every size; nothing is assumed.

bounce_t1, bounce_t2, bounce_t3, exhaust, merge_mid, merge_first, bounce_halt, lean/Counter.lean; exhaust0, mid1, mid2, lean/Counter2.lean

Halting from blank tape is exactly halting of the counter model (no assumption)

bounceM is the counter model as a function on every state (n0; list of blocks): it returns the next state or halt. Proved: it never fails to give an answer (bounceM_ne_stuck: the third value stuck of its result type is never returned); a next is a run of the machine of at least one step (bounceM_next); a halt is a halting configuration (bounceM_halt); and blank tape reaches the counter (0; (1,5), (0,0)) at step 403 (blank_to_counter). Hence, in plain words: the machine halts from blank tape if and only if repeating the model's bounce from (0; (1,5), (0,0)) reaches halt (halts_iff_model : HaltsFromBlank ↔ ∃ k, runM k (next 0 [(1,5),(0,0)]) = halt). Nothing is assumed: the earlier version needed the hypothesis that the model never meets an undefined pattern; that hypothesis is gone because every pattern is now defined and proved.

halts_iff_model, bounceM_ne_stuck, bounceM_next, bounceM_halt, norm_sound, blank_to_counter, lean/Model.lean

A halt needs a charged pair of blocks

Call two neighbouring blocks (d, n), (d', n') neutral when n ≡ d' + 2 (mod 3) and charged otherwise. In a neutral pair an empty block is followed by a digit 1 and the two merge, while every halting pattern starts with an empty block followed by a digit 0. Proved: if every pair of the list is neutral, the next bounce of the model is not a halt, for every n0. The pairs behind the empty blocks that the end of a round leaves at the very end of the list are exempt, so the end of the list needs no argument about sizes.

Where a charge can be made (all small states)

On every list of up to 6 blocks with digits below 3 and block lengths below 5 in which every pair is neutral (230,592 states): the next bounce is not a halt; if n0 + d1 ≡ 1 (mod 3), every pair is neutral afterwards too; and n0 + d1 ≡ 1 is kept unless the first block ran out and merged into the front block in that bounce. A charged pair is made only at the end of a round, when n0 ≡ 1 (mod 3) fails. Checked by enumeration, not proved for all sizes.

No halt of the counter model in 561,525,639 rounds (accelerated, 16 November)

py/cycle.py runs the young blocks at the front symbolically, on affine forms in the number of repeats, with a comparison counting only when it is decided for every value. When the front repeats with a linear drift (plus one geometric term) it skips K rounds at once, with K bounded by the next event of a block behind the front. Every round with an event is done by the exact model. It agrees with py/skip.py at every round start for rounds 1 to 300,000, and on 303,752 rounds (87 skips) from round 41,649,462. From round 41,649,463 it reached round 561,525,639 without a halt: 89,753 skips covered 519,148,318 rounds, 2 rounds went to the exact model, and 24,728 blocks remain. There is still exactly one charged pair (residue 1), now 208th from the right end. The charged block's fate is decided about 2.7·1012 rounds out, which is beyond this method's memory. This is a bounded run.

No halt in the first 1.37×10124 steps (region-memo accelerator)

The region-memo accelerator tools/py/bbtools/regaccel.py ran with blocks of 4 cells, from blank tape for 1200 seconds and reached step 1.37×10124 without a halt. It keeps the tape run-length coded and, for each stretch of tape from the left end, a macro (the run until the head first leaves that stretch) computed by a symbolic run of the machine with the long runs as variables; a macro is used only when the linear inequalities its symbolic run assumed hold, otherwise the stretch is run again by the same recursion. The next deciding event: an A phase in round 16,952,683,091 (21 November 2026)

In every round a block with q blocks to its right is passed exactly 3q − 1 times, whatever is to its left, so the charged block and everything right of it evolve on their own; blocks to its left only merge into it, which can only make it longer. py/rightpart.py runs that part alone, in closed form between events and with the exact model in every round in which a block may run out. It agrees with py/skip.py on the blocks right of the split at all 58,000 round starts from round 2,000 to 60,000. From round 561,525,639 the right end has events in rounds 906,304,366, 14,812,159,822 and 16,952,683,090, and then an A phase in round 16,952,683,091: the last block runs out with two empty blocks behind it, and the counter wraps about 4.6×1012 times without new front blocks. Up to that round the front cannot reach the charged block (its left neighbour lives 8×1010 rounds), the charged block outlives its right neighbour, and so the charged pair cannot halt the model. A phases are where charges are made (the first block runs out into the front block), so this round, not the race about 2.7×1012 rounds out, is the next one that can decide halting. Deciding it needs the exact front of that round, which no run has reached (py/cycle.py would need about 40 hours). Run with nothing fed into it, the charged block outlives its right neighbour through 20 more A phases until the list is down to 5 blocks (round 9.2×10108); the real block holds at least as much as long as some front block survives every A phase to its left (observed, not proved).

heuristic Evidence only

Growth shape: power/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.545). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.155).

tools/py/bbtools/triage.py

What the charge means for halting

If the charged block runs out while the block after it is not empty, the borrow finds an empty block followed by a digit 0: the model halts. A block with p − 1 blocks to its right loses 3p−1 per round, so the charged block would last 3·1011 rounds and its right neighbour 1.9·1011: the neighbour would go first, and the charged block is also fed by the young blocks that run out on its left. Nothing is proved about the long run. A round-skipping run to round 33,199,619 (next claim) saw one event behind the charged block, after which both blocks last 9 times longer: 2.7·1012 and 1.7·1012 rounds, the neighbour still first. The earlier guess on this page, that a halt would come from the end of the list, is withdrawn.

The front in closed form, and no halt up to the A phase of round 16,359,800,336,602,988 (argument, 23 November 2026)

The young groups follow a lifetime model (lifetime n/3q falls by 1 per round; a death multiplies everything left of it by 9; the aged newborn grows 8-fold per two-round cycle), which matches the exact model with 0 mismatches over tens of thousands of rounds and on the real list for 6×106 rounds. The exact model is sensitive, though: it reads one to two more bits of the young sizes at each cycle break, so neither this closed form nor an exact run (about 1016 bits of state) can follow the real front to that A phase, and whether it makes a third charged pair is not decided. A halt there would need one of the two charged blocks to run out; their lifetimes (about 1022 rounds and more) are far beyond that round, so the model does not halt before the end of that A phase. This is an argument, not a run. The exact run (py/cycle.py) was extended to round 19,437,497,185 with no halt and charges unchanged.

Conserved differences

Counting blocks from the right end, per round block p loses 3p-1 (the last loses 2), so the differences np+1 − 3np (p ≥ 2) do not change between merges. That is why the blocks at the right end run out together, in rare collapses (rounds 23 and 49,668 so far).

Does it halt from blank tape?

Not known. Equivalent (in Lean, with no assumption) to the counter model reaching its halting pattern. A halt needs a charged pair of blocks (Lean); the run has carried one since round 49,668 and still has exactly one at round 33,199,619 (observed), and the model halts if its block runs out before the block after it. Whether that ever happens is a question about sizes, like a Collatz problem.
