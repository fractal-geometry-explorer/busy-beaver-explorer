What is known about 1RB1RF_1LC0RE_1RD0LC_0LB0RA_1LD1RD_1RB---

1RB1RF_1LC0RE_1RD0LC_0LB0RA_1LD1RD_1RB---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 13 November 2026.

In short

The question is open, and reduced to a counter with no assumption left. Write x = 1110 and a = 10. Most of the time the tape is C> 0 10 x^n0 [1 a^d1 x^n1] ... [1 a^dk x^nk] 1: blocks of x with a ternary digit d in front of each. One round trip of the head is a ternary decrement: the first nonzero digit drops by one, the zeros below it become 2, every block the borrow passes loses one x and the first block gains one. When the counter runs out a new round starts with one more block. Every rule is proved in Lean for all sizes, and the machine halts from blank tape if and only if the counter model reaches a halting pattern: the borrow meeting an empty block followed by a block with digit 0 (halts_iff_model, kernel-checked). Since 12 November the theorem has no hypothesis: the model is a function defined on every list of blocks, including the patterns that never show up in the run, and each of its cases is proved to be what the machine does. The model has run 332,875 rounds (more than 10292 steps) without halting. A halt needs a charged pair of blocks, two neighbours whose block length and digit do not match mod 3 (Lean, good_not_halt). The run has carried one such pair since round 49,668 (observed), and the model halts if that pair's block runs out before the block after it; sizes say this is not about to happen, but nothing is proved about the long run.

Sweep rules

The head sweeps over long runs of a repeated word, rewriting each copy, for any number n of copies and any surrounding tape. Examples:

  • L D> (1011)^n R → L (0101)^n D> R
  • L E> (1101)^n R → L (1010)^n E> R
  • L B> (1110)^n R → L (0101)^n B> R

One bounce is a ternary decrement

From C> 0 10 x^n0 [1 x^(m1+1)] ... [1 x^(mj+1)] [1 a^(e+1) x^n] rest (blank to the left, any tape after) the machine reaches C> 0 10 x^(n0+1) [1 a^2 x^m1] ... [1 a^2 x^mj] [1 a^e x^n] rest, for every n0, every list of passed blocks m1..mj, every n, every digit e + 1 ≥ 1 and every rest. In words: the first nonzero digit drops by one, the blocks before it lose one x each and get digit 2, the front block gains one x. Proved by induction over the passed blocks from pieces written by py/counter.py; nothing is assumed.

bounce_any, lean/Counter2.lean (and bounce_gen, lean/Counter.lean, for e ≤ 1)

The other rules of the counter

Empty blocks (0,0) at the right end: one is removed, two stay (an endless supply of borrows), three become (1,0). A round ends when every digit is 0: (n0; (0,m1+1), ..., (0,mk+1)) becomes (0; (1,n0+1), (0,m1+1), ..., (0,mk), (0,0)), and with no block at all (n0; ) becomes (0; (1,n0), (0,0)). An empty block followed by a block with digit 1 is one more x (a merge, an equality of tapes). The borrow meeting an empty block followed by a nonempty block with digit 0 (or by an empty block and then such a block, or by two empty blocks and anything more) halts the machine. New on 12 November, the cases that never occur in the run: the borrow meeting one or two empty blocks followed by a block with digit e + 2 makes the machine turn round as at the end of a round, (n0; Z, (0,0), (e+2,n), rest) → (0; (1,n0+1), Z, (0,0), (e,n), rest) with the passed blocks Z unchanged. All proved for every size; nothing is assumed.

bounce_t1, bounce_t2, bounce_t3, exhaust, merge_mid, merge_first, bounce_halt, lean/Counter.lean; exhaust0, mid1, mid2, lean/Counter2.lean

Halting from blank tape is exactly halting of the counter model (no assumption)

bounceM is the counter model as a function on every state (n0; list of blocks): it returns the next state or halt. Proved: it never fails to give an answer (bounceM_ne_stuck: the third value stuck of its result type is never returned); a next is a run of the machine of at least one step (bounceM_next); a halt is a halting configuration (bounceM_halt); and blank tape reaches the counter (0; (1,5), (0,0)) at step 403 (blank_to_counter). Hence, in plain words: the machine halts from blank tape if and only if repeating the model's bounce from (0; (1,5), (0,0)) reaches halt (halts_iff_model : HaltsFromBlank ↔ ∃ k, runM k (next 0 [(1,5),(0,0)]) = halt). Nothing is assumed: the earlier version needed the hypothesis that the model never meets an undefined pattern; that hypothesis is gone because every pattern is now defined and proved.

halts_iff_model, bounceM_ne_stuck, bounceM_next, bounceM_halt, norm_sound, blank_to_counter, lean/Model.lean

A halt needs a charged pair of blocks

Call two neighbouring blocks (d, n), (d', n') neutral when n ≡ d' + 2 (mod 3) and charged otherwise. In a neutral pair an empty block is followed by a digit 1 and the two merge, while every halting pattern starts with an empty block followed by a digit 0. Proved: if every pair of the list is neutral, the next bounce of the model is not a halt, for every n0. The pairs behind the empty blocks that the end of a round leaves at the very end of the list are exempt, so the end of the list needs no argument about sizes.

The model agrees with the machine on random states

On 3,000 random lists of blocks (digits 0 to 3, including every pattern that does not occur in the run) one bounce of the Python transcription of the model gives the tape the machine itself reaches, or a halt exactly when the machine halts (py/model.py random 3000). Where a charge can be made (all small states)

On every list of up to 6 blocks with digits below 3 and block lengths below 5 in which every pair is neutral (230,592 states): the next bounce is not a halt; if n0 + d1 ≡ 1 (mod 3), every pair is neutral afterwards too; and n0 + d1 ≡ 1 is kept unless the first block ran out and merged into the front block in that bounce. A charged pair is made only at the end of a round, when n0 ≡ 1 (mod 3) fails. Checked by enumeration, not proved for all sizes.

In the model's run from blank tape the first block runs out in rounds 22, 183 and 49,668. The first two leave n0 right by the end of the round. In round 49,668 the last block runs out at the end of a round, two empty blocks stay at the end and supply borrows without end, and while the counter wraps round the whole front of the list runs out; round 49,669 starts with one charged pair (residue 1). It is still there at round 255,000, on a block of about 1.3·10113 copies of x, 214th from the right end.

heuristic Evidence only

Growth shape: power/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.545). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.155).

tools/py/bbtools/triage.py

What the charge means for halting

If the charged block runs out while the block after it is not empty, the borrow finds an empty block followed by a digit 0: the model halts. A block with p − 1 blocks to its right loses 3p−1 per round, so the charged block would last 3·1011 rounds and its right neighbour 1.9·1011: the neighbour would go first, and the charged block is also fed by the young blocks that run out on its left. Nothing is proved about the long run, and each round costs more than 3200 bounces, so the present simulator cannot follow it. The earlier guess on this page, that a halt would come from the end of the list, is withdrawn.

python3 py/charge.py run 50000 prints the lifetimes

Conserved differences

Counting blocks from the right end, per round block p loses 3p-1 (the last loses 2), so the differences np+1 − 3np (p ≥ 2) do not change between merges. That is why the blocks at the right end run out together, in rare collapses (rounds 23 and 49,668 so far).

Does it halt from blank tape?

Not known. Equivalent (in Lean, with no assumption) to the counter model reaching its halting pattern. A halt needs a charged pair of blocks (Lean); the run has carried one since round 49,668 (observed), and the model halts if its block runs out before the block after it. Whether that ever happens is a question about sizes, like a Collatz problem.
