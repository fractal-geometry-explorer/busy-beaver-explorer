Does this machine ever halt?

1RB1RF_1LC0RE_1RD0LC_0LB0RA_1LD1RD_1RB---

Nobody knows, but the question is now a question about a counter. Each round trip of the head is a ternary decrement, proved in Lean for every size, and the machine halts exactly when this counter meets one pattern. This page runs the real machine in your browser and explains the counter.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from A1 (writes 1, moves R): A>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

Macro structure

The tape is a ternary counter

Write x for 1110 and a for 10. Whenever the head, in C, is at the left end of the tape, the tape reads

C> 0 10 x^n0 [1 a^d1 x^n1] [1 a^d2 x^n2] ... [1 a^dk x^nk] 1

a first block of x, then k groups, each a separator 1, a digit d (zero, one or two copies of a) and a block of x. Write the state as (n0; (d1,n1), ..., (dk,nk)). Consecutive visits, from step 2,297:

step 2,297   (2; (2,10), (2,1), (2,0))
step 2,345   (3; (1,10), (2,1), (2,0))
step 2,407   (4; (0,10), (2,1), (2,0))
step 2,625   (5; (2,9),  (1,1), (2,0))
step 2,715   (6; (1,9),  (1,1), (2,0))
step 2,819   (7; (0,9),  (1,1), (2,0))
step 3,065   (8; (2,8),  (0,1), (2,0))

The digits count down in base 3, least significant first: 222, 122, 022, 212, 112, 012, 202, ... Each time the borrow passes a group, the group loses one x; the first block gains one x per visit.

The rule

One round trip is one decrement

From the left end, C sweeps right, turning the x of the first block and of every group with digit 0 into pairs a, until it reaches the first nonzero digit. It removes one a there, and the head zig-zags back to the left end: each zig-zag eats two a on its left and leaves one x on its right, so the blocks are rebuilt, one x shorter, with digit 2 in front:

C> 0 10 x^n0 [1 x^(m1+1)] ... [1 x^(mj+1)] [1 a^(e+1) x^n] rest
  → C> 0 10 x^(n0+1) [1 a^2 x^m1] ... [1 a^2 x^mj] [1 a^e x^n] rest

This is proved in Lean for every n0, n, e and every list of passed groups, with any tape after (bounce_gen): six pieces found by the symbolic simulator and an induction over the groups.

Rounds

Rounds, and why the blocks shrink by powers of 3

A round starts with every digit equal to 2, so the counter holds 3m − 1 for m groups. Counting down to 0, group i is passed once for every multiple of 3i on the way, 3m−i − 1 times. When every digit is 0 the borrow runs off the end; the head converts the tape back, and the next round starts with one more group in front, of size 3m + 1 (all proved: exhaust). In one formula, with the blocks c1, ..., cm at the start of a round:

(c1, ..., cm)  →  (3^m + 1, c1 − 3^(m−1), c2 − 3^(m−2), ..., c(m−1) − 3, cm − 2)

That is the "geometric decrements" seen in the plain run: at the right end the blocks of pairs 10 (2 per x) lose 4, 6, 18, 54, 162, ... per round, and the front block is 5 + 2·3m = 1463, 4379, 13127, ...

Running out

Merges and the end of the list

A block smaller than its decrement runs out during the round. Once empty it becomes (2,0), then (1,0), then (0,0), just 1. An empty group followed by a group with digit 1 reads 1 1 10 = 1110: one more x, so the two groups join the block before them (a merge, an identity of tapes). This keeps the list at 5 to 9 groups for the first 1010 steps; later it grows slowly (608 groups after 332,875 rounds of the model).

Empty groups at the right end act as extra digits: one is used up, two stay forever (an endless supply of borrows, the "A phase", which lasts until the last group runs out), three become (1,0). The last group loses 2 per round; it starts an A phase only if it runs out with odd size, which happened twice in 332,875 rounds.

Halting

Where a halt would come from

The machine halts (F reading 1) exactly when the borrow meets an empty group (0,0) followed by a nonempty group with digit 0, or by an empty group and then such a group, or by two empty groups and anything more: proved (bounce_halt). And that is the only way: the machine halts from blank tape if and only if the counter model reaches that pattern (halts_iff_model, checked by Lean's kernel, nothing assumed). The model is a function defined on every list of groups. For the patterns that have never occurred in the run it was proved what the machine does: for example, if the borrow meets an empty group followed by a group with digit 2, the machine turns round right there, as it does at the end of a round, and the digit 2 becomes 0 — which is the halting pattern two bounces later unless that group is empty too.

In the run, consecutive groups always satisfy ni ≡ di+1 + 2 (mod 3) (checked, apart from a few states after an F event; not proved). When a block runs out, its next digit is therefore 1 and the groups merge: the halting pattern cannot form in the middle of the list. What remains is the end of an A phase: if the group before the last is exactly empty at the moment the last group runs out, the machine halts. Counting from the right, the differences np+1 − 3np are conserved between merges, so this asks whether one large conserved difference hits one small value at one rare moment. That is a Collatz-like question; no halt in 332,875 rounds, about 10292 steps.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.545). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.155).

After 109 steps the tape spans 72,272 cells (52,864 left of the start, 125 right), with a density of 1s of 0.74.

Sweep rules

The head sweeps over long runs of a repeated word, rewriting each copy, for any number n of copies and any surrounding tape. Examples:

  • L E> (1101)^n R → L (1010)^n E> R

Kernel
bounce_any, lean/Counter2.lean (and bounce_gen, lean/Counter.lean, for e ≤ 1)
One bounce is a ternary decrement

From C> 0 10 x^n0 [1 x^(m1+1)] ... [1 x^(mj+1)] [1 a^(e+1) x^n] rest (blank to the left, any tape after) the machine reaches C> 0 10 x^(n0+1) [1 a^2 x^m1] ... [1 a^2 x^mj] [1 a^e x^n] rest, for every n0, every list of passed blocks m1..mj, every n, every digit e + 1 ≥ 1 and every rest. In words: the first nonzero digit drops by one, the blocks before it lose one x each and get digit 2, the front block gains one x. Proved by induction over the passed blocks from pieces written by py/counter.py; nothing is assumed.

Kernel
bounce_t1, bounce_t2, bounce_t3, exhaust, merge_mid, merge_first, bounce_halt, lean/Counter.lean; exhaust0, mid1, mid2, lean/Counter2.lean
The other rules of the counter

Empty blocks (0,0) at the right end: one is removed, two stay (an endless supply of borrows), three become (1,0). A round ends when every digit is 0: (n0; (0,m1+1), ..., (0,mk+1)) becomes (0; (1,n0+1), (0,m1+1), ..., (0,mk), (0,0)), and with no block at all (n0; ) becomes (0; (1,n0), (0,0)). An empty block followed by a block with digit 1 is one more x (a merge, an equality of tapes). The borrow meeting an empty block followed by a nonempty block with digit 0 (or by an empty block and then such a block, or by two empty blocks and anything more) halts the machine. New on 12 November, the cases that never occur in the run: the borrow meeting one or two empty blocks followed by a block with digit e + 2 makes the machine turn round as at the end of a round, (n0; Z, (0,0), (e+2,n), rest) → (0; (1,n0+1), Z, (0,0), (e,n), rest) with the passed blocks Z unchanged. All proved for every size; nothing is assumed.

Kernel
halts_iff_model, bounceM_ne_stuck, bounceM_next, bounceM_halt, norm_sound, blank_to_counter, lean/Model.lean
Halting from blank tape is exactly halting of the counter model (no assumption)

bounceM is the counter model as a function on every state (n0; list of blocks): it returns the next state or halt. Proved: it never fails to give an answer (bounceM_ne_stuck: the third value stuck of its result type is never returned); a next is a run of the machine of at least one step (bounceM_next); a halt is a halting configuration (bounceM_halt); and blank tape reaches the counter (0; (1,5), (0,0)) at step 403 (blank_to_counter). Hence, in plain words: the machine halts from blank tape if and only if repeating the model's bounce from (0; (1,5), (0,0)) reaches halt (halts_iff_model : HaltsFromBlank ↔ ∃ k, runM k (next 0 [(1,5),(0,0)]) = halt). Nothing is assumed: the earlier version needed the hypothesis that the model never meets an undefined pattern; that hypothesis is gone because every pattern is now defined and proved.

Heuristic
this page
Why the merges never halt

In every state of the run checked (the first 300,000 bounces), except 9 states right after the F event, consecutive blocks satisfy ni ≡ di+1 + 2 (mod 3). So when a block runs out (its digit drops 1 → 0 with no x left), the next digit is 1 and the two merge; the halting pattern, an empty block before a digit 0, cannot form there.

Heuristic
this page
Conserved differences

Counting blocks from the right end, per round block p loses 3p-1 (the last loses 2), so the differences np+1 − 3np (p ≥ 2) do not change between merges. A halt needs the block before the last to be exactly empty when the last runs out during an endless-supply phase, which is one such difference taking one small value: a coincidence of two independent large numbers, as in other Collatz-like holdouts.

Open
Does it halt from blank tape?

Not known. Equivalent (in Lean, with no assumption) to the counter model reaching its halting pattern; no invariant excluding it is known. The mod-3 pattern of the next claim-level heuristic would, if proved, exclude a halt in the middle of the list, but the end of the list (the endless-supply phases) needs an argument about sizes.
