What is known about 1RB0RD_1LC0LE_0RA0LB_1RC1RF_1LB1RD_0RC---

1RB0RD_1LC0LE_0RA0LB_1RC1RF_1LB1RD_0RC---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 9 November 2026.

In short

The question is open. The machine's tape is a row of blocks of 001: all but the last are frozen, the last is rebuilt again and again by a bouncer that lives inside it. Phase P1 of that bouncer (any number of bounces, all sizes) is proved in Lean; the rule for a whole return of the head, a' = a + b + 7, is measured, not proved. Halting needs the head in D on two 1s side by side; that never happens in the first 109 steps.

Shift rules of the sweeps

Lean proves, for every count and every tape around, how the head crosses a block of 001 leftward in C (9 steps per copy, rewriting it as 100), and one whole bounce of the inner bouncer of the live block: from L 1 1 (001)^m 0 (001)^(j+4) 0 (110)^(k+1) 1 1 0 A> 0^∞ the machine reaches the same shape with m+3, j−3 and k+1 in 36j + 24k + 151 steps (bounce_tail).

Phase P1 of the live block, for every number of bounces

Write Live(x, y, z) for the tape L 1 1 (001)^x 0 (001)^y (011)^z 0 A> 0^∞ (any L). Lean proves (x, y+1+3n, z+2) → (x+3n, y+1, z+2+n) for every x, y, z, n (p1, an induction over bounce_tail), and from an empty right part (x, y+6+3n, 0) → (x+4+3n, y+2, n+2) (p1_from0, using the first two bounces bounce_z0 (12y + 35 steps) and bounce_z1 (36y + 127 steps)). So phase P1 always ends with the middle part y equal to 2, 3 or 4.

heuristic Evidence only

Growth shape: power/sqrt

Left of the start, the visited part of the tape grows like a power of the step count other than 1/2 (fitted exponent 0.131). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.387).

tools/py/bbtools/triage.py

The tape is a row of frozen blocks and one live block

At every return of the head to the left end (state C there, 135 times in 109 steps) the tape is C>0 1 0 1 (100)^59 0^3 1 (100)^107 0 1^3 (001)^1452 0 (1001)^2 (001)^392 …: blocks of 001 separated by short walls. Every block but the last stays the same from then on (59, 107, 1452, 392, 165, 337, 837 in the run to 109); only the last one changes.

py/observe.py, tools/c/tmrun.c … at C L

Growth of the live block: a' = a + b + 7

When the live block reads (001)^a (011)^b 01 at a left return, at the next left return it reads (001)^(a+b+7) (011)^(b'): (229,6) → (242,82) → (331,87) → (425,116) → (548,148) → (703,189) → (899,240) → (1146,306). b'/a' tends to about 0.27, so the block grows by a factor of about 1.27 per return, until it splits a new frozen block off.

The inner bouncer's phase change

Inside the live block, phase P1 moves 001s from the middle part to the left part until the middle part is used up: (100)^a (010)^b (110)^c becomes (100)^(a+3) (010)^(b−3) (110)^(c+1) each bounce (now proved for any number of bounces, see above). The following phase P2 then turns (a, 0, c) into (a', b', 0) with a' + b' = a + c + 1 and a' = c − d for a constant d that depends on the block to its left (d = 39 for four phases in a row from step 4·106 on). In the coordinates of Live: from (x, 2, z) the next empty-right configuration is (x', y', 0) with x' + y' = x + z + 3 in all 9 cases seen in 109 steps; x' = z + 1 while there is no frozen block to the left (4 cases up to step 2·104), x' = z + 1 − 41 for 3 phases (steps 4·106 to 2·107) and z + 1 − 333 for 2 (steps 5·108 to 6·108). P2 reaches the left end of the tape, so it is not a rule about the live block alone; it is not proved.

the A-at-right samples of tools/c/tmrun.c

Never one step from a halt

The machine halts when F reads a 1, and F is entered only from D reading a 1 (D1 → 1RF). In the first 3·106 steps D reads a 1 3,851 times, always with a 0 to its right, so F always reads 0.

the direct simulation of py/observe.py (scratch counter)

Proposed family: F01, periodic blocks driven by a bounded engine

The description grows slowly if at all: 29 to 37 level-2 tokens at every record from 2.7·108 to 2·1010 steps, and 10 to 32 runs in the macro simulator (blocks of 3 cells) at the sampled records from 106 to 9·1012 steps. At step 19,693,788,191 the tape has frozen blocks of 60, 107, 1,452, 394, 165, 338, 838 and 12,270 copies of 100 or 001 and a live part (001)^21588 (011)^2262. Within a level this is the F01 shape (a live block with a short engine, phase P1 already proved in Lean), and a level ends with the block frozen, as in 1RB0LC_0RC0RF_1RD0LE_1LA1RA_1LC1RB_0RB---. The list of frozen blocks is not bounded: 5 blocks at 7.6·107 steps, 8 at 2·1010.

Does it halt from blank tape?

Not known. Deciding it would need the rule for a whole return of the head (phase P2 and the splitting of the live block, which both involve the frozen blocks to the left) as a map on the block sizes, proved, and then an argument that its outcome never puts D next to two 1s. Phase P1 is now proved; the splitting looks like a Collatz-like condition on the sizes modulo 3.
