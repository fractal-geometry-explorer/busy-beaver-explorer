Nobody knows whether this six-state machine halts from blank tape. Like 1RB---_0RC0RD_1LD1RB_0LE0LC_1RA0LF_1LD1LE in this group, its tape has two parts: a stretch 1 0 1 0 … and a solid block of 1s. At the left end the stretch is on the left (0 0 0 (10)^909 1^1859); at the right end the block is on the left (0 1^238 (10)^1718). Unlike in that machine, the block does not keep its length across a trip.

Status as of 22 November 2026.

In short

The question is open, and it is now exactly a question about one orbit of a three-number map. Lean proves (kernel, core Lean) that the machine halts if and only if DeepMind's map on C(m, k, b) = 0∞ 1m (10)k C> 1b 0∞ stops, and that this happens exactly when the orbit visits a state with m = 3b + 1.

Where the run is. Iterated from C(0, 0, 2) for 3.26·1021 steps of the map (7.03·1032 machine steps): no halt. Sizes reach about 2.6·1011. The orbit came within 1 of the halting line m = 3b + 1 several times (m − 3b = 0 or 2), last at m ≈ 1.3·1011; heuristically each new decade of the step count has a small fixed chance of a halt, so a halt may well come, far out of reach.

Halts if and only if DeepMind's map stops

The machine halts from blank tape if and only if the orbit of DeepMind's map DM.next on states C(m, k, b) = 0∞ 1m (10)k C> 1b 0∞ from DM.start = C(0, 0, 2) stops. Proved here on this repository's machine semantics with core Lean (it used to be a cited axiom from google-deepmind/cryptids): each of the 12 clauses of the map is one of 18 symbolic rules taking the configuration of its left side to that of its right side, or to a halt (lean/DMRules.lean, written by tools/deepmind/dmproof.py from DeepMind's configuration template), and TM.halts_iff_orbit turns them into the halts-iff statement. #print axioms: propext, Classical.choice, Quot.sound.

deepmind_halts_iff, lean/DMMap.lean, lean/DMRules.lean

Halts if and only if the orbit visits m = 3b + 1

The map stops only at C(2, 0, b) with b ≥ 2, and only C(1, k, 0) is sent there. A state C(m + 3, k, b + 1) always takes the sweep clause C(m + 3, k, b + 1) → C(m, k + 2, b), so from C(3B + 1, k, B) B sweeps reach C(1, k + 2B, 0) and two more steps stop the map. Hence: the machine halts from blank tape if and only if the orbit of the map from C(0, 0, 2) visits a state C(3B + 1, k, B) (B = 0 included).

How it could halt

The halting transition is F reading 1. F is entered only from E reading 1 (moving right). So a halt is exactly E>1 1: E on a 1 with a 1 to its right.

the transition table

Near misses: a halt is plausible but far away

At a sweep start the quantity d = m − 3b decides: d = 1 halts. In the run above d was within 2 of 1 at 16 sweep starts (d = −1, 0, 2 or 3), at sizes from 6 up to about 1.3·1011, roughly once per decade of the step count. If d were a random number of size comparable to b, the expected number of hits per decade of steps would be a small constant: the machine would halt with probability 1, but after a number of steps with a long exponent. Counting sweep starts with |d − 1| ≤ 100 gives about 20 per decade of steps (between 14 and 28 in almost every decade from 103 to 1032), so about 0.1 expected hits of d = 1 per decade, about 3 over the whole run, where none occurred (a Poisson chance of about 5%: mildly surprising, not a sign of an invariant; the residues of d mod 6 near 0 are even). This is a model, not evidence either way.

Does it halt from blank tape?

Not known. Lean reduces the question exactly to whether the orbit of DeepMind's map from C(0, 0, 2) ever visits a state with m = 3b + 1; nothing known rules that out or predicts when it happens.
