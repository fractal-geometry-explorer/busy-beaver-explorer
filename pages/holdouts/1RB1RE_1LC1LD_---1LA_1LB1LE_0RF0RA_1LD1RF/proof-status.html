What is known about 1RB1RE_1LC1LD_---1LA_1LB1LE_0RF0RA_1LD1RF

1RB1RE_1LC1LD_---1LA_1LB1LE_0RF0RA_1LD1RF

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open, and probably cannot be settled by computation. Lean proves that the machine halts from blank tape exactly when an explicit arithmetic iteration reaches its halting case (halts_iff). The kernel evaluates its first epochs: they do not halt, and epoch 3 provably ends in a new epoch 4. Epoch 4 starts with a run of about 102·1013 ones; whether it halts at its end depends on parities of numbers with more than 1013 digits. Heuristically it halts there with probability 3/4, and eventually with probability 1.

Other proofs and outside reports

Community label

In the community's BB(6) tracker the machine's class is Bell-like. Its 3 November 2026 edition lists the machine as a cryptid: its halting is thought to come down to a Collatz-like question that no known method decides. These are labels read off the run by others, not results.

One phase

Write P c u x for the tape 0^inf 1^c (01)^u 0 0 (10)^x F> 0^inf. For u = 2 or 3 and x ≥ 1, P (c+4) u x reaches P c u' x' with X = x+u+4, u' = 2 + X mod 2, x' = 3⌊X/2⌋ − 1: four ones are eaten on the left, the block on the right grows by half. Built from the bounce rule L (01)^(x+2) 0 0 (10)^(y+1) F> → L (01)^x 0 0 (10)^(y+4) F> (4y+18 steps) applied k times.

phase, bounce_iter, lean/Phase.lean; bounce, glue2, glue3, lean/Rules.lean

The eight epoch ends

When fewer than 4 ones are left (r = c mod 4) and x ≥ 16: r = 3 gives the new epoch P (2x+4+2u) 3 5; r = 0 with u = 3, or r = 1 with u = 2, gives P (2x+5) 3 5; the four other cases (r = 0, u = 2; r = 1, u = 3; r = 2) halt.

end_some, end_none, lean/Phase.lean; end03 … end23, lean/Rules.lean

Halting is the iteration reaching none

With epochs 0 = some 3 and epochs (k+1) = (epochs k).bind ends, where ends c applies c/4 phases to (u, x) = (3, 5) and then the epoch-end table: the machine halts from blank tape if and only if epochs k = none for some k.

halts_iff, lean/Phase.lean

heuristic Evidence only

Growth shape: fixed/sqrt

Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.496).

tools/py/bbtools/triage.py

It probably halts, unimaginably late

Epoch 3 makes 114,817,814,715,807 phases, so c4 = 2x+4+2u has about 2·1013 digits and c4 mod 4 = 2(x+u) mod 4. If x+u is odd, epoch 4 ends with r = 2: a halt. If it is even, epoch 4 halts unless its own last u is 3. With the parities behaving like coin flips, the halt comes at the end of epoch 4 with probability 3/4, and eventually with probability 1 (r = 3 is always followed by r = 0 or 2, and r = 2 always halts). Computing the parity needs about 1027 bit operations at the very least.

Does it halt from blank tape?

Not known: equivalent (in Lean) to whether the epoch iteration ever reaches its halting case. The first undecided epoch end needs the parity of x+u after 1.1·1014 steps of X → ⌊3X/2⌋+5, numbers of up to 1013 digits; heuristically it halts there with probability 3/4.
