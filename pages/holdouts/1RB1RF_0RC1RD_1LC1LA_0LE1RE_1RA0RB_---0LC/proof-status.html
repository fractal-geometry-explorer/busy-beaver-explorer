What is known about 1RB1RF_0RC1RD_1LC1LA_0LE1RE_1RA0RB_---0LC

1RB1RF_0RC1RD_1LC1LA_0LE1RE_1RA0RB_---0LC

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state machine halts from blank tape. It is one of three G13 holdouts with the same behaviour (the others are 1RB0LA_1RC---_0LD1RD_0RA0RE_0RF1RC_1LF0LA and 1RB0LA_1RC---_0LD1RD_0RB0RE_0RF0LD_1LF0LA): a solid wall of 1s that grows to the right by 3 cells every time the head comes back to it, and in front of it a short list of blocks of 1s that the head rewrites on every pass, following a recursive rule found from the simulation and checked on more than a million passes. This page says what that rule is, what is checked, and what is still open.

Status as of 12 November 2026.

In short

The question is open. The run is understood at the level of passes: between two visits of the head to the wall the list of blocks changes by a short recursive rule, and every one of the 1,901,400 wall visits in the first 109 steps follows it (C simulator plus py/passmap.py, not a proof). The rule itself never halts; what is not understood is the rare pass in which the list reaches the wall, where in the sibling machine 1RB0LA_1RC---_0LD1RD_0RB0RE_0RF0LD_1LF0LA the whole structure collapses and restarts. Lean proves the bounded runs and that the machine halts if and only if the run reaches E>0 1 0.

The only way to halt

The run from blank tape halts if and only if it reaches a configuration E>0 1 0 (the head in state E on a 0, with these cells to its right). F is entered only by A1 = 1RF; A is entered by C1 = 1LA, which leaves a 1 right of the head, and by E0 = 1RA. So the halt is E>0 1 0, 1 A>1 0, 1 1 F>0. The proof is an invariant of the run: while no such configuration has occurred, A on a 1 has a 1 on its right and F reads a 1.

The pass map holds for the first 109 steps

Each time the head, in state E, stands just right of the wall (a run of at least 1000 1s followed by one 0), the tape right of the wall is a list of blocks 1^(3k) 0 (k = 0 meaning an extra 0) and a tail 1^(6+3j). Of these visits in the first 109 steps, 1,901,400 follow the pass map of the README from the previous visit: 1,901,400 after one pass, 0 after two or three (the head came back to the wall in another state in between, unseen by the sampler). 0 passes reach the wall itself, where the map does not apply. At step 999,999,9xx the wall has 5,706,542 cells and the list is 1 1 2 1 7 3 3 2 1 1 T0.

py/passmap.py, c/blkev.c

State E reads a 0 only 73 times in 109 steps

In the first 109 steps the head is in state E on a 0 exactly 73 times: 69 times with 0 0 0 to its right (last at step 459,739), once with 0 0 1 (step 2,506) and 3 times with 0 1 1 (last at step 241,338); a 1 never follows directly, so the critical 1 0 did not occur.

Growth shape: fixed/linear

Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows in proportion to the step count (the head drifts steadily that way) (fitted exponent 1.004).

py/passmap.py in each folder

Two encodings of the same list

On the way right the head rewrites each block 1^(3k) 0 as 1^3 0 (1^2 0)^(k-1) (same width), and on the way back it rewrites it again; only the end of the list, and the place of the first empty block, change from pass to pass.

Does it halt from blank tape?

Not known. Lean reduces the question to one pattern: the machine halts if and only if the run reaches E>0 1 0 (halts_iff_crit). Missing for a non-halting proof: Lean proofs of the pass rules for every list (they are recursive, so they need an induction on the list), and above all a rule for the passes that reach the wall, where the wall is erased, the structure restarts from the left end of the tape and later absorbs its own debris. Only a few such restarts have been seen, so their rule has to be derived from the machine, not fitted to data.
