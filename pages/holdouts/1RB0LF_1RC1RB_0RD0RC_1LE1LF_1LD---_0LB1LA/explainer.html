The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in E reading 1. E is entered only from D0 (writes 1, moves L): 1 D>0. So a halt is the moment this pattern appears, with the head on the cell after >.

One sweep

Rewriting the right part, back and forth

At step 16,085,367 the tape (as runs) is 11 0^6 111 0^8 1^21 0^7 1^2670 0^1377 with C on a 0 at the right end. Going left, D and E fill the zeros with ones, then A and F turn the big block of ones into (10)^1334. Near the left the head turns, and a slow zigzag (10 steps a pair) turns the (10) back into ones; then C, crossing the ones that were zeros, turns them back into zeros. After 18,762 steps the tape is ... 1^21 0^6 1^2669 0^1381: the block of ones lost one cell, the zeros gained four. All these passes are shift rules proved in Lean.

Many sweeps

The phase map

Sample the tape once a sweep, with C on the 0 at its right end: it reads w 1^K 0^Z, a counter word w, the long block of K ones, and the Z zeros the block has given back.

One sweep depends only on the counter. Lean proves the head's whole trip from the counter across the block and back, for every K and Z (pass_d, pass_c): the counter is not read, the block keeps its shape, Z grows by 4 and the step count is linear. The same trip with an odd number of ones would end in a halt, but the count only ever grows by 4. So a sweep can be run on a short block and lifted, and the right end of the tape never halts.

Many sweeps are an odometer. Inside a phase the counter works like an odometer whose digits are short runs of ones and zeros: each sweep changes its right end, down to the deepest carry, and takes 1 or 3 cells from the block (4 every two sweeps). A run of sweeps that stays inside the last v cells depends on those cells alone, so it is cached and reused, and long runs are built from short ones. Some thousands of sweeps are run for real per phase, however long the phase.

A phase. When the block is used up, the zeros (about 2K of them) become the new block and a phase starts with w 1^K 0^1. Phase 1 starts at step 13 with K = 6, then K = 14, 38, 94, 198, 418, 838, 1678, … In every phase so far

K(n+1) = 2 K(n) + 2      except at events, where it is 2 K(n) + 10
K(n) + 2 = 13448 · 2^(n-11) + 8 · Σ 2^(n-m)   (n ≥ 11, sum over the events m ≤ n)
t(n) / K(n)^2 → 5/6       (a phase lasts about 5K^2/2 steps)

The events after phase 6 are phases 11, 94, 122, 218, 490. An event follows exactly the phases whose counter ends in 1^2 0^2. Read from its right end the counter is a list of blocks 1^b 0^3 that change slowly, and the last block loses one 1 every phase: when it is gone, an event follows, the block before it becomes the last and merges with its neighbours, and the next event is about that many phases away. Read off phase 218 (last block 269 cells), this predicted an event at phase 490, and the run found it there; after it the last blocks merged into one of 2,581 cells, so the next is not due before about phase 3,080. The exact run reached phase 800 (step 1.60·10483) without a halt.

Could it stop?

Never a 1 behind D

E reading a 1 halts. Working backwards through the table, the only way there is D reading a 0 with a 1 just to its left (Lean: halt_shape). D reads a 0 in every leftward pass over the zeros, but the cell to its left is then still a 0: in 109 steps it read a 0 66.7 million times, always with a 0 on its left.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.111). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.508).

After 109 steps the tape spans 32,052 cells (120 left of the start, 24,496 right), with a density of 1s of 0.709.

Kernel
d_run, a_run, d_zigzag, b_run, c_run, lean/Rules.lean
The sweeps' shift rules

Leftward, D and E turn (00)^n into (11)^n, then A and F turn (11)^n into (10)^n, 2 steps a pair; rightward, a zigzag from 0 0 D> turns (10)^n back into (11)^n, 10 steps a pair; B crosses ones unchanged and C turns them into zeros.

Kernel
halt_shape, halt_after_shape, lean/Rules.lean
The shape of a halt

E on a 1 halts; E is entered only from D on a 0 (1LE). D comes from C on a 0 moving right (C wrote a 0 where E would land) or from E on a 0 moving left. So it halts iff D reads a 0 with a 1 to its left: 1 D> 0 puts E on that 1 (the converse by reading the table, not formalized).

Computed
python3 tools/py/bbtools/regaccel.py 1RB0LF_1RC1RB_0RD0RC_1LE1LF_1LD---_0LB1LA 6 600 mirror; holdouts/regaccel.json
No halt in the first 7.46×1035 steps (region-memo accelerator)

The region-memo accelerator tools/py/bbtools/regaccel.py ran the mirrored table (so that the counter is at the left end), with blocks of 6 cells, from blank tape for 600 seconds and reached step 7.46×1035 without a halt. It keeps the tape run-length coded and, for each stretch of tape from the left end, a macro (the run until the head first leaves that stretch) computed by a symbolic run of the machine with the long runs as variables; a macro is used only when the linear inequalities its symbolic run assumed hold, otherwise the stretch is run again by the same recursion. So the run is exact, step count included. Check: 21 configurations of this run (every time the head faced blank tape on the right, up to 2×109 steps) agree cell for cell with a direct run (tools/py/regcheck.py). This is a bounded run and says nothing about later steps.

Kernel
pass_d, pass_c, pass_d_halt, pass_c_halt, lean/Passes.lean
The trip through the block, for every length

Leaving the counter as 0 0 D> (or 1 0 C> 0) with (10)^(k+1) (11)^(2j+2) and blank tape to its right, the head crosses the block, turns and comes back, F (or A) on the block's first cell, in 8j + 12k + 32 (or + 34) steps, with 4 more ones and the counter unread. With an odd number of ones the same trip halts at the far end. So a sweep depends only on the counter (and K mod 4), and the right end never halts.

py/phasemap.py, c/sweep.c, results/phases.tsv
No halt to phase 800, about 10483 steps (phase map)

py/phasemap.py runs the machine exactly, step count included: each sweep on the counter with the block cut to 32 + K mod 4 cells and lifted (the trip above), runs of sweeps that stay in a suffix of the counter cached as an odometer would be, and phase changes run in full (checked linear in Z). It reached the start of phase 800, step 1.60·10483, with no halt. A bounded run: it says nothing about later phases.

Heuristic
results/phases.tsv; README, The phase map
The law of the phases (phases 1 to 800)

Phase n starts with w 1^K 0^1 (phase 1 at step 13 with K = 6). Then Kn+1 = 2Kn + cn with c = 2 except at phases 3 to 6 and 11, 94, 122, 218, 490 (c = 10), so from phase 11 on Kn + 2 = 13448·2n−11 + 8Σ2n−m over those m ≤ n; tn/Kn2 → 5/6. An event follows exactly the phases whose counter ends in 1^2 0^2; the counter's last block 1^b 0^3 loses one 1 a phase, so events are about a block length apart.

Does it halt from blank tape?

Not known. A halt needs 1 D> 0 inside the counter. Deciding it needs the counter word as numbers: the odometer of a phase and the list of blocks across phases.
