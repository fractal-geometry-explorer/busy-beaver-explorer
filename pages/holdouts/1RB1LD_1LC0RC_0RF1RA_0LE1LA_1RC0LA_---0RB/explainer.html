The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 0. F is entered only from C0 (writes 0, moves R): C>0 0. So a halt is the moment this pattern appears, with the head on the cell after >.

Macro structure

What the machine does: Collatz-like: blocks split 1:3 by quarters

After the start the tape is always a handful of long blocks of 1s, separated by gaps of one, two or four 0s, e.g. 1^1840 0 1^1387 0 1^1041 0^2 1^780 0^4 1^2338 0 1 at step 298,989,466. Everything the machine does is arithmetic on these block lengths.

Splitting by quarters. In state E, at a gap of two 0s before a block of M ones: 1^a E> 0 0 1^M 0 0 1^b. If M is odd, a bouncer runs through the block and back and the tape becomes 1^(a+1) E> 0 0 1^(M−4) 0 0 1^(b+3): four ones leave the block, one goes left and three go right. Lean proves this round for every odd M ≥ 11 and every tape around (quarter1, quarter3, quarter5 in lean/Rules.lean, 12n + 25 steps for M = 6n + 11 …); py/split.py checks it for odd M from 5. Repeated, it turns M = 4q + r into q ones added on the left and 3q on the right. In the run: 7359 = 4·1839 + 3 becomes 1^1840 … 1^5544 (1840 = 1 + 1839, 5544 = 27 + 3·1839), then 5544 → 1387 + 4158, 4158 → 1041 + 3118, …

Folding. An even block cannot be split this way; instead the head zig-zags between it and its left neighbour, moving two ones out of the neighbour and three into the block each time: A>0 1^90 0^2 1^7227 → A>0 1^88 0^2 1^7230 → … → 0^2 1^7362. So a neighbour of 2n ones is merged as 3n. Lean proves this for every n and every tape to the right (fold in lean/Fold.lean): A> 0 1^(2n) 0 0 1^M reaches A> 0 0 0 1^(M+3n), then A> 0 1 1 0 1^(M+3n).

These two moves (×1/4 and ×3/4 for odd blocks, ×3/2 for the fold) and the small cases at the end of a split (remainders 0–3, gaps of four 0s) make a Collatz-like map on the list of block lengths. The largest block grows like the square root of the step count (22,527 at step 1.87·109).

Halting

What a halt would require

F reading 0 halts. On small examples the split halts when it ends with M = 0, 2 or 4 in the shape above (the head meets three 0s in state E: E0 → C0 → F0), that is, when a split starts on an even block. In the first 3·108 steps that never happens: all 23,443 split rounds start on odd blocks, all folds are of even blocks. The split ends with M = 1 or 3 and hands over to the next block through a carrier 0 1 that runs right (end1, end3, carry, proved); what follows depends on the neighbouring blocks. If that parity pattern could be shown to be preserved, the machine would never halt; it is not known.

Lean

What is proved, and what is not

  • Rules (lean/Rules.lean, kernel): quarter1, quarter3, quarter5, described above.
  • Fold (lean/Fold.lean, kernel): fold and fold_full, for every n and M, from the rules fold_step, fold_last, fold_open in lean/FoldRules.lean.
  • Split endings, first steps (lean/FoldRules.lean, kernel): end1, end3, carry, lsweep.
  • Bounded run (lean/Blank.lean): no halt in 107 steps (native), 10,000 (kernel); the halting transition is the only way to stop.

Everything else on this page is observation of the simulated run (heuristic). Nothing here decides halting.

Next

What would move it forward

Write the rest of the split endings: after end1 / end3 the carrier crosses the next block, and then, depending on whether that block is followed by the right end of the tape or a gap of one or two 0s, a left sweep starts a new split or a fold. With those cases as symbolic rules, check whether "every split starts on an odd block" is preserved; if it is, that is a nonhalting proof.

fold, fold_full, lean/Fold.lean; rules in lean/FoldRules.lean (py/fold_rules.py)
The fold, for every size

For every n, every M ≥ 1 and every tape R to the right: 0^inf A> 0 1^(2n) 0 0 1^M R reaches 0^inf A> 0 0 0 1^(M+3n) R, and then 0^inf A> 0 1 1 0 1^(M+3n) R: a left-end block of 2n ones is merged into its neighbour as 3n. Three symbolic rules (fold_step, 12n + 23 steps per zig-zag; fold_last; fold_open) and an induction over n.

Where a halt can happen (closed tape language, 5-cell windows)

The closure search of bbtools.ctl with windows of 5 cells is closed but allows halts; the halting abstract configurations constrain the neighbourhood of a halt: a halt (F reading 0) needs 00000 or 00110 to the left and 01001, 0111x, 01110 or 01111 on the right (8 abstract configurations). A Python check, not a Lean certificate (the Lean library only has the right-edge and no-halt corollaries, which do not apply).

ev3 event log (scratch), README
Parity pattern in the run

In the first 3·108 steps every block that a split starts on is odd (23,443 split rounds start, 14,388 with M ≡ 3 and 9,055 with M ≡ 1 mod 4), every block folded at the left end is even (7,115 zig-zags), and every round that starts at the left end with A>1^K has K odd. A split on an even block is what halts (it ends at M = 0, 2 or 4 and E meets three 0s), so a proof that this parity pattern is preserved by the split endings would prove the machine never halts. The endings depend on the neighbouring blocks (the carrier 0 1 runs right to the next gap, then a left sweep, then a new split or fold), and that case analysis is not written down yet.

Open
Does it halt from blank tape?

Not known. F reading 0 halts. On small examples the split halts when it ends with M = 0, 2 or 4 in the shape above (the head meets three 0s in state E: E0 → C0 → F0), so halting is a question about remainders mod 4 of the blocks met by the splits: open, Collatz-like.
