Does this machine ever halt?

1RB---_1RC0LF_1RD1RD_1RE1RA_1LF0RC_1LC1LB

Nobody knows. This machine has run 1011 steps without stopping. Its tape is a list of numbers, each written as a block of ones two more than a multiple of three; a pattern walks along the list like a carry in a binary counter, doubling the time at every step. It can stop only from one local pattern, C> x 1 1, which it has never produced.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in A reading 1. A is entered only from D1 (writes 1, moves R): D>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

Structure

What the tape looks like

Seen at the moments the head, in state E, reaches a new cell on the right, the tape is a list of numbers: 1^(3a) 0 1^(3m1+2) 0 1^(3m2+2) 0 … 1^(3mk+2) 0 E>0, a first run of 1s whose length is a multiple of 3 and then blocks of 1s each two more than a multiple of 3, each followed by a single 0. In the 1011-step run 107 of the 130 such moments have exactly this form; the others are the moments when the head has just come back from the left end. The list ends in 2 0 0 … 0, and each new cell on the right appends one more 0 (a block 1 1 0). Further left one or two numbers change at each record, a pattern that walks left one block per record, and the time between records doubles each time: a binary clock. When the walk reaches the left part, the head visits the left end, the list is rewritten and a new walk starts.

Halting

The one way to stop

The halting transition is A reading a 1. A is entered only from D reading a 1, and D only from C, which writes a 1 and moves right whatever it reads. So C halts two steps later exactly when the two cells after it are both 1 (Lean: halt_ctx, halt_ctx'; the converse, that no other configuration halts two steps later, is halt_iff_2). C is entered from B on a 0, from E on a 1 (both moving right) and from F on a 0 (moving left, so F would need 0 1 under and after it); halt_pred_3 lists exactly these configurations three steps before a halt. So the machine halts exactly when it produces C> x 1 1; Lean proves both directions (halt_ctx: the steps from there to the halt; halt_iff_2: nothing else halts two steps later).

What is left

What a proof would need

Not known. The blocks keep every run of 1s short of the pattern x 1 1 after C at the places C is entered, as long as the list keeps its form; what is missing is the rule that rewrites the list (how a walk changes the numbers, and what the left end does), from which one could prove that the form is kept forever.

The basic moves are proved in Lean for every length (lean/Rules.lean: crossing a run of one word in a fixed number of steps per copy), so a proof would need only the rule of the counter on top of them.

The clock

2k applications of one map

At the visits of the right end in state C the tape is W (0 1 1)n 0 C>0, n growing by one per visit. From the visit at step 1,603,719,355 (n = 1), the word W at the visit with n = k+2 is the word at the visit before after exactly 2k applications of one base map (the run from the visit with n = 1 to the next), for k = 0, …, 8 (up to 256 applications). That is the clock of five other holdouts, where it is proved in Lean; here only the test by running the machine is done.
