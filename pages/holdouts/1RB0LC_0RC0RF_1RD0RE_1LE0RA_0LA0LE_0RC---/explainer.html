Does this machine ever halt?

1RB0LC_0RC0RF_1RD0RE_1LE0RA_0LA0LE_0RC---

Nobody knows. The machine counts in base 5 with markers that drift along the tape and now and then collide; a collision has never halted it, and it could only halt if two collisions came close together.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from B1 (writes 0, moves R): B>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The family

One core, forty machines

This machine is one of 40 holdouts built on the same five states. Written in one common frame (frame A), every one of them has the table

stateABCDEF
reads 01RB0RC1LD0LE1LAF0
reads 10LC0RB0RE0LF or 1LF0LBhalt

and they differ in three things only: the bit that D writes on its way into F (D1), what F does on a 0 (F0), and the state the run starts in. This machine is the mirror image (left and right exchanged) of the core with D1 = 0LF and F0 = 0LE, that is of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0LE---, with the states renamed A→D, B→E, C→A, D→B, E→C, F→F (frame B); its start state A is the core's state C. So its run from blank tape is, step for step and mirrored, the run of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0LE--- started in state C on blank tape, and the block lists below read right to left on this machine's own tape. Lean proves this for the machine's own table (halts_iff in lean/Family.lean): it halts from blank tape exactly if the frame-A table halts from blank tape in state C.

What the 40 machines share. States A to E never enter F while they run the nested counter, so between two entries into F all 40 machines do the same thing, and one law covers them. In frame A the tape is a list of blocks (10)^b; a visit to the list [b1, …, bk] makes five visits to the list without its first block. When the blocks are large and of the right parity (a clean visit) this has a closed form: b1 loses 5, block i loses 18·5i−2, the last block gains 12·5k−2. Both the recursion and the closed form are Lean theorems for every depth, on each of the 40 tables (go_spec, go_closed). Two quantities are therefore conserved by every clean visit (visit_conserves): the residue of block i modulo 18·5i−2, and the drift bi+1 − 5·bi of two neighbouring blocks (neither the first nor the last). The residue fixes at which phase and with which small value a block will run out; the drift is the length the next block still has at that moment.

This machine's run, seen from the left end. Each time the head comes back to the left end of the tape (frame A) the tape is a plain list of blocks. Move the slider through these moments: the middle blocks drain at their fixed rates, the last block grows, a block that runs out disappears and its neighbours merge, and new blocks are born at the right end. The list is from the exact block-list map (below), which was checked against the plain simulation of the machine on the F-events of the first 3·109 steps.

How far it has been run. The exact block-list map (clean visits by the proved closed form, every other visit by an exact run-length simulation) runs this machine for 1.4·10200 steps without a halt: 496 returns to the left end, 251 entries into F, every one reading 0, with the tape around the head 010001000100[F]001010101010 (208×, F reads 0); 010001000100[F]001010110101 (43×, F reads 0). Every one of these entries is the kind proved harmless in Lean (fevent, fevent_reads_zero): a visit ends in state C on the 0 of a phase-1 tail, and F then reads the last cell of a 1000.

Why this does not settle halting. A clean visit cannot halt, and an isolated exceptional event (one block running out between long neighbours, a birth, the harmless F-event) does not halt in any run so far. Short block lists of the same shape do halt, so a proof has to control the block lengths: it would have to show that two exceptional events never fall close together, that is, that a drift is never small when its block runs out. The drifts only change at exceptional events, where they are sums and differences of large earlier blocks; nothing is known that keeps them away from 0. Observed in this run, at the left-end events: after step 1020 the smallest drift in absolute value is 73,892, after step 10100 it is 5,610,142. That is evidence, not a proof, and it is sampled at the left-end events only.

Macro structure

A base-5 counter of markers

Stop the machine each time the head steps onto a new cell at the growing end. The tape is then always

1 (0010)b0 m1 (0010)b1 … mk (0010)bk 000

(mirrored in this machine: it grows to the left) long blocks of the word 0010 separated by markers, each in one of six phases: 1 (0), 0 (0′), 0011 (1), 011 (2), 11 (3), 00111 (4).

Between two such moments the head makes one sweep: a wave runs from the end toward the start, passing every marker in phase 4, and turns at the first marker that is not; that marker goes up one phase, and on the way back the phase-4 markers are reset to phase 0. The phases are the digits of a counter in base 5 that counts the sweeps. When every marker is in phase 4 the wave runs to the start of the tape and the counter gains a digit (a new marker at the end).

The blocks around a marker change with its phase (phase 0 takes two words from the block before it, phases 0′ and 3 one), so the markers drift toward the start, the last one fastest. When a marker has used up the block before it, it merges with the marker there: a few special sweeps, after which the counter goes on. Lean proves the regular sweeps for all block lengths.

Run the counter. The tape between two sweeps, written as its first block b0 and the markers with the block after each. Each step is one sweep of the machine by the two regular rules; the run stops at a merge, where a marker has used up the block before it and the machine does something special.








  Open question
  
Where it could halt


The only halting transition is F1, and F is entered only at some merges (and, in two of the sixteen machines, on a detour that does what the others do in one step). Every entry into F so far has read a 0. Every merge of two markers with long blocks around them runs, symbolically and for all block lengths, without halting. But short tapes of the same shape, where two short blocks meet, often halt.
So the machine halts only if two merges ever happen close together on the tape. The counter is deterministic, and the block lengths it makes look very regular (many are close to multiples of powers of 5), but nothing here decides whether such a coincidence ever comes.


Sixteen holdouts run this counter, in five distinct runs; this machine is in class III. The family is described in full on the page of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0LC---.

The family's visit rule and its closed form
In frame A a visit starts with the head in state A on the 0 in front of plain blocks (10)^b1 1 (10)^b2 1 … 1 and ends when the head first steps left of that cell. go_spec proves for every depth that a clean visit turns the list l into go n l in exactly goT n l steps (the first block is spread, the rest gets five visits, the first block is folded back 5 shorter); go_closed gives the closed form (b1−5, b2−18, b3−90, …, bk+12·5k−2) when b1 is odd and at least 7, the other blocks even and block i at least 2+18·5i−2. visit states it as a run of this machine. Also proved: the birth of a block, and that the entry into F after a visit that ends in state C on a phase-1 tail reads a 0 (fevent, fevent_reads_zero). The proofs are generated for this machine's own frame-A table; they never use F0.

tailEff_res, tailEff_drift, visit_conserves, lean/Family.lean
What a clean visit conserves
For the blocks after the first, the last one left out: a clean visit (a list the closed form applies to) changes neither the residue of block i modulo 18·5i−2 nor the drift bi+1 − 5·bi of two neighbours. So these numbers change only at the exceptional events (a block running out, a birth, an entry into F, the left end). This is a law between events, not a proof that the machine never halts.
