A 6-state Busy Beaver machine · Status as of 13 November 2026.

Does this machine ever halt?

1RB0LE_1RC---_0RD0RE_1LE0RB_0LA0LF_0RC0LD

Nobody knows. Started on a blank tape, this machine bounces back and forth across a tape of 4-cell blocks, and its run comes in phases: inside a phase every round trip does the same thing (proved in Lean for every size), and at the end of a phase the tape is rebuilt about three times bigger. A symbolic search finds that it can only stop from one tape shape, reached when two block counts hit an exact line; in about 10111 steps they have not.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in B reading 1. B is entered only from A0 (writes 1, moves R): A>0 1; D1 (writes 0, moves R): D>1 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

Where it could stop

The one way to halt

The table has one halting entry: state B reading a 1. B is entered in two ways: A reads a 0, writes a 1 and moves right (A>0 1 halts at once), or D reads a 1, writes a 0 and moves right (D>1 1 halts). So the machine halts exactly when, at one of these two moments, the cell to the right of the head holds a 1.

In the first 108 steps B is entered more than 13 million times and always finds a 0. Most of these entries happen inside the long sweeps, where the blocks around the head are fixed words, so they are safe by construction; the danger is concentrated at the two ends of the tape, where the head turns.

Macro structure

The main regime: blocks of four cells

Stop the simulator each time the head stands at the left end of the tape in state F. Most of the time the tape then reads

F>0^6 (1000)^a 1 0 1 1 1 (0001)^b T

where T, the tail, is one of three short words that take turns: 0 1 0 0 0 1 0 1 0 0 0 0 1, 0 1 0 1 1 0 1 0 0 0 0 1 and 0 1 1 1 0 1 1. One round trip of the head does this:

  • Moving right, a pair of 0s travels with the head (state D) and turns every block into solid ones: 0 0 D>1 0 0 0 becomes 1 1 1 1 0 0 D>, 28 steps per block, and the 0001 blocks likewise. Halfway through a sweep the whole tape looks like 1^(4a+…) 0 0 0 1^(4b+1) ….
  • At the right end the tail changes to the next of its three shapes, and on two shapes of three it swallows one block 0001.
  • Moving left, state A turns the ones back into blocks: 1 1 1 1 A>1 becomes A>1 0 0 0 1, 10 steps per block, which, read from the other end, is again 1000.
  • At the left end a short dance (states F, D, A, E) writes two more blocks 1000.

So three round trips take a = 13, b = 27 to a = 19, b = 25. Lean proves this for every a and b: with P a b the tape above with the first tail, P a (b+3) becomes P (a+6) (b+1) in 114a + 114b + 1115 steps (P_step), and by induction P a (b+2k+1) becomes P (a+6k) (b+1) (P_iter). The run from blank tape is exactly P 13 27 after 30,224 steps (reach_P), so for the next 13 rounds of three trips nothing can go wrong.

The long run

Phases, each about three times the last

A regime like this cannot last: the 0001 blocks run out. Then the tail meets the solid part, the head carries a message to the left, and the tape is reorganised: the left blocks, about 3b of them, become the right reservoir of the next phase, and the left part starts again from (1000)^3. The phases start with

b = 0, 2, 6, 32, 94, 287, 862

at steps 613, 1,279, 3,045, 22,299, 150,253, 1,249,630 and 10,800,216 (py/phases.py). The factor is about 3, but the offsets (32 = 3·6 + 14, 94 = 3·32 − 2, 287 = 3·94 + 5) depend on which tail shape is current when the reservoir runs out: an arithmetic dependence of the kind that makes a machine Collatz-like.

After the phase with b = 862 the rebuild is incomplete: a second segment (1000)^859 stays behind on the right, and the next phases start at b = 8, 36, 290, 1156 while that segment shrinks to 850, 742, 454. So the long run is a nest of counters, a segment being used up as fuel by the phases inside it. At 3·1011 steps the tape has three long segments. Whether the machine halts depends on whether some phase end ever leaves a 1 to the right of A>0 or D>1, and that needs the phase ends worked out in general, which is the next step.

Class search

One halting shape, two exact lines

Look at the tape each time the head is at the left end in state F and the tape starts 00001 (1000)^k 101. A symbolic simulator can run such a tape with its long block counts left as unknowns, and tells us when the outcome depends on them. Sorting the tapes into classes (a shape, with the parity of each long count) and running each class to the next such tape gives a finite list: 185 classes, cut into 3,768 pieces, and every piece ends in a class of the list. This is the closed-set method that proved two other holdouts non-halting, but here one class halts:

H(P) = F> 00001 (1000)^P 101000011011101 (P odd)

H is entered from only two shapes, each holding two long blocks, and only when their counts are in an exact relation:

A(P,Q) = F> 00001 (1000)^P 10100001101000 (0001)^Q 01000000101 with Q = 3P − 16
B(P,Q) = F> 00001 (1000)^P 101000010000001011 (1000)^Q 101000000101 with Q = 3P − 24

A plain step-by-step simulator confirms it on examples: A(27, 65) halts after 480,259 steps, A(27, 63) and A(27, 67) do not halt in 3 million. So the machine halts from blank tape exactly if its run ever meets A or B on its line (a result of these programs, not yet of Lean).

Does it? In an exact accelerated run of about 10111 steps, A comes up 108 times and never closer than 749 blocks to its line; B comes up 1,236 times, always with Q even where the line needs Q odd. Finer residues (mod 4, mod 8) do not rule the A line out. The question has become: does one orbit of a pair of numbers ever hit a line? That is the same kind of question as the Collatz-like holdouts, and it is open.

Heuristic
py/phases.py
Phases that roughly triple

A phase starts at F>0^6 (1000)^3 1 0 1 1 1 (0001)^b …. The successive starting values are b = 0, 2, 6, 32, 94, 287, 862 (steps 613 to 10,800,216): during a phase the left part grows by 6 blocks while the right loses 2, so it ends with about 3b blocks of 1000, and these become the next phase's 0001s. After b = 862 the rebuild is incomplete and a second segment (1000)^859 stays to the right; the next phases (b = 8, 36, 290, 1156) eat it slowly (859, 850, 742, 454). The phase map depends on which of three tail shapes is current when the 0001s run out, an arithmetic (Collatz-like) dependence that is not analysed yet.

Computed
py/closure/pclosure.py, py/closure/paccel.py; certificates py/closure/classes_mod2.json.gz, classes_mod8.json.gz
A closed set of 185 node classes with one halting shape

A node is the tape at a left-end event in state F that reads 00001 (1000)^k 101…. A class is a node shape in which every count of at least 20 is free, with a fixed parity. Each class is run symbolically (several free counts at once) to the next node; when a run needs to know more about the counts the class is split into pieces. Starting from the node at step 20,791 of the run from blank tape the search ends: 185 classes, 3,768 pieces, none undecided. Every piece reaches a node of a class in the set, except two pieces that halt, both of the shape H(P) = F> 00001 (1000)^P 101000011011101 with P odd. With residues mod 4 and mod 8 the search also ends (318 and 430 classes) and again only H halts. This is a result of the programs, not of Lean.

The halting shape is reached only on two lines

In the certificate the only pieces that lead to H are: shape A(P,Q) = F> 00001 (1000)^P 10100001101000 (0001)^Q 01000000101 with Q = 3P − 16, which runs to H(8P − 27), and shape B(P,Q) = F> 00001 (1000)^P 101000010000001011 (1000)^Q 101000000101 with Q = 3P − 24, which runs to H(8P − 41) (P odd, at least 21). So, as far as the programs are right, the run from blank tape halts if and only if it visits A or B on its line. Residues do not separate the lines from the rest of A and B (checked up to mod 8), so the class method cannot decide the machine.

Heuristic
python3 py/closure/hline.py run 120 py/closure/classes_mod2.json.gz
How close the run comes to the two lines (observed)

In that run A is visited 108 times; the closest to its line is |Q − 3P + 16| = 749, and the residues of P and Q show no obstruction (P mod 8 is 1, 3 or 7, Q takes every residue). B is visited 1,236 times, always with P ≡ 7 mod 8 and Q even, so Q − 3P + 24 is odd and the B line cannot be hit while this holds; it is observed, not proved (the class set allows odd Q).

Open
Does it halt from blank tape?

Not known. By the class search it is the question whether the pair of block counts (P, Q) ever lands on the line Q = 3P − 16 at shape A or Q = 3P − 24 at shape B: a Collatz-like question about one orbit. Next steps: a proof that B is only visited with Q even, the node map as explicit arithmetic iterated much further, and a Lean replay of the certificate.
