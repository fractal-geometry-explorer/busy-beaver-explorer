A 6-state Busy Beaver machine · Status as of 12 November 2026.

Does this machine ever halt?

1RB1RA_1LC1LB_1RE0LD_1RA0LB_---0RF_1RC0RA

Nobody knows. The tape is a list of blocks of 1s, and the head gives half of each block to its two neighbours. Lean proves that the machine halts exactly when one explicit orbit of block lists puts 2^k − 1 ones in the last block at the right moment: a question about the binary digits of a number, like Collatz.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in E reading 0. E is entered only from C0 (writes 1, moves R): C>0 0. So a halt is the moment this pattern appears, with the head on the cell after >.

The tape

Blocks of 1s, split in halves

The tape is always a list of blocks of 1s. Left of the head the blocks are separated by one 0, right of it by 00. The head works through the blocks from left to right, one pass at a time. Standing in state E on the first cell of a block of b ones, it makes round trips inside the block; every round trip removes two of its 1s and gives one to the block on the left and one to the block on the right.

  • b odd, b = 2j + 1: after j round trips a single 1 is left. It becomes a new block 11 and the head goes on to the next block, which has grown by j.
  • b even, b = 2j + 2: after j round trips the head turns back. On its way to the left end every block it passes loses a 1 and its separator 0 becomes 00; then the next pass starts.
  • b = 0: E reads a 0 and the machine halts.

One pass from the run (steps 2,313 to 3,633; E> is the head, on the first cell of the block written after it):

1^6 0 11 E> 1^35 00 1^8                     35 = 2·17+1

The rule

The map G, proved

Write e fs b rest for the head in E on a block of b, with the list fs of blocks to its left (nearest first) and the list rest of blocks to its right, and s fs m rest for the head in B on the 0 in front of a block of m, on the way back. Let c be the first entry of rest (0 if there is none) and let inc j add j to the first entry of a list. The whole machine is this table:

fromto
e fs 0 resthalt
e fs (2j+1) (c :: rest)e (2 :: inc j fs) (c + j) rest
e fs (2j+2) (c :: rest)s (inc j fs) (c + j + 3) rest
s (f+2 :: fs) m rests fs f (m+1 :: rest)
s (1 :: g :: fs) m rests fs (g + m + 3) rest
s (0 :: fs) m rest, s [] m reste (inc 1 fs) (m + 1) rest

Every row is a Lean theorem for all values (G_sem in lean/Map.lean): the machine really goes from the left configuration to the right one, in at least one step. Blank tape reaches s [] 3 [] after 8 steps, so the machine halts from blank tape if and only if the orbit of s [] 3 [] under G reaches the first row (halts_iff). Nothing is assumed in that statement.

G is cheap to iterate: one application handles a whole block however long. A C program with exact step counts (c/gs.c) has followed it for 2·1010 applications, which is 2.6·1027 steps of the machine, without a halt. Lean itself checks the first 107 applications.

What halting would need

A last block of 2^k − 1 ones

The first row needs a block of length 0 under the head. Blocks to the right of the head are never empty, so this happens in one way only: a pass gets through every block (each one odd when the head arrives) to the last block of the tape, and that block has 2k − 1 ones. Then 2k − 1 → 2k−1 − 1 → … → 3 → 1 → 0: each halving leaves an odd number, the head never turns back, and E reads 0 (Lean: last_block_halts). With any other last block an even number turns up and the head turns back.

So the question is about the binary digits of one number at the moments a pass reaches the right end. That happens about once in 140 applications of G, and the number is then a large part of the tape (the median is 0.6 of all the 1s). If it behaved like a random number, the chance that it is all 1s in binary would add up to an expected 0.02 to 0.03 halts each time the tape doubles, for ever: a halt is not excluded by any residue argument we know, and it is not likely soon either. The closest call so far was at application 219,298, where the last block was 49,151 = 1011111111111111 in binary: one digit off.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.355). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.304).

After 109 steps the tape spans 4,709 cells (3,258 left of the start, 537 right), with a density of 1s of 0.998.

Kernel
lean/Rules.lean (generated by py/rules.py)
Shift rules of the sweeps

The head crosses blocks of 1s: L A> (1)^n R to the right and L (1)^n B>1 R to the left, one step a cell, for every n and all tapes L, R.

Kernel
lean/Leaves.lean (generated by py/leaves.py)
The leaf rules

Eight rules, each for every block length and any tape around it: one round trip inside a block (L E> 1b+4 00 R becomes L 1 E> 1b+2 00 1 R in 2b + 11 steps: the block gives one 1 to each side), the end of an odd block, the end of an even block, and the steps of the way back to the left end. Found and proved by bbtools.symtm.prove.

Kernel
G, rounds, G_sem, lean/Map.lean
The map G on block lists

Two kinds of configuration, each given by a list of block lengths: e fs b rest (state E on the first cell of a block of b ones; fs are the blocks to its left, separated by single 0s, rest the blocks to its right, separated by 00) and s fs m rest (state B on the 0 in front of a block of m, on the way back). G is an explicit computable map on them: an odd block 2j+1 gives j ones to each neighbour, leaves a block 11 and the head goes on; an even block 2j+2 gives j to each neighbour and the head turns back; on the way back each block loses a 1. The theorem G_sem says, for every such configuration x and with nothing assumed: if G x is a configuration y, the machine goes from x to y in at least one step; if G x is undefined, the machine halts from x.

Kernel
halts_iff, G_none_iff, lean/Map.lean
Halts iff the orbit of G halts

The machine halts from blank tape if and only if the orbit of s [] 3 [] (the tape B> 0 111, reached from blank tape in 8 steps) under G reaches a configuration where G is undefined. Those are exactly the configurations e fs 0 rest: state E reading 0 (G_none_iff).

Kernel
last_block_halts, lean/Map.lean
A last block of 2k − 1 ones halts

If the head arrives in E at the last block of the tape and that block has 2k+1 − 1 ones, the orbit halts k + 2 applications of G later: the block is halved k times down to a single 1, and then E reads 0. In the run this is the only way to halt, because blocks right of the head are never empty (this last remark is read off the rules, not a Lean theorem).

Heuristic
c/gs.c
A halt is neither excluded nor likely soon

A pass reaches the right end of the tape about once in 140 applications of G, and the last block is then a large part of the tape (the median is 0.6 of all the 1s); it halts only if that number is 2k − 1. If the last blocks behaved like random numbers this would give an expected 0.02 to 0.03 halts each time the tape doubles, for ever (about one expected halt over the run so far, so that seeing none is unremarkable). The 2-adic valuations of (last block + 1) seen in the run are distributed like those of random numbers, so no residue invariant excludes a halt. Closest call: application 219,298, last block 49,151 = binary 1011111111111111.

Open
Does it halt from blank tape?

Not known. By halts_iff the question is exactly whether the orbit of G ever sends the head to the right end of the tape with a last block of 2k − 1 ones: a Collatz-like question about the binary digits of one number in an explicit orbit.
