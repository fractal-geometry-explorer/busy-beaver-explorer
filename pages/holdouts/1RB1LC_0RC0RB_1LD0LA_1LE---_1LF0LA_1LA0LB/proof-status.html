What is known about 1RB1LC_0RC0RB_1LD0LA_1LE---_1LF0LA_1LA0LB

1RB1LC_0RC0RB_1LD0LA_1LE---_1LF0LA_1LA0LB

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

The tape holds two binary counters: U, counting up, and V, counting down. Each tick adds 1 to U and takes 1 from V; when V runs out the machine reads a few digits off the bottom of U and writes a new, longer V. That rebuild is now worked out as a function of the counter.

Status as of 9 November 2026.

In short

The question is open, and reduced to the rebuild map. Lean proves the ticks, any phase of ticks, 38 rebuild rules and one theorem for an infinite family of rebuilds (every k). Every rebuild stops by a 4-state walk over pairs of digits of N (checked for every N < 216, not proved); the subtracted δ has no closed form in general. The machine halts if and only if some rebuild of the run gives δ = N' + 1.

Probably never. No halt in the first 1017730 steps (exact macro simulation); from the seventh rebuild of the run on N' is hundreds of digits longer than δ, and a random-digit model makes the coincidence vanishingly unlikely.

The tick rules of the two counters

For each of the headers 0110101, 0110111 the run uses, two theorems: with V odd, L 00000 (00001)^j 00 D>0110101 01 R becomes L 00001 (00000)^j 00 D>0110101 11 R in 10 * j + 34 steps; with V having i + 1 trailing zeros, L 00000 (00001)^j 00 D>0110101 (11)^(i+1) 01 R becomes L 00001 (00000)^j 00 D>0110101 (01)^(i+1) 11 R in 8 * i + 10 * j + 42 steps. That is U + 1 and V − 1 for every number j of carries and i + 1 of borrows and every tape L, R beyond (proved along the symbolic run of tools/py/bbtools/symtm.py).

38 rebuild rules

For 38 residue classes of the up-counter N modulo 2j (j in [3, 5, 7], headers 0110101, 0110111) the rebuild after V = 0 is proved for every length n of V and every tape L left of the digits it reads: L dj-1..d0 00 D> H (11)^(n+k) 1 0^inf becomes L 00 D> H' w (01)^(n+e) 1 0^inf, that is: the up-counter loses its lowest j digits (N becomes N >> j) and the new down-counter is 2n+k+c − δ with c and δ fixed by the class. For example, header 0110101 and N = 1 (mod 23): new header 0110101, 8 more digits, δ = 737. The classes were found by sampling; each theorem is then proved along the symbolic run of tools/py/bbtools/symtm.py.

lean/Rebuild.lean (38 theorems, written by holdouts/1RB1LC_0RC0RB_1LD0LA_1LE---_1LF0LA_1LA0LB/py/gen_rebuild_rules.py)

Any run of ticks

For both headers, every up-counter U (of any width w), down-counter V and every k ≤ V with U + k < 2w: k ticks take the tick configuration to the one with U + k and V − k, the widths unchanged and no cell beyond the counters read. Proved by induction on k from the tick rules.

phase, lean/Phase.lean

The rebuild for a whole family, every k

For every k ≥ 1, b in {0, 1}, n ≥ 2k + 3 and every tape beyond: when V = 0 has n digits, the header is 0110101 and the lowest 2k + 3 digits of N are, from the bottom, 2k + 1 ones, a 0 and b, the rebuild ends at the clean tick configuration with up-counter N >> (2k + 3), header 0110101 (b = 0) or 0110111 (b = 1), and a down-counter of n + 5k + 8 digits with value 2n+5k+8 − δ + b, δ = 1 + 32k+1 (3 · 22k+3 − 1). One theorem for the whole family, not one per class: four local passes proved along symbolic runs (lean/Family.lean, written by py/gen_family.py), four phases of 22k − 1 or 22k+1 − 1 ticks by the phase lemma, and two carries into the top word. For k = 1 it is the class N = 7 or 23 (mod 25) of lean/Rebuild.lean (δ = 97281).

The macro map and its simulator

At each moment V reaches 0 the tape is the clean configuration 0^inf F U 00 D> H (11)^n 1 0^inf (F the counter's top word), so the state is (H, n, N) with N the up-counter read as one number. py/rebuild.py writes that tape, runs the rebuild (tick runs of its sub-phases jumped by the proved tick rules, the rest cell by cell in C) to the next clean tick configuration (H', n', N', V'), and then adds the V' ticks of the phase by arithmetic: next state (H', n', N' + V'), steps by the closed formula of the tick costs. Tested: its first 7 states and step counts, up to about 10161 steps, equal those of py/counters.py (itself tested against tools/c/tmrun.c).

The rebuilds that halt, N < 216

For every N < 216, both headers, and n − len(N) + 1 in {0, 1} (the only values the run produces, len(N) the number of binary digits of N with the sentinel), the rebuild halts in exactly 22 cases, all with N = 2L+1 − 1 (every digit 1): header 0110101 with L even (n = L or L + 1), header 0110111 with L odd and n = L. The halting step counts grow by a factor 4 per two digits (1727, 6769, 26787, ... for header 0110101, n = L + 1). Every other rebuild returns to a clean tick configuration.

A halting configuration two rebuilds away

For N < 214 (same inputs) the rebuild always gives N' = N >> j for some j, or N' = 2, and N' − δ = −1 (the next counter N' + V' all ones) only for N = 5885 and 5889, n = 12, 13, header 0110101. For N = 5889, n = 13 that all-ones counter has the halting parity: the tape 1 [5889 in 5-cell digits] 00 D>0110101 (11)^13 1, run directly by c/fromtape.c, halts after 545,221,856 steps (a rebuild, 221 − 737 ticks, a halting rebuild), the same count as the macro simulator's. So the machine can halt from configurations of its own family; the question is whether the run from blank tape reaches one.

Where every rebuild stops: a walk over pairs of digits

The rebuild reads N's digits from the bottom in pairs b2i+1b2i and moves a 4-state automaton (table on the explainer page); header 0110101 starts it in O, 0110111 in Q. If it stops on its k-th pair, j = 2k + 1 digits are read, N' = N >> j, the new header is 0110101 or 0110111 by the last digit read, and V gains c = (5j + 1)/2 digits. Compared with the exact rebuild of py/rebuild.py: for every N < 216, both headers and n − len(N) + 1 in {0, 1}, 151,368 rebuilds follow it and none contradict it; 110,768 are not covered (the walk does not stop below the top digit of N). For 2,000 random 200-digit N, both headers, all 4,000 follow it (longest walk j = 127). In the macro run from blank tape, 940 of the first 941 rebuilds follow it (longest walk j = 5,015); the other one, rebuild 5, is not covered: its walk reaches the top of N (it read 80 of the 82 digits and left N' = 2). The automaton was read off the data; it is not proved.

The reduction: halting iff δ = N' + 1 once

If the halting rebuilds are the all-ones ones for every N (checked below 216), then, since the next counter is N' + V' = 2n' + N' − δ, the machine halts if and only if some rebuild of the run gives δ = N' + 1 with new header 0110101 and n' odd. A rebuild of a proved class has a fixed δ (at most 24 digits for j ≤ 7) and N' = N >> j, so once N has more than 31 digits (from the second rebuild on) only the classes not yet in Lean (j ≥ 9) can do it.

What the rebuild map looks like in the run

All 847 rebuilds of the macro run have N' = N >> j. j is odd except once (rebuild 5 read 80 of the 82 digits) and then the new V has c = (5j + 1)/2 more digits than the old. The number of digits read has a long tail (84 with j = 3, 108 with j = 5, 83 with j = 7, 77 with j = 9, 61 with j = 11, 54 with j = 13; up to j = 2481), like the stopping time of a random walk on the digits. From rebuild 7 on, N' always has at least 301 more digits than δ (the gap grows with n), so δ = N' + 1 never came close.

Probably never halts

δ has about 2.5j to 3.5j digits and N' about len(N) − j, so δ = N' + 1 needs a rebuild that reads about a quarter of the counter and then an exact match of the remaining three quarters, digit for digit. Treating those digits as random, that has probability about 2−0.7 n at a rebuild with n digits; n is over 45 from the third rebuild on and grows by about 70 per rebuild, so the sum over the whole run is tiny. A heuristic, not a proof: the digits of N are produced by the machine, not drawn at random.

What δ depends on

Outside the family above, δ is not a function of the walk's path alone: for the same path it depends on the lengths of the runs of 00 and 11 pairs (growing by a factor of about 4 per pair). Inside, the rebuild runs phases of ticks with small counters over the low digits (on a grid shifted by one cell), and some of these reach V = 0 and run a smaller rebuild. No closed form of δ for all N was found; the family is the simplest path (O, ..., O, stop).

Does it halt from blank tape?

Not known. Lean proves the ticks, any phase of ticks, 38 short rebuild classes and the family above for every k; the stopping rule of every rebuild is a 4-state walk (checked, not proved), but δ outside the family has no closed form yet. So neither the rebuild for all N nor an invariant excluding δ = N' + 1 is proved, and non-halting from blank tape is not proved.
