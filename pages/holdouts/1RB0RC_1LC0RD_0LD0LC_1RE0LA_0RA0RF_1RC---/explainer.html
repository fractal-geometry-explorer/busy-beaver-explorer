This machine is a nested counter: the tape is a row of blocks, and between them small gadgets count to five and carry to the right, like the wheels of an odometer that eat the blocks they sit between. The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from E1 (writes 0, moves R): E>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The family

One core, forty machines

This machine is one of 40 holdouts built on the same five states. Written in one common frame (frame A), every one of them has the table

stateABCDEF
reads 01RB0RC1LD0LE1LAF0
reads 10LC0RB0RE0LF or 1LF0LBhalt

and they differ in three things only: the bit that D writes on its way into F (D1), what F does on a 0 (F0), and the state the run starts in. This machine is the mirror image (left and right exchanged) of the core with D1 = 0LF and F0 = 1LB, that is of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_1LB---, with the states renamed A→B, B→C, C→D, D→E, E→A, F→F (frame G); its start state A is the core's state E. So its run from blank tape is, step for step and mirrored, the run of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_1LB--- started in state E on blank tape, and the block lists below read right to left on this machine's own tape. Lean proves this for the machine's own table (halts_iff in lean/Family.lean): it halts from blank tape exactly if the frame-A table halts from blank tape in state E.

What the 40 machines share. States A to E never enter F while they run the nested counter, so between two entries into F all 40 machines do the same thing, and one law covers them. In frame A the tape is a list of blocks (10)^b; a visit to the list [b1, …, bk] makes five visits to the list without its first block. When the blocks are large and of the right parity (a clean visit) this has a closed form: b1 loses 5, block i loses 18·5i−2, the last block gains 12·5k−2. Both the recursion and the closed form are Lean theorems for every depth, on each of the 40 tables (go_spec, go_closed). Two quantities are therefore conserved by every clean visit (visit_conserves): the residue of block i modulo 18·5i−2, and the drift bi+1 − 5·bi of two neighbouring blocks (neither the first nor the last). The residue fixes at which phase and with which small value a block will run out; the drift is the length the next block still has at that moment.

Why this does not settle halting. A clean visit cannot halt, and an isolated exceptional event (one block running out between long neighbours, a birth, the harmless F-event) does not halt in any run so far. Short block lists of the same shape do halt, so a proof has to control the block lengths: it would have to show that two exceptional events never fall close together, that is, that a drift is never small when its block runs out. The drifts only change at exceptional events, where they are sums and differences of large earlier blocks; nothing is known that keeps them away from 0. Observed in this run, at the left-end events: after step 1020 the smallest drift in absolute value is 4,664, after step 10100 it is 1,783,318. That is evidence, not a proof, and it is sampled at the left-end events only.

The picture

Blocks that change form at every sweep

The tape is made of two words, a = 10 and b = 1000. Moving right, the head turns every b it crosses into aa; moving left, it turns aa back into b. So a block is a2y or by depending on which way the head last went through it. The blocks are separated by short gadgets: g0 = 1001, g1 = 1001100, g2 = 100110, g3 = 10011, g4 = 10010, or a bare 0 (s).

The rule

An odometer of five-state wheels

Look at the tape each time the head comes back to the left end in state D. It reads bk G1 by1 G2 by2 … Gn. One round later the first block has one more b and the first gadget has advanced one step in the cycle g0 → g1 → g2 → g3 → g4 → g0:

step of the wheelalso
g0 → g1the block after it loses one b
g1 → g2, g2 → g3nothing
g3 → g4carry: the next gadget advances
g4 → g0one b moves from the block after to the block before
s → g0the block before loses one b

So gadget i+1 turns once for every five turns of gadget i, exactly like an odometer, and each full turn of a wheel drains two b from the block on its right. Every one of these rounds is a theorem in Lean, for all block lengths.

When a carry runs off the last gadget, the head sweeps across the whole tape and back (a reset): all gadgets become s, and a new wheel is born at the left end. The full sweeps are the rare moments when the head reaches the right end of the tape.

Why it is hard

Wheels that run out of road

A wheel drains the block on its right, and a block can run empty. Then the two gadgets on either side meet and something irregular happens: they merge into a short-lived gadget (100, 1, 10, …), or blocks merge, or a new wheel appears. These events are rare (a few dozen in 109 steps against tens of thousands of regular rounds) but they decide the shape of everything that follows.

State F, the only one that can halt, is used only in one such event: two g4 wheels meeting across an empty block. The five machines of the family differ exactly there: in this one a new level b g1 is born at the left and the pair becomes the gadget X = 100 (later a carry into X acts like a carry into the end of the tape). F always reads a 0 there; a halt would need the pattern D>0 1 1, which no event seen so far produces.

Why shapes are not enough

A closed alphabet, but no closed set

One way to prove that a machine never halts is to find a set of tape shapes that contains the start, maps into itself, and never allows a halt. Here the shapes would be rows of gadgets with blocks of any length. The gadgets do close: the irregular events only ever produce eight more of them (1, 10, 100, 1001101, 10011010, 10011011, 100110110, 1001101100), so the alphabet is finite.

The set itself does not close. When the transient gadget 10 meets the transient gadget 1 across an empty block, the stretch 101 appears, and with the head arriving on it in D the machine halts (trap_halts, proved in Lean). Worse, b6 g4 b5 g4 b2 g0 b2 g0, a tape of regular gadgets with no empty block, also leads to a halt (witness_halts). Which tapes are safe depends on the block lengths, on whether two blocks empty at the same moment. That is arithmetic the shapes do not see.

The family's visit rule and its closed form

In frame A a visit starts with the head in state A on the 0 in front of plain blocks (10)^b1 1 (10)^b2 1 … 1 and ends when the head first steps left of that cell. go_spec proves for every depth that a clean visit turns the list l into go n l in exactly goT n l steps (the first block is spread, the rest gets five visits, the first block is folded back 5 shorter); go_closed gives the closed form (b1−5, b2−18, b3−90, …, bk+12·5k−2) when b1 is odd and at least 7, the other blocks even and block i at least 2+18·5i−2. visit states it as a run of this machine. Also proved: the birth of a block, and that the entry into F after a visit that ends in state C on a phase-1 tail reads a 0 (fevent, fevent_reads_zero). The proofs are generated for this machine's own frame-A table; they never use F0.

Kernel
tailEff_res, tailEff_drift, visit_conserves, lean/Family.lean
What a clean visit conserves

For the blocks after the first, the last one left out: a clean visit (a list the closed form applies to) changes neither the residue of block i modulo 18·5i−2 nor the drift bi+1 − 5·bi of two neighbours. So these numbers change only at the exceptional events (a block running out, a birth, an entry into F, the left end). This is a law between events, not a proof that the machine never halts.

Halting would need two exceptional events close together

A clean visit cannot halt, and in the runs every exceptional event with long blocks around it ends without a halt; short lists of the same shape do halt. When block i runs out, the next block has about the length of their drift, so a second event close by needs a drift near 0 at that moment. Heuristic
Why it is hard

The odometer itself is regular, but the block lengths it drains come from earlier resets, and when a block runs empty the gadgets on both sides merge in ways that depend on their phases mod 5. The sequence of these events, and whether one ever produces D>0 1 1, looks irregular; CTL with 4 to 8 states finds no closed invariant.

Open
Does it halt from blank tape?

Not known. A proof of non-halting needs an invariant that relates block lengths (for example, that the gadget 10 never meets the gadget 1 across an empty block). Shapes alone do not suffice: witness_halts gives a tape of regular gadgets from which the machine halts.
