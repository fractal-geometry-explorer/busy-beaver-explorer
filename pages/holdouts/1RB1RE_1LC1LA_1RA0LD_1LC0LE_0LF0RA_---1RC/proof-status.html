What is known about 1RB1RE_1LC1LA_1RA0LD_1LC0LE_0LF0RA_---1RC

1RB1RE_1LC1LA_1RA0LD_1LC0LE_0LF0RA_---1RC

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 13 November 2026.

In short

The question is open, and it is now a question about a small system of events, proved in Lean. This machine is the table of 1RB0RD_1LC0RA_1LF1LD_0RE0LC_---1LB_1RB1RC (bbchallenge 74982) read in a mirror and started in another state. It is a counter ticked once per sweep by a carry automaton. When a carry runs through all the digits it reaches the left end of the tape, and there, for every counter, it either adds a digit, turns all the units at the right end into digits, or halts. The machine halts from blank tape exactly when this event system halts from a one-digit counter (kernel only). The eight overflows so far were extensions and conversions; the last, at step 506,587,790,058, turned 410,923 units into digits. The next one is of the order of 21.3·105 sweeps away, and its kind is not known. The two machines are separate halting questions.

No halt in the first 10,000 steps

The list simulator of the shared library, proved to agree with the machine's semantics, runs 10,000 steps from blank tape without a halt, evaluated by Lean's kernel.

blank_runs_kernel, lean/Blank.lean

A halt can only happen at the left end

A closed tape language from windows of 4 cells covers the run from blank tape; in it the halting transition F0 can only fire with blank tape to the left of the head. So the machine halts iff F reads a 0 with only blank tape to its left (it can only get there as E0 → 0LF).

halts_iff_edge, lean/Edge.lean, lean/EdgeCert.lean

The same table as 74982, in a mirror

Reading the table right to left and renaming the states (A, B, C, D, E, F here are C, F, B, A, D, E of 1RB0RD_1LC0RA_1LF1LD_0RE0LC_---1LB_1RB1RC) gives that machine's table. A step of one is a step of the other on the mirrored tape, so this machine halts from blank tape exactly when 74982 halts from blank tape started in state C. The table of this machine is restated in that Lean file.

is_mirror, mirror_step, halts_mirror, holdouts/1RB0RD_1LC0RA_1LF1LD_0RE0LC_---1LB_1RB1RC/lean/Twin132695.lean

Every overflow, for every counter

The counter is digits on every second cell with a 1 between neighbours and a last cell at the left end. When the carry runs through all the digits and reads the last cell d: in state a, d = 0 becomes 1 and d = 1 gives the counter one more digit; in state b on 0 or state c on 1 the machine halts; in state b on 1 or state c on 0 all the units become counter digits. After each of these the last cell is 1, so from then on the machine halts exactly when a carry reaches the left end in state c.

The machine is the event system

16 steps from blank tape the machine is at an arrival with one unit, the single digit 1 and last cell 1. It halts from blank tape if and only if the event system evstep halts from there.

heuristic Evidence only

Growth shape: fixed/sqrt

Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.495).

tools/py/bbtools/triage.py

A binary counter of odd runs

Between visits of the right end the head rewrites the odd runs next to the unit block: (1,3)→(5) every other visit, (3,3)→(7) every 4th, (3,1,5)→(7,3) every 8th, and so on, halving: a binary counter of the visits. Its width stays fixed between overflows (123 cells from step 104 to 5·1011). These rewrites are the carry automaton of 74982 seen on run lengths; the automaton itself is proved for every digit string.

The next overflow is out of reach

The next overflow needs a carry through 410,984 digits. On small counters the number of sweeps to the next overflow doubles about every 3 digits, which puts it at the order of 21.3·105 sweeps. The sequence of carry states leaving a prefix of the counter, kept as a straight-line program, stops compressing after about 150 digits (5,000 nodes at 100 digits, 7.3·106 at 200), so its kind was not computed.

holdouts/1RB0RD_1LC0RA_1LF1LD_0RE0LC_---1LB_1RB1RC/py/events.py program

The epoch after step 7,545

Between the overflows at steps 7,545 and 5·1011 the tape is a fixed prefix, a reservoir (1,3)^k of run pairs made by the overflow, an active counter region that eats into the reservoir (k = 14, 10, 5, 4, 4, 2, 1, 1, 0 at visits 56, 26..213) and then grows one long run (length 21..33 at visits 212..216), and the units. The numeral system of the active region is not decoded.

Does it halt from blank tape?

Not known. It halts if and only if, at some overflow, the carry reaches the left end in state c. The next overflow is the first chance.
