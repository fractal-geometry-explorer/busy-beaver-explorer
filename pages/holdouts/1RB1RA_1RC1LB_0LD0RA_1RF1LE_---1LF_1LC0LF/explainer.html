Does this machine ever halt?

1RB1RA_1RC1LB_0LD0RA_1RF1LE_---1LF_1LC0LF

Nobody knows. Started on a blank tape, this machine builds a list of blocks of 1s and runs a nested counter on it: the last block grows by two in each round, each round takes twice as long as the one before, and when the last block outgrows its neighbour an overflow rewrites the list one level up. This page runs the machine, explains the rounds, and lists what is known.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in E reading 0. E is entered only from D1 (writes 1, moves L): 0 D>1. So a halt is the moment this pattern appears, with the head on the cell after >.

The picture

A list of blocks

Whenever the head stands in state C on the first blank cell right of everything written, the tape is a row of blocks of 1s with a single 0 between neighbours. Write it as a list: [4, 17, 27, 9] is the tape 1^4 0 1^17 0 1^27 0 1^9 C>0. A round is the stretch of the run from one such moment to the next. The machine only ever works near the end of the list; everything that happens is a change of the last two or three numbers.

The rules

Odd rounds, even rounds, overflows

Odd round. If the last block n is odd and at most 2A+1, where A is the block in front, the round turns […, A, n] into […, A, n+2] and takes exactly 3·2(n+3)/2 − 6 steps. Inside the round the machine erases the last block, leaves a marker 11 at its far end, and fills the gap again by enumerating patterns of 11 pairs with odd gaps between them (the patterns of k pairs come in binomial numbers, together 2(n−1)/2: it is a binary counter written as positions). The counter borrows cells from the right end of A, as deep as (n−1)/2 cells, and puts them back. This law is now proved in Lean for every n (see “How a round works”).

Even round. If n is even and at most 2A+2, […, A, n] becomes […, A−1, n−1, 3] in 6·2n/2 − 2n − 2 steps. An overflow always leaves an even last block, so after it the list grows by one block and the odd rounds start again from 3.

Overflow. When n reaches 2A+3 the counter needs more cells than A has and borrows across the 0 into the block B in front of A. What comes out depends on B and on the block X in front of B, in the same way a round depends on its last two blocks: for B ≤ 2X+2 the blocks merge ([X−1, A+B+1, 2A+6] for even B, [X+A+2, 2A+B+5] for odd B), for larger B the overflow moves up one more level. If B = 1 the machine halts. These closed rules hold for short lists only; the general overflow is the recursion of the next section running out of cells, and is computed exactly rather than by a formula.

Example. [4, 17, 27, 57]: here B = 17 ≥ 2·4+5, odd, so the rule [X, A+2X+7, 2A+B−2X+3] gives [4, 42, 66], which is what the machine wrote after 3,221,226,692 steps of overflow.

Inside a round

How a round works: one recursive move

Write [q, k] C> w for the tape … 1^q 0 1^k C>0 w (the head on the 0 after the block k, the word w to its right) and u for the three cells 110. The whole round is one move applied recursively:

movebeforeaftersteps
sweep (k ≥ 5)[q+1, k] C> w[q, 3] C> 0^(k−5) u wk + 6
M j k[q, k] C> u^j 0 0 R[q+j, k+2j+2] C> R3·2(k+3)/2 − 6 + 2j² + (2k+5)j
Z a k[q, k] C> u^a 0 u 0 0 R[q+a, k+2a+2, 3] C> Rthat of M a k, plus 4

The sweep erases the block, leaves the marker 11 at its far end, and moves the separator in front one cell left: one cell is borrowed from q. For k ≥ 5, M j k is a sweep, then the odd rounds M 0 3, M 0 5, … (each eats two of the zeros), then M (j+1) (k−2) one level down, which swallows the marker and returns the borrowed cell. For k = 3 the units u are absorbed one at a time by a short zigzag. So a round of size n is a recursion of depth (n−3)/2 and needs q ≥ (n−1)/2 cells to borrow: that is exactly the condition n ≤ 2A+1 of the odd round, and the step count doubles with each level. The odd round is M 0 n; the even round is a sweep, a chain of odd rounds and Z 0 (n−3).

All of this is proved in Lean (lean/Counter.lean) by induction on k, for every q, j and every tape on both sides. An overflow is the same recursion when q is one cell short: at the bottom the sweep's separator runs into the separator of the block in front, and that block is then swept as if it were one level higher in the counter.

Halting

Why it is hard to settle

Each epoch of the run is an even round, a run of odd rounds, and an overflow that takes about as long as everything before it, so the step count roughly squares each time. Because the moves above are proved and have exact step counts, a program can apply them instead of stepping, and follow the run exactly: through [17, 97, 138] at 1.8·1021 steps, [5, 53, 363, 682] at 4.7·1085, [5, 14, 40, 225, 1525, 8815, 12596] at 8.9·101803, and past 104300 steps, with no halt.

The machine halts only when C reaches the 0 right of a block of length 1. Every overflow rewrites blocks near the front of the list (it starts with 4, 17, 17, 5, 20, 5, 20, 5, 5 in successive epochs), so whether that can ever happen depends on how the deepest levels of this counter behave forever. Nobody knows yet; the list keeps getting longer and its blocks larger, but the front blocks stay small.

The round laws for every size, by induction

Odd round: L 1^A 0 1^n C>0 → L 1^A 0 1^(n+2) C>0 in 3·2(n+3)/2 − 6 steps for every odd n ≥ 3 and A ≥ (n−1)/2. Even round: L 1^A 0 1^n C>0 → L 1^(A−1) 0 1^(n−1) 0 1^3 C>0 in 6·2n/2 − 2n − 2 steps for every even n ≥ 4 and A ≥ (n−2)/2. Both follow from two general moves of the inner counter, M j k: [q,k] C> (110)^j 00 R → [q+j, k+2j+2] C> R and Z a k: [q,k] C> (110)^a 0 110 00 R → [q+a, k+2a+2, 3] C> R, proved by induction on k for all j, q ≥ (k−1)/2 and all tapes L, R (a sweep, a chain of odd rounds, and the move with one more unit).

Overflow rules for small blocks

With blank tape left of X, the overflow [X, B, A, 2A+3] becomes: halt if B = 1; [X+A+1, 2A+8] if B = 2; [X+A+2, 2A+B+5] for odd B ≤ 2X+1; [X+A+3, 2A+B+6] for B = 2X+3; [X, A+2X+7, 2A+B−2X+3] for odd B ≥ 2X+5; [X−1, A+B+1, 2A+6] for even 4 ≤ B ≤ 2X+2; [X, A+B+2, 2A+6] for B = 2X+4; [X, 2X+4, A+B−2X−1, 2A+6] for even B ≥ 2X+6. Checked for 3 ≤ X ≤ 8, B ≤ 24, 2 ≤ A ≤ 9 (1,152 cases). The large overflow of the run, [4,17,27,57]→[4,42,66], is the case odd B ≥ 2X+5. With more blocks left of X the cases B ≥ 2X+3 change: the overflow climbs one more level. These are instances of the recursion (the moves M and Z with too little to borrow); the run's own overflows follow other cases, computed exactly below.

Open
Does it halt from blank tape?

Not known. It halts exactly when C reads the 0 right of a block of length 1. Each epoch (even round, odd rounds, overflow) roughly squares the step count; the overflow cascades rewrite the front of the list in a pattern not yet understood, so no proof and no convincing heuristic in either direction.
