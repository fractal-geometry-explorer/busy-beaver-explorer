What is known about 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_1LB---

1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_1LB---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 13 November 2026.

In short

The question is open. The machine is a base-5 counter written as walls in a sea of 1000 blocks (described below; its one-sweep and carry rules are proved in Lean). It can halt only during a rare event, the merger of two walls; every merger type tried symbolically (both walls in any of their six shapes, 0 to 2 blocks apart) ends without halting, and the C simulator finds no halt in the first 1010 steps. A proof would have to cover every merger and edge event; that has not been done.

Family F05. One of 40 holdouts on the same five-state core; the family's exact block-list map runs this machine for 3.4·10200 steps without a halt.

The family's visit rule and its closed form

In frame A a visit starts with the head in state A on the 0 in front of plain blocks (10)^b1 1 (10)^b2 1 … 1 and ends when the head first steps left of that cell. go_spec proves for every depth that a clean visit turns the list l into go n l in exactly goT n l steps (the first block is spread, the rest gets five visits, the first block is folded back 5 shorter); go_closed gives the closed form (b1−5, b2−18, b3−90, …, bk+12·5k−2) when b1 is odd and at least 7, the other blocks even and block i at least 2+18·5i−2. visit states it as a run of this machine. Also proved: the birth of a block, and that the entry into F after a visit that ends in state C on a phase-1 tail reads a 0 (fevent, fevent_reads_zero). The proofs are generated for this machine's own frame-A table; they never use F0.

go_spec, go_closed, visit_closed, visit, birth, fevent_reads_zero, lean/Family.lean (written by holdouts/1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---/py/gen_family_lean.py)

What a clean visit conserves

For the blocks after the first, the last one left out: a clean visit (a list the closed form applies to) changes neither the residue of block i modulo 18·5i−2 nor the drift bi+1 − 5·bi of two neighbours. So these numbers change only at the exceptional events (a block running out, a birth, an entry into F, the left end). This is a law between events, not a proof that the machine never halts.

tailEff_res, tailEff_drift, visit_conserves, lean/Family.lean

The sweep and carry rules

With the head in state D on the first 1 at the left end, 0^∞ D> (1000)^(x+1) W (1000)^(y+1) R, one sweep moves the first wall W one step along its cycle 1001 → 1001100 → 100110 → 10011 → 10010 → 1001, for every x, y and every tape R (four theorems, one per shape that does not carry). From 10011 the sweep carries: it also moves the second wall one step (four theorems, one per shape of the second wall that does not carry on). The step counts are linear in x.

No halt in the first 3.4·10200 steps (exact block-list map)

The machine run as a map on block lists (clean visits by the closed form, a Lean theorem; every other visit by the exact run-length simulator, memoised) reaches step 3.4·10200 without a halt: 592 returns to the left end, 287 entries into F, all reading 0, all with the tape of the proved harmless kind around the head (010001000100[F]001010101010 (192×); 010001000100[F]001010110101 (95×)). The list has 143 blocks at the last left-end event. Its F-events (step and cell read) agree with the plain cell-by-cell simulation of the machine on the first 3·109 steps (6 F-events).

Where F comes in

State F is reached only through E reading a 1, which an ordinary sweep never does: in 1010 steps it happened 6 times, never in an ordinary sweep or carry (their Lean proofs never pass through F) but in the rare events, and each time F read a 0 (F0 → 1LB).

The mergers tried end without a halt

A symbolic run (head, literal cells and repeated blocks with variable counts, any tape R beyond) from 0^∞ D> (1000)^(x+3) W₁ (1000)^g W₂ (1000)^(y+6) W₃ (1000)^(z+4) R, for each of the 36 pairs of shapes W₁, W₂ and each gap g = 0, 1, 2: 104 of the 108 cases return to the ordinary form without a halt; 4 stopped unresolved (NeedSplit), and none halts. It is evidence, not a proof: mergers deeper in the tape have another wall near on the left, and the edge events (a wall reaching the right end, the overflow) are not covered.

The n-gram closed position set decider of the Coq-BB5 paper finds a (spurious) path to the halt for windows of 3 to 7 cells with or without history, and for the lead machine of the family up to 40 cells: windows cannot tell how the walls are spaced.

heuristic Evidence only

Halting would need two exceptional events close together

A clean visit cannot halt, and in the runs every exceptional event with long blocks around it ends without a halt; short lists of the same shape do halt. When block i runs out, the next block has about the length of their drift, so a second event close by needs a drift near 0 at that moment. Observed at the left-end events of this run: after step 1020 the smallest drift in absolute value is 2,606, after step 10100 it is 10,405,806. New drifts are made of sums and differences of earlier blocks, which grow with the run, so close pairs of events should become ever rarer; but nothing proved keeps a drift away from 0, and the figures are sampled at the left-end events only.

Does it halt from blank tape?

Not known. It would halt only if some merger of walls (or edge event) put E on a 1 followed by a 1. The mergers tried never do, which suggests it never halts; a proof needs a closed description of every configuration between samples (a regular language over walls and gaps), which is the next thing to try.
