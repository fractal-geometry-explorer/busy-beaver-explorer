Does this machine ever halt?

1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_1LB---

Nobody knows, but the machine has a clear structure: it is a base-5 counter. The tape is long runs of the block 1000 broken by short walls; each wall is one digit, and its shape is the digit's value. A head bouncing between the left end and the first wall counts the sweeps.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from E1 (writes 0, moves R): E>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The family

One core, forty machines

This machine is one of 40 holdouts built on the same five states. Written in one common frame (frame A), every one of them has the table

stateABCDEF
reads 01RB0RC1LD0LE1LAF0
reads 10LC0RB0RE0LF or 1LF0LBhalt

and they differ in three things only: the bit that D writes on its way into F (D1), what F does on a 0 (F0), and the state the run starts in. This machine is the mirror image (left and right exchanged) of the core with D1 = 0LF and F0 = 1RA, that is of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_1RA---, with the states renamed A→B, B→C, C→D, D→E, E→A, F→F (frame G); its start state A is the core's state E. So its run from blank tape is, step for step and mirrored, the run of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_1RA--- started in state E on blank tape, and the block lists below read right to left on this machine's own tape. Lean proves this for the machine's own table (halts_iff in lean/Family.lean): it halts from blank tape exactly if the frame-A table halts from blank tape in state E.

What the 40 machines share. States A to E never enter F while they run the nested counter, so between two entries into F all 40 machines do the same thing, and one law covers them. In frame A the tape is a list of blocks (10)^b; a visit to the list [b1, …, bk] makes five visits to the list without its first block. When the blocks are large and of the right parity (a clean visit) this has a closed form: b1 loses 5, block i loses 18·5i−2, the last block gains 12·5k−2. Both the recursion and the closed form are Lean theorems for every depth, on each of the 40 tables (go_spec, go_closed). Two quantities are therefore conserved by every clean visit (visit_conserves): the residue of block i modulo 18·5i−2, and the drift bi+1 − 5·bi of two neighbouring blocks (neither the first nor the last). The residue fixes at which phase and with which small value a block will run out; the drift is the length the next block still has at that moment.

This machine's run, seen from the left end. Each time the head comes back to the left end of the tape (frame A) the tape is a plain list of blocks. Move the slider through these moments: the middle blocks drain at their fixed rates, the last block grows, a block that runs out disappears and its neighbours merge, and new blocks are born at the right end. How far it has been run. The exact block-list map (clean visits by the proved closed form, every other visit by an exact run-length simulation) runs this machine for 3.4·10200 steps without a halt: 592 returns to the left end, 287 entries into F, every one reading 0, with the tape around the head 010001000100[F]001010101010 (192×, F reads 0); 010001000100[F]001010110101 (95×, F reads 0). Every one of these entries is the kind proved harmless in Lean (fevent, fevent_reads_zero): a visit ends in state C on the 0 of a phase-1 tail, and F then reads the last cell of a 1000.

Why this does not settle halting. A clean visit cannot halt, and an isolated exceptional event (one block running out between long neighbours, a birth, the harmless F-event) does not halt in any run so far. Short block lists of the same shape do halt, so a proof has to control the block lengths: it would have to show that two exceptional events never fall close together, that is, that a drift is never small when its block runs out. The drifts only change at exceptional events, where they are sums and differences of large earlier blocks; nothing is known that keeps them away from 0. Observed in this run, at the left-end events: after step 1020 the smallest drift in absolute value is 2,606, after step 10100 it is 10,405,806. That is evidence, not a proof, and it is sampled at the left-end events only.

Macro structure

Blocks and walls

Stop the machine each time its head is back at the left end of the tape, in state D on a 1. The tape always reads the same way: runs of the four-cell block 1000, separated by short walls. Written c for the block and the walls by their cells, here is the tape of 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_1LB--- at step 9,999,852,852:

c^30987 10011 c^19877 10010 c^1496 10010 c^1342 1001 c^2100 10010 c^2778 1001 c^815 100110 c^521 1001

A wall is always one of five words, 1001, 1001100, 100110, 10011, 10010, or a single 0 (a digit that has not started counting yet, see below), and the tape ends on the right with 1001. In the middle of a merger, described below, a wall can briefly be a longer word.

Macro structure

One sweep moves one digit

From the left end the head runs right over the first run of blocks, turning each 1000 into 0101 in four steps, and stops at the first wall. It changes the wall's shape and walks back, zigzagging six steps per block and turning 0101 back into 1000. The run in front grows by one block, so the sweeps get longer and the left side of the tape grows like the square root of the time: that is the bouncer half of the growth shape.

The wall's shape goes round a cycle of five: 1001 → 1001100 → 100110 → 10011 → 10010 → 1001. The step from 10011 to 10010 is the carry: on that sweep the head does not turn at the first wall but goes on to the second and moves it one step too (and if that one is also at 10011, on to the third). So the walls are the digits of the number of sweeps written in base 5, the first wall the lowest digit. Lean proves these rules for runs of any length (lean/Walls.lean).

When every wall is at 10011 the carry runs through all of them to the right end: the tape grows there by three cells, every wall becomes a single 0, and a new lowest digit is born at the left end. A 0 wall becomes 1001 the first time a carry reaches it, and stops the carry. So the counter gains a digit at each overflow, the overflows come about five times further apart each time, and the right end of the tape grows like a logarithm of the time. In 1010 steps there were 18 overflows.

Emergent behavior

Drifting walls and mergers

A plain counter would be easy to prove non-halting. This one is not plain, because the walls move. Each time a wall goes round its cycle it shifts two blocks to the right, so a low digit drifts right faster than the digit after it and the run between them shrinks. When it is used up the two walls merge: for a few sweeps the wall is a longer word, then one ordinary wall is left and a new lowest digit is born at the left end. In 1010 steps walls merged 18 times.

When a merger happens, and with which shapes, depends on the whole history of the counter: it is the kind of arithmetic that makes these machines hard. State F is reached only through E reading a 1, which an ordinary sweep never does: in 1010 steps it happened 6 times, never in an ordinary sweep or carry (their Lean proofs never pass through F) but in the rare events, and each time F read a 0 (F0 → 1LB).

The variants of this family share states A to D and differ only in E and F, that is, only in what a merger does: 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0LE1RF_0RA---, 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_0LB---, 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_0RD---, 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA1RF_0RE---. Every merger tried by symbolic simulation (36 pairs of shapes, gaps of 0 to 2 blocks) ends in the ordinary form without a halt, which points to a machine that never halts. Turning that into a proof means describing every configuration, mergers and edge events included, by a finite set of patterns that the machine maps into itself.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.499). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.071).

After 109 steps the tape spans 97,920 cells (73,778 left of the start, 64 right), with a density of 1s of 0.366.

go_spec, go_closed, visit_closed, visit, birth, fevent_reads_zero, lean/Family.lean (written by holdouts/1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---/py/gen_family_lean.py)
The family's visit rule and its closed form

In frame A a visit starts with the head in state A on the 0 in front of plain blocks (10)^b1 1 (10)^b2 1 … 1 and ends when the head first steps left of that cell. go_spec proves for every depth that a clean visit turns the list l into go n l in exactly goT n l steps (the first block is spread, the rest gets five visits, the first block is folded back 5 shorter); go_closed gives the closed form (b1−5, b2−18, b3−90, …, bk+12·5k−2) when b1 is odd and at least 7, the other blocks even and block i at least 2+18·5i−2. visit states it as a run of this machine. Also proved: the birth of a block, and that the entry into F after a visit that ends in state C on a phase-1 tail reads a 0 (fevent, fevent_reads_zero). The proofs are generated for this machine's own frame-A table; they never use F0.

Kernel
tailEff_res, tailEff_drift, visit_conserves, lean/Family.lean
What a clean visit conserves

For the blocks after the first, the last one left out: a clean visit (a list the closed form applies to) changes neither the residue of block i modulo 18·5i−2 nor the drift bi+1 − 5·bi of two neighbours. So these numbers change only at the exceptional events (a block running out, a birth, an entry into F, the left end). This is a law between events, not a proof that the machine never halts.

Heuristic
data/f05_run.json (drift), holdouts/1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---/py/f05_run.py
Halting would need two exceptional events close together

A clean visit cannot halt, and in the runs every exceptional event with long blocks around it ends without a halt; short lists of the same shape do halt. When block i runs out, the next block has about the length of their drift, so a second event close by needs a drift near 0 at that moment. Observed at the left-end events of this run: after step 1020 the smallest drift in absolute value is 2,606, after step 10100 it is 10,405,806. New drifts are made of sums and differences of earlier blocks, which grow with the run, so close pairs of events should become ever rarer; but nothing proved keeps a drift away from 0, and the figures are sampled at the left-end events only.

Does it halt from blank tape?

Not known. It would halt only if some merger of walls (or edge event) put E on a 1 followed by a 1. The mergers tried never do, which suggests it never halts; a proof needs a closed description of every configuration between samples (a regular language over walls and gaps), which is the next thing to try.
