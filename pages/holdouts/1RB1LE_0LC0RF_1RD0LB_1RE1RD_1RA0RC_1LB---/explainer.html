Does this machine ever halt?

1RB1LE_0LC0RF_1RD0LB_1RE1RD_1RA0RC_1LB---

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows, but the rewriting is now understood. The tape is a list of numbers written in unary, each a block of 4k+3 ones; every round trip of the head replaces the list, written in two 4-cell letters, by its running XOR. This page shows the encoding, the proved rules, and what a halt would need.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from B1 (writes 0, moves R): B>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The structure

A list of unary numbers, rewritten every round trip

The head runs from end to end; a visit adds 1 to 4 cells at the left end and 3 to 8 at the right. Just after a rightward sweep the tape is a list of blocks of ones separated by single 0s, and almost every block has a length 4k+3: the tape is a list of numbers k1, k2, ... in unary. The leftward sweep rewrites each block: state B turns each pair 11 into 10, and the left end of a block 0111 into 00010, so a block of 4k+3 ones becomes 2k+1 single 1s, 000 1 0 1 0 ... 1 0, and the blocks are separated by 000. The rightward sweep zigzags: at every block it backs up a few cells, and over the inside of a block it turns 001, 010, 100 into 110, 101, 011 (states C, D, E), rebuilding blocks of 4k+3 ones, but not the same ones.

How the list changes from one round trip to the next is decoded in the next section: in 4-cell letters, a round trip replaces the word by its running XOR. Seen at the right end, the first numbers repeat a short cycle (1 0 0 3 1 0 0 ... comes back every few round trips) while the rest looks random; both are what a running XOR anchored at the left end does.

The rewrite decoded

A round trip is a running XOR

Cut the tape into letters of 4 cells, counted from the left end. Just after a rightward sweep every letter is one of two: s = 0111 (a block of ones starts here) or c = 1111 (the block goes on). A block of 4k+3 ones, with the 0 in front of it, is the word s ck, so the list of numbers is a word of s and c letters. In these letters a round trip has a short exact description, proved in Lean for every word:

  • Leftward sweep. Each block s ck becomes the group 1 (01)2k 000 of 2k+1 single 1s, shifted one cell to the right (block_B, left_sweep).
  • Rightward sweep. The head reads the groups in state E and A in turn, E, A, E, A, ..., with no exception. A group read in E is written back as sk+1. A group read in A is written back as ck+1, and the head also turns the s just behind it into c (group_E, group_A, right_sweep).

Put together, the letter the rightward sweep writes at each place is the parity of the number of block starts it has read so far: the new word is the running XOR of the old one (outL_eq_pxor). Read the other way, each letter before a round trip is the XOR of the same letter after the round trip and its left neighbour. Backwards in time the list evolves by the XOR cellular automaton (elementary rule 102, the rule that draws Pascal's triangle mod 2), and forwards by its inverse. In the list of numbers: the numbers are read in pairs (a, b), and each pair becomes a zeros followed by the number b + 1.

120 consecutive round trips of the real run, steps 9.3·106 to 1.2·107, one row per round trip, time downwards, one pixel per letter, the left end of the tape on the left. Letters: dark is s, light is c, grey is the layer at the right end that is not yet in letters. Check: each letter of a row is recomputed from the row below it as the XOR of the letter below and its left neighbour; green where that gives the letter of the run, red where it does not.



The rule on the list: pairs (a, b) become a zeros and then b + 1. Away from the two ends of the tape this is exactly what the machine does to its list of blocks. The default list is a stretch of the real tape after about a million steps; one round trip of the run turned it into 0 1 0 0 0 2 0 0 3 0 0 0 0 0 0 2 0 1, as the rule says.




What follows from it:


    

  • Information only moves right. A letter after a round trip depends only on the letters at its left. Nothing at the right end can change the bulk of the list.
    • 

  • The left end. The tape grows by exactly one cell at the left end each round trip and the letter grid moves with it, so the left end is a fixed boundary for the rule. The running XOR repeats itself on the first 2j letters after 2j+1 round trips: this is the short cycle of the first numbers of the list.
    • 

  • The right end. A layer of the last few groups (13 cells on average, at most about 100 in the first 109 steps) is not yet in letter form; there the rightward sweep sometimes turns back early, and new letters join the word. This layer is not decoded.
    • 

  • Where a halt could come from. The sweep rules above take a fixed number of steps for every word, so no halt happens in the bulk: a halt (B on two adjacent 1s) can only come from the two ends of the tape, and the left end has been periodic in every run so far. The halting question is now a question about the layer at the right end, fed by the running XOR arriving from the left.
    • 



Checked on the run (py/ca_check.py): every letter that two consecutive round trips have in common, up to the right-end layer, obeys the rule, for this machine and the five other machines with the same tapes, to 2·108 steps each (for this machine 4,159 round trips and 8,492,322 letters, no exception).

  Halting
  
What a halt would need


F1 is the only halting transition, and F is entered only from B on a 1 (writing 0, moving right). So the machine halts exactly when B reads a 1 followed by another 1. In the first 109 steps F is entered 117,032,159 times; the cell after was 0 every time. No halt in 1010 steps.
Twin of 1RB1RA_1RC0RE_1RD1LB_0LE0RF_1RA0LD_1LD--- (1RB1RA_1RC0RE_1RD1LB_0LE0RF_1RA0LD_1LD---): renaming the states A, B, C, D, E, F here to C, D, E, A, B, F gives that machine's table, so this one is it started in its state C (without the two 1s that machine writes first). The runs differ cell by cell but have the same structure.

Where a halt can come from
If the machine halts on its third step from a configuration, that configuration is one of: A with 0 under the head, 1 right, 1 two right; F with 1 left, 0 under the head. So a run can reach a halt only through one of these patterns, and a proof that the machine never halts only has to rule them out. The proof splits on the state and the five cells around the head.

Kernel
lean/Sweep.lean (generated by py/ca.py) and lean/Bulk.lean
The round trip is a running XOR
In 4-cell letters s = 0111, c = 1111: the leftward sweep turns every block s ck into the group 1 (01)2k 000 (block_B, left_sweep, for any list of blocks); the rightward sweep reads the groups in E and A in turn and writes sk+1 for a group read in E, ck+1 for a group read in A, turning the s behind it into c (group_E, group_A, right_sweep, for any list of pairs of groups); and what the rightward sweep writes is the running XOR of the letter word it read (outL_eq_pxor, with its inverse, the XOR of neighbours, in xdiff_pxor). The two ends of the tape are not covered.

Regular-language deciders tried (F11)
None of these closes: each reaches a halting configuration in its abstraction, which says nothing about whether the machine halts. n-gram CPS (tools/c/ngramcps.c), equal widths on both sides: a halting local configuration is reached with plain up to width 24, history 1 up to width 24, history 2 up to width 24, history 3 up to width 24, LRU history up to width 7 (larger widths ran out of the 150 s or 60 million configuration budget). n-gram CPS with every cell tagged by its position mod p: fails for p = 2 up to width 20, p = 3 up to width 20, p = 4 up to width 20, p = 6 up to width 20. n-gram CPS where each side also carries the state of a small automaton that has read that side from the far end (every automaton with up to 3 states on both sides, or 4 states on one side), with position mod 1..4 and widths 4, 6, 8: no closed set without a halt in all 120 parameter sets. Run-length windows (the K nearest runs of equal macro cells on each side, run lengths kept exactly below T and mod M above): fails for all 72 parameter sets (cells of 1 to 4 bits, K = 2, 4, 6, T = 2, 4, M = 1, 2, 4). Two-automaton closed tape language by SAT (a deterministic automaton reading each side inward, n states each, CaDiCaL): no solution for n = 2..8; n = 9 not finished in 150 s.

    
Open
Does it halt from blank tape?
Not known. The list of numbers is rewritten each round trip by a sequential process with a finite carry (the zigzag of the rightward sweep), but how the list evolves is not understood; a proof would need an invariant of the list (a closed language of lists) that keeps B away from two adjacent 1s.
