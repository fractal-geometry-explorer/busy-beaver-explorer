OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 13 November 2026.

In short

The question is open. This machine is in frame B: its table is the mirror image (L and R exchanged) of the frame-A table 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_1LB--- with the states renamed A→D, B→E, C→A, D→B, E→C, F→F, and it starts where that machine would be in state C. So its run from blank tape is, step for step and mirrored, the run of 1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_1LB--- started in C (checked from the two tables by frames.py and by simulation). The F-transition of the analysis is this machine's B1, the halting state is F. The nested counter that drives the run is proved in Lean for every depth (go_spec), with its closed form, the birth of blocks and the F-event; the remaining exceptions (merges, the left end) are simulated exactly. No halt in 1.4·10100 steps: every F-event so far is of the proved harmless kind.

Family F05. One of 40 holdouts on the same five-state core; the family's exact block-list map runs this machine for 5.4·10200 steps without a halt.

What a clean visit conserves

For the blocks after the first, the last one left out: a clean visit (a list the closed form applies to) changes neither the residue of block i modulo 18·5i−2 nor the drift bi+1 − 5·bi of two neighbours. So these numbers change only at the exceptional events (a block running out, a birth, an entry into F, the left end). This is a law between events, not a proof that the machine never halts.

tailEff_res, tailEff_drift, visit_conserves, lean/Family.lean

The visit rule for every depth

A visit starts with the head in state A on the 0 in front of plain blocks (10)^b1 1 (10)^b2 1 … 1 and ends when it first steps left of that cell; it never reads the tape on its left. go_spec proves, by induction on the depth n and for every left context, that a clean visit (a decidable condition: every block it spreads is odd and ≥ 7, every second block nonempty) turns the list l into go n l in exactly goT n l steps, where go is the recursion: spread b1, five visits to [b2+1, b3, …] with the tail bumps +3, +1, +1, +1 between them, then b1−5. It is built from seven rules (PUSH, TURN, TAIL1–4, POP) proved by bbtools.symtm for all counts.

go_spec, push … pop, lean/Family.lean

Its closed form

go_closed: if b1 is odd and ≥ 7 and the later blocks are even, the last ≥ 2 and block i (i = 2..k−1) ≥ 2 + 18·5i−2, then the visit is clean and gives (b1−5, b2−18, b3−90, …, bk−1−18·5k−3, bk+12·5k−2) (a single odd block gains 1); visit_closed states it on the tape. With the tail bump after the visit this is the measured round rule (−4, −18, …, +12·5m−2) for every m.

go_closed, visit_closed, lean/Family.lean; closed step count in holdouts/1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---/py/cf.py (trusted)

Rounds, births and the F-event

round1–round4: a clean visit followed by one phase of the tail on its left. birth: a visit to a single even block [2k+4] gives [2k+2, 8] in 10k+188 steps (where new blocks come from). fevent and fevent_reads_zero: the only way into F seen in the runs (a C exit onto the 0 of a phase-1 tail, then C0, D1) makes F read the last cell of a 1000 or of 100, which is 0 for every q and every tape around.

heuristic Evidence only

Halting would need two exceptional events close together

A clean visit cannot halt, and in the runs every exceptional event with long blocks around it ends without a halt; short lists of the same shape do halt. When block i runs out, the next block has about the length of their drift, so a second event close by needs a drift near 0 at that moment. Observed at the left-end events of this run: after step 1020 the smallest drift in absolute value is 1,596,384, after step 10100 it is 1,596,384. New drifts are made of sums and differences of earlier blocks, which grow with the run, so close pairs of events should become ever rarer; but nothing proved keeps a drift away from 0, and the figures are sampled at the left-end events only.

data/f05_run.json (drift), holdouts/1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---/py/f05_run.py

Where a halt would have to come from

F is entered only by D1 (D reads a 1 during the left sweep, where a spread block is turned back), and halts only when it then reads a 1. In this run every F-event has the same clean context (010001000100[F]0010101 (8×)). Random block lists do reach a halting F-event (about 1 in 150 F-entries; e.g. [15, 31, 17, 59, 31] halts after 63,153 steps), so the halt is reachable in principle; whether the blank-tape run ever produces such a list is the open part. F-events get rarer as the blocks grow (the top-level round time grows about fivefold per block).

holdouts/1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---/py/random_lists.py

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.499). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.057).

Does it halt from blank tape?

Not known. The visit rule is proved for every depth, its closed form, births and the F-event too; what is missing is a proof that the unclean visits of the blank-tape run (merges, small first blocks, the left end) always end in a C exit of the proved kind and never in an F exit onto a 1, that is an invariant on the block lists reached from blank tape.
