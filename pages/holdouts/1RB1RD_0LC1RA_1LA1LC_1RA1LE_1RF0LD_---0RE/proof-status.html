What is known about 1RB1RD_0LC1RA_1LA1LC_1RA1LE_1RF0LD_---0RE

1RB1RD_0LC1RA_1LA1LC_1RA1LE_1RF0LD_---0RE

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. Its tape is always an alternating block (10)^x next to a solid block 1^y, and the machine moves cells between them by doubling, like its near-twin 1RB1RD_0LC1RA_0RA1LC_1RA1LE_1RF0LD_---0RE. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. Lean proves no halt in the first 10,000 steps by the kernel alone and in the first 107 with native_decide; an exact macro simulator finds no halt in the first 1015 steps. Lean proves both phase rules (below) for all sizes.

What Lean proves. The whole phase map, every case for all sizes (E(x, z) = E>0 (10)^x 1^z, A(x, y) = (10)^x 1^y A>0 and the bounce frame Q(m, j, t) = (10)^m 1 D>0 0 (1010)^j 1^t), and halts_iff: the machine halts from blank tape if and only if the map, iterated from A(0, 0) (the blank tape), reaches E(x, 0) or E(x, 1). By native_decide the first 108 phases (about 4.1·1021 machine steps) do not. Lean also proves that the even phases lead only to even phases or to an all-ones tape, and checks, for every all-ones tape of length n < 105, that its run halts before the next even phase or all-ones tape exactly when n is 3 or 28·2k − 2k − 13 (15, 41, 95, 205, …). What is not proved: that this list holds for every n, and that the run never lands on it.

Where a halt would come from. F0 halts, and F is entered only from E0: the machine halts only when E stands at the left end with at most one 1 after the alternating block. Probing every two-block tape with x, y < 150, a parity rule keeps that from happening except right after the tape has become all ones; from 1^n A>0 it halts exactly for n = 3, 15, 29, 41, 95, 205 (n ≤ 400), the list n = 28·2k − 2k − 13 plus 3 and 29.

Why it has not halted. All-ones moments are rare: in the first 109 steps the tape was 1^n A>0 at n = 4, 10, 58, 81, 278 and 634, and between 109 and 1015 steps only at n = 5881, 9702, 12113, 28074, 29561 and 405562. None is in the list. The machine very probably never halts, but nothing here proves it.

Other proofs and outside reports

Community label

In the community's BB(6) tracker the machine's class is Cubic Mess. Its 3 November 2026 edition lists the machine as a cryptid: its halting is thought to come down to a Collatz-like question that no known method decides. These are labels read off the run by others, not results.

No halt in the first 10,000 steps

The list simulator of the shared library, proved to agree with the machine's semantics, runs 10,000 steps from blank tape without a halt, evaluated by Lean's kernel.

blank_runs_kernel, lean/Blank.lean

The two phase rules, for all sizes

Lean proves, with rfl steps, the crossing lemmas and induction on the number of bounces, that E(x,z) reaches E(2x+4, z−2x−6) whenever x ≥ 1 and z ≥ 2x + 7 (ephase), and A(x,y) reaches A(x−y/2−2, 2y+6) whenever y ≥ 4 is even and 2x ≥ y + 4 (aphase). Each phase is a start piece, one bounce (10)^(m+1) 1 D>0 0 (1010)^j 1^(r+3) to (10)^m 1 D>0 0 (1010)^(j+1) 1^(r+1) per copy of 10, and an end piece, generated by py/gen_rules.py; the proof is the one of 1RB1RD_0LC1RA_0RA1LC_1RA1LE_1RF0LD_---0RE, with a different start piece for the A phase. The parity analysis that uses these rules is not proved.

lean/Rules.lean, lean/EPhase.lean

The whole phase map

Write E(x, z) = E>0 (10)^x 1^z, A(x, y) = (10)^x 1^y A>0 and the bounce frame Q(m, j, t) = (10)^m 1 D>0 0 (1010)^j 1^t. next sends each of them to the next one the machine reaches (bounces taken all at once), with 25 cases; next_sound proves every case for all parameters (one symbolic run of lean/Pieces.lean each, generated by py/pieces.py, and induction for the bounces). next fails only at E(x, 0) and E(x, 1), which halt (e_halts).

lean/Phases.lean, lean/Pieces.lean

Halts if and only if the map reaches E(x, 0) or E(x, 1)

halts_iff: the machine halts from blank tape if and only if some iterate of next from A(0, 0) (the blank tape) is E(x, z) with z ≤ 1.

lean/Phases.lean

The parity classes

even_next: the even phases (E(x, z) with z even and z ≥ 2, A(x, y) with x ≥ 1 and y even, Q(m, j, t) with t even) lead only to even phases or to an all-ones tape. So from an even phase the machine cannot halt before the tape is next all ones (even_safe).

The two phase rules, along the run

Write E(x,z) for E>0 (10)^x 1^z and A(x,y) for (10)^x 1^y A>0 (blank around). In the first 109 steps every left phase with z ≥ 2x+8 went E(x,z) → E(2x+4, z−2x−6) (469 times) and every right phase with y even and 2x ≥ y+8 went A(x,y) → A(x−y/2−2, 2y+6) (495 times).

py/phasemap.py

heuristic Evidence only

Growth shape: power/power

Left of the start, the visited part of the tape grows like a power of the step count other than 1/2 (fitted exponent 0.333). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.343).

tools/py/bbtools/triage.py

Step counts of the phases

From probes: the left phase takes 4x²+24x+30 steps (the same as in its twin, whose states D, E, F, B it shares) and the right phase y²+6y+12. Doubling costs the square of the block, so the width grows like t1/3.

py/phases.py

Halting needs an all-ones tape from a sparse list

From every two-block tape with x, y, z < 150 the next one was computed. E(x,z) with z even ≥ 2 and A(x,y) with x ≥ 1, y even lead only to tapes of the same kind or to an all-ones tape 1^n A>0, never to a halt; the machine halts only from E(x,0) and E(x,1). From 1^n A>0 the next tape is E(3, n−2), the alternating block then goes 3, 10, 24, 52, … (x ↦ 2x+4), and the run halts exactly when the ones run out leaving one: n = 15, 41, 95, 205, … = 28·2k − 2k − 13, plus 3 and 29 (all n ≤ 400 checked directly). Not proved for all sizes.
