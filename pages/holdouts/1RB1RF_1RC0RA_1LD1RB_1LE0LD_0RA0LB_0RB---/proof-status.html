OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 12 November 2026.

In short

The question is open. Lean (kernel) proves the halting configurations, no halt in the first 10,000 steps (107 with native_decide) and three shift rules. Direct C runs find no halt in 2·1010 steps and show the word-and-counter structure described below; the map of the left-end rebuilds, which is where a halt could happen, is not known.

Round 6, the proved neighbours. busycoq (pull request 36) proves the machines that differ from this one only in the entry E0. That entry is used from the first steps of this run and again and again (24 times in the first 1010 steps (10 in the first 103, 18 in 104, 20 in 105, 22 in 106, 23 in 107, 24 in 109)), and each use leaves a different left end than in the neighbours, so their proof does not carry over. No transfer; the question stays open.

Shift rules of the sweeps

W 0 1^3 0 1^(2k+1) B>0 0 → W 0 1 0 1 0 1 1 C> 0^(2k) 1 (head on the first of the 2k 0s) in 2k+11 steps (the last block erased after a record); B> (10)^k → (01)^k B> and B> (01)^k → (11)^k B> in 2k steps.

rec_erase, b_sweep10, b_sweep01, lean/Rules.lean

What the entry E0 does, and the two halting patterns

The entry fires when D, erasing 1s leftwards, reads a 0 with another 0 on its left: four steps later (D0, E0, A1, F0) the cells read 0 1 0 and B is on the next cell to the right. The machine halts from exactly two local patterns, each proved in Lean to halt whatever else is on the tape: C reading a 0 with two 0s on its left (0 0 C>0) and B reading 1 1 1. That there is no other way to halt is read backwards from the table (an argument on paper, not in Lean).

e0_event, halt_c, halt_b, lean/Halt.lean

heuristic Evidence only

Growth shape: exp/fixed

Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.016).

tools/py/bbtools/triage.py

Records are words; time doubles

At every record of the first 2·1010 steps outside the left-end rebuilds the tape is a word ending in 1^n B>0, n grows by 2 per record (to 57), the rest changes by one local rewrite, and the time between records tends to double.

records of the direct run

Halting only at the left end

A reads a 1 (the only way to F) only while the left end of the word is rebuilt, after the moving rewrite has reached it (some of these rebuilds are restarts of the last block).

Does it halt from blank tape?

Not known. The record-to-record map and the map of the left-end rebuilds have not been derived, so there is no accelerated simulation beyond direct runs.
