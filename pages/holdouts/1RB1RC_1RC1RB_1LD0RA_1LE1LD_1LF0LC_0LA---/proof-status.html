OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 22 November 2026.

In short

The question is open, and it is now the Pascal machine's question. This table is the table of 1RB0RE_0RC---_1LD1LE_1LE1LD_1RF0LC_1RA1RF in a mirror, started in state C: every bounce writes the next row of Pascal's triangle mod 2, an odd frozen block halts, and the machine never halts if that machine's list program never fails from EO [b, a, b, a] none 1 (all Lean, kernel). The list program ran 106 steps from there without failing.

Where a halt can come from

If the machine halts on its third step from a configuration, that configuration is one of: D with 1 two left, 0 left, 0 under the head. So a run can reach a halt only through one of these patterns, and a proof that the machine never halts only has to rule them out. The proof splits on the state and the five cells around the head.

halt_route, lean/Route.lean (written by py/route.py)

One bounce is one row of Pascal's triangle mod 2

Every theorem of the Pascal machine's folder holds here with left and right exchanged; its Lean files are compiled here unchanged (lean/P75625/). At a left turn in C, with the zone right of the head a word in the 4-cell letters 0111 and 1111 and the frozen tape 1 1 1 ... left of it, one bounce turns the zone into the next row of Pascal's triangle mod 2 (closed form by Lucas' theorem), and takes two cells from the frozen block. A frozen block of odd length followed by 0 1 halts, whatever the zone, clean or walled (the halt: D reading 0 with 0 and then 1 to its left).

bounce, bounces, halts_of_odd, halts_of_odd_wall, lean/Mirror.lean; closed_form, lean/P75625/Lucas.lean

The holdout is the Pascal machine's list program, from another start

The first left turn in C, at step 26, is the list state EO [b, a, b, a] none 1 of the Pascal machine's list machine arun (zone b a b a). If that list machine never fails from there, this machine never halts. The Pascal machine's own run starts it at EO [b, a] none 1.

start, not_halts_of_arun, lean/Mirror.lean; astep, lean/P75625/End.lean

Where the list machine can fail

For every state: a turn with no lone 1 in the zone never fails; a crossing turn with a clean far part whose tape ends in a single 1 never fails, and plain and crossing turns ending in a single 1 hand that on. So the list machine fails only at a crossing turn with blank end, at an EO turn during a crossing, or at a crossing turn whose far part is not clean.

astep_T, astep_EO, astep_T2_end, astep_endOne, astep_none, lean/Fail.lean

Regular-language deciders tried (F11)

None of these closes: each reaches a halting configuration in its abstraction, which says nothing about whether the machine halts. n-gram CPS (tools/c/ngramcps.c), equal widths on both sides: a halting local configuration is reached with plain up to width 24, history 1 up to width 24, history 2 up to width 24, history 3 up to width 24, LRU history up to width 6 (larger widths ran out of the 150 s or 60 million configuration budget). n-gram CPS with every cell tagged by its position mod p: fails for p = 2 up to width 20, p = 3 up to width 20, p = 4 up to width 20, p = 6 up to width 20. n-gram CPS where each side also carries the state of a small automaton that has read that side from the far end (every automaton with up to 3 states on both sides, or 4 states on one side), with position mod 1..4 and widths 4, 6, 8: no closed set without a halt in all 120 parameter sets. Run-length windows (the K nearest runs of equal macro cells on each side, run lengths kept exactly below T and mod M above): fails for all 72 parameter sets (cells of 1 to 4 bits, K = 2, 4, 6, T = 2, 4, M = 1, 2, 4). Two-automaton closed tape language by SAT (a deterministic automaton reading each side inward, n states each, CaDiCaL): no solution for n = 2..7; n = 8 not finished in 150 s.

sweeps of 13 November 2026 (family F11); the tagged and run-length deciders are not in the repository yet

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.085). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.506).

tools/py/bbtools/triage.py

Blocks of length 4k + 3

At each visit of the left end up to step 5.2·108, every block of 1s except the first two and the last has length 4k + 3; the counts for k = 0, 1, 2, … halve at each step (2,665, 1,336, 716, 315, … of 5,366 at step 522,867,988). Observed in simulation, not proved.

c/sim.c, README

Rounds grow by about 1.75

Between consecutive long gaps the list, read as a word with 4k + 3 ↦ 1^k 0, grows from 26 to 97, 351, 1,136, 3,508, 10,746 letters every second round (about 1.75 a round), and the step count by about 3.1 a round.

Does it halt from blank tape?

Not known. It halts exactly if the Pascal table started in C halts (Lean), and it never halts if the Pascal machine's list machine never fails from EO [b, a, b, a] none 1 (Lean). Whether it fails is the same open question as for the Pascal machine, from another start.
