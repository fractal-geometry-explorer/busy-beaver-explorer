Does this machine ever halt?

1RB0RF_1RC1LB_1LD1RE_1LB0LD_1RF0RC_1RA---

Nobody knows. Between its rebuilds this machine is a binary counter that applies one small operation to a list of blocks at every tick, and the list is, read in binary, the time left until the next rebuild. This page runs the machine, lets you step the list and the counter, and lists what is known.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from A1 (writes 0, moves R): A>1 1; E0 (writes 1, moves R): E>0 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

The picture

A binary counter that rewrites a list

Stop the machine each time the head is in state C on a 0 just right of a 1. The tape is then a list of blocks of 1s separated by single 0s, a block of one 1, a last block, and right of the head a zone of single 1s. From one such moment to the next (a sub-round) two things happen, and they do not influence each other.

The list takes one step. Its last block, of 2a + 1 cells, gives 2 cells to the block on its left and falls apart into a blocks of 1: x, 2a+1 becomes x+2, 1, ..., 1. Counting a block of 2a + 1 as the digit a: the last digit a is removed, the digit before it grows by 1, and a zeros are appended.

The counter ticks. The last block and the zone hold a binary counter. A round is 2m sub-rounds in which they fill 5(m + 1) cells; then the last block is 5(m + 2) cells and round m + 1 starts. This is why each round takes twice as long as the one before.

The list gets shorter in the end, and how long that takes can be read off it: a list with digits a1, ..., ak is a single block after exactly T steps, where T has a binary 1 at the positions ak, ak + ak−1 + 1, ak + ak−1 + ak−2 + 2, and so on. The list is the time it has left, written in binary. Try it:

Rebuilds. When a single block is left, the sub-rounds are irregular for a while: the block is cut into 2 1 1 1 ..., cells of the last block and the zone move into the list, and then the regular life starts again with a longer list.   Halting
  
Why it is hard to settle


The machine halts only in state F reading a 1. In a regular sub-round that does not happen (in the model). What the irregular stretch after a single block does has no rule yet. For the sibling 1RB0RE_0RC0RF_1LD1RA_1RE0LD_0LB1RC_1LE---, which follows the same model in another coding, some tapes of the machine's own shape halt; for this machine a search over small single blocks found none.


The run from blank tape has passed 3,792 rebuilds, more than 109,553 steps, without a halt. After that comes a stretch in which the list counts upwards for too long to simulate cell by cell; it is not modelled yet, so the run cannot be followed further for now.

The shape of the run


Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.04).



After 109 steps the tape spans 203 cells (6 left of the start, 191 right), with a density of 1s of 0.345.

Computed
holdouts/1RB0RF_1RC1LB_1LD1RE_1LB0LD_1RF0RC_1RA---/py/model.py (check 400000)
Between rebuilds: a binary counter that applies one list operation per tick
The same model as for the sibling 1RB0RE_0RC0RF_1LD1RA_1RE0LD_0LB1RC_1LE---, in another coding. At the moments the head is in C on a 0 just right of a 1, the tape is a list of blocks of 1s separated by single 0s (the interior), then a block of one 1, a last block l, and to the right of the head a zone of single 1s. Call it regular if the first block is even, the other interior blocks are odd, l is a positive multiple of 5, and the gaps of the zone are 0 mod 5 (the first, counted from the head) and 4 mod 5 (the others). From one such moment to the next (a sub-round) the interior takes one step W: (..., x, 2a + 1) becomes (..., x + 2, 1, ..., 1) with a blocks of 1. The last block and the zone are a binary counter: with segments s1 = g1, si = gi + 1, a last block l > 5 becomes a new first segment l − 5 and l = 5; with l = 5 the n leading segments equal to 5 are removed, the next segment loses 5 cells (blank tape supplies them if there is none) and l = 5n + 10. So l plus the segments is 5(m + 1) for 2m sub-rounds (one round), then m grows by 1. Checked against the machine one sub-round at a time: of the 400,000 sub-rounds after step 1,399 (16 million steps) the 399,965 regular ones all follow this; the other 35 are the transient of the first rebuild. Observed and checked, not proved.

    
Computed
holdouts/1RB0RF_1RC1LB_1LD1RE_1LB0LD_1RF0RC_1RA---/py/model.py (check 400000, rounds)
The list is the binary expansion of the time it has left
With digits ai = (bi − 1)/2, W removes the last digit a, adds 1 to the digit before it and appends a zeros. A tail (..., q, a) becomes (..., q + a + 1) after exactly 2a steps, so an interior with digits a1, ..., ak is a single block after exactly T = Σi 2ai + ... + ak + k − i steps of W. (This is arithmetic on the rule W, not on the machine.) Checked on the machine: the model predicts the single block at sub-round 7,964 of that run and it is there; and after the first rebuild the lists at six ends of rounds, up to step 1.07·1010, are those of a direct run of the machine (2 1^7 3 1^3 7 1^10 7 3 1^4 | 1 | 120 at step 335,864,993, ..., 2 1^6 3 15 1^10 7 3 1^4 | 1 | 145 at step 10,737,738,872).

    
Heuristic
holdouts/1RB0RF_1RC1LB_1LD1RE_1LB0LD_1RF0RC_1RA---/py/model.py (run 3792), c/trans.c
3,792 rebuilds without a halt
A run that takes the regular sub-rounds by arithmetic (any number at once, with the two rules above) and gives everything else to the machine itself, cell by cell: the transient after each single block. It passes 3,792 rebuilds; by then the counter has made more than 231,736 sub-rounds, so the machine more than 109,553 steps. A halt could only be found by the direct part and none was. The arithmetic part rests on the two rules above for all sizes, which are checked, not proved. The run stops there for a practical reason. Some transients contain a second kind of regular stretch (observed, not modelled): the block before the last one is 2l/5 + 1 instead of 1, the list counts the sub-rounds upwards in binary instead of downwards, and a gap of the zone of 5q + 4 cells is used up in about 2q+1 sub-rounds. The 1,504th transient has one with q = 24, which the run simulates cell by cell (about 109 steps); after rebuild 3,792 comes one that is too long for that.

    
Open
Does it halt from blank tape?
Not known. Between rebuilds the machine cannot halt if the model is right; what the transient of a rebuild does has no rule yet, and a second kind of regular stretch inside the transients, in which the list counts upwards, is not modelled. The sibling 1RB0RE_0RC0RF_1LD1RA_1RE0LD_0LB1RC_1LE---, which follows the same model, has tapes of its own shape that halt, so the shape alone is unlikely to decide this machine either.
