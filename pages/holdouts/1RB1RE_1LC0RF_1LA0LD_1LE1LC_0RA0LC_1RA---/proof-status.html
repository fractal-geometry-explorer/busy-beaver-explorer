What is known about 1RB1RE_1LC0RF_1LA0LD_1LE1LC_0RA0LC_1RA---

1RB1RE_1LC0RF_1LA0LD_1LE1LC_0RA0LC_1RA---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 9 November 2026.

In short

The question is open. The machine is a base-4 counter whose digits carry timers. Lean proves the sweep rule (one increment, any number of carries) for all values, and also that tapes of the same counter shape with short timers halt: so nonhalting cannot follow from the shape of the tape alone, it depends on the timer values the run from blank tape produces. An accelerated simulation that applies the rule in closed form and simulates every irregular sweep exactly reaches 102000 steps without a halt, never with more than one irregular pattern inside the counter at a time.

Other proofs and outside reports

Community label

In the community's BB(6) tracker the machine's class is Skelet 1-like Class 1. These are labels read off the run by others, not results.

The machine stops exactly when it reads the symbol of a halting transition (F1); the generated statement covers every configuration.

No halt in the first 10,000 steps

The list simulator of the shared library, proved to agree with the machine's semantics, runs 10,000 steps from blank tape without a halt, evaluated by Lean's kernel.

blank_runs_kernel, lean/Blank.lean

The sweep rule, any number of carries

At the left end in state C the tape is a^n0 s(d1) a^n1 ... s(dk) a^nk with a = 001 and separators s(0)=0, s(1)=011, s(2)=00, s(3)=0101. One sweep adds one to the base-4 number d1 d2 ...: for every n0 ≥ 2, every block ≥ 1 and every list of carried digits 3 (a list of any length), the carried digits become 0 and their blocks gain one a, and the first digit below 3 goes up by one (its block loses one a on 0→1 and 2→3).

sweep0, sweep1, sweep2, lean/Rules.lean (lists by induction, lean/Seq.lean)

Exact step count without carry

A sweep without carry takes 8·n0 + 6 steps (with carries, 8(n0+...+nj) + 10j + 6, checked by simulation).

step0, step1, step2, lean/Rules.lean

The same tape shape halts with short timers

C> a^2 0 a^4 01 (one digit, block 4) halts at step 309,457 and C> a^43 0101 a^4 0101 a^4 01 (digits 3, 3, blocks 4, 4) at step 4,905,443. Both are sweep starts of exactly the counter form; the step counts agree with the accelerated simulator and a plain C simulator. A nonhalting proof must therefore use the timer values of the actual run.

counter_2_0_halts, counter_43_33_halts, lean/Perturbed.lean

No halt in the first 109 steps

The C simulator tools/c/triage.c runs 109 steps without a halt; at the end 68,700 cells have been visited and 26,681 of them hold a 1.

holdouts/triage.json

No halt in 102000 steps

py/accel.py applies t sweeps at once between irregular events (the counter plus t, each timer N_i = n_i + c(d_i) minus the wraps of its digit, the step count summed in closed form) and simulates every irregular sweep (overflow, fused digits) with an exact run-length simulator. From blank tape it reaches 102000 steps without a halt. It agrees with the plain simulator at every sweep start (checked up to 3·106 steps in Python and 3·108 with tools/c/tmrun.c), and the run-length simulator agrees with the plain one on random tapes.

py/accel.py, py/rlsim.py

Many counter tapes with other timers halt

All tapes with one or two digits, blocks 1..4 and n0 = 2..12: 136 halt within 107 steps. 300 random tapes with 2..7 digits and the block after digit i up to 4i+2: 22 halt within 10150 steps, 20 of them at steps of 6 to 25 digits, one near 1052 and one near 1089.

py/perturb.py

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.523). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.092).

tools/py/bbtools/triage.py

Only a small set of irregular patterns

Up to 10300 steps only about twenty different irregular separator patterns appear after the simulated sweeps (two separators touching when a timer has run out, and the end 01 during overflow), each recurring many times, and there is never more than one irregular pattern inside the counter at a time (3,008 simulated sweeps with one, 2,405 with none).

python3 py/accel.py run 1e300

A cryptid-like tail

In the random runs the rate of halting falls off as the timers grow (a fusion of two digits is dangerous only when other timers run out in the same short window). The run from blank tape is far past the stage where most random runs halt; that it keeps surviving is likely, but nothing known forces it.

py/perturb.py, README

open Open

Does it halt from blank tape?

Not known. The only halting transition is F1; normal sweeps never reach it (proved). A halt needs several timers to run out close together, as in the short-timer tapes above; whether the run from blank tape ever produces such a coincidence is an open arithmetic question about its timers.
