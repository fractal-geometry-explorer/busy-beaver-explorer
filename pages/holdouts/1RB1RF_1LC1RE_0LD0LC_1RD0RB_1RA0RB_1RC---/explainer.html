Does this machine ever halt?

1RB1RF_1LC1RE_0LD0LC_1RD0RB_1RA0RB_1RC---

Nobody knows. Started on a blank tape, this machine keeps a word of blocks of 1s on the left and a binary counter on the right, and rewrites the word by a fixed map at every count. The regular steps and the reset of the word are proved in Lean. Whether it halts comes down to a race: the gaps left behind by each reset have to be cleared before the word runs out again.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from A1 (writes 1, moves R): A>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The structure

A word and a counter

This machine is one of six G12 holdouts that share every transition except two: A1 (0RF or 1RF) and F0. Here A1 is 1RF and F0 is 1RC. Both are used only at an F event, when state A reads a 1, which is rare (see the last section). Everything else is the same for the six machines, and so is this page up to that point.

Most of the time the tape reads W 0 1^(3a) B>0 R. We call this a Q configuration. W is a word: blocks of 1s separated by single 0s, with a blank tape to its left. The first block is even and every later block is odd. R is a run of gaps 0^(3p+2) 1. The run of 3a ones before the head and the gaps together hold a binary counter: a and the gap sizes p are its digits, read in parts. The head stays between the word and the counter. It goes left and rewrites the end of the word, then goes right and adds one to the counter.

On the word the machine applies a fixed map φ. It removes the last block b, adds 2 to the block before it, and appends (b−1)/2 blocks of a single 1. The total width stays the same. Applying it repeatedly, a word with blocks 2 3 1 5 goes like this:

word (blocks)tape
2 3 1 51^2 0 1^3 0 1 0 1^5
2 3 3 1 11^2 0 1^3 0 1^3 0 1 0 1
2 3 3 31^2 0 1^3 0 1^3 0 1^3
2 3 5 11^2 0 1^3 0 1^5 0 1
2 3 71^2 0 1^3 0 1^7

Repeated φ carries every block into the first one: the word eventually becomes a single block. The number of steps this takes is exactly N(W) = Σi≥2 2(Si−1)/2, where Si is the width of the word from block i to the end. So φ is itself a counter, written in a mixed radix.

Proved in Lean

One Q-step: φ twice, the counter plus one

From one Q configuration to the next, the machine applies φ twice to the word and adds one to the counter. The step count is a linear function of the parameters. The step depends only on the last one or two blocks of the word (a last block of 2j+5, a last block of 3, or a last 1 after an odd block) and on the lowest part of the counter (at least two units, or one unit followed by t gaps of length 2). That gives six cases.

word endscountersteps
1^(2j+5)a+2 ≥ 23a + 8j + 41

1^(2i+1) 0 1a+23a + 8i + 33
1^(2i+1) 0 1one unit, t8i + 3t + 33

All six are Lean theorems checked by the kernel, for every value of the parameters and every tape beyond. lean/Rules.lean states them as shift rules. lean/Macro.lean restates them on Q configurations qc W a P T, with φ defined as a Lean function on lists, for example qstep_big_wide.

Simulated

Long cycles, anomalies and collisions

Between Q events the counter climbs. When it overflows, the run of ones 1^(3k) gets longer by one unit and the counter starts again from zero. A full cycle with counter length k applies φ about 2k times, and each extra unit roughly doubles the time. That is why the right side of the tape grows like the logarithm of the step count.

The regular Q-steps break down in two ways, called transients. An anomaly happens when the word has become a single block: φ has nothing left to carry, and the block restarts as 2 1 1 … one cell further left. A collision happens when the counter overflows into a gap that is too short. The accelerated simulator py/hyb.py (in the folder of 1RB0RF_1LC1RE_0LD0LC_1RD0RB_1RA0RB_0LC---) jumps over regular stretches with the closed forms above and runs every transient cell by cell. It agrees with direct simulation on every F event up to 2·1010 steps, and on direct runs of 3·108 steps from Q events picked at random in the middle of phases.

For this machine it ran 300 transients without a halt, up to about 22836 steps, with the tape 5664 cells wide.

Proved in Lean

The anomaly: the word starts again

Each φ moves width into the first block, so after N(W) steps the word is a single block (or a block and a single 1). The next Q-step cannot apply φ and does something else, the anomaly. It is short and exact. The head erases the counter's low part, slides the block one cell to the right through the hole it leaves, and comes back rewriting the block as 1 1 0 1 0 1 …:

beforeaftersteps
1^(2c+2) 0 1^(3a+3) B>0 R1^2 (0 1)^c 0 1^3 B>0 0^(3a) 1 R3a+8c+17
1^(2c+2) 0 1 0 1^(3a+6) B>0 R1^2 (0 1)^c 0 1^3 0 1^3 B>0 0^(3a+1) 1 R3a+8c+46

The new word 2 1 1 … 1 has the same width w, and N(W) = 2(w−2)/2 − 1 for it: it lasts that many φ steps. The counter starts again from one unit. Where the old low part was there is now a gap of 3a or 3a+1 cells. That is not of the form 3p+2: it is the misaligned gap. All of the old counter's gaps are still behind it. These are Lean theorems for every a, c and every tape R (anomaly_one, anomaly_two in lean/Transients.lean). The third shape, a block and a single 1 with a one-unit counter, goes through an F event and depends on A1 and F0, so it is not among them.

As the new counter overflows, the misaligned gap shrinks by 3 each time. When it is down to 0 or 1, the next overflow is a collision. The head carries that part of the counter into the end of the word, and the next old gap, a few cells shorter, becomes the misaligned one. This cascade continues until the old gaps are used up and the counter is aligned again.

Simulated

A race between the word and the cascade

Shape alone does not keep the machine running. Lean checks that the Q configuration 1^2 0 1^3 0 1^3 B>0 halts after 190 steps (qc_short_halts). Its word is valid and its counter is aligned, but the word is so short that it runs out again while the misaligned gap made by the first anomaly is still there. The second anomaly then leaves gaps of 1 and 0 in a row, and the collision on them halts. The real run avoids this only because each cascade ends long before the word runs out.

For this machine the cascade after an anomaly ends at most 2278 steps later. The epoch, from one anomaly to the next, lasts up to 22762 steps. The margin (bits of the epoch minus bits of the cascade) is at least 8.0, and is that small only in the first epochs. A proof would need a bound on the cascade, set by the size of the counter at the anomaly, that stays below the word's N(W).

Halting

Where it could stop

F is reached only from A reading a 1, and F halts on a 1. So a halt needs A to read 1 1. Regular Q-steps never let A read a 1. Only transients do; such a moment is an F event. In the first 2·1010 steps this machine has 7 F events, and at every one the cell after the 1 is a 0.

All the F events we saw happen in collisions. A collision starts when the counter's low part is one unit followed only by gaps of length 2 and then a misaligned gap of length 0 or 1. The head sweeps that part of the counter into the word, and the next gap becomes the misaligned one, shortened by a few cells. A halt needs a gap of length 0 right after such a gap. The gaps behind the misaligned one come from the counter as it was at the anomaly. In every run they have length ≡ 2 (mod 3) and at least 2, so the halt never comes.

Status: open. Lean proves the regular dynamics, the anomaly and that the word-and-gap pattern alone does not prevent a halt. The collisions, the race and the alignment of the gaps are simulated, not proved.

The anomaly, exactly

When the word has run out the machine rewrites it in one sweep, for every value of the parameters and every tape beyond: from 1^(2c+2) 0 1^(3(a+1)) B>0 R (blank to the left) it reaches 1^2 (0 1)^c 0 1^3 B>0 0^(3a) 1 R, one cell further left, in 3a+8c+17 steps; from the word 1^(2c+2) 0 1 with a+2 units it reaches the word 2 1…1 3 with a gap of 3a+1 in 3a+8c+46 steps. The new gap is the misaligned one (not of the form 3p+2).

Kernel
qc_short_halts, lean/Transients.lean
The word-and-gap pattern is not an invariant

From the Q configuration 1^2 0 1^3 0 1^3 B>0 (a valid word 2 3, a one-unit counter, no gaps, blank tape) the machine halts at step 190. Its word is so short that it runs out a second time before the misaligned gap made by the first anomaly is cleared; the second anomaly leaves gaps of 1 and 0 in a row, and the collision on them halts. So no proof can use only the shape of the word and of the gaps (even/odd blocks, gaps ≡ 2 mod 3): it has to carry the sizes.

Pieces of the irregular steps

Five rules that hold for all six machines of the family and for every value of the parameters: the head rewrites the end of the word as φ applied twice and comes back, without reading the tape on either side (3 shapes of the word's end); and the way a regular step with a one-unit low part ends (next gap at least 3 cells, or blank tape).

The anomaly with a one-unit counter, for this machine

Word a block 2c+2 and a single 1, counter low part one unit (4 rules): with no gap of 2 behind, the new word is 2 1…1 5 1 and the next gap (at least 5 cells) loses 5; with one gap of 2 behind, the new word is 2 1…1 5 3 and the next gap (at least 4 cells) loses 4; the same with blank tape. The counter restarts from one unit. This step passes an F event, so it differs between the six machines. These rules are statements about tapes; they are not yet part of the macro map below.

Kernel
coll_*, lean/Collide.lean; restated as zcoll_* in lean/CollideQ.lean
Some collisions

A collision starts with the counter's low part one unit, then t gaps of length 2, then a misaligned gap of 0 or 1 cells. Ten cases, each with a next gap of at least 5 cells or blank tape (20 rules): misaligned gap 0 with 0, 1, 2 or 3 gaps of 2 behind when t is even and 0, 1 or 2 when t is odd; misaligned gap 1 with at least one gap of 2 behind when t is even (any number) and with 0 or 1 when t is odd. In each the word takes its double step, its last block grows by 2, 3t/2 single 1s and one to four more blocks are appended, and the next gap loses 3, 4 or 5 cells. Proved for every value of the parameters and any tape to the left.

Kernel
astep, astep_sound, lean/Full.lean (generated by py/gen_full.py in 1RB0RF_1LC1RE_0LD0LC_1RD0RB_1RA0RB_0LC---); notation in lean/Abstract.lean
A partial macro map

A function astep that sends a word-and-counter configuration (word, low part, list of gap lengths) to the next one. It is defined for the regular steps, for the anomaly when the low part is wide enough, and for the collisions above; elsewhere it answers ‘no rule’. Lean proves that wherever it is defined the machine really goes from the first configuration to the second, in at least 17 steps. It does not cover the anomaly with a one-unit counter, and the very first configuration of the run from blank tape (step 27) is one, so this map cannot yet follow the run from the start: it is a building block, not a bound.

Gap alignment

Open
Does it halt from blank tape?

Not known. What is missing, in order: (1) the remaining collision cases as Lean rules. Unlike in the 0LC machine, a collision here does not clear the misaligned gap: it shortens the next gap by 3 to 7 cells, which is misaligned in turn, so gaps of every small length occur and each needs its own case; in several cases the head also goes back into the word. A finer description (the configurations with an empty low part that follow an F event) would probably replace this case list by a few rules. (2) the one-unit anomaly and those rules inside the macro map, so that it follows the run from step 27. (3) the size argument: every cascade of collisions ends before the word runs out. For the 0LC machine, where (1) and (2) are done, (3) is the open part and looks like a Collatz-type question; the same is to be expected here.
