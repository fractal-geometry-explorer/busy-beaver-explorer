Does this machine ever halt?

1RB1LA_1LC0RE_1LF1LD_0RB0LA_1RC1RE_---0LD

Space Needle is one of the community's cryptids: whether it halts is equivalent to whether a simple sequence of numbers, 6, 10, 17, 41, 101, 251, 626, ..., ever reaches a power of two. This page shows how the machine computes that sequence, and what is proved about it.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 0. F is entered only from C0 (writes 1, moves L): 0 C>0. So a halt is the moment this pattern appears, with the head on the cell after >.

The tape

Blocks of 1s, and a state that keeps coming back

Run the simulator to step 45 and the tape reads A>0 1 1 1 0 0 1: the head, in state A, on the 0 just left of everything, then a block of three 1s, a gap of two 0s, a block of one 1. Call this shape

X(b, c) = 0^∞ A>0 1^b 0 0 1^c 0^∞

so step 45 is X(3, 1). The machine keeps coming back to this shape: X(0, 5) at step 64, X(7, 1) at 107, X(2, 7) at 158, X(14, 1) at 274, X(38, 1) at 2,640, X(98, 1) at 31,346, X(248, 1) at 434,602. In between, the tape holds two or three long blocks of 1s separated by single 0s, and the head works on them in long regular phases. Nothing else ever happens: the whole run is these visits and the phases between them.

One macro step

Bouncer, zig-zag, shift

Take X(14, 1). Three kinds of motion carry it to X(38, 1):

  • The bouncer. A writes a 1 left of the block and the head runs to the right end of the block. From 0 1^(m+3) C>0, states C, F, D erase two 1s, A runs left, B and E run right: the middle block loses two 1s and each side gains one, 1 0 1^(m+1) C>0 1. Repeated, the block of 14 shrinks to 2 while blocks of 7 grow on both sides. Each bounce crosses the whole block, so this phase takes time quadratic in b.
  • The zig-zag. Then the head stands at the left end in state A, before 1^a 0 1^b. Going back and forth it moves the 0 between the two blocks one cell at a time, ending with the first block one shorter, the second two longer, and the whole picture one cell further left: A>0 1^(a+1) 0 1^b becomes A>0 1^a 0 1^(b+2). Repeated a times, the first block disappears into the second.
  • The merges. When the first block is empty, the gap of two 0s closes up and the next block becomes the first; with no block left after it, the tape is X(m, 1) again.

For X(14, 1): the bouncer leaves 1^7 0 1^2 C>0 1^7, then A>0 1^6 0 1^2 0 1^8; six zig-zags give A>0 0 1^14 0 1^8; a merge gives A>0 1^15 0 1^8; fifteen zig-zags give A>0 0 1^38, and the last merge X(38, 1). Each of these steps is a lemma in Lean, proved for all values of the lengths.

The map

mxdys's rules

Done in general, the phases give one rule per case of b:

fromtowhat happens
X(0, c)X(c + 2, 1)the empty block merges
X(1, c)halt13 steps later F reads a 0
X(2k + 2, c)X(5k + c + 7, 1)bouncer, k zig-zags, merge, 2k + 3 zig-zags, merge
X(2k + 3, c)X(k, k + c + 4)bouncer ends on an odd block: b roughly halves

An even b multiplies b by about 5/2 and resets c to 1; an odd b halves b and stores the rest in c. The machine halts when b reaches 1, which can only happen by halving. Lean proves the four rules and that the machine halts from blank tape exactly when the orbit of (3, 1) reaches b = 1 (halts_iff in lean/Macro.lean).

The orbit: (3, 1) → (0, 5) → (7, 1) → (2, 7) → (14, 1) → (38, 1) → (98, 1) → (248, 1) → (623, 1) → (310, 315) → (1092, 1) → (2733, 1) → (1365, 1370) → (681, 2055) → (339, 2398) → (168, 2570) → (2992, 1) → …

One number

Doucette's sequence

Look only at the visits X(b, 1) and write D = b + 3. Between two of them, the odd rule applies v times, where 2v is the largest power of two dividing D: each odd step halves D exactly (b + 3 becomes (b + 3)/2) and adds to c. Then one even step uses everything stored in c. Adding it up, the next D is

F(D) = D + v + 3a,   where D = 2^v · (2a + 1).

From X(3, 1), D = 6, and the sequence runs 6, 10, 17, 41, 101, 251, 626, 1095, 2736, 2995, 7486, 13100, … If some D is a power of two, the halvings run down to D = 4, which is b = 1: the machine halts. If not, they always stop at an odd D ≥ 3 and the even step follows. Lean proves this equivalence (halts_iff_pow2 in lean/Collatz.lean): Space Needle halts if and only if Doucette's sequence reaches a power of two.

Each term is a visit to the left edge, and each costs far more machine steps than the last (a cubic number in b): the visit X(2992, 1) (D = 2995) comes at step 519,524,312, the next one, X(7483, 1), at step 10,608,569,291. The sequence itself is cheap: Lean's kernel checks the first 20,000 terms, compiled Lean 300,000, and C 3·106. None is a power of two.

Why it is open

A coincidence that should never happen

F(D) is about D · (1 + 3/2v+1): an odd D grows by a factor of about 5/2, a D with many factors 2 by much less. If the low bits of the terms are like random bits, v is 0 half the time, 1 a quarter of the time, and so on, and D gains about 0.94 bits per step (a factor of 1.92). A number of n bits is a power of two with chance about 2−n, so the chance that any term after the first few dozen is a power of two is astronomically small. In 3·106 terms, v has never exceeded 24.

So the machine almost certainly never halts. Proving it is another matter: one would have to show that a sequence built by additions never has all its bits but one equal to 0, that is, control the 2-adic valuation of every term. Questions of this kind (like the Collatz problem) are beyond present mathematics, which is why Space Needle is called a cryptid. Run backwards, the condition is a chain of congruences: a power of two 2n can be reached from a multiple of 2k only for special n (for k = 0, only n ≡ 0 mod 4), and the smallest powers of two reachable within a few steps are already enormous; but no one has turned this into a proof.

First look

The shape of the run

Left of the start, the visited part of the tape grows like a power of the step count other than 1/2 (fitted exponent 0.311). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.059).

After 109 steps the tape spans 3,249 cells (2,978 left of the start, 23 right), with a density of 1s of 0.999.

What is known

Every result, by what it rests on

Kernel
step_none_iff, lean/Blank.lean
The halting configurations

The machine stops exactly when F reads a 0.

Kernel
lean/Rules.lean, py/gen_rules.py
Shift rules

Fifteen rules on symbolic tapes, for all values of their parameters and any surrounding tape: one bounce of the bouncer (L 0 1^(m+3) C>0 R to L 1 0 1^(m+1) C>0 1 R), one zig-zag, the ends of the phases, the halt of (1, c), and blank tape to (3, 1) in 45 steps. Written by tools/py/bbtools/symtm.py as chains of rfl steps and the crossing lemmas.

Kernel
even_rule, odd_rule, zero_rule, halt_rule, lean/Macro.lean
mxdys's macro rules

Write X(b, c) for 0^∞ A>0 1^b 0 0 1^c 0^∞. For every b and c ≥ 1: X(0, c) reaches X(c + 2, 1); X(2k + 2, c) reaches X(5k + c + 7, 1); X(2k + 3, c) reaches X(k, k + c + 4); X(1, c) halts 13 steps later. Proved by three inductions (the bouncer, the zig-zag, the shift of a block) over the shift rules.

Kernel
halts_iff, lean/Macro.lean
The reduction to mxdys's map

Let g be the map above on pairs (b, c), and orbit n its n-th iterate from (3, 1). The machine halts from blank tape if and only if some orbit n has b = 1.

Kernel
halts_iff_pow2, macro_F, macro_pow2, lean/Collatz.lean
The reduction to Doucette's sequence

Let D0 = 6 and Dk+1 = F(Dk) with F(D) = D + v + 3a for D = 2v(2a + 1). The configurations X(b, 1) of the orbit are exactly b = Dk − 3; between two of them come v odd steps, each halving b + 3, and one even step. So the machine halts from blank tape if and only if some Dk is a power of two.

Computed

The macro rules against the machine

A direct run of 3·1010 steps (c/verify.c) meets the shape X(b, c) exactly at the configurations the orbit of g predicts, in order, and at no others: 19 of them, from X(3, 1) at step 45 to X(7483, 1) at step 10,608,569,291 and X(3740, 3745) at step 10,636,589,390.

Computed
c/doucette.c
No power of two in the first 3·106 terms

Multi-precision C (c/doucette.c, checked against Python for the first 105 terms: bit length and largest v agree). The 3·106th term has about 2.8·106 bits; the largest v seen is 24, the mean v is 0.998. The community reports 108 terms with at most 25 factors of 2.

Heuristic
c/doucette.c
Probviously non-halting

If the low bits of Dk behave like random bits, v is geometric with mean 1, D grows by an average factor of about 1.920 per term (0.9412 bits, LegionMammal978's estimate; 0.9414 measured), and the chance that a term of n bits is a power of two is about 2−n. Summed over the terms after the ones checked, the chance of a halt is far below 10−10000.

Open
Does it halt from blank tape?

Not known. Equivalent (in Lean) to: does Doucette's sequence ever reach a power of two? No method is known that controls the 2-adic valuation of terms of such a sequence.
