Nobody knows. Started on a blank tape, this machine runs a Collatz-like map on two counters, and it would halt only if one pass of that map ended exactly at zero. This page runs the real machine in your browser, explains the map, and lists what is known.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in E reading 0. E is entered only from C0 (writes 0, moves R): C>0 0. So a halt is the moment this pattern appears, with the head on the cell after >.

What it does

Two counters on one tape

Run the simulator for a while and stop when the head is at the left end in state B. The tape always has the same simple form: two blank cells, then a copies of 10, then a solid block of b ones, then (usually) one more 10:

B>0 0 (10)^a 1^b 1 0

So the machine is a device with two counters. A few of the pass starts from the first 4,000 steps, as (a, b): (2, 35), (6, 29), (14, 15), (12, 21), (2, 43), (6, 37), (14, 23). The total width 2a + b grows by 2 with each pass, so the tape grows only as fast as the number of passes, and each pass takes time proportional to about the square of the width: after 109 steps the tape is about 2,900 cells wide.

Macro structure

One pass: doubling, folded

In a pass, state A walks back and forth eating the 10s on the left one at a time. Each eaten 10 costs two 1s from the right block and adds four 1s to a block that grows in the middle. When the 10s are used up, the middle block becomes the new run of 10s. If b is large enough this is simply

(a, b) → (2a + 2, b − 2a − 2),

as in (2, 35) → (6, 29) → (14, 15). When the right block runs out first, the head rebounds off the right end: the middle block becomes the new right block (about twice as long as the old one) and eating continues. So a pass is a little Euclid-like loop, and (14, 15) goes to (12, 21): seven 10s eaten, a rebound, then the last six. With a few more rules for the rare even cases this pass_map (in py/passmap.py) predicts every one of the 3,095 passes in the first 1010 steps exactly. Every case, rebounds included, is proved in Lean for all parameters (next_sound in lean/Phases.lean).

Measured against the width, a is being doubled and folded back, like the tent map x → 2x on a strip. That is why the tape contents look irregular: the sequence of a's is as erratic as the binary digits of a number.

The halting question

Halting needs b = 0

The only halting transition is E reading a 0. E is entered only from C reading a 0, and C and E together zip rightwards over 0 1 0 1 …, C on the 0s and E on the 1s. That zipper starts only at a pass start, on the two blank cells, and it runs over all the 10s. If a solid block follows, C reads a 1 and turns back. If the 10s are followed by blank tape, E reads a blank and the machine halts: from B>0 0 (10)^n it stops after 2n + 5 steps (proved in Lean for every n, zip_halts).

So the machine halts exactly when a pass ends with b = 0 and the closing 10 present. The width 2a + b + 2 has the parity of b, and the map changes that parity only at rare special passes; for long stretches b is odd and can never reach 0. In the short stretches where b is even, a goes through a chain of plain doublings and the next value of b is 0 only if 2a + 2 equals b exactly, a coincidence of probability about 1/width.

Iterating the map (much faster than the machine) for 108 passes, out to a tape 2·108 cells wide: only 166 passes end with an even b, the smallest b was 2, and no pass ends at 0. The expected number of future hits, summing 1/width over the even passes, is tiny and shrinking, so the machine very probably never halts; but proving it means controlling where the doubling map lands, a Collatz-type question. Lean proves that this is exactly the question: the machine halts if and only if the map reaches a pass start with at most one 1 in the right block (halts_iff).

The phase map, all cases

Write PS a c for 0^inf B>0 0 (10)^a 1^c 0^inf (a pass start) and Q R m c for 0^inf (10)^R (11)^m A> 1^c 0^inf (inside a pass). For all parameters the machine goes: PS (a+1) (c+2) → Q a 2 (c+2); PS 0 2 → PS 0 5; PS 0 (c+3) → PS 2 (c+1); j rounds Q (R+j) (m+2) (c+2j+1) → Q R (m+2+2j) (c+1); end Q 0 (m+2) (c+5) → PS (m+4) (c+1); the special ends Q 0 (m+2) c for c = 1, 2, 3, 4 → PS 0 (2m+8), PS 0 (2m+6), PS 0 (2m+11), PS 0 (2m+9); the rebounds Q 1 (m+2) c → PS 2 (2m+6), PS 2 (2m+4) and Q (R+2) (m+2) c → Q R 2 (2m+8), Q R 2 (2m+6) for c = 1, 2. Each case is one symbolic run (or an induction over rounds); next is this map.

Kernel
halts_iff, init_ps, ps_halts, next_none, lean/Phases.lean
Halting is equivalent to the map reaching c ≤ 1

The run from blank tape reaches PS 0 2 after 4 steps; PS a 0 and PS a 1 halt; on every configuration the map reaches, next is defined except there. Hence the machine halts from blank tape if and only if some iterate of next from PS 0 2 is PS a c with c ≤ 1.

native_decide
no_halt_phases, okFor_sound, lean/Phases.lean
No halt in the first 108 phases

Iterating next from PS 0 2, the first 108 phases (20,000,581 pass starts) contain no PS a c with c ≤ 1, by compiled evaluation. So a halt, if any, comes after more than 2·107 passes, far beyond the 3,100 passes direct simulation reaches in 1010 steps.

Kernel
pass_plain, rounds, lean/Pass.lean; cycle, pass_start, pass_end, lean/Rules.lean
The plain pass

For all a, s and every tape R after the block of 1s: from B>0 0 (10)^(a+2) 1^(s+2a+7) R, blank to the left, the machine reaches B>0 0 (10)^(2a+6) 1^(s+1) R. In pass-map terms (a, b) → (2a + 2, b − 2a − 2) whenever a ≥ 2 and b ≥ 2a + 3. (The first version of the proof; the phase map above contains it.)

108 passes of the map, no halt

Iterated from the first pass start, the map runs 108 passes (tape width 2·108) without reaching c ≤ 1. Only 166 passes end with b even; b ≤ 5 happened 35 times, b = 2 once. With halts_iff this is a statement about the machine, resting on the Python code (exact integer arithmetic) instead of Lean.

Open
Does it halt from blank tape?

Not known. Halting is equivalent (proved in Lean) to the phase map reaching a pass start with c ≤ 1, an arithmetic coincidence that the map avoids for 108 passes and that gets rarer as the tape grows, but nothing rules it out.
