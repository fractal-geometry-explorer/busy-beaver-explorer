What is known about 1RB1RD_0LC0LB_0RE0LD_1LB0RB_1RF---_0RA0RC

1RB1RD_0LC0LB_0RE0LD_1LB0RB_1RF---_0RA0RC

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 9 November 2026.

In short

The question is open. The machine runs a base-7 odometer whose step and carry are proved in Lean for all block lengths; a halt needs F on 1 0 1 (proved in Lean), a misaligned carry sweep. Perturbing the block lengths of a real configuration (even keeping them mod 7) makes it halt, so non-halting depends on the arithmetic of the lengths; what happens when a block runs out is described from simulation only.

No halt in the first 10,000 steps

The list simulator of the shared library, proved to agree with the machine's semantics, runs 10,000 steps from blank tape without a halt, evaluated by Lean's kernel.

blank_runs_kernel, lean/Blank.lean

The odometer step

At the left end the tape is B> [x] M_d [y] … ([k] = (010)k) with markers M0..M6 = 0, 001, 00110, 0010001, 0[2]10, 00101, 0011. One visit moves the first marker from M_d to M_(d+1), adds a copy to [x] and changes the next block by −1, −1, −1, −1, +1, 0 (d = 0..5), for every x, y and any tape beyond.

digit_0 .. digit_5, lean/Rules.lean

The carry

From M6 the first marker returns to M0 with its block +1 and the next marker moves from M_e to M_(e+1) with its block changed as in the step (e = 0..5), for all lengths.

carry_0 .. carry_5, lean/Rules.lean

A halt needs F on 1 0 1

Two steps before any halt the head is in state F on 1 0 1, three steps before in E on 0 1 0 1: the sweep C0 E0 F1 … that carries the odometer meets 0 1 where a well-formed marker gives 0 0.

halt_needs, lean/Halting.lean

Overflow and run-out events

When all digits are 6 the carry reaches the right end, all markers become 0 and a new lowest digit is put in front. When a block gets below about 4 it merges with its marker into longer words and a partial reset puts a new digit in front and merges blocks (examples in the README).

c/events.c, README.md

Non-halting depends on the block lengths

Replacing the block lengths (those ≥ 5) of the real configuration at step 299,991,864 by random lengths in [5, 300] makes the machine halt in 19 of 100 trials within 2·107 steps, and in 6 of 300 when every length keeps its residue mod 7. No closed tape language that forgets the lengths (window CTL, or mod-7 run tokens) can prove non-halting.

c/pert.c, README.md

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.446). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.095).

Does it halt from blank tape?

Not known. The rule when a block runs out is not decoded, so halting is not yet a question about a map; it would need a block to run out in a wrong phase (for instance while the next digit is 6).
