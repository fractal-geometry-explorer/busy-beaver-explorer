Does this machine ever halt?

1RB0LD_0LC0RE_1LA0RD_0RB0LD_1RC1RF_1RA---

Nobody knows. Started on a blank tape, this machine feeds two counters from one engine: per pair of visits, 3 is added to a binary number on the left and 1 to a base-3 number on the right. Each time the left one overflows the layout shifts and junk piles up on the right. It halts only if a sweep after an overflow finds three 1s in a row; 24 close calls in 2·1011 steps, all misses.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from E1 (writes 1, moves R): E>1 1. So a halt is the moment this pattern appears, with the head on the cell after >.

The machine

One engine, two counters

Watch the head at one cell, cell 65 (counting from the start cell), in state A: call each such moment an event. From step about 107 on, the tape at an event reads, left to right,

0…0 1 [H] 0110 [low] | [phase] [R] 0 1 0…
partdigitsmeaning
H0100 = 0, 0101 = 1binary, most significant first
low1000 = 0, 1010 = 1binary, lowest digit next to the head
phase111 or 110alternates every event
R001 = 0, 011 = 1, 010 = 2base 3, lowest digit first

A 111-event adds 1 to low. A 110-event adds 2 to low and 1 to R. When low wraps around, H gets 3. So every pair of events adds 3 to the left side and 1 to the right side: after n pairs the left side holds 3n in binary and the right side holds n in base 3.

A real example from the run (steps 9,021,183 to 9,021,575): low goes 5, 6, 8, 9, 11, 12, 14, 15 and wraps to 1 while H goes from 2 to 5; R goes 3377, 3377, 3378, 3378, 3379, 3379, 3380, 3380, 3381.

These rules are theorems: lean/Events.lean proves each kind of event for every number of carried digits, with its exact step count (for example 12n+12 steps for a 111-event that carries over n ones). A simulator that uses nothing but these rules reproduces the actual run cell for cell and step for step at all 466,024 events from step 9,021,183 to step 31,040,523.

The long run

Every overflow shifts the layout

When H overflows, the carry runs to the left end of the tape, which grows by 2 cells; a sweep to the right resets H and rewrites the start of R. After each such visit the boundary between H and low sits one 2-cell symbol further right, and digits of a new kind (110, 101, 100) pile up at the start of R as junk. Inside each period the machine is again a set of counters with simple rules (for instance, in the period from step 114,227,597 to 297,999,547 a two-digit junk counter runs through 9 states in 9 events while R gains 8), but each period has its own rule.

Where it could stop

Twenty-four close calls

The machine halts only in F reading 1, and F is entered only from E1. So it halts exactly when state B meets three 1s in a row (B> 1 1 1: B1 = 0RE, E1 = 1RF, F1 halts). In 2·1011 steps E1 is used 24 times; every time F then read a 0. After step 152,484 every one of them comes in the sweep that follows a left-end visit (within about 600 steps), at cells from 44 to 127, most often in the pattern 1000 [1] 0101.

The event rules never meet 1 1 1, so the counters by themselves cannot halt the machine. The question is entirely about what the sweeps after an overflow find in the junk at the start of R. The digit 111 has appeared there once, for two events right after the visit at step 114,227,597, but no sweep reached it in state B.

Next

What would settle it

Write the rules of all periods as one family (the boundary moves one symbol per visit, so the period number should be a parameter), decode what each reset sweep writes into R, and decode the change of epoch at step 1.064·1011. Then the close calls become a statement about the junk, and halting asks whether a sweep ever lines up with 1 1 1.

lean/Events.lean (generated by py/events.py)
The event rules of the first regime, for all sizes

At an event (A on cell 65) with tape 1 H 0110 low | phase R 01: a 111-event adds 1 to the binary counter low (digits 1000/1010) in 12n+12 steps for n carried ones; a 110-event adds 2 to low and 1 to the base-3 counter R (digits 001/011/010) in 12k+12n+40, +44 or +52 steps; when low wraps, H (digits 0100/0101) gets 3, in all four cases of H mod 4 and every number j of carried ones. 35 theorems, each for all n, k, j.

Can a reset sweep find 1 1 1?

The machine halts exactly when B meets 1 1 1. The event rules never do; the open question is what the sweeps after left-end visits find in the junk of R, in the later periods and epochs, whose rules are not yet written as one family.
