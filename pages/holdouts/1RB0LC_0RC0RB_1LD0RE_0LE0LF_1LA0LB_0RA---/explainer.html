Does this machine ever halt?

1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---

Nobody knows, but the machinery is clear. In frame A the tape is a list of blocks (10)^b; the head works through them like a nested counter in base 5, and the only way to halt is a rare F-event going wrong. The counter is proved in Lean for every depth; run as an exact map on block lists it reaches 6.8·10100 steps and meets 138 F-events, all harmless.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from D1 (writes 0, moves L): 1 D>1. So a halt is the moment this pattern appears, with the head on the cell after >.

The mechanism

Blocks of 10 and a nested counter

Away from rare moments the tape (in frame A) is a list of blocks: runs (10)^b separated by single 1s. At an event the head, in state A, has just turned right at the left edge of the blocks it is about to work on; everything to its left is spread out as (1000)^q ending in a short tail.

A round on the last m blocks runs the head right over them (state B, six steps per 1010, which becomes 0100) and back (states E, A, C, D, four steps per 1000). A round on blocks j..k contains five rounds on blocks j+1..k, so the work is nested like a counter in base 5, and a round on the last m blocks changes them by:

(From phase 1 of the tail the first block gets 2 more.) After the round the tail on the left has moved one phase on (10, 1, 1001, 101, 11); after five phases one 1000 of the spread block on the left is used up, which is how the deeper block counts down. Between consecutive events of this run: 30,679 events in 10^9 steps; transitions: same 14,749, same* 4,887, down 6,087, up1 3,934, up2 786, up3 155, up4 32, up5 5, X 43.

The whole run

A visit calls five visits

Cut the run into visits: a visit starts when the head (state A) stands just left of a list of plain blocks and ends when it steps back out to the left. It never looks at the tape on its left, so its outcome depends on the list alone. A visit to [b1, b2, …, bk] with b1 odd spreads b1 (PUSH), then makes five visits to the shorter list [b2+1, b3, …], nudging the tail between them (+3, +1, +1, +1), and finally folds b1 back up, 5 smaller (POP). That is a counter in base 5, and it is now a Lean theorem for every depth.

When the blocks are big enough the whole visit has a closed form: b1 loses 5, block i loses 18·5i−2, the last gains 12·5k−2, in about Σ 5i+1bi steps (also proved). The rest are exceptions: a single even block gives birth to a new last block 8 (proved), a block that runs out merges with its neighbour, and the left end sees an even first block.

Doing clean visits by formula and only the exceptions cell by cell gives an exact simulator of the machine that reaches 6.8·10100 steps in 19 seconds; it agrees with the plain simulation event for event for the first 1011 steps.

The halting condition

Where a halt could come from

Only D1 enters F; F1 halts, F0 = 0RA (frame A) lets the run go on. In 6.8·10100 steps of the exact map there are 138 F-events, all reading 0, of two kinds: 010001000100[F]001010101010 (97×); 010001000100[F]001010110101 (41×).

All of them happen the same way: an unclean visit ends in state C instead of B, on the 0 of a spread block's tail 10. C0 writes 1 and steps left onto the tail's 1, D1 sends the head into F one cell further left, and that cell is the last 0 of a 1000 (or of the 100 that starts a spread block). This is proved for every tape around (fevent_reads_zero), so these F-events can never halt.

A halt would need a different way in: an unclean visit that exits into F directly, or a C exit onto some other tail. Random block lists do that now and then (about once per 150 F-entries), so the question is whether the lists that the blank-tape run builds avoid it forever. Nobody has proved that.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.051). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.471).

After 109 steps the tape spans 73,842 cells (41 left of the start, 52,201 right), with a density of 1s of 0.334.

Kernel
go_spec, push … pop, lean/Family.lean
The visit rule for every depth

A visit starts with the head in state A on the 0 in front of plain blocks (10)^b1 1 (10)^b2 1 … 1 and ends when it first steps left of that cell; it never reads the tape on its left. go_spec proves, by induction on the depth n and for every left context, that a clean visit (a decidable condition: every block it spreads is odd and ≥ 7, every second block nonempty) turns the list l into go n l in exactly goT n l steps, where go is the recursion: spread b1, five visits to [b2+1, b3, …] with the tail bumps +3, +1, +1, +1 between them, then b1−5. It is built from seven rules (PUSH, TURN, TAIL1–4, POP) proved by bbtools.symtm for all counts.

Kernel
go_closed, visit_closed, lean/Family.lean; closed step count in holdouts/1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0RA---/py/cf.py (trusted)
Its closed form

go_closed: if b1 is odd and ≥ 7 and the later blocks are even, the last ≥ 2 and block i (i = 2..k−1) ≥ 2 + 18·5i−2, then the visit is clean and gives (b1−5, b2−18, b3−90, …, bk−1−18·5k−3, bk+12·5k−2) (a single odd block gains 1); visit_closed states it on the tape. With the tail bump after the visit this is the measured round rule (−4, −18, …, +12·5m−2) for every m.

Kernel
round1 … birth, fevent_reads_zero, lean/Family.lean
Rounds, births and the F-event

round1–round4: a clean visit followed by one phase of the tail on its left. birth: a visit to a single even block [2k+4] gives [2k+2, 8] in 10k+188 steps (where new blocks come from). fevent and fevent_reads_zero: the only way into F seen in the runs (a C exit onto the 0 of a phase-1 tail, then C0, D1) makes F read the last cell of a 1000 or of 100, which is 0 for every q and every tape around.

Where a halt would have to come from

F is entered only by D1 (D reads a 1 during the left sweep, where a spread block is turned back), and halts only when it then reads a 1. In this run every F-event has the same clean context (010001000100[F]0010101 (13×)). Random block lists do reach a halting F-event (about 1 in 150 F-entries; e.g. [15, 31, 17, 59, 31] halts after 63,153 steps), so the halt is reachable in principle; whether the blank-tape run ever produces such a list is the open part. F-events get rarer as the blocks grow (the top-level round time grows about fivefold per block).

Does it halt from blank tape?

Not known. The visit rule is proved for every depth, its closed form, births and the F-event too; what is missing is a proof that the unclean visits of the blank-tape run (merges, small first blocks, the left end) always end in a C exit of the proved kind and never in an F exit onto a 1, that is an invariant on the block lists reached from blank tape.
