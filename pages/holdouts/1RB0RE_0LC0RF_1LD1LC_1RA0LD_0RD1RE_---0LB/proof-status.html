What is known about 1RB0RE_0LC0RF_1LD1LC_1RA0LD_0RD1RE_---0LB

1RB0RE_0LC0RF_1LD1LC_1RA0LD_0RD1RE_---0LB

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 13 November 2026.

In short

The question is open. The run is a sequence of levels, each about 2 to 6.6 times as long as the one before. Every single visit of the left end in the common phases is a Lean theorem for all block sizes, and for the four common level types the map from one level to the next is an exact formula. But some levels contain a binary counter, and what follows them depends on the binary digits of a block length; no closed description of those levels has been found. The machine halts exactly when the head, in state A, stands on a 0 followed by 1 0; that has not happened in 5.6·1015 steps.

120 one-visit rules for the other phases

Each visit of the left end in the phases of the four common level types is a theorem for every block size: entering the drain phase (tails P, Q, R, S), the 14-visit drain cycle that removes four words 100, the four endings according to the block length mod 4 up to the recycling of the left block, and the pour phase of tail S. Each rule is one visit: from one tape with the head at the left end to the next.

No halt in the first 5.6·1015 steps

An exact accelerated simulator (blocks of 30 cells, run-length coded; a repeated cycle is skipped only after it has been re-run with the counts as free variables) runs 5,608,376,993,382,856 steps without a halt. Its tape was compared with plain step-by-step simulation at 50,000,050,596 steps: same state, all 399,483 cells equal. The shared C simulator tools/c/triage.c independently runs 109 steps (52,423 cells visited, 28,979 ones).

c/hsim2.cpp, py/cmpc.py, c/dump.c; holdouts/triage.json

Exact halting condition

The machine halts exactly when a configuration A> 0 1 0 occurs: state A on a 0 whose right neighbours are 1 then 0. (F is entered only from B reading 1; if F reads 1 it steps back onto the 0 that B wrote. So only B reading 1 followed by 0 halts, and B gets there from A reading 0.) A hand argument from the table, not in Lean.

README.md, section When it halts

The rules cover whole levels; the level map for b = 12..27

Plain simulation of 64 levels (tails P, Q, R, S, b from 12 to 27): every visit is an instance of one of the Lean rules, and the next level is the one the formulas give: for tail P, b' = (9b+10)/2, (9b+11)/2, (9b+10)/2, (9b+9)/2 with next tail P, Q, R, S for b = 0, 1, 2, 3 mod 4; for Q the constants are 12, 13, 12, 11; for R, b' = b+4; for S, b' = 2b+3 or 2b+4.

py/levelmap.py

The level map for every b (12 of 14 level types)

A symbolic run with the block counts as free variables, which stores a cycle only after re-running it with free counts and splits into cases by remainder when a jump needs it, follows a level from start to the next level start. For 12 of the 14 level types that occur, every case ends in a level start of one of the 14 types (91 cases), with the next block length a linear form such as 18k+113 from 4k+24. The check fails for the two types that contain the binary counter (2 cases), so the set is not closed. Python, not checked by Lean.

py/closure.py

heuristic Evidence only

Growth shape: sqrt/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.46). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.615).

tools/py/bbtools/triage.py

A binary counter inside some levels

In a level whose tail is (100111)^m the tape between the blocks is a string of the words 100 (digit 0) and 11100 (digit 1). Read as a binary number it goes up by one each time the tail loses one word, from 0 to m−1 (six runs, m up to 100). The next level depends on the digits of m: for b = 400 and m = 1..69 the next block length lies between 1,205 and 2,657 and the tail takes nine shapes.

py/counter.py

No level start that was tried halts

About 25,000 random level starts of the 14 types (block counts 20 to 149) all reach a level start of one of the same 14 types; so do the counter levels with b = 400, m = 1..69; random level starts with counts below 20 (many more shapes) do not halt either. Scratch scripts, plain simulation.

Twelve levels of the real run

Level starts from blank tape: b = 13, 77, 83, 670, 674, 5,397, 10,798, 62,092, 279,420, 1,257,395, 5,658,282, 11,316,567 (the last at step 1.92·1015), each step agreeing with the level map where the map is known. Does it halt from blank tape?

Not known. A proof that it runs for ever needs a closed description of the counter levels: a set of tapes with an arbitrary string of the two digit words between the blocks. Nothing suggests a halt.
