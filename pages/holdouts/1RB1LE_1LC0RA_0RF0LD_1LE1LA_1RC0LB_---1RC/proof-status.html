What is known about 1RB1LE_1LC0RA_0RF0LD_1LE1LA_1RC0LB_---1RC

1RB1LE_1LC0RA_0RF0LD_1LE1LA_1RC0LB_---1RC

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 12 November 2026.

In short

The question is open, and Collatz-like. Write a = 10, b = 110. At the moments the head, in B, extends the tape to the left, the tape is B> 0 0 a^k b a^m 1 (two blocks, one marker) or B> 0 0 a^k b a^m b a^n 1 (three blocks). The first block doubles, k → 2k + 3, and takes k + 2 pairs from the second block each time; when the second block is too short the marker runs off the end and the blocks are rebuilt from what is left. All of this is one explicit map on the lists [k, m] and [k, m, n] (eight cases, below). The map is fitted: it agrees with a direct run of the machine on 1,053 small lists and with the run from blank tape at all 214 marker moments of the first 3.7·107 steps, but it is not proved. Proved in Lean: blank tape reaches the list [1, 1, 1] at step 72, and a block with no marker halts whatever its length. By the map, a block with no marker is produced exactly from two equal blocks [k, k], so the machine halts if and only if the orbit of [1, 1, 1] ever meets [k, k]. It has not in 3·108 iterations, where the blocks are numbers of about 1,000 bits; no residue pattern excludes it. The community tracker lists this machine as a cryptid (halting reduces to a Collatz-like question), which is what this map shows.

The map agrees with the machine

No halt in 3·108 iterations of the map

Iterating the fitted map with exact integers from [1, 1, 1]: no list [k, k] in 3·108 iterations (py/map.py far 3e8, a few minutes); the blocks are then numbers of about 1,000 bits. This says the machine does not halt for an astronomically long time if the fitted map is right.

heuristic Evidence only

Growth shape: power/sqrt

Left of the start, the visited part of the tape grows like a power of the step count other than 1/2 (fitted exponent 0.229). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.478).

tools/py/bbtools/triage.py

The map on marker lists

From one marker moment to the next (fitted):

  • [k, m] with m ≥ k+2 → [2k+3, m−k−2] (the marker doubles);
  • [k, k+1] → [1, 2k+3, 1];
  • [k, k] → [2k+3], a block with no marker, which halts;
  • [k, m] with m < k: [k−m, 2m+3] if k−m is odd, [1, k−m−1, 2m+3] if it is even;
  • [k, m, n] with n odd: [2k+3, m−k−2, n] if m ≥ k+2; [1, 2k+n+4] if m ≤ k; [1, 4k+n+10] if m = k+1.
From [1, 1, 1] only these lists occur (the third block is always odd, the first always odd). This is a fit to simulations, not a theorem.

py/map.py

No residue pattern excludes a halt

In the orbit k is always odd and m changes parity at each doubling, so m = k is not excluded by parity; and k − m ≡ 0 occurs at the expected rate modulo each of 3, 4, 5, 7, 8, 9, 12, 16, 24, 32, 48 (3·106 iterations). The chance of an exact hit shrinks as the blocks grow, so a halt looks very unlikely, but that is the usual heuristic for Collatz-like maps, not a proof.

Does it halt from blank tape?

Not known. If the fitted map is right, it is the question whether the orbit of [1, 1, 1] ever meets a list of two equal blocks [k, k]; a Collatz-like question. The map itself still has to be proved (the doubling pass by induction, and the overflow cases).
