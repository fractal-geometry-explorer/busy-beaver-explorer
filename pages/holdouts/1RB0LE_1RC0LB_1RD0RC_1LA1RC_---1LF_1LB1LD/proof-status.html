OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 9 November 2026.

In short

The question is open, and halting looks very unlikely. The tape is a list of blocks (1101)^n separated by single 0s. At each rest (head at the left end in state B) the tape is B>1 P (1101)^A 0 (1101)^b1 0 … with P = 0 or 000, and the list enters only through g = 6 + b1/2 + b2/4 + …. The next rest is A → (3A+g)/2 (with −3 or −6 for type 0), or, when the parity is wrong, a push: A+1 joins the list and A restarts at about (A+g)/4. This map reproduces all 36 rests of the direct run up to 1010 steps and 350 rests started from random configurations; it is built from sweep rules proved in Lean, but the map itself is not proved. Iterated 2·105 times from blank tape, A never comes near the tiny values from which the machine halts.

Sweep rules of the transfer and counting phases

Four rules from one moment the head is at the left end in state B reading 1 to the next, for every value of the counts: the transfer phase (two copies of 1101 leave the block left of the marker 00, three arrive right of it) and the counting phase with the marker next to the counter (the counter gains one while six copies cross the marker; at depth k it is 6·2k; depths 1, 2 and 3 are in lean/Deep.lean, below).

t_one, t_two, u0_one, u0_two, lean/Rules.lean

Counting rules at depth 1, 2 and 3

With one, two or three blocks between the counter and the block holding the marker, one unit of the counter costs 12, 24 or 48 copies of 1101 crossing the marker (8 + 4, 16 + 8, 32 + 16 in the two halves), for every value of the counts and any tape to the right. The mechanism: the block boundaries act as a binary counter, so the head makes 2k trips to the marker per unit at depth k. The rest map itself is still not proved.

u1_one … u3_two, lean/Deep/*.lean (from py/gen_deep.py)

The rest map, checked against the machine

With g = 6 + b1/2 + b2/4 + … (always an integer on the orbit, and A+g always a multiple of 3): type 000 goes to (3A+g)/2 when A+g is even, otherwise pushes A+1 and goes to type 000 with (A+g−5)/4 (A+g = 1 mod 4) or type 0 with (A+g+1)/4; type 0 goes to type 0 with (3A+g−3)/2 (A+g odd) or type 000 with (3A+g−6)/2. From type 0, A = 3, empty list (62 steps) it reproduces all 36 rests of the direct run up to 1010 steps, and the machine run from 350 random rests (A up to 600, lists of up to four blocks) reaches the predicted next rest every time.

py/map.py events 1e10, py/map.py random

Where it halts

Run from every rest with A < 40 and a list of at most two short blocks, the machine halts only from A = 0 with an empty list (type 0 or 000), after 91 steps, by the whole tape collapsing; the other small cases that leave the map involve blocks of length 1, which the orbit never creates once A > 1.

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.542). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.14).

tools/py/bbtools/triage.py

The map iterated far, and the odds of a halt

Iterated 2·105 times from blank tape, A stays at 64 or more from the 10th rest on and has 50,000 bits at the end (66,996 pushes). The size A+g is multiplied by 3/2 at every non-push rest and by about 3/4 at a push (a third of the rests): a random walk in log size with strong upward drift. Reaching size ~10 again from the 2·104 of the rest at 9.8·109 steps has probability of order 10−10; probviously non-halting.

py/map.py iterate 2e5

Does it halt from blank tape?

Not known. A proof would need the rest map for all values in Lean: the counting rule at every depth (an induction over the binary counter on the block boundaries), the marker crossing block boundaries mid-cycle, and the start and end phases. It would also need an argument that A+g never falls back to the handful of tiny configurations that halt, which is a Collatz-type question.
