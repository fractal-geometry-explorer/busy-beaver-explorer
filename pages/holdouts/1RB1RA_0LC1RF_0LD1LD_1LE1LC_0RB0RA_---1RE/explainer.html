A carry that multiplies by four

1RB1RA_0LC1RF_0LD1LD_1LE1LC_0RB0RA_---1RE

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether it halts. Lean proves that the machine is a simple rule on a list of numbers: a carry walks left through the blocks of 1s, turning a block of length v into one of 4v + 3. The machine could only stop if a block of length one were ever skipped by the carry, and in 104000 steps none is.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 0. F is entered only from B1 (writes 1, moves R): B>1 0. So a halt is the moment this pattern appears, with the head on the cell after >.

The shape of the run

Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.557).

After 109 steps the tape spans 61,049 cells (2,469 left of the start, 37,368 right), with a density of 1s of 0.96.

What the machine does

A list of blocks

Stop the machine each time its head is at the right end of the tape in state B. The tape is then a row of blocks of 1s, each separated from the next by a single 0 (a block may be empty: two 0s in a row). Write down the block lengths, and the machine becomes a rule that turns one list of numbers into the next. Here are the first visits:

Lean proves this for every list, not just the ones the run produces: theorem visit says one sweep of the machine does exactly what the rule sweep says, and theorem nonhalt_of_orbit says that if the rule can be applied for ever starting from the list [1], the machine never halts.

One sweep

The rule

Call the last block z. The head walks left from the right end. It passes z if z is even, then passes every odd block, and stops at the first block that would leave it in the wrong state: z itself if z is odd, otherwise the last even block e before z. That block is the target. Then:

  • the block x just left of the target loses one 1 and the target gains 4 (z gains 2 if it is the target);
  • if x is empty (or the target is the first block), x becomes a new block of two 1s instead and the target gains only 1;
  • on the way back z loses 2 (if z is not the target); if z is already empty it disappears and the block before it loses 2.
Emergent behaviour

A carry that multiplies by four

Repeat the rule and a pattern appears. The target is a carry sitting just right of a block x. Each visit it takes one 1 from x and grows by 4, while z pays 2. When x is empty, x becomes a fresh carry of 2, and the old carry, now odd, has length 2 + 4x + 1 = 4x + 3. The new carry then eats the next block to the left. So one pass of the carry moves every block one place to the right and replaces its length v by 4v + 3:

3 → 15 → 63 → 255 → 1023 → 4095 → …

At the far left there is nothing to eat (the blank tape counts as empty blocks), and the carry instead creates a new block of length 3 at each visit. That is why the tape is made of long runs of blocks of lengths 3, 15, 63, …, each run one level up from where it was one pass before. Late in the run, at 107 visits:

2 3×21508 11 15×828 7 34 63×2541 191 255×2097 127 703 1023×194 3071 4095×60 2047 8239 16383×42 …

The fuel for all this is the last block z. When it runs out, the last finished block is poured into a new z (z odd: the block before it loses 1 and z gains 2 at each visit) and a new carry of 2 starts next to it. The fuel grows with the blocks, so the passes go further and further.

Where it could stop

Only at a jump, and only on a block of one

The machine stops only when F reads a 0. In the rule that means one of three shapes: there is no even block for the head to stop at (it then runs into the left end), a block of exactly one 1 lies between the target and z (F meets the 0 after it on the way back), or an empty target follows an empty block.

In the carry's ordinary work none of these can happen: the blocks between the carry and z are all finished blocks 4v + 3, at least 3 long, and the carry itself is even. The only moment the target moves somewhere unexpected is a jump: the fuel runs out while the new carry is still right next to z, z becomes even, and the head now runs left past a stretch of odd blocks to the last even block before them. Up to 101000 steps there are 188 jumps; some pass more than 1019 blocks, and the shortest block any jump passes has length 3.

Blocks of length 1 do exist: they are what is left of a block of 3 when the fuel ran out after the carry had taken two of its 1s, and they always have the (even) carry just to their right, which stops any later jump before it reaches them. A halt would need a jump at the exact moment such a carry is being drained and is odd. That is a coincidence of probability roughly one over the size of the blocks involved, and the blocks grow by a factor of four per pass; so the machine very likely never halts. Proving it needs an invariant of the list rule that captures this structure, which is the open step.

Why it is hard

A halt is an equation between huge numbers

Zoom in on a jump. After a refuel the end of the list looks like … u x 2 z0: a new carry of 2 next to the fuel z0, about to eat the block x. Eating x takes x + 1 visits, and the fuel lasts z0/2 + 1 visits. If the fuel is enough, nothing special happens. If it is not, the carry is stuck next to z when the fuel runs out, it becomes the new fuel, and x is left with a remainder

r = x − z0/2 − 1.

The head then looks for the last even block. If r is odd it skips r, and if r is exactly 1 the machine stops. (Two similar coincidences, r = 0 next to an empty block, or a skipped block of length 1, also stop it.)

So whether the machine halts comes down to whether this equation between three block lengths ever holds exactly. Those lengths have hundreds or thousands of digits and are built from earlier ones by 4v + 3, sums and halvings. In the exact run to 102000 steps there are 358 jumps; the remainder is never smaller than 583 (the very first jump), never below 1/512 of the fuel, and its last binary digits look like those of a random odd number. If the numbers really behave randomly, the chance of ever hitting r = 1 is about the sum of 1/(fuel) over all future jumps: far below one in a googol.

That is why a proof is hard: it would have to show that an equation between huge, unrelated-looking numbers never holds, the same kind of difficulty as the Collatz problem. Lean already reduces the machine to the list rule; what is missing is a way to control those exact values.

Kernel
visit, lean/Macro.lean
The machine is a block-list system (every case)

With the tape at a visit of the right end in B written as the list of its blocks of 1s, sweep is one visit: the last block z is the target if it is odd, otherwise the last even block e before it (the blocks between must all be odd and at least 3); the block x left of the target loses one 1 (or, if x is empty, becomes a new block of two and the target gives back three); the target gains 4 (z gains 2); z loses 2, and an empty z is removed while the block before it loses 2. Theorem visit: for every list on which sweep is defined, the machine goes from that tape to the tape of the result in at least one step. sweep is undefined exactly at the halting shapes (no even block, a block of one 1 crossed on the way back, an empty target after an empty block).

Kernel
nonhalt_of_orbit, lean/Macro.lean
The reduction

Theorem nonhalt_of_orbit: if the orbit of the list [1] (the tape after the first step) under sweep is defined for ever, the machine does not halt from blank tape. So the machine halts if and only if the block-list system reaches one of its halting shapes (the converse direction is the machine's own halting case, not stated in Lean).

py/blocks.py, README
The carry: v becomes 4v + 3

At almost every visit the target is a carry block just left of a run of finished blocks: it eats its left neighbour x one 1 per visit (gaining 4) and, when x is empty, x becomes a fresh carry of 2 and the old one has length 4x + 3. So a pass of the carry shifts each block one place right and maps v to 4v + 3 (3 → 15 → 63 → 255 …), while at the front it creates new blocks of length 3. The fuel is the last block z, which pays 2 per visit; when z runs out, the last finished block is drained into a new z (the odd phase: y loses 1, z gains 2) and a new carry of 2 starts next to it.

Where a halt could still come from

In the carry's ordinary work every block it crosses on the way back is a finished block 4v + 3 ≥ 3, so the halting shapes can only appear at a jump: z runs out while the new carry is still next to it, z becomes even and the next target is the last even block further left, skipping a stretch of odd blocks. A halt needs a block of length 1 in that stretch (or no even block at all). Up to 101000 steps there are 188 jumps (183 skip at least one block); the shortest block any of them skips has length 3.

Where a halt can come from

A closed tape language from windows of 6 cells (7,371 abstract configurations) allows F0 only with the left side reading 1 and then blank: next to the left end. The left end is visited about 2,500 times in 3·108 steps, almost always in E on a 0 before 1^3 0.

Kernel
lean/Rules.lean (from py/rules.py)
The sweep rules

With z the last block, y, x, w before it, at the right end in B: z odd: (y, z) → (y − 1, z + 2); z even ≥ 4, y even: (x, y, z) → (x − 1, y + 4, z − 2); z even ≥ 4, y odd ≥ 3, x even: (w, x, y, z) → (w − 1, x + 4, y + 2, z − 2); for every length and every tape to the left. Proved from symbolic traces (shift rules, rfl, omega).

Computed
python3 py/jumps.py 2000 300
The jump remnant, at every jump up to 102000 steps

At a refuel the list ends … u x 2 z0. If x ≥ z0/2 + 1 the fuel runs out while the new carry is still next to z (a jump), and x keeps the remnant r = x − z0/2 − 1; the machine then halts iff r = 1, or r = 0 and u = 0, or the stretch of odd blocks the head skips contains a 1 or reaches the left end (e.g. [2, 3, 3, 11, 2, 18], r = 1, halts). py/jumps.py records all 358 jumps of the exact run to 102000 steps: the smallest remnant is 583, r is never below 2−9 times the fuel F = z0/2 + 1, r mod 8 is spread like a random odd number, and the sum of 1/r is 0.003.

Heuristic
README
Why a halt looks unlikely

A halt needs an exact coincidence at a jump, such as x = z0/2 + 2 (remnant 1), between block lengths that come from different generations of the carry and show no arithmetic relation (no congruence forbids it, no inequality keeps the remnant large). The heuristic chance is about the sum of 1/F over the future jumps, and the fuel F grows roughly exponentially along the jumps (9 bits at the first, 3,315 bits at the 358th), so the expected number of halts is far below one: the machine very likely never halts.

README, next steps
Does it halt from blank tape?

Not known. A proof needs an invariant of sweep (a set of block lists containing [1], closed under the rule, with no halting shape). Since a halt is an exact equation between block lengths with thousands of digits, such an invariant would have to pin down the values of the large blocks, not just their sizes and parities; this looks as hard as a Collatz-type question. Plain parity-and-size abstractions are too coarse (e.g. [2, 4, 2] → [1, 8, 0] → [10] halts).
