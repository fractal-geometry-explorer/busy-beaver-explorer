What is known about 1RB---_1RC0RD_1RD1RA_1LE1RB_0LF0LE_1RF0RD

1RB---_1RC0RD_1RD1RA_1LE1RB_0LF0LE_1RF0RD

Nobody knows whether this six-state machine halts from blank tape. Its run is a pair of binary counters: one written as a long block of 1s at the right end, whose full count takes about 22·2j steps, and one written in the single 0s that separate the blocks on the left, which receives 2j at each full count. This page lists what has been established, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. The event rule is now proved in Lean for every size: between overflows the run is two binary counters, and the machine cannot halt there. Halting can only happen at an overflow, which follows an explicit map (with a recursive constant C(r)) that agrees with the machine on every event and overflow of a 4·1011-step run and on all 1,950 overflows with at most 9 bits; iterated for 100,000 phases it never reaches the only place where the machine can halt. The overflow map is checked, not proved.

The event rule, for every size

Right after each event the head, in state B, stands at the start of a binary counter written in groups 0 0 d (lowest digit first), here (0 0 0)^d 0 0 1, and left of it the bit string bs in pairs 1 b ending with the pair 0 1: call that P(d, bs). Proved for every d, every bit string and every left context: one count adds 1 to the right counter and 4 to the left string (its two lowest pairs are left alone) whenever neither increment carries out (count); 2d counts add 2d·4 (iter, by induction on d); so P(d, b1 :: lo ++ h) reaches P(d+1, b1 :: lo ++ inc h) whenever lo has d bits and h has a 0, i.e. bs + 2d+1 without carry out of the top bit (event_rule). event_to_P links the README's event bits 0 1^(3d+4) B>0 to P(d+1, bits + 2), and blank_to_P shows the run from blank reaches P(0, 10) at step 69. The step counts are not stated. Every pair of consecutive P configurations of a run to 2·107 steps either follows the rule (22) or is an overflow (6) (py/pchain.py).

count, iter, event_rule, event_to_P, blank_to_P, lean/Count.lean

Halting only at an overflow

Follows from blank_to_P and event_rule (the deduction is not itself a Lean theorem). Because event_rule is a statement that the machine runs (no halt) from one P configuration to the next, the machine can halt only during a phase P(d, bs) in which bs has no 0 at or above bit d+1, that is when adding 2d+1 carries out of the top bit. Non-halting is exactly the statement that every such overflow phase ends in a new P configuration; the overflow map (trusted, below) says which one.

event_rule, lean/Count.lean

An exact accelerated run

py/accel.py follows the run from one P configuration to the next with the proved rules (jumps whose endpoints are proved; the step counts are checked against the direct run, not proved) and simulates only the overflows cell by cell (c/transient.c). The steps of a count are 30 + 6t + 8r (t, r the two carry lengths, from the step counts of the lemmas), summed over a phase in closed form; the result equals the step of every P configuration of a direct run to 2·107 steps (py/pchain.py). It reproduces the overflows of the direct run, the seventh ending at P(24, …) at step 1,857,557,588 after 3.7·108 simulated steps; the simulated stretch of an overflow grows quickly with the number of digits the machine eats, so this does not replace the map for long runs.

py/accel.py, c/transient.c

The overflow map

When adding 2j carries out of the top bit, let R = X + 2j − 2M. If R is even the next event has X = R + 1, M + 1, N + 3. If R is odd, let k be the number of trailing pairs of bits whose low bit is 1 and r = R mod 4k: the next event has X = C(r) + ⌊R / 4k⌋, M + 3k + 1 bits and N − 3(2k − 1), where C(01) = 43, C(11) = 104 and C(r) = C(⌊r/4⌋) + ct·8k−1 with t the number of trailing 11 pairs, c0 = 42, ct = 248·4t−1 − 21 (2ck−1 + 21 when all k pairs are 11). Checked against the machine on all 1,950 overflows with at most 9 bits (whose odd pairs stop below the top bit), on all 126 patterns r with k ≤ 6 and 12 random ones with k = 7, 8, and on the 9 overflows of the run to 4·1011 steps.

py/macro.py (checkO, checkC, check)

Where it can halt

In every case run with at most 9 bits, the machine halts only when the bit string is all ones and j = M (9 cases); the other 67 overflows whose odd pairs reach the top bit do not halt. The map covers everything else.

py/macro.py 0 checkO 9

heuristic Evidence only

100,000 phases of the map

Iterated from the first event, the map runs 100,000 phases (each phase a run of additions ended by an overflow) without its odd pairs ever reaching the top bit: M grows to 508,578, which is about 10153,000 steps of the machine. The number k of odd pairs at an overflow is 1 in 35% of phases, 2 in 15%, then roughly halves, with a long tail (largest 92). A halt needs k ≥ M/2.

py/macro.py 100000

Blockers pile up

Computed with the trusted overflow map: at an overflow the top M − j0 bits of the remainder R are all 1 (2,998 of the first 3,000 overflows). A pair of R whose low bit is 0 is a blocker; a halt needs a string without blockers. In 20,000 overflows the number of blockers grows about linearly (639 at overflow 2,000, 3,302 at 10,000, 5,901 at 18,000). Evidence against a halt, not a proof.

py/macro.py (the function phases), py/blockers.py 20000

open Open

A proof

The event rule is proved for all sizes (kernel). Still open: the overflow map for all sizes (at an overflow the left string is reset and the right counter ends up one cell out of phase; the machine then eats the counter's low digits in pairs, which is where C(r) comes from), and an argument that the iterated map never fills a string with odd pairs. The map looks like a random process on growing strings, so an invariant that excludes the halting case is not in sight.
