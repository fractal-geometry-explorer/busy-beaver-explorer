What is known about 1RB0LC_0LA1RD_1LA0RE_1RE0RF_1LF---_1LB1RF

1RB0LC_0LA1RD_1LA0RE_1RE0RF_1LF---_1LB1RF

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. The head sweeps across the whole tape, adding a cell at each end per sweep, and the tape between holds runs of 1s and short 0-runs with no visible regular words. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. Lean proves the exact way a halt would happen (B reading 1 0 1) and that the other way in is harmless; the C simulator finds no halt in the first 1011 steps, and in the first 1010 steps the dangerous transition D0 only fires at the left end of the tape, always with a 0 after it. Why the left end never reads 1 0 1 is not known.

The halting configurations

The machine stops exactly when it reads the symbol of a halting transition (E1); the generated statement covers every configuration.

step_none_iff, lean/Blank.lean

Where a halt can come from

If the machine halts on its third step from a configuration, that configuration is one of: B with 1 under the head, 0 right, 1 two right. So a run can reach a halt only through one of these patterns, and a proof that the machine never halts only has to rule them out. The proof splits on the state and the five cells around the head.

halt_route, lean/Route.lean (written by py/route.py)

How a halt comes about

E reading 1 is the only halt. E is entered from C reading 1 and D reading 0 (enter_E); the first is harmless (via_C_safe); D is entered only from B reading 1 (enter_D). So a halt is exactly B>1 0 1 (halt_B), three steps before the end.

halt_E, halt_D, halt_B, enter_E, enter_D, lean/Halt.lean

The way in through C is harmless

C is entered only from A reading 1, moving left; A has just written 0 on the cell to C's right, so when C reads 1 and moves right, E reads that 0 and goes on. For every surrounding tape.

enter_C, via_C_safe, lean/Halt.lean

Shift rules

For every n and every surrounding tape: F crosses 1^n and (1 0)^n to the right; moving left, A shifts (1 0)^n, C shifts (0 1)^n and B shifts (0 1 1)^n one cell.

fright, fright10, aleft, cleft, bleft, lean/Rules.lean

No halt in the first 1011 steps

The C simulator (tools/c/tm.h) runs 1011 steps from blank tape without a halt; the visited tape then spans 378,448 cells, 251,493 of them 1.

c/longrun.c

The danger is only at the left end

In the first 1010 steps A reads 0 only on a fresh cell at the left end (28,462 times) and D reads 0 only two cells later (17,077 times). At those moments the three cells to the right of A are always 1 0 0 (then D reads 0 0) or 0 1 1 (then B turns back), never the halting 1 0 1.

c/evt.c

Regular-language deciders tried (F11)

None of these closes: each reaches a halting configuration in its abstraction, which says nothing about whether the machine halts. n-gram CPS (tools/c/ngramcps.c), equal widths on both sides: a halting local configuration is reached with plain up to width 15, history 1 up to width 15, history 2 up to width 14, history 3 up to width 14, LRU history up to width 10 (larger widths ran out of the 150 s or 60 million configuration budget). n-gram CPS with every cell tagged by its position mod p: fails for p = 2 up to width 12, p = 3 up to width 12, p = 4 up to width 12, p = 6 up to width 12. n-gram CPS where each side also carries the state of a small automaton that has read that side from the far end (every automaton with up to 3 states on both sides, or 4 states on one side), with position mod 1..4 and widths 4, 6, 8: no closed set without a halt in all 120 parameter sets. Run-length windows (the K nearest runs of equal macro cells on each side, run lengths kept exactly below T and mod M above): fails for all 72 parameter sets (cells of 1 to 4 bits, K = 2, 4, 6, T = 2, 4, M = 1, 2, 4). Two-automaton closed tape language by SAT (a deterministic automaton reading each side inward, n states each, CaDiCaL): no solution for n = 2..8; n = 9 not finished in 150 s.

sweeps of 13 November 2026 (family F11); the tagged and run-length deciders are not in the repository yet

heuristic Evidence only

No regular words

Compressed at the sweep ends, the tape shows runs of 1s of length 1 to 13 separated by 0-runs of length 1 or 2, and short repeats such as (0 1)^k and (0 1 1)^k, but no word that repeats across the tape and no counter.

tools/c/tmrun.c records

Growth shape

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.501). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.5).

Does it halt from blank tape?

Not known. A proof would have to show that the left end of the tape, at the moments A reaches a fresh cell there, never starts with 1 0 1; the cells there are rewritten by every sweep and no invariant for them is known. Window CTL up to 7 cells and n-gram CPS (widths up to 9, see the README for the larger runs) fail.
