What is known about 1RB0LD_1LC0RA_1RA1LB_1LA1LE_1RF0LC_---0RE

1RB0LD_1LC0RA_1RA1LB_1LA1LE_1RF0LC_---0RE

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

Open, and probably never halting. Every so often the tape is P(n) = (10)^n A> 0. Lean (kernel) proves a computable macro step from P(n) to P(n′) or to a halt, for every n, from 21 symbolic rules. Its value follows a closed form (checked, not proved, for every n ≤ 200,000): with hk = 5·2k − k − 6 (3, 12, 31, 70, 149, …) and hk < n < hk+1, P(n) goes to P(3n − 10·2k + 3k + 14), and P(hk) halts. So the machine halts if and only if the orbit of 4 ever lands exactly on some hk. Lean checks that it does not for 200 map steps by the kernel (1086 machine steps) and 2,000 by native_decide (10798); Python follows it for 105 map steps. A target is hit by chance about once in 2k tries while k grows by about two thirds of a bit per step, so the chance of a halt later on is about 10−20,000.

The macro step from P(n), for every n

With P(n) = 0^inf (10)^n A> 0^inf, the function pstep n returns either P(n′) with an exact step count, or a halt, and pstep_sound proves for every n that the machine does exactly that. Inside: the head sweeps left turning the tape into 2n+2 ones (T phase); a doubling counter c = 1, 6, 16, 36, … eats 2c+6 ones per round through a zigzag (zig_iter, induction) and becomes 2c+4 (t_round); when fewer than 2c+6 ones are left the remainder decides: 0 or 1 left halts, otherwise a final sweep (x_iter) writes the new (10)^n′. The step counts are closed polynomials (no recursion), so pstep can be evaluated.

pstep_sound, tend_sound, tphase_sound, lean/Macro.lean; rules in lean/Rules.lean (from py/rules.py)

The closed form of the macro step

For hk < n < hk+1 with r = n − hk − 1: n′ = 5·2k − 1 + 3r in 12r² + (40·2k+6)r + (100·4k+23)/3 − 10·2k steps; P(hk) halts. A Python transcription of the Lean pstep agrees with this for every 1 ≤ n ≤ 200,000 (the closed form itself is not proved in Lean). Direct simulation agrees too: all 16 P-events of the run from blank tape up to 1010 steps (n = 4, 9, 24, 52, 99, 163, 198, 303, 618, 1246, 2493, 4957, 9792, 19180, 37107, 70411; the last at step 9,108,900,940) match in n and step.

py/macro.py check 200000, py/macro.py orbit 1e10, c/pevents.c

105 macro steps without a halt

Python iterates the closed form (exact big integers) for 105 macro steps from P(4) without landing on an hk; n then has 66,605 bits and the step count is about 1040,100.

heuristic Evidence only

Probviously non-halting

At level k, n′ ranges over about 5·2k values in steps of 3, and on average 2/3 of a target hj per level lies among them; treating r as random, the chance of a halt is about 2−k per macro step. The level grows by about 0.66 per macro step (n multiplies by about 1.58), so the sum converges: from the end of the 105 checked steps (k about 66,605) the chance that it ever halts is about 10−20,000. The machine is a cousin of the “Cryptids”: its halting is a question about the digits of an orbit, which no known method decides.

open Open

Does it halt from blank tape?

Not known. It halts if and only if the orbit of 4 under the map reaches some hk (given the closed form; with only the Lean macro step: if and only if pstep ever returns a halt along the orbit).
