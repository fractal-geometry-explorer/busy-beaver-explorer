1RB0LE_1RC0LD_1RD1RA_1RE0RB_0LA0RF_1LE---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 9 November 2026.

In short

The question is open. This is the counter of 1RB0LC_1RC1RE_1RD0RA_0LE0RF_1RA0LD_1LD--- with its states renamed (A→B, B→C, C→D, D→E, E→A), started in a different state. Lean proves every ordinary sweep, every left-end sweep except the start of a nested run, and that the inner sweeps of a nested run follow the same digit rule; it runs 258,046 proved sweeps: no halt in the first 266,357,150,814 steps, where the third nested run starts. The cell simulator reaches 3·1011 steps, inside that nested run.

No halt in the first 10,000 steps

The list simulator of the shared library, proved to agree with the machine's semantics, runs 10,000 steps from blank tape without a halt, evaluated by Lean's kernel.

blank_runs_kernel, lean/Blank.lean

One sweep, for every digit list

Read a block 0 1^(3d+2) as the digit d. From the right end the head passes every odd digit, stops at the first even digit b (with the digit a on its left) and returns: a 0 (2k+1)… becomes (a+2) 0^(2k) 1… and a b (2k+1)… (b = 2i+2) becomes (a+1) 0^(b−1) 1 0^(2k) 1…, in 21 + 10b + Σ(20k+16) steps, for all values and any tape left of a.

sweep_zero, sweep_even, cost_sum, lean/Sweep.lean

Sweeps at the left end

A stop at the first digit grows the leftmost block 1^r by 6 (digit 0) or 3 (digit 2i+2); a carry through all digits at r = 3 adds two leading zeros and three cells on the left; at r = 6j+9 the leftmost block becomes 1^3 and 2j+3 zeros. The other phase of the right end (0 1^4 C>0) turns the last digit 1 into 2 0.

raw_zero, raw_even, lean/Sweep.lean; carry3_sweep, carry9_sweep, phase2_sweep, lean/Carry.lean

From blank tape to sweep 29

After 5,512 steps (after two nested runs, checked step by step) the tape is 1^3, the digits 0 0 1 1 1 0 2 and ten digits 1, and the right end in its other phase 0 1^4 C>0.

reach_D0, lean/Reach.lean

Inside a nested run: the same counter

A carry through odd digits, the first one 1, into 1^(6j+6) turns the block into 1^3 and 2j+1 digits 0 and turns the head back before the right end (nest_sweep). From there the inner sweeps change the digits by exactly the outer rule (core_zero, core_even, with any tape right of the pass), their right end alternates between two phases, and every second sweep eats one passed digit 1 (inner_X_zero, inner_X_even, inner_Y_zero, inner_Y_even).

lean/Inner.lean, lean/InnerRules.lean

nextR does one sweep on digits coded as runs ((d, c): c copies of d, from the right end), covering the same cases as next; whenever it answers, the machine makes that sweep in that many steps.

The rest of a nested run

Passed digits 3, 5, … are eaten in another phase pattern; the inner counter has its own left-end events, including nested runs inside the nested run; the run ends with the right end in its other phase when the passed region is used up. Seen in simulation (on both machines), not formalized. In this run nested runs come at sweeps 5, 28 and 258,075.

Where a halt would come from

Following the table backwards, the machine halts exactly when C reads a 0 followed by 0 1 1 (a right-moving head meeting 0 0 1 1). No proved sweep produces it; a halt would have to come from a nested run.

Does it halt from blank tape?

Not known. Closing it needs the whole nested run as a theorem (shared with the other machine), so that the sweep program is total, and an argument that nested runs always end in a sweep configuration. The third nested run, about 3·1011 steps long, is beyond a cell-by-cell native_decide check.
