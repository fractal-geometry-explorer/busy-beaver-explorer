What is known about 1RB1LF_1LC0RD_---1LA_0LA0RE_1LA1RA_1LB0LD

1RB1LF_1LC0RD_---1LA_0LA0RE_1LA1RA_1LB0LD

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 13 November 2026.

In short

The question is open, and reduced to an orbit. The run is a sequence of rounds; a round takes D> 0 0 111 0 1^n T to D> 0 0 111 0 1^n' T' with n' = 4⌊(n−1)/3⌋ + d, where (d, T') is computed from the tail T and (n−1) mod 3 alone. Lean proves this round map for every tail on which its simulator answers, and that, as long as it answers along the orbit, the machine halts from blank tape exactly when the orbit reaches a halting round. The map has been iterated for 2·106 rounds without a halt (and it always answered). A random-model estimate puts the chance of a halt near 10-15 per round: halting is expected eventually but only after an astronomically long run.

The sweeps

From A> 0 11 0 11 0 111 (0111)^k 0 1^(m+4) T at the left end, one sweep (10k + 45 steps) takes three ones from the block and adds a counting block 1110: (0111)^(k+1) 0 1^(m+1); by induction any number of sweeps.

Some round starts halt

The round start with 57 ones and the tail 0110101010 11 (blocks of ones 2, 1, 1, 1, 2) halts within 2,575 steps. So the halting transition is reachable from the round shape; the question is whether the orbit from blank tape gets such a tail.

halting_round, lean/Round.lean

The round map for every tail

After the sweeps the tape is 0 11 0 11 0 111 (0111)^t 0 1^c T. A simulator keeps one copy of 0111 on each side, works cell by cell in the two ends, and crosses the t − 2 copies between only whole, by six shift rules; it never looks at t. Lean proves that whatever it answers is what the machine does: if roundMap (n, T) = (n', T') the machine goes from the round start (n, T) to the round start (n', T'), with n' = 4(t − 2) + N and (N, T') depending only on T and c; if it answers halt the machine halts in that round. For all n ≥ 7 and every word T. The simulator may also answer stuck (a meeting with the block that the six rules do not cover, or out of fuel); that has not been seen for any tail.

round_next, round_halt, lean/Reduction.lean; arun_sound, arun_halt, lean/Zone.lean

Reduction to the orbit

Let orbit be the orbit of the round map from (11, empty tail), the second round start of the run. If the map never answers stuck along the orbit, the machine halts from blank tape if and only if the orbit reaches a halting round. Without any hypothesis: a halting round in the orbit gives a halt, and an orbit that goes on for ever gives a run that never halts.

Orbit: 2·106 rounds, no halt, never stuck

Iterating the round map from (11, empty tail) for 2·106 rounds (n then has 249,880 decimal digits) never reaches a halting tail and the simulator always answers; only 26 tails occur (the empty tail and 011 in 78% of the rounds, each deeper level about three times rarer), the longest with five blocks of ones (2, 1, 2, 1, 3). The nearest halting tail, blocks 2, 1, 1, 1, 2, is 36 rounds from the empty tail, 29 of them pushes.

Rounds between end events, by remainder class

Sample the run whenever the head is in state A reading 0 with only 0s to its right. Read leftwards from the head, the tape is then A U^m B: one long periodic block between two short context words. For each class (A, U, B, m mod 3) the next sample is simulated for six values of m and extended as an affine map of m (with a cubic step count). Along the direct run from blank tape to 3·109 steps (31 events) the class map predicts the next event in all 20 rounds it applies to. This is an extrapolation checked by computation, not a proof.

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.501). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.079).

tools/py/bbtools/triage.py

Random model: halts eventually, but astronomically late

If c is uniform and independent from round to round (it is, empirically, for each tail), the tail is a recurrent Markov chain that returns to empty with probability 1, and the chance that an excursion hits a halting tail is between about 10-18 (one shortest path) and 10-13 (no halting mass found with paths pruned below 10-13). So the model halts with probability 1, after some 1013–1018 rounds; since n grows by 4/3 per round and a round takes about n2/3 steps, that is far beyond any simulation.

py/roundmap.py

200 rounds of the class map without a halt

Iterated with exact integers from the event at step 70,452 of the run (A = 01001, U = 0110, m = 77, B = 0101): 200 rounds without meeting a halting class; m then has 75 bits (about 1046 steps of the machine). 9 distinct contexts occur, the longest of 13 cells. The iteration stops there, at a context too large for the six simulations (a second long block has formed); this is a limit of the tool, not an event of the machine.

Does it halt from blank tape?

Not known. By the reduction it halts iff the orbit of the round map reaches a halting (tail, c) pair (given that the map keeps answering, as it has for 2·106 rounds): a question about the base-3 digits of a number multiplied by about 4/3 each round, like other Collatz-like cryptids.
