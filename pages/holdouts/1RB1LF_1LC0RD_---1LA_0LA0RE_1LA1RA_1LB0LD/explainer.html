Does this machine ever halt?

1RB1LF_1LC0RD_---1LA_0LA0RE_1LA1RA_1LB0LD

Nobody knows. Started on a blank tape, this machine runs in rounds: a block of ones is eaten three at a time and comes back 4/3 as long, while a short tail at the right end acts as a tiny stack driven by the block's length mod 3. Some tail shapes halt; the run has not produced one in 106 rounds.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in C reading 0. C is entered only from B0 (writes 1, moves L): 0 B>0. So a halt is the moment this pattern appears, with the head on the cell after >.

What it does

Rounds, sweeps and a tail

At the start of every round the whole tape is D> 0 0 111 0 1n T: the head at the left end in state D, a long block of n ones, and a short tail T on the right. During the round the head sweeps back and forth across the tape. Each sweep runs right to the block of ones, takes three ones from it and comes back, leaving one more counting block 1110 on the left; the tape grows by one cell on the left every sweep. That is why the left side grows like the square root of the step count.

When only 1, 2 or 3 ones are left (n = c + 1 + 3t, c ∈ {0, 1, 2}), the end of the round turns each of the t counting blocks (4 cells) back into four ones, works a little on the tail, and the next round starts with n' = 4t + d ones. The tape reaches one cell further to the right only at these ends, once per round, and rounds come exponentially further apart: the right side grows like the logarithm.

Lean

The round map, for every tail at once

The end of a round looks different for every tail, and there are infinitely many tails. What they share: after the sweeps the tape is 0 11 0 11 0 111 (0111)t 0 1c T, and the head only ever crosses the long run of counting blocks whole, in one of six ways (for example in state A, left to right, turning every 0111 into 1001). So the round end can be computed by a small simulator that keeps one counting block on each side, steps cell by cell at the two ends, and jumps over the t − 2 blocks between by a shift rule. It never looks at t.

Lean proves that whatever this simulator answers is what the machine does, for every t (lean/Zone.lean, generic; lean/Reduction.lean, this machine). The result is a computable round map roundMap (n, T) = (4(t − 2) + N, T'), halt, or stuck (no answer), and the theorem halts_iff: if the map never answers stuck along the orbit of (11, empty tail), the machine halts from blank tape exactly when that orbit reaches a halting round. The kernel checks the first 500 rounds; the same simulator in Python has run 2·106 rounds and agrees with plain simulation on about 7,900 (tail, c) cases.

What is still missing for a statement with no hypothesis is a proof that the simulator never gets stuck, i.e. a description of all reachable tails.

Halting

Where a halt could come from

The sweeps and the common round ends never halt. The tail behaves like a small stack: a round with c = 1 (probability about 1/3) pushes it one shape deeper, other rounds keep it or pop it back toward empty. Some deep shapes make the end of the round run into the halting transition (C reading 0): the shortest one found, with blocks of ones 2, 1, 1, 1, 2, needs 36 rounds in a row of the right kind (29 pushes). Lean checks that such a round start really halts.

In 106 rounds from blank tape the deepest tail had five blocks of ones; tails come up about three times less often for each step of depth. If the residues c behave like dice, a halt is certain eventually, but only after about 1013 to 1018 rounds, when n has more than 1012 digits. Deciding it means understanding the base-3 digits of an orbit of n → 4⌊(n−1)/3⌋ + d, which is out of reach, as for Antihydra.

Remainder classes

Does any remainder class halt?

A generic test used on the whole family: sample the run whenever the head is in state A reading 0 with only 0s to its right. Read leftwards from the head, the tape is then A Um B, one long periodic block between two short context words A and B. The round to the next sample is computed class by class: for a class (A, U, B, m mod 3) six values of m are simulated, and when they agree the round is taken to be an affine map of m. Against the direct run to 3·109 steps the class map is right in all 20 rounds it applies to. It is an observed law, not a proved one.

The orbit. Iterated with exact integers from the event at step 70,452 of the run (A = 01001, U = 0110, m = 77, B = 0101): 200 rounds without meeting a halting class; m then has 75 bits (about 1046 steps of the machine). 9 distinct contexts occur, the longest of 13 cells. The iteration stops there, at a context too large for the six simulations (a second long block has formed); this is a limit of the tool, not an event of the machine.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.501). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.079).

After 109 steps the tape spans 39,843 cells (29,237 left of the start, 55 right), with a density of 1s of 0.751.

Kernel
round_next, round_halt, lean/Reduction.lean; arun_sound, arun_halt, lean/Zone.lean
The round map for every tail

After the sweeps the tape is 0 11 0 11 0 111 (0111)^t 0 1^c T. A simulator keeps one copy of 0111 on each side, works cell by cell in the two ends, and crosses the t − 2 copies between only whole, by six shift rules; it never looks at t. Lean proves that whatever it answers is what the machine does: if roundMap (n, T) = (n', T') the machine goes from the round start (n, T) to the round start (n', T'), with n' = 4(t − 2) + N and (N, T') depending only on T and c; if it answers halt the machine halts in that round. For all n ≥ 7 and every word T. The simulator may also answer stuck (a meeting with the block that the six rules do not cover, or out of fuel); that has not been seen for any tail.

Kernel
halts_iff, halts_of_orbit, not_halts_of_orbit, lean/Reduction.lean
Reduction to the orbit

Let orbit be the orbit of the round map from (11, empty tail), the second round start of the run. If the map never answers stuck along the orbit, the machine halts from blank tape if and only if the orbit reaches a halting round. Without any hypothesis: a halting round in the orbit gives a halt, and an orbit that goes on for ever gives a run that never halts.

Heuristic
py/roundmap.py
Random model: halts eventually, but astronomically late

If c is uniform and independent from round to round (it is, empirically, for each tail), the tail is a recurrent Markov chain that returns to empty with probability 1, and the chance that an excursion hits a halting tail is between about 10-18 (one shortest path) and 10-13 (no halting mass found with paths pruned below 10-13). So the model halts with probability 1, after some 1013–1018 rounds; since n grows by 4/3 per round and a round takes about n2/3 steps, that is far beyond any simulation.

Open
Does it halt from blank tape?

Not known. By the reduction it halts iff the orbit of the round map reaches a halting (tail, c) pair (given that the map keeps answering, as it has for 2·106 rounds): a question about the base-3 digits of a number multiplied by about 4/3 each round, like other Collatz-like cryptids.
