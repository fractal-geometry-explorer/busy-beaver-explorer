Does this machine ever halt?

Nobody knows. Started on a blank tape, this machine runs a binary counter: every overflow takes twice as long as the last. This page runs the real machine in your browser, describes the counter, and lists what is known.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 0. F is entered only from E1 (writes 1, moves R): E>1 0. So a halt is the moment this pattern appears, with the head on the cell after >.

The run at a glance

Space-time diagram and records

The diagram stacks the tape at many moments. Sampling at each new cell shows the shape of the run as the visited region grows; sampling evenly in time shows where the head spends its time. The records list every step at which the head reaches a cell no earlier step reached, with the side, the width so far and the whole tape: the first place to look for a repeating macro structure.

What it does

A counter in pairs of cells

Stop the simulator at a random moment after a few million steps and look at the cells left of the head. They read as pairs, 00 and 11: the digits of a binary number. The head runs left over the digits, flipping 11s to 00s until it finds a 00 to turn into 11, then comes back. That is adding one in binary, and the lengths of the head's leftward trips, 2, 4, 2, 6, 2, 4, 2, 8, … cells, are the carry pattern of a counter.

When every digit is 11 the carry runs to the left end and the counter overflows: the solid block at the left end grows by two cells, D>0 0 1^(2n+1) becomes D>0 0 1^(2n+3), and the next overflow takes twice as long. Measured: 58,949,630 steps between two overflows, then 117,899,246, then 235,798,526.

Macro structure

A marker and epochs

Each overflow also moves a small block, 1^3, 1^5 or 1^7, one 10 further right through a long run 1 0 1 0 1 0 … on the right part of the tape. When it reaches the end of that run the tape is rewritten and the left block falls back to a single 1: a new epoch starts. After six short early epochs (restarts at steps 5, 54, 233, 846, 3,829 and 17,354), one epoch ends at step 22,706,655 (left block 1^41), the next at step 81,579,964 (1^39); the one after that has reached 1^45 by step 1.5·1010, and at the present rate its 20 or so remaining overflows will take far more steps than anyone can simulate.

So the tape grows only logarithmically in time, which is why the run looks stuck at a small width: about 180 cells after 109 steps.

The holdout 1RB1LE_1RC0RD_1LD0RE_0LA0LC_1LC1RF_---0RA has the same table with the states renamed, and a different start state; its run follows this one 77 steps ahead, with a slightly different right end of the tape.

The halting question

What a halt would need

The only halting transition is F reading a 0. F is entered only from E reading a 1 and stepping right, so the machine halts when E reads a 1 whose right neighbour is 0. In the first 108 steps F is entered 9,523,781 times, always onto a 1: the counter's digits and the marker track never offer E that pattern. Showing that they never will is the open part; it needs an exact description of how one epoch hands over to the next.

First look

The shape of the run

Left of the start, the visited part of the tape grows like a power of the step count other than 1/2 (fitted exponent 0.152). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

After 109 steps the tape spans 183 cells (158 left of the start, 22 right), with a density of 1s of 0.59.

Computed
tools/c/tmrun.c (at D L)
Overflows double

Each time the head is at the left end in state D the tape starts D>0 0 1^(2n+1) 0, and n goes up by one from one such time to the next within an epoch. The gaps between them double: for example 58,949,630, then 117,899,246, then 235,798,526 steps.

Computed
py/digits.py, tools/c/tmrun.c
Epochs, as digit strings

At every overflow (D at the left end) the tape after D>0 0 is a string of odd blocks 1^(2d+1) separated by single 0s; read it as digits d. The first digit goes up by one per overflow and falls back to 0 at an epoch restart, which happens at steps 5, 54, 233, 846, 3,829, 17,354, 22,706,655 and 81,579,964 in the first 108 steps (first digit before the restart 0, 2, 3, 5, 7, 8, 20, 19). Within the epoch that starts at 17,354 the rest of the string is a field of 0 digits with a marker digit that alternates 2, 1, 2, 1, … and moves right 3 places per 2 overflows; the epoch ends when the marker reaches the digits 1 0 0 1 at the right end (… 2 3). The restart rewrites the whole string, e.g. at step 22,706,655 to 0 1 0 2 0 2 0 6 0 3 0…0 1 0 0 1, and at 81,579,964 to 0 1 12 1 0…: the left part of the string is itself a slowly changing higher-level counter, so the epoch-to-epoch map does not keep one fixed shape with growing parameters.

Heuristic
head reversals after step 1.2·108
A binary counter

Between overflows, the cells left of the head read as pairs 00 and 11, and the leftward excursions of the head have the lengths of a ruler sequence (2, 4, 2, 6, 2, 4, 2, 8, … in steps of 2 cells), the pattern of carries in a binary counter.

Kernel
cases, lean/Cases.lean; the runs in lean/Pieces.lean; generated by py/frames.py lean with tools/py/bbtools/listframe.py; library tools/lean/TM/ListFrame.lean
A run-length frame map, every case proved

At every head turn write the tape as two lists of runs (blocks of equal cells), left and right of the head: a frame with list parameters. A table of 69 cases, each a pattern on the first few runs of both sides (lengths exact or at least 4, the rest of each side any list), sends each frame to the frame of the next head turn; every case is proved for all values of its parameters and all lists by one symbolic run (RLCase.sound), so the frame map next = rlNext cases is sound (rlNext_sound). Between two head turns this machine crosses only a few run boundaries, which is why a finite table covers a tape whose number of runs grows without bound.

The frame map from blank tape

The run from blank tape reaches the first frame (init_f0, kernel), and the frame map is defined for its first 1,000,000 frames (native_decide). If it is defined forever along this orbit, the machine never halts (no_halt_of_total).

Heuristic
py/shapes.py
No finite frame map with scalar parameters

The frame-map method (stop at head turns, match the tape against finitely many templates with block-length parameters, fit affine cases) needs the tapes at head turns to fall into a bounded number of shapes. Here they do not: tokenizing the tape at every 7th head turn into maximal powers of words of length at most 4, the first 107 steps give 454,843 distinct shapes (exponents of 3 and more merged), 409,534 of them new in the last decade, and up to 36 tokens per tape; the number grows tenfold per decade of steps. For comparison the same count saturates at 32 shapes of at most 5 tokens for 1RB1LC_1LC1RD_1LA0LB_0RB1RE_1RF0RA_---0RC and at 89 for 1RB1RF_1LC1LF_0RE1LD_0LB1LD_---1RC_1RA0RD, where frame maps were proved. The cause is the counter itself: its digits form an arbitrary word, and the word of higher digits on the right grows too, so a frame needs a list parameter; the run-length frames above are such frames.
