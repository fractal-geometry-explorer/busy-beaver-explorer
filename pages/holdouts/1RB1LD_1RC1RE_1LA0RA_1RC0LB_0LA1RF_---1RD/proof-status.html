What is known about 1RB1LD_1RC1RE_1LA0RA_1RC0LB_0LA1RF_---1RD

1RB1LD_1RC1RE_1LA0RA_1RC0LB_0LA1RF_---1RD

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open, and the run is now an explicit map. Read in cell pairs, the tape is a bit string. The run is a base-4 countdown on its blocks 010: separators pass borrows along like the digits of a counter, and the block grown at the near end becomes the new timer at each overflow. Nine rules, the ticks and two overflows, are proved in Lean. The map reproduces every tick boundary of the first 6·109 steps exactly, and runs on to 1.0·1019 steps without a halting event. Halting could only come from the far end once its last block wears away. The machine writes exactly the same tape as 1RB1LD_1RC1RF_1LA1RD_1RE0LB_---0RA_0LA1RC for at least 109 steps.

The ticks

From 0^∞ 1110 (111110)^(n+1) 1 A> (101110)^x SEP …, one tick reaches the same form with n+2, and the separator after the first block (the timer) moves one step along r = 10 → q = 1110 → p = 101011 → s = 11 → r: r → q costs the next block one, q → p costs the timer one, p → s changes nothing, s → r costs the timer one, gives the next block one and passes a borrow on. Also the wall cycle: with a timer of one followed by s, three ticks take two from the next block and pass no borrow. Every n, every block length, every tape to the right.

tick_r, tick_q, tick_p, tick_s, tick_w, tick_q2, tick_p1, lean/Rules.lean

Overflow, for two and three blocks

When every separator is s and the far end reads 1111, the borrow runs to the far end. From one tick boundary to the next, the list (n+1; x1, …, xk) becomes (6; n+2, x1−1, x2−1, x3, …) with separators r, q, r, … and far end 10101111: the grown w-block is the new timer. Proved for k = 2 and k = 3, for all n and block lengths.

An exact map reproduces the run

Read the tape right of the head in cell pairs 1b → b. The run is then a map on (n, word): the ticks above as rewrites of the bits, the other phase of a tick (01 W moves as W), the wall, and events (a borrow at the far end, a timer running out), which are computed by running the machine on a copy with every block cut to 40 copies and lifted back. Each event is computed with two cuts, which must agree. In the first 6·109 steps the map reproduces all 22,198 tick boundaries of the machine exactly: n, the word and the step count. 53 of these moves are events.

holdouts/1RB1LD_1RC1RE_1LA0RA_1RC0LB_0LA1RF_---1RD/py/macro.py, py/check_macro.py, c/rword.c

Same tape as its twin

This machine and 1RB1LD_1RC1RF_1LA1RD_1RE0LB_---0RA_0LA1RC write the same symbol at the same cell and move the same way at every one of the first 109 steps. Where one is in C, the other is in C or E, depending on the symbol under the head. They stay twins as long as three local patterns hold: after B reads 0 the next cell is 0, after D reads 0 it is 1, and after E reads 1 it is 1.

The map runs on to 1.0·1019 steps

From the first tick boundary, the map runs 627,024,786 ticks to step 10,230,187,408,184,952,134 with 205 events. Both cuts agree at every event, and no cut copy halts. The first 400 moves by the other phase and by the wall were also compared with the machine. The run meets 89 overflows; the largest new timers are 4,194,301 (at 1.1·1015), 33,628,307 (at 2.2·1016), 129,459,917 (at 3.3·1017), 416,954,747 (at 3.5·1018). At the end the list is 1, 222,014,566, 1, 612,354, 493, 644, 9,920, 1,002.

The overflow formulas

Every overflow the map meets follows one of two formulas: 74 times F1 (all separators s, far end 11: (n; x1, …) → (6; n+1, x1−1, x2−1, x3, …)) and 15 times F2 (the timer runs out at a q: (n; 1, x1, …) → (6; n, x1+1, x2−1, …)).

heuristic Evidence only

Growth shape: fixed/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.514). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

tools/py/bbtools/triage.py

The far end cannot halt while the last block lasts

A borrow arriving at the far end halts the machine when the far end reads 01, 101, 1101 and a few similar words. The 102 far ends seen in 6·109 steps close under borrow arrivals into 128 far ends, none of which halts. All of them fall into the cycle 11 → overflow → 0011 → 11, where the last block loses one per overflow. This assumes that a far end behaves the same behind any block of 10 or more copies.

holdouts/1RB1LD_1RC1RE_1LA0RA_1RC0LB_0LA1RF_---1RD/py/farend.py

Why it is hard

Block i, counted from the timer, loses about 2·4-(i+1) per tick, so the far end is reached exponentially rarely, and the last block (1,002 at the end of the long run) wears down by one per overflow. Halting is only possible at an event, once the far end has changed shape.

open Open

Does it halt from blank tape?

Not known. The open part is what the list looks like once its last blocks have worn away, and whether a far end like …01 can then appear.
