Does this machine ever halt?

1RB0LF_1LC0LD_1RD1LB_---1RE_0RA1RE_1LA0LE

Nobody knows yet, but the question has been boiled down. This machine is a doubly exponential counter: a block of 1s on the left and blocks on the right wear each other down two by two, units merge into blocks twice as big, and each epoch 1^N F>0 0 1^3 leads to a new one with N about 2√N/3. Lean proves it halts exactly when a left block of four meets nothing but single 1s, which happens when N is one of 6, 20, 50, 112, 238, ... = 2n+4 − 2n − 10. The orbit 10, 27, 60, ..., 17220, 8534636888060 has missed them all.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in D reading 0. D is entered only from B1 (writes 0, moves L): 0 B>1; C0 (writes 1, moves R): C>0 0. So a halt is the moment one of these patterns appears, with the head on the cell after >.

Structure

What the tape is made of

At every macro configuration the head is in state F on a gap 0 0. Left of it is one block of X ones, with blank tape beyond. Right of it is a row of blocks of 1s, each followed by one 0: first a run of units (single 1s), then at most one even block or an extra 0, more units, and at most one odd block at the end:

0^∞ 1^X F>0 0 (1 0)^a [mid] (1 0)^b [tail] 0^∞

F walks over a unit in two steps, so the units are free to travel between the gap and the first real block. Lean's Q = ⟨X, a, mid, b, tail⟩ names this shape, and mstep says what comes next, with the exact number of steps.

The basic moves

Rounds and merges

A round. With k units in front of a block Y ≥ 2 and X ≥ 3, the head goes over and back: the left block and the block both lose two 1s, and two new units appear.

A merge. If an extra 0 comes after the units instead, and X ≥ 5, the left block loses four 1s and the units, the 0 and the next block Z fuse into one block 2k + Z + 5.

So against an odd block 2q + 3, q + 1 rounds use it up into 2q + 3 units, which then merge into the block 2(2q + 3) + 5: a doubling pass that costs the left block 2q + 6 ones (pass). When the left block runs out, a restart carries units and a block back to the left end as the new left block.

The emergent behaviour

A doubly exponential counter

An epoch starts at an outer configuration O(N) = 1^N F>0 0 1^3. First the right block doubles again and again (3, 11, 27, 59, ...) while eating N. What is left of N becomes a stock of units in front of a stored block. Then come inner epochs: the left block is 24·2j − 3 (21, 45, 93, ...), a small block doubles through 6, 18, 42, ..., eating one unit per merge, and a restart doubles the left block. Each inner epoch uses j + 4 units. When the units are gone, everything merges and the epoch ends at O(N').

With u units there are about √(2u) inner epochs, so N' is about 2√(2u), roughly 2√N/3. From blank tape:

10 → 27 → 60 → 118 → 254 → 514 → 1014 → 2106 → 17220 → 8534636888060

The last value is reached after about 6.5·1025 steps; the next one has on the order of a million bits.

The danger

Where it could halt

The machine halts only when the left block is exactly four 1s and the right side holds nothing but units: D then reads a blank (halts_iff_four). In an epoch that happens when a doubling pass leaves exactly four 1s. Adding up the passes 3, 11, 27, ..., this is exactly when

N = 2n+4 − 2n − 10   = 6, 20, 50, 112, 238, 492, 1002, 2024, ...

Lean proves that each of these halts (outer_halts); for every N up to 3000 they are the only epochs that halt. The orbit came close (118 next to 112, 2106 near 2024) but never hit. These targets get exponentially sparse while N grows doubly exponentially, so a hit looks ever less likely, but nothing proves that the orbit avoids them.

Status

What is proved

Kernel: the 14 cell rules; the block machine and its soundness (mstep_sound, mstep_halt); halts_iff and halts_iff_four; the doubling pass and outer_halts.

native_decide: no halt in the first 191,906,825,348,151 steps (blank_runs_macro).

Computed: the block machine agrees with the machine on 108 steps; the outer orbit up to 8534636888060; the halting set for N ≤ 3000. Not proved: the inner-epoch formula in general, and whether the orbit ever hits the halting set.

The cell rules

Fourteen rules for every value of their variables, written by bbtools.symtm.prove: the walk of F over a unit, a round (the left block and the first block that is not a unit each lose two 1s, two units appear), a merge (units, a 0 and the next block become one block 2k + Z + 5), a restart at the left end, the moves at a left block of 2, the endings at the right end, and the halt at a left block of 4.

Doubling passes, and where they halt

A pass against the block 2q + 3 takes the left block x + 2q + 7 to x + 1 and the block to 2(2q + 4) + 3 (pass); it halts if the left block is 2q + 6 (pass_halt). Hence the outer configuration 1^N F>0 0 1^3 halts for every N = 2n+4 − 2n − 10 (6, 20, 50, 112, 238, 492, ...) (outer_halts).

The inner epochs

After the doubling passes the units in front of a stored block feed inner epochs: Xj = 24·2j − 3 becomes Xj+1, using j + 4 units, in 1152·4j − 216·2j + 10 steps. Found from the run and checked for j < 400, not proved; so N' is about 2c√N with c about 1/3.

Heuristic
README.md
Why it probably never halts

The halting set has one element per doubling of N, so a random N of its size lies in it with chance about 1/N; the orbit is already at 8.5·1012 and grows doubly exponentially, so the chance of a later hit is negligible.

Open
Does it halt from blank tape?

Open: it halts iff the outer orbit hits 2n+4 − 2n − 10 (the if direction proved in Lean, the converse computed for N ≤ 3000). The map N → N' depends on the remainder of the doubling passes, a Collatz-like question.
