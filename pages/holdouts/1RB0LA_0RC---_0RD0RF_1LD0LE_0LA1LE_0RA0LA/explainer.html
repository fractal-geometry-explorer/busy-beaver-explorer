A 6-state Busy Beaver machine · Status as of 8 November 2026.

Does this machine ever halt?

1RB0LA_0RC---_0RD0RF_1LD0LE_0LA1LE_0RA0LA

Nobody knows. This machine keeps a solid block of 1s with one or two holes in it, and spends each round moving a hole: the first block is turned into 0 1 pairs, and every two pairs come back as a glider that knocks the hole 3 cells left. Rounds cost about the square of the width and add a few cells, so the width grows like the cube root of the time.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in B reading 1. B is entered only from A0 (writes 1, moves R): A>0 1. So a halt is the moment this pattern appears, with the head on the cell after >.

What it does

A solid block with holes

Run the machine for a while and stop it when the head is at the left end in state E. The tape is nearly all 1s, cut by one, two or a few single 0s, the holes. At step 994,226,005 it is E>0 1^2584 0 1^1236: two blocks, 2,584 and 1,236 ones long. Write a tape like that as a list of block lengths, here [2584, 1236].

Between two such moments the machine does one round, and a round shuffles the blocks: the hole ends up somewhere else, and there are a few more 1s. The rounds use three moves.

Macro structure

A round: sweep, gliders, a hole that moves

The sweep. Moving right from the left end, states B, C, F and A turn each pair 1 1 of the first block into 0 1: the block 1^16 becomes (01)^8, 4 steps a pair.

Gliders. If the block had even length, the sweep ends next to the hole with two 0s, 0 0, and they move right through the next block of ones, one cell every 5 steps: 1^p 0 0 D> 1^q becomes 1^(p+1) 0 0 D> 1^(q-1). That is a glider. When it reaches the next hole (three 0s in a row), D fills them and the hole reappears 3 cells to the left of where it was. E then walks back left over the ones.

Back for more. E stops at the last 0 1 pairs of the swept block; two pairs make a new glider, which runs right, knocks the hole 3 more cells left, and so on. Here is the round from [16, 20], one line each time the head turns right (dark cells are 1s):

These rows are the real tape from py/rounds.py's simulation. A first block of length 4K gives the first glider plus K more, one per two pairs (here K = 4); a block of length 4K + 2 gives one glider more, from the last pair and the two 0s it leaves at the left end. Lean proves the whole round for every K and every second block:

  • [4K, a, b, …] becomes [a + K, 3K + 3 + b, …]
  • [4K + 2, a, b, …] becomes [a + K, 3K + 6 + b, …]

So the hole after the second block disappears into the new second block, and the new hole sits 3K + 3 (or 3K + 6) cells before the next one: roughly three quarters of the old first block. The old second block moves to the front, a quarter of the first block bigger. All 347 even rounds of the first 109 steps follow these formulas exactly.

The hard case

Odd blocks and the one halting pattern

If the first block has odd length, the sweep does not stop at the hole: C>1 0 1 becomes 0 1 0 C>, the sweep carries on into the next block, and the hole is left behind as a 0 0 mark among the pairs. The gliders then come back over a stretch with marks in it, and the result depends on the parities of several blocks at once. These rounds add 4 to 18 ones instead of 3 or 4, and they are what makes the sequence of blocks look random: the first block is odd about half the time.

The machine halts only if B reads a 1, which happens exactly when a rightward sweep meets B>0 1 0 0 1: an odd stretch, then two 0s, then a 1. Two 0s in a row exist only as gliders and as the marks behind the sweep. At the start of every one of the 685 rounds simulated (to 109 steps) the tape had only single holes, so no sweep had anything to trip on. Proving that this lasts for ever means writing the rest of the odd rounds as rules too (their first step, cross, is proved), and finding an invariant on the blocks finer than single holes: that is the open step.

Growth law

Why the width grows like t1/3

A round from blocks [x, a] sends about x/4 gliders, and each glider crosses the second block and comes back, about 6 steps per cell: a round costs about 1.5·x·a steps. Both blocks are a fair fraction of the width w, so a round costs of the order of w2 steps, and it adds only a handful of cells (3 to 18 ones). Adding a constant to w at a cost of w2 steps each time gives w3 ~ t: the width grows like the cube root of the step count. After 109 steps the tape is 3,824 cells wide; 109 to the power 1/3 is 1,000.

Computed
plain simulation of single rounds
Odd rounds depend on many blocks

From an odd first block the sweep crosses holes (cross) for as long as the parity keeps it on the last 1 of a block, so the round merges several blocks and its result depends on all their parities: e.g. [41, 20, 30, 14, 16] → [65, 75], [41, 20, 30, 15, 16] → [35, 99], [41, 20, 31, 14, 16] → [10, 97, 21].

Computed
py/classround.py
A class of round starts that is nearly closed

Take as round start E on the 0 left of a tape 0? 1^a1 (0 1^ai)* (single holes, a1 ≥ 1, the other blocks ≥ 2). For all 4,616 such tapes of at most 20 cells the round ends without halting on a tape of the same class. For 24 cells (21,303 tapes) two do not: 101111011011111101101111 and 101111011110111101101111 end with a block of length 1 inside (both give 0 1^3 0 1 0 1^28 0 1^6). So this simple class is not an invariant; one that is must say more about the blocks.

Heuristic
py/far.c
No small automaton proof

A finite-automata-reduction search (a DFA on one side, the least NFA on the other) finds no certificate with a DFA of up to 8 states on the left, or up to 7 on the right; DFAs built from windows of up to 4 cells with parity and pattern flags fail too.

Heuristic
py/rounds.py
Why the width grows like t1/3

A round from a first block x sends about x/4 gliders through the second block a, each taking about 6a steps there and back, so a round costs about 1.5·x·a steps, of the order of the width squared; it adds 3 to 18 ones (3 for x = 4K, 4 for x = 4K + 2, more for odd x). Width w after t steps then satisfies w2 dw ~ dt, so w ~ t1/3.

Heuristic
tools/py/bbtools/ctl.py
The only way to halt

The halting transition is B reading 1. B is entered only from A on a 0, and A sits on a 0 with a 1 to its right only after C, F, A in a row, so a halt is exactly a rightward sweep meeting B>0 1 0 0 1: an odd stretch of ones followed by two 0s. Inside a round two 0s appear only as gliders and as marks left behind the sweep, never ahead of it, in all the rounds simulated. A closed-language (CTL) search with windows of 8 cells does not see this: it finds abstract configurations that halt.

Open
Does it halt from blank tape?

Not known. The even rounds are proved, and so is the sweep's step through a hole that starts an odd round; the rest of an odd round (gliders crossing the marks, over any number of merged blocks) is not. Single holes with blocks of at least 2 is not an invariant (two 24-cell counterexamples), so a proof needs a finer one.
