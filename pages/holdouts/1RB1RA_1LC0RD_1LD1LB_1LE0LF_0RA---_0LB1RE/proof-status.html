What is known about 1RB1RA_1LC0RD_1LD1LB_1LE0LF_0RA---_0LB1RE

1RB1RA_1LC0RD_1LD1LB_1LE0LF_0RA---_0LB1RE

Nobody knows whether this six-state machine halts from blank tape. This page records what is established about it, sorted by what each result rests on. Only a first analysis has been done: the macro rules are not yet known.

Left of the start, the tape is blocks of an odd number of 1s separated by double 0s, and the head reaches the left end in state C; right of the start it is a long stretch of words 1 and 1 1 separated by single 0s, mostly (1 0)^n, which grows like a power of the step count.

Status as of 12 November 2026.

In short

The question is open. No halt in the first 1010 steps (C simulator); the macro configuration and its rules are not yet known, so there is no map to analyse and no heuristic for halting beyond the localisation of the halt below.

Round 6, the proved neighbour. The machine proved in busycoq is this table mirrored and started in state D; in this machine's terms it is the run from the tape 1 A>0 (one extra 1) instead of blank tape. Its proof is a closed tape language that exists once its own run has settled (after 106 steps, not before 105). The same search from this machine's run after 108, 109, 1010 and 1011 steps does not close, so those configurations are not covered by the neighbour's proof. No transfer; the question stays open.

Where a halt can come from

If the machine halts on its third step from a configuration, that configuration is one of: C with 1 two left, 0 left, 0 under the head. So a run can reach a halt only through one of these patterns, and a proof that the machine never halts only has to rule them out. The proof splits on the state and the five cells around the head.

halt_route, lean/Route.lean (written by py/route.py)

Where a halt can be

A closed tape language of windows of 5 cells (tools/py/bbtools/ctl.py, closure checked by the script, not by Lean) contains every configuration reachable from blank tape, and its only halting configurations have E reading a 1 with at least four 1s right of the head (E>1 1 1 1 1). In the run so far the right region has shown no runs of five 1s, so a halt would have to happen inside a long block of 1s, as in the left region.

python3 -m bbtools.ctl 1RB1RA_1LC0RD_1LD1LB_1LE0LF_0RA---_0LB1RE 5

Not decided by n-gram CPS up to width 14

The n-gram Closed Position Set decider (tools/c/ngramcps.c) with equal widths 4, 6, 8, 10, 12 and 14, plain and with the fixed-length (1) and LRU history augmentations, either reaches a halting local configuration (UNKNOWN) or stops at 3·107 local configurations: it does not prove non-halting at these settings.

ngramcps MACHINE N [-H 1 | -U] -m 30000000

The right end grows by three cells per visit

Counting a visit as the head reaching the right end after having been more than 50 cells to its left, the first 2·109 steps have 15,470 visits; at 15,386 of them the right end has grown by exactly 3 cells since the previous visit (57 times by 6, the rest by 0, 1 or 5). The head turns back at a point that drifts to the right by about 29 cells per visit, so the zone it sweeps shrinks, and every so often (3,478 times) the turning point jumps far to the left and a new phase starts. Visits get further apart as the right region grows, which gives the power-law growth.

c/rvisits.c: ./rvisits MACHINE 2000000000 50

The neighbour's proof, reproduced for start D

busycoq proves the neighbour with CPS_LRU 100000001 400000 400000 8 3200 2 6 0 0: run 108+1 steps, then find a set of abstract configurations (blocks of 8 cells; on each side the 2 nearest blocks and the list of up to 6 different blocks seen beyond) that is closed under the machine and contains no halt. Our own implementation of that search, on this table started in D, finds such a set with 4,091 abstract configurations from the configuration after 106+1 steps (about 4,035 on busycoq's mirrored machine, also from 107+1 and 108+1). From blank tape and from 105 steps it does not close within 300,000 summaries: the neighbour's run has to settle first. A search program, not a proof.

c/cpslru.cpp: cpslru MACHINE 1000001 300000 D - 8,2,6,0

The same search does not close from this machine's run

From this machine's own configurations after 108+1 steps (parameters 8,2,6), and after 109+1 and 1010+1 steps with ten parameter sets (blocks of 1, 2, 4, 6, 8, 12, 16 cells; 1 to 8 exact blocks; lists of 4 to 8), and after 1011+1 steps with two, the search either exceeds 300,000 summaries or 6,000,000 abstract configurations, or (blocks of one cell) reaches a halting abstract configuration. A closed set is the smallest one containing its start, so this also shows that these four configurations are not in the neighbour's closed language: had one been, its closure would have stayed inside those 4,091 configurations. It does not show that no closed language exists.

heuristic Evidence only

Growth shape: exp/power

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.062). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.677).
