Decided: it haltsProved in this repository, checked by Lean and by Coq. The ledger below says what each part rests on.

This six-state, two-symbol Turing machine was one of the holdouts left open by the bbchallenge project. It halts: Lean and Coq each prove it, with a simulator that is proved correct and then evaluated from blank tape to the halting transition. The Coq proof also proves the exact number of steps. This page lists what has been established, sorted by what each result rests on.

Status as of 16 November 2026.

In short

It halts. Proved in Lean (halts, lean/Halt.lean): a run-length simulator with closed-form jumps is proved to follow the machine (kernel), and its run from blank tape reaches the halting transition (native_decide, which trusts Lean's compiler). It is also proved in Coq on busycoq's definitions (halts_172044, steps_172044, coq/). There the evaluation is done by the kernel's virtual machine, so that proof does not trust a compiler, and it counts every step. The number of steps, 853177647932005270554892218084645935472995035642746848454477793277027802995098762076895667304703808111420498351739937140047615589683 (about 8.53·10131), is proved in Coq: the machine reaches its halting configuration after exactly that number minus one steps and at no other time (kernel). Three separately written simulators agree with it. The tape is a binary odometer whose digits are counters of the word 011; each counter is a fuel tank that loses a unit every 2j visits of the right end. After 9.6·1065 visits the odometer is the whole tape, 2.9·1066 cells, every bit is 1, and the carry falls off the left end.

The machine halts: a second proof, in Coq (busycoq)

halts_172044 : halts tm c0 on the definitions of busycoq's BB6 branch, with no axioms. The same method as the Lean proof (the visit rule and the closed-form jump, proved for every zone; a run-length simulator proved to follow the machine) plus two block rules that cross a whole counter level in one round (D leftwards over 1 0 (011)k 1, C rightwards over (100)m 1 0 1 1 0, proved for every k, m). They bring the run from 88.9 to 19.0 million rounds. The run from blank tape to F0 is evaluated by vm_compute, which the kernel checks: about 8.5 minutes with the step counts below (160 seconds without them, in an earlier version on the busycoq fork).

The exact number of steps: 8.53·10131

steps_172044 : halts_in tm c0 (N.to_nat K) /\ forall n, halts_in tm c0 n -> n = N.to_nat K, with K = 853177647932005270554892218084645935472995035642746848454477793277027802995098762076895667304703808111420498351739937140047615589683 minus one: the machine reaches its halting configuration after exactly K steps and at no other time, so it runs for K + 1 steps with the halting transition (the bbchallenge count). Being exact, this is also the best possible lower and upper bound. Every lemma of the Coq proof states its number of steps (busycoq's multistep). A visit takes 6(n0+…+ni−1) + 4i + 11 steps. V visits take a closed form, 11V + 6V(V−1) plus a sum over the levels of the odometer (Jz), proved by induction on V. The run carries its count and ends with run 225 start = RHalt K.

steps_172044, jump, Jz_succ, round_sound, coq/M_1RB1RD_1RC1RB_1LD0RA_1RA0LE_1LF0LC_HHH1LE.v

The visit rule of a zone, for every zone

When the tape ends in counters (011)nk … (011)n0 separated by 11 (bit 0) or 01 (bit 1), one visit is a binary increment of the bits: the lowest 0 bit si is set, ni loses 1, every bit cleared moves one unit to the counter on its left, n0 gains 2. Proved for every number of counters, every count and every tape left of the zone, by induction on the carry.

visit, lean/Zone.lean

V visits at once

In the coordinates N0 = n0 − s1, Nj = nj + sj − sj+1 a visit is a plain binary increment in which Nj−1 loses 1 when bit j is set and N0 gains 2. For every V after which the bits have not overflowed and every Nj is still at least 2, the machine goes from the zone to the zone V visits later, given in closed form.

jump, addV_succ, inc_physP, lean/Jump.lean

The simulator follows the machine

Each round of the run-length simulator (one transition, a run of a word crossed when one or two copies are crossed in the same state, a copy unpacked, or a jump whose hypotheses it has checked) takes the configuration it stands for to a configuration the machine reaches; if it answers true, the machine halts. The leftward half of the simulator is the mirror image of the rightward half (steps_mir).

mstep_sound, tryJump_sound, run_sound, lean/Sim.lean, lean/Run.lean

The machine halts from blank tape

The simulator of lean/Sim.lean and lean/Run.lean, started on blank tape, meets the halting transition F0 within 108 rounds (about 88.9 million: 68.6 million single transitions, 13.4 million runs crossed, 86,734 jumps). How it ends

At the last visit the tape is 1 n214 01 n213 01 … 01 n0 0 with n214 = 91,562 and n0 about 2.5·1065: every bit is 1, the carry crosses all 215 counters in one walk of 2.9·1066 steps and F reads a 0 at the left end. The word at the left end had been eaten over the previous overflows (11111101111, 11111101, 11101111, 11101, 1111, 1).

The irregular visits

When a counter runs low or the bits overflow, the words between counters change (11101, 11101111, 1101101101, …) and counters merge or split; no closed rule is known for these visits, they are simulated (in the Lean proof too). The first counter ran out four times (near 105, 1014, 1039 and 1066 visits); three times the left end recovered, the fourth time it did not.
