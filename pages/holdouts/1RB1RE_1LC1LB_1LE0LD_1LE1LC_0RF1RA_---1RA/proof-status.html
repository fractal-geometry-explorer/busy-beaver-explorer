What is known about 1RB1RE_1LC1LB_1LE0LD_1LE1LC_0RF1RA_---1RA

1RB1RE_1LC1LB_1LE0LD_1LE1LC_0RF1RA_---1RA

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 22 November 2026.

In short

The question is open, and it is now an exact arithmetic question. Read the tape as a list of runs of ones. Lean proves that from one visit of the left end to the next the list changes by an explicit map (visit), and that the machine halts from blank tape exactly when the orbit of the list [12, 1, 1, 1, 1, 1, 1, 1, 1, 1] under this map reaches a list in which every run is even (halts_iff). The map is a counter growing by 3/2 per epoch whose parities drive a growing stack of slower counters; a halt needs the whole stack used up. An exact simulator ran 10,000,000 epochs (more than 103,521,825 steps) without a halt. The real counter digs into the stack exactly as deep as a random 2-adic counter does, and such digs fall off geometrically (a factor 0.68 per run of the stack), so a halt looks very unlikely; it is not excluded. Lean also proves that no invariant on the parities of the runs (or on the runs mod 4, 8 or 16) can exclude it, and a list with the same stack as the real run but a different counter value halts: a proof would have to follow the 3/2 counter's arithmetic.

The sweep

Read as runs of 1s separated by single 0s, with u a run of length 1: [X, 4, un+2, R] becomes [X+6, 4, un, R] in 2X+32 steps, for every X = 2x+2, every n and every tape R.

sweep, lean/Rules.lean

The conversion

[2x+8, uk+2, R] becomes [6, 4, ux, 4, uk, R] in 4x+74 steps: the long run is turned into half as many units.

convert, lean/Rules.lean

A halt can only happen past the right end

A closed tape language from windows of 4 cells covers the run from blank tape; in it the halting transition F0 can only fire with blank tape from the head on, so the machine halts iff F steps onto the blank region right of the tape. The right end of the tape has not moved since step 1.8·105.

halts_iff_edge, lean/Edge.lean, lean/EdgeCert.lean

The moves of one visit

Eight shift rules, each for all values of its counts and all tapes around: the entry, E crossing even runs, E meeting an odd run (joined with the next one, or turned into units if it is the last), the halt when E meets two 0s, an even run crumbling into units, the run before it absorbing two of them, and the conversion at the left end.

lean/VisitRules.lean, written by py/visit_rules.py

The visit map

For every list l of the domain D (runs ≥ 1, none of length 2, first run even and ≥ 12 or the list starting 6, 4, 1, 1): from the visit with runs l the machine reaches the visit with runs visit l, which is again in D, or halts if visit l = none. And visit l = none exactly when all runs (the first after adding 2) are even.

visit_step, scan_none_iff, lean/Visit.lean

Halting is a question about the visit map

The run from blank tape is at the visit [12, 19] after 423 steps, so the machine halts from blank tape if and only if the orbit of that list under visit reaches none. (Axioms: propext, Quot.sound, Classical.choice.)

blank_to_V, halts_iff, lean/Visit.lean

No invariant on run parities, or on runs mod 4, 8 or 16

No set of parity words (the list of r mod 2 over the runs) contains the word of [12, 19], is closed under the visit map on the domain D, and avoids every halting list; the same for residues mod 4, 8 and 16. The proof is an explicit chain of lists of D (14, 18, 20 and 56 lists): the first has the residue word of [12, 19], each is mapped to a list with the residue word of the next, the last halts. Checked by decide. (Axioms: propext, Quot.sound.)

no_parity_invariant, no_residue_invariant, lean/NoParityInvariant.lean; chains from py/residue_chain.py

A parity word is one residue class of the counter

For any stack dynamics L' = g(L, p) and counter m' = (3m + c(L, p))/2 with c(L, p) ≡ p mod 2, where p = m mod 2: two counters give the same first n parities from the same stack iff they agree mod 2n, and every word of n parities occurs. So the counters that follow a given parity word of length n form exactly one residue class mod 2n, and any event decided by the parities (reaching a depth of the stack, emptying it) has a 2-adic measure equal to its probability under fair coin flips. The epoch map of this machine has this form (computed, not proved here).

The last step before a halt

Among all 1,628,875 lists of the domain with at most 6 runs (each at most 13), the next visit halts exactly from [X, 1] and [X, 4, odd, odd, even, …, even]; only [X−6, 3] maps to [X, 1]. And directly from the map: the last run of the orbit (a 1) can only become even at a visit where every run except the last two is even, so a halt needs the cascade to work through the whole stack.

A halting list with the real stack

For large m the next stack depends only on the stack and the parity of m (py/adversary.py), and m' = (3m + c)/2 with c fixed by the stack and the parity. From the stack 4 u17 4 u3 4 1 of the real visit [6, 4, u368, …] at step 181,429, 247 odd epochs and then one even epoch halt the machine. Solving for m gives m0 = 41155288665286261693662459474261276833979426164594950575389163897113542655 (mod 2248); the exact simulator run from [6, 4, um0, 4, u17, 4, u3, 4, 1] halts after 248 epochs (a step count of 780 bits). So a proof has to see m mod 2248. The breadth-first searches over parities (468,328 stacks to depth 19, a sampled search to depth 40) were too shallow to meet this word.

python3 py/halting_twin.py

Rounds between end events, by remainder class

Sample the run whenever the head is in state D reading 1 with only 0s to its left. Read rightwards from the head, the tape is then A U^m B: one long periodic block between two short context words. For each class (A, U, B, m modulo 1 or 2 (the smallest modulus that works for the context)) the next sample is simulated for six values of m and extended as an affine map of m (with a cubic step count). Along the direct run from blank tape to 3·109 steps (59 events) the class map predicts the next event in all 25 rounds it applies to. This is an extrapolation checked by computation, not a proof.

The real counter digs like a random 2-adic counter

Call the dig from an epoch the largest later drop of the number of runs of the stack; a halt needs a dig of the whole stack. Over the first 106 epochs the real run digs 10 runs or more from 3.6% of the epochs, 20 or more from 0.079%, 30 or more from 0.0016%, at most 35. Coin flips from the real stack (by word_class, random 2-adic counters) give the same shares within sampling error (3.3% and 0.05% at 10 and 20). The tail falls by a factor 0.68 per run; extrapolated, the 2-adic counters that could still empty the stack of epoch 107 (11,380,629 runs) have measure about 10−1,906,000. A literal “depth d needs d parities” is false: some words of 12 parities dig 27 runs.

py/dig.py

The stack is touched only near its top

In 100,000 epochs the head passed 1 entry of the stack in 73% of the epochs, 2 in 22%, 3 in 4%, 4 in 0.27%, 5 in 0.04%, 6 twice, while the stack gains 0.28 entries per epoch; its size never came back more than 10 entries below an earlier value. If the parities keep behaving like coin flips, the chance that the stack is ever emptied is negligible.

python3 py/visit.py epochs 100000

Growth shape: fixed/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.493). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

tools/py/bbtools/triage.py

A stack of slower counters

The list right of the unit block behaves like nested copies of the top level: its first run grows by 6 and loses a unit at each odd epoch, and is converted into units when they run out; deeper items change exponentially more rarely, and the bottom of the list has been frozen for most of the run. The list grows by about one item per three epochs (29 tokens at epoch 83).

Does it halt from blank tape?

Not known. Exactly: does the orbit of [12, 19] under the visit map ever reach a list whose runs are all even? That needs the whole stack to be used up. The number of even runs stays odd, which does not exclude it. No invariant on the runs mod 2, 4, 8 or 16 can exclude it (proved), and a list with the real stack and another counter value does halt, so a proof must use the arithmetic of the 3/2 counter.
