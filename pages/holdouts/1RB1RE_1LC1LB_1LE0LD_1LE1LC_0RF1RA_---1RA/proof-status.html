What is known about 1RB1RE_1LC1LB_1LE0LD_1LE1LC_0RF1RA_---1RA

1RB1RE_1LC1LB_1LE0LD_1LE1LC_0RF1RA_---1RA

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 13 November 2026.

In short

The question is open. The machine is a counter that grows by a factor 3/2 per epoch (two moves proved in Lean), whose parities drive a growing stack of slower counters. Lean also proves that a halt can only happen past the right end of the tape, which would need the whole stack to be used up; through 83 epochs (1030 steps) the stack only grows and its bottom has frozen.

The sweep

Read as runs of 1s separated by single 0s, with u a run of length 1: [X, 4, un+2, R] becomes [X+6, 4, un, R] in 2X+32 steps, for every X = 2x+2, every n and every tape R.

The conversion

[2x+8, uk+2, R] becomes [6, 4, ux, 4, uk, R] in 4x+74 steps: the long run is turned into half as many units.

convert, lean/Rules.lean

A halt can only happen past the right end

A closed tape language from windows of 4 cells covers the run from blank tape; in it the halting transition F0 can only fire with blank tape from the head on, so the machine halts iff F steps onto the blank region right of the tape. The right end of the tape has not moved since step 1.8·105.

83 epochs, 7·1029 steps, no halt

The macro simulator with proved cycle jumps (tools/py/bbtools/cycles.py, exact step counts) runs to 1030 steps. The unit count m of epoch 83 is 780,830,244,113,908; m' = 3m/2 + d with d in {−2, +1, +4} (m even) or {−1/2, +5/2} (m odd), and an epoch takes 1.500·m2 steps.

py/epochs.py

Rounds between end events, by remainder class

Sample the run whenever the head is in state D reading 1 with only 0s to its left. Read rightwards from the head, the tape is then A U^m B: one long periodic block between two short context words. For each class (A, U, B, m modulo 1 or 2 (the smallest modulus that works for the context)) the next sample is simulated for six values of m and extended as an affine map of m (with a cubic step count). Along the direct run from blank tape to 3·109 steps (59 events) the class map predicts the next event in all 25 rounds it applies to. This is an extrapolation checked by computation, not a proof.

heuristic Evidence only

Growth shape: fixed/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.493). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

tools/py/bbtools/triage.py

A stack of slower counters

The list right of the unit block behaves like nested copies of the top level: its first run grows by 6 and loses a unit at each odd epoch, and is converted into units when they run out; deeper items change exponentially more rarely, and the bottom of the list has been frozen for most of the run. The list grows by about one item per three epochs (29 tokens at epoch 83).

No halting class among 5,000 contexts

Breadth first from the starting context, with every remainder at every context (whether or not the numbers can really produce that sequence of remainders, and only for m large compared with the contexts): 5,000 contexts expanded, 6,526 found, to depth 23. None of them halts; the search is not complete (the set of contexts keeps growing), and it says nothing about a halt that needs a context as long as the block itself.

Does it halt from blank tape?

Not known. A halt needs the stack to be emptied; the parities of m that drive it look random. The epoch-end cases (parity of m and the first items of the list) are read off the run, not proved.
