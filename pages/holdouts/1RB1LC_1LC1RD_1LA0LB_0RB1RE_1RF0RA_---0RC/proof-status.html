1RB1LC_1LC1RD_1LA0LB_0RB1RE_1RF0RA_---0RC

Open: a cryptidIts halting is thought to come down to a Collatz-like question that no known method decides (the community's label, not a result).

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. Its tape is mostly two blocks: an alternating block (10)^x followed by a solid block 1^y. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. Lean proves no halt in the first 10,000 steps by the kernel alone and in the first 107 with native_decide; the C simulator finds no halt in the first 109 steps; an exact macro simulator (blocks of 2 cells) finds no halt in the first 1015 steps.

What Lean proves. The whole frame map: 6 tape shapes, 30 cases, each proved for all sizes by a symbolic run (next_sound), and the cases where the map is undefined halt (none_halts). So the machine halts from blank tape if and only if the map, iterated from the frame the run reaches after 1 steps, reaches one of those cases (halts_iff). By native_decide the first 108 frames (about 5.95·1011 machine steps) do not. Whether the orbit ever does is open.

Other proofs and outside reports

Community label

In the community's BB(6) tracker the machine's class is Cubic Mess. Its 3 November 2026 edition lists the machine as a cryptid: its halting is thought to come down to a Collatz-like question that no known method decides. These are labels read off the run by others, not results.

The whole frame map

next in lean/Phases.lean sends each of the 6 frames to the next one the machine reaches, in 30 cases; next_sound proves every case for all parameters, each from a symbolic run in lean/Pieces.lean (generated by py/pieces.py) glued by tape_eq. Where next is undefined (.b l j 2, .d l 0 1, .d l 1 0) the machine halts (none_halts).
