1RB0LB_0RC0LD_1LD1RE_0LA0RF_0RD1RF_0RC---

This six-state machine is a holdout of the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on: the structure of its run (two counters ticking together), the rules proved in Lean, and the open question.

Status as of 8 November 2026.

In short

The question is open. The machine runs two binary counters off one engine, one of them with stretches of junk between its digits. It can halt only if a carry finds a 1 where it has found a 0 every time so far. No halt in the first 1011 steps.

Both counters go up by 1 at every event

Over the whole period from step 108,210,236 to 153,262,400 (524,288 events, the head turning in A at the engine) the left counter read off the tape goes 0, 1, 2, ..., 219 − 1, up by exactly 1 each time; the right counter read from its digit cells (9, 19, 22, 25, 28, 31, 34, 72, 75, 85 cells right of the head) goes up by 1 modulo 210 from one event to the next at all but 4 of the 524,287 steps, at the start of the period and where a carry reaches a digit for the first time (the digit cells are then still being rewritten).

How much of the run the increments cover

In the first 108 steps (1,048,574 events) 95.2% of the events are instances of these theorems (left 524,258; right0 262,133; right1 92,325; junk_10 78,635; junk_110 39,313; junk_jk 1,733; right1m 9; right0m 1). The other 50,167 are carries over junk layouts the rules do not list (two junk stretches, junk words other than 1010000) and the moments around left-end visits. The same numbers as the reference: the run is the same cell for cell.

Does it halt from blank tape?

Not known. It halts only if F reads a 1, i.e. only if after D1 (0RF) and E1 (1RF) the head finds a 1; it never has, and the layout of the junk, which would decide it, is not decoded.
