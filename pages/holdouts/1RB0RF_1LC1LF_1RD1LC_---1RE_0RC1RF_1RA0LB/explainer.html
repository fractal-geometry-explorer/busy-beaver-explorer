Does this machine ever halt?

1RB0RF_1LC1LF_1RD1LC_---1RE_0RC1RF_1RA0LB

Nobody knows whether this machine halts. Underneath, it is a binary counter: the number is written twice, mirrored about one cell, and every increment is one trip of the head. The counter runs in rounds that double in length, and slower counters to its left are driven by its carries. It has run 1010 steps without halting.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in D reading 0. D is entered only from C0 (writes 1, moves R): C>0 0. So a halt is the moment this pattern appears, with the head on the cell after >.

The core

A binary counter written twice

Run the simulator past two million steps and the head settles around one cell, near the right part of the tape, and swings out to both sides by distances 4, 8, 4, 12, 4, 8, 4, 16, ... cells: the ruler sequence of a binary counter. The number n is written twice, once on each side of that cell, in words of four cells:

bit 1bit 0order
right of the head10111111least significant bit first (nearest the head)
left of the head11111010least significant bit nearest the head; it holds n - 1

So the configuration holding n is ... W(n-1) 1 1 D>1 1 1 1 1 V(n) .... For n = 5 the right side reads 11111 1011 1111 1011 (bits 1, 0, 1) and the left 1111 1010 1010 11 D (n - 1 = 4 = 100). Leading zeros on the left are the long stretch 1 0 1 0 ..., on the right the long block of 1s: room for more digits.

One increment is one trip. D, E, F go a step right, then B and F sweep left turning the pairs 1 1 of the left side's trailing 1-digits into 0 1 (the carry), C turns the first 0-digit into a 1, and A and F sweep back right restoring the alternating cells; on the right a single 0 is moved to flip the bits of n. If n - 1 ends in t + 1 ones this takes 8t + 42 steps, if it ends in a 0 and n in s + 1 ones, 14s + 48 steps. Both rules are theorems in lean/Rules.lean, for every t, s and every tape around.

Level two

Rounds that double

The left copy is boxed in: 12 digits of room between the counter's cell and a block 1^13 0. The right copy is not: when n reaches 2w, its top bit runs into the end of the tape, the head arrives at the right end, the last block grows by four cells (0 1^m 0 1 0 1 0 1 A>0 becomes 0 1^(m+4) 0 1 0 1 A>0, also proved), and the count starts again at 1 with room for one more bit.

Measured on a direct run up to 2·109 steps, the counter went through n = 1, ..., 2w - 1 for every w from 12 to 24, one increment at a time, at the same cell. A round costs about 56 steps per increment, so round w takes about 2.3·105 · 2w-12 steps: this is why the right end is reached at times that double (1.84, 2.76, 4.60, 8.28, 15.6, 30.3, 59.7 million, ...).

Level three

Slower counters on the left

Because the left copy has only 12 digits, it overflows every 4096 increments. Its carry goes on into the tape further left, which holds a second counter written in a different code (blocks 1^4, 1^8, 1^12, 1^16 that grow by four, and a small digit with four phases), and the head comes back with the left copy cleared. Further left still is a list of short blocks, 1^7, 1^4, 1^3, that are used up one by one: the head goes all the way to the left end only when n hits 214, then 214 + 217, then 214 + 217 + 220, and some of these visits consume a block.

The first 920,431 steps are a smaller version of the whole thing; there the list runs out, and the tape is rebuilt with a longer list, a wider counter and a block 1^59 in place of 1^15. After 5.4·108 steps the second list is down to three blocks 1^3. When it runs out, the next rebuild should come, but at a step count far beyond what can be simulated directly.

Halting

Where a halt could happen

The machine stops when D reads a 0. A closed tape language with windows of 5 cells, which contains every configuration reachable from blank tape, adds that the four cells left of the head must read 1 1 0 1. None of the proved rules does this: inside a round the counter cannot halt. A halt could only come from the rare events, the overflows into the left counters or a rebuild, whose rules have not been worked out.

So the question reduces to a long chain of nested counters, of which the innermost two levels are understood. The natural next step is to write the rules of the left counters and of the rebuild as functions of their parameters, prove them with the same shift-rule machinery, and build a simulator that does a whole round in one move; it could then follow the run to the end of the second epoch and see what the rebuild produces.

sweep_A, sweep_F, sweep_E, sweep_C, sweep_B, lean/Rules.lean
The sweeps

Five shift rules, for every length n: A> (10)^n becomes (01)^n A>, F> (01)^n becomes (10)^n F>, E> (01)^n becomes (11)^n E>, C crosses 1^n leftwards unchanged, and B with F turns pairs 1 1 into 0 1 moving left.

Kernel
inc_odd, inc_even, lean/Rules.lean
The counter's increment rules

Write W(m) for the bits of m, most significant first, as 1111 (1) / 1010 (0), and V(n) for the bits of n, least significant first, as 1011 (1) / 1111 (0). The configuration ... W(n-1) 1 1 D>1 1 1 1 1 V(n) ... goes to the same configuration for n + 1: in 8t + 42 steps when n - 1 ends in t + 1 ones (inc_odd), in 14s + 48 steps when n - 1 ends in a 0 and n in s + 1 ones (inc_even). Both hold for every t, s and every tape beyond the words they name, as long as the next word on each side is a 0-digit (1010 on the left, 1011 resp. 1111 as stated on the right).

python3 py/counter_check.py 2e9 (about 15 minutes; output in py/counter_check_2e9.txt)
The counter runs in rounds, checked to 2·109 steps

At every step C0 → D the script tests whether the tape is the counter configuration with some n (left value equal to n - 1 modulo its width). From 1.15·106 steps on, the 35.7 million matches form runs at one fixed cell in which n goes up by exactly one each time: n = 1, 2, ..., 2w - 1 for every w from 12 to 24 (round 24 ends at step 1,881,955,329; round 25 is under way at 2·109), with the left half always 12 digits wide. Until step 9.2·106 (rounds 13 to 17) a round is cut into runs at the multiples of 4096, where the 12-digit left half overflows and the head leaves to the left and comes back with the count resumed; from then on each round is one unbroken run. The round lengths double: about 2.3·105·2w-12 steps, about 56 steps per increment.

Heuristic
tmrun ... at C L, head positions left of the counter
The left half overflows every 4096 increments

The left copy has room for 12 digits (it is bounded by a block 1^13 0). Every 4096 increments it overflows; the head then carries into the region further left, which holds a second counter in a mixed code (blocks 1^4, 1^8, 1^12, 1^16 growing by four, and an inner 4-phase digit), and comes back with the left half cleared. In round 16 this region goes through 16 different states, one per overflow.

Rare visits to the far left

Between 1.9·106 and 109 steps the head reaches the far left end (in state F) seven times, at steps 3,682,344, 5,522,782, 9,203,628, 68,017,235, 185,638,122, 303,258,880 and 538,500,366, each time during the increment to n = 214 (rounds 15, 16, 17), 214 + 217 (round 20) or 214 + 217 + 220 (rounds 21, 22, 23): the next counter configuration holds that value + 1. In units of the 4096 increments between left overflows these are 4, 44 and 444 in octal. At these visits the tape reads F>0 (10)^a [left digits] (10)^26 1^59 0 1^11 0 1^11 ... 0 (10)^2: the right part is just V(n) seen after the leftward sweep (zeros at bits 14, 17, 20, ...), and a left digit (1^7, then 1^4) is used up at some of them. After 5.4·108 steps three digits 1^3 0 1^3 0 1^3 are left.

Heuristic
tmrun ... records
Epochs

The first 9.2·105 steps are a smaller copy of the same structure, with a block 1^15 where the second epoch has 1^59 = 1^(4·15 - 1). At step 920,431 the left digits have run out and the tape is rebuilt with a longer list of left digits and a wider counter. If this repeats, the second epoch ends when its last left digits are used up, at a step count far beyond direct simulation; whether it does, and whether the rebuild can ever produce the halting pattern, is not known.

Open
Does it halt from blank tape?

Not known. A halt needs D reading a 0 (after 1 1 0 1), which none of the counter's rules produce; it could only come from the rare events at the ends of the tape, whose rules are not yet worked out. What is missing: the rules of the left counters and of the epoch rebuild, as functions of their parameters, and a fast simulator built on them.
