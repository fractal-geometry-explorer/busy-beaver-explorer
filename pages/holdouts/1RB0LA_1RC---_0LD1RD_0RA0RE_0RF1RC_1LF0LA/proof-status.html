What is known about 1RB0LA_1RC---_0LD1RD_0RA0RE_0RF1RC_1LF0LA

1RB0LA_1RC---_0LD1RD_0RA0RE_0RF1RC_1LF0LA

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Nobody knows whether this six-state machine halts from blank tape. It is one of three G13 holdouts with the same behaviour (the others are 1RB0LA_1RC---_0LD1RD_0RB0RE_0RF0LD_1LF0LA and 1RB1RF_0RC1RD_1LC1LA_0LE1RE_1RA0RB_---0LC): a solid wall of 1s that grows to the right by 3 cells every time the head comes back to it, and in front of it a short list of blocks of 1s that the head rewrites on every pass, following a recursive rule found from the simulation and checked on more than a million passes. This page says what that rule is, what is checked, and what is still open.

Status as of 12 November 2026.

In short

The question is open. The run is understood at the level of passes: between two visits of the head to the wall the list of blocks changes by a short recursive rule, and every one of the 1,311,505 wall visits in the first 109 steps follows it (C simulator plus py/passmap.py, not a proof). The rule itself never halts; what is not understood is the rare pass in which the list reaches the wall, where in the sibling machine 1RB0LA_1RC---_0LD1RD_0RB0RE_0RF0LD_1LF0LA the whole structure collapses and restarts. Lean proves the bounded runs, that the machine halts if and only if the run reaches D>0 0 1, and the pass rule itself for every list in the cases that do not involve the wall or the shape 2 0 1 Y (96.9% of the passes of the first 109 steps).

The leftward rewrite, for every n

From L 111 (110)^n … written as L (110)^n 111 B>000 R, the machine reaches L 111 B>000 (111)^n R in exactly 11n steps, for any tapes L and R: one 11-step unit L 110 111 B>000 R → L 111 B>000 111 R (generated by symtm) chained by induction.

The only way to halt

The run from blank tape halts if and only if it reaches a configuration D>0 0 1 (the head in state D on a 0, with these cells to its right). B is entered only by A0 = 1RB; A is entered by A1 and F1, which move left and leave a 0 right of the head, and by D0 = 0RA. So the halt is D>0 0 1, 0 A>0 1, 0 1 B>1. The proof is an invariant of the run: while no such configuration has occurred, A on a 0 has a 0 on its right and B reads a 0.

halts_iff_crit, lean/HaltIff.lean

Both sweeps of a pass, for every list

For every list of blocks and any tapes on both sides: state D crosses the blocks 1 0 1 1 (111)^j (the list as D meets it) to the right and leaves 0 111 (011)^j for each; state A at 0 000 crosses those back to the left and leaves 0 1^(3j+3) for each, the cursor A>0 000 travelling along. Proved from four fixed runs (3, 6, 11 and 12 steps) by induction on the block size and on the list.

rsweep, lsweep, lean/Sweeps.lean

The pass relation is sound, for every list and every left tape

A visit is L 0 D>1 0 k1 … kn X with any tape L on the left. Lean defines a relation Reach on lists with seven rules (sweep over a block; bounce: n 0 1 Y becomes (n−2) 1 2 and the sweep goes on into Y, for n ≥ 3; and five ends: … Tj → … j T0, … T0 → … 0 T0, … n 0 T0 → … (n−2) 1 1 T0 for n ≥ 3, … 2 0 T0 → … 0 1 1 T0, and … a 1 0 X → … [1^(3a+3) X] for any tape X) and proves: every derivation is a run of the machine from the visit to the next visit, with three more 1s on the left (the wall grows by 3). This holds for every list and every L, so it covers the recursion of the pass map. No rule exists yet for 2 0 1 Y (an empty block with a 2 on its left and a block after it), nor for an empty block (or 1 0) at the very start of the list, where the wall takes part.

holdouts/triage.json

The pass map holds for the first 109 steps

Each time the head, in state D, stands just right of the wall (a run of at least 1000 1s followed by one 0), the tape right of the wall is a list of blocks 1^(3k) 0 (k = 0 meaning an extra 0) and a tail 1^(7+3j). Of these visits in the first 109 steps, 1,311,505 follow the pass map of the README from the previous visit: 1,311,477 after one pass, 28 after two or three (the head came back to the wall in another state in between, unseen by the sampler). 4 passes reach the wall itself, where the map does not apply. At step 999,999,9xx the wall has 3,954,209 cells and the list is 4 2 1 1 1 2 1 1 8 1 1 1 3 1 1 1 1 3 1 2 1 1 T5.

py/passmap.py, c/blkev.c

State D reads a 0 only 25 times in 109 steps

In the first 109 steps the head is in state D on a 0 exactly 25 times: 11 times with 0 0 0 to its right (first at step 42, last at step 20,653,972) and 14 times with 1 1 1 (first at step 262, last at step 4,054,180); the critical 0 1 never follows. All 25 fall in the starts and restarts of the structure (steps up to 2,740, 3,775,216 to 4,370,514, then 13,579,469 and 20,653,972); in the passes that follow the pass map D always reads a 1.

c/crit.c

The proved passes cover 96.9% of the wall visits in 109 steps

Of the 1,311,509 pairs of consecutive wall visits in the first 109 steps, 1,270,317 are exactly one pass derivable in the proved relation (460,247 ending with the new empty block, 321,518 with a merge, 243,654 with the tail splitting off, 122,579 with a split, 122,319 with the split of a block of size 2) and 27 are two or three such passes in a row (visits between them not recorded). Not covered: 41,162 pairs of the shape 2 0 1 Y, and 3 where 1 0 stands at the wall. No pair contradicts the relation.

py/passrel.py

heuristic Evidence only

Growth shape: fixed/linear

Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows in proportion to the step count (the head drifts steadily that way) (fitted exponent 0.95).

tools/py/bbtools/triage.py

The same map for three machines

The same pass map, with the same list notation, describes 1RB0LA_1RC---_0LD1RD_0RB0RE_0RF0LD_1LF0LA and 1RB1RF_0RC1RD_1LC1LA_0LE1RE_1RA0RB_---0LC; only the starting list, the state in which the head meets the wall and the tail offset differ (1^(7+3j) here).

py/passmap.py in each folder

Two encodings of the same list

On the way right the head rewrites each block 1^(3k) 0 as 1^3 0 (1^2 0)^(k-1) (same width), and on the way back it rewrites it again; only the end of the list, and the place of the first empty block, change from pass to pass.

observed in the simulation

The arrival rule needs only two 0s

Proved: the arrival 0 A>0 000 0 X → 111 0 D>1 0 X (15 steps) holds with any tape on the left, wall or not. Conjecture drawn from it, not checked: when a pass leaves an empty block inside the list and the sweep goes on to the right of it (the case 2 0 1 Y), the returning sweep turns at that empty block and a new pass starts on the right part alone, which would be how a wall starts and why py/passmap.py sees some visits only after two or three passes.

wall_turn, lean/PassTail.lean (the rule); the reading of it is a conjecture

open Open

Does it halt from blank tape?

Not known. Lean reduces the question to one pattern (the machine halts if and only if the run reaches D>0 0 1) and proves most of the pass map for every list (pass_sound). Missing for a non-halting proof: the rule for 2 0 1 Y and the rules for an empty block at the wall (where the wall, or an older structure behind it, takes part), and an invariant: a description of all lists, walls and debris the run can reach, closed under all rules, in which D never meets 0 0 1. Only three restarts have been seen in 109 steps, so that invariant has to be derived from the rules, not fitted to data.
