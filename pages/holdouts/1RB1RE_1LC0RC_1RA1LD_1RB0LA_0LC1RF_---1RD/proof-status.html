What is known about 1RB1RE_1LC0RC_1RA1LD_1RB0LA_0LC1RF_---1RD

1RB1RE_1LC0RC_1RA1LD_1RB0LA_0LC1RF_---1RD

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 9 November 2026.

In short

The question is open. The machine runs a base-4 counter at the left end of the tape: digits a, b, ab, bb (0 to 3) separated by long blocks of pairs ba, incremented once per excursion of the head, and every block shrinks by two pairs per cycle of the digit after it (a countdown timer). The digit rules are proved in Lean for all block lengths. Lean also shows that tapes of the same shape with short blocks halt, so nonhalting cannot follow from the shape alone: it depends on the block lengths the run from blank tape produces. No halt in 1011 steps.

The digit rules

At the left end the tape is D> 0 b (ba)^n1 s1 (ba)^n2 s2 ...; one excursion of the head increments the first separator: a → b, ab → bb (c1, any tape to the right), b → ab with one pair moving from the right block to the left block (c2), and bb → a with a carry into the next separator a or b (c4, c5), for all block lengths.

c1, c2, c4, c5, lean/Rules.lean (generated by py/gen_rules.py)

Where it would halt

The only halting transition is F reading 0, and F is entered only from E reading 1, so the machine halts exactly when the head in state E reads 1 0 (from the transition table).

The shape of the tape

At each new cell on the right the tape is 1^3 0 P^n1 Q P^n2 ... Q P^nk 1^8 0 C>0 with P = 150 and Q = 170; the number of blocks grows from 2 to 7 in the first 8.5·108 steps, the last block losing one pair per event. Observed by simulation, not proved.

tools/c/tmrun.c

Every block is a countdown timer

By the digit rules, when digit j goes 1→2 a pair moves from the block after it to the block before it, and when it wraps 3→0 the block before it gains a pair. So the block after digit j loses 2 pairs per cycle of digit j+1 (every 4j+1 increments) and the first block gains 2 per cycle of the first digit; checked on the run from blank tape (e.g. the second block 13, 11, 9, 7, 5, 3 at consecutive cycles of the second digit, steps 131,121 to 176,267).

README, lean/Rules.lean (the rules for the lowest digits)

Many short counter tapes halt

Of all tapes of that form with at most two inner separators and blocks 1..4, 142 halt within 107 steps; of 200 random ones with up to five inner separators and blocks 2..6, 8 halt within 5·107.

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.506). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.063).

Does it halt from blank tape?

Not known. The halt would need the timers to run out in a bad combination (as in the short tapes above); whether the run from blank tape ever produces one is open. The boundary rules (a block running out, the carry off the top, a new digit at the left) are not yet written down.
