1RB0LE_0RC0RD_1LC0RB_0RE1RD_1LF1LE_0LA---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open, and it is now proved in Lean to be a question about a simple map on lists of numbers. At the moments the head, in A, is at the left wall, the tape is a list of blocks of 1s separated by 00. From one such moment to the next the list changes by a halving cascade: halve the first block, carry the other half into the next block, and go on halving while the value halved was even. Lean proves that the machine halts from blank tape iff the orbit of (1, 1) under this map reaches a cascade that runs past the last block with a carry that is a power of 2 (halts_iff). Iterating the map 6·1010 times from the start finds none.

The halving round

L 0 1^k 0 0 0 1^(m+2) D> 0 0 1^n R becomes L 0 1^(k+1) 0 0 0 1^m D> 0 0 1^(n+1) R in 2m+11 steps, for all k, m, n and any tapes L, R: two 1s leave the block being halved, one to each neighbour. Also the runs of D (right) and E (left) over 1s. Generated by py/rules.py.

halve, d_run, e_run, lean/Rules.lean

The run is the orbit of the cascade map (Lean theorem)

Write Wall(ns) for 0^inf A> 0 0 1^n1 0 0 1^n2 … 0 0 1^nk 0^inf. For every list ns of blocks ≥ 1, if the cascade map F sends ns to ns′ the machine goes from Wall(ns) to Wall(ns′) (and ns′ has blocks ≥ 1), and if F ns = none the machine halts from Wall(ns). The blank tape is at Wall([1, 1]) after 13 steps. So the machine halts from blank tape iff the orbit of [1, 1] under F reaches none. The map in Lean is written the way the machine computes it (cascM, tailM, F); #eval of its orbit agrees with py/cascade.py. Proof: 13 rules generated by symtm (the halving round, the start at the wall, the even and odd ends, the gap move, the sweep back, the merge, the halt past the end), and a hand-written induction over the list.

halts_iff, F_correct, casc_correct, tail_correct, blank_to_wall, lean/Cascade.lean; rules in lean/Rules.lean

When the machine halts

In the Lean map, F ns = none exactly when an even halving runs past the end of the list with the value 2 (the next block would be 0): a block can become 0 only past the end of the list, where the carry c is halved again and again (new blocks c/2, c/4, ...) until it is odd; if c is a power of 2 it runs down to a block 0, which is a halt (past_end: the machine then reaches F reading 1 within 62 steps, for every tape to the left). Examples: [2], [2, 1], [4, 2], [6, 1] halt.

The cascade map, checked against the run (before the proof)

At each moment the head, in A, extends the tape to the left, the tape is 0^inf A> 0 0 1^n1 0 0 1^n2 ... 0 0 1^nk 0^inf. The map of py/cascade.py predicts the next list exactly for all 1,779 such moments in the first 109 steps (from (1, 1) at step 13), and the machine's next list agrees with it for 1,500 random lists of 1 to 6 blocks (small and large values), halts included.

No halt in 6·1010 rounds

Iterating the map from (1, 1) for 6·1010 steps (c/cascade.c, about 13 minutes) never makes a block 0; 778,155,275 cascades ran past the end of the list, and the smallest odd part of a carry there is 3. By the theorem above this is a run of the machine of that many wall visits without a halt (trusting the C program's arithmetic).

c/cascade.c

heuristic Evidence only

Growth shape: power/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.354). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.288).

tools/py/bbtools/triage.py

The sum grows by 3 per step; halting is a question of chance

A cascade keeps the sum of the blocks except for the final +2 and +1, so after t steps of the map the sum is 3t + 2, while the number of blocks stays small (5 to 9). About 1.5% of steps run past the end, with a carry of the order of the blocks; such a carry is a power of 2 with probability of order 1/carry. Summed over the future this expected number of halts grows only like the logarithm of the number of steps, so if the carries behave like random numbers the machine would halt eventually, but nothing here predicts when, and nothing rules out a hidden reason that keeps the carries away from powers of 2.

Does it halt from blank tape?

Not known, and now exactly a question about the map: does the orbit of [1, 1] under F ever run past the end of the list with a carry that is a power of 2? That reduction is a Lean theorem (halts_iff); the question about the map is open (Collatz-like).
