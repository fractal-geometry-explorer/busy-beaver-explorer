What is known about 1RB1LE_1RC1RA_0LD1RB_1LE1LD_1RF0LA_---0RE

1RB1LE_1RC1RA_0LD1RB_1LE1LD_1RF0LA_---0RE

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. Its tape is always an alternating block (10)^x next to a solid block 1^y, and the machine moves cells between them by doubling, back and forth. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. Lean proves no halt in the first 10,000 steps by the kernel alone and in the first 107 with native_decide; an exact macro simulator finds no halt in the first 1015 steps. Lean proves the left phase rule (below) for all sizes.

What Lean proves. The whole phase map, every case for all sizes (E(x, z) = E>0 (10)^x 1^z, R(x, y) = (10)^x 1^y C>0 and the bounce frame Q(m, k, t) = (10)^m 1 A>0 0 (10)^k 1^t), and halts_iff: the machine halts from blank tape if and only if the map, iterated from R(0, 2), which the blank tape reaches in 2 steps,, reaches E(x, 0) or E(x, 1). By native_decide the first 108 phases (about 4.1·1021 machine steps) do not. Lean also proves that the even phases lead only to even phases or to an all-ones tape, and checks, for every all-ones tape of length n < 105, that its run halts before the next even phase or all-ones tape exactly when n is 0, 6 or 32·2k − 2k − 12 (20, 50, 112, 238, …). What is not proved: that this list holds for every n, and that the run never lands on it.

Where a halt would come from. F0 halts, and F is entered only from E0: E stands on the 0 at the left end and walks right with F over 0101…, so a halt needs at most one 1 after the alternating block. Probing every two-block tape with sizes below 150, a parity rule keeps that from happening except right after the tape has become all ones; from 1^n C>0 it halts for n = 20, 50, 112, 238 (n = 32·2k − 2k − 12) and for 15 values of n below 40 (all n ≤ 400 checked).

Why it has not halted. All-ones moments are rare: in the first 109 steps the tape was 1^n C>0 at n = 2, 5, 10, 71, 279, 466, 763 and 3002, and between 109 and 1015 steps only at n = 5882, 10234, 12114, 24455, 37818, 48395, 53042 and 405563. None is in the list. The machine very probably never halts, but nothing here proves it.

The machine stops exactly when it reads the symbol of a halting transition (F0); the generated statement covers every configuration.

No halt in the first 10,000 steps

The list simulator of the shared library, proved to agree with the machine's semantics, runs 10,000 steps from blank tape without a halt, evaluated by Lean's kernel.

blank_runs_kernel, lean/Blank.lean

The left phase rule, for all sizes

Lean proves, with rfl steps, the crossing lemmas and induction on the number of bounces, that E(x,z) reaches E(2x+4, z−2x−6) whenever x ≥ 1 and z ≥ 2x + 7 (ephase). The phase is a start piece, one bounce (10)^(m+1) 1 A>0 0 (1010)^j 1^(r+3) to (10)^m 1 A>0 0 (1010)^(j+1) 1^(r+1) per copy of 10, and an end piece, generated by py/gen_rules.py: the proof of 1RB1RD_0LC1RA_0RA1LC_1RA1LE_1RF0LD_---0RE, whose state D plays the part of A here. The right phase and the parity analysis are not proved.

lean/Rules.lean, lean/EPhase.lean

The whole phase map

Write E(x, z) = E>0 (10)^x 1^z, R(x, y) = (10)^x 1^y C>0 and the bounce frame Q(m, k, t) = (10)^m 1 A>0 0 (10)^k 1^t. next sends each of them to the next one the machine reaches (bounces taken all at once), with 18 cases; next_sound proves every case for all parameters (one symbolic run of lean/Pieces.lean each, generated by py/pieces.py, and induction for the bounces). next fails only at E(x, 0) and E(x, 1), which halt (e_halts).

lean/Phases.lean, lean/Pieces.lean

Halts if and only if the map reaches E(x, 0) or E(x, 1)

halts_iff: the machine halts from blank tape if and only if some iterate of next from R(0, 2), which the blank tape reaches in 2 steps, is E(x, z) with z ≤ 1.

lean/Phases.lean

The parity classes

even_next: the even phases (E(x, z) with z even and z ≥ 2, R(x, y) with x ≥ 1 and y odd, Q(m, k, t) with t even) lead only to even phases or to an all-ones tape. So from an even phase the machine cannot halt before the tape is next all ones (even_safe).

Growth shape: power/power

Left of the start, the visited part of the tape grows like a power of the step count other than 1/2 (fitted exponent 0.334). Right of the start it grows like a power of the step count other than 1/2 (fitted exponent 0.342).

tools/py/bbtools/triage.py

Step counts of the phases

From probes: the left phase takes 4x²+24x+30 steps, the right phase y²+6y+7 (y even) or y²+4y+5 (y odd). Doubling costs the square of the block, so the width grows like t1/3.

py/phases.py

Halting needs an all-ones tape from a sparse list

From every two-block tape with x, y, z < 150 the next one was computed. E(x,z) with z even ≥ 2 and C(x,y) with x ≥ 1, y odd lead only to tapes of the same kind or to an all-ones tape 1^n C>0, never to a halt; the machine halts only from E(x,0) and E(x,1). From 1^n C>0 the run goes to E(0, n+1) and then E(4, n−5); the alternating block grows 4, 12, 28, 60, … (x ↦ 2x+4), and the run halts when the ones run out leaving exactly one: n = 20, 50, 112, 238, … = 32·2k − 2k − 12. For n ≤ 37 there are 15 more fatal values (1, 3, 6, 7, 9, 16, 18, 21, 22, 24, 29, 30, 31, 34, 37). All n ≤ 400 checked directly; not proved for all sizes.

Does it halt from blank tape?

Not known. It would need an all-ones tape whose length is in a sparse list; nothing rules that out.
