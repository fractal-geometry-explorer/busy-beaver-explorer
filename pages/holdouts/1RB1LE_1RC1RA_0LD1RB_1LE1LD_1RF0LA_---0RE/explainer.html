Does this machine ever halt?

1RB1LE_1RC1RA_0LD1RB_1LE1LD_1RF0LA_---0RE

Open: a cryptidIts halting is thought to come down to a Collatz-like question that no known method decides (the community's label, not a result).

Nobody knows, but the mechanism is clear. The tape is an alternating block next to a solid block; the machine doubles one at the other's expense, back and forth. It can halt only right after the tape becomes all ones, and only if the number of ones is in a sparse list (20, 50, 112, 238, …, or a few small values).

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 0. F is entered only from E0 (writes 1, moves R): E>0 0. So a halt is the moment this pattern appears, with the head on the cell after >.

Macro structure

Two blocks, doubling

Stop the machine whenever its head first reaches a new cell and the tape is always an alternating block 10 10 10 … followed by a solid block of 1s. With a for 10, around step 4.8·107:

  • step 47,422,764: a^436 1^630 B>0
  • step 47,823,454: a^119 1^1266 B>0
  • step 47,882,082: E>0 a^238 1^1027 1110
  • step 48,114,400: E>0 a^480 1^545 1110

At the right end the solid block doubles (630 to 1266), eating the alternating block; when that no longer fits, the head goes to the left end and the alternating block doubles instead (119, 238, 480), eating the solid one. Writing E(x,z) for E>0 (10)^x 1^z and C(x,y) for (10)^x 1^y C>0:

  • left phase: E(x,z) → E(2x+4, z−2x−6) while z ≥ 2x+8, in 4x²+24x+30 steps: the head bounces between the blocks, each bounce moving one 10 across;
  • right phase: C(x,y) → C(x−⌊y/2⌋−2, 2y+5) while it fits, in about y² steps.

A doubling of a block of size x costs about x² steps and the tape grows by a few cells per phase change, so a tape of width w takes about w³ steps: the width grows like the cube root of time. The split point moves like the doubling map x ↦ 2x on a circle, a textbook chaotic map.

The one way to halt

Halting needs an exact landing

F reading 0 halts, and F is entered only from E reading 0; E and F together walk right over 0101…. So the run halts only from E>0 (10)^x or E>0 (10)^x 1: a left phase that uses up the solid block leaving exactly one 1.

Parity prevents that in the normal course of things: probing all two-block tapes with sizes below 150, if z is even in the left phase and y is odd in the right phase, the next two-block tape is again of that kind or the tape becomes all ones. From 1^n C>0 the left phase restarts at E(4, n−5); the alternating block goes 4, 12, 28, 60, …, using 14, 30, 62, … ones, and the run halts if exactly one is left: n = 20, 50, 112, 238, 496, … (n = 32·2k − 2k − 12), besides 15 values below 40 (every n ≤ 400 checked).

All-ones moments are rare: n = 2, 5, 10, 71, 279, 466, 763, 3002 in the first 109 steps, and only 5882, 10234, 12114, 24455, 37818, 48395, 53042 and 405563 between 109 and 1015. None was in the list. A crude model (a phase change hits an exact value with chance about 1/width) makes such moments rarer and rarer, and each must also land on a list whose members double: the machine very probably never halts. A proof would have to control the exact remainders of a doubling map.

The same mechanism, with other fatal lists, runs in 1RB1RD_0LC1RA_0RA1LC_1RA1LE_1RF0LD_---0RE and its two near-duplicates.

Proof

The phase map in Lean

Every configuration the run passes through at a phase boundary is one of three shapes: E(x, z) = E>0 (10)^x 1^z, R(x, y) = (10)^x 1^y C>0 and the bounce frame Q(m, k, t) = (10)^m 1 A>0 0 (10)^k 1^t. The function next in lean/Phases.lean sends each one to the next shape the machine reaches, and next_sound proves each of its 18 cases for all parameters, from symbolic runs generated by py/pieces.py. Nothing is left out: next is undefined only at E(x, 0) and E(x, 1), and those halt.

So the question is exactly whether the orbit of R(0, 2), which the blank tape reaches in 2 steps, under next reaches E(x, 0) or E(x, 1) (halts_iff). The first 108 iterates do not (native_decide); by the step counts that is about 4.1·1021 machine steps. The even phases cannot reach a halt without an all-ones tape in between, and for all-ones tapes shorter than 105 cells Lean checks which ones lead to a halt first: n = 0, 6 or 32·2k − 2k − 12 (20, 50, 112, 238, …). The last open step is to prove that list for every n and to show that the run never hits it.

Kernel
lean/Rules.lean, lean/EPhase.lean
The left phase rule, for all sizes

Lean proves, with rfl steps, the crossing lemmas and induction on the number of bounces, that E(x,z) reaches E(2x+4, z−2x−6) whenever x ≥ 1 and z ≥ 2x + 7 (ephase). The phase is a start piece, one bounce (10)^(m+1) 1 A>0 0 (1010)^j 1^(r+3) to (10)^m 1 A>0 0 (1010)^(j+1) 1^(r+1) per copy of 10, and an end piece, generated by py/gen_rules.py: the proof of 1RB1RD_0LC1RA_0RA1LC_1RA1LE_1RF0LD_---0RE, whose state D plays the part of A here. The right phase and the parity analysis are not proved.

Heuristic
py/phases.py probe, py/phases.py ones
Halting needs an all-ones tape from a sparse list

From every two-block tape with x, y, z < 150 the next one was computed. E(x,z) with z even ≥ 2 and C(x,y) with x ≥ 1, y odd lead only to tapes of the same kind or to an all-ones tape 1^n C>0, never to a halt; the machine halts only from E(x,0) and E(x,1). From 1^n C>0 the run goes to E(0, n+1) and then E(4, n−5); the alternating block grows 4, 12, 28, 60, … (x ↦ 2x+4), and the run halts when the ones run out leaving exactly one: n = 20, 50, 112, 238, … = 32·2k − 2k − 12. For n ≤ 37 there are 15 more fatal values (1, 3, 6, 7, 9, 16, 18, 21, 22, 24, 29, 30, 31, 34, 37). All n ≤ 400 checked directly; not proved for all sizes.

The parity classes
