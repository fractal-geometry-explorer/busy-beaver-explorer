Does this machine ever halt?

1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_1LC---

Nobody knows, but the machinery is clear. In frame A the tape is a list of blocks (10)^b; the head works through them like a nested counter in base 5, and the only way to halt is a rare F-event going wrong. The counter is proved in Lean for every depth; run as an exact map on block lists it reaches 2.2·10100 steps and meets 90 F-events, all harmless.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from D1 (writes 0, moves L): 1 D>1. So a halt is the moment this pattern appears, with the head on the cell after >.

The family

One core, forty machines

This machine is one of 40 holdouts built on the same five states. Written in one common frame (frame A), every one of them has the table

stateABCDEF
reads 01RB0RC1LD0LE1LAF0
reads 10LC0RB0RE0LF or 1LF0LBhalt

and they differ in three things only: the bit that D writes on its way into F (D1), what F does on a 0 (F0), and the state the run starts in. This machine is the core itself (frame A) with D1 = 0LF and F0 = 1LC, started in state A. Lean proves this for the machine's own table (halts_iff in lean/Family.lean): it halts from blank tape exactly if the frame-A table halts from blank tape in state A.

What the 40 machines share. States A to E never enter F while they run the nested counter, so between two entries into F all 40 machines do the same thing, and one law covers them. In frame A the tape is a list of blocks (10)^b; a visit to the list [b1, …, bk] makes five visits to the list without its first block. When the blocks are large and of the right parity (a clean visit) this has a closed form: b1 loses 5, block i loses 18·5i−2, the last block gains 12·5k−2. Both the recursion and the closed form are Lean theorems for every depth, on each of the 40 tables (go_spec, go_closed). Two quantities are therefore conserved by every clean visit (visit_conserves): the residue of block i modulo 18·5i−2, and the drift bi+1 − 5·bi of two neighbouring blocks (neither the first nor the last). The residue fixes at which phase and with which small value a block will run out; the drift is the length the next block still has at that moment.

This machine's run, seen from the left end. Each time the head comes back to the left end of the tape (frame A) the tape is a plain list of blocks. Move the slider through these moments: the middle blocks drain at their fixed rates, the last block grows, a block that runs out disappears and its neighbours merge, and new blocks are born at the right end. The list is from the exact block-list map (below), which was checked against the plain simulation of the machine on the F-events of the first 3·109 steps.

How far it has been run. The exact block-list map (clean visits by the proved closed form, every other visit by an exact run-length simulation) runs this machine for 2.1·10200 steps without a halt: 577 returns to the left end, 192 entries into F, every one reading 0, with the tape around the head 010001000100[F]001010101010 (149×, F reads 0); 010001000100[F]001010110101 (43×, F reads 0). Every one of these entries is the kind proved harmless in Lean (fevent, fevent_reads_zero): a visit ends in state C on the 0 of a phase-1 tail, and F then reads the last cell of a 1000.

Why this does not settle halting. A clean visit cannot halt, and an isolated exceptional event (one block running out between long neighbours, a birth, the harmless F-event) does not halt in any run so far. Short block lists of the same shape do halt, so a proof has to control the block lengths: it would have to show that two exceptional events never fall close together, that is, that a drift is never small when its block runs out. The drifts only change at exceptional events, where they are sums and differences of large earlier blocks; nothing is known that keeps them away from 0. Observed in this run, at the left-end events: after step 1020 the smallest drift in absolute value is 92,200, after step 10100 it is 223,584. That is evidence, not a proof, and it is sampled at the left-end events only.

The mechanism

Blocks of 10 and a nested counter

Away from rare moments the tape (in frame A) is a list of blocks: runs (10)^b separated by single 1s. At an event the head, in state A, has just turned right at the left edge of the blocks it is about to work on; everything to its left is spread out as (1000)^q ending in a short tail.

A round on the last m blocks runs the head right over them (state B, six steps per 1010, which becomes 0100) and back (states E, A, C, D, four steps per 1000). A round on blocks j..k contains five rounds on blocks j+1..k, so the work is nested like a counter in base 5, and a round on the last m blocks changes them by:

(From phase 1 of the tail the first block gets 2 more.) After the round the tail on the left has moved one phase on (10, 1, 1001, 101, 11); after five phases one 1000 of the spread block on the left is used up, which is how the deeper block counts down. Between consecutive events of this run: 11,007 events in 10^8 steps; transitions: same 5,300, same* 1,749, down 2,166, up1 1,413, up2 284, up3 55, up4 11, up5 1, X 27.

The whole run

A visit calls five visits

Cut the run into visits: a visit starts when the head (state A) stands just left of a list of plain blocks and ends when it steps back out to the left. It never looks at the tape on its left, so its outcome depends on the list alone. A visit to [b1, b2, …, bk] with b1 odd spreads b1 (PUSH), then makes five visits to the shorter list [b2+1, b3, …], nudging the tail between them (+3, +1, +1, +1), and finally folds b1 back up, 5 smaller (POP). That is a counter in base 5, and it is now a Lean theorem for every depth.

When the blocks are big enough the whole visit has a closed form: b1 loses 5, block i loses 18·5i−2, the last gains 12·5k−2, in about Σ 5i+1bi steps (also proved). The rest are exceptions: a single even block gives birth to a new last block 8 (proved), a block that runs out merges with its neighbour, and the left end sees an even first block.

Doing clean visits by formula and only the exceptions cell by cell gives an exact simulator of the machine that reaches 2.2·10100 steps in 17 seconds; it agrees with the plain simulation event for event for the first 1011 steps.

The halting condition

Where a halt could come from

Only D1 enters F; F1 halts, F0 = 1LC (frame A) lets the run go on. In 2.2·10100 steps of the exact map there are 90 F-events, all reading 0, of two kinds: 010001000100[F]001010101010 (74×); 010001000100[F]001010110101 (16×).

All of them happen the same way: an unclean visit ends in state C instead of B, on the 0 of a spread block's tail 10. C0 writes 1 and steps left onto the tail's 1, D1 sends the head into F one cell further left, and that cell is the last 0 of a 1000 (or of the 100 that starts a spread block). This is proved for every tape around (fevent_reads_zero), so these F-events can never halt.

A halt would need a different way in: an unclean visit that exits into F directly, or a C exit onto some other tail. Random block lists do that now and then (about once per 150 F-entries), so the question is whether the lists that the blank-tape run builds avoid it forever. Nobody has proved that.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.076). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.534).

After 109 steps the tape spans 87,185 cells (53 left of the start, 66,632 right), with a density of 1s of 0.312.

For the blocks after the first, the last one left out: a clean visit (a list the closed form applies to) changes neither the residue of block i modulo 18·5i−2 nor the drift bi+1 − 5·bi of two neighbours. Halting would need two exceptional events close together

A clean visit cannot halt, and in the runs every exceptional event with long blocks around it ends without a halt; short lists of the same shape do halt. When block i runs out, the next block has about the length of their drift, so a second event close by needs a drift near 0 at that moment. Observed at the left-end events of this run: after step 1020 the smallest drift in absolute value is 92,200, after step 10100 it is 223,584. New drifts are made of sums and differences of earlier blocks, which grow with the run, so close pairs of events should become ever rarer; but nothing proved keeps a drift away from 0, and the figures are sampled at the left-end events only.

The visit rule for every depth

A visit starts with the head in state A on the 0 in front of plain blocks (10)^b1 1 (10)^b2 1 … 1 and ends when it first steps left of that cell; it never reads the tape on its left. go_spec proves, by induction on the depth n and for every left context, that a clean visit (a decidable condition: every block it spreads is odd and ≥ 7, every second block nonempty) turns the list l into go n l in exactly goT n l steps, where go is the recursion: spread b1, five visits to [b2+1, b3, …] with the tail bumps +3, +1, +1, +1 between them, then b1−5. It is built from seven rules (PUSH, TURN, TAIL1–4, POP) proved by bbtools.symtm for all counts.

Where a halt would have to come from

F is entered only by D1 (D reads a 1 during the left sweep, where a spread block is turned back), and halts only when it then reads a 1. In this run every F-event has the same clean context (010001000100[F]0010101 (5×)). Random block lists do reach a halting F-event (about 1 in 150 F-entries; e.g. [15, 31, 17, 59, 31] halts after 63,153 steps), so the halt is reachable in principle; whether the blank-tape run ever produces such a list is the open part. Does it halt from blank tape?

Not known. The visit rule is proved for every depth, its closed form, births and the F-event too; what is missing is a proof that the unclean visits of the blank-tape run (merges, small first blocks, the left end) always end in a C exit of the proved kind and never in an F exit onto a 1, that is an invariant on the block lists reached from blank tape.

tools/py/bbtools/triage.py
Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.076). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.534).
