1RB0LE_1LC0RA_1LD0RC_1LE1LF_1LA0LC_0LA---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. The machine is a macro machine on lists of numbers: the tape at the left end is A>1 (10)^N sep (10)^w1 sep … (10)^wk sep W, and one sweep takes the fuel N to N−2 and rewrites the start of W by one of a dozen local rules. Lean (kernel) proves such a sweep, with the done blocks w1…wk arbitrary (any number, any values ≥ 2), for the window rules that carry the run; the machine has no halting move inside them. The full list of rules (py/mac14.py) is checked against the machine for 2·107 steps sweep by sweep and at all 33 refills up to 1010 steps, and runs 187,450 sweeps without meeting a case it does not cover. Not proved: the rare fuel-1 sweep and windows with small values, and above all that the run never leaves the rules.

kernel Proved in Lean, kernel-checked

The halting configurations

The machine stops exactly when it reads the symbol of a halting transition (F1); the generated statement covers every configuration.

step_none_iff, lean/Blank.lean

The cell pieces of a sweep

Leaving the left end (start_s, start_z), crossing a done block going right (rb) and coming back (lbA, lbD for values ≥ 4, lb3A … lb2D for 3 and 2), the end at the left (endA_s … endD_0), 14 window rules and the pair rule on the fuel block, each for every value of its counts and every tape around it. Written by bbtools.symtm.prove.

lean/Rules.lean, py/gen_rules.py

One sweep over any list of done blocks

sweep_gen: for fuel n+3, any list of done blocks of values ≥ 2 and any window rule that turns back in state A, the machine goes from cfg (n+3) ds W to cfg (n+1) ds W'. sweep_gen2 (fuel 2 → 0) and sweep_gen0 (fuel 0: refilled to 2) likewise. Proved by induction over the list (rpass, lpass).

sweep_gen, rpass, lpass, lean/Macro.lean

The window rules

With fuel ≥ 3 and any done blocks: the pair rule x s y → x+4 s̅ y−1 (pair_dot, pair_bang), append, p1_bd, p1_bb, p1_db, p1_dd (two blocks merge), merge, end_db, next, end_b, restart2; and the pair rule on the fuel block itself (own_dot, own_bang, with step counts).

lean/Macro.lean

The macro machine agrees with the machine

py/check.py 2e7 checks every one of the sweeps of the first 2·107 steps against the macro rules. py/r14.c prints the tape at every refill (fuel 0) up to 1010 steps; py/cmp.py finds the macro machine equal to it at all 33 of them (74,633 sweeps).

187,450 sweeps inside the rules

py/far.py runs the macro machine 187,450 sweeps (far past 1010 machine steps) and never meets a window or fuel case that its rules do not cover.

py/far.py

heuristic Evidence only

Growth shape: fixed/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.498). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

Does it halt from blank tape?

Not known. A proof would need an invariant on the lists that the macro rules preserve (so that no window ever falls outside them), plus Lean proofs of the remaining cases: the sweep with fuel 1 (two rules in one visit), the windows with small values, and the rules on the fuel block other than the pair rule.
