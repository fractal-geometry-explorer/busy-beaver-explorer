Does this machine ever halt?

1RB0LE_1LC0RA_1LD0RC_1LE1LF_1LA0LC_0LA---

Nobody knows. The tape turns out to be a list of numbers, written as blocks of 10s, with a fuel counter at the left end. Each sweep of the head spends 2 units of fuel and does one small piece of arithmetic at the first unfinished block; when the fuel runs out, a finished block becomes the new fuel. Lean proves the sweep exactly; the rules have run 187,450 sweeps without a gap.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 1. F is entered only from D1 (writes 1, moves L): 1 D>1. So a halt is the moment this pattern appears, with the head on the cell after >.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.498). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

After 109 steps the tape spans 80,103 cells (49,545 left of the start, 733 right), with a density of 1s of 0.499.

Structure

The tape is a list of numbers

Watch the tape whenever the head, in state A, stands on the leftmost visited cell, on a 1. Read from there, the tape is blocks of 10 separated by single cells: a list v0 s1 v1 s2 v2 … of numbers (how many 10s) and separators (. for 0, ! for 1). The first number is a fuel counter N. Then come done blocks, each followed by the 5-cell separator 0 1 1 0 0 (. 0 ! 1 . in the list), and then the window, the first block that is not done:

Here N = 3, one done block of 2, and the window 2 . 3.

The basic move

One sweep: fuel −2, one rule at the window

From the left end the head runs right in state B. It crosses each done block, leaving it in a temporary form ((10)^w sep becomes (01)^(w−1) 1010101), does a few dozen steps of work at the window, and turns back in state A. On the way back it puts every block back, two cells further left, and at the left end the fuel has dropped by 2. The commonest rule is the pair rule: x s y → x+4 s̅ y−1 (the separator flips):

The sweep costs about 2 steps per cell of the done blocks plus 4 per 10 of the window. Lean proves it for every list of done blocks, by induction over the list (rpass, lpass, sweep_gen).

The macro machine

A dozen local rules

What happens at the window depends only on its first few entries (x is the value there):

When the window is the fuel block itself, its own pair rule runs (own_dot, own_bang). When the fuel is 0, the sweep refills it: the list 0 sep v1 … becomes 2 . v1 …, so the first done block joins the fuel (sweep_gen0). Fuel 1 is a special case where one visit applies two rules; that case is not yet proved in Lean.

The emergent behaviour

Carries and powers of four

Each refill turns the leftmost done block into fuel, and the fuel pays for pair rules that multiply the window by about 4 while counting its neighbour down. Many of the done blocks that result have the form 4k−2 (2, 14, 62, 254, 1022, 4094, 16382, …), and long runs of 2-blocks pile up at the right end. The run is like an odometer with irregular digits: the big blocks on the left grow by factors of 4, the short blocks on the right accumulate, and carries ripple through the middle. Every refill so far has been followed by enough work to reach the next refill; nobody has a proof that this always happens.

Status

What is proved and what is missing

Lean, kernel: the cell pieces of a sweep (lean/Rules.lean, written by bbtools.symtm), one whole sweep for any done blocks and the window rules above (lean/Macro.lean).

Computed: the full macro machine (py/mac14.py) checked against the machine sweep by sweep for 2·107 steps and at every refill up to 1010; 187,450 sweeps without leaving its rules.

Missing: the fuel-1 sweep, small-value windows and the other fuel-block rules in Lean; a statement that puts all rules together as one map on lists; and an invariant showing the lists always stay inside the rules. Halting would need a window outside every rule; inside the rules proved in Lean the machine never reaches the halting move F1.

sweep_gen, rpass, lpass, lean/Macro.lean
One sweep over any list of done blocks

sweep_gen: for fuel n+3, any list of done blocks of values ≥ 2 and any window rule that turns back in state A, the machine goes from cfg (n+3) ds W to cfg (n+1) ds W'. sweep_gen2 (fuel 2 → 0) and sweep_gen0 (fuel 0: refilled to 2) likewise. Proved by induction over the list (rpass, lpass).

Open
Does it halt from blank tape?

Not known. A proof would need an invariant on the lists that the macro rules preserve (so that no window ever falls outside them), plus Lean proofs of the remaining cases: the sweep with fuel 1 (two rules in one visit), the windows with small values, and the rules on the fuel block other than the pair rule.
