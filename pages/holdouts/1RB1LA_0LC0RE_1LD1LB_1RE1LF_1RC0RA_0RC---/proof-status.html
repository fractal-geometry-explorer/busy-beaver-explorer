What is known about 1RB1LA_0LC0RE_1LD1LB_1RE1LF_1RC0RA_0RC---

1RB1LA_0LC0RE_1LD1LB_1RE1LF_1RC0RA_0RC---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open. The machine is a base-4 counter of walls in a sea of 100, incremented from the right end. Lean proves one sweep for every carry chain (any length) for every edge event seen: the overflow, four kinds of merger and seven left-end cases; an exact digit simulator, checked against the direct run, ran to 2.2·1015 steps without a halt or an unknown event. No closed set of digit configurations has been found: the safe mergers depend on a mod-4 relation between neighbouring digits.

Other proofs and outside reports

Community label

In the community's BB(6) tracker the machine's class is Skelet 1-like Class 1. These are labels read off the run by others, not results.

The shift rules

Going right, E turns (101)n and (011)n into (010)n, A turns (011)n into (100)n, B turns (110)n into (001)n; going left, D turns (100)n back into (101)n, B and C rewrite (010)n and (001)n, A runs over 1s. Each for every n and every surrounding tape.

lean/Rules.lean (from py/rules.py)

One sweep adds one, for a carry chain of any length

At the sample point (C on a 0 at the right end) the tape is a list of digits (100)^r W. With the first non-S3 digit (the stop) in shape S0, S1 or S2 and any list ts of S3 digits after it (any length, any runs), one sweep turns the stop into the next shape (S0→S1, S1→S2 with its left run one shorter, S2→S3), every S3 of the chain into S0, and lengthens the last run by one. Proved by induction on the list (seqtm).

sweep_s0, sweep_s1, sweep_s2, lean/Sweeps.lean, lean/Seq.lean

The overflow, the mergers and the left end

0^inf 10 followed only by S3 digits (any number): one sweep crosses the whole tape, every S3 becomes S0 and a new digit S1 is born at the right end (overflow). An S1 with left run 0 receiving a carry fuses with the wall before it: after S into one S0 (merge_s_s1), after S3 into S and S0 (merge_s3_s1), after S2 into X6 = 1000000 (merge_s2_s1); X6 and X5 as stops (sweep_x6, sweep_x5). At the left end, eight cases with a first digit of run 0 (left_s_s1, left_s0, left_s1, left_s2, left_s3, left_s_s0, left_s_s2, left_s3_s). Each for any carry chain.

The digit model is exact

py/digits.py maps one sample to the next by running the machine symbolically (symtm) on a window (the carry chain, the stop, and as many digits before it as the run touches; the rest an unknown context; long runs as variables). Compared with the direct run from blank tape: the same tapes and the same step counts at all 14,148 sample points up to 2·108 steps.

No halt in 2.2·1015 steps

From the sample at 2·109 steps the digit model ran 4.9·107 sweeps more, to 2.2·1015 steps: no halt and no window it could not read back as digits; overflows and mergers as described, the first block went from 14 down to 0 (one per overflow) near 2.1·1015 steps, the left end rearranged ([0]S3 [0]S [436]S0 → [0]S [0]S0 [435]S0) and the counter went on.

No halt in the first 1.77×1019 steps (exact macro run)

A macro simulator (blocks of 6 cells, long runs of equal blocks crossed in one go; exact: every macro step is a run of the machine, counted step for step) ran from blank tape to step 17,748,289,296,345,434,315 without a halt. At this block size it gives the same state, head position and tape as the direct simulator after 2,000,017,009 steps. This is a bounded run and says nothing about later steps.

heuristic Evidence only

Growth shape: exp/sqrt

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.064). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.539).

tools/py/bbtools/triage.py

Why it probably never halts

Every event seen is one of a small catalogue of local rewrites of digits, each a Lean rule, none of which reaches F on a 1. The dangerous mergers (an S1 of run 0 after S0 or S1, which would leave the vocabulary) never occur, because of a mod-4 relation: for neighbouring digits y x, phase(y) + run(x) + [x is S2 or S3] mod 4 is fixed while both live, and is 2 or 3 in 2,091,564 of 2,092,788 neighbour pairs over the first 3·105 sweeps (the rest inside S[0]S0 compounds).

py/closure.py kinv; README, Notes for later

No small closed language

The fixpoint search py/closure.py ngram (every place a sweep can happen in a word of the language, run symbolically) does not close for bigrams or trigrams with run classes 0, 1, ≥2, nor for bigrams with residues mod 4, a marked left end and the compounds S[0]S0, S[0]S1 (536 bigrams, then windows with X5 or X6 before an S1 of run 0, which the real run never shows).

Does it halt from blank tape?

Not known. Missing: a closed set of digit configurations. n-gram languages over (wall, run class), with classes 0/1/≥2 or with residues mod 4, compounds and a marked left end, all fail to close in py/closure.py, and cell-level closed tape languages (windows of 3..7 cells, block trackers) do not close within 4·105 abstract configurations. Also missing: carry chains with an S3 of run 0 in seqtm, and the assembly in Lean.
