What is known about 1RB0LD_1RC1RF_1LA0RA_0LA0LE_1LD1LA_0RB---

1RB0LD_1RC1RF_1LA0RA_0LA0LE_1LD1LA_0RB---

Nobody knows whether this six-state, two-symbol Turing machine halts when started on a blank tape: it is one of the holdouts left open by the bbchallenge project. This page lists what has been established about it, sorted by what each result rests on.

Status as of 8 November 2026.

In short

The question is open, and reduced in Lean to a Collatz-like orbit. The machine follows (Lean, kernel) the map (3k, y) → (4k+1, y+4), (3k+1, y) → (4k+5, y+6), (3k+2, y) → (4k+8, y−1) on its walls, and never halts as long as that orbit, started at (0, 0), never reaches y = 0 with z not a multiple of 3 (not_halts_of_orbit). With native_decide: the first 10,000 macro steps stay inside the rules, so no halt in the first 102400 steps. In Python the orbit ran 106 macro steps (z has 124,940 digits) and y only grew, to 2,999,377; it never came below 4. The counter y behaves like a random walk with drift +3 per step, so an exit looks hopeless, but proving that is a Collatz-type problem, like bbchallenge's Antihydra.

Other proofs and outside reports

Community label

In the community's BB(6) tracker the machine's class is Bell-like. Its 3 November 2026 edition lists the machine as a cryptid: its halting is thought to come down to a Collatz-like question that no known method decides. These are labels read off the run by others, not results.

The cell rules

One sweep A>0 (10)^x 0 10 0^(z+3) → A>0 (10)^(x+2) 0 10 0^z in 4x + 11 steps, for every x, z and every tape to the right; and the six ends of a wall (z = 0, 1, 2 left, x = 0 or x ≥ 1), for every x and y. Written by bbtools.symtm.prove.

sweep_cells, end0s … end2z, lean/Rules.lean

The macro rules

With the wall C z y = A>0 0 10 0^z (10)^y 0 1: k sweeps at once (sweeps, cost 4k² + 7k from x = 0), and the three ends end0: S x 0 (y) → C (2x+1) (y+4), end1: S x 1 (y+1) → C (2x+5) (y+7), end2: S x 2 (y+1) → C (2x+8) y.

sweep, sweeps, end0, end1, end2, lean/Macro.lean

The machine follows the map on (z, y)

next z y: (3k, y) → (4k+1, y+4); (3k+1, y) → (4k+5, y+6); (3k+2, y) → (4k+8, y−1), the last two for y ≥ 1. next_sound: the machine goes from C z y to the next wall in exactly mcost z y steps. From blank tape the first wall C 0 0 comes after 7 steps (init_wall).

next_sound, init_wall, lean/Reduce.lean

Why an exit looks hopeless

If z mod 3 behaves like a fair die, y is a random walk with steps +4, +6, −1 (drift +3). From height y it ever reaches 0 with probability about 0.335y; y is 2,999,377 after 106 steps and was never below 4. Every exit would still have to halt from C z 0, which only some do (C 92 0 halts after 54,805 steps; C 8 0 does not in 106).

py/orbit.py, README.md

Growth shape: fixed/sqrt

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.5). Right of the start it stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half).

Does the orbit ever exit?

Not known: whether the orbit of (0, 0) ever has y = 0 with z not a multiple of 3 is a Collatz-type question about the digits of z in base 3, like Antihydra.
