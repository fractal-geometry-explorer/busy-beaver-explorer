Does this machine ever halt?

1RB1RF_1LC---_1LE1RD_1RA0RC_0LF0LA_0LD0RB

Nobody knows yet, and it looks like a Collatz problem. The tape is a block of ones followed by a block of 01s, and the machine keeps trading one for the other: doubling the ones, paying in 01s, then draining the 01s back into ones. It stops only if a doubling leaves exactly one 01. In 8,598 epochs (more than 103,100 steps) that has not happened.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in B reading 1. B is entered only from A0 (writes 1, moves R): A>0 1; F1 (writes 0, moves R): F>1 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

First look

The shape of the run

Left of the start, the visited part of the tape grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.433). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.09).

After 109 steps the tape spans 24,444 cells (16,450 left of the start, 167 right), with a density of 1s of 0.651.

The tape

Ones, then 01s: a map on two numbers

Each time the head turns at the left end the tape is 1n (01)k 111, or all ones. Write A(n, k) or D(n, k) for that tape with the head in state A or D. The next left-end state is:

stateconditionnext
all ones, n oddD(1, (n+1)/2) from A, D(3, (n+1)/2) from Dconversion
all ones, n evenother(n+3, 0)
n evenk ≥ 2other(n+4, k−1)drain
n evenk = 1other(n+7, 0)all ones again
n odd2k > n+5D(2n+7, k−(n+5)/2) or A(2n+6, k−(n+5)/2)doubling
n odd2k = n+5all ones: D(2n+10, 0) or A(2n+9, 0)
n odd2 ≤ k, 2k < n+5other(n−2k+6, 2k)failed doubling
n oddk = 1halt

(“other” is the other letter.) From blank tape: D(3,0) → D(3,2) → A(5,4) → D(3,8) → D(13,4) → A(11,8) → A(31,0) → D(1,16) → D(9,13) → D(25,6) → A(19,12) → A(47,0) → … The all-ones states D(N, 0) are the epochs: N = 3, 124, 583, 2143, 8167, 34679, …, growing by a factor 2.3 on average. An epoch takes about N2 steps, which is why the tape grows like the square root of the step count.

The map was found from the run and is checked against the plain machine on more than 7,000 built tapes and on the run from blank tape; it is not yet proved in Lean (only the drain is).

Does it halt?

Only if a doubling leaves exactly one 01

The only halt is state B reading 1; Lean proves the kind of sweep that does it: state D over an even block of ones that ends in 0 111. On the map the halt comes from a state with n odd and k = 1, and it can only come from a doubling in D: D(n, k) with 2k = n+7 goes to D(2n+7, 1) and stops. (A doubling in A leaves n even; a failed doubling leaves k even.) For example the tape of 26 ones halts: D(26,0) → A(29,0) → D(1,15) → D(9,12) → D(25,5) → A(21,10) → D(7,20) → D(21,14) → D(49,1) → halt.

From blank tape the map has been followed through 8,598 epochs, more than 103,100 steps, and 2k = n+7 never occurred in state D. Each doubling stage leaves a remainder that looks random between 0 and n/2, so the chance of hitting exactly 1 shrinks like 2/n while n grows geometrically: the machine almost certainly never halts. Proving it would mean controlling exact remainders along an exponentially growing orbit, as for the Collatz-like cryptids.

How a halt happens

A sweep in state D over an even block of 1s that ends in 0 111 reaches B on a 1 (no transition) in 2n+3 steps, whatever lies to the right; over an odd block ending in 0 1111 it passes to the right end.

The left-end map

With A(n, k), D(n, k) the head in state A two cells (D: three cells) left of 1n (01)k 111 (k = 0: 1n): for n even, s(n, k) → other(n+4, k−1), and other(n+7, 0) when k = 1, other(n+3, 0) when k = 0; A(n, 0) → D(1, (n+1)/2) and D(n, 0) → D(3, (n+1)/2) for n odd; for n odd and k ≥ 2: D(n, k) → D(2n+7, k−(n+5)/2) and A(n, k) → A(2n+6, k−(n+5)/2) when 2k > n+5, all ones of length 2n+10 resp. 2n+9 when 2k = n+5, other(n−2k+6, 2k) when 2k < n+5; n odd and k = 1 halts. Equal to the plain machine on all 7,000 states with n < 70, k < 50, 300 random larger states, the first 170 left-end states from blank tape and every epoch N ≤ 150; its epoch values agree with the 126 epochs of the accelerated run to 10100 steps. Checked, not proved.

py/emap.py, py/leftcheck.py
The halting condition

By the map, the machine halts iff the orbit from D(3, 0) reaches D(n, k) with n odd and 2k = n+7: the doubling leaves one pair, D(2n+7, 1), and the machine stops within the next sweeps (the Lean lemma halt_even shows the kind of sweep that stops it). A doubling in A leaves n even and a failed doubling leaves k even, so there is no other way.

Heuristic
py/orbit.py
A halt needs an exact remainder

Each doubling stage in D ends with a remainder between 0 and about n/2, and a halt needs it to be exactly 1: about 2/n per stage if remainders behave like random numbers, with n growing geometrically. Past the epochs already followed the chance is around 2−10,000.

Does it halt from blank tape?

Not known. It is the question whether the orbit of the left-end map ever reaches D(n, (n+7)/2) with n odd: a Collatz-like question. The map and this reduction are computed, not yet proved in Lean (the doubling stage, a nested zig-zag, is the missing part).
