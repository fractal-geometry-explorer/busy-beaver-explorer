Does this machine ever halt?

1RB0RC_0RC1RC_0LD0RA_1LE0LF_0LA1LC_---1LA

It never halts, and Lean proves it. Two blocks of the tape trade places, about seven times longer each round; now and then the left block is poured into a third block at the far right. After 1.8·1015 steps the whole pattern repeats exactly, with only that third block longer each time.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in F reading 0. F is entered only from D1 (writes 0, moves L): 0 D>1. So a halt is the moment this pattern appears, with the head on the cell after >.

statereads 0reads 1
A1 R B0 R C
B0 R C1 R C
C0 L D0 R A
D1 L E0 L F
E0 L A1 L C
Fhalt1 L A

Tape as words

Seven-cell words on the left, three-cell words on the right

Look at the tape each time the head, in state E, reaches the left end. It is a block of seven-cell words 1011001, a short irregular zone, and then blocks of the three-cell word 011 separated by a few zeros. The last block, (011)^r, ends the tape.

Going right, the head shifts a block of three-cell words by one cell. Going left, it crosses two words at a time. So what happens at the end of a block depends only on whether its length is even or odd: every rule found has the form “for all lengths of this parity”.

Macro behaviour

Collect, expand, drain

Three regular phases take almost all the time. p counts the seven-cell words, q or m the three-cell words of the middle block, r those of the last block.

phasetape when state E reaches the left endone cycle
collect0 (1011001)^p (101)^5 10 (011)^q 000 (011)^r2 visits: p + 2, q − 2
expand0 (1011001)^p 1011 0^5 110110011010 (101)^m 1000 (011)^r4 visits: p − 2, m + 14
drain0 (1011001)^p 1011 0^5 1101100110110 (011)^16 001101100110 (011)^r72 visits: p − 52, r + 414

Collecting turns three-cell words into seven-cell words one for one; expanding gives seven three-cell words back for each seven-cell word. So each round the blocks are about seven times longer: about 600, 4,370, 30,750, 215,000, 1,506,000 words. Collect and expand are proved in Lean for any number of cycles, by hand and again, with the drain, by the executor.

Between the phases there are short irregular stretches where the separators collide. Usually the next round starts. Sometimes the stretch ends in the drain pattern: then the whole left block is poured into the last block (414 words for 52), and the left part starts again from a small state, in front of a much longer last block.

Why it never halts

The left part comes back to the same state

The left part of the tape never needs more of the last block than the parity of its length, and a drain adds an even number of words. After the second drain the left part reaches a state that it meets again, exactly, two drains later:

E> 0 (1011001)^59 1011 00000 1101100110110 (011)^16 001101100110 (011)^r

first with r = 16,797,709 (step 1,818,198,163,340,705), then with r = 337,840,637 (step 725,814,446,706,290,623), then 658,883,565, and so on: 321,042,928 more each time, 116,320,154 visits of the left end apart.

To prove that this goes on for ever, one period is run with r replaced by 65 + 2x, x unknown. Whenever a step would depend on the value of x the run stops; it never had to. It ends in the same configuration with 65 + 321,042,928 + 2x. So every odd r ≥ 65 leads to a larger odd r, and no halting step occurs on the way. A configuration that keeps coming back, larger, never halts.

All of this is a Lean proof. The program that runs the period (a symbolic executor: it moves over whole blocks at once and applies a proved cycle many times in one go) is written in Lean and proved correct once: whatever it does, the machine does, for every x. Lean then runs it: 5.0 million moves from blank tape to the first C(r), 5.6 million moves for one period. Those two runs are done by compiled code (native_decide), which is the one thing trusted beyond Lean's kernel. The exact step counts quoted above come from separate simulators, which agree with each other and with a plain simulator on the first 1010 steps.

A narrow escape

Almost the same tape halts

With 61 words instead of 59 in the left block, the same pattern halts after about 1.8 million steps, for every odd r. With r even instead of odd, it halts too, much later. Tapes of the same general shape with other counts halt in a few percent of random trials.

So there is no simple description of “safe tapes” that contains the run: it is safe because it sits on one exact orbit. That is why the automatic deciders, which look for such descriptions, left this machine open, and why the proof follows the orbit itself.

A growth cycle implies non-halting

With C(r) = E> 0 (1011001)^59 1011 00000 1101100110110 (011)^16 001101100110 (011)^r: if the run from blank tape reaches some C(65 + 2x), and every C(65 + 2x) reaches C(65 + 2(x + 160,521,464)) in at least one step, the machine does not halt from blank tape. The two hypotheses are proved by the replay below.

Kernel
run_sound, run_pos, rule_instN, ruleOK_of_run in lean/Exec.lean; shRTbl_ok, shLTbl_ok in lean/ExecData.lean
A symbolic executor, proved sound

Tapes are lists of cells and blocks (w)^n with n = c + a0x0 + a1x1 + …, the x free. A move is a shift rule from a table (a block crossed at once, one or two copies at a time), or one machine step, and at each arrival of state E at the left end a re-bracketing of the tape and a cycle rule applied N times at once. Any step that would depend on a variable fails. Theorem: if the executor goes from S to S′ in k moves and its tables are valid, the machine goes from S to S′ for every value of the variables. The 31 shift rules are proved by evaluation in the kernel; the N-fold application of a cycle rule by induction.

native_decide
rule0_ok … rule11_ok, lean/ExecData.lean
Twelve cycle rules, for all values of their counts

Each rule says: this tape with counts bi + 2xi comes back with counts bi + Di + 2xi, for all xi (eleven are collect or expand, plain or with inert zones in between, 2 or 4 visits; one is the drain, 72 visits, 201,007 executor moves). Each is one run of the executor without cycle rules, evaluated by native_decide.

Neighbouring classes halt

The same pattern with 61 words in the left block halts for every odd r ≥ 65, after 1,772,276 + 5,220 (r − 65) steps (confirmed by plain simulation for r = 65, 67, 71); C(r) with r even ≥ 64 halts at its 21,362,421st event. So the real run is safe only because of the exact orbit it is on.

Independent check of the growth cycle

A second accelerated simulator, written from scratch without reading the first (verify/sim3.cpp, validated against plain simulation to 1010 steps), lands exactly on C(16,797,709) at step 1,818,198,163,340,705 from blank tape, and takes C(r) exactly to C(r + 321,042,928) at the predicted step for r = 65, 67, …, 85 and r = 16,797,709.
