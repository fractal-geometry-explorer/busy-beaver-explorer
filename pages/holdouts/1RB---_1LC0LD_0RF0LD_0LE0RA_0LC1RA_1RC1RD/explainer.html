Does this machine ever halt?

1RB---_1LC0LD_0RF0LD_0LE0RA_0LC1RA_1RC1RD

OpenNobody has proved whether this machine halts. Everything below is what is known so far.

Probably never. The machine multiplies a number n by 3/2 or by 9/8 at each pass. A short word at the right end of the tape carries a second, much smaller counter, which mostly moves up or down by one and occasionally grows by half. Halting needs the small counter to catch up with the big one, and the big one is far ahead.

The machine

6 states, two symbols, 1 halting transition

Each entry says what to write, which way to move and which state to enter. The machine starts in A on a blank tape (all 0s).

The machine stops when it is in A reading 1. A is entered only from D1 (writes 0, moves R): D>1 1; E1 (writes 1, moves R): E>1 1. So a halt is the moment one of these patterns appears, with the head on the cell after >.

What it does

A big number and a small counter

Every so often the head is in state E at the left end, on six 0s, followed by n copies of 10 and a short tail word. The tail is 1, Xk = 000 (10)^k 1, Yk = 11 (01)^k or Zk = 000 (10)^k 0001.

With the tail 1, one pass multiplies n by 3/2: n even gives (3n+6)/2 and the tail stays 1, n odd gives (3n+1)/2 and the tail X0. With an X or Y tail, a pass multiplies n by 9/8 and changes the small counter k according to n mod 8:

n mod 801234567
from XkYk−1YkXk+1XkXk+1Yk−2Yk−1×3/2
from YkYk−2Yk−1×3/2Yk−1YkXk+1XkXk+1

Here ×3/2 means that k becomes 3k/2+3 (tail X) when k is even, and (3k+1)/2 with the tail Z when it is odd. When k would go below 0, the tail goes back to 1. A Zk tail does one 3/2 pass that subtracts about 4.5k, then returns to 1 or X0. So the run alternates between phases of 3/2 passes and phases of 9/8 passes, during which a small counter wanders and sometimes grows. From blank tape, n = 0, 3, 5, 8, 12, 21, …, and n = 48,351 at step 2.1·1010.

Can it stop?

Only if the small counter catches up

All of these rules hold for every n, except the Zk rule, which needs n ≥ 12k+12. Below that bound the tail turns into longer words and the machine can halt (for example from Z15 with n = 189). So the machine can only halt if, at some Z-event, the counter k is at least about n/12.

That is very unlikely. k starts again from 0 in every 9/8 phase, and it grows by half only at 1 pass in 8, with an even k, while n grows at every pass. In the run the tightest moment was pass 28 (n = 3,989, k = 5), with a margin of 55. After pass 70 the margin is above a million, and after 105 passes n has 8,063 digits while k has never passed 1,046.

What is checked

The map is proved; the question is about one orbit

  • Every pass is proved. Lean's kernel checks that from every E-event (except Zk with n < 12k+12) the machine reaches the E-event the map predicts, in exactly the predicted number of steps. The proof is split into 83 cases (by tail and by n mod 8 or mod 2). Each case is a run of the symbolic simulator through a few sweeps, with the repeated part (three rounds of the 9/8 phase, or one of the 3/2 phase) done once and iterated by induction.
  • The orbit from blank tape is checked by evaluating the map in Lean: 3,000 passes in the kernel (more than 10450 steps), 105 passes compiled (1016000 steps), never entering the unproved region.
  • What is missing for a non-halting proof is an argument that k never catches up with n along the whole orbit. The residues of n that drive k are themselves a Collatz-like sequence, so this is as hard as the usual Collatz-type questions.
The region where a halt starts

Inside Zk with n < 12k + 12

The map of the other sections leaves out one region: Zk with n < 12k + 12. There the n-block runs out before the tail block (10)k does, so the pass never reaches its 3/2 part. The whole pass is the 9/8 phase of a Z tail: each group of nine rounds uses 24 of n and 2 of k. It ends with the rest of the tail block, about k − n/12, still on the tape, followed by a new end word. For n ≡ 7 (mod 8) the rest of the block is itself multiplied by 9/8 before the next E-event, a second level of the same mechanism.

Proved in Lean's kernel (lean/ZRegion0–5.lean, lean/ZMap.lean): 190 families cover every start of the region, and Z0 for every n. zregion: the machine halts in the pass exactly when k is odd and n = 12k + 9. Every other start reaches a next E-event E> 0^6 (10)^n' T, with n' = (9n + c)/8 and T given by the family.

Each cell below is one start (n across, k up, k ≤ 24; the halting starts are the red marks on the line n = 12k + 9), coloured by what the pass leaves behind. Click a cell or type k and n.

Most new tails are a block followed by a short end word (X- or Y-shaped), and the next passes treat the block as the counter k of the X and Y rules until the end word is reached. Followed by direct simulation, all 1,248 region starts with k < 14 either return to the mapped tails within 11 passes (1,220), halt (15: the line n = 12k + 9, and a few, such as Z3 at n = 23, two or more passes later), or are the start n = 2, which gives Zk+1 at n = 2 again and never halts (13). So after the region the run is again a word on the right and a number on the left; a full halts-iff needs the X and Y rules for tails with any end word, which is the next step.

Remainder classes

Does any remainder class halt?

A generic test used on the whole family: sample the run whenever the head is in state E reading 1 with only 0s to its left. Read rightwards from the head, the tape is then A Um B, one long periodic block between two short context words A and B. The round to the next sample is computed class by class: for a class (A, U, B, m modulo 2, 8 or 24 (the smallest modulus that works for the context)) six values of m are simulated, and when they agree the round is taken to be an affine map of m. Against the direct run to 3·109 steps the class map is right in all 22 rounds it applies to. It is an observed law, not a proved one.

The orbit. Iterated with exact integers from the event at step 146,886 of the run (A = 1 04, U = 01, m = 90, B = (empty)): 646 rounds without meeting a halting class; m then has 192 bits (about 10117 steps of the machine). 81 distinct contexts occur, the longest of 1,049 cells. The iteration stops there, at a context too large for the six simulations (a second long block has formed); this is a limit of the tool, not an event of the machine.

Can any class halt? Breadth first from the starting context, with every remainder at every context (whether or not the numbers can really produce that sequence of remainders, and only for m large compared with the contexts): 103 contexts expanded, 143 found, to depth 11. None of them halts; the search is not complete (the set of contexts keeps growing), and it says nothing about a halt that needs a context as long as the block itself. 682 classes could not be computed (their six simulations disagree or are too long).

First look

The shape of the run

Left of the start, the visited part of the tape grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a counter or of a Collatz-like map whose values are written on the tape (fitted exponent 0.128). Right of the start it grows like the square root of the step count, the signature of a head sweeping back and forth across the whole tape and adding a cell or a few at the end of each sweep (a bouncer-like shape) (fitted exponent 0.41).

After 109 steps the tape spans 13,857 cells (61 left of the start, 9,722 right), with a density of 1s of 0.5.

Heuristic
README
Probviously non-halting: the index would have to catch up with n

A halt can only start from Zk with n < 12k+12. In a phase of X/Y tails, k moves by −2 to +1 and is multiplied by 3/2 at 1 pass in 8, and it starts again from 0 at every phase. Along the orbit the fraction of Z-events with k ≥ K falls like K−1.1 to K−1.7 (0.6% for K = 100), while n grows by a factor of about 9/8 per pass. So the chance that some phase reaches k ≈ n/12 is about (n/12)−1.2 per phase: about 10−5 at the end of direct simulation, and far smaller after that, where n has thousands of digits.

Open
Does it halt from blank tape?

Not known, but very probably not. Unlike Antihydra-type machines, the bad region is not reached by a fair random walk: k would have to grow as fast as n. No simple invariant k ≤ f(n) is in sight: within a 9/8 phase the residues n mod 8 that drive k are themselves a (9n+c)/8 orbit, and since (9n+c)/8 is a bijection on residues, any finite sequence of residues occurs for some n. So a bound on k is a Collatz-type statement about this orbit. Of the 3·105 starts (1, n) with n < 3·105, only n = 8, 11, 13, 15 reach the uncovered region within 200 passes. A halts-iff in terms of the map is not yet closed: the exits of the region are new tails, and the X and Y rules are proved only for the end words of X, Y and Z.
