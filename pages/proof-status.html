What is proved about the holdout, and what is open

1RB0RE_1LC0RA_1LA1LD_1LA---_0RF0LB_0LD1RE

This six-state Turing machine is one of the BB(6) holdouts: nobody knows whether it halts when started on a blank tape. This page says where the formal proof stands, what is left, and how to check every part of it yourself.

Status as of 27 October 2026. The work is moving; this page is updated as results are merged into the repository.

In short

The question is not settled. What is proved, in Lean 4, is that if the machine ever halts from blank tape, its run must first reach one of two kinds of rare configuration that the proof cannot yet rule out:

  1. a clean tape of width at least 2⁴¹ whose width falls, at every depth, in a residue class the clean-tape tree leaves open (at 36 binary digits, 1,255,963 classes of W/2, together a fraction 1.83 × 10⁻⁵ of the widths), or
  2. a pass start of the machine's main loop, wider than 2⁴¹, that its pass-start tree leaves open at every depth, reached from a loop entry that cannot close.

This is the theorem blank_halt_pass. A second version, blank_halt_pass_kernel, proves the same shape of statement (from width 2²⁰ and 2²⁴ instead of 2⁴¹) using Lean's kernel alone, with no compiled code in the trusted base. Separately, an exhaustive C computation shows that no clean tape below 2⁶¹ leads to a halt.

The run from blank tape, stage by stage

The machine's tape can be read as stripes 1010… with a few marks on them (gaps, markers, walls and blocks). Its run from blank tape passes through clean tapes (one marker at the end), sometimes enters an eight-round loop that divides the distance to the right end by 16 on each pass, and can only halt at a close at the right end or where two marks touch. The proof follows a halting run through every stage. Each stage below is labelled by what its proof trusts.

1. The mark rules and the round theorem

21 rules say how the machine moves the marks, for every stripe length and any surrounding tape, and one round of the machine is exactly one round of the mark model, or a halt exactly where the model says.

kernel

2. From blank tape to the first wide clean tape

The model is run from blank tape to the clean tape of width 2²⁰ (294,033 rounds), checked by the kernel; or to width 2³² (1.2 × 10⁹ rounds), after which every clean tape of width between 2³² and 2⁴¹ in an open class (26,508,327 of them) is run directly to a wider one.

kernel to 2²⁰native_decide to 2⁴¹

3. From clean tape to clean tape: the clean-tape tree

Split by residue classes of W/2, at every depth: from a clean tape outside the cut classes the machine reaches a wider clean tape without halting, or a loop entry from which no member of its class can close. The tree is built by an explorer that is proved to build only valid trees, so nothing is evaluated.

kernel

4. Through the loop: exit, endgame, chain and σ bound

Every loop state runs without halting to a clean tape, a break of the end-meeting chain, or another pass (358 classes). Every pass start either has its right-end distance R in the closing set {2, 4, 8, 16, 24, 32, 48, 64, 176} with its left countdown L₁ in R's class, or runs on without closing until it leaves the loop or lands on the next pass start by one of three exact maps. By induction along this chain, a run closes through the loop only from such a pass start, and that gives the σ bound log₂W ≤ σ + 6.38.

kernel

5. Past the loop's end: pass-start trees

From a pass start where the chain ends, the run is followed on, outside the trees' cut classes, to the next landing of the chain or to a wider one-marker clean tape, at every depth, and there the clean-tape tree takes over again.

kernel

What remains: the cut classes of steps 3 and 5

Configurations that a tree cuts at every depth are not followed further. A halt from blank tape must go through one of them.

open

What is proved

blank_halt_pass

A halt from blank tape needs a clean tape of width ≥ 2⁴¹ in a cut class of the clean-tape tree with loop entries at every depth, or a pass start wider than 2⁴¹ in a cut class of its pass-start tree at every depth; the run reaches it, halts from it, and the mark model reaches a contact from it.

lean/thm/PassEntryHalt.lean · native_decide for the prefix and direct runs

blank_halt_pass_kernel

The same from width 2²⁰: open clean tapes of width ≥ 2²⁰ (cut by the plain tree below 2²⁴ and the tree with entries above), or open pass starts of width ≥ 2²⁴. Nothing is evaluated by compiled code; #print axioms lists only propext, Classical.choice and Quot.sound.

lean/thm/PassEntryHalt.lean · kernel

The σ bound

A pass divides R³ and L₁² by the same factor, and every closing class has R³/L₁² ≤ 176³/256². So a close through the loop needs log₂W ≤ σ + 6.38, where σ = 3 log₂(W/R) + 2 log₂(|L₁|/W) at the start of the last run of full passes. From width ≥ 2²⁴ a close is p full passes after at most one half pass. The bound is attained (R = 2,816, L₁ = −16,384).

LoopChain.sigma, loop_halt_sigma, blank_halt_sigma, LoopChain.close_wide · kernel

The loop chain

If the machine halts from a pass start with gaps ≥ 448, its run follows full passes (R → R/16), a half pass (only as the first step) and round-7 breaks through every landing whose gaps stay ≥ 448, at any width. Within the loop it closes only from a pass start in a closing class.

LoopChain, loop_chain_halt in lean/thm/LoopHalt.lean · kernel

The exit and the endgame

exit_stretch: every loop state with gaps ≥ 390 ends in one of 358 classes (298 breaks, 58 clean tapes, 2 passes). endgame_stretch: for every even R, the exact closing table. Both trees are checked by the kernel subtree by subtree, and each leaf ends at a stated event.

lean/thm/ExitTheorem.lean, EndgameTheorem.lean · kernel

The 60-digit exhaustive search

Every clean tape below 2⁶¹ reaches the next clean tape without halting: 36.9 billion settled classes and 121 billion direct runs, about 1.8 × 10⁵² machine steps. Rerun with the corrected simulator (the "trailing wall" fix found by the formalization), it reproduces the original result line for line, the corrected case never occurring.

csearch/nrefdfs2.c, dfs/merged60_fixed.txt · C search

Also proved, and used along the way: the route tree for two-marker states (route_tree_clean, at every depth), and certificates with independent Python checkers for the exit (358 classes), the endgame (40,991 classes; 83,699 in either phase) and the route tree to 36 and 40 digits. A differential test (simtest/) runs every simulator against the proved model.

What is open

Do the open pass starts get reached?

Some pass starts that the pass-start trees leave open really do halt: one in eight of those with R = 6 leaves the loop at round 2 and closes in round 7 (for example walls 743, 1,802 and 3,319, width 3,326, halting after 11,362,209 steps). So no depth of these trees can close the case on its own. The question is whether the machine's own run ever reaches one. A lead: at all 28,660 loop entries of the 36-digit clean-tape tree, R is affine in the class coordinate with a nonzero coefficient, so a chain from them ends at R < 178 only at isolated members of a class. The rest reach the tree for R ≥ 178, whose open fraction falls from 8.8% of a class at 16 splits to 4.1% at 20, with no halt found among them. (These figures come from an untrusted program; they are not yet proved.)

The clean tapes left open at every depth

1,255,963 classes at 36 digits remain open over the widths ≥ 2⁴¹. Their number grows about 1.52-fold per digit, so their measure shrinks about 0.76-fold per digit. That it shrinks to zero is a measurement, not a theorem. Deeper trees or a new invariant could cut these further.

A lock for the extra-wall loops

With extra walls, the loop has other passes. The pass P and the detour Q each have a never-zero countdown (Q's is quadratic), and every periodic word in P and Q up to length 12 has one, but mixtures of them have none. A working lock would bound the halts these loops can carry, and might settle both open cases at once.

Heuristic odds of a halt beyond the exhaustive range are tiny (of order 10⁻³² or less), but they are estimates from measured rates, not proof. The summary page grades every statement as proved, checked, measured or heuristic.

How to check it

The proofs use Lean 4.34.0 with the core library only (no Mathlib, no Lake). scripts/setup-lean.sh installs it to /opt/lean-4.34.0 (it needs root, for /opt and /etc/profile.d). Times below are on 4 cores.

git clone https://github.com/fractal-geometry-explorer/busy-beaver-explorer
cd busy-beaver-explorer
sudo scripts/setup-lean.sh && . /etc/profile.d/lean.sh
cd bb6-holdout/lean

./check.sh            # the BB6 modules: rules, rounds, trees, explorers (about a minute)
./check_end.sh        # every theorem file, kernel and native pieces (about 22 minutes)
./check_end.sh --deep # also the 40-digit measures (about 39 minutes)
./check_route.sh --fast   # the route tree at every depth, and its 36-digit measure

Each theorem file ends with #print axioms. For blank_halt_pass_kernel it should list only propext, Classical.choice and Quot.sound; for blank_halt_pass it also lists what native_decide adds for the two evaluated checks, prefix_ok and clean_direct_ok. The certificates check in Python with exact arithmetic:

cd bb6-holdout/cert && gunzip -k *.gz
python3 check_endgame.py endgame_leaves.txt
python3 check_exit.py exit_leaves.txt
python3 check_tree.py tree36_leaves.txt     # hours

The exhaustive search is about 80 CPU hours to 60 digits, split into 384 parts by dfs/run_parts.sh and merged with dfs/merge.py; compare the result with dfs/merged60_fixed.txt.

The statement of blank_halt_pass in Lean 
theorem blank_halt_pass (T : Nat) (hT : steps T ⟨blank, blank, .A⟩ = none) :
    (∃ W k, directWidth ≤ W ∧ W % 2 = 0 ∧
      (∀ d, (cleanTreeGE directWidth d).cutMem [(W : Int) / 2, 0] = true) ∧
      steps k ⟨blank, blank, .A⟩ = some (roundStart [⟨.M, W - 2⟩] W) ∧
      steps (T - k) (roundStart [⟨.M, W - 2⟩] W) = none ∧
      ∃ t, Reach ⟨[], 1, [⟨.M, W - 2⟩], W⟩ t ∧ t.wf ∧ (EndClose t ∨ InteriorContact t)) ∨
    ∃ R a b W k, directWidth < W ∧ PassStart448 [⟨.W, a⟩, ⟨.W, b⟩, ⟨.W, W - R - 1⟩] W R ∧
      (∀ d, PassCut d R a b W) ∧
      steps k ⟨blank, blank, .A⟩ = some (roundStart [⟨.W, a⟩, ⟨.W, b⟩, ⟨.W, W - R - 1⟩] W) ∧
      steps (T - k) (roundStart [⟨.W, a⟩, ⟨.W, b⟩, ⟨.W, W - R - 1⟩] W) = none ∧
      ∃ t, Reach ⟨[], 1, [⟨.W, a⟩, ⟨.W, b⟩, ⟨.W, W - R - 1⟩], W⟩ t ∧ t.wf ∧ (EndClose t ∨ InteriorContact t)

Here directWidth = 2⁴¹, steps is the machine itself (none means halted), and roundStart is the tape of a mark state.
