# 1RB0RF_1RC0LD_1RD0RA_1LB1LE_0LB0RE_0RD---

bbchallenge id 179725. Open. A **nested crossing counter**: the tape is a handful of long blocks of 3-cell words
(`101`, `100`, `001`) and one *final block* of a 9-cell word (`110110100` and its rotations). The run is a sequence of
phases; in each phase a few block lengths change linearly (one period of each phase is proved in Lean for every block
length), and a phase ends when a block runs out. One *round* (drain, cross, absorb, ...) multiplies the tape length by
about 2.2. An exact accelerated simulator (`py/accel.py`, checked against direct simulation) follows the run to
**1.2·10^300 steps** (399 drain phases) without a halt. The mirror image of this machine, with states A and D
exchanged, is exactly `1RB1RE_1LC0RA_1LA0LD_1LB0LF_0RB0LE_0LA---`: that machine is this one started in state D.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RF |
| B | 1RC | 0LD |
| C | 1RD | 0RA |
| D | 1LB | 1LE |
| E | 0LB | 0RE |
| F | 0RD | --- |

## The phases

Each row is one period of a phase (`lean/Phases.lean`, `PhasesDrain.lean`, `PhasesFeed.lean`; kernel; generated by `py/phases.py` from the rules
`py/phase_rules.py` extracts from the run; `lean/Rules.lean` has two older forms). Counts are `x_i + c`, for
all x_i; tails like `1 0 0 1 0 0` are literal cells.

| phase | what changes per period | steps | Lean |
|---|---|---|---|
| drain | final block -11, a marker moves 18 words `101` right-to-left through the first block, a new block +36 | 396(x1+x2+x3+x5) + 16594 | `drain11` |
| cross | a marker `1` moves 6 words `101` left, final block +1 | 132(x1+x2) + 396 x3 + 1033 | `cross6` (also `traverse`) |
| double cross | two markers move 12 words, final block +1 | 264 x1 + ... + 2452 | `cross12`, `cross12b` |
| absorb (left end) | left block `001` +4, its neighbour -2 | 18 x1 + 72 | `absorb2` (also `absorb`) |
| feed (left end) | a middle block -18, left block +30, final block +1 | 108 x0 + ... + 3028 | `feed30` |

## One round, from the exact run

Write X for the first long block (`101` words, read at the right end) and Y for the final block at the start of a
drain phase. Up to O(1) words (step 2.5·10^37: X = 1,791,060,405,272,277,757, Y = 127,176,870,295,632,309):

1. drain: Y runs out (Y/11 periods); the first block splits as `(101)^(X-18Y/11) 1 (101)^(18Y/11)` and a block
   C = 36Y/11 appears.
2. cross: the marker crosses the first part; the final block becomes D = (X - 18Y/11)/6.
3. absorb: at the left end the block of X words becomes 2X words.
4. Then one of two continuations, chosen by residues of the counts (the literal junction left by the earlier phases,
   e.g. `(001)^4` or `(001)^5`):
   * **short**: the absorb also eats C, and the next drain starts with X' = 2X + 36Y/11, Y' = D = X/6 - 3Y/11;
   * **long**: a second drain (of D, with C waiting as `(100)^C`), cross, double cross, absorb, feed (C goes into
     the left block 5/3 per word) and absorb give X' = 56X/11 + 444Y/121, Y' = 31X/132 + 17Y/242.

Both maps keep Y/X between about 0.04 and 0.08, so the drain always ends with the final block (never the first
block) and every block stays long; which branch comes next depends on residues of the counts modulo the phase
periods (6, 11, 12, 18), a Collatz-like choice. From blank tape the tape length grows 1.96 to 4.0 times per drain
phase (about 2.2 typical); the exact run's drain phases are listed in `py/rounds_1e300.log` (`py/rounds.py`).

## Exact simulation (`py/accel.py`)

Block-run-length tape with shift rules (a block `(w)^n` is crossed at once when one copy carries a short word across
it in the same state). At each *event* (the head reaches a new cell, or with `ACCEL_X=1` also crosses a long block)
the tape is compressed and its shape recorded. When a shape recurs twice with the same change of counts, the period
is re-run *symbolically* with each changing block's count a free variable plus a threshold; if it returns to the
same shape with counts x_i + T_i + d_i it holds for all x_i and is applied as many times as the shrinking blocks
allow, the steps summed in closed form. So the run is exact (same tape and step count as the machine):
`py/check_accel.py` compares it with direct C simulation (`c/tapeat.c`) after every jump up to 1.6·10^10 steps, 0
mismatches (with and without `ACCEL_X`). From blank tape: 10^100 steps in 47 s, 1.2·10^300 steps in 140 s, no
halt; the number of distinct verified periods levels off (183 by 10^21, 245 by 10^251).

## Halting

The only halting transition is F on a 1; F is entered only from A on a 1. In every phase rule the cell F reads is
a 0; a halt would need one of the finitely many residue-dependent phase ends to go wrong, and none of the ones
met up to 10^300 steps does.

## Status

Open. Kernel: halting configurations, 10,000 steps, the six phase periods of `Phases*.lean` and the two of
`Rules.lean`. Native: 10^7 steps. Trusted: no halt in 10^10 steps (`c/ev.c`), and in 1.2·10^300 steps by the exact
accelerated simulator (Python, checked against C up to 1.6·10^10). The phase ends (which branch, what junction) are
from the simulation only.

## For later

* A closure proof: `py/closure.py` runs the phases symbolically with all counts abstract, splitting on remainders
  when a block runs out; as written it forgets the relations between counts (Y < X/10), explores spurious cases
  and its queue grows (thousands of branches, hundreds of templates). Tracking the inequality between the first and
  final block, or abstracting at round starts with residues, might close it.
* State the round map with exact residues (each branch is an affine map on residue classes).
* Same family as 1RB1RA_1LC0RB_1LE0LD_0LB1LD_0RA0LF_---0RE and 1RB0RE_0LC0RF_1LD1LC_1RA0LD_0RD1RE_---0LB.
