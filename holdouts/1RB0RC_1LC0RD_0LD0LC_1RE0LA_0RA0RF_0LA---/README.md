# 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_0LA---

bbchallenge id 59221. One of the six-state holdouts whose halting from blank tape is open. **Open**: a
base-5 counter whose digits are defects in a periodic background; the counting is proved in Lean for all
configurations, the collisions of its digits are not.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RC |
| B | 1LC | 0RD |
| C | 0LD | 0LC |
| D | 1RE | 0LA |
| E | 0RA | 0RF |
| F | 0LA | --- |

## Status

Open. Proved in Lean, by the kernel unless marked:

- `lean/Blank.lean`: the halting configurations; no halt in 10^4 steps (kernel), 10^7 (`native_decide`).
- `lean/Pieces.lean`: the nine piece rules of a visit, for all counts and all surrounding tape.
- `lean/Counter.lean`: `visit`, one visit of the head is one increment of a base-5 counter, for every
  configuration where the increment is defined; `run_sound`, the same iterated.
- `lean/Merge.lean`: `merge_ee`, the visit that meets two adjacent `e` digits.
- `lean/Reach.lean` (`native_decide`): the run from blank tape reaches a counter configuration after
  1,001,215 steps (`reach`), and the counter rule alone carries it 198 visits further (`counted`).

Computed (trusted): the exact visit-level simulator `py/vsim.py` runs 10^16 steps (75,701,323
visits) without a halt. Open: whether the collisions of the counter's digits can ever produce the halting
pattern.

## The tape: a background with digits

Stop the machine whenever the head is on the leftmost cell in state A (a *sample configuration*). The tape is then

    0 0 W^g0 X1 W^g1 X2 W^g2 ... Xk W^gk 0 0 1          W = 0001

a left gap of `g0` copies of `W`, then *digits* `Xi` each followed by a gap of `gi` copies of `W`, and a *wall*
`001` with blank tape after it. The digits are five words:

| digit | cells | value | after a visit | gaps |
|---|---|---|---|---|
| a | `0011` | 1 | b | one `W` fewer after it |
| b | `0011001` | 2 | c | |
| c | `001101` | 3 | d | |
| d | `00111` | 4 | e, and carry | |
| e | `00101` | 0 | a | one `W` moves from the gap after it to the gap before it |

A sixth defect, a single extra `0` (`00001` in place of `0001`, written `z`), is an empty digit.

## One visit is one increment (proved)

Between two sample configurations the head goes right through the left gap (turning each `0001` into `1010`),
meets the first digit, and either passes it (a `d` becomes `e`: the carry) or increments it and turns back,
restoring the background, to the left end, where the tape grows by three cells. With the first digit as the least
significant, the digits form a **base-5 counter incremented once per visit**. In `lean/Counter.lean`:

```
bump : List (Dg × Nat) → Option (Nat × List (Dg × Nat))   -- the increment, with the gap moves
visit : bump xs = some (δ, ys) →
  steps (10 * g + 11 + cost xs) (sample g xs T) = some (sample (g + 1 + δ) ys T)
```

where `cost` adds 10·gi + 24 for every `d` passed and 24 for the turn. `bump` is undefined when
the carry reaches the wall (overflow) or the digit that takes the increment has an empty gap after it (a
collision). The proof composes nine piece rules (`lean/Pieces.lean`, generated by `bbtools.symtm` from
`py/fam.py`):

| rule | from | to | steps |
|---|---|---|---|
| `start` | `0^inf A> 0 0 W^n R` | `0^inf (1010)^n 1 E> 0 0 1 R` | 4n+5 |
| `carry` | `L 1 E> 0 0 1 d W^m R` | `L 1 0 1 0 1 (1010)^m 1 E> 0 0 1 R` | 4m+9 |
| `bounce_a` | `L 1 E> 0 0 1 a W R` | `L 1 0 1 A> 0 0 b R` | 24 |
| `bounce_b` | `L 1 E> 0 0 1 b W R` | `L 1 0 1 A> 0 0 c W R` | 24 |
| `bounce_c` | `L 1 E> 0 0 1 c W R` | `L 1 0 1 A> 0 0 d W R` | 24 |
| `bounce_e` | `L 1 E> 0 0 1 e W R` | `L 1 0 1 A> 0 0 W a R` | 24 |
| `left_gap` | `L (1010)^k 1 0 1 A> 0 0 R` | `L 1 0 1 A> 0 0 W^k R` | 6k |
| `left_d` | `L 1 0 1 0 1 1 0 1 A> 0 0 R` | `L 1 0 1 A> 0 0 e R` | 15 |
| `left_end` | `0^inf 1 0 1 A> 0 0 R` | `0^inf A> 0 0 W R` | 6 |

In the run, 99.988% of all visits are plain increments (first 10^13 steps, `py/census.py`).

## Emergent behaviour: drift, overflow, collision

- **Drift.** A digit moves 9 cells right per 5 increments; the left end moves 3 cells left per visit. Digit `i` is
  incremented every `5^i` visits, so the lowest digit runs right at about 1.8 cells per visit, the next at a fifth
  of that, and the highest ones stand almost still near the wall. Every digit slowly catches up with the next.
- **Overflow.** When every digit is `d` the carry runs into the wall: all the `d` become empty digits `z`, the wall
  moves a few cells right, and a new digit is born at the left end (16 of the 46 births in the first 10^13
  steps).
- **Collision.** When the gap after the lowest digit runs out (always on an `a→b` or `e→a` step, so a collision
  starts as `a` or `b` next to any digit), the pair forms compound words for a few increments, then fuses into one
  digit, or leaves the phase defect `001`, which makes the next visit give birth to a new lowest digit at the left
  end.

The tape is `0^inf`, a counter of a few digits spread over a width of about the square root of the step count, and
the wall: the fixed/sqrt growth of the triage. `py/frames.py` writes the data of the explainer's two widgets (a
stepper through real visits and the tracks of all digits over the first 30,000 visits).

## Where it could halt

The machine halts only in state F reading a 1, reached only from `D>0 1`: D writes a 1 and moves right, E reads that 1, erases it and moves right in state F, and F halts on a 1 (in the usual case `D>0 0`, E reads the 0 and goes on in state A). So it halts
exactly when the head, in state D, reads `0 1 1`. In the background and in every plain visit D reads `0 0`.
`D>0 1 0` (a near miss) occurs inside some collisions, for example the visit that meets two adjacent `e`
(`lean/Merge.lean`): 8 times in the first 10^15 steps, always followed by a 0. Random tapes made of
the same digits with gaps of 0 to 3 halt fairly often (633 of 2,000 within 3·10^6 steps), so the halting question
is whether the counter ever crowds its digits into such a collision. That depends on the exact gaps at every
collision, which depend on the whole history of the counter. No reduction to a known problem is claimed.

## Evidence and how far

- `py/vsim.py`: exact visit-level simulator. It runs each visit concretely on a copy of the tape whose gaps longer
  than 16 `W` are cut to 16, then puts the cut copies back (10 steps per `W` crossed both ways, calibrated
  per machine). Checked equal to the direct simulator on every sample configuration of the first 3·10^7 steps,
  step counts included. 10^15 steps take about 3 minutes.
- 10^16 steps: 75,701,323 visits, no halt; the near miss 9 times.
- `py/census.py`: plain visits and what the others meet; `py/frames.py`: the widget data.

## For later

The next step towards a proof would be a model of the collisions: a closed description of what a collision of
`a` or `b` with each digit leaves (the table is finite, about ten cases plus the compound words they pass through),
then an invariant on the gaps that rules out the crowded collisions in which `D` reads `0 1 1`. The gaps are
driven by the counter's own history (a gap shrinks by 2 W per 5^i visits, and collisions reset them), so such an
invariant would have to follow the whole multi-scale dynamics; nothing simpler is known to work.
