# The BB(6) holdouts

bbchallenge's list of the six-state, two-symbol machines whose halting from blank tape is open: 608 machines up to
equivalence (`BB6_holdouts_608.txt`, 30 October 2026). Six of them have their own folders at the top of the
repository (`bb6-*`); every other one has a folder here, named by its machine. The map of all of them is
[`pages/holdouts/index.html`](../pages/holdouts/index.html).

## What every folder starts with

`gen.py` writes, from one bounded run (`triage.json`):

- `README.md`: the table, the growth shape of the run, the tape late in the run;
- `status.json`: the ledger the pages are built from, every claim with what it rests on (kernel, native_decide,
  computed, heuristic, open);
- `lean/Machine.lean` (generated by `tools/py/bbtools/leangen.py`), `lean/Blank.lean` (the halting configurations,
  10,000 steps from blank tape by the kernel, 10^7 by `native_decide`), `lean/check.sh`;
- `pages/holdouts/M/explainer.html` (the machine running in the browser, the space-time diagram, the growth plot,
  the ledger) and `proof-status.html`.

## The triage

`tools/c/triage.c` runs a machine 10^9 steps and records how far the visited tape reaches on each side at every
power of two of steps; `tools/py/bbtools/triage.py` fits a growth exponent to each side and names its shape: `exp`
(logarithmic growth: a counter, a Collatz-like map), `sqrt` (sweeps across the whole tape: bouncer-like), `power`,
`linear`, `fixed` (no new cell in the second half of the run). The class of a machine is the pair. It is a first
sort, read off one run, not a result.

`known.json` holds the names the community gave some of them (Antihydra, Space Needle, Lucy's Moonlight, ...),
from the bbchallenge wiki.

## Taking a machine over

1. Set `"generated": false` in its `status.json`, so `gen.py` leaves the folder alone and the tests stop comparing
   it with the generated one.
2. Write what the machine does into `README.md` and `status.json` (`summary`: one sentence for the index page;
   `group`: the family it belongs to; `decision`: `open`, `halts` or `nonhalting` once it is proved; claims; and
   `explainer.sections` for hand-written sections of the explainer).
3. Add Lean files next to `Blank.lean` and list them in `lean/check.sh`; machine-specific scripts go in `py/` or `c/`
   in the folder.
4. `python3 holdouts/build_pages.py M` rebuilds that machine's pages and the index; `python3 holdouts/test_holdouts.py`
   checks that everything is current. The index is generated, so on a merge conflict in it rebuild it with
   `python3 holdouts/build_pages.py --index-only`.

## Related machines

Many of the 608 are tied to one another, in four different ways that must not be confused: the same table started in
another state (130 tables, 335 machines; a different run, so a separate halting question), the same run from
different tables, a slowed-down copy, and the same tapes at another pace. `related.py compute` checks all of them by
running the machines (10^7 steps each, `tools/c/cfgmatch.c`, `lockstep.c`, `tapehash.c`) and writes `related.json`;
`related.py apply` writes the "Related machines" section of every README and `status.json` concerned, and
`related.py check` (run by the tests) says whether they are current. Only the comparison of tables is exact;
everything about runs is an observation.

## Proofs and labels from outside

`external.json` holds, for every machine, what is known from outside its own ledger: Rocq proofs in open pull requests
of ccz181078/busycoq (46 machines, read on 12 November 2026; none merged, none compiled here), the one machine proved
in busycoq's BB6 branch, the class and the cryptid label the community tracker gives it, and the five Coq proofs kept
in this repository. `build_pages.py` shows it as a box on both pages of the machine and as the machine's standing on
the index (decided here, proved elsewhere, outside proof awaiting review, cryptid, open). A machine's `status.json`
stays the record of what this repository checked; an outside proof changes its `decision` only once it is compiled
here. When a pull request is merged or a new one appears, edit `external.json` and run `python3 holdouts/build_pages.py`:
no machine folder changes.

## Rebuilding everything

```sh
gcc -O2 -o triage tools/c/triage.c && mkdir -p tri
awk '{print $2}' BB6_holdouts_608.txt | xargs -P 4 -I{} sh -c './triage {} 1000000000 400 > tri/{}.json'
python3 holdouts/make_triage.py BB6_holdouts_608.txt tri
python3 holdouts/gen.py && python3 holdouts/build_pages.py
. /etc/profile.d/lean.sh && for d in holdouts/*/lean; do $d/check.sh; done     # about 11 s a machine
```

CI (`.github/workflows/holdouts.yml`) checks the pages on every pull request and the Lean of the folders it
touches; the full Lean check runs by hand in four shards.
