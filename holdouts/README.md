# The BB(6) holdouts

bbchallenge's list of the six-state, two-symbol machines whose halting from blank tape is open: 608 machines up to
equivalence (`BB6_holdouts_608.txt`, 30 October 2026). Six of them have their own folders at the top of the
repository (`bb6-*`); every other one has a folder here, named by its machine. The map of all of them is
[`pages/holdouts/index.html`](../pages/holdouts/index.html).

## What every folder starts with

`gen.py` writes, from one bounded run (`triage.json`):

- `README.md`: the table, the growth shape of the run, the tape late in the run;
- `status.json`: the ledger the pages are built from, every claim with what it rests on (kernel, native_decide,
  computed, heuristic, open);
- `lean/Machine.lean` (generated by `tools/py/bbtools/leangen.py`), `lean/Blank.lean` (the halting configurations,
  10,000 steps from blank tape by the kernel, 10^7 by `native_decide`), `lean/check.sh`;
- `pages/holdouts/M/explainer.html` (the machine running in the browser, the space-time diagram, the growth plot,
  the ledger) and `proof-status.html`.

## The triage

`tools/c/triage.c` runs a machine 10^9 steps and records how far the visited tape reaches on each side at every
power of two of steps; `tools/py/bbtools/triage.py` fits a growth exponent to each side and names its shape: `exp`
(logarithmic growth: a counter, a Collatz-like map), `sqrt` (sweeps across the whole tape: bouncer-like), `power`,
`linear`, `fixed` (no new cell in the second half of the run). The class of a machine is the pair. It is a first
sort, read off one run, not a result.

`known.json` holds the names the community gave some of them (Antihydra, Space Needle, Lucy's Moonlight, ...),
from the bbchallenge wiki.

## Taking a machine over

1. Set `"generated": false` in its `status.json`, so `gen.py` leaves the folder alone and the tests stop comparing
   it with the generated one.
2. Write what the machine does into `README.md` and `status.json` (`summary`: one sentence for the index page;
   `group`: the family it belongs to; `decision`: `open`, `halts` or `nonhalting` once it is proved; claims; and
   `explainer.sections` for hand-written sections of the explainer). A section can carry a `stepper`: the macro
   rules of the machine as linear forms, which the page turns into buttons that apply them to the counts (see the
   top of `tools/pages/build_explainer.py`, and the folders of 32641, 65826 and 11019 for examples).
3. Add Lean files next to `Blank.lean` and list them in `lean/check.sh`; machine-specific scripts go in `py/` or `c/`
   in the folder.
4. `python3 holdouts/build_pages.py M` rebuilds that machine's pages (and, locally, the shared pages);
   `python3 holdouts/test_holdouts.py` checks that everything is current. Commit the machine's own pages only: the
   shared pages are not in git (see below).
5. When a result changes what is known, add a new file `recent.d/YYYY-MM-DD-short-name.json` holding one entry
   (date, PR numbers, kind, what it rests on, a plain-language title and text, the machines by full name; the fields
   of an entry of [`recent.json`](recent.json)). Do not edit `recent.json` itself: a file per result means parallel
   pull requests never touch the same lines. `build_overview.py` merges both into `pages/holdouts/recent.html`.

## Shared pages are built on main, not committed

`pages/holdouts/index.html`, `families.html`, `recent.html`, `ranking.html`, `holdouts/RANKING.md` and
`holdouts/ranking.json` are written from every machine folder at once, so when they were committed every merge made
every other open pull request conflict. They are now in `.gitignore`, and the Pages workflow
(`.github/workflows/pages.yml`) builds them with `python3 holdouts/build_pages.py --index-only` on each push to
main. On the site they are at https://fractal-geometry-explorer.github.io/busy-beaver-explorer/holdouts/ (with
`RANKING.md` and `ranking.json` beside `ranking.html`). Build them locally to look at them; never `git add -f` them.
A branch made before this change that still edits them gets a modify/delete conflict once when it merges main:
resolve it with `git rm --cached <file>` for each (the deletion wins) and carry on.

## Families of the undecided machines

[`FAMILIES.md`](FAMILIES.md) (21 November 2026) groups the 522 machines not yet decided here into families that one
proof technique could settle together, from table distance (tables one transition apart, up to renaming and mirror)
and shared mechanism, and ranks them. The outside proofs of busycoq PRs 43 to 68 were compiled on 21 November
(`tools/coq/busycoq/prs-43-68`, 34 machines decided, PR 60's 836 native jobs included); the next recommendations are
the F05 core (45 machines), the clock-and-word counters (15) and halt hunts on the base-4 and ternary countdown
counters (22). `regroup.py` writes it and `families.json`, which the holdout map uses for its family filter;
`build_overview.py` (run by `build_pages.py`) turns both into the page `pages/holdouts/families.html`, showing each
machine's standing today.

## Closest to being solved

`RANKING.md` (built by CI, not committed; on the site beside the ranking page) ranks every undecided machine by how close it is to a decision and gives the next concrete
step for each, with the top ten recommended attacks; the sortable version is
`pages/holdouts/ranking.html`. `rank.py` writes both and `ranking.json` from what the
repository records (index rows, `status.json`, `families.json`, the Collatz triage, the number-theory ranking), and
`build_pages.py` reruns it, so a machine drops off the ranking when it is decided. The score is a judgement, not a
result.

## Related machines

Many of the 608 are tied to one another, in four different ways that must not be confused: the same table started in
another state (130 tables, 335 machines; a different run, so a separate halting question), the same run from
different tables, a slowed-down copy, and the same tapes at another pace. `related.py compute` checks all of them by
running the machines (10^7 steps each, `tools/c/cfgmatch.c`, `lockstep.c`, `tapehash.c`) and writes `related.json`;
`related.py apply` writes the "Related machines" section of every README and `status.json` concerned, and
`related.py check` (run by the tests) says whether they are current. Only the comparison of tables is exact;
everything about runs is an observation.

Whether any of these relations can be *proved*, so that one proof settles several machines, is in
[`EQUIVALENCES.md`](EQUIVALENCES.md): a re-sync bisimulation checked in Lean (`tools/lean/TM/Sync.lean`) closes for none
of the open pairs, nor for 23 new candidates from a hash screen, so the 552 open holdouts remain 552 distinct questions.

Holdouts one transition away from a table that DeepMind proved never halts are in
[`DEEPMIND_NEIGHBOURS.md`](DEEPMIND_NEIGHBOURS.md): 10 open holdouts in 4 tables, none settled by DeepMind's proofs
as they stand; for `1RB0LD_1LC1RE_1LA1RC_1RA0LC_0RF---_0LD1RB` Lean proves that it halts if and only if DeepMind's
table `1RB1RE_1LC1RB_1RA0LD_1RC0LB_0RF---_0LD1RA`, started in state C, halts.

## Proofs and labels from outside

`external.json` holds, for every machine, what is known from outside its own ledger: Rocq proofs in open pull requests
of ccz181078/busycoq (46 machines, read on 12 November 2026; none merged, none compiled here), the one machine proved
in busycoq's BB6 branch, the class and the cryptid label the community tracker gives it, and the five Coq proofs kept
in this repository. `build_pages.py` shows it as a box on both pages of the machine and as the machine's standing on
the index (decided here, proved elsewhere, outside proof awaiting review, cryptid, open). A machine's `status.json`
stays the record of what this repository checked; an outside proof changes its `decision` only once it is compiled
here. When a pull request is merged or a new one appears, edit `external.json` and run `python3 holdouts/build_pages.py`:
no machine folder changes.

## Rebuilding everything

```sh
gcc -O2 -o triage tools/c/triage.c && mkdir -p tri
awk '{print $2}' BB6_holdouts_608.txt | xargs -P 4 -I{} sh -c './triage {} 1000000000 400 > tri/{}.json'
python3 holdouts/make_triage.py BB6_holdouts_608.txt tri
python3 holdouts/gen.py && python3 holdouts/build_pages.py
. /etc/profile.d/lean.sh && for d in holdouts/*/lean; do $d/check.sh; done     # about 11 s a machine
```

CI (`.github/workflows/holdouts.yml`) checks the pages on every pull request and the Lean of the folders it
touches; the full Lean check runs by hand in four shards.
## Regular invariants by SAT (16 November 2026)

`tools/py/satctl.py` looks for a closed tape language given by two finite automata, one per side of the head, that
contains the run from blank tape and excludes every halt; a solution becomes a Lean proof through `TM.CTL.not_halts`
(`tools/py/satctl_lean.py`, tested end to end on a toy machine). It was run on all 558 open holdouts:

- **No machine has such an invariant within the sizes searched.** With deterministic automata the solver proved
  that none exists with up to 11 states per side for 513 machines (up to 16 for three of them); with
  nondeterministic automata on both sides, none with up to 6 states for 441 machines and up to 4 for the rest.
  The remaining sizes timed out. Per machine: `holdouts/satctl.json`.
- This is a negative result about one method, not about the machines: a binary counter's tapes are regular, but
  in these holdouts halting depends on arithmetic of the counters (when a walk reaches the top digit, when a word
  runs out), which a small automaton cannot track.

## Why the upstream counter proofs do not carry over (busycoq PRs 48, 57, 58, 59)

- **PR48** (`1RB0RA_1RC0LC_0LD1RF_1RA1LE_1LD0LB_0RE---`, a round invariant over a DFA-guided transducer): it
  needs the word's head to become fixed. The eight open clock-and-word machines dissolve their block and restart
  in phases, and in `1RB0RA_1RC0RC_1LD0LE_1RA1LC_1LC0LF_0LC---` the call counts include a factor 3/2 (see its
  README). The invariant would have to be found again per machine, around a phase-to-phase map that is not known.
- **PR57 / PR58** (wall invariant for up/down counters): it applies when every rebuild reads the whole counter.
  In the three open siblings `1RB1LC_0RC0RB_1LD0LA_1LE---_1LF0LA_1LA0LB`, `1RB1LD_1RC0RB_1LA1RC_1LE0LA_1LF---_1LC---`
  and `1RB1LE_1RC0RB_1RD1LF_1LA0LC_1LD0LA_---0RE` a halt needs exactly the rare rebuild that does, and the walk
  lengths have a power-law tail.
- **PR59** (halting by an accelerated visit law): already used for our proofs that
  `1RB0LB_0RC0LE_1RD0RF_1LB1RB_0LA0RE_1RE---` and `1RB0LB_0RC0LE_1RD0RF_1LB1RB_0LA1RB_1RE---` halt. The three
  open machines with the same first four rules rewrite `1011` differently and run past round 200,000.
- Every open machine that shares a table with an upstream-proved machine (another start or a mirror) is itself
  already in an upstream pull request.

## Standard deciders rerun on the 257 unfamilied holdouts (21 November 2026)

Cyclers and translated cyclers to 2·10^9 steps, backward reasoning to depth 3,000, n-gram CPS up to 30-cell windows
(with histories, LRU and asymmetric windows) and RepWL with blocks up to 48 cells: none of the 257 machines in no
family of `FAMILIES.md` was decided. Details and per-machine results: [`deciders_rerun/`](deciders_rerun/README.md).
