# 1RB1RE_1RC0RF_0LD---_1LE1LD_1RA0LB_0RE1LC

bbchallenge id 157718. One of the six-state holdouts whose halting from blank tape is open. At the growing left end
two **blocks (011)^n and (01)^m grow by eating long runs of 1s further right** (one growth phase proved in Lean);
between these phases the head works through an irregular region of short words, and that part is not understood;
halting is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RE |
| B | 1RC | 0RF |
| C | 0LD | --- |
| D | 1LE | 1LD |
| E | 1RA | 0LB |
| F | 0RE | 1LC |


## What it does

The right end of the tape has not moved since early in the run; the left end grows like the square root of the
step count. Seen at the moments the head is at the left end in state B, the tape often reads

    0^inf B> 0 (011)^n 0 011 011 (01)^m (01101)^q 011 1^r ...

and over two cycles (six visits of the left end) the run of ones loses three cells while the blocks grow:

    n -> n+1,  m -> m+3,  r -> r-3        in 10m+20n+20q+204 steps          (lean/Rules.lean `eat`)

(proved for every n, m, q and every tape beyond, generated by py/rules.py with bbtools.symtm; the theorem states the
end configuration as the run re-brackets it). For example at step 11,262,236 n = 145, m = 433, q = 167, r = 230;
at 12,203,786, r = 6. When the run of ones is used up, the head starts working on the next part of the tape, an
irregular list of the words `011`, `01`, `10` and runs of 1s, and a new phase starts later with the next long run
of ones; the runs of ones that get eaten (1^606, 1^147, 1^125 in the first 10^7 steps) are made by earlier phases.
At 10^9 steps the head is inside the tape, between `(100)^6706 1` and `(101)^468 ...` (see the samples below).

## Fourth pass: the tape as run lengths, two pumps, and why it resists acceleration

At each new leftmost cell reached in state D (`c/dv.c`) write the tape as the lengths of its runs of 1s, single 0s
between runs (`2^a` = a runs of length 2, i.e. the block `(011)^a`; `1^k` = k runs of length 1, the block `(01)^k`):

    1  2^a  FRONT  ...  X  ...

Two regimes alternate; in both the left block gains runs of 2 and a single long run X further right loses 3 cells:

    pump 1 (two visits):   1 2^a  3 2^2 1^k  ... X ...   ->   1 2^(a+2) 0 2^2 1^k ... X ...   ->   1 2^(a+1) 3 2^2 1^(k+3) ... X-3 ...
    pump 2 (one visit):    2^a  (1 2)^j  ... X ...       ->   2^(a+2)  (1 2)^(j-1)  ... X-3 ...

Pump 1 is the growth phase `eat` of `lean/Rules.lean` in run lengths (n -> n+1, m -> m+3, r -> r-3 over six visits of
the left end in state B). Examples: visits at steps 115,587 to 124,455 (pump 1, X = 36 down to 0) and 230,038 to
246,548 (pump 2, X = 81 down to 0). When X reaches 0 the head works through the list behind it and rewrites a
stretch of it at once (for example 105,073 steps between the visits at 124,600 and 229,673); the list is long and
irregular (4,041 runs at 2*10^8 steps; pieces `2 1`, `2^3 1^k`, `0 2^2 1^k`, `(1 2)^j` and isolated long runs), and
these rewrites were not decoded.

**No acceleration found.** The exact macro simulator written for 1RB1RF_1LC1LF_---1LD_1LE0RA_1RE1LB_1RD0LD
(`c/msim.c` there: blocks on a fixed grid, runs crossed at once, linear cycle jumps) agrees with the plain machine
on this machine too (state, head and tape hash at 1,000,002 and 300,000,001 steps) but gains nothing for blocks of
2, 3, 6 or 12 cells: the tape mixes words of period 2, 3 and 5 cells (`01`, `011`, `10110`) and has tens of
thousands of runs of blocks (24,000 at 5*10^10 steps with blocks of 6). A simulator on run lists with learned
rules (as for 1RB1RF_1LC1LB_1RD1LD_1RE0RA_---0LB_0LF0RC) would need rules that act on a window of the list, not on
the whole tape.

## Phases to 5·10^11 steps (22 November 2026)

Observed with the plain simulator `c/snap.c` (no halt in the first 5·10^11 steps; trusted computation, not checked
by Lean) and summarised by `py/phases.py` (`evidence/phases-5e11.txt`: the tape every 10^9 steps as its big blocks).
Seen from far away the tape is

    (100)^a   [ 1^X  or  (011)^n / (101)^n  or  (11100)^m ]   (5-word)^K   irregular stretch   (10)^c  tail

where "5-word" is one of the rotations of `00111` or `01011` (the run rewrites a block between rotations each time
it crosses it). The run alternates between two kinds of phase:

- **S (left end fixed).** The zone `(100)^a` shrinks and the block of 5-words grows, from left to right; the
  irregular stretch is unchanged or grows.
- **G (left end moving left).** The pump of `lean/Rules.lean` (`eat`): the zone `(100)^a` grows, eating a run of
  ones `1^X` (with X close to 6a) or a stretch of `(011)`/`(101)`. In the early G phases the irregular stretch is
  also eaten, and the 5-word block is turned into a new irregular stretch.

**The current phase (since 2.82·10^11) is very regular.** The tape is

    (100)^a  ~7 cells  1^X  (5-word)^66518  1^Y  (0110110101011)^63  [120,574 cells, unchanged]  (10)^3212  tail

In this phase K = 66,518 does not change, the irregular stretch is not touched, and the right end has stayed at
cell 24,097 since 4.6·10^10 steps. Over one long round the head turns `1^X` into `(01)^(X/2)` and back (crossing
the 5-word block, which changes rotation), while X tracks 6a + 9 (for example a = 69,856 and X = 419,145 at 4.97·10^11).
Y goes down slowly, from 261,805 at 2.84·10^11 to 54,641 at 5·10^11. When Y runs out, the head will reach the
13-word block and the irregular stretch again. No phase so far needed anything from the irregular stretch except at
these hand-overs, so a halt (C reading 1 next to six 1s, per the CTL search below) would have to happen there.

The end of this phase and what follows: see the next section.

## Past 5·10^11 steps with a block accelerator (23 November 2026)

`c/bacc.cpp` is an exact accelerator built for this run. It keeps the tape as blocks (word, count) and:

- crosses a whole block w^k in one jump when one copy (or two, or three) is crossed and the head leaves in the
  state it came in with (cached trial);
- repeats a moving front, such as the conversion `(01)^n` to `(11)^n` one word at a time, once its configuration
  minus two block counts has come back twice with the same count changes;
- crosses runs of 64 cells with no structure in one go when that chunk has been crossed before (cached).

It is a trusted computation, not a proof. Checked against the plain simulator `c/snap.c` (`py/tapecmp.py`: same tape,
head position and state): at 10^8 steps from blank tape, and from saved plain tapes 1·10^11 to 1.5·10^11, 2.5·10^11 to
3·10^11, 3·10^11 to 5·10^11 and 4.99·10^11 to 5·10^11. In the regular phases it covers 10^10 steps in well under a
second; on the long stretches with no structure it is only a few times faster than the plain simulator.

**No halt in the first 2.16·10^12 steps** (from the plain tape at 5·10^11, `evidence/bacc-5e11-to-2.15e12.txt`: the
tape as its big blocks every 10^10 steps). What the run did:

| steps | what happens |
|---|---|
| 5·10^11 to 5.95·10^11 | the regular phase above continues; the run of ones `1^Y` runs out |
| 5.95·10^11 to 9.2·10^11 | the irregular stretch is eaten from 120,571 to about 70,000 cells while the left end keeps moving; the 5-word block shrinks from 66,518 to 48,627 words; blocks of a 19-cell word come and go |
| about 9.2·10^11 | the tape is rebuilt as `(001)^a (5-word)^135383 (11)^Z (0110110110101)^13146`, then 142,999 cells of irregular stretch |
| 9.3·10^11 to 1.86·10^12 | a new regular phase: a grows from 104,120 to 360,930 and Z goes down from 374,882 to 0; the 5-word block, the 13-word block and the irregular stretch do not change |
| 1.86·10^12 to 2.16·10^12 | the second hand-over: the left zone (now `(100)^a`, a about 385,000) is fixed and slowly shrinks, the 5-word block is turned into blocks of 13- and 19-cell words, and the irregular stretch grows to about 880,000 cells |

So far the run looks like a slow hierarchy. Each regular phase builds the left zone `(100)^a` (or `(001)^a`) at the
expense of a run of ones or of `(11)`. Each hand-over turns blocks into a larger irregular stretch and then a larger
regular phase. A halt would need C to read a 1 next to six 1s inside a hand-over. The hand-overs are where the
accelerator is slow, and they are not decoded.

## Where it could halt

The machine halts only on C reading 1. The CTL search of `bbtools.ctl` (K = 6) allows it only with six 1s to the
left of the head: inside or next to a long run of ones, which is exactly what the growth phases eat. A halt needs
the head to arrive in state C on a 1 just after such a run, which the phase rule above never does; it would have
to happen in the irregular part between phases.

## Status

Open. Proved in Lean: the halting configurations, no halt in 10^7 steps (`lean/Blank.lean`), one double cycle of the
growth phase (`lean/Rules.lean`). Observed (not proved): the phase structure. Not understood: the irregular region
between phases and how it makes the next run of ones, so there is no macro map yet.

### Next steps

- Decode what happens when the pumped run X reaches 0, as rewriting rules on a window of the run list (the
  list is too long and irregular for whole-tape shapes), then build a run-list simulator with local rules.
- Restate `eat` in a normal form (`rep_rotate`) and iterate it, as for the other machines of this batch.
- Study the irregular region between phases: record it at each phase start and look for a rewriting system (it
  resembles the digit lists of 1RB1RF_1LC1LF_---1LD_1LE0RA_1RE1LB_1RD0LD).

## Deciders tried (F11, 13 November 2026)

None closes. Each reaches a halting configuration in its abstraction, which says nothing about halting.

- n-gram CPS (`tools/c/ngramcps.c`), equal widths on both sides: a halting local configuration is reached with plain up to width 16, history 1 up to width 15, history 2 up to width 13, history 3 up to width 12, LRU history up to width 4 (larger widths ran out of the 150 s or 60 million configuration budget).
- n-gram CPS with every cell tagged by its position mod p: fails for p = 2 up to width 12, p = 3 up to width 12, p = 4 up to width 12, p = 6 up to width 12.
- n-gram CPS where each side also carries the state of a small automaton that has read that side from the far end (every automaton with up to 3 states on both sides, or 4 states on one side), with position mod 1..4 and widths 4, 6, 8: no closed set without a halt in the 47 of 120 parameter sets that were run (sweep not finished).
- Run-length windows (the K nearest runs of equal macro cells on each side, run lengths kept exactly below T and mod M above): fails for all 72 parameter sets (cells of 1 to 4 bits, K = 2, 4, 6, T = 2, 4, M = 1, 2, 4).
- Two-automaton closed tape language by SAT (a deterministic automaton reading each side inward, n states each, CaDiCaL): no solution for n = 2..9; n = 10 not finished in 150 s.
