# 1RB1RE_0RC0RF_1LC1RD_1RA0LE_0RA0LD_0RA---

bbchallenge id 60274, one of the six-state holdouts. **Open; only the shape is known.** The tape is a list of
blocks of a = 111110 and b = 111010 with short separators, and a small counter-like region at the right end; within
a phase one block of a's is transferred into another, one a at a time, while a block of b's grows; the phases are
nested several levels deep. One sweep rule is proved in Lean; the phase rules are only observed.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RE |
| B | 0RC | 0RF |
| C | 1LC | 1RD |
| D | 1RA | 0LE |
| E | 0RA | 0LD |
| F | 0RA | --- |

## What it does

Words: `a = 111110`, `b = 111010`. At each new cell on the right (`c/events.c`, `R` events) the tape reads like

    1^2 0 a^7 1^3 0 1^2 0 a^x 1^3 0 1^2 0 a^y b a b a b^2 a^5 b^5 a b^z [right end] A> 0

(step 8.3·10^8 to 10^9). Within this phase x + y = 7388 stays fixed and z = x − 3716: every ~6 events at the right
end one a moves from the block a^y to the block a^x and the block b^z gains a b. The right end, a few dozen cells of
`1^3 0`, `1 0` and `b`, changes at every event like a small counter. Earlier phases show the same pattern with more
levels: for example from step 2.1·10^7 to 3.0·10^7 the tape is

    1^2 0 a^5 1^3 0 1^2 0 a^632 1^3 0 1^3 0 1^3 0 a^u 1^3 0 1^2 0 a^v b^2 a b a b a^2 b^w ...

with u + v constant (8 + 595 = 541 + 62) and w following u. When a transferring block runs out, the blocks are
reorganised and a new phase starts; the left side of the tape (17 cells after 10^9 steps) grows like the logarithm
of time, the right side like its square root.

Proved for all lengths (`lean/Rules.lean`, generated by `py/gen_rules.py`):

    b_right:  L 0 A> b^n R  ->  L (010111)^n 0 A> R      (10n steps; 0 b^n = (010111)^n 0, the block is unchanged)

**Halting.** The only halting transition is F reading 1, and F is entered only from B reading 1 (B1 → 0RF). So the
machine halts exactly when the head in state B reads `1 1`.

## For later

Only the shape is known. To make progress: (1) find the per-event rule of the right-end counter (it looks like a
counter in the words `1^3 0`, `1 0`, `b`) and the sweep that moves one a from a^y to a^x (the leftward sweeps
rewrite the b-block; `symtm` finds leftward crossings that turn b into other words, to be matched with the
rightward ones); (2) the reorganisation at the end of a phase, from samples around the steps where a transferring
block reaches 0 (e.g. around 3.0·10^7 and 4.2·10^7); (3) then a map on the block lengths. This is more than a day
of work.

## Status

Open. Lean: the halting configurations (`step_none_iff`), no halt in 10,000 steps by the kernel and in 10,000,000
by `native_decide` (`lean/Blank.lean`); the sweep `b_right` for all lengths (`lean/Rules.lean`). C
(`tools/c/triage.c`): no halt in 1,000,000,000 steps.

## Family screen (F09, 13 November 2026)

runs the machine from blank tape for 2·10^10 steps and, at the first new leftmost and rightmost cell after each
threshold 10^6·4^k, compresses the tape twice: repeats of a word of at most 40 cells (level 1), then repeats of

Next step: Sample at the records where the tape is shortest (state D at the left end) and find the map on the block lengths and the tail; then the F01 closure.

## Eras up to 10^16 steps (F09, 13 November 2026)

The earlier sections describe one phase. `c/msim_turns.c` (the macro simulator with a line at every reversal of the head)
and `py/phases.py` (which groups the left turns by the list of long runs on the tape) give the picture up to 10^16 steps:
`py/phases_1e16.txt`, 51 groups of at least 30 left turns with the same runs of at least 300 copies (blocks of 6 cells).
Everything in this section is observed in one run; none of it is proved.

**No halt in the first 7·10^16 steps** (the macro simulator of the family screen, level: trusted).

The run is a sequence of eras. An era starts when the head turns at the left end with no long run on its left; the
tape right of it then starts with one long run. Eras found (runs of at least 50 copies before 10^9 steps, at least 300 after):

| first step | long run at the left end | copies |
|---|---|---|
| 3,226,696 | `100000` | 173 |
| 20,781,572 | `000010` | 633 |
| 733,253,862 | `100000` | 3,701 |
| 1,116,403,678 | `100000` | 7,389 |
| 6,800,106,750 | `000010` | 7,401 |
| 301,992,023,962 | `100000` | 118,265 |
| 1,758,349,347,884 | `000010` | 118,281 |
| 61,827,815,752,564 | `100000` | 709,541 |
| 393,284,449,924,170 | `000010` | 4,257,168 |

Two kinds of era alternate from step 1.1·10^9 on, one over the word `100000` and one over `000010`, and the main run grows
by a factor that is not constant: about 1 (7,389 to 7,401; 118,265 to 118,281), 16 (7,401 to 118,265) and 6 (118,281 to
709,541 to 4,257,168). Inside an era the machine is a bouncer making a few passes. In each pass a wall of `110111` (or
`011111`) grows by one block per sweep and eats a run of n blocks, while a new run grows behind the far end, so a pass
takes about n sweeps. The long phases of the era starting at step 301,992,023,962:

| first step | left turns | what changes |
|---|---|---|
| 301,992,023,962 | 287 | `100000^n` 118,265 → 117,979; `010001^m` 59,111 → 58,982; nothing long left of the head |
| 303,312,950,888 | 117,332 | wall `110111^k` 332 → 117,663; `100000^n` 117,946 → 615; a second run `100000` 300 → 117,630; `010001^m` 58,965 → 300 |
| 743,670,569,254 | 117,635 | second wall `110111^k` 300 → 117,934 behind a finished `110111^118264`; `100000` 117,934 → 300; `100010` 302 → 117,932 |

Between the passes the short markers and the irregular tail at the right end (about a dozen blocks that change at
every sweep) decide what the next pass does. That is where the factors 1, 6 and 16 must come from; the rule is not
known. Because the passes are plain bouncer passes, a proof would need only the map from one era to the next, including
the tail. Reproduce (about 9 minutes):

    gcc -O2 -o msim_turns c/msim_turns.c
    ./msim_turns 1RB1RE_0RC0RF_1LC1RD_1RA0LE_0RA0LD_0RA--- 6 1e16 - 1 t | grep " A> " | python3 py/phases.py /dev/stdin 300 30
