# 1RB0LD_1RC1RE_1LA0LD_1LB1LC_0RA1RF_1RA---

bbchallenge id 37988. A six-state holdout of BB(6). **Open.** The run is an odometer built from blocks
`(10)^n`: each sweep carries a parity signal to the right, like the carry of a binary counter. An exact item-level
model (checked against direct simulation) ran 5·10^10 sweeps (4.3·10^21 steps) with no halt.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0LD |
| B | 1RC | 1RE |
| C | 1LA | 0LD |
| D | 1LB | 1LC |
| E | 0RA | 1RF |
| F | 1RA | --- |

## What it does

The tape grows to the left. At every *sweep start* the head is in state D on the leftmost cell (a 0), and the tape to
its right is a list of **items**, a block `(10)^n` and one separator cell s:

    D> 0 (10)^n0 s0 (10)^n1 s1 ... (10)^nk sk          s0 = 0, sk = 1   written [(n0, s0), ..., (nk, sk)]

A sweep runs right to some item and back. What it changes is decided by a signal, X (act) or Y (pass):

* leaving item 0 the signal is X if n0 is even, Y if n0 is odd; every sweep adds 3 to n0;
* X at an item with n ≥ 1: n decreases by 1, the sweep ends;
* Y at (n, 0): unchanged; the signal becomes X if n is even, Y if odd;
* Y at (n, 1): n odd: the separator becomes 0; n even: the item becomes (n+1, 0) and the next item loses 1; either way
  the signal becomes X.

Steps of a sweep that ends at item d: 12 + 3d + 3·Σ_{j<d}(2n_j + 1), plus 2 (odd) or 4 (even) per separator-1 item
crossed. On separator-0 items this is a **binary carry chain on the parities** b_i = n_i mod 2: the sweep skips the
leading run of odd items and shortens the item after the first even one, so item k is shortened about once every
2^k sweeps. Four special sweeps handle empty items:

| sweep | when | result | steps |
|---|---|---|---|
| reset | X at (0, 0), all earlier separators 0 | [(2,0), (n0,1), ..., (n_{i-2},1), (n_{i-1}+1, 1), rest] (a following (0,0) merges in) | 28 − 3i + 3Σ_{j<i}(2n_j+1) |
| merge | X at (0, 1) inside the list | (p,0) (0,1) (m,s) → (p+m, s) | as a regular sweep |
| end decrement | X at a last (0, 1) | (p,0) (0,1) → (p−1, 1) | as a regular sweep |
| end reset | Y at the last item (m, 1) | like a reset of the whole list, last item (m+2, 1) if m odd, (m+1, 1) (1, 1) if even | 34 − 3k + 3Σ_{j<k}(2n_j+1) + 6m |

Every other sweep is *unmodelled*; the halting sweep is one of them. Emergent behaviour: an odometer whose digits are
unbounded. The front item counts sweeps (3 per sweep); when an item is exhausted, a reset pushes the front item into
the list as a new long item; the list grows slowly (36 items after 5·10^10 sweeps). The far end keeps small
separator-1 leftovers from the first steps, e.g. `(7304,1) (1851,1) (175,1) (69,1) (7,1) (1,1)` after 10^10
sweeps, which the carry chain reaches only once every 2^30 sweeps or so; end resets add new `(1,1)` items there.

## Where it could halt

The only halting transition is F1. `lean/Halt.lean` proves that a sweep start
`D> 0 0 (10)^(2a+1) 0 (10)^(2b) 1 1 1 R` (Y meets an even separator-1 item followed by an empty separator-1 item
and a 1) halts. More generally, the item simulator stops on any unmodelled sweep; none occurred.

## Status and evidence

Open. Evidence, by trust level:

| result | level | where |
|---|---|---|
| sweeps acting on items 1, 2, 3 and the reset at item 1, for all lengths | kernel | `lean/Rules.lean` (`x_at_1`, `reset_at_1`, `y_x_at_2`, `yy_x_at_3`), generated by `py/gen_rules.py` |
| the halting pattern halts | kernel | `halt_case`, `lean/Halt.lean` |
| no halt in 10^4 / 10^7 steps | kernel / native | `lean/Blank.lean` |
| the item model and its step counts are exact: 37,000 random item lists against cell-by-cell sweeps, every sweep start of the first 3·10^6 steps from blank (Python) and of the first 3·10^7 (C against the records) | trusted | `py/items.py check`, `c/items.c` |
| 5·10^10 sweeps, 4.3·10^21 steps, all modelled: no halt | trusted | `c/items.c` |

## Reproduce

```sh
. /etc/profile.d/lean.sh && holdouts/1RB0LD_1RC1RE_1LA0LD_1LB1LC_0RA1RF_1RA---/lean/check.sh
python3 holdouts/1RB0LD_1RC1RE_1LA0LD_1LB1LC_0RA1RF_1RA---/py/gen_rules.py > holdouts/1RB0LD_1RC1RE_1LA0LD_1LB1LC_0RA1RF_1RA---/lean/Rules.lean
python3 holdouts/1RB0LD_1RC1RE_1LA0LD_1LB1LC_0RA1RF_1RA---/py/items.py check
gcc -O2 -o items holdouts/1RB0LD_1RC1RE_1LA0LD_1LB1LC_0RA1RF_1RA---/c/items.c && ./items 1e9 1e8     # 2·10^18 steps in about 15 s
```
