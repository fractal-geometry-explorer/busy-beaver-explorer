# 1RB0LE_1RC---_0RD0RE_1LE0RB_0LA0LF_0RC0LD

## What it does

A two-sided bouncer on blocks of four cells, running in phases.

**Where it can halt.** Only in B reading a 1. B is entered from `A>0` (write 1, move right) and from `D>1` (write 0,
move right), so the machine halts exactly when one of these happens with a 1 just right of the head. In the first
10^8 steps B is entered 13,163,946 times, always onto a 0.

**The main regime.** At the left end in state F the tape is

    P a b  =  F>0^6 (1000)^a 1 0 1 1 1 (0001)^b T

with the tail T cycling through `0100010100001`, `010110100001`, `0111011`. A round trip: moving right, D carries a
pair `0 0` and turns each block into `1111` (`0 0 D>1000 -> 1111 0 0 D>`, 28 steps a block); at the right end the tail
moves to its next shape and, on two shapes of three, swallows one `0001`; moving left, A turns `1111 A>1` into
`A>1 0001` (10 steps a block), which is `1000` again re-bracketed; at the left end a short dance adds two `1000`.
Three trips: `P a (b+3) -> P (a+6) (b+1)` in `114a + 114b + 1115` steps.

**Phases.** When the 0001s run out the tape is rebuilt: the ~3b left blocks become the next reservoir and the left
part restarts at `(1000)^3`. Phase starts (`py/phases.py`): b = 0, 2, 6, 32, 94, 287, 862 at steps 613 ... 10,800,216.
The offsets depend on the tail shape when the reservoir empties (Collatz-like). After b = 862 the rebuild is
incomplete: a segment `(1000)^859` remains on the right and is eaten slowly by the following phases
(b = 8, 36, 290, 1156; segment 859, 850, 742, 454). At 3·10^11 steps the tape has three long segments: a nest of
counters.

## Where it can halt: one shape, reached only on two exact lines (symbolic class search, 13 November 2026)

Tools in `py/closure/` (not Lean; the results below rest on these programs and on the comparison with a plain
simulator):

- `paccel.py`: the exact accelerated simulator of `holdouts/1RB0RD_1RC0LF_…/py/closure/accel.py`, extended to runs
  with several free counts. A symbolic run refuses every step whose outcome depends on a variable.
- `pclosure.py`: a *node* is the tape at a left-end event in state F that reads `00001 (1000)^k 101…` (k ≥ 1). A
  *class* is a node shape with every count ≥ 20 free, each with a fixed residue. A class is run symbolically to the
  next node; when the run needs the residue of a count, or the sign of an affine form in two counts, the class is
  split into *pieces* and each piece is run again.
- `pvalidate.py` with `c/round.c`: every piece, and random points of every class, against a plain step-by-step
  simulator (the tape of the next node must be equal cell by cell).
- `hline.py`: reads the certificates, the plain runs of the lines below, the run from blank tape.

**Result of the search (tool level).** Started from the class of the node at step 20,791 of the run from blank tape
(`00001 (1000)^35 1010000100001`), the search ends with an empty queue and no undecided piece:

| residues | classes | pieces | halting pieces | certificate |
|---|---|---|---|---|
| mod 2 | 185 | 3,768 | 2, both in H | `classes_mod2.json.gz` |
| mod 4 | 318 | | only in H | (not stored) |
| mod 8 | 430 | 2,877 | 3, all in H | `classes_mod8.json.gz` |

Every other piece runs to a node of a class in the set. The only halting shape is

    H(P)    =  F> 00001 (1000)^P 101000011011101                        P odd, P ≥ 21

and the only pieces that lead to H are, for odd P ≥ 21,

    A(P, Q) =  F> 00001 (1000)^P 10100001101000 (0001)^Q 01000000101          with Q = 3P − 16   →  H(8P − 27)
    B(P, Q) =  F> 00001 (1000)^P 101000010000001011 (1000)^Q 101000000101     with Q = 3P − 24   →  H(8P − 41)

So, as far as the tools are right: **from blank tape the machine halts if and only if the run visits A on the line
Q = 3P − 16 or B on the line Q = 3P − 24.** The class set does not decide this: the classes of A and B off the lines
have the same residues as on them (with residues mod 8 the predecessors of H are A with (P, Q) ≡ (1,3), (3,1), (7,5)
and B with (7,5)), so no finer residue split separates the lines. This is the "a class halts" outcome of the
closed-set method: a Collatz-like question about the orbit of the pair (P, Q), not a closed set.

**Checks.** `pvalidate.py`: mod 2 certificate, 4,539 piece runs and 713 class points, 0 problems; mod 8 certificate,
4,476 piece runs and 1,702 class points, 0 problems (for a point, exactly one piece of its class must contain it).
Plain runs (`hline.py plain`): H(P) halts for P = 21, 23, 25, 31, 51, 101 (after 1,645 … 6,925 steps; it also halts
for the even P tried, which the class set never reaches); A(P, 3P−16) halts for P = 27, 29, 41, 101 and
B(P, 3P−24) for P = 29, 31, 45, while the neighbours Q ± 2 do not halt in 3·10^6 steps.

**The run from blank tape (observed).** `hline.py run 120 …`: 2,992 nodes, up to a step count of 112 digits (about
10^111 steps), no halt; every node from step 20,791 on is in a class of the mod 2 certificate. H is never visited.
A is visited 108 times, the closest to its line being |Q − 3P + 16| = 749 (P mod 8 is 1, 3 or 7; Q takes every
residue mod 8). B is visited 1,236 times, always with P ≡ 7 mod 8 and Q even, so Q − 3P + 24 is odd and the B line
is never hit in this sample (not proved: the class set allows B with Q odd), the closest being 2,999 away.

**Further, with the node map (`nodemap.py`, 16 November 2026).** Iterating the certificate's pieces with exact
integers from the first big node: 1,000,000 nodes (counts up to 2,031 digits), no halt, and the closest approaches
to the two lines are still the early ones (749 and 2,999). **B is visited with Q odd**: first at node 3,693 (step
count of 124 digits, just past the sample above), 60 times in the first 10^6 nodes. The accelerated simulator
(`pclosure.real_nodes`) gives the same first visit. So the even-Q pattern was an artifact of the sample, and the B
line is a real part of the question.

Why it took so long. In the regime with big counts the node map acts on the ratio r = Q/P like a continued
fraction: C goes to B with r → (r − 1)/4 (if r > 1), B and A go to C with r → (r − 3)/8 (if r > 3), the
`10100001 (1000)^P …` shapes loop with r → (1 − r)/(4r) and go to A with r → (r − 1)/4, and A and B with r < 3
go to those shapes with r → (3 − r)/(8r). The only way into B with Q odd is A with Q odd and Q ≥ 11P − 12, then C
with Q odd and Q ≥ P + 16; that needs an earlier ratio within about 1/180 of 1 (or of 3), a near miss of a line.
Such near misses are rare but not excluded by anything; no inequality invariant keeps the run out (a template
polyhedra search over the certificate, with 12 slopes, loses every relational bound).

## Lean replay of the class search (16 November 2026)

`halts_iff_lines` (`lean/Lines.lean`), proved in Lean with `native_decide`:

    HaltsFromBlank ↔ ∃ P, P % 2 = 1 ∧ 21 ≤ P ∧ (Reach init (A P (3P − 16)) ∨ Reach init (B P (3P − 24)))

with A and B the two shapes above, as explicit configurations. So "halts if and only if the orbit hits one of the two
lines" is now a Lean theorem, not only a result of the programs.

How it is checked. `py/replay/explore.py` redoes the class search with the replay engine (`py/replay/engine.py`, the
Python model of the Lean executor) and writes a certificate (`py/replay/cert.json.gz`): 185 classes (text and
parity of every count, all counts ≥ 20), 6,294 leaves, 45 cycle rules, and the arrival (7,227 executor moves from
blank tape end at `F> 00001 (1000)^35 1010000100001`). Each class has a tree of primitive splits of its free
variables (a residue, the first few values, or a comparison of two variables) whose leaves each run, with the
variables still free, to a node of a listed class or to a halt. `py/replay/gen.py` re-checks all of it in Python
(about 4 minutes) and writes the Lean data.

In Lean: `lean/Exec.lean` is the symbolic executor with several variables (copied from the replay of
1RB0RD_1RC0LF_1LA0LB_---1RE_1LB1RA_0LC0RA, with the event and the rule strategy changed) and its soundness
theorems; `lean/Pieces.lean` has the split trees (`chk_sound`: the leaves cover every value), the classes, and the
generic theorem `halts_iff_of_checks`: if every class passes `clsOK`, every entry of `pre` passes `preOK` and the
arrival passes, then the machine halts if and only if its run reaches an entry of `pre` (a start that runs into a
halting class). The certificate is stored as strings of numbers (`lean/Data.lean`) and read back by `lean/Decode.lean`;
the reader is not trusted, the theorems are about the lists it returns. `lean/Check0.lean` … `Check7.lean` evaluate
`clsOK` on all classes, `lean/Arrive.lean` the arrival and `pre`, `lean/Replay.lean` assembles `halts_iff_pre`, and
`lean/Lines.lean` writes the 14 entries of `pre` out as the two lines.

What it rests on: the soundness theorems are checked by the kernel; the evaluations of the checks (the 8 class
chunks, the arrival, `pre`) are `native_decide`, so they also trust Lean's compiler. `#print axioms halts_iff_lines`
lists only `propext`, `Classical.choice`, `Quot.sound` and the `native_decide` axioms of those checks. The whole
check takes about 7 minutes with 4 parallel jobs.

## Open, and next steps

- The machine is a two-register process on (P, Q) with one halting shape. Halting from blank tape is the question
  whether the orbit ever lands on one of the two lines. It looks like the Collatz-like ("cryptid") machines of
  family F12 rather than a closed-set candidate.
- ~~Prove that B is only visited with Q even~~: false, the run visits B with Q odd from node 3,693 on (above).
- Write the node map as an explicit map on (shape, P, Q) from the certificate and iterate it with big integers; the
  certificate has every piece as affine forms, so this is mechanical.
- Done: the Lean replay of the certificate (above), with `native_decide`. A kernel-only check would need a faster
  executor or much more time.
