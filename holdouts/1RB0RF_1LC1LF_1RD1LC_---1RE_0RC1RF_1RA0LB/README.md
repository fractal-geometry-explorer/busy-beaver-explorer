# 1RB0RF_1LC1LF_1RD1LC_---1RE_0RC1RF_1RA0LB

bbchallenge id 39952. One of the six-state holdouts whose halting from blank tape is open. Family: binary counter
with rounds of growing width, nested in slower counters (exp/exp).

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RF |
| B | 1LC | 1LF |
| C | 1RD | 1LC |
| D | --- | 1RE |
| E | 0RC | 1RF |
| F | 1RA | 0LB |

## What it does

**A binary counter written twice.** From about 1.15·10^6 steps on, the head works around one fixed cell and the
number n is written on both sides of it in 4-cell words: on the right V(n), least significant bit first, `1011` for
a 1 and `1111` for a 0; on the left W(n-1), least significant bit nearest the head, `1111` for a 1 and `1010` for
a 0. The configuration holding n is

    ... W(n-1) 1 1 D>1 1 1 1 1 V(n) ...

and one increment (one trip of the head out and back) takes it to n + 1: 8t + 42 steps when n - 1 ends in t + 1 ones,
14s + 48 steps when n - 1 ends in a 0 and n in s + 1 ones. Leading zeros are the stretch `1 0 1 0 ...` on the left
and the long block of 1s on the right.

**Rounds.** The left copy has room for 12 digits (it is bounded by a block `1^13 0`), the right one is open. A round
counts n = 1, ..., 2^w - 1; then the right copy's top bit runs into the right end, the last block grows by four
(`0 1^m 0 1 0 1 0 1 A>0` → `0 1^(m+4) 0 1 0 1 A>0`) and the count restarts at 1 with one more bit of room. A round
costs about 56 steps per increment, about 2.3·10^5·2^(w-12) steps: the right end is reached at times that double.

**Slower counters.** Every 4096 increments the 12-digit left copy overflows and the carry goes on into the region to
its left, a second counter in a different code (blocks `1^4`, `1^8`, `1^12`, `1^16` that grow by four, and an inner
digit with four phases); the head comes back with the left copy cleared. Further left is a list of short blocks
(`1^7`, `1^4`, `1^3`, ...). The head reaches the far left end only when n hits particular values (2^14 in rounds 15
to 17, 2^14 + 2^17 in round 20, 2^14 + 2^17 + 2^20 in rounds 21 to 23), and some of these visits use up one of these
blocks. At such a visit the right part of the tape, `1^59 0 1^11 0 1^11 ...`, is V(n) as the leftward sweep leaves it
(zeros at bits 14, 17, 20, ...): the "blocks of 4k + 3" of the first look.

**Epochs.** The first 920,431 steps are a smaller copy of the same structure, with `1^15` where the second has
`1^59` = 1^(4·15 - 1); there the list of left blocks ran out and the tape was rebuilt. After 5.4·10^8 steps the
second list is down to `1^3 0 1^3 0 1^3`.

## What is established

**Proved in Lean, kernel only** (`lean/Rules.lean`, generated by `py/gen_rules.py` with `bbtools.symtm`):

- the halting configurations (`step_none_iff`, `lean/Blank.lean`); no halt in 10,000 steps;
- the sweeps, for every length: `sweep_A` (`A> (10)^n` → `(01)^n A>`), `sweep_F` (`F> (01)^n` → `(10)^n F>`),
  `sweep_E` (`E> (01)^n` → `(11)^n E>`), `sweep_C`, `sweep_B` (pairs `1 1` → `0 1`, moving left);
- the counter's increment rules `inc_odd` (8t + 42 steps) and `inc_even` (14s + 48 steps), for every t, s and
  every tape beyond the words they name;
- `right_end`: `0 1^n 0 1 0 1 0 1 A>0 0^inf` → `0 1^(n+4) 0 1 0 1 A>0 0^inf` in 22 steps.

**Proved in Lean with `native_decide`:** no halt in 10^7 steps.

**Computed** (trusted):

- No halt in the first 10^10 steps (`tools/c/tmrun.c`); no halt in 10^9 (`tools/c/triage.c`).
- The rounds, to 2·10^9 steps: `py/counter_check.py` tests, at every step C0 → D, whether the tape is the counter
  configuration for some n, and groups the matches into runs where n goes up by exactly one at a fixed cell. From
  1.15·10^6 steps on, the 35.7 million matches cover n = 1, ..., 2^w - 1 for every w from 12 to 24 (round 24 ends at
  step 1,881,955,329), the left half always 12 digits wide. Until 9.2·10^6 steps a round is cut into runs at the
  multiples of 4096 (the left overflows); from then on each round is one run. Output: `py/counter_check_2e9.txt`.
- The far-left visits: `py/far_left_check.py` reads the counter right after each of the seven far-left visits
  between 1.9·10^6 and 10^9 steps: n = 2^14 + 1 (three times), 2^17 + 2^14 + 1, 2^20 + 2^17 + 2^14 + 1 (three times).
- Where a halt can be: a closed tape language of windows of 5 cells (`bbtools.ctl`, checked by the script) contains
  every configuration reachable from blank tape; its only halts have D reading a 0 with `1 1 0 1 D>0`. Windows of 6
  and 7 cells close too, still with a halt (`1 1 0 1 1 0 1 D>0 0^inf` for 7).

**Heuristic** (seen in simulation, not checked mechanically): the left overflow into a second counter every 4096
increments; the left blocks used up at the far-left visits; the
two epochs and the rebuild at 920,431 steps.

**Open:** whether it halts. None of the proved rules can halt; a halt could only come from the rare events (left
overflows, far-left visits, an epoch rebuild), whose rules are not worked out.

## For later

Write the rules of the left counter and of the far-left visits as functions of their parameters (the trigger values
look like 4, 44, 444 in octal, times 4096), prove them with `bbtools.symtm` (with the 12-digit left copy concrete and
the right copy as a variable), then build a simulator that takes a whole round, or a whole left-counter cycle, in one
move. That should follow the run to the end of the second epoch (far beyond direct simulation) and show what the
rebuild produces and whether it can ever give `1 1 0 1 D>0`. A Lean theorem tying `inc_odd`/`inc_even` into "the
counter goes from 1 to 2^w - 1" needs the encodings W and V as Lean functions and an induction on n.
