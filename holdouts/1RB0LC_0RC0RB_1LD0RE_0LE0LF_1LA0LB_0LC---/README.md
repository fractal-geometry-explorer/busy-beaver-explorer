## Status

**Open.** One of sixteen holdouts that run the same *marker counter*: a base-5 counter written on the tape as markers between long blocks of `0010`, whose markers drift and occasionally collide. The family is described in full in the family lead [`1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0LC---`](../1RB0LC_0RC0RB_1LD0RE_0LE0LF_1LA0LB_0LC---/README.md). Lean proves the pieces of a sweep and whole sweeps for all block lengths (kernel); an exact accelerated simulator runs the machine to 10^16 steps without a halt.

## What it does

Stop the machine each time the head steps onto a new cell at the right end (state E). The tape is then always

    1 (0010)^b0 m1 (0010)^b1 m2 ... mk (0010)^bk 000

blocks of the word `0010` separated by **markers**, each in one of six phases:

| phase | 0 | 0' | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|---|
| marker | `1` | `0` | `0011` | `011` | `11` | `00111` |

(a stretch of cells between blocks is read as the fewest markers that spell it; blocks can be empty). Between two such moments the head makes one **sweep**: a wave in state D runs left, turning each `0010` into `1010` and each marker in phase 4 into `10101`, until it meets a marker not in phase 4; that marker goes up one phase and a wave in state C runs back right, restoring the blocks and resetting the phase-4 markers to phase 0. So the phases are the digits of a **base-5 counter** that counts sweeps, the last marker being the units digit:

- regular turn: the markers after the turning marker go from phase 4 to 0, and each block after them grows by 1; the turning marker goes up one phase, and the blocks before / after it change by −2 / +2 (phase 0), −1 / +1 (phase 0'), 0 / +1 (phases 1 and 2), −1 / +1 (phase 3). It needs at least 2 blocks before it in phase 0 and 1 in phases 0' and 3.
- overflow (every marker in phase 4): the wave reaches the `1` at the left end and comes back in state B; b0 grows by 2, every marker becomes phase 0', the blocks b1..b(k−1) grow by 1, and a new marker `0011` with an empty block appears at the end. The counter gains a digit.
- merge (the block condition fails): a marker has used up the block before it and runs into the marker there. The two interact for a few sweeps (a marker can vanish, a new one can appear at the end) and the run goes on with regular turns.

The tape grows by 3 cells a sweep and a sweep costs about 10 steps per block it crosses, so the tape grows like the square root of the time. A marker in phase p drifts left by 9 cells per cycle of its own phases, so the units marker drifts fastest, catches up with the marker before it after about 3 times the length of the block between them, and merges; the block it leaves behind (about 10/3 of the old one) becomes the new gap. The deeper blocks shrink slower, about 5 times slower per level, and their merges are rarer: in this machine a block of 54 words stood at the left end from step 10^5 to 5.7·10^12, when the second marker merged into the left end and b0 became 11,299.

To 10^11 steps, 282,383 of the 282,433 sweeps are regular turns and 12 are overflows, all exactly as above (`py/model.py`); the other 38 are merges, of 13 kinds.

**Where it could halt.** The only halting transition is F1, and F is entered only from D1: D reads a 1 only in some merges, and then F reads the cell to its left. In this machine F0 = 0LC continues the merge. Every entry into F so far has read a 0 (9 in the first 10^16 steps). `py/merges.py` runs every merge of two markers with long blocks around them symbolically, for all block lengths: none halts, in any of the sixteen machines. But random short tapes of the same shape, where two short blocks meet, often halt within a few thousand steps (`py/clusters.py`). So the machine halts only if two merges ever happen close together on the tape, and that is a question about the arithmetic of a counter whose digits drift: open.

**Sixteen machines, five runs.** All sixteen run the same core (states A–E; the second group the mirror image, with states renamed A,B,C,D,E → D,E,A,B,C and started in the core's state C). They differ only in what D1 and F do at a merge, which changes how some merges end, so the runs part ways at the first merge where D reads a 1. Machines whose D1/F detour ends in the same tape run identically: `py/compare.py` finds five distinct runs (classes I–V, listed in each machine's README), the mirrored members agreeing with the direct ones in every marker from some sweep on, with a different first block.

For this machine, D1 is 0LF and F0 is 0LC.

**Same class as** (the same tapes at another pace for the direct members, the same markers for the mirrored ones; these are not the same run): none of the other fifteen (class II).

- `py/check.py` runs the family checks for this machine: `check_rl.py` (the run-length simulator `c/rl.c` of the family lead agrees with the plain simulation at every sweep end of the first 10^8 steps), `model.py` (to 10^11 steps: 282,433 sweeps, 282,383 regular turns and 12 overflows exactly as the rules say, 38 merges, 4 entries into F), `merges.py` (none of the 48 merges of two markers with long blocks around them halts, for any block lengths).

- Lean (`lean/Blank.lean`): no halt in 10^7 steps.
- To rerun: `python3 py/check.py 1e11` (the `model.py` count above; the default 1e10 is quicker).
