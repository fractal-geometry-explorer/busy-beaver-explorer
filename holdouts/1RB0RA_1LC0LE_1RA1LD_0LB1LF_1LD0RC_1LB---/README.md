# 1RB0RA_1LC0LE_1RA1LD_0LB1LF_1LD0RC_1LB---

bbchallenge id 112769, a six-state holdout of group G05 (growth class fixed/sqrt: the tape grows to the left like
the square root of the step count, the right end hardly moves). **Open.** The machine is a stack of nested counters
whose front level follows a Collatz-like map `y ↦ 4y/3`; the clean part of that map is proved in Lean for all
values, and the run is followed (exactly, by the shared cycle accelerator) to 10^1000 steps without a halt.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RA |
| B | 1LC | 0LE |
| C | 1RA | 1LD |
| D | 0LB | 1LF |
| E | 1LD | 0RC |
| F | 1LB | --- |

## What it does

**The tape.** Write `W = 110` and `V = 100`. At the start of every sweep of the main regime the tape is

    0^∞ C> 0 1 0  W^p  1111  W^x 11100 V^y  W^z 11100 V^w  ...  11 0^∞          cfg p (lv x y (lv z w ...))

the head in state C on the blank cell at the left (growing) end, a **counter** `W^p`, a marker `1111`, and then a
row of **levels** `lv u v = W^u 11100 V^v`, each a run of `110`s, a separator `11100` and a run of `100`s. The
nearest level `(x, y)` is the **front**. For example, at step 58,429 the tape is
`cfg 2 (lv 0 72 (lv 12 26 (lv 10 3 (lv 2 1 (lv 2 0 (lv 2 0 11))))))`.

**One sweep** (`sweep`, 8p + 24x + 75 steps): the head runs right through the counter and the front, turns three
`100`s into four `110`s and comes back. So the separator of the front moves right by three words and the tape
grows by three cells at the left:

    (x, y + 3)  ->  (x + 4, y)

**A phase** (`phase`) is ⌊y/3⌋ sweeps. What happens then depends on `r = y mod 3`:

| r | end of the phase (`end0`, `end2`) | front after | next level | counter |
|---|---|---|---|---|
| 0 | the separator meets the next level | `(0, x)` | `(z, w) -> (z + 2, w − 2)` | `p + 2` |
| 2 | the same with two `100`s left over | `(0, x + 2)` | `(z, w) -> (z + 2, w − 2)` | `p + 2` |
| 1 | a different regime: nested secondary bouncers rebuild the left part | — | — | reset |

**The emergent behaviour: a Collatz-like counter.** On a front level that starts empty, a phase takes `y` to

    y ↦ 4y/3                 (y ≡ 0 mod 3)
    y ↦ 4(y − 2)/3 + 2       (y ≡ 2 mod 3)

and ticks the counter `p` and the next level. From step 58,429: `y = 72 → 96 → 128 → 170 → 226`, `p = 2 → 10`,
the next level `(12, 26) → (20, 18)` (`clean_chain`, reaching step 399,523 exactly). `226 ≡ 1`, and the phase ends
in the other regime: the counter `W^p` and the old front are converted into further levels by secondary bouncers
(a second head-bounce region with its own linear regime, visible between steps 685,000 and 1,330,000), and the run
returns to the clean form with `p = 0`: `734 → 978 → 1304 → 1738 ≡ 1`, and so on. Each level further right
ticks by 2 each time the level before it is reset; when its `100`s run out it is reset in turn and its
neighbour ticks, so the levels form a mixed-radix counter whose digits get longer every time they are reset
(each reset makes the level a little longer). The time to the next carry grows
geometrically (each phase multiplies `y` by about 4/3 and costs about `y²` steps), hence the square-root growth.

**Where it could halt.** Only F reading 1 halts; F comes from D reading 1 (`1LF`), so the machine halts exactly
when D reads a 1 whose left neighbour is a 1, i.e. when C reads 1 at `1 1 C>1`, or E reads 0 at `1 1 E>0`. The
sweep and the clean phase ends never do this (they are proved for all values). Whether the `y ≡ 1` regime, or the
reset of a level far to the right, can ever produce it is the open part.

## Status and evidence

**Lean, kernel** (`lean/Rules.lean`, generated by `py/gen_rules.py` with `bbtools.symtm`): `sweep0`, `sweep1`,
`sweep2` (one sweep for every `p`, `x`, `y`), `reset2`, `reset0` (the clean phase ends for every `p`, `x`, `z`,
`w`). **`lean/Macro.lean`**: the encoding `cfg`, `lv`; `sweep` (all `x`), `phase` (k sweeps, by induction, step
count `pst`), `end2`, `end0`, and the clean phase map `cleanA` (y = 3(k+1)) and `cleanB` (y = 3(k+1) + 2).

**Lean, `native_decide`** (`lean/Start.lean`): `start`, blank tape reaches `cfg 2 (lv 0 72 (lv 12 26 R3))` after
58,429 steps (list simulator of `TM/Fin.lean`, compared after dropping trailing blanks, `app_trim`). Then
`clean_chain` (kernel) runs four clean phases to step 399,523. `lean/Axioms.lean` prints the axioms. Also
`blank_runs_native` (10^7 steps, `lean/Blank.lean`).

**Computed (trusted)**: `py/run_accel.py 1000`: the shared cycle accelerator (`bbtools.cycles` on 3-cell blocks,
every jump an instance of a cycle rule proved symbolically by `bbtools.symtm`) runs **10^1000 steps without a
halt** in about seven minutes (5,609 cycle rules, 3,726 jumps; 10^300 takes two minutes). The tape then has about 20 run-length blocks: the
levels described above, with counts of hundreds of digits.

**Heuristic**: the rules keep their shape across 10^1000 steps; the residues of `y` mod 3 look irregular, as in a
Collatz-like map.

**Open**: a proof needs the `y ≡ 1` regime and the reset of every level as closed rules, and then an invariant
that the resulting level machine never makes `1 1 C>1` or `1 1 E>0`.

## Reproduce

```sh
. /etc/profile.d/lean.sh && holdouts/1RB0RA_1LC0LE_1RA1LD_0LB1LF_1LD0RC_1LB---/lean/check.sh   # under a minute
python3 holdouts/1RB0RA_1LC0LE_1RA1LD_0LB1LF_1LD0RC_1LB---/py/gen_rules.py      # rewrites lean/Rules.lean
python3 holdouts/1RB0RA_1LC0LE_1RA1LD_0LB1LF_1LD0RC_1LB---/py/run_accel.py 1000  # no halt in 10^1000 steps (7 min)
```

## For later

The next step is the `y ≡ 1` regime: write the secondary bouncer (`Q a_k Q a_m … b2 a_n M b_v`, seen between steps
685,710 and 1,326,447) as a rule for all values, and the reset of a level whose `100`s run out (step 1.5·10^16 for
the third level). With those, the level machine would be closed, and a halts-iff reduction (or a non-halting proof,
if no rule can produce `1 1 C>1`) would follow the pattern of `cleanA`/`cleanB`.
