# 1RB1RE_1LC0RA_1RD0LB_1LB1RC_1LF0RD_---0LE

bbchallenge id 87254, one of the six-state holdouts. **Halting is reduced, in Lean, to a map on one number**:
the machine halts from blank tape if and only if the orbit of 1 under the map `next` below reaches `none`. In
closed form the map is "multiply by 3 and subtract a multiple of a power of two", and it halts when n lands
exactly on one of the thresholds c_i = 10·2^i − i − 7. That has not happened in 1,250,000 steps of the map
(n has 833,000 bits by then) and is not expected ever to happen; the question is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RE |
| B | 1LC | 0RA |
| C | 1RD | 0LB |
| D | 1LB | 1RC |
| E | 1LF | 0RD |
| F | --- | 0LE |

## What it does

The samples are the configurations with the head at the left end of the tape:

    S n  =  0^inf C> 0 (10)^n 1 0^inf

(from blank tape, S 1 at step 4). A round from S n to the next sample has two phases.

**Phase 1.** S (n+1) becomes `V n 0 0`, where

    V K i m  =  0^inf 1^(2K) 0 A> 0 (10)^(2i) 111 0 (10)^m 1 0^inf

a left block of 2K ones, a middle block of 2i pairs `10` and a right block of m pairs. Each bounce (`b1`) takes
two ones from the left block and one pair from the right block, and adds two pairs to the middle block:
V (K+1) i (m+1) → V K (i+1) m. When the right
block is used up, `b2` moves the middle block over to the right, with five more pairs: V (K+4) i 0 → V K 0 (2i+5).
So the right block goes through 0, 5, 15, 35, 75, ... = 5·2^t − 5 pairs, and the left block pays for it. The phase
ends when the left block runs out:

| rule | from | to |
|---|---|---|
| `b3` | V 0 i (m+1) | T (2i+2) m, then S (4i + m + 8) |
| `e0` | V 0 i 0 | W3 (2i+2) = `C> 0 (10)^(2i+2) 111`, then S (4i + 7) |
| `e1` | V 1 i 0 | W2 (2i+4) = `C> 0 (10)^(2i+4) 11`, then S (4i + 10) |
| `e2` | V 2 i 0 | **halt** (state F reading 0, after 24i + 56 steps) |
| `e3` | V 3 i 0 | T 0 (2i+5), then S (2i + 9) |

**Phase 2.** `T x z = 0^inf C> 0 (10)^x 111 0 (10)^z 1 0^inf` becomes S (2x + z + 4) (`phase2`): the left block
is turned into 2x+1 ones and each bounce turns two of them into a pair of the right block.

All rules are proved for all values in `lean/Rules.lean` (generated by `py/gen_rules.py` with
`tools/py/bbtools/symtm.py`) and chained in `lean/Phase2.lean` and `lean/Phase1.lean`. The function `ph K i m` of
`lean/Phase1.lean` follows the rules above, one bounce at a time; the map is `next n = ph (n − 1) 0 0`.

## The map in closed form

Adding up the costs of the sub-phases gives, with thresholds c_i = 10·2^i − i − 7 (c_{−1} = −1, then 3, 12, 31, 70,
149, 308, 627, ...): for c_i < n ≤ c_{i+1},

    next(n) = 3n − 2c_i + i + 3     if n < c_{i+1}
              HALT                  if n = c_{i+1}

Writing n = c_i + d with 0 < d < 10·2^i − 1, the offset d becomes 3d + i + 3, so the position in the current level
roughly triples and wraps into the next level or the one after. `py/orbit.py cmp 10000` checks that this closed form
equals Lean's `next` for all n < 10,000 (the closed form itself is not proved in Lean). The orbit of 1:

| k | n | level i (c_i < n ≤ c_{i+1}) |
|---|---|---|
| 0 | 1 | −1 |
| 1 | 7 | 0 |
| 2 | 18 | 1 |
| 3 | 34 | 2 |
| 4 | 45 | 2 |
| 5 | 78 | 3 |
| 6 | 100 | 3 |
| 7 | 166 | 4 |
| 8 | 207 | 4 |
| 9 | 330 | 5 |
| 10 | 382 | 5 |
| 11 | 538 | 5 |
| 12 | 1006 | 6 |
| 13 | 1773 | 7 |

The 19 samples of the first 10^9 machine steps are exactly the first 19 points of the orbit
(`c/samples.c | py/orbit.py check`).

In words: n is a single number written in unary as pairs `10`; the machine measures it against the thresholds
c_i by repeatedly doubling a ruler (the right block, 5·2^t − 5 pairs) paid for out of n. Whatever is left over,
tripled, is the next n. The tape's left end moves once per round, and n grows by a factor of about 3 per round
(about 0.67 bits per round, since the level also wraps), so the left side grows like the logarithm of time and the
right side, swept back and forth, like its square root.

## Does it halt?

`halts_iff_orbit` (`lean/Phase1.lean`, checked by the kernel, no `native_decide`): the machine halts from blank
tape **if and only if** `orbit k = none` for some k, where `orbit 0 = some 1` and `orbit (k+1) = orbit k >>= next`.

- Iterated 1,250,000 times with the closed form (`py/orbit.py`), the orbit never lands on a threshold; at the end
  n has about 833,000 bits, so the machine has run for far more than 2^800000 steps.
- A halt at the next step is possible only when 3n = 4c_i + 3, which needs c_i ≡ 0 (mod 3), i.e. i ≡ 0 or 1
  (mod 6). Over the run the closest relative approach |3n − 4c_i − 3| / c_i (for c_i > 10^6) was 5.9·10^−6, still
  a distance of more than 2^380000.
- Heuristic: if the offset d behaves like a random number in its level, the chance of hitting the threshold
  exactly at a step of level i is about 1/(10·2^i). These chances add up to a convergent sum, so the expected
  number of future hits is about 2^−800000: the machine is expected never to halt, but nothing proves it. This is
  a cryptid in the sense of Antihydra: a Collatz-like map whose long-term behaviour is out of reach.

## Status

Open, reduced to the map. Lean (kernel): the halting configurations, no halt in 10,000 steps (10^7 with
`native_decide`), every rule of a round, and `halts_iff_orbit`. Trusted: the closed form of the map, its match
with 10^9 simulated steps, and 1,250,000 map steps without a halt. Heuristic: a halt is not expected.
