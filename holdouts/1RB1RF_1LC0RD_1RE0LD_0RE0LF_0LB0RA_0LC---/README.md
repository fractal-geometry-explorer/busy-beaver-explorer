# 1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---

bbchallenge id 27281. One of the six-state holdouts whose halting from blank tape is open. Family: Binary counter fed by a work zone (1RB1R?_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC--- twins).

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RF |
| B | 1LC | 0RD |
| C | 1RE | 0LD |
| D | 0RE | 0LF |
| E | 0LB | 0RA |
| F | 0LC | --- |

**Verdict.** **The question is open.** It halts only when F reads a 1, which has not happened in 5·10^11 steps. The tape holds three counters: a binary counter at the left end, a second binary counter in the middle whose overflow increments it, and a tail of irregular gaps at the right that the middle counter reads at every count. Lean proves the increment of the left counter and the reset, carry and settle rules of the middle one; the tail has no known rule, and a halt could only come from there.

## What it does

Twin 2b; the other twin is `1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---`. They differ only in A1 (2a: 1RD, 2b: 1RF), and A reads a 1 only when the left
counter overflows (the first time at step 132). The family's scripts are in `holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/`.

The tape holds three counters, one inside the next:

- **Left end: a binary counter.** After a fixed prefix (`1010101101010110` for 2a; `10` for 2b, `1010101101` after step
  2.26·10^9): 4-cell digits `1010` (one) and `1000` (zero), least significant on the right, ended by `11`. The increment
  `L 1000 (1010)^n C>1 1 R -> L 1010 1 (0001)^n 0 D> R` (12n+8 steps) is proved in Lean for both twins.
- **Middle: a second binary counter.** Right of the `11`, digits `0001` (zero) and `0101` (one). A cycle starts with
  `L B> (1010)^n R -> L (0001)^n B> R`; each count ends with F at its right end, and the carry
  `L 0001 (0101)^c 0001 F> 0000 R -> L 0101 (0001)^c 00 F> 000101 R` (12c+42 steps) and the settle step
  `L 0001 (0101)^c 00 F> 0001 y z R -> L 0101 (0001)^c 0001 F> 00 y z R` (12c+32 steps) add one; all proved in Lean
  (`lean/Middle.lean`). When it overflows it is swept back to `(1010)^n` and one increment goes to the left counter.
- **Right: the tail.** A list of gaps between single 1s, read and rewritten at every count of the middle counter. Its
  first gaps run through three phases, one per cycle, the rest changes every three cycles; no rule is known. The right
  end grows by a few cells at long intervals, and ends in a block `(110)^n`.

For 2a the steps per left increment are constant over long stretches (exactly 53,010 ± 1 increments in each window of
2.5·10^8 steps from 5·10^8 to 1.5·10^9) and change only near overflows of the left counter (`c/lcnt.c`).

## What is established

**Proved in Lean, kernel only:**

- **The halting configurations.** The machine stops exactly when it reads the symbol of a halting transition (F1); the generated statement covers every configuration. (`step_none_iff`, `lean/Blank.lean`)
- **No halt in the first 10,000 steps.** The list simulator of the shared library, proved to agree with the machine's semantics, runs 10,000 steps from blank tape without a halt, evaluated by Lean's kernel. (`blank_runs_kernel`, `lean/Blank.lean`)
- **Shift rules.** One shift rule for all n and any surrounding tape: B crosses `(100)^n` leaving `(101)^n`. (`lean/Rules.lean`, `holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/py/gen_rules.py`)
- **The increment of the left counter.** For every n and any tape around it, `L 1000 (1010)^n C>1 1 R` reaches `L 1010 1 (0001)^n 0 D> R` in 12n+8 steps: C walks left over n one-digits `1010`, turns the zero-digit `1000` into a one, and B walks back turning each one-digit into a zero-digit. A1 is not used, so the same theorem holds for both twins. (`counter_increment`, `lean/Rules.lean` (generated by `holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/py/gen_rules.py`))
- **The middle counter.** Right of the `11` that ends the left counter sits a second binary counter of 4-cell digits, `0001` (zero) and `0101` (one). Four rules, for every number of digits and any tape around them: a cycle starts with `L B> (1010)^n R` → `L (0001)^n B> R` (n zero digits, 4n steps); a carry `L 0001 (0101)^c 0001 F> 0000 R` → `L 0101 (0001)^c 0 0 F> 0001 0 1 R` (12c + 42 steps) turns the c trailing ones into zeros and the zero above them into a one; and a settle step `L 0001 (0101)^c 0 0 F> 0001 y z R` → `L 0101 (0001)^c 0001 F> 0 0 y z R` (12c + 32 steps, for y z = 01 and 00) counts once more. A1 is not used, so the theorems hold for both twins. (`middle_reset`, `middle_carry`, `middle_settle_01`, `middle_settle_00`, `lean/Middle.lean` (generated by `holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/py/gen_middle.py`))

**Proved in Lean with `native_decide`:**

- **No halt in the first 10^7 steps.** The same run, evaluated by compiled code. (`blank_runs_native`, `lean/Blank.lean`)

**Trusted computation (C/Python, not Lean):**

- **No halt in the first 10^9 steps.** The C simulator `tools/c/triage.c` runs 10^9 steps without a halt; at the end 150 cells have been visited and 52 of them hold a 1. (`holdouts/triage.json`)
- **No halt in the first 2·10^10 steps.** Direct simulation with `tools/c/tmrun.c`. (`tmrun 1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC--- 20000000000`)
- **No halt in the first 5·10^11 steps.** Direct simulation with `tools/c/tmrun.c` (single-step, no acceleration). (`tmrun 1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC--- 500000000000`)
- **Where the twins differ.** In the first 10^9 steps A reads a 1 only 17 times, always with 0s on both sides; F reads only 0s, followed by a 0 except 16 times. (`holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/c/ctx.c`)
- **A binary counter at the left end.** Whenever the head is at least 8 cells right of the counter, the tape from the left end reads `10`, then 4-cell digits `1010` (one) and `1000` (zero), then `11`. Read as a binary number (least significant digit on the right) this counter goes up at almost every change. From step 1.5·10^7 to 10^9 the decoded value changes 149,850 times; 149,848 are increases and 2 are changes of width (19 → 24 → 26 digits as the script reads them; the counter has 26 digits at the end, with value 19,634,864, about 29% of the way to overflow). (`c/leftsnap.c`, `py/cntchk.py` in holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---)
- **Three counters, one inside the next.** Between two increments of the left counter the head runs the middle counter from its reset up to its overflow; each count ends with F at the right end of the middle counter, where the next cells of tape (the *tail*) are read and rewritten (the carry and settle rules above move a `0 1` into and out of the tail). The overflow of the middle counter is swept back to `(1010)^n` and passed left as one increment of the left counter. For 2b the number of steps per left increment changes between long stretches in the same way (6,673 steps per increment in the first 10^9 steps, 3,599 in the next 10^9). (`holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/c/lcnt.c`)
- **A reads a 1 only at overflows.** A reads a 1 only when the left counter overflows: after step 2·10^4, at steps 2.0·10^6, 5.5·10^6, 1.5·10^7, 3.6·10^7, 4.8·10^8, 2.26·10^9 and three times at 1.33·10^10. At the read at 2.26·10^9 the fixed prefix of the counter changed from `10` to `1010101101`, the shape 2a has had since step 10^6, so the left counter of 2b is no longer read by the decoder after that (its digits are still there, shifted by the new prefix). (`holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/c/a1.c`, `holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/c/lcnt.c`)
- **Not decided by n-gram CPS up to width 14.** The n-gram Closed Position Set decider (`tools/c/ngramcps.c`) with equal widths 4, 6, 8, 10, 12 and 14, plain and with the fixed-length (1) and LRU history augmentations, either reaches a halting local configuration (UNKNOWN) or stops at 3·10^7 local configurations: it does not prove non-halting at these settings. (`ngramcps MACHINE N [-H 1 | -U] -m 30000000`)

**Heuristic:**

- **Growth shape: exp/fixed.** Left of the start, the visited part of the tape stopped growing in the second half of the run (bounded so far, or growing so slowly that no record fell in the last half). Right of the start it grows like the logarithm of the step count: each new cell costs a roughly constant factor more time, the signature of a *counter* or of a Collatz-like map whose values are written on the tape (fitted exponent 0.046). (`tools/py/bbtools/triage.py`)
- **Tape structure.** Late in the run the tape is made of long stretches of `(0 1)^n`, `(0^3 1)^n` and `(1^2 0)^n`; both ends grow, the right one by single cells at irregular times (e.g. 2a: cell 175 at step 4.7·10^8). The stretches `(0 1)^n` and `(0^3 1)^n` are the digits 1010 and 1000 of the left binary counter read with another phase (see below).
- **The (110)^n block at the right end.** At the right end a block `(110)^n` grows by one word at some of the right records (for 2a, n = 12, 13, 14 at the right records at 4.7·10^8, 5.8·10^8 and 9.6·10^8 steps). It is the far end of the tail (see above). (`tools/c/tmrun.c` snapshots)
- **The tail is an irregular list of gaps.** Right of the middle counter the tape is a list of gaps between single 1s. Read at the start of each cycle (2a, near step 3·10^8), its first few gaps run through three phases, one per cycle, and the rest of the list changes once every three cycles, in a way that looks like a rewriting system on gap lengths (for example `14` → `0 1 0 1 8` → `0 1 2 8` → `2 3 1 5` → `0 4 0 1 5` → `3 4 5` → `8 5` → ...). The configuration of tail and middle counter at an increment of the left counter never repeated (in the run of 2a) in the first 3·10^9 steps (996,093 increments, compared by hash; `holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/c/zper.c`). The right end of the tape grows a few cells (3 to 8) at a time, at irregular steps. No rule for the tail has been found. (`tools/c/tmrun.c` snapshots)

**Open:**

- **Does it halt from blank tape?.** Not known. The machine halts only when F reads a 1. The left counter and the middle counter are understood and their moves are proved; what is missing is a rule for the tail, which the middle counter reads at every count and which decides when the right end grows. A halt would have to come from the tail.

## For later

The tail: log the gap list at each increment of the left counter and look for the rule that maps it to the next one
(it looks like a rewriting system on gap lengths with a three-cycle phase). Then prove the whole cycle (reset, all counts,
overflow) with the tail as a parameter; with a closed rule for the tail that would decide the machine.

```sh

holdouts/1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/lean/check.sh
python3 holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/py/gen_rules.py 1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC--- H27281 | diff - holdouts/1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/lean/Rules.lean
gcc -O2 -o tmrun tools/c/tmrun.c && ./tmrun 1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC--- 20000000000
gcc -O2 -o leftsnap holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/c/leftsnap.c && ./leftsnap 1RB1RF_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC--- 1000000000 110 > ls.txt && python3 holdouts/1RB1RD_1LC0RD_1RE0LD_0RE0LF_0LB0RA_0LC---/py/cntchk.py ls.txt 2b
```
