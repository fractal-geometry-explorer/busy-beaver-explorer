# 1RB0RE_1LC0RD_1LD0LD_1RA0LC_1RA1RF_1RA---

bbchallenge id 131775, one of the six-state holdouts (group G06: one side of the tape stops growing, the other grows
like a square root). Whether it halts from blank tape is open. Its tape is a list of blocks of `10`s with short separators; each sweep the first block grows by one and single units move between neighbouring blocks, a carry-like pattern that has not been reduced to a rule yet.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RE |
| B | 1LC | 0RD |
| C | 1LD | 0LD |
| D | 1RA | 0LC |
| E | 1RA | 1RF |
| F | 1RA | --- |

## What it does

The tape grows to the left; the right end stopped growing. Three million steps in it reads, from the left,

```
D> 0 (10)^129 0 (10)^191 1 (10)^255 0 0 0 (10)^158 1 (10)^159 0 0 0 (10)^429 1 (10)^94 0 0 0 (10)^86 1 ... 1 1 0 0 (10)^28 1 1
```

a list of blocks `(10)^x` separated by `0`, `0 0 0` or `1`. The head crosses the whole tape every sweep (states A and
E run right across the blocks, shifting them by one cell, C and D run back; `a_right`, `e_right`, `c_left`,
`d_left`). Over consecutive sweeps the first block grows by one, the separators `0` and `0 0 0` swap, and single
units pass between the two blocks on either side of a separator: (10)^191 1 (10)^255 becomes (10)^192 1 (10)^254,
then (10)^193 1 (10)^253 a few sweeps later. Every so often the first block is cut off and the list shifts (a new
block appears at the left end).

**The tick is a binary increment** (exact rule, checked sweep for sweep). At each left turn the tape is

```
0^inf D> 0 (10)^a  s1 (10)^b1 1 (10)^c1  s2 (10)^b2 1 (10)^c2  ...  tail
```

Each pair `(10)^b 1 (10)^c` is a digit, and its separator says its value: `0` is a 1 and `0 0 0` is a 0. One sweep
adds one, starting from the left:

- every leading digit 1 becomes 0 (its separator becomes `0 0 0`, and c loses one `10`);
- the first digit 0 becomes 1 (its separator becomes `0`, and b gains one `10`);
- a gains one.

The sweep takes exactly `6 + 4a + 8(b1 + ... + bn) + 4(c1 + ... + cn) + 8n` steps, where n is the number of digits
passed. The head turns back at the digit that becomes 1, so a sweep only goes as far as the carry.

`py/ticks.py` checks this on the output of `c/blocks.c`. Of the 25,117 sweeps in the first 3·10^8 steps, 24,787
follow the rule with exactly this step count. The other 330 are events:

- **Merge** (25 sweeps): the carry passes a digit whose c is 1. When the next digit is a 0, the two digits merge:
  `(10)^b 1 (10)^1` followed by `0 0 0 (10)^b' 1 (10)^c'` becomes one digit 0, `(10)^(b+b'+2) 1 (10)^c'`. This
  holds in 22 of the 25 cases.
- **End** (145 sweeps): the carry passes every digit. The first block a is then cut off and becomes a new digit,
  and the roles of the separators shift.
- **Irregular** (160 sweeps): the tape is not of the form above. These are mostly the few sweeps right after an
  end event, with separators `0 0` or `0 1` in the tail.

So the machine is a binary counter whose digits carry two block lengths. b counts how often a digit went 0 to 1, and
c runs down each time it went 1 to 0. The events (merge and end) are rare and are what keep the list changing.

## Status

**Open.** What the blocks do over many sweeps (where the units go, when the first block is cut off, and what happens when a block empties) has not been reduced to a rule. The machine can halt only in F reading 1 (`step_none_iff`); no configuration of the block list is known that leads there.

## Proved in Lean

- `lean/Rules.lean` (generated by `lean/rules.py`), shift rules for the pieces of a sweep:
- `a_right`: A runs right across `(10)^n` (between zeros), shifting it by one cell.
- `a_right1`: the same between ones.
- `d_left`: D runs left across `(10)^n` unchanged.
- `c_left`: C runs left across `(01)^n` unchanged.
- `e_right`: E runs right across `(01)^n`, shifting it back.
- `tick_stop`: the whole tick when the first digit is 0. `0^inf D> 0 (10)^(a+1) 0 0 0 (10)^b 1 R` becomes
  `0^inf D> 0 (10)^(a+2) 0 (10)^(b+1) 1 R` in 4a + 10 steps, for every a, b and R.
- `tick_pass1`: the whole tick with a carry over one digit, in 4a + 8b + 4c + 34 steps, for every a, b, c, d and R.
  `0^inf D> 0 (10)^(a+1) 0 (10)^(b+1) 1 (10)^(c+2) 0 0 0 (10)^d 1 R` becomes
  `0^inf D> 0 (10)^(a+2) 0 0 0 (10)^(b+1) 1 (10)^(c+1) 0 (10)^(d+1) 1 R`.
- `lean/Blank.lean` (generated): the halting configurations (`step_none_iff`) and no halt in the first 10^7 steps.

## For later

- Prove the tick for any number of passed digits (induction over the digits). It needs a forward rule per digit,
  `A> 0 (10)^b 1 (10)^(c+1)` to `(10)^(b+1) 1 (10)^c 1 A>`, which holds in simulation, and the zigzag of the way
  back.
- Pin down the end event and the irregular tail, then run the counter on the digit list (an accelerated simulator).
- Find which block configurations lead to F reading 1.
