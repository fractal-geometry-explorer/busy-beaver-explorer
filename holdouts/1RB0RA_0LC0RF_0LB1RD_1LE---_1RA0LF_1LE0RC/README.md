# 1RB0RA_0LC0RF_0LB1RD_1LE---_1RA0LF_1LE0RC

bbchallenge id 114265, a six-state holdout of group G05 (growth class fixed/sqrt: the tape grows to the right like
the square root of the step count; the left end stops at 204 cells left of the start after 4.4·10^6 steps).
**Open.** The machine is a counter that sits still while a long block of `11010`s grows beside it, one word per
visit. The two long passes over that block are proved in Lean for all lengths. The counter's own rule is not
found yet. The run is followed to 10^11 steps without a halt; the tape is then 202,789 cells wide.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RA |
| B | 0LC | 0RF |
| C | 0LB | 1RD |
| D | 1LE | --- |
| E | 1RA | 0LF |
| F | 1LE | 0RC |

## What it does

**The tape.** Write `P = 11000110`, `q = 11010`, `x = 1100`, `y = 1110`. After about 3·10^7 steps the tape at the start of
every excursion is

    1 0 P^31  [counter, about 1,550 cells of x, y, q, P, 0]  P 0 0 P 1 0  q^k  B> 0^∞

For example, at step 29,968,458 the right part is
`… q x y x y x q y^2 x^4 0 y x y x^2 P 0 y x^3 q x^3 y x q x^2 P 0^2 P 1 0 q^962 B>0`. The first 1,260 cells of the tape
(`1 0 P^31 q x y q P 0^2 x^3 …`, up to cell 1,057 right of the start) are the same at step 3·10^7 and at step 10^9.

**One excursion** (about 44k + 4,000 steps):

1. `pass_left` (17k + 20 steps for `k = n + 2`): from the blank cell at the right end in state B, the head runs left across the
   whole `q` block, 17 steps per word, and reaches the counter in state C.
2. The head bounces inside the low part of the counter for a few thousand steps. This rewrites the counter, mostly in its last
   100 to 300 cells.
3. `pass_right` (27n + 44 steps): from `A> 1 1 1 0 (11010)^(n+1)` the head runs right across the block, 27 steps per word,
   and reaches a new cell at the right end.

Each excursion makes the `q` block one word longer: `q^961` at step 29,920,431, `q^962` at step 29,968,458, `q^6,038`
at step 10^9. So excursion number k costs about 44k steps, and the tape grows like the square root of the time.

**The counter.** How deep the head goes into the counter on each excursion follows a ruler-like pattern. The
turning points come in classes 25 cells apart, and each class is about 2.6 times rarer than the one before it.
Here are the leftmost positions (relative to the start cell) of the 5,645 runs from the counter back to the right end
between steps 3·10^7 and 10^9 (in the same time the `q` block grew by 5,075 words):

| leftmost cell | 1299 | 1274–1282 | 1249–1257 | 1224–1232 | 1199–1207 | 1174–1182 | 1149–1157 | 1124–1132 | ≤ 1107 |
|---|---|---|---|---|---|---|---|---|---|
| returns | 352 | 2,680 | 1,568 | 648 | 249 | 91 | 35 | 13 | 9 |

This is the signature of a counter whose digits are blocks of about 25 cells, with a carry into digit j about
every 2.6^j excursions. The digits can be read off. Cut the last 500 cells left of
the marker `P 0 0 P 1 0` into 25-cell blocks, at each of the 1,200 times the head is in state B at the right
end during the last 3,000 records of the first 3·10^7 steps. Every block then has the form

    11a0 11b0 1100 110c 0 11d0 11e0          (a, b, c, d, e in {0, 1})

so each digit holds five bits. 28 of the 32 patterns occur; the commonest, `a b c d e = 0 1 1 1 0`, is 47% of the
24,000 blocks. The turning points 4 cells apart inside one class are probably at these bits. What one visit does
to the bits (the carry rule) is not found yet, and neither is the exact growth factor. It may be a mixed radix, or
a Collatz-like rule. Deep carries are rare, which is why the left part of the
tape looks frozen: between steps 3·10^7 and 10^9 the head never went further left than cell 1,057.

**Where it could halt.** The only halting transition is D reading 1. D is entered only from C reading 1 (`1RD`),
so the machine halts exactly when C reads a 1 whose right neighbour is a 1 (`C> 1 1`). The two passes never do
this (they are proved for all `k`). In 10^9 steps the counter work in step 2 never did either, but whether it
can is the open question.

## Status and evidence

**Lean, kernel** (`lean/Rules.lean`, generated by `py/gen_rules.py` with `bbtools.symtm`):

- `pass_left`: `steps (17n + 54)` from `L 1 1 0 0 0 1 1 0 1 0 (11010)^(n+2) B> 0^∞` to
  `L 1 1 C> 0 0 0 0 0 1 0 1 0 1 1 0 (10110)^(n+1) 1 0 1 0^∞`.
- `pass_right`: `steps (27n + 44)` from `L A> 1 1 1 0 (11010)^(n+1) 0^∞` to `L 0 (10110)^(n+1) 1 0 1 1 0 1 B> 0^∞`.

Both hold for every `n` and every tape `L` to the left. Also the generated `step_none_iff` and `blank_runs_kernel`
(10,000 steps) in `lean/Blank.lean`.

**Lean, `native_decide`**: `blank_runs_native`, no halt in 10^7 steps (`lean/Blank.lean`).

**Computed (trusted)**: a direct C simulation runs 10^11 steps without a halt; the tape is then 202,789 cells wide. In 10^9 steps every return to the right end after
step 3·10^7 starts from inside the counter, between cells 1,057 and 1,299. The `q` block is uniform apart from the
cells the head is working on.

**Heuristic**: the excursion structure (one `q` word per excursion), the frozen left part, and the geometric
depth distribution, all from the simulation.

**Open**: the counter's digits and its carry rule. With those, an excursion would be one closed rule, and a
halts-iff statement on the counter orbit would follow.

## For later

The next step is to decode the counter. The plan:

- Record the last 300 cells left of `P 0 0 P 1 0` at the start of each excursion.
- Find the 25-cell digit words and the rule for one excursion, with the shallowest turn (cell 1,299) as the first case.
- Prove that rule with `bbtools.symtm` (the contexts `L` and the `q` block are already handled by `pass_left` and
  `pass_right`).
- Then write a counter-level simulator. One counter step costs about 44k machine steps, so this would reach far
  past 10^11.
