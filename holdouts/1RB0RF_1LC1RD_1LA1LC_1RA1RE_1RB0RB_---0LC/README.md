# 1RB0RF_1LC1RD_1LA1LC_1RA1RE_1RB0RB_---0LC

A zigzag rewriter: the head rewrites the tape between two encodings in many short back-and-forth moves, so it rarely reaches the ends; the left end grows in bursts whose sizes, from the second on, are multiples of 1,065 cells. Halting is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RF |
| B | 1LC | 1RD |
| C | 1LA | 1LC |
| D | 1RA | 1RE |
| E | 1RB | 0RB |
| F | --- | 0LC |

## What it does

**The two encodings.** At a left turn: blocks of ones and blocks of zeros, `0 1^13 0^5 1^4 0^5 1^4 0^5 1^4 0^2 1^12 0^4
1^16 0^2 …`. At a right turn: blocks of ones of length mostly 3k+2 separated by single 0s, `1^9 0 1^2 0 1^8 0 1^2 0
1^2 0 1^5 0 1^5 0 1^11 …`. Turns are rare: the head zigzags (the trajectory has many local extrema in the middle of
the tape), so in the first 3·10^6 steps there are only 9 left turns. The repeated crossings it makes are the shift
rules of `lean/Rules.lean`:

| rule | from | to | what it does |
|---|---|---|---|
| `c_ones` | `L (1)^n C> 1 R` | `L C> 1 (1)^n R` | Leftward: C runs over ones. |
| `b_111` | `L B> (111)^n R` | `L (110)^n B> R` | Rightward: B turns each 111 into 110. |
| `b_word` | `L B> (111100)^n R` | `L (110111)^n B> R` | Rightward: B turns each 111100 into 110111. |

**Bursts (observed).** The left end grows in bursts (`c/bursts.c`: `bursts M 1000000000 L`): by 3,410
cells at 1.3·10^6 steps, then by 1,065 (5.5·10^6), 1,065 (1.5·10^7), 1,065 (3.0·10^7), 5,325 (4.5·10^7), 5,325
(2.3·10^8), 8,520 (3.5·10^8), 2,130 (5.9·10^8): from the second on, multiples of 1,065 = 3·5·71. The tape at the left
turn after a burst begins with the same 699 cells (later 1,613) as before it, though the left end moved by thousands of
cells: a burst rebuilds the leftmost structure at the new end. Its twin in the group, 1RB0RC_1LC0RB_1LD0LD_1RA1LE_---0LF_1LB1LF,
uses the same kind of tape (blocks of ones in two encodings) but sweeps cleanly; the two are not the same machine up to
renaming.

**Halting.** The only halting transition F0 is reached from `A>1 0`. In 10^9 steps A reads a 1 138,854,484 times,
always with a 1 on its right (`c/prehalt.c`).

## For later

Find the recursion behind the bursts (sizes 1,065·k) and the rule that maps the tape before a burst to the tape after
it; that would turn the run into a sequence of bursts with an explicit map.

## Deciders tried (F11, 13 November 2026)

None closes. Each reaches a halting configuration in its abstraction, which says nothing about halting.

- n-gram CPS (`tools/c/ngramcps.c`), equal widths on both sides: a halting local configuration is reached with plain up to width 20, history 1 up to width 20, history 2 up to width 13, history 3 up to width 12, LRU history up to width 3 (larger widths ran out of the 150 s or 60 million configuration budget).
- n-gram CPS with every cell tagged by its position mod p: fails for p = 2 up to width 20, p = 3 up to width 20, p = 4 up to width 20, p = 6 up to width 16.
- n-gram CPS where each side also carries the state of a small automaton that has read that side from the far end (every automaton with up to 3 states on both sides, or 4 states on one side), with position mod 1..4 and widths 4, 6, 8: no closed set without a halt in all 120 parameter sets.
- Run-length windows (the K nearest runs of equal macro cells on each side, run lengths kept exactly below T and mod M above): fails for all 72 parameter sets (cells of 1 to 4 bits, K = 2, 4, 6, T = 2, 4, M = 1, 2, 4).
- Two-automaton closed tape language by SAT (a deterministic automaton reading each side inward, n states each, CaDiCaL): no solution for n = 2..9; n = 10 not finished in 150 s.

## Where a halt can come from

`lean/Route.lean` (kernel, written by `py/route.py`): `halt_route`, two steps before any halt the machine is in one
of: D with 0 under the head, 1 right, 0 two right.
