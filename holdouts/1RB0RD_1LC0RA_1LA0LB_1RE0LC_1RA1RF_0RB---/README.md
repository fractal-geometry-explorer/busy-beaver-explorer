# 1RB0RD_1LC0RA_1LA0LB_1RE0LC_1RA1RF_0RB---

bbchallenge id 93459. Halting from blank tape is open. Active phases drain a right-end block into a left counter, one unit per bounce; rebuild phases make a new block.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RD |
| B | 1LC | 0RA |
| C | 1LA | 0LB |
| D | 1RE | 0LC |
| E | 1RA | 1RF |
| F | 0RB | --- |

## What it does

With `w = 1010110` and `a = 10`, at left extensions in an active phase the tape is `0 0 w^n <middle> 1 a^k w`.
Each bounce adds one `w` at the left and removes one `a` from the right block:

    step 302,136,397     n = 648     k = 10159
    step 1,001,302,397   n = 5848    k = 4959
    step 2,126,686,397   n = 10648   k = 159

When the block is used up, the head stops reaching the left end (steps 2.17·10^9 to 3.85·10^9) and builds a new
right block from the middle of the tape, which is hierarchical: `(a^2 w a^10 w)^m`, `(a^8 w a^40 w)^m`, and a few large
blocks (21, 333, 922, 530, 2289, ...). Active phases started at steps 24.4·10^6 (block 569), 295.8·10^6 (10236) and
3.85·10^9 (6363).

## What is proved

- Lean, kernel (`lean/Rules.lean`, from `py/rules.py`): the sweep rules

    L A> (01)^n R -> L (10)^n A> R
    L (01)^n B> 0 R -> L B> 0 (01)^n R
    L B> (10)^n R -> L (01)^n B> R
    L (10)^n C> 1 R -> L C> 1 (10)^n R
    L A> (1010101)^n R -> L (0110010)^n A> R
    L A> (10101)^n R -> L (01100)^n A> R
    L A> (0110101)^n R -> L (1001100)^n A> R
    L B> (1101010)^n R -> L (0011001)^n B> R

- Lean (`lean/Blank.lean`, generated): the halting configurations, no halt in 10^4 / 10^7 steps.
- Lean, kernel (`lean/Rules.lean`, `sweep0` .. `sweep3`): the outer round trip of the trio, which never reads E0, holds
  here too. With c = 1101010 and a = 10: `11010 w (10)^(k+2) 1 -> 11010 c w (10)^(k+1) 1` for every w over c and a with
  up to four blocks of c's, all exponents symbolic. (In the tokens above, the left counter `w^n` is this growing front
  block of c's.) The first outer phase, at step 19,276, has five blocks, `c^2 a^3 c a^40 c a^8 c a^5 c` with k = 46;
  the five-block rule is generated by the same code but its kernel check did not finish in 50 minutes, so it is left
  out.

Everything under "What it does" is observation from simulation, not proof.

## Open

## Shared exact engine (24 November 2026)

The three machines `1RB0RD_1LC0RA_1LA0LB_1RE0LC_1LC1RF_0RB---`, `1RB0RD_1LC0RA_1LA0LB_1RE0LC_1LD1RF_0RB---` and
`1RB0RD_1LC0RA_1LA0LB_1RE0LC_1RA1RF_0RB---` differ only in E0, which their outer round trip never reads; one engine,
[`trio.py`](../1RB0RD_1LC0RA_1LA0LB_1RE0LC_1LC1RF_0RB---/py/trio.py), runs all three. It is exact: it never
extrapolates.

- *Sweeps.* A run of n copies of a word is crossed at once when one copy, run on its own with up to three cells of
  context, gives back the same state and context (induction on n).
- *Bounce jumps.* From a turn of the head, every run it touches gets a variable for its count; counts and the step
  counter are carried along as affine forms and every decision that depended on a count is recorded as a guard. If a
  later turn has the same state, head cells and (after a string-preserving canonical form: each run turned to the least
  rotation of its word, absorbing the whole copies next to it) the same tape with every count shifted by a constant,
  that stretch of run is a proof, for all counts that meet the guards, of a rule `X(x) -> X(x + d)`. The jump applies
  it as many times as the guards allow, with the exact step sum.
- *Groups.* Repeated sequences of runs become one run of a longer word, up to 4096 cells.

So a jump here is a theorem about the machine checked by running it symbolically, not an observation; what is not
proved is the Python code itself. [`trio_check.py`](../1RB0RD_1LC0RA_1LA0LB_1RE0LC_1LC1RF_0RB---/py/trio_check.py)
compares tape, state and head with the plain C simulator.

**Result.** From blank tape the engine ran 2.18·10^16 steps of this machine in 2 hours on one core without reaching a halting transition. Its tape, state and head were equal to the C simulator's at 6 step counts, the last at 10,018,574,273 (`data/trio_check.json`). Unlike the older `rsim.py` run above, the steps after the last check rest on exact rules, with no extrapolation; they are still a computation, not a Lean proof.

**Nested blocks (observed).** The inner phases build blocks inside blocks. The groups the engine forms are runs of
words of 38, 110, 326, 974, 2918, 8750, 26246, 78734 and 236198 cells: 2 + 4·3^(j+2) cells at level j, each level 3
times the last minus 4. Each such word is two c's in a sea of a's, `c a^x c a^y`, with x + y = 6·3^(j+1) − 6 (12, 48,
156, 480, ...); level 0 is the `c a^2 c a^10` of the first inner phase. The same sizes appear in all three machines
(the largest ones only in runs that allowed longer groups than the 4096 cells of the final runs).
