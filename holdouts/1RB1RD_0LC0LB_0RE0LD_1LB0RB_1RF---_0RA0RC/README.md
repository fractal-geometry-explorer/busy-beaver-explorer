# 1RB1RD_0LC0LB_0RE0LD_1LB0RB_1RF---_0RA0RC

bbchallenge id 63822. One of the six-state holdouts whose halting from blank tape is open. **It runs a base-7 odometer: blocks of the word `010` separated by markers, each marker a digit that cycles through
seven shapes, every change of shape paid for by the block after it.** The odometer step and its carry are proved in
Lean for all block lengths; what happens when a block runs out is described from simulation, not yet as a rule.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RD |
| B | 0LC | 0LB |
| C | 0RE | 0LD |
| D | 1LB | 0RB |
| E | 1RF | --- |
| F | 0RA | 0RC |

## What it does

Write `[k]` for `(010)^k`.  Each time the head reaches a new cell at the left end (state B, blank on its left) the
tape reads

    B> [x] M_d1 [y1] M_d2 [y2] ... M_dk [yk]

where each marker is one of seven words, a digit `d` of an odometer:

| d | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| marker M_d | `0` | `001` | `00110` | `0010001` | `0 [2] 10` | `00101` | `0011` |
| change of the block after it, d -> d+1 | -1 | -1 | -1 | -1 | +1 | 0 | +1 (and carry) |

**One visit of the left end adds one to the odometer** (lowest digit first): the first block gains a copy, the first
marker moves to its next shape and the block after it changes as in the table.  From `M6` the marker goes back to `M0`,
its block gains one, and the next marker moves on: a carry.  Proved in Lean for every `x, y, z` and any tape further
right (`digit_0` .. `digit_5`, `carry_0` .. `carry_5` in `lean/Rules.lean`, generated by `py/rules.py`); a carry
through several 6s is the same sweep repeated (checked symbolically, not yet in Lean as an induction).  Over a full
turn of a digit its block loses 2, so the block after digit j loses 2 per 7^j visits.

Example (steps 1,700,763 to 1,847,181, all checked against the simulation): `B> [272] 00101 [189] 0010001 [651] 00101 [437]`
counts up through `B> [343] 0011 [169] 0011 [649] 0011 [437]`.

**Overflow.** When every digit is 6 the carry runs to the right end (the rare events at the slow end of the tape):
all markers become `1`, the head returns, all markers become `0` and a new lowest digit is put in front, the old first
block becoming the block after it:

    1,847,181   B> [343] 0011 [169] 0011 [649] 0011 [437]
    1,851,995   [344] 1 [170] 1 [650] 1 [437] 0 E> 0          (right end)
    1,869,618   B> [2] 001 [344] 0 [170] 0 [650] 0 [437]

**A block runs out.** When the block after a marker gets below about 4, the marker and the block merge into longer
words (`001100100010001`, `00110010001`, `001110`, `0000`, ...), and a partial reset (`C> 000100 ...` at the left end)
puts a new digit in front and merges blocks, e.g.

    128,522   B> [183] 001110 [27] 0010001 [3]
    131,096   C> 000100 [183] 00 [27] 0010001 [3]
    132,897   B> [14] 0011 [179] 0000 [26] 0010001 [3]
    135,619   C> 000100 [15] 0 [205] 0010001 [3]

These events are listed in full by `c/events.c MACHINE N 010 1 1`.  They are the part not yet written as a rule.

## How it could halt

The machine stops only on E reading 1.  E is entered only from C on a 0 (moving right), C from B on a 0 (moving left,
and B has just written a 0 where E will look) or from F on a 1 (moving right), F only from E on a 0.  So
(`halt_needs`, `lean/Halting.lean`) two steps before a halt the head is in F on `1 0 1`, three steps before in E on
`0 1 0 1`.  The chain C0 E0 F1 C0 E0 F1 ... is the sweep that carries the odometer to the right over `001 001 ...`; a
halt is that sweep meeting `0 1` where every well-formed marker gives `0 0`.

**Perturbation test** (`c/pert.c`, computed).  Take the real configuration at the left-end visit of step 299,991,864,
`B> [2252] 0 [2] 10 [1757] 0011 [203] 0010001 [9176] 0011 [563] 0 [419]`, and replace every block of length at least
5 by a random length in [5, 300]: 19 of 100 trials halt within 2·10^7 steps; keeping each length's residue mod 7
still 6 of 300 halt.  In one halting run followed in detail a block runs out while the next marker is `0011`
(digit 6), the merged shape decays to a malformed marker `11` (never seen in 3·10^8 steps of the real run), and a
later sweep halts; others halt near the right end after a block there runs out.  So the run avoids
the halt because of the actual block lengths (which digit is where when a block runs out), not because of the shape of
the tape or residues: no closed tape language that forgets the lengths (the window CTL, or a CTL with mod-7 run
tokens, which was tried) can prove it.

## Does it halt?

Open.  Proved (Lean, kernel): the halting configurations and 10^7 steps without a halt (`lean/Blank.lean`), the
odometer step and carry for all lengths (`lean/Rules.lean`), and that a halt needs F on `1 0 1` (`lean/Halting.lean`).
Computed: no halt in 2·10^10 steps (`c/sim.c`), the overflow and run-out events above, the perturbation test.

## For later

More than a day of work remains.

1. Carry chains as an induction in Lean: the outbound sweep crosses `0011 [y+4]` as `E> 0011 [y+4] -> 1010100 (100)^(y+3) E>`
   and the return converts each unit to `0 [y+5]`; a tape function over a list of units makes the induction.
2. Decode the run-out events (the merged shapes listed by `c/events.c`) as a rule on (marker, block) pairs, and the
   partial reset that follows; then the whole run is a map on lists of (digit, block length).
3. With the map, the halting question becomes: does a block ever run out while the next digit is 6 (or one of the
   other malformed cases found by `c/pert.c`)?  Iterate the map far beyond the machine.  The first block reaches
   `7^4 + 2` and `7^5 + 2` at resets, a hint that the lengths are tied to powers of 7.

## Files

- `py/rules.py`: generates `lean/Rules.lean` (the odometer).
- `c/sim.c`: plain simulation from blank tape with the `[k]` compression, printing the edge events.
- `c/events.c`: the tape at each new cell at either end, any word compressed.
- `c/pert.c`: the perturbation test.

## Deep exact run

No halt in the first 1.24x10^19 steps: the macro simulator `holdouts/1RB0LB_1RC0LA_1LB0RD_1RE1RD_1RB1RF_1LA---/c/msim.c` with blocks of 6 cells ran
from blank tape to step 12,428,929,969,419,733,536. It is exact, and at this block size it agrees with the
direct simulator after 2,000,010,402 steps (`python3 holdouts/1RB0LB_1RC0LA_1LB0RD_1RE1RD_1RB1RF_1LA---/py/deep.py run 240`, then `verify`).
