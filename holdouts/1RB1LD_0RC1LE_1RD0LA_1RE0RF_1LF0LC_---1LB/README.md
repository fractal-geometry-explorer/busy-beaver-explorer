# 1RB1LD_0RC1LE_1RD0LA_1RE0RF_1LF0LC_---1LB

bbchallenge id 180047. One of the six-state holdouts whose halting from blank tape is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LD |
| B | 0RC | 1LE |
| C | 1RD | 0LA |
| D | 1RE | 0RF |
| E | 1LF | 0LC |
| F | --- | 1LB |

A nested counter on the words b = `1^6 0` and c = `1^5 0`. One round of a phase is proved in Lean for all sizes. The
conversions between phases are described from simulation.

## What it does

- **Round** (`round`, Lean). From state A at the left end of `1 0 0 b c b^(k+2) 0 0 1^m`, the machine reaches state A
  at the left end of `1 0 0 b c b^(k+1) 0 0 1^(m+10)` in 80k + 307 steps, for every k, m and any tape to the right.
  In between it zigzags twice across the run of b's, re-encoding it in other 7-cell words. `zig` is half a round
  for any left part, and `cR1`, `cR2` and `dL` are the crossings.
- **Phase.** A run b^k next to 1^m is used up in k rounds and leaves 1^(m+10k). The block is then cut into copies of
  c, and the c's into a new run of b's and a new block. For example, around step 1.05·10^9, `1^40215` became
  `c^6703` and then `b^3351 0 0 1^16752`. Deeper in the tape there are more runs and blocks (e.g.
  `b^1788 0 0 1^8934` at step 6.6·10^8), so the counter is nested.
- **Gadgets.** The left end runs through several gadgets (`1 0 0 b c`, `1 0^6 c 0 0 c`, `1 0^4 b 1^3 b c`, …). They
  decide which conversion follows. Large conversions seen: c^94, c^151, c^343, c^638, c^1064, c^2338, c^6703,
  c^9773 (step 1,834,926,828).

## Does it halt?

The halting transition is F0. F is entered only from E0 (`1LF`), so a halt needs E to read a 0 with a 0 to its left.
A round never does that, so a halt could only come during a conversion. Open.

## For later

- List the gadgets at the left end and prove each conversion (1^M into c's, c's into b's and 1s) with symtm, for all
  sizes. This gives a map on the counts and the gadget, which can then be iterated with exact integers to look for
  the E0-then-F0 pattern.
- Use `bbtools.cycles` with block size 7 to accelerate the runs past 10^10 steps.
- Tried on 12 November 2026: the generic accelerator `holdouts/1RB1LF_1LC0RD_0LD0LC_1RE0LA_0RA0RC_0RE---/py/accel.py`
  with block size 7 gives no real speed-up here (3·10^8 steps in 30 s, with either bounce setting), because a phase
  is not a repeated bounce at one end. A dedicated run-length simulator is needed, in the style of
  `holdouts/1RB1LC_1LC0RD_0LE1LA_---1RA_1RF0LA_0RF0RB/py/accel.py`: cross a run of b's in one move with the proved
  `zig`/`cR1`/`cR2`/`dL` crossings, and jump over the k rounds of a phase. The halting pattern to watch for is
  E reading a 0 that has a 0 on its left (E0 -> 1LF, then F0).

## Files

- `lean/Rules.lean`: `round`, `zig`, `cR1`, `cR2`, `dL`, generated by `py/gen_rules.py` (`bbtools.symtm`).
- `c/tok.c`: prints the tape at events (here: state A at the left end), tokenized into the words b and c.

## Status

Open. Lean: `step_none_iff`, no halt in 10,000 steps by the kernel and in 10^7 by `native_decide` (`lean/Blank.lean`),
and the rules above (`lean/Rules.lean`, kernel). C (`tools/c/triage.c`): no halt in 10^9 steps.
