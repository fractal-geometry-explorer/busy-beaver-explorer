The question "does this machine halt, and when?" can be asked at four levels of description. Each level keeps less detail than the one above it and has a coarser unit of time, and each step down is a theorem saying that the lower level does exactly what the machine does. At the bottom, a function that keeps the ladder as numbers runs from the tape of visit 3,040 to the halting transition; that evaluation, with the theorems, is the proof (the bottom line).

Level 1The machine
A tape of cells and a head in one of six states. One unit of time is one step.
From blank tape to the halt: 1.27·10758 steps.
 Level 2Hits on a level
At every second visit the tape is a front, levels 4^n s and a tail. One unit is one hit (two visits); a level moves to the next of 16 positions, in 112n + c or 56n + c steps.
Kernel every hit, every n: hit0 … hit15 Level 3The ladder as an odometer
Each level is two numbers, position and block count. One unit is any number y of hits at once on the whole ladder.
Kernel levels are transparent: stack_run Level 4The accelerated run
The levels as numbers, only the front and the tail as cells. One unit is one hit on the tail: 3,539 of them from visit 3,040 to the halt.
Kernel the function is sound: loop_sound

The two evaluations at the bottom, the plain run of the first 27,172,911 steps (fsteps0) and the accelerated run (run0), are done by Lean's compiled code (native_decide); everything above them is checked by the kernel. A Coq proof makes the same argument with its run checked by its kernel.
