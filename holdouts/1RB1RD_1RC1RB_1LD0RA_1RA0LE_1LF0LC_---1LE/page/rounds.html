The first step down replaces the tape by a compressed tape: two stacks of items, one on each side of the head, where an item is a single cell or a word repeated n times, for any n. A round of the program (mstep in lean/Sim.lean) is one of four things:

  • a transition: the head reads the cell in front of it and the machine makes one step;
  • a run crossed: in front of the head lies a run of copies of a word, and one copy, entered in some state, is left on the far side in the same state. Then every copy is crossed in the same way, so the whole run is crossed at once and the steps are multiplied out;
  • two copies crossed: the same with two copies of the word taken together;
  • a copy unpacked: otherwise one copy is taken off the run and written out as cells.

Leftward moves are handled by mirroring the table, so one rule covers both directions (steps_mir). Kernel mstep_sound: every round leads from the configuration the stacks stand for to the next one by real steps of the machine, whatever is on the stacks. How the program folds cells into runs only affects its speed, never its correctness.

The stepper runs the program and the plain machine side by side. After every round the machine is moved on by the number of steps the round claims, and the two tapes are compared cell by cell.
