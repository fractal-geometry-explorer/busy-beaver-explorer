The question "does this machine halt, and when?" can be asked at four levels of description. Each level keeps less detail than the one above it and has a coarser unit of time, and each step down is a theorem saying that the lower level follows the machine exactly. At the bottom a program built from levels 2 to 4 runs from blank tape to the halting transition; that run is the proof (the bottom line).

Level 1The machine
A tape of cells and a head in one of six states. One unit of time is one step.
From blank tape to the halt: 8.53·10131 steps.
 Level 2The compressed tape
The tape as runs of a short word, a run of a million copies being one item. One unit is one round: a transition, a whole run crossed, or one copy unpacked.
Kernel each round follows the machine: mstep_sound Level 3Visits of a zone
The tape each time the head reaches new ground on the right, as counters of 011 with bits between them. One unit is one visit: 6(n0 + … + ni−1) + 4i + 11 steps.
Kernel a visit is a binary increment: visit Level 4The odometer of tanks
The same counters in the coordinates Nj, where they are fuel tanks. One unit is one jump of V visits at once, up to 2214 of them.
Kernel V visits in closed form: jump

The visits that are not of the regular form (a tank nearly empty, or the binary number overflowing) have no rule at level 3 or 4; the program runs them at level 2. Lean proves that whatever mixture of rounds and jumps the program makes is a run of the machine (run_sound, kernel), and evaluates the program from blank tape with compiled code (run_halts, native_decide). Coq does the same with the exact step count, checked by its kernel.
