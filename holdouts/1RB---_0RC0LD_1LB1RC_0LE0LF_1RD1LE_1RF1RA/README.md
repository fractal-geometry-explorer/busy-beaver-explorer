# 1RB---_0RC0LD_1LB1RC_0LE0LF_1RD1LE_1RF1RA

bbchallenge id 15414. One of the six-state holdouts whose halting from blank tape is open. Family: **two-thirds block splitter**.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | --- |
| B | 0RC | 0LD |
| C | 1LB | 1RC |
| D | 0LE | 0LF |
| E | 1RD | 1LE |
| F | 1RF | 1RA |

## Status

Open, reduced to an exact question. Lean (`lean/Blocks.lean`, kernel only): the machine is the **block map** below
(`next_sound`); it halts from blank tape iff the block map, from the frame `B [1] []`, reaches one of three critical
frames (`halts_iff_critical`). By `native_decide` none of the first 10^8 frames is critical (`no_halt_frames`;
300,362,311,724 machine steps by `py/blockmap.py run 100000000`). C: no halt in 10^9 steps. `lean/Series.lean`:
cutting a block of exactly 15 cells at the left end halts, of exactly 2 or 3 never halts; neither seen while the
tape grew to 5.3·10^10 ones (`c/series.c`, trusted).

**New (22 Nov 2026), kernel only.** `lean/Invariant.lean`: every frame after the first satisfies an invariant
(`inv_next`, `inv_orbit`): E frames are `E L (m :: 0 :: R')` with m ≥ 1 and no other empty block, C frames have a
non-empty second block on the left and an empty block on the right only first, B frames have at least 5 cells left
of the head and no empty block, and no F frame occurs. So two of the three critical frames are never reached and
**the machine halts iff the block map reaches `C (2 :: L) (r+1 :: R)`** (`halts_iff_C`), never straight from an E frame
(`critical_after_BC`). `lean/Sweep.lean`: that frame is only reached in a rightward sweep, and **the machine halts iff
some sweep start has a bad right list** (`halts_iff_sweep`, see "Sweeps" below). `lean/Cuts.lean` (`cut_even`): a
left-end descent that ends after an even cut hands its sweep a first block of 4u+1 cells, never 3.

## The block map (Lean)

`blk [a, b, c, ...]` is the tape `1^a 0 1^b 0 1^c 0 ...`, then blank, read away from the head (a block may be empty:
`0 0` is an empty block; the empty list is blank tape). A frame is a state and the block lists of both sides:

    E L R :  blk(L) E> 0 blk(R)        C L R :  blk(L) C> 0 blk(R)
    B L R :  blk(L) B> blk(R)          F L R :  blk(L) F> blk(R)

The map (`next` in `lean/Blocks.lean`, `nxt` in `py/blockmap.py`; a missing block counts as 0):

| frame | condition | next frame | steps |
|---|---|---|---|
| `E (i :: L) (m :: R)` | m = 0 | `E L (i+1 :: R)` | i+3 |
| `E (i :: L) (1 :: r :: R)` | | `C (r :: i+2 :: L) R` | r+5 |
| `E (i :: L) (m :: R)` | m ≥ 2 | `C (m−2 :: i+2 :: L) R` | m+7 |
| `C (0 :: L) (r :: R)` | | `C (r+1 :: L) R` | r+3 |
| `C (1 :: b :: L) (r :: R)` | | `E L (b :: 0 :: r+1 :: R)` | b+3 |
| `C (2 :: b :: L) (0 :: R)` | | `B (b+5 :: L) R` | 8 |
| `C (2 :: L) (r :: R)` | r ≥ 1 | **halts** (`0 1 1 C> 0 1`) | |
| `C (a :: L) (r :: R)` | a ≥ 3 | `C (r+1 :: a−1 :: L) R` | r+7 |
| `B (a :: L) (0 :: s :: R)` | | `C (s :: a :: L) R` | s+1 |
| `B (0 :: b :: L) (r :: R)` | r ≥ 1 | `E L (b :: 0 :: r−1 :: R)` | b+2 |
| `B (1 :: b :: L) (1 :: R)` | | `F (b+4 :: L) R` | 6 |
| `B (1 :: b :: L) (2 :: R)` | | `B (b+5 :: L) R` | 7 |
| `B (1 :: L) (r :: R)` | r ≥ 3 | **halts** (`0 1 B> 1 1 1`) | |
| `B (a :: L) (r :: R)` | a ≥ 2, r ≥ 1 | `C (r−1 :: a :: L) R` | r+4 |
| `F (a :: L) (0 :: R)` | | `F (a+1 :: L) R` | 1 |
| `F (a :: L) (1 :: R)` | | `B (a+2 :: L) R` | 2 |
| `F L (r :: R)` | r ≥ 2 | **halts** (`F> 1 1`) | |

Every row is a theorem for all block lists (one symbolic run each, `lean/BPieces.lean`, generated by `py/blocks.py`
with `bbtools.symtm`); the three halting rows are `none_halts`, and `next_none_iff` says they are the only frames
without a next frame. `py/blockmap.py check 3000000` follows the machine itself: 42,875 frames, each at exactly the
step the table gives.

The cut of the next section is rows 3, 8, 5 in a row: `E (i :: L) (m :: 0 :: j :: R)` → `C (m−2 :: i+2 :: L) (0 :: j :: R)`
→ `C (1 :: m−3 :: i+2 :: L) (j :: R)` → `E (i+2 :: L) (m−3 :: 0 :: j+1 :: R)` for m ≥ 5. A sweep to the right is row 8
repeated (each block hands one cell to the next); at blank tape row 8 leaves a block of one cell, and row 5 turns
the head round.

## What it does

At the left end in state E the tape is `E>0 1^x 0 0 1^y ...` (single 0s between the other blocks). A
**splitting step** takes it to `E>0 1^x' 0 0 1^y' ...` with x' = ⌈2x/3⌉, y' = y + x − x' + 1 (the second block
sometimes written `1 0 1^(y'−2)`), the rest unchanged: 810 of the 1,241 consecutive left-end visits in 10^9 steps
(`tmrun M 1000000000 at E L`), e.g. 494 → 330 → 220. Cost ≈ x²/3 steps (2,827,525 for x = 2,903).

The cut is a zigzag between the single 0 inside the first block and the double 0 (`1^i 0 1^m 0 0 1^j`): per trip
i += 2, m −= 3, j += 1.

When the first block is short the head goes to the right end (state C) and rebuilds long blocks there
(`... 0 1^522 0 1^2831 0 1 C>0` at step 968,216,616 → `... 0 1^1682 0 1^1745 0 1 C>0` at 972,860,864); the next
left-end visit starts from a long block again. Not yet described exactly.

Halting: A on a 1, entered only from F on a 1. In block terms: the three halting rows of the table (proved to be
the only ones). Growth: a series of cuts costs ≈ 0.6·x² steps for O(1) new cells, so width ~ t^(1/3) (3,612 cells
at 10^9).

Scripts: `py/blockmap.py` (the block map: `check`, `run`, `show`), `py/blocks.py` (writes the two Lean files),
`py/splits.py` (splitting-step statistics from a `tmrun ... at E L` log).

## Series (whole zigzags)

`lean/Series.lean` (kernel only):

- `zig`: `E (i :: L) (m+2+3t :: 0 :: j :: R)` reaches `E (i+2t :: L) (m+2 :: 0 :: j+t :: R)` in 3t frames.
- `halts_of_15`: if the run from blank tape reaches `E [] (15 :: 0 :: j :: R)`, the machine halts (critical frame 23
  frames later). `critical_mid`: the same from `E (4 :: L) (9 :: …)`, `E (2 :: L) (12 :: …)`, `E (6 :: L) (6 :: …)`.
- `never_halts_of_2`, `never_halts_of_3`: if the run reaches `E [] (2 :: 0 :: j :: R)` or `E [] (3 :: 0 :: j :: R)`,
  the machine never halts (`E [] (2 :: 0 :: j :: R)` goes to `E [] (2 :: 0 :: j+1 :: R)` in two frames, forever).

None of these frames has been seen. Trusted computation: `c/series.c` (the block map with each zigzag in one step,
checked against `py/blockmap.py` at 4·10^7 frames) runs 249,644,974,080 of its steps from the first frame with no
critical frame and no loop; the tape then holds 53,495,934,532 ones. That is of the order of 10^30 machine steps
(estimate from width ~ t^(1/3); the program does not count machine steps).

Observed, not proved. At the left end a block of m cells is cut to 2(m+1)/3 or 2m/3 until m ≡ 1 mod 3; after the
first cut the values are even, so 15 can only be the first value of a descent. Descents reach blocks of at most 20
cells about five times per doubling of the tape (`-DSTATS`, 6·10^10 steps: m = 4, 6, …, 20 cut 15 to 25 times each;
7, 9 and 19 once each, early). `c/mc.c`: 2,000 restarts from the tape at 647,185 ones, every block of at least 100
cells changed by a random 0..99, each run to four times the size: no critical frame, no loop. Random small tapes
halt often, so the large tapes avoid the critical frames for a reason not yet found.

## Sweeps (where it could halt)

While the head moves right through C frames each step moves one block from the right list to the left list
unchanged; the sweep stops at the first block of at most one cell: 0 turns the head round (state E), 1 halts unless
it is the last block. A sweep starts at a B frame (`B L (r+1 :: R)` → `C (r :: …) R`) or, once early in the run, at
`E L (1 :: 0 :: R)`. `halts_iff_sweep` (`lean/Sweep.lean`, kernel only): the machine halts iff the run reaches a sweep
start whose right list r₀, r₁, … has

- r₀ = 3 and r₁ ≥ 1, or
- r₀ ≠ 2 and the first block among r₁, r₂, … with at most one cell is a 1 that is not the last block

(`bad`, `SweepStart`). With the invariant, the third critical frame `0 1 1 C> 0 1` is the only way to halt.

Why 3 is rare as r₀: at the left end every value of a descent after the first is even, and `cut_even`
(`lean/Cuts.lean`) shows `E [] (18u+6 :: 0 :: j :: R)` → `B [8u+7] (4u+1 :: j+6u+1 :: R)` in 30u+7 frames: the
sweep starts on 1, 5, 9, 13, … cells. `c/sweeps.c` (trusted) tests every sweep start of 10^9 frames of the block map
with zigzags in one step (71,452,928 B frames): none is bad. r₀ is below 32 (and not the last block) 140 times, with
values 1, 5, 8, 9, 13, 14, 15, 16, 17, 18, 21, 25, 28, 29, 30, 31, never 2, 3, 4, 6, 7. The smallest later block a
sweep reads before turning, away from the last block, is 2 once and otherwise at least 4.

No finite invariant of this kind is in sight (heuristic): after the first 10^5 frames, blocks of fewer than 20 cells
occur only among the leftmost six blocks, as the last block, or next to the head (measured over 10^9 frames). `py/absint.py`, an abstract block map
that keeps up to 8 blocks at each end exactly (values below T exact, larger ones as "at least k"), started from
the real frames 2·10^6 and 10^8 with T = 30, finds an abstract path to the critical frame in under a second. Each
such path makes the last block small and then several small blocks next to each other, which the run has not done.
What keeps the blocks large is their size, which a finite pattern cannot express.

## Later

1. The whole cut is now a rule (`zig`, see "Series" below). Still to do: a whole sweep (induction on the list), to
   get a coarser map whose step is one cut or one sweep.
2. Invariant: done for two of the three critical frames (`lean/Invariant.lean`). For the third, the open question
   is whether a sweep ever starts on a bad list (`lean/Sweep.lean`). The community tracker calls the machine a
   "lottery" (simulated there to 2.7·10^19 steps), so there may be no invariant for it.
