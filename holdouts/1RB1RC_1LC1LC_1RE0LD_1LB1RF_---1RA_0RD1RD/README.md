# 1RB1RC_1LC1LC_1RE0LD_1LB1RF_---1RA_0RD1RD

bbchallenge id 151747. One of the six-state holdouts whose halting from blank tape is open. **It halts iff an
explicit two-counter map ("subtract the smaller count, triple it") ever lands on its diagonal; this reduction is
proved in Lean (kernel).** The map has been iterated for 10⁶ rounds without landing there, and a probability
argument says it never will.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RC |
| B | 1LC | 1LC |
| C | 1RE | 0LD |
| D | 1LB | 1RF |
| E | --- | 1RA |
| F | 0RD | 1RD |

## What it does

Counting cells in pairs, every *round* starts with the head in state C on the blank cell left of the tape, the
tape being one of two shapes (`(11)^u` is `u` pairs of 1s):

    P u v  =  C> 0 11 0 (11)^u 0 (11)^v
    Q u v  =  C> 0 11 0 11 0 (11)^u 0 (11)^v

From a round start the head runs to the right end. Then it *bounces*: it walks left into the middle block
`(11)^u`, comes back to the right end, and each such bounce takes one pair off the middle block, one pair off the
last block and adds three pairs to the block on the left. So the round subtracts: the bouncing stops when the
smaller of the two blocks runs out, and the left block has gained three pairs for each pair spent. Then the head
walks to the left end and the next round starts, with the left block (plus a few cells) as the new middle block and
what is left of the larger block as the new last block:

| round start | `u < v` | `u ≥ v + 2` | `u = v` or `u = v + 1` |
|---|---|---|---|
| `P u v` | `P (3u+2) (v−u−1)` | `Q (3v+3) (u−v−2)` | halts |
| `Q u v` | `Q (3u+3) (v−u−1)` | `P (3v+5) (u−v−2)` | halts |

The halt: when both blocks run out in the same bounce, the head runs off the right end in state E, which has no
transition on a blank. From blank tape the machine reaches `P 3 0` in 42 steps, and the orbit begins

    P 3 0 → Q 3 1 → P 8 0 → Q 3 6 → Q 12 2 → P 11 8 → Q 27 1 → P 8 24 → P 26 15 → Q 48 9 → P 32 37 → …

So the machine runs a *Euclid-like subtraction with tripling*: of the two counts, the smaller is subtracted from the
larger and tripled. The sum `u + v` grows by the smaller count each round (by a factor of about 1.24 on average,
0.307 bits a round). Each round costs about `(u + v) · min(u, v)` steps (a bounce crosses the tape), so the tape
length grows like the square root of the step count (the right side of the tape, where the blocks are), while the
round starts add a few cells at the left end once per round, which grows like the logarithm of the step count.
That is the exp/sqrt shape the triage saw.

## Does it halt?

It halts iff some round has `u = v` or `u = v + 1`, that is iff the two counts come within one of each other.

* **Proved (Lean, kernel only):** the whole reduction, `halts_iff'` in `lean/Reduction.lean`: the machine halts
  from blank tape iff the orbit of `next` from `P 3 0` reaches a pair with `u = v` or `u = v + 1`. Behind it, the
  round theorem `round` (every round, for every `u ≥ 3` and `v`, ends where `next` says) and `round_halt` (the
  halting rounds halt), in `lean/Macro.lean`, built from 31 symbolic rules in `lean/Rules.lean` generated by
  `lean/rules.py` with `tools/py/bbtools/symtm.py` (single steps by `rfl`, runs over repeated words by
  `TM.cross_l`/`cross_r`), and an induction on the number of bounces (`bounce_iter`). Axioms: `propext`,
  `Quot.sound`, `Classical.choice`.
* **Proved (Lean, kernel):** the first 10,000 rounds do not halt (`first_rounds`, by `decide +kernel` on the map;
  by then `u + v` has about 3,000 bits, so this is far beyond any step count a simulator can reach).
* **Computed:** the map iterated for 10⁶ rounds (`py/orbit.py 1e6`) does not reach the diagonal; `u + v` then has
  about 307,000 bits (a longer run, stopped at 2.7·10⁶ rounds and 828,000 bits, found none either;
  its closest approach was about 2^−22, at round 1,937,790). The first 26 round starts of a direct 3·10⁷-step simulation agree with the map
  (`py/orbit.py 1000 --check 3e7`), and every case of the rule was checked against direct simulation for all
  small `u`, `v`.
* **Heuristic:** the direction `u/(u + v)` behaves like a chaotic orbit of an expanding piecewise map (`x ↦ 3x/(1+x)`
  below one half and its mirror above), so the chance that a round lands within one of the diagonal is of the order
  of `1/(u + v)`, which shrinks geometrically. Summed over all rounds after the 10⁶ computed ones, the chance of halting is about
  `2^−300000`; the closest approach after round 20, measured by `|u − v − ½| / (u + v)`, was about
  2^−20 (round 20,726; `py/orbit.py` prints it), while hitting the diagonal at round 10⁶ would need about
  2^−307000. No congruence rules the diagonal out: the residues mod `m` reachable by the map (both branches
  allowed) include diagonal ones for every `m` from 2 to 39 and for `m` = 81, 243, 729, 2187, so a proof of non-halting would have to
  control the order of the counts, not only their residues. This is a cryptid in the sense of bbchallenge:
  probviously non-halting, open.

## For later

A non-halting proof needs an argument that `|u − v| ≥ 2` forever. Ideas: (1) look for an invariant region of the
ratio `u/(u + v)` together with lower-order terms that excludes the diagonal (the ratio map is expanding, so this
looks unlikely); (2) the residue sets mod 3^k shrink in relative size (7/18 mod 3, 171/1458 mod 27) — check whether
some modulus combined with the order of the counts closes; (3) otherwise this is in the same position as Antihydra.

## Files

- `lean/Rules.lean` (generated by `lean/rules.py`): the symbolic rules of a round, for all values of the counts.
- `lean/Macro.lean`: the bounces by induction, the ends of a sweep, `next`, `round`, `round_halt`.
- `lean/Reduction.lean`: the orbit from blank tape, `halts_iff`, `halts_iff'`, `first_rounds`.
- `py/orbit.py`: the map, its long iteration, and the check against direct simulation.
