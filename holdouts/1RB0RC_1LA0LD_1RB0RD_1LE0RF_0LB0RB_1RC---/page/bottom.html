It never halts.

Started on a blank tape, 1RB0RC_1LA0LD_1RB0RD_1LE0RF_0LB0RB_1RC--- runs for ever. Lean states it as

theorem nonhalting : ¬ HaltsFromBlank := nonhalt_of_reach (m := 6) reach_C7      -- lean/Reach.lean

where HaltsFromBlank is the machine's own halting from blank tape, defined from its transition table in lean/Machine.lean. In words: the run from blank tape is at C 7 after 16,730,681,219 steps, and from any C k with k ≥ 1 it reaches C (k+1), and so on without end.

Why a halt cannot come

The only halting transition is F reading 1. State F is entered only from D reading 1 (D1 = 0RF), so a halt needs the head in state D on 1 1. In the bouncer phase this never happens: the period is proved for every number of blocks, and the run over X is the same every time. Before it, Lean checks the whole run of 16,730,681,219 steps from blank tape, in eight chunks of about 2×109 steps: the C simulator proposes the configurations at the chunk boundaries, and a block simulator proved correct in Lean (blocks of 16 cells, one table lookup per block crossing) checks each chunk, with native_decide.

What it rests on

#print axioms nonhalting (lean/Axioms.lean) shows the standard axioms and, besides them, the compiled evaluations of native_decide (Lean.ofReduceBool). So the result is native_decide: it trusts Lean's compiler for these fixed computations, and the kernel for everything else.

Not needed for the proof: Kernel step_none_iff (where it can halt) and blank_runs_kernel (no halt in 10,000 steps), native_decide blank_runs_native (107 steps), all in lean/Blank.lean; Kernel dsweep and blk_cross (lean/Sweep.lean), the rightward sweep in state D as a block transducer on the "Q encoding", a building block for the earlier phase; Computed no halt in 1011 steps (py/lturn.c); Heuristic the description of the five epochs before the bouncer.

The chunk files depend only on lean/Bound.lean and lean/Final.lean, so they can be checked in parallel; lean/check.sh runs them one after another, about 25 minutes in all. The box near the top of the page says where a second, independent proof in Coq lives (coq/ in this machine's folder); there the long computations run under vm_compute inside Coq's kernel.

The panels of this page re-run the computations behind the native facts in your browser, with code written for the page: the block simulator through the eight chunks, the two window runs and the closing equality. That is a third, independent evaluation, not a proof: it trusts the browser's JavaScript.
