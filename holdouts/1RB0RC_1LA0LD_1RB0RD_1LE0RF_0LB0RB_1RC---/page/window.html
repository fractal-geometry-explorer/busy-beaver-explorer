An excursion is three million steps over a fixed list of cells, so Lean simply runs it. The difficulty is that the tape left of X holds the blocks, whose number n is a variable. lean/Window.lean solves this with a list simulator on a window: wsteps n ⟨l, r, s⟩ runs the machine on the cells l (left of the head, nearest first) and r (from the head on, blank beyond its end), and fails if the head would move left of l. Kernel wsteps_over (with wsteps_over1 and wsteps_over3 for windows of one and three cells): a run on the window that succeeds is a run of the machine with any tape at all further left. So a single evaluation covers every n.

native_decide The three facts of lean/Period.lean that are evaluated:

theorem w1_ok : wsteps 1517479 ⟨[true], X, .B⟩ = some ⟨[], false :: r1t, .E⟩
theorem w2_ok : wsteps 1511551 ⟨[true, true, false], r1t, .B⟩ = some ⟨[], false :: r2t, .E⟩
theorem close : [true, false] ++ r2t = accb ++ X

The first excursion starts with the head on the first cell of X in state B and the 1 written by pass 1 as its whole window on the left; it ends with that window used up, the head back on that cell, now a 0, in state E. The second starts with the three cells 0 1 1 written by pass 2. The last fact says that what the second excursion leaves behind, behind the two cells 1 0 that pass 3 writes in front of it, is one more block 1010001000100 followed by X again. period chains the five pieces with these facts, and rep_rotate moves the new block to the front: 1 0 (1000100010010)^(n+1) = (1010001000100)^(n+1) 1 0. Then C (n+1) reaches C (n+2) in 184n + 3,029,224 steps, for every n.
