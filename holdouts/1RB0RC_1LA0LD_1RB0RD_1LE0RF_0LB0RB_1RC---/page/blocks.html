The first 16,730,681,219 steps are checked in Lean by running them. Run one cell at a time this would be slow, so lean/Block.lean cuts the tape into blocks of 16 cells, each kept as a number from 0 to 65,535 (cell i of a block is bit i). A configuration of the block machine, MC, is the list of blocks left of the head, the list from the head on, the state, and whether the head is on the first cell of its block or on the last.

A table tbl has one entry for each state, block and side of entry: 6 · 216 · 2 = 786,432 entries. An entry says what the machine does inside the block until the head leaves it: the new block, the new state, the side it leaves on and the number of steps. It is computed by brun, a run on the block's 16 cells alone, and brun_ok proves that such a run is a run of the machine whatever lies outside the block. The simulator msim makes one table lookup per block crossing; chkF then makes the few steps that are left one at a time and compares the result with a given configuration.

Kernel chkF_ok: if chkF returns true for a start c, a step count t and an end g, then steps t (sem c) = some g.toCfg, a statement about the machine itself. native_decide tblOk: every entry of the table is what mkEntry computes (20 s). Neither needs anyone to trust the table.

Click cells to set a block, choose a state and a side, and the browser runs brun on those 16 cells. Each row is one step inside the block.


 
The index is idx q b side = (stIdx q · 65536 + b) · 2 + side, as in lean/Block.lean.
 An entry is empty (none) when the run halts inside the block or is still inside after 4,000 steps (FUEL); the block machine then falls back to single steps.

The whole run to C 7


Lean cuts the run into eight chunks at the steps T·i/8, T = 16,730,681,219. The configurations at the cuts
come from the C simulator py/dumpT.c, which only proposes them: chunk1 …
chunk8 each check one chunk with chkF (native_decide, about 3 minutes each), and
reach_C7 chains them into steps 16730681219 init = some (C 7). The last chunk ends at
finalF, and finalF_ok (kernel) says that finalF is C 7.


The same run fits in a browser. This button runs the block simulator of this page from blank tape through the eight
chunks and compares the end with C 7 built from X. It takes some seconds; the page stays usable meanwhile, and the
panel at the top of the page then starts from this C 7 instead of the one built from X.
