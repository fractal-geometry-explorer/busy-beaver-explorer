# 1RB1RE_0LC0LF_0LA0LD_1LE1LC_1RA0LB_---0RE

bbchallenge id 40254, one of the six-state holdouts. **Open; partly understood.** The machine is a rewriting
system acting on the left end of a word made of blocks `a^n` and `x^n` (a = 10, x = 1000), with a slow counter
`y^K` (y = a^4 0) at the right end. The two basic left-end rules are proved in Lean for all values; the rules for
the deeper levels of the word are only observed.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RE |
| B | 0LC | 0LF |
| C | 0LA | 0LD |
| D | 1LE | 1LC |
| E | 1RA | 0LB |
| F | --- | 0RE |

## What it does

Words: `a = 10`, `x = 1000`, `y = a^4 0 = 101010100`. Every time the head stands at the left end in state E,
the tape is

    0^inf E> 0 a^p 0 x^q a^r 0 x^s ... a^t y^K a^3 0 0^inf

a list of blocks, with a counter y^K at the right end (K = 46 at step 4.3·10^8, 51 at 9·10^8; the right side of the
tape grows like the logarithm of time). The head sweeps over the first blocks only; the long blocks, all swept,
make the left side grow like the square root of time. Proved for all values (`lean/Rules.lean`, generated by
`py/gen_rules.py`):

    ra:  0^inf E> 0 a^(p+1) 0 x^(q+1) R   ->  0^inf E> 0 a^(p+4) 0 x^q R      (4p + 26 steps)
    ri:  L a 1 E> 0 a^k 0 x^(q+1) R       ->  L 1 E> 0 a^(k+3) 0 x^q R        (4k + 24 steps)

`ra` turns one x into three a per sweep; `ri` is the same sweep when a stack of a's lies to the left of the head,
which loses one a per sweep. Observed (by simulation, `c/events.c`) on top of these, with first blocks
a^p 0 a^m 0 x^q:

- if m ≤ q: (p, m, q) → (1, 3m + p + 1, q − m)  — the m pairs are moved to a stack and `ri` runs m times;
  examples: (1, 11, 4023) → (1, 35, 4012) → (1, 107, 3977) → (1, 323, 3870) → (1, 971, 3547) → (1, 2915, 2576),
  and (714, 1491, 6138) → (1, 5188, 4647);
- if m > q the next level of the word is rewritten, e.g.
  `E> 0 a 0 a^2915 0 x^2576 a^2088 0 x^1110 y^46` → `E> 0 a^3 0 x^167 a^7732 0 x^487 a^3330 y^47`, and
  `E> 0 a^4611 0 a^9072 0 x^200 y^47` → `E> 0 a^4612 0 0 x^4434 a^600 y^48`: a block x^q next to the counter
  becomes a^(3q) and the counter y^K gains one.

**Halting.** The only halting transition is F reading 0; F is entered only from B reading 1, and B reads a 1 only
after E reads 1 (E1 → 0LB). So the machine halts exactly when the head in state E reads a 1 with `0 1` to its
left. None of the rules above does that.

## For later

Stopped after the two basic rules and the observed m ≤ q step. Missing: the exact rules for m > q (several cases
by m − q, partly fitted in scratch work), the rules at the second level (x^q next to y^K → a^(3q), K + 1), and the
assembly into a map on the list of block lengths. That map is a nested rewriting system, plausibly of the
Collatz-like kind (the pure regime `0 a^3 0 x^n y...` gives n → 3n/2 for even n). Next: prove the m ≤ q step as a
Lean induction over `ri` (it needs a rule moving a^m onto the stack, found by `symtm` with offsets m + 2), fit the
m > q cases with `c/events.c`, then iterate the list map in Python.

## Status

Open. Lean: the halting configurations (`step_none_iff`), no halt in 10,000 steps by the kernel and in 10,000,000
by `native_decide` (`lean/Blank.lean`); the rules `ra` and `ri` for all values (`lean/Rules.lean`). C
(`tools/c/triage.c`): no halt in 1,000,000,000 steps.
