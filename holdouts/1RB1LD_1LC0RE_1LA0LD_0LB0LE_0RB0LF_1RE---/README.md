# 1RB1LD_1LC0RE_1LA0LD_0LB0LE_0RB0LF_1RE---

bbchallenge id 26895. One of the six-state holdouts whose halting from blank tape is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LD |
| B | 1LC | 0RE |
| C | 1LA | 0LD |
| D | 0LB | 0LE |
| E | 0RB | 0LF |
| F | 1RE | --- |

## What it does

**A base-3 countdown on a list of blocks, and an exact map for the whole run.** At the start of every tick, the
head turns at the right end in state E, and the tape reads

    [left part] 1 0 1 0 0 E> 0 (1110)^y 111111 0^inf

Read the left part from the head outwards (right to left), up to its last 1, and call it the **word**. A block is
v = `0001` (the tape `1000`). The first block is the *timer*, and the block (1110)^y on the right grows by 4 every
tick. The usual separators are c = `010101`, r = `01` and z = `00` (on the tape `101010`, `10`, `00`). The other
separators are `1`, `01101` and `00101` (on the tape `1`, `10110`, `10100`).

A tick is a borrow into the separator after the timer. At a separator with block a before it and block b after it:

| rule | separator | becomes | blocks | Lean |
|---|---|---|---|---|
| A | starts with `01` (c, r, `01101`) | `00` + the rest (r, z, `00101`) | a - 1 | `tick_c`, `tick_10` |
| B | z `00` | c | a - 1, the borrow goes on to the next separator | `tick_00`, `pass_00`, `stop_c`, `stop_10` |
| C | `00101` | `1` | none | `tick_d`, `stop_d` |
| D | `1` | `01101` | a - 1, b - 1 | `tick_1`, `stop_1` |

A tick takes 30y + 5j/2 + 210 + 13m + e steps, where j is the cell position of the last separator the borrow
reaches, m is the number of B, and e = 0, 12, 6 for A, C, D. Then y grows by 4. The usual separators make a base-3
digit (c -> r -> z -> c, passing a borrow at z -> c). The other three make a **wall**: `1` -> `01101` -> `00101` -> `1`
takes 2 from the block before and 1 from the block after every three borrows, and never passes a borrow on.

Everything else is an **event**. Three kinds have exact formulas, and each holds at every instance the map meets in its long run (O1 15 times, O2 27 times, O3 35 times):

- **O1, the block next to the timer empties** (the separator after the timer is `0000`): the list
  (y; x1, x2, x3, ...) becomes (8; y+2, x1-1, x2-1, x3, ...). The `0000` becomes `00`, and a wall `01101` appears
  after x1-1. The growing block becomes the new timer.
- **O2, the timer empties** (the word starts with `00`): (y; 0, x1, x2, ...) becomes (8; y+2, x1-1, x2, ...). The
  `00` becomes the wall `1`.
- **O3, overflow at the far end** (every separator is z and the far end is `0 0001`, a last block of one behind an
  r): (y; x1, ..., xk, 1) becomes (8; y+2, x1-1, ..., xk-1). The separators become z, c, ..., c and the far end
  becomes `010101011`. Lean proves this for k = 1 (`overflow_1`).

The other events are borrows reaching the far end. They are computed by running the machine itself on a copy of the
configuration with every block cut to 40 copies and y cut to 40. The copy is run again with each block, and y, made
larger, which shows how the result and the step count depend on each size. Each event is computed with two different
cuts, and the two must agree.

## The map against the machine

`py/macro.py` is this map. `c/lword.c` prints every tick boundary of the real run. `py/check_macro.py` checks each
row against the one before it. **In the first 10^11 steps, 127,803 of 127,803 moves reach exactly the machine's
next row**: the same y, the same word and the same step count. 185 of the moves are events.

Run on its own from the first tick (`py/longrun.py`), the map reaches 1.6·10^18 steps, 340,407,518 ticks and
442 events, all with both cuts agreeing, and no cut copy halts. At the end the list (timer first) is

    y = 42,611,784; blocks 41,152,831, 513,803,810, 148,399,482, 164,597,001, 57,486,640, 28,532,194, 22,038,808, 1,066,527, 760,322, 342,766, 332,654, 80,670, 13,737, 4,158, 1

## Where it could halt

The machine halts only on F reading 1. Ticks never do that. A borrow arriving at the far end halts the machine when
the far end ends in `111` or a few similar words (`1111`, `11101`, `000011`, ...: 24 cases up to 7 cells,
`py/farend.py`). In 10^11 steps the run has shown 119 different far ends (what follows the last block of 10 or more).
That set is closed under borrow arrivals, and none of it halts. So the far end cannot halt as long as the last big
block lasts. That block is worn down at each O3, and the far end is reached only when every separator is z, which is
exponentially rare. Whether halting ever happens comes down to what the list looks like when the last blocks have
worn away.

## Rules proved in Lean (`lean/Rules.lean`, generated by `lean/rules.py`)

These hold for all block lengths and every surrounding tape:

- `tick_c`, `tick_10`, `tick_00`: the three kinds of tick, from the E-turn to the next E-turn (or to the borrow).
- `pass_00`, `stop_c`, `stop_10`: the borrow at each kind of separator.
- `sweep`, `arrive`: the sweep back to the right end, and the turn into the next tick.
- `tick_d`, `tick_1`, `stop_d`, `stop_1`: the wall separators `10100` (word `00101`) and `1`, both as the
  separator after the timer and when a borrow arrives. `10110` (word `01101`) is covered by `tick_10` and `stop_10`.
- `overflow_1`: overflow O3 with one block, from the E-turn to the next E-turn.

## Status

**Open.** Proved in Lean: the halting configurations and no halt in 10^7 steps (`lean/Blank.lean`), thirteen tick,
borrow and overflow rules (`lean/Rules.lean`). Checked against the machine: the map reproduces every tick boundary of
the first 10^11 steps exactly, and it runs on to 1.6·10^18 steps without a halting event. Heuristic: the far end
cannot halt while the last block lasts.

## For later

- A proof of the far-end closure: the 119 suffixes and their moves, each as a symtm rule.

  last blocks have worn away.
