# 1RB1LE_0RC1RC_0RD0RB_1RE0RF_1LA0LE_---1RB

bbchallenge id 2090. A BB(6) holdout whose halting from blank tape is open (group G07).
Family: **nested countdowns with erase sweeps (bouncer with growing epochs)**. Decision: **open**.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LE |
| B | 0RC | 1RC |
| C | 0RD | 0RB |
| D | 1RE | 0RF |
| E | 1LA | 0LE |
| F | --- | 1RB |

## What it does

Look at the tape each time the head is in E on the blank cell right of the tape (`E> 0^inf`, a *visit*; the
wall cycle C, D, E writes `0 1` per round, 13,577 rounds in 3·10^8 steps).

**Countdown (proved).** The end of the tape reads `L 0 1^(2j) 0 0 1 1 0 (10)^a 0 0 (10)^b 1 E>`, and

    L 0 1^(2j)   0 0 1 1 0 (10)^(a+1) 0 0   (10)^b     1 E>
    L 0 1^(2j)   0 0 1 1 0 (10)^(a+1) 1 1 0 (10)^(b+1) 1 E>     next visit
    L 0 1^(2j+2) 0 0 1 1 0 (10)^a     0 0   (10)^(b+3) 1 E>     the visit after

so every two visits j + 1, a − 1, b + 3 (3 cells a visit), and the head never goes left of `1^(2j)`.

**Epochs.** When a runs out the countdown stops and a long sweep (up to 2.6·10^6 steps) rewrites the left part;
a new countdown then starts with a about three times larger:

| epoch starts at visit | 10 | 44 | 107 | 260 | 713 | 2070 |
|---|---|---|---|---|---|---|
| a at the start | 3 | 30 | 75 | 225 | 677 | 1783 |

Each epoch lasts about 2a visits. From visit 5639 (5.7·10^7 steps) several countdowns are stacked at the right end
(`... 1 1 0 0 1 (10)^43 0 0 (10)^1135 0 1 (10)^5351 1 E>`), so the epochs nest; at visit 7170 the end reads
`0 0 1 (10)^4586 0 0 (10)^2295 1 E>`.

**The end of a countdown (proved).** When a reaches 0 three more visits follow,

    L 0 1^(2j) 0 0 1 1 0 0 0 (10)^b     1 E>
    L 0 1^(2j) 0 0 1 1 0 1   (10)^(b+2) 1 E>
    L 0 1^(2j+2) 0 0 1 0 0   (10)^(b+3) 1 E>
    L 0 1^(2j+2) 0 0 1 1     (10)^(b+5) 1 E>

and then the **erase sweep**: E goes left through the whole right part, turning the run `(10)^B` into a solid run
of 1s and the run `1^(2J)` into 0s, and stands in A on the cell to the left:

    L 0 0 1^(2J) 0 0 1 1 (10)^B 1 E>      ->      L A> 0 1 0 0^(2J) 1 1 0 0 1^(2B+1)          2J + 2B + 15 steps

So a countdown ends by wiping its own counter: where the run of 1s stood there is a **gap of 2J zeros**, and the
`(10)` run is one solid block. What comes next depends on the tape to the left. With a countdown one level up
standing there (`0 1 1 0 0 1 (10)^c ...`), that one loses a copy of `10` and the head enters the gap in D
(`outer_step`). The head then fills the gap in many short sweeps that do not reach the right end (5,000 steps for
the 64-cell gap at the end of the epoch a = 30): it leaves new `(10)` runs with markers between them (8, 9 and 13
copies there) and turns the solid block back into `0 0 0 1 (10)^75`, the next countdown. This filling of the gap is
the part that is not decoded; it is where the "three times larger" comes from and where a halt would have to
happen.

**Where it can halt.** Only F reading 0. F is entered only from D reading 1 (`0RF`), D only from C reading 0
(`0RD`), C only from B: the machine halts exactly when **C reads a 0 and the two cells to its right are 1 0**
(for example B stepping onto the 1 of `1 0 1 0`: in a `(10)` run the head must always arrive in the other phase).
The closed tape language of windows of 6 closes but allows F0 in 970 abstract configurations (20 at the right
edge); windows of 8 do not close in the search limit. So the halt is not confined.

## Status

* **Lean (kernel)**: `lean/Rules.lean`, generated by `py/rules.py`, for all counts and every tape L: `visit_p`,
  `visit_q` (the countdown), `exit1`, `exit2`, `exit3` (its last three visits), `erase` (the erase sweep),
  `outer_step` (the step of the countdown one level up, to the entry into the gap).
* **Lean**: `lean/Blank.lean`: the halting configurations; no halt in 10^4 steps (kernel), 10^7 (`native_decide`).
* **Trusted**: `py/blocksim.py` (runs of `10` crossed by shift rules) agrees with the C simulator at every visit up
  to 3·10^7 steps (`py/bscheck.py`); the epoch table comes from it. No halt in 10^9 steps (direct C simulation).
* **Open**: how the gap is filled, and so the map from one epoch to the next; whether `C> 0 1 0` is ever reached.

## Next steps

* The gap: follow the head from `... 1 1 1 0 D> 0^(2J) 1 1 0 0 1^(2B+1)` with J as a parameter. It is not one shift
  rule (the symbolic run stops at the gap), so look for the inner loop: the visits of the gap's right edge, as was
  done for the right end of the tape. If the filling is itself a countdown on the gap, the epochs are a recursion
  (each epoch runs the earlier ones inside its gap) and the epoch map follows.
* With the epoch map, look for a CTL with more context (windows of 7-8 seeded with the rules) that excludes
  `C> 0 1 0`.
