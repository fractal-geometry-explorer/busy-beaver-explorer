Events and steps computed by the simulators (py/closure/accel.py, py/replay/engine.py, verify/sim3.cpp, which agree); the Lean statement does not count them.

One period is two epochs, two drains. To prove that it goes on for ever, one period is run with r replaced by 65 + 2x, x unknown. Whenever a step would depend on the value of x the executor stops; it never had to. It ends in the same configuration with 65 + 321,042,928 + 2x, after 5,581,714 moves (period_run, lean/Period.lean, evaluated by native_decide). With run_pos this is the theorem grow_cyc: for every x, C(65 + 2x) reaches C(65 + 2(x + 160,521,464)) in at least one step. The run from blank tape reaches C(16,797,709) = C(65 + 2·8,398,822) (reach_cyc: 5,037,044 moves, lean/Arrive.lean). And the kernel proves the last step, nonhalting_of_growth_cycle in lean/Cycle.lean: if the run reaches some C(65 + 2x) and every C(65 + 2x) reaches a later one in at least one step, then the run from blank tape is at such a configuration at later and later steps, so it is still running at every step: the machine never halts.

Why only the parity of r matters

The claim behind the symbolic period can be watched on the real machine for small r: start from C(r) for two odd values of r and compare the two runs event by event. Up to the last block the two tapes are the same, and the last blocks keep their difference. Start one of them from an even r and the tapes part at once; C(r) with r even halts, at event 21,362,421 (computed, py/closure/classes.py).

The left part is the tape from the head to the start of the last block (011)^r; the plot shows its length (in cells) and the last block's count, event by event, for the first r. 3,000 events are about 1.5·108 steps for each run.
