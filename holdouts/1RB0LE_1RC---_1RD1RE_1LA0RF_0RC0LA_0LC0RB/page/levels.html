The question "does this machine halt?" is answered here at four levels of description. Each level keeps less detail than the one above it, and each step down is a Lean theorem, checked by the kernel: what happens at the lower level is exactly what the machine does. At the bottom, the question is whether a list of linear inequalities on a few numbers is kept by twenty arithmetic cases, and that is a question omega can settle.

Level 1The machine
A tape of cells and a head in one of six states. One unit of time is one step.
Kernel Lean runs the first 29,301 steps from blank tape itself (blank_O). Level 2Forms and rules
The tape at a visit to one end, written as a form such as O a b c: a few run lengths. One unit is one rule: a turn of a cycle or an exit, a few end visits.
Kernel same run as level 1: each of the 27 rules says the machine goes from form X to form Y in an exact number of steps, for all sizes (lean/Cycle.lean, Phase.lean, Branch.lean, Ends.lean). Level 3A map on ten forms
Only the form at the start of each phase. One unit is one move: a cycle run to its end and one exit. There are 20 cases, each affine in the numbers.
Kernel same run as level 2: each case mv_* (lean/Closed.lean) chains a cycle iterate and one exit rule. Level 4The invariant Good
For each form, 3 to 16 linear inequalities on its numbers. Not a new clock: one argument that covers every move at once.
Kernel good_step: from a Good form the machine makes at least one step and reaches a Good form (one mv_* case and omega each).
The way in: table_from_blank Kernel follows the run from blank tape through 196 moves, to T2 34158019330534 128092572489511 160237983842729 41908435347077 at step 5.7·1029, and good_last Kernel checks with decide that this form is Good. From there level 4 takes over (the bottom line).
