This page walks through the Lean proof that this machine, started on a blank tape, never halts. You do not need to know Lean or Turing machine theory. Each step says what is claimed, shows it on the real machine in your browser, and says what checks it. Here every piece is checked by Kernel, Lean's small trusted core. The proof uses no native_decide and no compiled code.

The idea of the proof is an invariant: a description of a set of tapes, called good, with three properties.

  1. The run reaches a good tape. From the blank tape the machine reaches a good tape. It gets there after about 5.7·1029 steps, by 196 moves that are each a proved rule.
  2. A good tape always leads to another good tape. From any good tape the machine makes at least one step, without halting, and arrives at a good tape again.
  3. So the machine never halts. Repeating step 2 forever gives runs of every length. A machine that halts only has runs up to some fixed length.

A tape is "good" when it has one of ten shapes, called forms. Each form is a short pattern with some numbers in it, and those numbers must satisfy a list of linear inequalities, such as 534·b ≤ 1321·a + 321·c. The rest of this page explains the forms, the rules that take one form to the next, and why the inequalities keep holding.

The table has one missing entry: B reading a 1. That is the only way to halt. Two transitions lead into B: A reading a 0 (writes 1, moves right) and F reading a 1 (writes 0, moves right). So the machine halts exactly when the head reads A> 0 1 or F> 1 1 (Lean: halt_A, halt_F).

The proof never looks for these patterns directly. It shows something stronger: from the blank tape, for every number n, the first n steps are all defined. That is the Lean statement ¬ HaltsFromBlank, where HaltsFromBlank means "some step reaches a configuration with no transition".

Watch the machine for a while and its tape turns out to be made of long runs of a few short words: 1000, 10, a 14-cell word such as 00001000001000, and a few others, with short fixed pieces between them. So the tape can be written as a form: a pattern with the run lengths as numbers. For example

Between turns the head sweeps across the long runs. A run of a million copies would take millions of steps to simulate. But what happens to a run is simple, and Lean proves it once for every length:

  • pass_10_right: C crosses (10)^n to the right in 2n steps and leaves it unchanged.
  • pass_10_left: A crosses (01)^n to the left in 8n steps (it carries 10 along).
  • fill_F: F turns (1000)^n into (1110)^n, 10 steps a copy.
  • fill_B: B turns (0001)^n into (0111)^n, 10 steps a copy.
  • clear_A: A, going left, turns (0111)^n into (0010)^n, 10 steps a copy.

Each is proved by running one copy for real (rfl: the kernel computes those few steps) and then a general lemma: if one copy takes the head through in the same state, n copies do too, in n times the steps. Kernel

Using these passes, Lean proves 27 rules. Each rule says: from form X with numbers like (a, b + 6, c + 2), the machine reaches form Y with numbers that are simple formulas of a, b, c, in an exact number of steps that is also a formula. The rule holds for every value of the variables. Kernel

The central example is the 4-visit cycle cycle: S1 a (b+2) (c+2) reaches S1 (a+3) (b+14) c in exactly 80a + 72b + 1356 steps. Each turn uses up two of the 14-cell words (c drops by 2), and the runs of 1000 and 10 grow by 3 and 12. The head visits the left end four times on the way.

Each rule's proof is a symbolic run: Lean steps the machine on a tape whose runs have lengths like b + 2, uses a pass to cross a whole run at once, and at the end shows the tape it got is the target form (by regrouping, e.g. (0010)^a 0 = 0 (0100)^a). Lean also proves the k-fold repeats such as cycle_iter, by induction on k.

Not every arrow is safe for every size. A rule needs its numbers to be large enough (for oentry, b ≥ 6 and c ≥ 2), and some combinations have no rule at all, for example T3 running out of 14-cell words while 5 or more 0010 are left. Those are the gaps the invariant of Step 6 closes.

The 196 moves cover a finite stretch of the run. To go on forever the proof needs one argument that works for all later moves. That is the invariant Good in lean/Closed.lean: for each form, a list of 3 to 16 linear inequalities on its numbers. They say three kinds of things:

shape
the growing numbers keep their ratios inside a fixed region. For O a b c, b stays between about 1.7 and 4.2 times a, and c between about 0.3 and 2.3 times a, in the shaded region of the picture below.
small parts
the bounded numbers stay in range (in RF, k is 4 or 5), and some numbers keep exact relations (in T3, x = 2a + 4).
size
one weighted sum is at least about 108, such as 71·b ≥ 50,000,000 for O.

The picture shows, for the forms O and S1, the region that the ratio inequalities allow (shaded), and the ratios of every O or S1 state of the replay (dots). The ratios move around from phase to phase but stay in the region. Filled dots are good states. Hollow dots are early states, which are still too small for the size condition.

Why do the inequalities keep holding? Seen from one phase to the next, the run is a map on the ten forms with 20 cases: one cycle run to the end, then one exit. The cases are split by the remainder of the count the cycle uses up (c mod 2, d mod 5) or the parity of the run just built. In each case the new numbers are fixed linear formulas of the old ones (lemmas mv_*). So the step from Good to Good is a question about linear inequalities, which Lean's omega procedure decides. Kernel Each case works because:

  • the map sends each form's region strictly inside the next form's region, with room to spare;
  • the size grows by a factor of at least 1.1 per case, so the room to spare grows faster than the fixed offsets in the formulas (the "+6", "+1356" and so on);
  • the inequalities imply every condition a rule needs (b ≥ 6 and so on), and that T3 has enough 14-cell words for all its turns. That rules out the gaps of Step 4.

That is good_step: from a good tape the machine makes at least one step and reaches a good tape. The coefficients (up to 1,321) were found by linear programming on the replay's numbers, with scripts outside the proof. Lean does not trust them: if one were wrong, omega would fail.

The last state of the replay is good: Lean evaluates its 16 inequalities with decide (good_last). Kernel

#print axioms H113677.nonhalting lists only propext, Classical.choice and Quot.sound, the three standard axioms of Lean's logic. There is no native_decide axiom: no compiled code is trusted anywhere in this proof.

The file lean/Blank.lean does contain one native_decide (a check that the first 107 steps do not halt), but nonhalting does not use it. It is a side fact, shown on the status page.

Other checks, separate from Lean Computed: the first 49 states of the replay match the plain run up to 3·1010 steps (c/checkpoints.c), and your browser can repeat the first ones in Step 5. The replay itself goes on without a gap to 10300 steps (2,281 states).

The end of lean/Closed.lean, theorem by theorem:

Good t
t is one of the ten forms, with numbers that satisfy that form's inequalities (gOp, gO0, gS1, gRF, gEF, gT3, gT2, gU3, gRG, gRG3).
good_step
from a good t, at least one step leads to a good t′. One case per form (step_Op … step_RG3), each split by remainder or parity into the 20 cases.
table_from_blank
some run from the blank tape ends at the last state of the replay (blank_O then table_run).
good_last
that last state is good.
nonhalting
¬ HaltsFromBlank. By induction on N: for every N there is a run from blank of length at least N ending at a good tape. So runs of every length exist, and the machine does not halt.
