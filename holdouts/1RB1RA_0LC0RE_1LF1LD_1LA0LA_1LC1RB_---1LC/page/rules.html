The same machine written the way the bbchallenge wiki writes Antihydra's: name the tapes exactly, then list the rules, each with the exact number of machine steps it takes. The Lean proof works one level below the doubling map, on the sweep of lean/Map.lean, so the table follows it. The last column names the Lean theorem with that step count: blank_to_S in lean/Map.lean, all others in lean/Rules.lean, each for every value of its counts. The halting row counts the steps up to and including the halting transition: halt_run proves 16k + 30 steps to a tape where F reads 0, which is undefined. lean/Map.lean rewrites these moves onto the tapes S and R (r_start, r_round, …, r_halt) and assembles them into the visit map F; that file keeps the tapes but not the step counts, and halts_iff proves the machine halts iff these rules, started at S(0, 4, 1), reach the halt row. lean/Doubling.lean (halts_iff_op) turns the same rules into the doubling map on (c, u, v) = (c, b + 1, a/2 + b + 2). Every row has also been checked against direct simulation (py/model.py rules): each rule on 3,740 tapes, the chain of rules from 2,856 visits to the next visit or the halt (28 of them halt), and every one of the 377 visits of the first 107 steps of the run, each at the predicted step.

A doubling (2b < a) is one start, b rounds and the end of the sweep: S(c, a, b) → S(c, a − 2b, 2b + 1) in 4b2 + 12b + 24 steps, that is 4u2 + 4u + 16 in the variables of the doubling map. For example S(1, 2, 6), a visit whose next reset halts: the sweep starts (42 steps) at R(1, 0, 0, 5), the pool is already empty so a carry (22) gives R(0, 2, 1, 2), two rounds (16 and 24) give R(0, 0, 3, 0), and with pool, left block and right block all empty the machine halts after 79 more: 183 steps in all, which is what direct simulation gives.
