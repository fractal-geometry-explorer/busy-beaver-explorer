Change variables: put u = b + 1 and v = a/2 + b + 2 (so a = 2(v − u − 1) and b = u − 1). The odometer's condition 2b < a becomes 2u < v, and its three wheels become one operation on (c, u, v) (op in lean/Doubling.lean):

2u < v          u ← 2u,  v ← v + 1                          a visit
2u > v, c ≥ 1   u ← 2u − v,  v ← v + 1,  c ← c − 1          a carry
2u = v, c ≥ 1   u ← 1,  v ← v + 2,  c ← c − 1               an emptying carry
2u > v, c = 0   c ← 2(v − u − 1),  u ← 2u − v,  v ← u + 3   a reset
2u = v, c = 0   halt

In words: double u; if that reaches v, subtract v and use up one unit of c; add one to v. So u is doubled modulo v, and the modulus creeps up by one at every operation. The left block c only counts the wrap-arounds: c of them are allowed, and the next one is a reset, which refills c with 2(v − u − 1) and drops the modulus to (2u − v) + 3. The machine halts exactly when a reset finds 2u = v, that is when u sits exactly at the middle of [0, v] at the moment the left block is empty.

The quantity that matters is the fraction x = u/v. Doubling sends x to about 2x when x < 1/2 and to about 2x − 1 when x > 1/2: the binary shift, the textbook example of chaos. The small corrections from v growing are what keep it exactly computable and unpredictable at once. One thing is conserved: c + v = 5 + visits + resets + emptying carries, so the modulus is essentially a clock that counts visits.
