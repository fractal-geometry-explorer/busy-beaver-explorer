# 1RB1LF_0LC0RE_1LA1RD_0LB1LB_1RC1RD_0LD---

bbchallenge id 32070. One of the six-state holdouts whose halting from blank tape is open.  Its tape is a few
long runs of the word `110` separated by short markers; the head sweeps the whole tape and moves material from one
run to another, and markers are created and destroyed now and then.  No regular round has been isolated yet;
this folder records the structure seen and the exact halting pattern.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LF |
| B | 0LC | 0RE |
| C | 1LA | 1RD |
| D | 0LB | 1LB |
| E | 1RC | 1RD |
| F | 0LD | --- |

## What it does

Each time the head is at the left end in state B, the tape read with `b = 110`, `c = 11110`, `d = 1111110` is a
short prefix and then a few long runs of `b` separated by markers such as `1^2 d`, `c 0^2` (every 400th visit
from blank tape, C simulation `tools/c/tmrun.c ... at B L`):

| step | tape after the head (`0^3` or `0 1 0 b` prefix dropped) |
|---|---|
| 13,719,178 | `d c b c b^20 1^2 d b^3 1^2 d b^290 c 0^2 b^510 1^2` |
| 50,149,940 | `d c b c b^171 1^2 d b^351 c 0^2 b^1110 1^2` |
| 97,492,291 | `1^2 d 1^4 d b^1445 c 0^2 b^729 1^2` |
| 157,357,383 | `d c b c b^269 1^2 d b^846 c 0^2 b^1596 1^2` |
| 226,944,012 | `d c b c b^232 1^2 d b^1029 c 0^2 b^1987 1^2` |
| 343,611,306 | `d c b c b^213 c 0^2 b^157 d c 0^2 b d b^3671 c 0^2 b^3 1^2` |
| 523,208,944 | `d c b c b^568 1^2 d b^684 c 0^2 b^4136 1^2` |
| 785,997,151 | `d c b c b^458 1^2 d b^3 1^2 d b^321 c 0^2 b^5410 1^2` |
| 938,559,503 | `d c^2 b 0^2 c b^3 c b^4971 c 0^2 b^1758 1^2` |

So the tape is mostly `110` repeated: between markers the runs `b^n` swap lengths (a run grows while its neighbour
shrinks, then a marker moves or vanishes and the roles change).  The right end of the tape almost never moves (the
"exp" side of the triage); the left part grows like the square root of the step count, a few cells per sweep.

### How it could halt

The halting transition is F1, F is entered only by `A1 -> 1LF`, and A only by `C0 -> 1LA`; so the machine halts
exactly when C reads a 0 with two 1s to its left (`1 1 C>0`).  Inside the runs `110` a 0 has `1 1` to its left, so
everything hinges on the head never arriving at such a 0 in state C; the markers are where this is decided.

## Family screen (F09, 13 November 2026)

The 22 machines of family F09 were screened in one way, to decide which family each belongs to. `holdouts/1RB0LC_0RC0RF_1RD0LE_1LA1RA_1LC1RB_0RB---/screen/screen.py`
runs the machine from blank tape for 2·10^10 steps and, at the first new leftmost and rightmost cell after each
threshold 10^6·4^k, compresses the tape twice: repeats of a word of at most 40 cells (level 1), then repeats of
groups of such tokens (level 2). A bounded description keeps the number of level-2 tokens bounded while the tape
grows. The long runs use the macro simulator `holdouts/1RB0LE_0RC1RC_0RD1LA_1LD0LA_1LF1LC_---0LA/c/msim.c`, sampled at one record per leading digit of the step count.
Everything in this section is observed in one run; none of it is proved.

**Proposed family: F01, periodic blocks driven by a bounded engine** (two or three long runs of one word, traded through a few markers).

The description is small and does not grow: 10 to 23 level-2 tokens at every record from 2.6·10^8 to 1.8·10^10 steps, and 9 to 19 runs in the macro simulator (blocks of 3 cells) at the sampled right-end records up to 10^18 steps. For example at the right-end records the tape is `(10)^3 001 (010)^3 (100)^3703 00101 0^6 1 0^4 (100)^19078 1010` at step 6,897,736,719 and `(10)^3 001 (010)^3 (100)^6716 (10)^3 (010)^26894 10` at step 17,594,309,535.

Two or three long runs of one three-cell word and a handful of markers is the F01 shape. The engine is not known: in the macro simulator (blocks of 3 cells) the left end is extended only 3,666 times in the first 3·10^8 steps and the shape of the markers differs from one extension to the next, so there is no single round to iterate yet.

Next step: List the marker configurations between the runs as a finite set of tails and try the F01 closure; if the set of tails does not close, the machine moves to the cryptids.

## Accelerated run to 10^1000 steps (F09, 13 November 2026)

`py/lvl2.py` is an exact simulator with two levels of acceleration. Level 1 is the macro simulator used in the family
screen (blocks of 3 cells, a run of one word crossed at once). Level 2 looks for a stretch of macro steps after which
the tape has the same shape and only the lengths of some runs have changed by fixed amounts; it replays the stretch
with those lengths as unknowns, which proves the stretch for all lengths satisfying a list of inequalities, and then
applies it as many times as the inequalities allow. Nothing is extrapolated: a repeat is applied only when the replay
covers every one of its cycles. The docstring of `py/lvl2.py` has the details.

Result: **no halt in the first 10^1000 steps.** The run stops at the first macro-step boundary after 10^1000, at step
1.0963…·10^1000 (a number of 1,001 digits), after 10,912,556 macro steps and 18,888 applied repeats (of at least 12 cycles
each). The tape then has 10 runs. Output: `py/lvl2_1e1000.txt` (about 4 minutes).

Checks: `py/check_lvl2.py` compares `lvl2.py` with the macro simulator `msim` (itself checked cell for cell against
the direct simulator). For this machine the state, the head side, the whole tape, the step count and all right-end
records agree at 1.0·10^12 steps (59 records), 1.1·10^15 steps (84 records) and 3.3·10^17 steps (104 records); the
same comparison passes for all 22 machines of family F09 at 3·10^6 steps. Beyond
that the result rests on the simulator alone (level: trusted).

### What the run shows (observed, not proved)

The tape is a short fixed-looking prefix, two to four very long runs of one three-cell word (`100`, `010`, `001` on
the left of the head; `011`, `101`, `110` on the right) and short markers between them. Almost all the time goes
into repeats in which the runs trade words at fixed rates. An example, at step 262,317,335,904,169:

    D> 101 010^2 000 001 000^2 100^5 101 | 111^2 011^2147627 110 001 101^1343390 100

A cycle of 105 macro steps takes 8 words off the run `011^…`, adds 8 words to the run `101^…` and adds 2 words to the
run `100^…` left of the head. It repeats 268,453 times, until the `011` run is used up (2,147,627 = 8·268,453 + 3); the
remainder 3 is left in the markers, and it decides which repeat comes next. So each repeat divides a run length by
a small number and the remainder steers the machine, which is the shape of a Collatz-like map.

In all 63 kinds (p, d) and 391 tape shapes occur. The kinds come in threes with the same d (p = 104, 105, 114; 208, 217, 242;
720, 729, 802; 49, 50, 52; 177, 180, 190), one for each of the three words. The rates form a ladder: 8, 16, 32, 64
and, 13 times, 256 (cycles of 2,777 to 2,960 macro steps). New kinds were still appearing late in the run, so the run
gives no finite table of rules, and the closed-set test planned in the family screen has nothing finite to close over yet.
What would settle the machine is not known: either a description of the whole ladder as one rule with a parameter, or an
argument about the remainders. Until then the family assignment F01 is doubtful, and the machine may belong with the
Collatz-like machines (cryptids).
