# 1RB1LF_1RC0RA_0RD1RA_1RE1LA_0LA---_1RF0LD

bbchallenge id 180268. One of the six-state holdouts whose halting from blank tape is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LF |
| B | 1RC | 0RA |
| C | 0RD | 1RA |
| D | 1RE | 1LA |
| E | 0LA | --- |
| F | 1RF | 0LD |

## What it does

Family: **binary counter with paying blocks** (a binary-weighted counter list).

Write `a` for `10` and `a^y` for `y` copies.  Every time the head reaches a new cell at the left end, the tape reads

    A> 0 a^x b1 a^y1 b2 a^y2 ... bk a^yk  tail

with single-cell **bits** `b_j` in {0, 1} between the blocks (a block of 0 or 1 copies makes the bits look like the
short words `00`, `01`, `0100`, `1101`, ... in a printout; they are still bits and blocks).  One visit of the left end
is one **binary decrement**, with b1 the lowest bit:

* find the lowest bit `b_j = 1`; set it to 0 and the bits below it to 1;
* the block right after that bit loses one copy (`y_j -> y_j - 1`);
* the first block gains two copies (`x -> x + 2`).

Proved in Lean for every x, y, z (`dec_1`, `dec_2`, `dec_3` in `lean/Rules.lean`: lowest set bit first, second,
third).  So block j pays one copy every 2^j visits: from one right-end event to the next (a full count from all ones
down to zero), the block j places from the right loses 2^j copies, the pattern the first pass saw.  When all bits are 0
the borrow runs into the tail, the head goes to the right end (the rare right-end events, where the tape reads
`a^x0 1^4 0 a^x1 1^4 0 ... a^xk 1^2 0 D> 0`), most bits are set back to 1 and the old first block becomes a block of
the list behind a fresh first block (`x = 2`).  When the borrow meets an empty block (`y_j = 0`), the list is
rewritten: blocks are split and merged and the first block restarts (examples in the table below, from `c/events.c`).
That rewriting rule is the part not yet decoded.

| left-end visit before | after the rewrite |
|---|---|
| `A>0 a^13 0 a^42 0 [] 0 a^37 1 a^3 1100` (step 14,297; `y2 = 0`) | `A>0 a^3 1 a^13 0 a^40 1 a^2 0 a^37 0 a^2 1100` |
| `A>0 a^29 0 a^6 0 a^30 0 a^130 00` (all bits 0) | `A>0 a^3 1 a^29 0 a^5 1 a^30 1 a^130 1100` |

The log side is the right end (it moves only at the rare full borrows), the sqrt side the left end (the first block
grows by 2 copies a visit and every visit sweeps to the lowest set bit and back).

## How it could halt

The machine stops only on E reading 1.  Going back four steps (`halt_needs_four_zeros`, `lean/Halting.lean`): E is
entered only from D on a 0, D next to a 1 only from C on a 0, C only from B on a 0, B only from A on a 0, so a halt
needs **the head in state A on `0 0 0 0 1`**: four blank cells inside the written tape.  In the counter, zeros come
alone or in pairs; a run of zeros grows by one only when B reads `1 1 0^r` (the 1 next to the zeros is cleared and
restored around it), so a halt needs a run of three zeros `11 000` met that way.  In 10^9 steps from blank tape such
a run of three is made 37 times (always `a^k 11 000 a^m`) and never grows to four (`c/zeroruns.c`, computed).

A run of four zeros is what two empty blocks next to each other give: with `y_j = y_(j+1) = 0` and the bits around them
0 the tape reads `a^x 0 0 0 a^y`.  That is how every halt found below happens.

**Perturbation test** (`c/pert.c`, computed).  Take the real configuration at the right-end event of step 173,780,460
and replace its block lengths by random ones: with lengths in [1, 60], 4 of 100 trials halt within 2·10^7 steps; with
lengths in [5, 300] of the same parity as the real ones (they are all odd), 3 of 300 halt within 5·10^7 steps.  The
real lengths never do.  So not halting depends on the actual values of the blocks (when two neighbouring blocks run
out together), not only on the shape of the tape or on residues: no closed tape language that forgets the lengths can
prove it.  This is why the window CTL fails, and also why a token-window CTL with run compression (tried, see For
later) fills up with halting configurations.

## For later

Where this stopped: the left-end macro state (x; bits; blocks) and its decrement are exact and in Lean for one, two
and three borrows.  Next:

1. The general decrement by induction over the number of borrows: the trace splits into an outbound unit
   `L B> 0 (10)^(y+1) R -> L 1 1 1 (01)^y B> R`, a turn at the first bit 1, and a return unit
   `L 1 1 1 (01)^y D> 1 R -> L D> 1 0 1 1 (01)^y R` (both found by `symtm`); a tape function over a list of block
   lengths makes the induction.
2. Decode the rewrite when the borrow meets an empty block and the full borrow into the tail (examples above; the
   events come from `c/events.c MACHINE N 10 1 1`), as a map on (x; bits; blocks).
3. With the map, halting is "two adjacent blocks empty with zero bits around them"; iterate the map (much faster than
   the machine) and look for a heuristic: block j pays 2^j copies per right-end event, so the time to exhaustion of
   each block is a ratio of its length to 2^j, and a halt needs two such clocks to run out together.
4. A closed-language proof cannot forget the block lengths (perturbation test); any proof has to carry the arithmetic.
