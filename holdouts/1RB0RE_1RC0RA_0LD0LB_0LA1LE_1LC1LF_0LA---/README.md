# 1RB0RE_1RC0RA_0LD0LB_0LA1LE_1LC1LF_0LA---

bbchallenge id 8754. A six-state holdout of BB(6). **Open.** It is a sweeping counter over a list of blocks `(10)^m`. Each pass changes the tape only at a counter and at one frontier, by an exact pass map with exact step counts. When the counter runs out, the first block becomes the next counter, and blocks grow by a factor 4 each time the frontier passes them.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RE |
| B | 1RC | 0RA |
| C | 0LD | 0LB |
| D | 0LA | 1LE |
| E | 1LC | 1LF |
| F | 0LA | --- |

## What it does

Sample the run each time the head arrives at the left end in state A, and write `a` for the word `10`. The tape
is then `a 0 a^c 1^k1 a^n1 1^k2 a^n2 ... 1^kr a^nr`: a counter c and a list of pairs (k, n), k = 1, 2 or 3. A
normal list alternates separators (2,1) and blocks (1,m) and ends with the marker (2,1). The first place where
this alternation breaks is the **frontier**. One pass (left end to left end) changes the tape only at the counter
and at the frontier. The whole run is this **pass map** (`py/passes.py`). Below, F and M are the number of blocks
left of the frontier and the sum of their m.

| rule | before | after | steps |
|---|---|---|---|
| a, counter phase | c, (1,q) first, q >= 1 | c+3, (1,q-1) | 6c+36 |
| b, counter ends | c, (3,1)(1,m) first | c-1, (2,1)(1,4)(1,m-1) | 6c+54 |
| c, block grows | (1,p)(1,q), q >= 1 | (1,p+4)(1,q-1) | 6c+20F+6M+6p+56 |
| d, next block | (1,p)(3,1)(1,m) | (1,p)(2,1)(1,4)(1,m-1) | 6c+20F+6M+6p+74 |
| e, block at end | (1,p)(3,1) END | (1,p)(2,1)(1,2)(2,1) END | 6c+20F+6M+6p+70 |
| g, timer | (2,1) END, no frontier | (2,1)(1,1)(2,1) END | 6c+20F+6M+44 |
| f, carry | (2,q)(2,1)(1,m), q != 1 | (2,1)(1,q+3)(2,m) | 6c+20F+6M+8q+48 |
| f1, carry G(1) | (2,1)(2,1)(1,m) after a block | (2,1)(1,4)(2,m) | 6c+20F+6M+56 |
| h, i, f2 | rare cases at the end of the list | see `py/passes.py` | |

The counter c goes down by one in every pass except in rule a. A pair (1,0) merges into the next pair. When c
reaches -1 the next two passes are a **rebuild**. The first applies the frontier rule as if c were 0, in 4 steps
fewer. The second, 70 steps long, turns the first block into a new counter phase: c = 5 and (1, m1-2).

So the behaviour is: in each round the counter phase (rule a) turns the first block m1 into c of about 3*m1.
Then every pass moves the frontier on. A block (1,p) grows by 4 per pass while it eats the next block (rule c), so
a block m becomes a block 4m. When the frontier reaches the end of the list, timer passes add blocks of 1 at the
right (rule g) until c runs out. If c runs out in the middle of the list, the frontier freezes there, and the
rebuild leaves it in the list as a bare block X = (1,x) or a carry Y = (2,q). The block sizes 4^k+2 (66, 258,
1026, 4098, 16386) come from repeated rule c.

**Checked against the machine.** `python3 py/passes.py check SAMPLES` replays every pass from step 440 to step
1,099,824,330 (16,064 passes) and agrees with the plain machine on the tape and on the step count (`c/leftend.c`
prints the samples). The rare rules h, i and f2 are checked on the tape only.

**Accelerated simulator.** `py/accsim.py` keeps runs of equal blocks as single items and applies many passes of one
rule at once, with exact step counts. Its state agrees with the plain machine, on both tape and step, at every
batch end up to step 2,782,338,426 (72 checks) and in windows of plain simulation at steps 4.89*10^10 and 5.29*10^10. It reaches step 79,277,382,450 after 164,003 passes and 13 rebuilds. There it stops at a case it
does not cover yet: a carry G(4) meets a frozen carry Y(1). It does not reach a halt.

| rebuild | step | new counter block m1 |
|---|---|---|
| 1-9 | 440 ... 2,782,338,426 | 6, 10, 18, 66, 130, 258, 1026, 4098, 16386 |
| 10 | 48,820,008,868 | 258 |

## Rules proved in Lean

`lean/Rules.lean` is generated by `lean/rules.py` (symbolic runs, `tools/py/bbtools/symtm.py`). Every rule holds for
all values of its variables and all tapes L, R:

| theorem | from | to | meaning |
|---|---|---|---|
| `left_end` | `0^inf A> 1 0 0 (10)^n+2 1 1 R` | `0^inf (10)^n+5 1 0 0 E> R` | The bounce at the left end. |
| `left_block` | `L 1 (10)^n+5 D> 1 0 1 R` | `L D> 1 0 1 (01)^n+2 1 1 0 1 1 0 1 R` | A leftward crossing of a block. |
| `right_end` | `L 1 (10)^n+5 1 B> 0 0^inf` | `L D> 1 0 1 (01)^n+4 1 1 0 0^inf` | The bounce at the right end. |
| `pass_start` | `0^inf A> 1 0 0 R` | `0^inf 1 0 1 0 1 0 A> 0 R` | A pass leaves the left end. |
| `pass_right` | `L A> 0 (10)^n 1 1 1 0 1 R` | `L (10)^n 1 1 0 1 0 A> 0 R` | Going right over one block, 2n+13 steps. |
| `pass_front` | `L A> 0 (10)^p+3 1 (10)^q+3 1 1 1 0 R` | `L A> 1 0 (01)^p+3 0 1 (10)^q+2 1 1 1 0 R` | The turn at the frontier, 6p+24 steps. |
| `pass_sep` | `L 1 1 0 1 0 A> 1 0 R` | `L D> 1 0 1 0 1 0 1 R` | Going left over a separator. |
| `pass_left` | `L (10)^n+3 D> 1 0 1 0 1 0 1 R` | `L A> 1 0 (01)^n 1 1 0 1 1 0 1 0 1 0 1 R` | Going left over one block. |
| `pass_end` | `0^inf 1 0 1 0 1 0 A> 1 0 R` | `0^inf A> 1 0 0 1 0 1 0 1 R` | The pass returns to the left end. |

`lean/Pass.lean` (written by hand) chains these by induction over the list of blocks. With `S = 1 1 1 0 1`,
`blk n = (10)^(n+3) S` and `front p q = (10)^(p+3) 1 (10)^(q+3) 1 1 1 0`, the theorem `pass` says that for
every c, p, q, every list of blocks ms and every tape R

    0^inf A> 1 0 0 blk (c+1) blk m1 ... blk mk front p (q+1) R   reaches
    0^inf A> 1 0 0 blk c     blk m1 ... blk mk front (p+4) q R.

This is rule c (block grows) for every list, in the machine's own tape form. The theorem gives the steps only as
some number s. The simulation count is 6c+20F+6M+6p+56.

## Status

Open. The pass map is known exactly (tape and steps) wherever the run has gone so far. It is checked against the
machine pass by pass to 1.1*10^9 steps, and by the accelerated simulator, checked in windows, to 7.9*10^10 steps.
Lean proves rule c for every list of blocks (`pass`), plus the shift rules. The other pass rules are checked by
simulation only. No halt has been seen. Halting needs state F to read a 1, and none of the pass rules found so far does that.

## For later

- Since this page was written, `accsim.py` got the rule for a carry G(q) meeting a frozen carry Y(1) (step
  79,277,382,450; its step constant is fitted on that one sample and agrees with the plain machine in a window up to
  step 79,284,502,668). With it the simulator goes on to step 170,030,338,894 (16 rebuilds, no halt), where it stops
  at the next uncovered case (rule f2 with a bare block further right). The stretch after 7.93*10^10 is not checked
  against the plain machine.
- Prove rules a, b, d, e, f and g in Lean in the same way as `pass`. Each one is a different turn lemma at the
  frontier, and the `rsweep` and `lsweep` inductions of `Pass.lean` can be reused. Then the rebuild.
- With all rules proved, the open question is a statement about the list dynamics. No pass rule writes the halting
  pattern, so a proof of non-halting would need the set of reachable lists closed under the map. The new cases
  (X, Y) appear only after rebuilds that freeze the frontier, so the set of item kinds has to be shown finite.
