After k rounds the word begins with about k/2 doublers, so about 2k/2 visits reach the blocks behind them, and round 161,211 could never be replayed visit by visit. But all the visits that reach one block are alike, so it is enough to know how many there are. VisitLaw.lean proves what n visits in a row do (VS n s s', for every n):

  • 000 r under n visits ends as the digit n mod 2, and ⌊n/2⌋ visits reach r (law_Z);
  • 100 r ends as the digit (n + 1) mod 2, and ⌈n/2⌉ visits reach r (law_H); the same for 110 r when n ≥ 1 (law_G);
  • 1010 r stays 1010, and 2n visits reach r (vs_L, with the guard on r);
  • a 0 where a block should start takes the first visit to become a 1 (law_0);
  • and the same laws for "one of the first n visits halts" (hvs_Z, hvs_H, hvs_G, hvs_L, hvs_X).

The pass. The checker (scan in VisitCheck.lean) carries the number of visits through the word block by block, in one pass, using these laws: through a doubler n visits become 2n; through a digit n becomes n/2, rounded down or up depending on the digit, and the digit is set to the parity of n; when the count reaches 0 the rest of the word is copied unchanged. The counts are huge but simple: each is a power of two minus a small number, so the checker keeps a count as a pair e, c standing for 2e − c, and doubling is e + 1, halving is e − 1. scan_sound proves that what the pass returns is what 2e − c visits of the rewriting system make; hscan_sound proves the same for its search for a halting visit (sound, not complete: when it is unsure it answers no).
