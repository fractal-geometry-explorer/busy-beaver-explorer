# 1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA0RF_1RC---

bbchallenge id 13768. One of the six-state holdouts whose halting from blank tape is open. One of five machines
sharing states A–E, `1RB0RC_1LC0RD_0LD0LC_1RE0LA_0RA?RF_F---` (E1 = 0RF with F0 = 1RC or 1RD; E1 = 1RF with F0 = 0LD,

|---|---|---|
| A | 1RB | 0RC |
| B | 1LC | 0RD |
| C | 0LD | 0LC |
| D | 1RE | 0LA |

## What it does

The tape is made of `a = 10` and `b = 1000`: moving right the head turns each `b` into `aa`, moving left `aa` back
into `b` (`a_cross`, `b_cross`, `d_cross`, `e_cross`, `c_halve`, `c_sep`). Between the blocks sit gadgets
`g0 = 1001`, `g1 = 1001100`, `g2 = 100110`, `g3 = 10011`, `g4 = 10010`, `s = 0`.

Each time the head returns to the left end in state D the tape is `b^k G1 b^y1 G2 b^y2 ... Gn` (in b-form). One round
later `k` has gained one `b` and `G1` has advanced in the cycle `g0 → g1 → g2 → g3 → g4 → g0`:

- `g0 → g1`: the block after it loses one `b` (`round_g0`);
- `g1 → g2`, `g2 → g3`: nothing else (`round_g1`, `round_g2`);
- `g4 → g0`: one `b` moves from the block after to the block before (`round_g4`);
- `s → g0`: the block before loses one `b` (`carry_s`);
- `g3 → g4`: carry, the next gadget advances by the same rules (`carry_g0`, `carry_g1`, `carry_g2`, `carry_g4`,
  `carry_s`).

So it is an odometer of base-5 wheels, wheel `i+1` turning once per five turns of wheel `i`, each full turn draining
two `b` from the block on its right. A carry off the last gadget is a *reset* (`reset1`, `reset2`): a sweep to the
right end and back turns every gadget into `s`, adds a `b` to every block but the first, and starts a new wheel
`b g1` at the left. These resets are the full sweeps of the run (the head at the right end in A, tape
`a^x1 1 a^x2 1 ...`).

The irregular part: a block can run empty, and then the gadgets on either side meet and merge (into short-lived
gadgets `100`, `1`, `10`, ...; blocks merge, or a new wheel is born). In 1.5·10^9 steps
36,648 rounds are regular and 50 irregular (`py/odometer.py`).

**State F**, the only one that can halt (F1), is entered from E reading a 1, after D wrote a 1 on a 0: a halt needs
`D>0 1 1`. F is entered only 3 times (steps 49,249, 18,721,952 and 18,863,922), when two `g4` meet across an empty block (`collide`;
then a new level `b g1` is born at the left and the pair becomes the gadget `X = 100` (later a carry into `X` acts like a carry into the end of the tape)) or at a gadget left by such an event, and it always
reads a 0. This is where the five machines differ; the left part of the tape regrows the same way after each reset, so
their first blocks agree for a long time (for example `187496` at about 7·10^10 steps for four of them).

## Closed set of shapes: does not close

The obvious route to a proof of non-halting is a closed set of tape shapes: rows of gadgets with blocks of symbolic
length, closed under rounds, with no halt. `py/shapes.py` runs every round symbolically over prefixes of up to three
gadgets (blocks empty or of any length >= 1, split when the run needs it, prefix extended when the run reaches the
unknown rest).

- **The alphabet closes.** Besides g0..g4 and s, the irregular events only produce `1`, `10`, `100`, `1001101`,
  `10011010`, `10011011`, `100110110`, `1001101100` (no new atoms at depths 2 and 3), and every irregular gadget
  seen in 2·10^10 steps of the run splits into these.
- **The set does not close.** At depth 3, 33 prefixes halt and 8,026 still need a longer prefix
  (carry chains through `g3`, runs of empty blocks).
- **The escape is the trap `101`** (`trap`, `trap_halts`, kernel): with the head in D on `b^(k+1) 1 0 1 1` the
  machine halts after 4k+15 steps, whatever follows. `1 0 1 1` is the transient gadget `10` (made when a carry turns
  g3 into g4 next to a g2 across an empty block, `g4 0 g2 → 10`) meeting the transient gadget `1`, also left by a
  collision, across an empty block: two blocks running empty at the same time. From `b^6 g1 b^2 g0` the run reaches `g4 0 g2 0 g0` (two empty blocks side by side) at step 1,793,340; the collision makes `10 0 g0`, later the stretch `101`, and the machine halts at step 1,970,087.
- **Shapes alone cannot work** (`witness_halts`, kernel, by evaluation): from `b^6 g4 b^5 g4 b^2 g0 b^2 g0`, only regular gadgets and
  every block of length >= 2, the machine halts after 3,722 steps. Without s: the same tape.
  (`py/witness_search.py` finds such tapes.)

In 2·10^10 steps: 130,729 regular rounds, 87 irregular; the transient gadgets occur, also next to another gadget across an empty block (`g3 0 1`, `g4 0 10`), but never as `10 0 1`.

So a decision needs an invariant on the block lengths: for example, that `10` never meets `1` across an empty
block in the run from blank tape. A shape-level (CTL-style) argument cannot capture that. The window CTL
of `tools/py/bbtools/ctl.py`, tried on `..._0RA0RF_1RC---`, also fails: with windows of 4, 6 and 8 cells the set it
finds allows a halt, and with 10 cells it finds no closed set within its round limit.

Last full sweep before 10^11 steps: step 65,190,407,297, blocks `187496 63060 2562 32478 22342 6336 2200 15`.

## Accelerated run

`py/accsim.py` simulates at the level of the list `[s0, n0, s1, n1, ...]` of stretches and block lengths, sampled
whenever the head returns to the left end in D on `1000`. Each round is a symtm run on a prefix of the list, with the
blocks symbolic (exact below 2, `v+2` otherwise, raised when the run needs it) and the rest of the tape an unknown
context. The result, a new prefix and an exact step count, both affine in the block lengths, is cached by shape. Rounds
whose result depends on small values are recomputed with exact blocks. So the regular rounds are not assumed; every
round is the machine's own behaviour.

- **Validation:** `accsim.py validate 20000000000` compares every round with `c/odo.c` on the plain machine: 130,816
  rounds up to step 19,999,839,554, the same tape and the same step count every time.
- **Run:** `accsim.py run` reached step **352,272,295,345,818,181** (3.523·10^17; 446,912,823 rounds in 40 minutes on one core, 290
  cached shapes) with no halt.
- **At the end:** 13 gadgets (at most 16 on the way), first block 73,588,199.
- **Resume:** the final state is in `py/accsim_ckpt.json`; run `accsim.py run STEPS SECONDS LOG py/accsim_ckpt.json`.
- **Near misses:** 44 kinds of irregular stretch occurred. Two blocks were empty side by side in
  52 rounds (first at step 186,325). The atom `10` stood before an empty block in 0 rounds, so
  the trap `10 0 1` never formed.

## For later

- Find an invariant on the block lengths that keeps two neighbouring blocks from running empty together (so that `10`
  never meets `1` across an empty block), or a reason why they do: the odometer drains a block by about 2 per
  turn of the wheel on its left, so these are relations between counters at different levels.
- Speed up `accsim.py` with closed forms for whole wheel turns (the regular rounds are translations of the
  block lengths), to go from 10^17 to 10^30 and beyond.
