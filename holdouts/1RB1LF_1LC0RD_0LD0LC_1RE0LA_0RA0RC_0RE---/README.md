bbchallenge id 69016. One of the six-state holdouts whose halting from blank tape is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LF |
| B | 1LC | 0RD |
| C | 0LD | 0LC |
| D | 1RE | 0LA |
| E | 0RA | 0RC |
| F | 0RE | --- |

## What it does

Family: **base-5 counter of gadgets + growing block.**

Write `a` for `10` and `b` for `1000` (a `b` takes the cells of two `a`s). The run alternates between two
encodings of the same list of blocks: during a round the blocks are runs of `b`s with a *gadget* between
neighbours; at the end of a round the head reaches the right end of the tape and the list is written with `a`s.

**The counter** (Lean, `lean/Counter.lean`). In the `b` encoding the tape is

    1 E> 0 0 b^n G1 b^m1 G2 b^m2 G3 ...

with the head at the left end. A gadget is a digit in base 5, one of five words:
`G0 = 10010`, `G1 = 1001`, `G2 = 1001100`, `G3 = 100110`, `G4 = 10011` (a gadget never ticked yet is a single `0`).
One *pass* (left end to the first gadget and back, `10n + 69` steps) ticks `G1`:

| tick | blocks |
|---|---|
| `G0 -> G1` | one `b` moves from the block right of the gadget to the block left of it |
| `G1 -> G2` | the same |
| `G2 -> G3`, `G3 -> G4` | nothing moves |
| `G4 -> G0` | carry: the pass goes on to the next gadget, which ticks the same way |

and the left block gains one `b` per pass. So the gadgets count the passes in base 5, and the blocks pay for the
ticks: block j (between gadgets j and j+1) gives two `b`s per cycle of gadget j and receives two per cycle of
gadget j+1. Lean proves the four passes (`pass_0` ... `pass_3`) and the carries into a second gadget in each phase
(`carry_0` ... `carry_3`) or into a fresh one (`carry_fresh`), for all block lengths >= 3. (A carry through any
number of `G4`s in a row also runs through `bbtools.seqtm` symbolically, but those Lean proofs time out, so they are
not included.) When every gadget carries, the head runs to the right end of the tape: a round ends.

**Round ends** (computed, `py/rounds.py`). At a round end the tape reads `a^x1 1 a^x2 1 ... a^xk 1 a^L` and
something; the last block `L` changes rarely (17, then 101, then 311 since step 4.2·10^9). From one round end to
the next, the block j places left of `L` loses `18·5^(j-1)` `a`s (the radix-5 weights; off by 2 at most next to a
rebuilt block), while it can pay; a block that cannot pay is rebuilt larger (or merged with its neighbours, so the
list gets shorter), and a new leftmost block appears of length `12·5^m - 4` (37,496,
187,496, 937,496, 4,687,496). The last round ends found:

| step | blocks x1 ... xk, then L |
|---|---|
| 4,630,936,542,285 | 983516, 915380, 559088, 22762, 14928, 6748, 18314, 311 |
| 5,953,766,898,087 | 937496, 702266, 859130, 547838, 20512, 14478, 6658, 18296, 311 |
| 19,165,583,940,505 | 3437476, 421018, 802880, 536588, 18262, 14028, 6568, 18278, 311 |
| 47,572,742,616,643 | 4687496, 2031226, 139768, 746630, 525338, 16012, 13578, 6478, 18260, 311 |

(read from the right: 18314 -> 18296 -> 18278 -> 18260 loses 18 each time, 6748 -> 6658 -> 6568 -> 6478 loses 90,
14928 -> 14478 -> 14028 -> 13578 loses 450, 22762 -> 20512 -> 18262 loses 2250, and so on.)

**Halting.** The machine stops on F reading 1. F is entered only from A on a 1 (`1LF`, moving left), so a halt
needs `1 A> 1`: the head in A on a 1 with a 1 on its left. In the run F always lands on a 0 (`1 F> 0`). The steady
counter never does it (the passes above are halt-free for all lengths); a halt would have to come from a block
running out, or from the re-encoding at a round end.

**Far runs.** `py/accel.py` (the same exact accelerated simulator as for 1RB1RC_1LC0RC_..., here with 4-cell
blocks and records at every left-to-right turn) agrees with the plain C simulator on the whole tape (`c/tapehash.c`)
at 10^7, 10^9, 5·10^9 and 10^10 steps, and runs 2.4·10^14 steps in 15 minutes without a halt. It jumps over the
innermost period only (five passes); the nested counter keeps it from going much further.

## Status

Open. Lean, all by the kernel:

* `lean/Blank.lean` (generated): the halting configurations (`step_none_iff`); no halt in 10,000 steps by the
  kernel, in 10,000,000 by `native_decide`.
* `lean/Rules.lean` (generated by `py/rules.py`): sixteen shift rules over the words `10`, `01`, `1000` and their
  rotations (`0001`, `0010`, `0100`, `0101`, `1010`): for instance `cross_A_r_10` (A runs right over `(10)^n`
  leaving `(01)^n`), for all `n` and any tapes around.
* `lean/Counter.lean` (generated by `py/counter.py`): the passes and carries of the base-5 counter above.

Computed: no halt in 2.4·10^14 steps (`py/accel.py`, checked against C up to 10^10); the round ends to 4.8·10^13
steps (`py/rounds.py`). Trusted: no halt in 10^9 steps (`tools/c/triage.c`).

## For later

Where this stopped: the counter is proved pass by pass; the round ends follow the radix-5 decrements above.
Next: (1) prove the carry through any number of `G4`s (the `seqtm` proof exists but needs a lighter Lean
statement, e.g. split per element, or more heartbeats than 4·10^6); (2) derive the round-end step: how the `b`
list with gadgets is turned into the `a` list and back, and what happens when a block cannot pay (the
"rebuilt" cases: 10784 -> 36244 and 2496 -> 59996 at the fifth block; 48746, 25082, 72626, 937496 -> 559088,
915380, 983516 at step 4.6·10^12); (3) with that, write the map from one round
end to the next as arithmetic on (x1, ..., xk, L) and iterate it instead of the machine, which takes about 3x
longer per round; (4) a second-level acceleration (jump over whole cycles of gadget 2, 3, ... with the closed form
of the counter) would let `py/accel.py` reach far more rounds.
