# 1RB1RF_1LC1LF_0RE1LD_0LB1LD_---1RC_1RA0RD

bbchallenge id 149707. One of the six-state holdouts whose halting from blank tape is open. Its tape is two counters, and pass to pass it runs a Collatz-like map that halts only on an exact arithmetic coincidence.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RF |
| B | 1LC | 1LF |
| C | 0RE | 1LD |
| D | 0LB | 1LD |
| E | --- | 1RC |
| F | 1RA | 0RD |

## Status

Open, and reduced to the phase map. Lean (`lean/Phases.lean`, kernel): every case of the phase map for all parameters (`next`, `next_sound`), and the machine halts from blank tape iff iterating `next` from `PS 0 2` reaches `PS a c` with c <= 1 (`halts_iff`); by `native_decide`, the first 10^8 phases (20,000,581 pass starts) do not (`no_halt_phases`). Lean (`lean/Blank.lean`): the halting configurations (`step_none_iff`), no halt in 10,000 steps by the kernel, in 10,000,000 by `native_decide`. Lean (`lean/Pass.lean`, kernel, the first version): the plain pass `(a, b) -> (2a+2, b-2a-2)` for all a >= 2, b >= 2a+3 and any tape after the block (`pass_plain`), and the halt from `B>0 0 (10)^n` (`zip_halts`). C (`tools/c/tmrun.c` via `py/passmap.py check`): no halt in 10,000,000,000 steps, and every pass in them follows the pass map. The map (`py/passmap.py iterate`, and `lean` for the copy of Lean's `next`): no halt in 10^8 passes.

## What it does

**Pass starts.** Each time state B is at the left end of the tape (a *pass start*) the tape is

    B> 0 0 (10)^a 1^b T 0^inf          T = 10 (t = True) or empty (t = False)

checked at all 3,096 pass starts in the first 10^10 steps (`py/passmap.py check`). The first ones are (0,2,F),
(0,4,T), (2,2,T), (0,12,F), ...; at step 974,240,225 it is a = 6, b = 2885, t = T.

**A pass.** State A eats the `10`s on the left one at a time. With `r + 1` of them left, a block `1^l` (l = 4 at
first) left of the head and `1^s` right of it, one round is

    (10)^(r+1) (11)^(2k+2) A> 1^(s+3)   ->   (10)^r (11)^(2k+4) A> 1^(s+1)     in 12k + 20 steps

(for all r, k, s; `cycle` in `lean/Rules.lean`, generated by `lean/rules.py` with `bbtools.symtm`). When the `10`s run out the block `1^l` becomes
the new `(10)^(l/2+2)` and b becomes s - 4. When the right block runs out first, the head rebounds off the right end:
the left block moves right as the new right block (`s = l + 1`, two more `10`s used up) and the loop goes on;
the even cases differ a little (`s = l + 8` and the trailing `10` is eaten, or `s = l + 1` and one is written).
`pass_map` in `py/passmap.py` is this loop. In the plain case it is `(a, b) -> (2a + 2, b - 2a - 2)`; one rebound
gives `(2a - b - 1, 3b + 4 - 2a)`. It reproduces every one of the 3,095 passes in the first 10^10 steps. Width
`2a + b` grows by 2 per pass (by 3 to 6 at rare special passes), so the run is a doubling-and-folding map on `a`
relative to the width, as erratic as binary digits; time per pass grows like the square of the width.

**Halting.** E0 is the only halting transition and E is entered only from C0; C and E zip right over `0 1 0 1...`
(C on 0s, E on 1s) and the machine halts when E reads a 0. In 10^9 steps B reads 0 only at or next to the tape ends, and
only the left end starts a zipper: it crosses the `10`s and stops at the 1s of `1^b`. So the machine halts iff a pass
ends with b = 0 and t = True: from `B> 0 0 (10)^n 0^inf` it halts after 2n + 5 steps (checked for n = 0..4).
(b = 0 with t = False gives the pass start `(0, 2a, True)` instead; it happened once, in the first pass.)

**Why it has not.** b has the parity of the width; it changes parity only at special passes (a pass whose end
would give b = -1 gives `(0, 2a', True)` instead). Odd stretches cannot halt. Even stretches are short chains
of doublings `(a, b) -> (2a + 2, b - 2a - 2)`, which reach b = 0 only if b = 2a + 2 exactly. Iterating the map
for 10^8 passes (width 2*10^8, far beyond what the machine can reach by simulation): 166 passes end with an even b,
23 parity changes, the smallest b at a pass end was 2 (once), no halt. Heuristically the chance of a halt in the
future is the sum of about 1/width over the even passes, which is small and grows only like a slowly converging
sum; a proof would need to control a Collatz-like coincidence.

## The phase map in Lean

`lean/Phases.lean` works with two kinds of configuration, both with blank tape outside:

    PS a c  =  B> 0 0 (10)^a 1^c            (a pass start; c = b + t in the notation above)
    Q R m c =  (10)^R (11)^m A> 1^c         (inside a pass)

and `next` sends each to the next one the machine reaches (rounds taken all at once):

    PS a 0, PS a 1                -> halt (C and E zip right; `pc_halt0`, `pc_halt1`)
    PS (a+1) (c+2)                -> Q a 2 (c+2)
    PS 0 2 -> PS 0 5,             PS 0 (c+3) -> PS 2 (c+1)
    Q (R+j) (m+2) (c+2j+1)        -> Q R (m+2+2j) (c+1)          (j rounds, `q_rounds`)
    Q 0 (m+2) (c+5)               -> PS (m+4) (c+1)              (end of a pass)
    Q 0 (m+2) 1, 2, 3, 4          -> PS 0 (2m+8), (2m+6), (2m+11), (2m+9)
    Q 1 (m+2) 1, 2                -> PS 2 (2m+6), (2m+4)         (rebounds)
    Q (R+2) (m+2) 1, 2            -> Q R 2 (2m+8), (2m+6)        (rebounds)

Each case is one symbolic run in `lean/Pieces.lean` (generated by `lean/pieces.py` with `bbtools.symtm`), glued to
`PS`/`Q` by the tactic `tape_eq` of `lean/Norm.lean`, which rewrites both tapes into one normal form and leaves the
repeat counts to `omega`. `next_sound` proves every case, `next_none` that on reachable phases (`m >= 2`, `c >= 1`)
`next` fails only at `PS a 0` and `PS a 1`, and `halts_iff` that the machine halts from blank tape iff some iterate
of `next` from `PS 0 2` (reached after 4 steps, `init_ps`) is such a `PS a c`. `no_halt_phases` checks the first
10^8 phases by `native_decide` (about 100 s). `py/passmap.py lean` iterates a Python copy of `next` and compares it
with `pass_map` at 10^8 pass starts (all agree).

## Later

- Is there a closed form? In the plain case x = a + 2 doubles; the rebounds look like a reflection with modulus
  near the width. A closed form would make the map's orbit a statement about binary digits.
