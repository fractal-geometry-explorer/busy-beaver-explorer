# 1RB0RD_1RC0LF_0LA0RB_1RE---_1LB1RA_0LE0LF

bbchallenge id 75248, a BB(6) holdout (group G06). Family: **bouncer with a mixed-radix odometer at the fixed end**.
Open. The community tracker files it as "a regular bouncer with an irregular edge that does not repeat"; this folder
makes that exact.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0RD |
| B | 1RC | 0LF |
| C | 0LA | 0RB |
| D | 1RE | --- |
| E | 1LB | 1RA |
| F | 0LE | 0LF |

## What it does

Cell 0 is the start cell. From step 2,035 on the tape is

    0^inf (1001111)^n 0100 111111 a b | R 0^inf        (the cut `|` is between cells 12 and 13)

a wall of n seven-cell words, twelve nearly constant cells, and a data word R. `Z(n, R)` is this tape with
`a b = 0 1` and the head on the first cell of R in state E.

One **cycle**, from Z(n, R):

1. The head works on R and on cells 5..12 only, for a few hundred steps. It crosses the cut a few times
   (bounces of 1 to 5 steps that only change `a b`).
2. It comes back onto cell 12 in state B or F, reading 1, with a 1 on cell 11.
3. It then sweeps the wall seven times and returns to the cut: `168 (n - 1) + 575` steps later the configuration is
   Z(n + 3, R'), where R' is the data as step 1 left it. The seven sweeps never look at the data.

Step 3 is proved in Lean for every n and every R (`cycle_B`, `cycle_F`). Steps 1 and 2 are what `c/edge.c` checks
on every cycle it runs (it stops if the head reaches cell 4 in any other way; it never did), not proved.

So the wall only counts. As long as steps 1 and 2 hold, the machine halts from blank tape iff the reduced machine
does: the plain machine on R with the jump of step 3. First cycles:

| cycle | n | step at Z | deepest cell | data R at Z |
|---|---|---|---|---|
| 0 | 7 | 2,035 | | `01010000010010001001` |
| 1 | 10 | 3,793 | 42 | `000010010100100000010010001001` |
| 2 | 13 | 5,895 | 16 | `100110010100100000010010001001` |
| 3 | 16 | 8,707 | 47 | `01001000000010010000001001000001001` |
| 4 | 19 | 11,853 | 22 | `00000010010010010000001001000001001` |

### The data word is an odometer (measured, not proved)

* The first k cells of R, as a function of the cycle number, are exactly periodic (cycles 50,000 to 300,000, every
  k up to 120): period 5 for k <= 7, then 15 (k <= 18), 30 (k <= 33), 60, 300, 900 (k <= 73), 2,700, 13,500, 40,500.
  Each new stretch multiplies the period by 2, 3 or 5.
* The deepest cell of a cycle: 16 in exactly 1 cycle of 5; each of 22, 25, 28, 31 in 1 of 15; each of 33, 34, 35,
  40 in 1 of 30; 46 in 11 of 60; 53 in 13 of 300; ... (10^7 cycles). The pattern of the first wheel (1/5, then
  4 x 1/15, 4 x 1/30, 11/60) comes back deeper in the data at cells 120..156 and 163..
* The data length grows like the logarithm of the cycle number: 136 cells at cycle 1,297, 261 at 1.3e6, 327 at
  6.0e6, 423 at 5.6e8; about 42 cells per factor 10.

What makes it hard: the wheels are not alike. The periods multiply by 5, 3, 2, 2, 5, 3, 3, 5, 3, ... and there is
no rule yet for the period of the wheel made when the far end is reached, so no finite description of the data
words that can occur.

### Where it could halt

Only D reading 1 halts (`step_none_iff`). D is entered only by A reading 1 (`0RD`), so a halt needs `A> 1 1` with
A arriving from the left, i.e. E reading `1 1 1`, i.e. a pattern `A> 1 0 (1 1 0)^k 1 1 1`. In the wall cycle this
does not happen (Lean), so a halt can only come from the data word.

## Status

Open. The reduced machine ran 750,000,000 cycles = 1.4e20 steps of the real machine without halting
(`c/edge.c`; the wall then has 2,250,000,007 words, the data 423 cells). The tracker reports 1e17 steps by others.

## Proved in Lean

- `lean/Cycle.lean` (hand-written): `Z`, `Exit`; `blank_reaches_Z` (blank tape reaches Z(7, 01010000010010001001)
  in 2,035 steps); `cycle_B`, `cycle_F`: `steps (168 n + 575) (Exit q (n+1) R) = some (Z (n+4) R)` for q = B, F.
- `lean/Rules.lean` (generated by `lean/rules.py`): `wall_cycle_B`, `wall_cycle_F`, `reach_Z` (the same, as the
  symbolic run writes the tapes), and the five shift rules they use: `c_right` (C right across `(0100000)^n`,
  17 steps a word), `f_left` (F left across `(1111100)^n`, 7 steps a word), `e_left`, `b_right`, `e_right`.
- `lean/Blank.lean` (generated): `step_none_iff`, no halt in the first 10^7 steps.

## Files

- `c/edge.c`: the reduced machine (data word step by step, the wall cycle as one jump), exact step counts.
- `py/check_edge.py`: compares `edge.c` with the plain machine on the first 3e6 steps and measures the prefix
  periods.

## For later

- Find the wheels: cut R into digits so that one visit is "add one with carry" and read off each digit's cycle.
  The first digit is cells 13..19 (period 5); the head turns at cell 16 when it does not carry.
- Find what decides the shape of the digit made at the far end. With that, either a closed set of data words
  (non-halting) or a concrete far-end event to search for.
