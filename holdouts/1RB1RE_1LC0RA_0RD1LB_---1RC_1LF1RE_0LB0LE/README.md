# 1RB1RE_1LC0RA_0RD1LB_---1RC_1LF1RE_0LB0LE

bbchallenge id 107208, one of the six-state holdouts; the bbchallenge wiki lists it as a "potential Cryptid,
chaotic". **Halting is reduced, in Lean, to a two-number map**: the machine halts from blank tape if and only if
the orbit of (2, 1) under the map `f` below reaches a pair (p, p + 1). That has not happened in 3,000,000 steps of
the map, and is not expected ever to happen; the question is open.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RE |
| B | 1LC | 0RA |
| C | 0RD | 1LB |
| D | --- | 1RC |
| E | 1LF | 1RE |
| F | 0LB | 0LE |

## What it does

Whenever the head is at the right end of the tape the tape is

    W p q r  =  0 (10)^p 0 (10)^q 1^r  E>0          (or X p q = 0 (10)^p 0 (10)^q A>0)

three blocks: p pairs `10`, a separator, q pairs, and r ones. The head sweeps over the whole tape (the right side
grows like the square root of the time) and the left end only moves when the left block is used up (the left side
grows like the logarithm of the time). The rules, each proved for all values in `lean/Rules.lean`:

| rule | from | to | steps |
|---|---|---|---|
| `w1`, `w1c` | W (p+1) q (r+2) | W p (q+2) (r+1) | 4q + 4r + 13 (+4) |
| `w2` | W (p+1) q 1 | X p (q+2) | 4q + 9 |
| `w3` | X (p+1) (q+2) | W (p+1) 0 (2q+6) | 4q + 18 |
| `w4` | X 0 (q+2) | W 2 0 (2q+5) | 12q + 51 |
| `w5`, `w5c` | W 0 q (r+2) | W (q+2) 0 (r+1) | 4q + 4r + 17 (+4) |
| `w6` | W 0 q 1 | halt (state D reading 0) | 4q + 12 |

One sweep moves one pair from the left block into the middle block, which gains two, and uses one 1. Reading the
tape only at the samples W p 0 r (empty middle block) gives the map

    f(p, r) = (2p + 2, r − p − 1)    if r ≥ p + 2     the left block runs out first: the middle block (2p pairs)
                                                        becomes the new left block, the tape grows on the left
              HALT                   if r = p + 1     the left block runs out with one 1 left
              (2, 4p + 1)            if r = p
              (p − r, 4r + 2)        if r < p         the ones run out first: the middle block becomes 4r + 2 ones

and from blank tape the first sample is W 2 0 1 at step 27. The orbit starts (2, 1), (1, 6), (4, 4), (2, 17),
(6, 14), (14, 7), (7, 30), (16, 22), (34, 5), (29, 22), (7, 90), ...; the 48 samples of the first 10^9 machine
steps are exactly its first 48 points (`c/samples.c | py/check_map.py`).

In words: p is a counter that doubles (plus 2) at each step while the reservoir r lasts; r pays p + 1 for each
doubling. When r can no longer pay, the machine "resets": the remainder r becomes the new left block and the
reservoir is refilled with 4r + 2 ones (or, if r was exactly p, with 4p + 1). The total p + r keeps growing, about
0.22 bits per map step.

## Does it halt?

`halts_iff_orbit` (`lean/Map.lean`, checked by the kernel, no `native_decide`): the machine halts from blank
tape **if and only if** some point of the orbit of (2, 1) is a pair (p, p + 1).

- Iterated 3,000,000 times (`py/orbit.py`), the orbit never hits; at the end p and r have about 653,000 bits.
  Each map step costs at least p machine steps, so this is far beyond 2^600000 machine steps. 63% of the steps are
  doublings, 37% resets with r < p; the case r = p occurred once (the third step).
- Heuristic: a halt can only happen at the end of a run of doublings, when the leftover r, spread over about 2p
  values, must equal p + 1 exactly. With the leftover behaving like a random number, the chance is about 1/(2p)
  per run, and p grows exponentially, so the expected number of future hits is astronomically small. The closest
  approach in 3·10^6 steps had |r − p − 1|/p ≈ 3·10^-6 (at p of 137,000 bits). A typical *cryptid*: almost surely
  it never halts, but a proof would have to control the digits of the orbit.
- No residue argument: for no modulus below 200 does the set of residue pairs reachable from (2, 1) under the three
  branches avoid the halting pairs.

## Status

Open, reduced to the map. Lean: the halting configurations (`step_none_iff`, `lean/Blank.lean`), the rules
(`lean/Rules.lean`, generated by `py/gen_rules.py` with `tools/py/bbtools/symtm.py`), the map and the reduction
(`map_step`, `blank_27`, `halts_iff_orbit`, `lean/Map.lean`), all by the kernel. Computed: the map against
10^9 machine steps, and 3·10^6 map steps without a halt.
