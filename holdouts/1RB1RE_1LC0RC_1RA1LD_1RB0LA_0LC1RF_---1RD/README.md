# 1RB1RE_1LC0RC_1RA1LD_1RB0LA_0LC1RF_---1RD

bbchallenge id 44531, one of the six-state holdouts. **Open; partly understood.** The tape holds a base-4 counter
whose digits sit between long blocks of pairs; the head runs from the left end to the lowest digit and back once
per increment. Every block is a countdown timer: it shrinks by two pairs per cycle of the digit after it. The digit
rules are proved in Lean for all block lengths. The same tape shape halts when the blocks are short (proved in
Lean for two examples), so whether the run from blank tape halts depends on the block lengths it actually
produces. No halt in 10^11 steps.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RE |
| B | 1LC | 0RC |
| C | 1RA | 1LD |
| D | 1RB | 0LA |
| E | 0LC | 1RF |
| F | --- | 1RD |

## What it does

Words: `a = 10`, `b = 1110`, and the pairs `ba = 111010`, `ab = 101110` (note `b (ab)^n = (ba)^n b`).

**At the left end** the tape reads

    0^inf D> 0 b (ba)^n1 s1 (ba)^n2 s2 ... (ba)^nk sk  [right end]

with separators `s_i` in {a, b, ab, bb}. One excursion of the head from the left end to the first separator and
back (from `D> 0` to `D> 0`) increments the first separator, proved for all block lengths and any tape on the
right (`lean/Rules.lean`, generated by `py/gen_rules.py`):

| rule | separator before | after | steps |
|---|---|---|---|
| `c1` | a | b (also ab → bb) | 18 n1 + 42 |
| `c2` | b, next block (ba)^(m+1) | ab; one pair ba moves from the right block to the left block | 18 n1 + 70 |
| `c4` | bb, next separator a | a, the left block one pair longer; the carry turns the next a into b | 18 (n1 + n2) + 88 |
| `c5` | bb, next separator b | a; the carry turns the next b into ab | 18 (n1 + n2) + 116 |

So each separator is a digit 0 → 1 → 2 → 3 → (carry) with a = 0, b = 1, ab = 2, bb = 3, and every carry, and every
1 → 2 step, also moves pairs between the neighbouring blocks. The first block grows by two pairs per cycle of
the first digit. A sample of the left-end configurations (`c/events.c | py/tokens.py`):

    D> 0 b (ba)^4 a (ba)^21 bb (ba)^59 b 1^4
    D> 0 b (ba)^4 b (ba)^21 bb (ba)^59 b 1^4
    D> 0 b (ba)^5 ab (ba)^20 bb (ba)^59 b 1^4
    D> 0 b (ba)^5 bb (ba)^20 bb (ba)^59 b 1^4
    D> 0 b (ba)^6 a (ba)^21 a (ba)^59 b 1^4         (double carry)

**At the right end** (each new cell there) the tape reads, with `P = 1^5 0`, `Q = 1^7 0`, `R = 1^8 0`,

    1^3 0 P^n1 Q P^n2 Q ... Q P^nk R C> 0

(the leftward sweep rewrites each `P` as `ba` and each `Q` as a separator). The block lengths at these moments:

|---|---|

| 126,709 | 14, 19, 59 |
| 197,452 | 57, 16, 58 |
| 303,811 | 62, 42, 12, 57 |
| 1,527,884 | 249, 27, 8, 56 |
| 3,220,711 | 254, 186, 11, 4, 55 |
| 14,755,412 | 750, 67, 139, 1, 54 |
| 18,716,097 | 318, 671, 47, 134, 54 |
| 40,853,370 | 1022, 63, 607, 31, 130, 53 |
| 111,562,311 | 1770, 580, 544, 15, 126, 52 |
| 417,334,150 | 3774, 827, 344, 485, 123, 51 |

**Every block is a timer.** Number the blocks B0 = n1 (before the first separator), B1, B2, ... and the digits
1, 2, ... (digit j sits between B(j-1) and Bj). By the rules, when digit j goes 1 → 2 one pair moves from Bj to
B(j-1), and when it wraps 3 → 0 B(j-1) gains a pair. So over one cycle of digit j+1 (4^(j+1) increments) Bj gains
2 and loses 4 (one per cycle of digit j): **Bj drops by 2 every 4^(j+1) increments** and runs out after about
Bj·4^(j+1)/2 increments, while B0 grows by 2 per cycle of the first digit. A sample from blank tape (left-end
moments with digits 1 and 2 both `a`; step, B0, B1, B2, digit 3):

    131,121    6  13  18  a
    135,647   14  11  18  ab
    142,305   22   9  17  bb
    152,177   30   7  17  a
    163,137   38   5  16  b
    176,267   46   3  16  ab
    205,764    6  56  15  b       B1 has run out: the digits are rearranged and B0 starts again

This is the same mechanism as the holdout `1RB1RE_1LC0RF_1LA0LD_1LE1LC_0RA0LC_1RA---` (a base-4 counter whose digits
carry timers). The last block loses one pair per right-end event; the number of blocks grows by one every few events, so the
right side of the tape (the number of digits) grows like the logarithm of time, and the left side (the total
length of the blocks, all swept by the head) like its square root.

**Halting.** The only halting transition is F reading 0, and F is entered only from E reading 1 (E1 → 1RF), so
the machine halts exactly when the head in state E reads `1 0`. None of the digit rules above does that.

## Does it halt?

Open, and **not by the shape of the tape alone**: tapes of exactly the left-end form above with short blocks halt.
For example (proved in Lean by evaluation, `lean/Perturbed.lean`; the step counts agree between a plain C and a
plain Python simulator):

    D> 0 b (ba)^3 a (ba)^3 a 1^4      digits 0, 0; blocks 3, 3    halts at step  81,375
    D> 0 b (ba)^7 a (ba)^4 a 1^4      digits 0, 0; blocks 7, 4    halts at step 227,426

Of all such tapes with at most two inner separators and blocks 1..4, 142 halt within 10^7 steps
(`py/perturb.py`); of 200 random ones with one to five inner separators and blocks 2..6, 8 halt within 5·10^7. In the second example above the
counter counts up normally until every digit is 3 (`(ba)^13 bb (ba)^70 bb (ba)^37 bb 11`), and the carry off the
top runs into the short end and halts (E reads `1 0`). So a nonhalting proof has to use the block lengths the run from
blank tape produces (the timers must never run out in a bad combination), as for the sister machine above.

## For later

Stopped (second pass) after: the digit rules in Lean, the timer drift of every block (from the rules and checked on
the run), the halting counter tapes, and no halt in 10^11 steps. Next: (1) the boundary cases, as before: a block
running out (n_i = 0; see 14,755,412 and 205,764), the carry passing the last separator (the right-end excursion),
the birth of a new digit at the left end (at step 118,324 the left end reads `D> 0 aa (ba)^22 a (ba)^60 a 1^4`);
prove each with `symtm.prove`; (2) with them, an accelerated simulator like `py/accel.py` of the sister machine
(closed-form bulk of increments between boundary events, using the drift above), to run far beyond 10^11 steps and
collect the catalogue of irregular patterns; (3) then look for an arithmetic invariant of the timers along the
actual run that keeps the bad combinations away.

## Status

Open. Lean: the halting configurations (`step_none_iff`), no halt in 10,000 steps by the kernel and in 10,000,000
by `native_decide` (`lean/Blank.lean`); the four digit rules for all block lengths (`lean/Rules.lean`); two tapes
of the counter form with short blocks halt (`lean/Perturbed.lean`, `native_decide`). C (`tools/c/tmrun.c`): no
halt in 10^11 steps (377,233 cells visited).

Their tables differ, and no renaming of the states turns one into the other. While they run, the states pair up as A–A, B–B, B–E, C–C, D–D, E–F, F–B (this machine first), which is not one to one. Transitions not used in these steps: this machine never uses F0 and the other never uses E0. Lean proves (`lean/Twin.lean` here, `lock_or_break`, `not_halts_of_noBreak`) that the two runs have the same tape, the same head position and paired states up to the first break, a configuration where the paired states act differently, and that neither machine halts if no break ever comes. A halt of either machine is itself a break, and the halting transitions of the two do not correspond, so the two are not known to halt together.

**Same table as the machine below, started in another state.** Renaming the states as shown turns this machine's table into the other one, the halting transition included. The other machine starts in its own state A, which is not this machine's A: its run from blank tape is the run of this table started in another state. These are different runs: in the first 10^7 steps of each, no configuration of this machine's run occurs in the other, even up to a shift of the tape. So each of these holdouts is its own halting question, and settling one does not settle another.
