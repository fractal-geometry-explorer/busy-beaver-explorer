# 1RB1RA_1LC0RC_1RE0LD_0RE0LF_1RA---_1RB1LF

bbchallenge id 141118. One of the six-state holdouts whose halting from blank tape is open (group G07, family: **counter with a halving carry wave (blocks of 1s as digits)**).

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1RA |
| B | 1LC | 0RC |
| C | 1RE | 0LD |
| D | 0RE | 0LF |
| E | 1RA | --- |
| F | 1RB | 1LF |

## What it does

**A counter whose digits are blocks of 1s, and a carry wave that runs through them.** The tape is always a list of
blocks of 1s, each followed by a single 0 (the *digits*). The right end of the tape works like the low digits of a
counter: the last four digits are `14 7 6 4` at the start of every *cycle* (state C reading the last cell, a 1):

    S0(ds) = 0^inf 1^dn 0 ... 1^d1 0 1^d0 0 1^14 0 1^7 0 1^6 0 1^4 0 C> 1 0^inf        ds = [d0, d1, ..., dn]

A cycle (5,369 steps, all inside the last five digits) adds 48 to `d0` and starts a **carry wave** on it, with
`a = d0 + 61` cells. The wave walks left one digit at a time. On a digit with `a` cells it zigzags inside the digit,
moving two cells per pass, one to each neighbour, and then:

* if `a` is **odd** (`a = 2j+3`), it leaves the digit `j+2` behind and moves to the next digit `y`, which now has
  `y + j + 1` cells: `a <- y + (a-1)/2`;
* if `a` is **even** (`a = 2j+2`), it stops: the digit becomes `j+4`, the next digit grows by `j+1`, and the head runs
  back to the right end through the digits the wave left behind, unchanged, to the next cycle start.

So every digit the wave passes is roughly halved, and the wave goes on while the values it meets are odd: a counter
in which a carry propagates through "odd" digits, like a binary counter whose digits are big numbers. Each carry adds
16 cells to the tape (the tape grows like the square root of the step count). At the **left end** of the tape there
is no next digit (`y = 0`): an odd value `a` there makes a new digit `(a-1)/2`, and the wave goes on into blank tape,
halving each time. The machine halts exactly when this reaches `a = 1`, which happens exactly when the value that the
wave brings onto the leftmost digit is `2^t - 1` (all ones in binary).

Example (the deep carry at step 2,705,689 of the run: digits written left to right, so `x = 114` is last):

    26 756 730 292 232 114 | 21 8 6 4     (cycle in progress; tape value of the wave on 114 is 127)
    a = 127 odd  -> leaves 64,  next 232 + 63 = 295
    a = 295 odd  -> leaves 148, next 292 + 147 = 439
    a = 439 odd  -> leaves 220, next 730 + 219 = 949
    a = 949 odd  -> leaves 475, next 756 + 474 = 1230
    a = 1230 even -> digit 618, next 26 + 615 = 641; run back to the right end
    641 618 475 220 148 64 | 14 7 6 4      (cycle start at step 4,073,393, as the simulation shows)

The rule is exact: checked cycle by cycle (digits and step counts) against the direct run (`py/model.py check`, 137
cycle starts up to 5·10^7 steps; the earlier search compared 1,096 cycle starts up to 3·10^9 steps), and **proved in
Lean** (below).

**Twin.** `1RB1RC_1LC0LE_1RD1RC_1LB0RA_---0LF_1RD1LF` writes the same tapes (with other states, and a different run
back to the right end); its folder has the same proof with its own rules.

## Status

**Reduced to an arithmetic iteration, proved in Lean (kernel).** `lean/Wave.lean`, theorem `halts_iff`:

    HaltsFromBlank <-> exists k, iter k = none

where `iter` iterates the digit map `next` (definitions `wave`, `waveL`, `next` in `lean/Wave.lean`) from the digits
`[26, 13, 9, 6]` of the first cycle start (step 6,517), and `none` means a wave arrived at the left end with `a = 1`.
The building blocks are generated by `py/rules.py` into `lean/Rules.lean` (each a symbolic trace checked by Lean:
the cycle, the start of the wave on a digit, one zigzag, the two ends, the sweep back across a digit, the end of the
sweep, and the halt); `lean/Wave.lean` composes them by hand (zigzags by induction, the sweep by induction on the
list of digits, the wave by induction on the digits to its left, the left end by strong induction on `a`). No
`sorry`, no axioms beyond Lean's three standard ones.

Whether `iter` ever reaches `none` is open: it asks whether the value carried onto the leftmost digit is ever of the
form `2^t - 1`. Iterating the map exactly, with step counts: `py/model.py run` (plain) finds no halt in the first
2·10^7 cycles (1.7·10^18 steps); `py/fast.py` (the effect of the lowest k digits until a wave leaves them is
memoized, like Hashlife; checked against the plain map up to 2·10^6 cycles) reaches the left end of the tape 29 times
in the first 4.6·10^24 cycles, **9·10^52 steps**, never with the value 1. The values it brings there have 7, 11, 10,
13, 17, 19, 23, 29, ..., 85 bits; most are even (0 trailing 1s), the most trailing 1s seen is 5.

**Heuristic.** If the low bits of these values behave like random bits, a value of b bits is all ones with
probability about 2^-(b-1); the values grow by a few bits from one visit of the left end to the next, so the chance
of a halt from now on is about 10^-8. The machine almost certainly never halts, but a proof would need to control
the binary digits of these values: a Collatz-like question.

Lean also has: the halting configurations and 10^7 steps (`lean/Blank.lean`), and the shift rules for crossing
blocks of 1s in both directions, for any length (`lean/Shifts.lean`, kernel). Simulation: no halt in 10^11 steps
(`tmrun`).

## Next steps

* `py/fast.py` runs out of memory after about 30 visits of the left end (the memo of the deep levels grows); a
  bounded memo would push the range further.
* Look for structure in the values carried onto the leftmost digit (they are not random: the map is deterministic);
  any invariant that keeps them away from `2^t - 1` would prove non-halting.
