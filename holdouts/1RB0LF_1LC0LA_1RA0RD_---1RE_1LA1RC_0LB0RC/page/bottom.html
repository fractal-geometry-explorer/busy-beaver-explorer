It never halts. Started on a blank tape, the machine 1RB0LF_1LC0LA_1RA0RD_---1RE_1LA1RC_0LB0RC runs for ever.

The Lean theorem is H36670.nonhalting : ¬ HaltsFromBlank in lean/Cert.lean, where HaltsFromBlank is defined from the machine's transition table in lean/Machine.lean.

What it rests on. Lean's kernel checks everything except two evaluations: start_ok (blank tape to the first template, about 148,000 symbolic moves) and ends_ok (the 62 end cases, 2.5 million moves), which are run as compiled code with native_decide because the kernel runs out of memory (over 6 GB) on runs this long. #print axioms H36670.nonhalting lists propext and Quot.sound, two standard axioms of Lean's logic, and the two native_decide axioms, one for each of those evaluations. Nothing about the run is assumed: a wrong number in the tables would only make a check answer false. native_decide

The argument in one picture

The proof is an invariant: a description of a set of tapes, called good, with three properties.

  1. The run reaches a good tape. From the blank tape, after 1,277,431 steps, the tape is good.
  2. A good tape always leads to another good tape. From any good tape the machine makes at least one step, without halting, and arrives at a good tape again.
  3. So the machine never halts. Repeating the second property forever gives runs of every length, and a machine that halts has runs of only bounded length.

What makes a tape "good" is levels 3 to 5 above: it is one of the 62 templates, a list of numbers written on the tape in a fixed pattern, with two of the numbers free (k and j) and the size condition Φ ≥ 215 on them. The second property then splits into finitely many checks, one per template and case.

Who checks the computations

Each round trip and end case becomes a computation: "does auto answer true on this input?". Who runs that computation is the one place where the proof uses two levels of trust:

decide +kernel
Lean's kernel evaluates the program itself, step by step. This is the most trusted way, and it is used for the 62 round trips and the potential tables.
native_decide
Lean compiles the program to machine code and runs it. The kernel then accepts the answer as an axiom. Used for the start (about 148,000 symbolic moves) and the 62 end cases (2.5 million in all), because the kernel ran out of memory (over 6 GB) on runs that long.

#print axioms H36670.nonhalting lists propext and Quot.sound (two standard axioms of Lean's logic) and exactly two native_decide axioms, one for start_ok and one for ends_ok. Trusting them means trusting that Lean's compiler and runtime evaluated the checker correctly on those inputs. The checker's own logic is not trusted: auto_reach is a kernel proof.

Independent checks of the two native_decide pieces Computed. These are separate from Lean and do not replace a kernel proof, but they test the same claims by a different route, plain simulation with a small C program:

  • The start: the plain simulation reaches exactly template R1_16 at (38, 163) at step 1,277,431. You can repeat it in the level 1 section; your browser does the same computation, and the one-moment panel at the top runs both the plain machine and the shift-rule simulator past it.
  • The 62 end cases: each one was run concretely at j = 0 (b with exactly 3·200 + β copies) and at j = 13, and each reached exactly the predicted template and numbers, taking up to 2.6 million steps. The level 4 section repeats this in your browser, at j = 200 on the plain machine and at any j on the shift-rule simulator.
  • The whole chain: the sequence of templates the tables predict was matched, in order, against the plain run from blank tape: 2,765 consecutive good tapes up to step 3·108, including 4 epoch ends. The one-moment panel at the top of the page repeats this match in your browser, one moment at a time.

A proof using only the kernel needs the long runs cut into pieces of a few thousand symbolic moves, with each intermediate tape written out (about 900 pieces). That work was started and is not finished.

The last lines of the proof, in words
Good c
c is template t with numbers k, j (t one of the 62), and j + 2k + pot(t) ≥ 215.
start_good
some run from the blank tape ends at a good tape (from start_ok).
good_step
from a good tape, at least one step leads to a good tape. If k ≥ 1 it uses that template's round trip, if k = 0 its end case, and the tables to show the new tape is good again.
nonhalting_of
by induction on N: for every N there is a run from blank of length at least N ending at a good tape. So runs of every length exist (not_halts_of_forall, forall_of_unbounded), and the machine does not halt.
nonhalting
¬ HaltsFromBlank, from nonhalting_of and ends_ok.
