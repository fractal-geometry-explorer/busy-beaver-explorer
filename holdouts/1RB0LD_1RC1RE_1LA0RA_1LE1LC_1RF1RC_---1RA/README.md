# 1RB0LD_1RC1RE_1LA0RA_1LE1LC_1RF1RC_---1RA

bbchallenge id 41716. One of the six-state holdouts whose halting from blank tape is open. It is a walker and
carry machine: a marker walks left and triples what it crosses, and a carry multiplies the tail by about 5/4. The
step counts of every regular sweep are exact; a hybrid simulator reached 3.2·10^12 steps without a halt.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 0LD |
| B | 1RC | 1RE |
| C | 1LA | 0RA |
| D | 1LE | 1LC |
| E | 1RF | 1RC |
| F | --- | 1RA |

## The tape

A sweep starts with the head in state C on the blank cell right of the tape, which is a sequence of groups
`1^m 0` followed by `1^t` (t = 2 except right after some carries). Almost all groups are `110`; the others are
*marked*. Write the tape as items (x, m), meaning x groups `110` then the marked group `1^m 0` (m ≠ 2), followed by
the tail of q groups `110` and `1^t`. From step 49 the tape is `1 0 (110)^2 1 1 C>`: items [(0,1)], q = 2.

## Regular sweeps: the walker (exact, Lean)

When t = 2 and the last item is (x, m) with m ≠ 1, the sweep takes **10q + 23 steps** and

| last item | becomes | tail | Lean |
|---|---|---|---|
| (x, m), m ≥ 4, m ≠ 5 | (x, m−3) | q + 2 | `walk_down` |
| (x, 5) | dissolves (its groups join the tail) | q + x + 3 | `walk_down` |
| (x, 3), x ≥ 1 | (x−1, 6) | q + 1 | `walk_left` |
| (y, m') (0, 3) | (y, m'+4) | q + 1 | `walk_merge` |

So every two sweeps the 3-mark moves one group left and the tail gains three groups. A whole phase
(x, 3) → (0, 3) is 2x sweeps, q → q + 3x, in 20qx + 30x(x−1) + 56x steps.

## Carries

When the last item is (x, 1), the sweep is a *carry*. With q = 4k + r and x ≥ k + 1 (a *shallow* carry), the
item becomes (x−k−1, 6) if r < 2 or (x−k−1, 3) if r ≥ 2; the tail becomes 5k groups (r < 2) or 5k + 3 (r ≥ 2) and
ends in `1^6` when r is odd; the sweep takes 50k² + 88k + 28 steps (r < 2) or 50k² + 138k + 82 (r ≥ 2), plus 7
when r is odd. A tail ending in `1^6` is then pushed as a new item (q, 3), leaving q = 1, in 13 steps (`push`).
When x ≤ k, or when there are no items or t is not 2, the carry reaches further left and rearranges several items;
these *deep* events are simulated cell by cell (there are few of them, 9 in the first 10^7 steps and 15 in the first 3.2·10^12, but each one costs a quadratic number of cell steps, so they limit the run: the 16th, with q = 853,485, was still running when the 25-minute run stopped).

So the run alternates multiplication by 3 (walker phases) and by about 5/4 (carries), with branches chosen by q mod 4
and by whether the item before can pay: a Collatz-like system.

## Halting

The only halting transition is F0. Regular sweeps, shallow carries and pushes never use it. Deep events can: the items
(0,1) (3,3) (1,1) with q = 10 halt after 1,164 steps. So the question is whether the orbit ever produces such a
deep event. No argument for that either way is known.

## Status and evidence

Open.

| result | level | where |
|---|---|---|
| the four walker sweeps and the push, for every tail length and every tape further left | kernel | `lean/Rules.lean` (`walk_down`, `walk_left`, `walk_merge`, `push`), generated by `py/gen_rules.py` |
| no halt in 10^4 / 10^7 steps | kernel / native | `lean/Blank.lean` |

| the hybrid simulator (unbatched) matches every sweep start of the first 3·10^7 steps of the direct run; batched and unbatched agree | trusted | `c/walker.c` |

| a deep-event configuration that halts | trusted | `py/walker.py check` |

## Reproduce

```sh
. /etc/profile.d/lean.sh && holdouts/1RB0LD_1RC1RE_1LA0RA_1LE1LC_1RF1RC_---1RA/lean/check.sh
python3 holdouts/1RB0LD_1RC1RE_1LA0RA_1LE1LC_1RF1RC_---1RA/py/gen_rules.py > holdouts/1RB0LD_1RC1RE_1LA0RA_1LE1LC_1RF1RC_---1RA/lean/Rules.lean
python3 holdouts/1RB0LD_1RC1RE_1LA0RA_1LE1LC_1RF1RC_---1RA/py/walker.py check
gcc -O2 -o walker holdouts/1RB0LD_1RC1RE_1LA0RA_1LE1LC_1RF1RC_---1RA/c/walker.c && ./walker 1e12 1
```

## For later

1. The deep events are the only unmodelled sweeps and the cell-by-cell part dominates the run time; derive closed
   forms for the common deep patterns (no items left, x ≤ k with one or two items paying) so the simulator can go
   much further.
2. Prove the shallow carry in Lean (it needs an induction over k with the tail re-bracketed by 4).
3. Look for a heuristic for how often deep events occur and whether the halting ones have positive density.
