# 1RB1LC_1RC0RF_1RD0LB_1RE0LD_1LF---_0RA1LA

bbchallenge id 66813, a BB(6) holdout (group G06). Family: **two blocks trading words, with resets**. Open; the run from blank tape is proved in Lean, with exact step counts, through all of level 1 to the first
configuration of level 2 (past 10^1543 steps), and every reset at a nearly empty tail is a theorem: one class halts,
fourteen never halt, the rest start a new tail.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LC |
| B | 1RC | 0RF |
| C | 1RD | 0LB |
| D | 1RE | 0LD |
| E | 1LF | --- |
| F | 0RA | 1LA |
## What it does

Everything happens left of the start. Write `c = 1100`, `d = 10110110`. At the records of the head at the left end
the tape is

    0^inf 0^k c^n J d^m 1 0 (1110)^r ...

with a short junction `J` that cycles through a few shapes (`1^2 0 1 0 1 0 1^2 0`, `1^2 0 1^2 0`, `1 0`, ...).

* **Turns at the left end** (`lean/Rules.lean`, generated by `lean/rules.py`): `bounce_c`:
  `0^inf (1100)^(n+1) C> 11 R` -> `0^inf 1 (1001)^(n+1) 1001 B> R` (16n+32 steps); `bounce_a`:
  `0^inf 1 (1001)^(n+1) A> 1 R` -> the same (16n+33 steps); `start_a`: `0^inf A> 0 (1100)^(n+1) R` ->
  `0^inf (1100)^(n+1) 1 B> R` (6n+7 steps). For all n and every tape R.
* **A period** (`lean/Rules.lean` `period`, `lean/Periods.lean` `periods`, kernel): with `cfg n m R` =
  `0^inf B> 0 0 1 (1100)^n (10110110)^m R`, `cfg n (m+5) R` -> `cfg (n+31) m R` in 448n + 6952 steps, for all n, m
  and every R (never read); q periods: (n, m+5q) -> (n+31q, m). The junction goes through its whole cycle in a period
  (84 records at the left end).
* **Phase ends and resets** (`lean/ResetRules.lean`, generated by `lean/resets.py`; `lean/Resets.lean`; kernel). A
  phase ends at `cfg n r (tl t R)` = `0^inf B> 0 0 1 (1100)^n (10110110)^r 1 0 (1110)^t R` with r < 5. The reset
  reads only the first 1 to 4 words `1110` of the tail and reaches, for every n, every t and every tape R (never read):

  | r | from (n, r, tail) | reaches | steps | theorem |
  |---|---|---|---|---|
  | 0 | (2a, 0, t+4) | `cfg 10 (a+2) (tl t R)` | 151n + 1560 | `reset0_even` |
  | 0 | (2a+1, 0, t+4) | `cfg 10 (a+3) (tl t R)` | 151n + 1605 | `reset0_odd` |
  | 1 | (n, 1, t+1) | `cfg (n+12) 0 (tl t R)` | 192n + 1374 | `reset1` |
  | 2 | (n, 2, t+4), n >= 1 | `cfg (n+32) 0 (tl t R)` | 512n + 8840 | `reset2` |
  | 3 | (2a, 3, t+3) | `cfg 10 (a+12) (tl t R)` | 471n + 8170 | `reset3_even` |
  | 3 | (2a+1, 3, t+3) | `cfg 10 (a+13) (tl t R)` | 471n + 8215 | `reset3_odd` |
  | 4 | (2a, 4, t+2) | `cfg 10 (a+13) (tl t R)` | 471n + 8286 | `reset4_even` |
  | 4 | (2a+1, 4, t+2) | `cfg 10 (a+13) (tl t R)` | 471n + 8241 | `reset4_odd` |

  That is the table measured before (n = 100..300) unchanged: m' = ceil((n+4)/2), floor((n+25)/2), floor((n+26)/2)
  for r = 0, 3, 4, and t loses 4, 1, 4, 3, 2 words; it holds for every n (n >= 1 for r = 2) and whatever follows the
  words read (the suffix `1 0^inf` of the real run, or the second-level suffix). A new phase `cfg 10 m'` runs
  floor(m'/5) periods (`periods_exact`: q periods from n take q(448n + 6952) + 6944 q(q-1) steps) to n = 10 + 31
  floor(m'/5), r = m' mod 5. So n about triples per phase while t loses 1 to 4 words.
* **The phase map** (`lean/Resets.lean`). `phase : Nat × Nat × Nat → Option (Nat × Nat × Nat)` is reset plus
  periods on (n, r, t) (the map of `py/m7map.py`; `none` when t is too small for the row, r >= 5, or r = 2 with
  n = 0) and `phaseSteps` its step count. `phase_spec`: if `phase (n, r, t) = some (n', r', t')` then for every R,
  `steps (phaseSteps (n, r, t)) (cfg n r (tl t R)) = some (cfg n' r' (tl t' R))`. `phaseRun k` iterates it k times
  with the summed steps and `phaseRun_spec` says the machine follows it; `phaseRun_some`: from any (n, r, t) with
  r < 5, n >= 1 and t >= 4k the map runs k phases (n' >= 10, r' < 5 and t' >= t - 4 at each step).
  `run_from_17` (by `decide`): `phaseRun 5 (17, 0, 6805) = some ((910, 0, 6790), 6708626)`, as `m7map.py` prints.
  `level1_end'` (by `decide` on 772-digit numbers): from `cfg 17 0 (tl 6805 R)` the machine reaches, in the exact
  step count, `cfg n 3 (tl 0 R)` after 2177 phases, for every R.

### The run (`c/m7fast.c`, `py/m7map.py`)

`m7fast` applies the period rule in one stroke wherever it fits (exact step counts) and simulates the rest; checked
against the plain machine (`VAL=11`: whole tape and state compared at 1,164 checkpoints, every jump included, to
5.9*10^10 steps). From blank tape, with the tail `1001`, the phase ends are (72, 0), (227, 0), (692, 2), (2180, 2),
(6799, 1); the last reset (step 373,111,704) writes the tail `10 (1110)^6805 1`. Then the phase ends (n, r, t) are
(17, 0, 6805), (72, 1, 6801), (84, 0, 6800), (258, 4, 6796), ... up to (235599917, 3, 6746) at step
447,668,812,972,368,258, where the 2 GB tape runs out. No halt.

`m7map.py` iterates the table: from (17, 0, 6805) at step 374,475,636 it reproduces all 19 phase ends of the run
with their exact step counts. The table is now a theorem for every n (above), so from that phase end on the run is
proved (`level1_end'`, with R = `1 0^inf`): phase 2175 ends at (n, 4, 5), phase 2176 at (n, 3, 3) with
n = 11 mod 100 (771 digits, about 10^1542 steps in all), phase 2177 at (n, 3, 0) with n = 63 mod 100 (772 digits,
about 10^1543 steps), without a halt. That the run from blank tape reaches (17, 0, 6805) with the tail
`10 (1110)^6805 1 0^inf` is now proved too (`blank_to_17`, below), and so is the reset after phase 2177.

With fewer words than a row reads (t < 4, 1, 4, 3, 2 for r = 0..4) the constructed tapes show other resets: the
tail is rebuilt with about n words `1110` and a new suffix (`1001101011001`), as the reset of (6799, 1) built a tail
of 6805 words. So the run is a nested structure, the same
kind of counter one level up, and the next level starts with numbers of about 770 digits.

## From blank tape to level 2, and every reset at a nearly empty tail (22 Nov)

**The run from blank tape** (`lean/BlankRun.lean`, rules in `lean/TailResetRules.lean` from `lean/tailresets.py`;
kernel, no `sorry`). Before the long tail exists the tail after the d block is `1001`, and its resets are rules for
every n: (n, 0) goes to the new phase (10, floor(n/2) - 1) and (n, 2) to (10, ceil(n/2) + 6), both keeping `1001`
(`tail0_even/odd`, `tail2_even/odd`); (n, 1) builds the long tail, (17, 0) with `10 (1110)^(n+6) 1` (`tail1`).
`blank_prefix` (7106 steps, `decide` on the list simulator) reaches (10, 10) with tail `1001`; then periods and these
resets give the phase ends (72, 0), (227, 0), (692, 2), (2180, 2), (6799, 1) and (17, 0, 6805): `blank_to_17`,
`steps 374475636 init = some (cfg 17 0 (tl 6805 s1))`. At the end of level 1 (`level1_end'`, phase 2177, (N, 3, 0)
with the suffix `1`) the reset reads the suffix and goes straight to (17, 0) with the tail
`10 (1110)^(N+20) 1001101011001` in 440N + 9367 steps (`level2_entry`). Together (`blank_to_level2`): from blank tape
the machine reaches, without halting, `cfg 17 0 (tl (N+20) s2)`, the first record of level 2, with N = 63 mod 100,
10^771 <= N < 10^772, after more than 10^1543 steps.

**The resets at a nearly empty tail** (`lean/NearEmpty.lean`, rules in `lean/NearEmptyRules.lean`, both from
`lean/nearempty.py`; kernel). A phase end `cfg n r (tl t s)` with t below what row r of the reset table reads (t < 4,
1, 4, 3, 2 for r = 0..4) reads into the suffix s. For each suffix of the run every such reset is a theorem for every
n (per parity where the end needs it). Measured first on n = 60..65 (`py/nearempty_table.py`, output in
`runs/nearempty_table.txt`); each class turned out linear in n, and Lean proves the symbolic run. Here `loop` is the
record `0^inf B> 0 0 1 (1100)^(n+k) 0 1 0^inf`, from which `loop5` gains five words 1100 every 80n + 395 steps
forever, so the class never halts (`*_never_halts`):

So the halting class and the looping classes of the 13 Nov section below are now theorems, and so is the way into the
halting class: `s2_r0_t6_halts`, a phase end (n, 0, 6) on level 2 with n = 0 or 9 mod 10 halts (the generic reset and
its periods end at (n', 2, 2)). Some level-2 resets go back to the tail `1001` of the start (a new level 0 inside the
old one), and some leave tails not tabulated here (`1100 1011001`, `10 1101001`, or the suffix itself right after the
d block): those are the third level. Which class the real run meets at the end of level 2 is still the open
question.

The proofs are written by a new emitter, `tools/py/bbtools/symframe.py`: the same symbolic run as `symtm.py`, but each
piece (a stretch of single steps, a crossing, a re-bracketing) is proved on the cells it touches for every tape beyond
them, stated once per file, and the pieces are chained by unification. The 36 rules of `NearEmptyRules.lean` take
0.7 MB and 22 s this way; with `symtm.prove` they were 21 MB and ran out of memory.

## Remainder classes at a nearly empty tail (closed-set test, 13 Nov)

The method that closed another holdout (keep the big counts free, track only remainders; it proves non-halting if no
class can halt) was tried here: n free, every r < 5, every tail `10 (1110)^t S` with t = 0..7 and t = 20, for the
first-level suffix S = `1` and the second-level suffix S = `1001101011001`, n = 60..69 (`c/reset.c` runs the plain
machine to the next record `B> 0 0 1 (1100)^n (10110110)^m 10...`; `py/classes.py` tabulates; output in `runs/`).

* The generic rows of the reset table hold with either suffix (t = 20); `lean/Resets.lean` now proves them for every
  suffix.
* **A halting class exists** on the second level: `cfg n 2` with the tail `10 (1110)^2 1001101011001` halts for every
  n tried (60..69, 80, 101; 31,436 steps at n = 60); so does t = 1, r = 2 with n = 6, 7 mod 10. It is reachable: t = 6,
  r = 0, n = 0 or 9 mod 10 starts a phase that ends there (n = 60, 69, 160, 1009 halt by direct simulation).
  With S = `1` no class with t <= 7 halts.
* **Looping classes exist**: e.g. r = 1 with the tail `101` enters a cycle that adds five words `1100` per round
  (junction `11011011011001` again and again; followed for 3,000 rounds, not proved).
* Other classes rebuild the tail (about 3.1 n words `1110`, suffix `1001101011001`) or leave a short tail (`1`,
  `1001`, `1011101`).
* The real run (table iterated; proved from (17, 0, 6805) on, see above) ends level 1 at r = 3, t = 3, n = 11 mod
  100 (771 digits); for n = 1 mod 10 the next record of this form (`c/reset.c`: after the proved phase to (n', 3, 0)
  and the reset there, which reads into the suffix) is `cfg 17 0` with the tail
  `10 (1110)^(31(n-1)/10+92) 1001101011001` (n = 61..211 checked). Level 2 then takes about 10^770 phases; its end
  depends on r and n mod 10 there.

Assumptions: the outcome of a class is taken from n = 60..69 only (plus the spot checks named); "loops" is a run cut
off at 2*10^9 steps; nothing in this section is proved in Lean except the generic rows (`lean/Resets.lean`).
Conclusion: no closed set exists, the question is Collatz-like (the tracker's "cryptid" label is right).

22 Nov: every class with fewer words than its row reads is now a theorem for every n (section above), and the
classes with more words left follow the proved reset table.

## Why the region-memo engine stalled, and the fix (21 Nov)

In the hour-long runs of PR #328 the region-memo engine (`tools/py/bbtools/regaccel.py`) used blocks of 4 cells and
got stuck near 10^9 steps. The reason is the word `d = 10110110`: it is 8 cells long, so with 4-cell blocks `d^m` reads
as `1011 0110 1011 0110 ...`, two different blocks alternating, and no run is longer than 1. The tape then has tens of
thousands of distinct runs, and the engine's recursion (one level per run) blows up. With blocks of 8 cells `d^m` is
one run, and so are `c^n` and the tail `(1110)^t` (as `11101110`):

    python3 tools/py/bbtools/regaccel.py 1RB1LC_1RC0RF_1RD0LB_1RE0LD_1LF---_0RA1LA 8 1800

reaches a step count of 186,096 digits (at least 10^186095) in 30 minutes without a halt, against 7.07·10^19058 for the
earlier Quick_Sim run. The tape it ends on is `0^inf (00110011)^~10^93046 00110010 <F 10011010 (11101110)^~10^771 ...`:
the first level runs in the block of about 10^93046 words, and the second-level tail of about 10^771 words is the one
predicted by the reset table above (level 1 ends with n of about 770 digits). Its run agrees cell for cell with a
direct run at all 7 points it was compared at, up to 2·10^9 steps (`tools/py/regcheck.py ... 8 2e9`). The bound is in
`holdouts/regaccel.json`. This is a bounded run (trusted Python) and says nothing about later steps; the outcome still
turns on the Collatz-like second level described above.

## For later

* The third level: the tails `1100 1011001` (`x3`), `10 1101001` (`tl 0 y`) and the suffix right after the d block
  (`cfg n 0 s2`), which some level-2 resets leave, are not tabulated; nor are the resets of the level-0 tail `1001`
  when it comes back inside level 2 (the same rules as at the start, `tail0_*` ... `t1001_r4_t0`, apply, with blank
  tape after it only).
* The end of level 2 of the real run: level 2 starts at `cfg 17 0 (tl (N+20) s2)` (proved) and lasts about
  (N+20)/2.5 phases of the proved phase map; its last phase end (r, t, n mod 10) decides between the rows of the
  table above. Nothing short of a closed form for about 10^770 iterations of the map is in sight.
