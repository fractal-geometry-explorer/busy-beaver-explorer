# 1RB1LC_1RC0RF_1RD0LB_1RE0LD_1LF---_0RA1LA

bbchallenge id 66813, a BB(6) holdout (group G06). Family: **two blocks trading words, with resets**. Open; the first level (periods and resets) is decoded with exact step counts.

| state | read 0 | read 1 |
|---|---|---|
| A | 1RB | 1LC |
| B | 1RC | 0RF |
| C | 1RD | 0LB |
| D | 1RE | 0LD |
| E | 1LF | --- |
| F | 0RA | 1LA |
## What it does

Everything happens left of the start. Write `c = 1100`, `d = 10110110`. At the records of the head at the left end
the tape is

    0^inf 0^k c^n J d^m 1 0 (1110)^r ...

with a short junction `J` that cycles through a few shapes (`1^2 0 1 0 1 0 1^2 0`, `1^2 0 1^2 0`, `1 0`, ...).

* **Turns at the left end** (`lean/Rules.lean`, generated by `lean/rules.py`): `bounce_c`:
  `0^inf (1100)^(n+1) C> 11 R` -> `0^inf 1 (1001)^(n+1) 1001 B> R` (16n+32 steps); `bounce_a`:
  `0^inf 1 (1001)^(n+1) A> 1 R` -> the same (16n+33 steps); `start_a`: `0^inf A> 0 (1100)^(n+1) R` ->
  `0^inf (1100)^(n+1) 1 B> R` (6n+7 steps). For all n and every tape R.
* **A period** (`lean/Rules.lean` `period`, `lean/Periods.lean` `periods`, kernel): with `cfg n m R` =
  `0^inf B> 0 0 1 (1100)^n (10110110)^m R`, `cfg n (m+5) R` -> `cfg (n+31) m R` in 448n + 6952 steps, for all n, m
  and every R (never read); q periods: (n, m+5q) -> (n+31q, m). The junction goes through its whole cycle in a period
  (84 records at the left end).
* **Phase ends and resets.** A phase ends at `cfg n r T` with r < 5. With the tail T = `10 (1110)^t 1 0^inf` the next
  phase end follows this table (measured on constructed tapes, n = 100..300, both parities, t = 20, 40, 41; the
  steps do not depend on t):

  | r | next | t | steps |
  |---|---|---|---|
  | 0 | new phase, m' = ceil((n+4)/2) | t-4 | 151n + 1560 (n even), 151n + 1605 (odd) |
  | 1 | (n+12, 0) | t-1 | 192n + 1374 |
  | 2 | (n+32, 0) | t-4 | 512n + 8840 |
  | 3 | new phase, m' = floor((n+25)/2) | t-3 | 471n + 8170 (even), 471n + 8215 (odd) |
  | 4 | new phase, m' = floor((n+26)/2) | t-2 | 471n + 8286 (even), 471n + 8241 (odd) |

  A new phase is `cfg 10 m'`; its floor(m'/5) periods end at n = 10 + 31 floor(m'/5), r = m' mod 5. So n about
  triples per phase while t loses 1 to 4 words.

### The run (`c/m7fast.c`, `py/m7map.py`)

`m7fast` applies the period rule in one stroke wherever it fits (exact step counts) and simulates the rest; checked
against the plain machine (`VAL=11`: whole tape and state compared at 1,164 checkpoints, every jump included, to
5.9*10^10 steps). From blank tape, with the tail `1001`, the phase ends are (72, 0), (227, 0), (692, 2), (2180, 2),
(6799, 1); the last reset (step 373,111,704) writes the tail `10 (1110)^6805 1`. Then the phase ends (n, r, t) are
(17, 0, 6805), (72, 1, 6801), (84, 0, 6800), (258, 4, 6796), ... up to (235599917, 3, 6746) at step
447,668,812,972,368,258, where the 2 GB tape runs out. No halt.

`m7map.py` iterates the table: from (17, 0, 6805) at step 374,475,636 it reproduces all 19 phase ends of the run
with their exact step counts. Taking the table to hold for every n (heuristic: measured to n = 300, matched by the
run to n = 2.4*10^8), it runs 2,176 more phases, about 10^1541 steps (n about 10^770), without a halt, until t < 6.

With t < 6 the constructed tapes show other resets: the tail is rebuilt with about n words `1110` and a new suffix
(`1001101011001`), as the reset of (6799, 1) built a tail of 6805 words. So the run is a nested structure, the same
kind of counter one level up, and the next level starts with numbers of about 770 digits.

## Remainder classes at a nearly empty tail (closed-set test, 13 Nov)

The method that closed another holdout (keep the big counts free, track only remainders; it proves non-halting if no
class can halt) was tried here: n free, every r < 5, every tail `10 (1110)^t S` with t = 0..7 and t = 20, for the
first-level suffix S = `1` and the second-level suffix S = `1001101011001`, n = 60..69 (`c/reset.c` runs the plain
machine to the next record `B> 0 0 1 (1100)^n (10110110)^m 10...`; `py/classes.py` tabulates; output in `runs/`).

* The generic rows of the reset table hold with either suffix (t = 20).
* **A halting class exists** on the second level: `cfg n 2` with the tail `10 (1110)^2 1001101011001` halts for every
  n tried (60..69, 80, 101; 31,436 steps at n = 60); so does t = 1, r = 2 with n = 6, 7 mod 10. It is reachable: t = 6,
  r = 0, n = 0 or 9 mod 10 starts a phase that ends there (n = 60, 69, 160, 1009 halt by direct simulation).
  With S = `1` no class with t <= 7 halts.
* **Looping classes exist**: e.g. r = 1 with the tail `101` enters a cycle that adds five words `1100` per round
  (junction `11011011011001` again and again; followed for 3,000 rounds, not proved).
* Other classes rebuild the tail (about 3.1 n words `1110`, suffix `1001101011001`) or leave a short tail (`1`,
  `1001`, `1011101`).
* The real run (table iterated, heuristic) ends level 1 at r = 3, t = 3, n = 11 mod 100 (771 digits); for n = 1 mod 10
  that reset gives `cfg 17 0` with the tail `10 (1110)^(31(n-1)/10+92) 1001101011001` (n = 61..211 checked). Level 2
  then takes about 10^770 phases; its end depends on r and n mod 10 there.

Assumptions: the outcome of a class is taken from n = 60..69 only (plus the spot checks named); "loops" is a run cut
off at 2*10^9 steps; nothing in this section is proved in Lean. Conclusion: no closed set exists, the question is
Collatz-like (the tracker's "cryptid" label is right).

## Status

Open.

* Lean: `lean/Blank.lean`, `lean/Rules.lean` (left-end turns, `period`), `lean/Periods.lean` (`periods`).
* No halt to 4.5*10^17 steps (exact, accelerated); heuristically none for 2,176 phases more (10^1541 steps).
* The only halting transition is E reading 1.

## For later

* Prove the resets as rules (each is a bounded number of trips; one per row of the table and parity), which would
  make the whole first level a Lean theorem.
* Prove the halting class and one looping class in Lean (bounded runs with n symbolic), so that "some class halts,
  some class never does" is a theorem.
* The resets at a nearly empty tail are tabulated above; a third level (after `1001101011001` is used up) is not.
