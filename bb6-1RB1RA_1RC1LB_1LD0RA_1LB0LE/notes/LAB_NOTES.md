# Lab notes: 1RB1RA_1RC1LB_1LD0RA_1LB0LE_1LF1LD_---0LD

## 30 October 2026: setup, the pass, and the pass map

Set up on the shared tools (`../../tools`): `lean/Machine.lean` generated by `bbtools.leangen` (namespace `BB6d`),
bounded runs in `lean/Blank.lean`, rules in `lean/Rules.lean` (generated by `lean/rules.py`).

| state | on 0 | on 1 |
|---|---|---|
| A | 1RB | 1RA |
| B | 1RC | 1LB |
| C | 1LD | 0RA |
| D | 1LB | 0LE |
| E | 1LF | 1LD |
| F | halt | 0LD |

**Where a halt comes from.** F is entered only by E0 (write 1, move left), so the machine halts exactly when E reads a
0 whose left neighbour is 0 (`halt_shape`, kernel).

**Bounded runs.** No halt in 20,000 steps (kernel), 10⁷ (`native_decide`), 10⁹ (C, 3,641 ones, about 4,000 cells),
10¹¹ (C, 15,234 ones, 8.5 minutes). The width grows like 4·t^(1/3) (about 4,000 cells at 10⁹ steps, about 1,000 passes).

**No linear invariant.** `bbtools.invariants` finds no conserved a·ones + b·pos + W[state] modulo 2 to 12.

### The pass

The records at the right end come in threes, `... A>0`, `... B>0`, `... C>0`, and at each `A>0` the tape is blocks of
ones separated by single 0s: `1^y1 0 1^y2 0 ... 0 1^yk A>0`. Call that a pass start and `[y1, ..., yk]` its block
list. From blank tape the pass starts are (`python3 py/passmap.py orbit 12`)

    [2,2] [3,5] [1,7,4] [5,11] [2,11,7] [5,14,5] [2,10,12,4] [2,14,16] [12,24] [14,26] [15,29] [7,25,16] ...

and pass n starts with 4(n+1) ones. A pass, with the Lean rule for each phase (`lean/Rules.lean`, every length):

1. `start`: A, B, C write three ones on the right; C0 turns D back onto the second (`L A> 0 0 0 R` to `L 1 D> 1 1 R`).
2. `de_sweep`, `de_sweep_odd`: D and E run left writing 0 and 1 in turn, turning `1^(2m)` into `(10)^m`-like stretches.
   Over an odd stretch E reaches the 0 before it, over an even one D does.
3. `e_cross`: E on a 0 with a 1 to its left writes 1, F writes 0 and D continues into the next block, leaving a `00`.
   If the cell to the left is 0 instead (an empty block, or the blank left end), F reads 0: the halt.
4. `d_stop`: D on a 0 writes 1 and B runs left to the previous 0, which moves one cell right; A starts the zigzag.
5. `zig`, `a_sweep`, `b_sweep`: one round `L 0 1^(p+1) A> 0 1 R` to `L 1 0 1^(p+2) A> R`; the rounds absorb the
   stretch the sweep left, then C meets the blank at the right end (C0) and the next pass starts.

In the first 2·10⁷ steps every C0 is at the right end (274 of them), so each pass has exactly one sweep.

So the sweep crosses the last block if it is odd, then crosses blocks while they are even, and stops at the first odd
block y_j (D reaches the 0 left of it). It halts if it runs off the left end: **last block odd, all others even**.

### The closed form (`py/passmap.py`, `passmap`)

With the blank on the left read as empty blocks y0 = y-1 = 0:

* y_k = 2m even (the sweep stops at once): drop y_k; y_(k-2) and y_(k-1) each gain m+2.
* y_k odd, stop at j < k: y_(j-2) gains (y_j−1)/2; y_(j-1) gains (y_j+1)/2 + h_(j+1); the blocks y_j..y_k become
  h_(j+1)+h_(j+2), ..., h_(k-1)+h_k, h_k−1, where h_i = y_i/2 for the crossed even blocks and h_k = (y_k+5)/2.
* stop block y_j = 1: not covered. The machine there changes the count of ones by an odd number (`[5,7,1,1]` goes to
  `[9,10]`, `[2,1,1]` to `[4,5]`, which then halts).

Checks: the form agrees with the machine (`run_pass`) on 2,847 random lists of up to 6 blocks and 282 of up to 10
(1 to 12 ones each), all cases but a stop block of 1; the orbit of the form from `[2,2]` is exactly the 1,005 pass
starts of the first 10⁹ steps (C records), and the test checks the first 10⁸.

**Consequence (conditional on the form).** Outside a stop block of 1 the form adds exactly 4 ones, so the count stays
0 mod 4; a halt needs the last block odd and the others even, an odd count. **So the machine halts only if the orbit
reaches a pass whose sweep stops at a block of a single 1.** All blocks the form makes are at least 2 except a new
first block (y_(j-2) + (y_j−1)/2 with y_(j-2) blank), so the stop block 1 can only be a first block that came from a
stop at y_j = 3 on an earlier pass.

### The orbit (`python3 py/passmap.py stats N`)

2·10⁶ passes (4 s): no halt, no stop block of 1 (after pass 50 the smallest stop block is 59);
block counts 2 (772,336), 3 (1,009,285), 4 (213,103), 5 (5,269), 6 (7). The blocks are fixed fractions of the
count of ones: two-block states are `[a, 2a+d]` with |d| ≤ 3 (d = −3..3 seen 7,099 / 165,683 / 208,085 / 165,682 /
211,619 / 7,099 / 7,069 times), returned to every 1 to 32 passes. Between returns a tail block on the right halves
each pass, e.g.

    [2012, 4697, 1343] [2348, 5035, 673] [2517, 5205, 338] [2688, 5376]

2·10⁷ passes (42 s, sum 8·10⁷ at the end): the same picture, no stop block of 1, the smallest after pass 50 still
59, block counts 2 to 6 (6 blocks 76 times), |d| ≤ 3.

The first block halves when the sweep stops at it (j = 1), which adds a block. That halving of the first block is
the only road to a stop block of 1, and it would need about log₂ of the count of ones halvings in a row.

## 31 October 2026: the closed form in Lean, and the reduction

`lean/Pass.lean`, kernel only (axioms `propext`, `Quot.sound`, and `Classical.choice` for the last three theorems;
no `native_decide`).

**Encoding.** Block lists nearest first, `zs = [yk, ..., y1]`, so that `enc zs` (blocks `rep y [true]` separated by
`cons false`, blank at the end) is the left stream and the pass start is `⟨enc zs, blank, A⟩`. Blank tape is `enc []`,
and blank on the left reads as empty blocks (`enc [0, 0] = enc []`), so no padding cases are needed in the runs.

**The map, recursively.** `next (y :: ys)`: y = 2m even gives `bump (m+2) ys` (the two nearest blocks of `ys` gain
m+2). y odd starts `sweep [(y+3)/2] ys`, which records g = y/2 − 1 for each even block it crosses, halts at an empty
block or the left end, gives `.one` at a block of 1, and at y = 2n+3 stops with `zag q ms gs` where `(q, ms) =
bump (n+1) rest`; `zag q ms (g :: gs) = zag g ((q+g+2) :: ms) gs`. In terms of the notes above, g_i = h_i − 1.

**The proof.** What the sweep leaves on the right is `U gs` (each g as `0 0 1 (01)^g`). Three new generated pieces:
`d_stop_empty` and `zig_empty` (the pieces with an empty block on the left, which `symtm` cannot state with a count
that may be 0) and `turn` (`A> 0 0 1` to `1 1 0 A>`). Then inductions: `zigs` (r rounds of the zigzag), `zag_run` (the
zigzag through `U gs`), `cross_even` and `sweep_run` (the sweep), `stop` (d_stop, a_sweep and the rounds), and `pass`.
`pass_halt` covers the halting outcomes.

**Counting.** `next_sum`: a pass adds 4 ones and keeps blocks nonempty (the last g is (yk+3)/2 ≥ 2, so `zag` never
leaves an empty block). `next_halt_odd`: with nonempty blocks, a halting pass has an odd count. So `orbit n` (pass n
from blank, `orbit 1 = [2, 2]`) has 4n ones and never halts, and

    theorem halts_only_by_one (h : HaltsFromBlank) : ∃ n, orbit n = .one

**Tests.** `TestLeanPassMap` evaluates `next` on 3,000 random lists and the orbit for 400 passes with `#eval` and
compares with `py/passmap.py`.

**Next.** The return map on two-block states `[a, 2a+d]`, and whether the first block can halve down to 1.
## 31 October 2026: the return map on two-block states (`py/returnmap.py`)

Everything here is computed on the closed form of the pass map (`py/passmap.py`). Lean now proves that closed form
(`pass`, `lean/Pass.lean`) and `passmap` is tested against Lean's `next`, so these results rest on Lean plus this
Python computation.

**Six short chains, all ending at d = 1** (`python3 py/returnmap.py chains`; algebra from the closed form, checked
on each whole class mod 4 by the symbolic run below). A reachable two-block state `[a, 2a+d]` has 3a + d = 0 mod 4.

| from | a mod 4 | to | passes |
|---|---|---|---|
| `[a, 2a]` | 0 | `[a+2, 2(a+2)−2]` | 1 |
| `[a, 2a−2]` | 2 | `[a+1, 2(a+1)−1]` | 1 |
| `[a, 2a+2]` | 2 | `[a+3, 2(a+3)−3]` | 1 |
| `[a, 2a−1]` | 3 | `[a+2, 2(a+2)+1]` | 2 |
| `[a, 2a+3]` | 3 | `[a+3, 2(a+3)+2]` | 2 |
| `[a, 2a−3]` | 1 | `[a+3, 2(a+3)+0]` | 3 |

So d = 2 → −3 → 0 → −2 → −1 → 1 and 3 → 2, and the return map is the map G on the states `[a, 2a+1]`, a = 1 mod 4:
the excursion from one such state to the next.

**G(a) = a + 12k after exactly 9k passes**, k ≥ 1. The orbit from blank tape is `[5, 11]` at pass 3, and from there
it is a chain of states `[a, 2a+1]` with **a = 5 mod 12**: write a = 12s + 5, then each excursion moves s to s + k.
In the first 2·10⁵ passes k = 1 (20,119 times), 2 (1,024), 3 (18): the orbit visits almost every s. So whether the
machine halts is a question about the excursion from `[12s+5, 24s+11]` for (nearly) every s, not about one
irregular orbit.

**The excursion, symbolically** (`python3 py/returnmap.py classes D`). The same `passmap` code runs on values
p + q·u (u ≥ 0 free) that know their parity while q is even; unknown parities split the class, and a block that could
be ≤ 1 for some u ≥ 0 where it matters sets the one value u = 0 aside. Down to a mod 2^62 (24 s):

* 19,231 routes, by k: 5, 20, 36, 130, 448, 1,680, 4,032, 9,747, 3,131, 2 for k = 1 … 10 (the counts for k ≤ 6
  are the same at mod 2^54: complete);
* **no class halts or meets a stop block of 1**; the only value set aside is a = 1 (`[1, 3]` stops at the block 1);
* 2,890 classes are still open (measure 2,890·2⁻⁶⁰ of a = 1 mod 4); their members below 2^62 were run one by one,
  and all return (k = 8 to 11).

So **for every a = 1 mod 4 with 5 ≤ a < 2^62 the excursion from `[a, 2a+1]` returns to `[a+12k, …]`, k ≤ 11,
without a halt or a stop block of 1** (trusted computation on the closed form). With the orbit chain above:
**with `halts_only_by_one`, no halt in the first 3.4·10¹⁸ passes** (until a passes 2^62; pass n has 4(n+1) = 3a + 1
ones). In steps that is far beyond 10¹⁸ (each pass is at least one step; the run so far takes about 0.016·S³ steps
for S ones, which would be about 10⁵⁵).

**The inner loop: the route list is infinite, but finite for each k.** After the first pass of an excursion the
last block is a + 2, and an odd last block is always crossed and becomes (z+3)/2, i.e. z − 3 halves. So that tail
lives exactly v₂(a − 1) passes, and the excursion is at least that long: k ≥ (v₂(a−1)+1)/9, unbounded
(a = 2^r + 1: k = 1, 2, 2, 2, 3, 4, 4, 4, 5, 5, 6, 6, 6, 7, 7 for r = 4, 8, …, 60). Inside it the front blocks run
their own excursions with their own halving tails (see a = 2²⁴ + 1), so the loops nest. On the other side, each pass
halves the u-coefficients at most once, so a route of 9k passes depends only on a mod 2^(9k+2) or so: in the data,
the routes with k = 1 … 5 need a mod 2^8, 2^17, 2^26, 2^35, 2^44 at most. So for each k the routes are finitely
many, and a proof has to handle the tail loop (and the loops it nests) by an induction on its length, not by a
finite table.

**How far from a stop block of 1** (heuristic). On every route down to mod 2^62, every stop block is at least about
a/64 (`classes` prints the worst ratio per modulus 2^m: 2^-x with x = 1 up to m = 10, 4 up to m = 45, 6 up to
m = 62). For a = 2^r + 1 the smallest stop block is about a·2^(−r/10) (1/16 at r = 20, 1/64 at r = 60). A stop block
of 1 needs x close to m; the observed x grows like m/10. For a ≤ 1.2·10⁶ the smallest ratio is 0.042 (a = 985,345).

**What a proof would need.** (1) The closed form in Lean (done, `pass`). (2) The six chains (one pass each in the closed form:
routine). (3) An induction for the excursion: the front with a halving tail of length L behaves like the front with
a shorter one, so that a stop block stays above a fixed fraction of a; the margins above say the fraction is about
2^(−v/10) where v is the depth of the 2-adic structure, so the statement to prove is likely "every stop block is at
least a·2^(−c·log₂ a) with c < 1", which is enough.

### Why: the stop block of 1 needs a stop at a 3 one pass earlier

From the closed form, a block of 1 can only be a new first block `(y_j − 1)/2` with `y_j = 3` and `j ≤ 2` (every other
new block is at least 2: `h_i + h_(i+1)` with crossed even blocks, `h_k − 1 ≥ 2`, and sums with old blocks). It stays
the first block until a sweep stops at or left of position 3, and it is the event exactly when a sweep crosses
everything right of it. The simplest family that does it in two passes, exactly (`tests/test_passorbit.py`, all x, z <
120, and it follows from the formulas for every x, z):

    [x, 3, z], x ≡ 2 and z ≡ 3 mod 4  →  [1, x + 2 + (z + 5)/2, (z + 3)/2]  →  stop block 1

(the other residues of `[x, 3, z]` with 4 | x + 3 + z never meet it in 300 passes). **On the machine itself these
halt a few passes later**: `[2,3,3]`, `[6,3,7]`, `[10,3,11]`, `[30,3,15]`, `[62,3,63]` all halt within 7 passes of
`run_pass`. More widely (`py/passorbit.py after 12`, 90 s): of the 1,502 lists of 4, 8 or 12 ones whose closed-form orbit
meets a stop block of 1, the machine run on from there halts in 1,431 cases within 200 passes, and every pass of those
runs is clean (blocks separated by single 0s). So the event is, in practice, the road to a halt.

So the question for the blank orbit is whether a sweep ever stops at a block of 3 in the first two positions. In the
10¹¹ passes it never stops at any block below 59 after pass 50, and every stop block is at least 1.4% of the ones on
the tape (the smallest ratio, 0.0141, at pass 13,321,949, has not moved since): the stop blocks grow with the tape,
while the event needs one of size 3. The small-block searches above say the same thing from the other side: lists
that meet the event are lists with small blocks, and they meet it within 60 passes or not at all.

**What this does not show.** None of it is a proof. The searches cover short lists, two-block lists to 10⁴ and
random lists; the blank orbit is one specific list, and its two-block states `[a, 2a + d]` are far outside the
ranges searched. A proof would show that a stop block stays above a fixed fraction of the tape along the excursions
of the return map, which is what the bound "about a/64" of the return-map entry suggests on every route checked.

## 31 October 2026: looking for an invariant that rules out the stop block of 1 (`lean/Front.lean`, `py/front.py`)

The aim was an invariant of the blank-tape orbit that excludes a sweep stopping at a block of 1, proved in Lean, which
with `halts_only_by_one` would prove non-halting. **No such invariant was found, and none of the simple kinds can
work** (below). Two invariants that do hold for every list were found and proved, and they narrow the event to one
place: the first block has to fall to 1.

### Proved (kernel, `lean/Front.lean`)

* **Blocks after the first stay at least 2** (`Good`, `next_good`, `orbit_good`). From the closed form: a new block
  is a sum `h_i + h_(i+1)` of halves of crossed even blocks, `h_k − 1 = (y_k + 3)/2`, a bumped old block, or an old
  block untouched, all at least 2, except the new first block `(y_j − 1)/2` when the sweep stops at `j ≤ 2`. So
  **a sweep can stop at a block of 1 only at the first block, after crossing all the others** (`one_front`).
* **With 4 | ones, two passes in a row never both stop at the first block** (`FrontStop`, `front_twice`,
  `orbit_front_twice`). A front stop of `[f, e_2, …, e_(k−1), b]` gives `[(f−1)/2, (f+1)/2 + e_2/2, e_2/2 + e_3/2, …,
  e_(k−1)/2 + (b+5)/2, (b+3)/2]`; for that to be a front stop again the new first and last blocks must be odd and
  the ones between even, which forces `f ≡ 3`, every `e ≡ 0` and `b ≡ 3 mod 4`, so 2 mod 4 ones. The orbit has 4n
  at pass n.
* Together, **`halts_only_at_front`**: if the machine halts from blank tape, some pass start of the orbit is
  `1 0 1^e 0 … 0 1^b A>0` with every `e` even and `b` odd, and the pass before it did not stop at its first block.

All kernel, no `native_decide` (`Axioms.lean`); `tests/test_front.py` checks the same statements on the Python closed
form (every list of up to 5 blocks of size up to 7 or 12, and random ones).

### So the question is how far the first block falls

From the closed form, the first block f changes only when the sweep stops at one of the first three blocks or the
list is short: a stop at the first block halves it (`f → (f−1)/2`), a stop at the second replaces it with
`(y_2 − 1)/2`, a last block that is even on a list of two replaces it with `y_2/2 + 2`, and every other pass keeps
it or makes it larger. Reaching 1 from f takes about log₂ f falls.

`python3 py/front.py stats N` measures the *descents* of the first block along the orbit: maximal stretches of
passes over which it never grows, with their depth, the number of front stops (halvings) in them.

    passes 1..10⁸ (3 min 20 s): Good on every list, no two front stops in a row
    descents by depth: 1: 30,512,034   2: 11,718   3: 86   4: 6   5: 5
    deepest: 5 front stops, first block 12,024,895 at pass 13,321,940 down to 375,777 at pass 13,321,952 (/32)
    smallest first block / ones after pass 50: 0.0071 at pass 13,321,952 (375,777 of 53,287,808)

(In the first 3·10⁶ passes the deepest descent has 3 front stops, a factor 8, and the smallest ratio is 0.0275.)

So in 10⁸ passes the first block never loses more than a factor 32 before it grows again, and it stays above 0.7%
of the ones, while the event needs it to fall to 1: even from its lowest point, 375,777, that is about 18 more
halvings in one descent. The deep descents are rare (11 of depth 4 or 5 in 3·10⁷ descents), and the deepest is
at the same place as the smallest stop block of the 10¹¹-pass run (0.0141 of the ones at pass 13,321,949).

### Why the suggested invariants are not invariants

* **"No stop block below 59 after pass 50"** holds on the orbit (10¹¹ passes) but is not kept by the pass map:
  nothing about block sizes alone is. The small starts that meet the event do it by a **halving loop**: a front
  stop on three blocks, then an even last block on four, repeated, halves the first block every two passes while the
  other two blocks stay about the same size. `py/front.py loop`:

      [110, 63, 23] → [31, 156, 13] → [15, 94, 87, 8] → [15, 100, 93] → [7, 58, 99, 48] → [7, 84, 125]
        → [3, 46, 107, 64] → [3, 80, 141] → [1, 42, 113, 72] → [1, 80, 151]   (stop block 1)

  Every block but the last is at least 23 here, and random lists with every block but the last in [T, 4T] meet the
  event for T = 40 (2 of 10,048 with 4 | ones, 300 passes); for T = 59, none of about 37,000 did in 200 passes. What
  keeps the orbit out of the loop is the parities of its blocks, that is the 2-adic digits, not their sizes.
* **"The shape `[a, 2a+d]`, |d| ≤ 3, is kept"** is not a statement about single passes: the excursions between
  two-block states go through 3 to 6 blocks, and 5,298 of the two-block states of the first 10¹¹ passes are outside
  it. Its real form is the return map: every excursion from `[a, 2a+1]` comes back without a stop block of 1.
* **No invariant made of inequalities and residues mod a fixed 2^m can work.** Each pass halves blocks, so the
  route of the next passes depends on ever higher bits: a route of 9k passes needs a mod about 2^(9k+2), and the
  open classes of the return map keep splitting with no two alike (the dynamics thread, to mod 2^74). Any set closed
  under the map that excludes the event has to carry unboundedly many bits, which is the Collatz-like part.

### What a proof would need

With `halts_only_at_front`, non-halting follows from a lower bound on the first block along the orbit: for instance
"the first block is at least c times the ones" for any fixed c > 0, or anything above 1. The data say c = 0.007
holds through 10⁸ passes. Proving it means bounding the descents, that is showing the halving loop cannot run for
long on the orbit, and that is a statement about 2-adic digits again. The universal form is the one the return-map
thread is after: on every excursion from `[a, 2a+1]`, every stop block (and so the first block) is at least
`a·2^(−f)` with f well below log₂ a, by induction on the tail length v₂(a − 1). The two facts proved here are the
pieces of that induction that hold for every list: the event is at the first block, and front stops never come two
in a row.
